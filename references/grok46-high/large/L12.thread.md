Escape table is `& > < " '` → `&amp; &gt; &lt; &quot; &#39;` via `ERB::Util.unwrapped_html_escape`.

Two helpers, keep distinct:

- **implicit** ([L212–L217](activesupport/lib/active_support/core_ext/string/output_safety.rb#L212-L217)): used by `concat`/`<<`. Escapes `arg.to_str` when receiver is safe and arg is not `html_safe?`.
- **explicit** ([L208–L210](activesupport/lib/active_support/core_ext/string/output_safety.rb#L208-L210)): used by `%`. Escapes `arg` itself (no `to_str`).

Once the receiver is unsafe, both helpers pass the arg through unescaped.

### Security invariants vs String compatibility

**Security (must not regress; XSS surface):**

1. Unsafe input into a **safe** receiver is escaped; `html_safe` input is not.
2. `safe_concat` on a **safe** receiver does **not** escape (trusted path). On an **unsafe** receiver it raises `SafeConcatError` and does not mutate — cannot launder dirty content.
3. `%` on a **safe** format string escapes unsafe named/positional args; `html_safe` args pass through.
4. Destructive rewrites (`gsub!`/`sub!` and the `UNSAFE_STRING_METHODS!` set) set `@html_unsafe = true`. After that the buffer is no longer trusted.
5. Safety does not recover: `dup`/`clone` of an unsafe buffer stays unsafe; `*` and `%` copy `@html_unsafe` onto the new buffer.
6. A still-safe `+`/`concat` of an unsafe buffer into a safe buffer **does** escape the dirty operand (`"hello".html_safe + dirty` → `"hello&lt;&gt;"`).

**String compatibility (preserve, but not XSS):**

- `<<`/`concat` mutate and return `self`; `concat(nil)` is a no-op.
- `+`, `*`, `%` return a new `SafeBuffer` and do not mutate the receiver.
- Unsafe `[]`/`slice`/`slice!` go through `to_str` and return a plain `String`.
- Non-bang `gsub`/`sub`/etc. return a plain `String` (`to_str.*`); bang versions stay `SafeBuffer` but mark unsafe.
