`retry_on` is a `rescue_from` wrapper. Matching uses Rescuable’s reverse handler list (`klass === exception`, cause fallback). One declaration shares one counter; separate declarations do not. Below the attempt limit it reports (if requested) and re-enqueues via `retry_job`; at exhaustion it runs `retry_stopped` + `after_discard`, then either the block or `raise error`.

### Entry

`perform_now` increments the global `executions` counter, runs perform callbacks + `perform`, then rescues `Exception` and calls `rescue_with_handler`. If a handler returns, `perform_now` returns that exception object (it does not re-raise). If nothing handles it, `after_discard` runs and the original exception is re-raised.

- [execution.rb](file:///home/user/workspace/repo/activejob/lib/active_job/execution.rb) L45–L57, L66–L70
- [instrumentation.rb](file:///home/user/workspace/repo/activejob/lib/active_job/instrumentation.rb) L24–L26

```text
perform_now
  executions += 1
  _perform_job  →  run_callbacks(:perform) { perform(*arguments) }
rescue Exception => exception
  handled = rescue_with_handler(exception)
  return handled if handled
  run_after_discard_procs(exception)
  raise
```

`retry_on` only registers a Rescuable handler. It does not wrap `perform` itself.

### Exception matching (bottom-to-top, superclass, cause)

`rescue_from` appends one `[class_name, handler]` pair per listed class. Lookup walks `rescue_handlers` **in reverse** and takes the first `klass === exception` match.

- [rescuable.rb](file:///home/user/workspace/repo/activesupport/lib/active_support/rescuable.rb) L31–L32, L54–L74, L93–L110, L126–L136
- Inheritance: `rescue_handlers` is a `class_attribute`. Subclass declarations are appended, so they are searched first. Tests: [rescuable_test.rb](file:///home/user/workspace/repo/activesupport/test/rescuable_test.rb) L153–L163
- Matching operator is `===`, not a literal `is_a?` call. For Exception classes that is the same as `is_a?`. Docs say `is_a?` ([exceptions.rb](file:///home/user/workspace/repo/activejob/lib/active_job/exceptions.rb) L24–L25, L107–L108).
- If nothing matches the exception, `rescue_with_handler` retries on `exception.cause`, with cycle detection ([rescuable.rb](file:///home/user/workspace/repo/activesupport/lib/active_support/rescuable.rb) L93–L110; [rescuable_test.rb](file:///home/user/workspace/repo/activesupport/test/rescuable_test.rb) L165–L178). Active Job exception tests do not cover cause matching.

Later `retry_on` wins over an earlier superclass handler. `AfterDiscardRetryJob` declares `retry_on(AfterDiscardError)` then `retry_on(ChildAfterDiscardError)`; a child error hits only the child handler, so `after_discard` runs once ([after_discard_retry_job.rb](file:///home/user/workspace/repo/activejob/test/jobs/after_discard_retry_job.rb) L17–L18; [exceptions_test.rb](file:///home/user/workspace/repo/activejob/test/cases/exceptions_test.rb) L423–L427).

`retry_on A, B` registers **two** handler entries that close over the **same** `exceptions` array, so they share one counter.

### Counters

Key is `exceptions.to_s` for that declaration (the array passed to `retry_on`), stored on `exception_executions` and serialized with the job.

The handler **increments first**, then compares `executions < attempts`. Default `attempts: 5` means the original run plus 4 retries; the 5th failure exhausts.

Same declaration, shared counter — 3× First + 2× Second with `attempts: 4` exhausts on the 4th failure and re-raises `SecondRetryableErrorOfTwo` ([exceptions_test.rb](file:///home/user/workspace/repo/activejob/test/cases/exceptions_test.rb) L38–L54; [retry_job.rb](file:///home/user/workspace/repo/activejob/test/jobs/retry_job.rb) L34).

Separate declarations keep separate counters — 4× DefaultsError (limit 5) then 3× FirstRetryableErrorOfTwo (limit 4) still succeeds ([exceptions_test.rb](file:///home/user/workspace/repo/activejob/test/cases/exceptions_test.rb) L56–L73).

Wait algorithms also use the per-declaration counter, not global `executions` ([exceptions_test.rb](file:///home/user/workspace/repo/activejob/test/cases/exceptions_test.rb) L312–L338).

Rails 5.2 payloads with `exception_executions == nil` fall back to the global `executions` counter ([exceptions.rb](file:///home/user/workspace/repo/activejob/lib/active_job/exceptions.rb) L207–L212; [exceptions_test.rb](file:///home/user/workspace/repo/activejob/test/cases/exceptions_test.rb) L364–L384).

### Re-enqueue, queue/priority, callbacks

### Does the original exception escape?

| Path | Escapes? |
|---|---|
| Retry (attempts remaining) | No. Handler returns; `perform_now` returns the exception object. |
| Exhaustion **with** block | No, unless the block or `after_discard` raises. |
| Exhaustion **without** block | Yes. Same instance, after `retry_stopped` and `after_discard`. |
| No matching handler | Yes, after `after_discard` in `perform_now`. |
