`isolate_namespace` is class-level setup. It does not dispatch requests. It stamps the engine and the passed module so later boot, route compile, helper inclusion, and request dispatch behave as an isolated app. Mounting and `call` are a later phase.

### Class-level setup

[`Rails::Engine.isolate_namespace`](railties/lib/rails/engine.rb) (lines 384–419) always:

1. Sets `engine_name` from the **module** name, not the engine class: `engine_name(generate_railtie_name(mod.name))`.
2. Sets `config.default_scope = { module: ActiveSupport::Inflector.underscore(mod.name) }`.
3. Sets `self.isolated = true`.

`engine_name` is an alias of `railtie_name`. `generate_railtie_name` is `underscore(string).tr("/", "_")`. So unisolated `MyEngine::Engine` is `my_engine_engine`; isolated `isolate_namespace MyEngine` is `my_engine` (asserted in [`engine_test.rb`](railties/test/railties/engine_test.rb) line 952). Nested `Bukkits::Awesome` becomes engine name `bukkits_awesome` and default scope module `bukkits/awesome`.

If the module does not already respond to `railtie_namespace`, isolation defines on its singleton class:

- `railtie_namespace` → the engine class
- `table_name_prefix` → `"#{engine_name}_"`, later `"#{ActiveRecord::Base.table_name_prefix}#{engine_name}_"`
- `use_relative_model_naming?` → `true`
- `railtie_helpers_paths` / `railtie_routes_url_helpers` → that engine’s helpers and `routes.url_helpers`

Each definition is skipped if the method already exists. Isolating the same module twice does not overwrite `railtie_namespace` ([`engine_test.rb`](railties/test/railties/engine_test.rb) 1228–1255). `engine_name`, `default_scope`, and `isolated = true` still apply to the engine that called it.

**Explicit `engine_name`:** assignment is `railtie_name=`. Isolation overwrites a name set *before* it. A name set *after* is what `mount` sees (`app.railtie_name` at draw time). `table_name_prefix` closes over `engine_name` at isolation time, so a later rename does not retarget the prefix. No engine/integration test assigns `engine_name` explicitly.

**Anonymous / unnamed namespaces:** `isolate_namespace` uses `mod.name` with no nil guard. Unnamed modules (`name == nil`) blow up in `Inflector.underscore`. An unnamed *engine class* is fine if isolation runs against a named module. The only anonymous-engine test is [`railties/test/engine_test.rb`](railties/test/engine_test.rb) 6–14, which checks `routes?` is false before routes are materialized.

### Table-name prefix and relative naming

Existing `table_name_prefix` is left alone. Otherwise Active Record prepends `ActiveRecord::Base.table_name_prefix` (`"ar_prefix_bukkits_posts"` in [`engine_test.rb`](railties/test/railties/engine_test.rb) 1369–1392).

`use_relative_model_naming?` makes `ActiveModel::Naming` strip the isolated module from `param_key` / `route_key`. Externally: `polymorphic_path(Bukkits::Post.new)` inside the engine is `/bukkits/posts/1`; `form_for` emits `name="post[title]"`. From the application, `polymorphic_path(Blog::Post.new)` uses app routes; `polymorphic_url([blog, Blog::Post.new])` uses the mount ([`mounted_engine_test.rb`](railties/test/railties/mounted_engine_test.rb) 273–280).

### Route-set creation

`Engine#routes` lazily does `config.route_set_class.new_with_config(config)`, which copies `default_scope`. `draw` wraps the block in `scope(module: "bukkits")`. `Mapping#add_controller_module` prefixes the compiled controller (`"foo"` → `"bukkits/foo"`). A leading slash (`"/foo"`) strips isolation. Isolation does **not** add a path or `as:` prefix, which is why isolated `resources :posts` is still `/posts` and `posts_path` while dispatch targets `Bukkits::PostsController`.

### Default `routes` vs custom `endpoint`

Instance `endpoint` is `self.class.endpoint || routes`. `call` always sets `req.routes = routes` and `req.engine_script_name`, then runs the middleware stack around that endpoint. A custom endpoint still publishes the engine route set in `env["action_dispatch.routes"]`.

### Engine with no route file

Initializer `make_routes_lazy` always calls `routes`, creating the set. `add_routing_paths` then registers with `app.routes_reloader` if `routes? || routing_paths.any?`. After that initializer, `routes?` is true, so a missing `config/routes.rb` still contributes an empty set. The reloader only `load`s existent files. The unit test that `routes?` is false is pre-initializer.

### Lazy vs eager loading

`make_routes_lazy` sets `route_set_class = LazyRouteSet` when `Rails.env.local?`. Finisher then:

```
reloader.execute_unless_loaded if !app.routes.is_a?(Engine::LazyRouteSet) || app.config.eager_load
```

Eager (typically production): routes load at boot. Local + `LazyRouteSet`: first helper, `respond_to?(:*_path)`, request, `recognize_path`, `url_for`, or mounted-helper use calls `reload_routes_unless_loaded`. Only `*_path`/`*_url` (and non-path mounted helper names) trigger the load; other missing methods do not ([`lazy_route_set_test.rb`](railties/test/engine/lazy_route_set_test.rb)).

### Mount helpers and `main_app`

`mount` defaults `:as` to `app.railtie_name`, draws into the parent set, and for a railtie defines a `script_namer` plus `define_mounted_helper` on the **engine** route set. `main_app` is **not** created by isolation; Finisher defines it on the **application** route set.

Action Controller/Mailer then include the app’s `mounted_helpers` and, on subclassing, either the isolated module’s `railtie_routes_url_helpers` or the app helpers. Isolated controllers get `foo_path` and `main_app.bar_path`, not app helpers. Isolated engines do not share each other’s mount helpers. Nested engines get `bukkits_awesome.bar_path`. Multiple mounts use distinct `as:` names and dynamic `script_namer`.

`prepend_helpers_path` does not copy an isolated engine’s helper dir onto the app. Controller helper lookup uses `railtie_helpers_paths` on the isolated module.

### Request-time dispatch

Isolation does not install a custom dispatcher. The parent router matches `mount`, `Engine#call` stamps the engine route set on the request, the engine router matches the already-prefixed `controller: "bukkits/foo"`, and `Request#controller_class_for` constantizes `"bukkits/foo".camelize + "Controller"` → `Bukkits::FooController`. No extra namespace walk happens at dispatch.

```text
CLASS BODY
  isolate_namespace(Mod)
    engine_name = underscore(Mod.name).tr("/", "_")
    isolated = true
    config.default_scope = { module: underscore(Mod.name) }
    define on Mod (first caller only):
      railtie_namespace, table_name_prefix,
      use_relative_model_naming?, railtie_helpers_paths,
      railtie_routes_url_helpers

BOOT
  make_routes_lazy → route_set_class, Engine#routes
  add_routing_paths → reloader.paths / route_sets
  define_main_app_helper → MountedHelpers#main_app
  eager? execute_unless_loaded : leave LazyRouteSet unloaded
  AC/AM on_load → mounted_helpers + RoutesHelpers

ROUTE DRAW (boot or first lazy access)
  engine draw → with_default_scope(module:)
  app mount → default as: engine_name, define_mounted_helper + script_namer

REQUEST
  app router → Engine#call → engine router
  controller = path_parameters[:controller].camelize + "Controller"
  helpers already chosen at controller class inherit
```

Isolation’s routing effect is almost entirely the compile-time `default_scope` plus helper/module wiring. Request dispatch only consumes the controller string those routes already contain.
