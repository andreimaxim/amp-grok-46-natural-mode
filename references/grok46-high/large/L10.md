**Block.** `compact_blank!` is not Ruby `Hash#compact`. Switching `value.blank?` to `value.nil?` changes the public contract and fails the existing tests.

### Contract vs claim

[`Hash#compact_blank!`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/enumerable.rb#L265-L276) is documented as “Uses `Object#blank?`” and is implemented as `delete_if { |_k, v| v.blank? }`. The non-bang sibling (lines 259–262) uses the same predicate. Docs at 190–208 and 297–307 already show `false`, `""`, `" "`, `[]`, and `{}` as blank.

[`Object#blank?`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/blank.rb#L7-L8) is “false, empty, or a whitespace string”: `nil`, `''`, `'   '`, `[]`, `{}`, `false`. `Numeric` (including `0`) is never blank; `true` is never blank.

Ruby `Hash#compact` only drops `nil`. `ActionController::Parameters` already splits the two APIs (`#compact` vs `#compact_blank`) in [`strong_parameters.rb`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1034-L1052).

### Tests at this revision

[`enumerable_test.rb`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L360-L389): `{ a: "", b: 1, c: nil, d: [], e: false, f: true }` → `{ b: 1, f: true }` for both bang and non-bang. A `nil?` body would keep `""`, `[]`, and `false`, so `test_hash_compact_blank!` fails.

Hash tests do not cover whitespace strings, empty-hash values, `0`, or bang identity — gaps, not a reason to ship.

### Observable treatment

| Value | `blank?` | current `compact_blank!` | proposed `nil?` / `compact` |
|---|---|---|---|
| `nil` | true | delete | delete |
| `false` | true | delete | keep |
| `""` | true | delete | keep |
| `" "` / `"\t\n"` | true | delete | keep |
| `[]` / `{}` | true | delete | keep |
| `0`, `1` | false | keep | keep |
| `true` | false | keep | keep |

Only `nil` matches. The rest of the blank set is a break.

### Bang return / identity

`delete_if` is used **so the method always returns `self`**, even when nothing changed (comment at line 274). That is not `Hash#compact!`, which returns `nil` when unchanged. Equating the APIs is wrong on both the filter and the bang return.

### Minimal regression matrix (no code edits)

Keep the existing hash fixture, then add: bang `equal?(self)` when values were blank and when none were; `{ a: " ", b: "\t\n", c: "x" }` → `{ c: "x" }`; `{ a: {}, b: { k: 1 } }` → `{ b: { k: 1 } }`; `{ a: 0, b: 1, c: nil }` → `{ a: 0, b: 1 }`; `{ a: false, b: "", c: nil }` — `compact_blank!` → `{}`, `compact` → `{ a: false, b: "" }`.
