Invalid verb: `Request#request_method` → `UnknownHttpMethod` (asserted on `request_path_params` with `:bacon`, same `check_method` on this path).

**URL-decoded dynamic segments.** Two decodes: Journey `CGI.unescapeURIComponent` on captures containing `%`, then RouteSet `URI::RFC2396_PARSER.unescape` on every String (RFC2396 unescape does **not** turn `+` into space). Tests: reserved chars (`UriReservedCharactersRoutingTest#test_route_recognition_unescapes_path_components`); `%20` → space, `+` stays (`test_paths_escaped`); `%0A` → newline for both `:dynamic` and `*wildcard` (`test_escapes_newline_character_for_*`); `%2B` and `+` both yield `"hello+world"` (`test_default_route_should_uri_escape_pluses`). Regex constraints run on the **encoded** path (`test_recognize_with_encoded_id_and_regex`).

**Unmatched route vs missing controller.** After the yield loop, no dispatcher/engine hit → `ActionController::RoutingError` `"No route matches #{path.inspect}"` (the **input** `path`, post-normalize or the absolute URL). Tests: `/none`, `/optional` without segment, `/admin/products` vs regexp controller, `/page/davidjamis`, `/`, too many segments. That is “no matching dispatcher/engine route,” including wrong verb and failed constraints.

If a dispatcher **did** match, `req.controller_class` runs (`action ||= "index"` as a side effect, then `controller.camelize << "Controller"` `#constantize`). `NameError` whose missing name is that constant is re-raised as `RoutingError` **`"A route matches #{path.inspect}, but references missing controller: #{params[:controller].camelize}Controller"`**. That is the recognize_path-specific distinction. `test_non_controllers_cannot_be_matched` (`/not_a/show/10` on `:controller/:action/:id`) exercises this via `recognize_path`.

**Live dispatch is different.** `Request#controller_class_for` raises `ActionDispatch::MissingController` (a `NameError`). `Dispatcher#serve` does not rewrite that. `test_route_error_with_missing_controller` uses `request_path_params` (full `routes.call`), so it expects `MissingController` / `uninitialized constant DoesNotExistsController`, not the `"A route matches"` RoutingError. `recognize_path` never surfaces `MissingController`; it always wraps it.

Engines recurse with `raise_on_missing: false` so a mount that doesn’t match internally falls through. Redirects and bare Rack apps are skipped (`dispatcher?`/`engine?` false) and do not count as a recognition. Lazy route sets only reload then `super` ([`railties/lib/rails/engine/lazy_route_set.rb`](railties/lib/rails/engine/lazy_route_set.rb)).

### Edge-case results

| Input / situation | Observable |
|---|---|
| `"/pages/show/10/"` | Same params as without slash (normalize) |
| `"http://host/page/x"` | Host/scheme on `req`; path from URI; no normalize |
| `"/foo?bar=1"` | Match on `/foo`; `bar` not in return value unless `extras:` |
| `extras: { page: "1" }` | Merged into returned path params |
| Bad URI | `RoutingError` with `URI::InvalidURIError` message |
| Wrong HTTP verb | `RoutingError` `"No route matches …"` |
| Unknown verb (`:bacon`) | `UnknownHttpMethod` when `request_method` is read |
| Encoded segment `%20` / `%0A` / `%3F` | Decoded in params; `+` remains `+` |
| No route | `RoutingError` `"No route matches #{path.inspect}"` |
| Route matches, controller missing (`recognize_path`) | `RoutingError` `"A route matches … missing controller: XController"` |
| Same, live `Dispatcher#serve` | `ActionDispatch::MissingController` |
| Engine miss | Continue; maybe later `"No route matches"` |
