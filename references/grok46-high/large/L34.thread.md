`retry_on` is a `rescue_from` wrapper. Matching uses Rescuable’s reverse handler list (`klass === exception`, cause fallback). One declaration shares one counter; separate declarations do not. Below the attempt limit it reports (if requested) and re-enqueues via `retry_job`; at exhaustion it runs `retry_stopped` + `after_discard`, then either the block or `raise error`.
