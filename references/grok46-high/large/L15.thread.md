### Query-cache clearing

The first statement is `self.class.connection_pool.clear_query_cache`. That drops the pool’s per-thread SQL cache so the subsequent SELECT cannot reuse a stale result.

[`test_reload_via_querycache`](activerecord/test/cases/persistence_test.rb) covers this: enable cache, `find` (cache the row), update the row inside `uncached`, then `reload` sees `"Mary"` from the database rather than the cached `"Shane"`.

### Scoped vs unscoped lookup, including `all_queries: true`

`apply_scoping?` is true only when `options[:unscoped]` is not set **and** the model has a default scope with `all_queries: true` **or** a `global_current_scope`:

```858:861:activerecord/lib/active_record/persistence.rb
      def apply_scoping?(options)
        !(options && options[:unscoped]) &&
          (self.class.default_scopes?(all_queries: true) || self.class.global_current_scope)
      end
```

When it is true, `_find_record` is called with `all_queries: true`, which uses `all_queries_scope` (those default scopes plus `global_current_scope`). When it is false, the lookup runs inside `self.class.unscoped`.

Ordinary `default_scope` (no `all_queries: true`) does **not** apply to reload. `test_default_scope_doesnt_run_on_reload` asserts the SQL has no `mentor_id`. `test_default_scope_with_all_queries_runs_on_reload` asserts it does.

`reload(unscoped: true)` skips scoping even for `all_queries: true` default scopes.

`Model.where(...).scoping` (without `all_queries: true`) sets only `current_scope`, not `global_current_scope`, so reload ignores it. `scoping(all_queries: true)` sets `global_current_scope` and the extra WHERE is merged.

`_find_record` looks up by `_in_memory_query_constraints_hash` (primary key, or `query_constraints` columns from in-memory attributes). Optional `:lock` adds `SELECT ... FOR UPDATE`.

### Association cache replacement and owner rebinding

`@association_cache` is not reset in place. It is replaced with the fresh record’s cache, then each association’s `owner` is set to `self`.

The fresh record is a newly instantiated row. Its cache is empty unless `_find_record` preloaded `strict_loaded_associations` (already-cached associations whose owner is `strict_loading?` and not n+1-only). That is what `test_strict_loading_has_one_reload` relies on.

For a normal already-loaded association whose DB contents changed: after reload the old association objects are gone from this record’s cache. The next accessor hits the database. Holding an old child object does not keep it attached.

`test_reload_sets_correct_owner_for_association_cache` is the owner-rebinding case: `Publication`’s `after_initialize` puts an association on the fresh object; without `owner = self`, a later `save` would touch the discarded fresh instance.

### Persistence and mutation-tracker reset

After a successful find:

- `@attributes` is the fresh record’s attribute set (unsaved in-memory writes discarded)
- `@new_record = false`, `@previously_new_record = false`
- Dirty then nils `@mutations_before_last_save` and `@mutations_from_database`

`changed?` / `changes` rebuild from a new `AttributeMutationTracker` on the replaced attributes. `saved_changes` / `previous_changes` rebuild from `NullMutationTracker` (`mutations_before_last_save` defaults to that when nil).

Autosave also clears `@marked_for_destruction` and `@destroyed_by_association` before `super`.

| Row hidden by ordinary default scope | Yes, unscoped SELECT | No | Same object | Found; ordinary default scope is not applied |
| Same row vs `default_scope ..., all_queries: true` | Yes, scoped SELECT | `RecordNotFound` if the row no longer matches | Unchanged (exception before swap) | Unchanged |
| Explicit `reload(unscoped: true)` with an `all_queries` default scope | Yes, unscoped SELECT | No if the row exists | Same object | Reloaded |
| `scoping` without `all_queries: true` | Yes, unscoped (ignores current_scope) | No | Same object | Reloaded |
| `scoping(all_queries: true)` that hides the row | Yes, scoped SELECT | `RecordNotFound` | Unchanged | Unchanged |
| Deleted row | Yes, SELECT | `RecordNotFound` (`deleted_post.reload` in `delete_all_test`) | Unchanged | Unchanged |
| Already-loaded association whose DB contents changed | Yes, SELECT for the owner; association not refreshed in place | No | Same owner object | `@association_cache` replaced (usually emptied); next association access queries |

`test_find_via_reload` is the identity/persistence reset: `Post.new; post.id = 1; post.reload` keeps the same object, loads the row, and `new_record?` becomes false.
