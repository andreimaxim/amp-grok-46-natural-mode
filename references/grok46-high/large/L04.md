`Array#extract_options!` is the splat-args convention for “optional trailing kwargs as a Hash.” It lives in [`activesupport/lib/active_support/core_ext/array/extract_options.rb`](activesupport/lib/active_support/core_ext/array/extract_options.rb). The contract is:

```ruby
def extract_options!
  if last.is_a?(Hash) && last.extractable_options?
    pop
  else
    {}
  end
end
```

**Trailing-only.** Only `last` is inspected. There is no scan, no `rindex`, no walk of earlier elements. If the last element is not an extractable hash, the method does nothing to the array and returns `{}`.

**`Hash#extractable_options?` vs subclasses.** The Hash method is `instance_of?(Hash)`, not `is_a?(Hash)`. A plain `Hash` (including a keyword-splat `{a: :b}`) is extractable. A `Hash` subclass is not, even though `last.is_a?(Hash)` is true. That second check is the gate: `is_a?(Hash)` only gets you into the predicate; `extractable_options?` decides whether it is an options hash or a positional Hash-like value.

**Subclass opt-in.** A subclass becomes extractable by overriding `extractable_options?` to return true. Rails does this for `ActiveSupport::HashWithIndifferentAccess`, `ActiveSupport::OrderedOptions`, and `ActiveSupport::OrderedHash`. The tests also cover a local `ExtractableHashSubclass`. A bare `Hash` subclass without the override stays positional.

**Receiver mutation.** Bang is literal. On a hit it `pop`s: the same object is returned, and it is no longer in the receiver. On a miss the receiver is unchanged.

**Return value when nothing qualifies.** Always a new empty Hash `{}`. That covers empty array, last element not a Hash, and last element a Hash that is not extractable. Callers can write `options = args.extract_options!` without a nil check.

**Why an earlier hash stays positional.** Because only the last slot is the options slot. `[hash, 1].extract_options!` returns `{}` and leaves `hash` in the array. Same for `[opts, other_opts]` if `other_opts` is not extractable: `opts` is not considered. That is what lets APIs mix a positional Hash (attributes, record, query, etc.) with a trailing options Hash, and what keeps Hash subclasses used as values from being stolen as options.

Evidence from [`activesupport/test/core_ext/array/extract_options_test.rb`](activesupport/test/core_ext/array/extract_options_test.rb):

- `[].extract_options!` and `[1].extract_options!` → `{}`
- `[{ a: :b }]` and `[1, { a: :b }]` → `{ a: :b }`, array popped
- `[HashSubclass.new]` → `{}`, array unchanged
- `[ExtractableHashSubclass.new]` / HWIA / OrderedOptions → extracted and popped
