## `Object#with` control flow (Active Support)

Implementation: [`activesupport/lib/active_support/core_ext/object/with.rb`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb). Tests: [`activesupport/test/core_ext/object/with_test.rb`](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb).

### Algorithm

```ruby
def with(**attributes)
  old_values = {}
  begin
    attributes.each do |key, value|
      old_values[key] = public_send(key)
      public_send("#{key}=", value)
    end
    yield self
  ensure
    old_values.each do |key, old_value|
      public_send("#{key}=", old_value)
    end
  end
end
```

([`with.rb` lines 31–44](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L31-L44))

It is per-attribute read-then-assign, not read-all-then-assign-all. Keyword-argument order is preserved, so `old_values` is filled in call order and later restored in that same order.

For `obj.with(a: 1, b: 2)`:

1. `old_values[:a] = obj.public_send(:a)`
2. `obj.public_send("a=", 1)`
3. `old_values[:b] = obj.public_send(:b)`
4. `obj.public_send("b=", 2)`
5. `yield self`
6. `ensure`: `a=` old, then `b=` old

A later attribute’s old value is not snapshotted until the previous attribute’s writer has already run.

### Block: receiver in, block value out

`yield self` ([line 38](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L38)) yields the receiver. The `begin`/`ensure` expression’s value is the block’s value; `ensure` does not override it unless it raises.

### `ensure` when the block raises

`ensure` always iterates `old_values` and writes each stored old value back with `public_send("#{key}=", old_value)` ([lines 39–42](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L39-L42)). If that restore does not raise, the original exception is re-raised.

[`restore attribute if the block raised`](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L45-L59): both writers succeed, the block raises `"Oops"`, both attributes return to `:public` and `:another_public`, and `RuntimeError` still propagates.

### Two attributes: first writer succeeds, second writer raises

Fixture ([`Record` 7–26](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L7-L26)):

- `public_attr` — public reader and writer, initial `:public`
- `mixed_attr` — public reader, **private** writer, initial `:mixed`

Call: `@object.with(public_attr: :changed, mixed_attr: :changed_too)` ([`with_test.rb` 61–73](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L61-L73)).

Exact sequence:

1. `old_values[:public_attr] = :public` (public reader)
2. `public_attr = :changed` succeeds — object now has `public_attr == :changed`
3. `old_values[:mixed_attr] = :mixed` (public reader still works)
4. `public_send("mixed_attr=", :changed_too)` raises `NoMethodError` (private writer)
5. `yield` never runs (`assert false` in the test block would fail if it did)
6. `ensure` sees `old_values == { public_attr: :public, mixed_attr: :mixed }` because the second **read** happened before the second **write** failed

What is restored:

- `public_attr` **is** restored to `:public` (first `ensure` write).
- `mixed_attr` **never changed**; `public_send` of a private writer does not invoke it. It stays `:mixed`.
- The second `ensure` write, `public_send("mixed_attr=", :mixed)`, **also** raises `NoMethodError` for the same private-writer reason.

So the only successful restore is `public_attr`. `mixed_attr` is unchanged, not successfully rewritten. The `NoMethodError` the test observes can come from the failed assignment **or** from the failed restore of `mixed_attr` (if `ensure` raises, that exception is the one that propagates). Final state asserted by the test: both attributes at originals, block body not entered.

Restoration is only for keys actually inserted into `old_values`. If the second **reader** raised instead of the writer, `mixed_attr` would not be in `old_values` and `ensure` would restore only `public_attr`. The test covers the setter-raises case, not the reader-raises case.

### Public reader and public writer

Both the snapshot and the assignment use `public_send` ([lines 35–36, 41](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L35-L41)). The comment at [lines 29–30](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L29-L30) states the method works only when both reader and writer are public.

[`only works with public attributes`](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L75-L89):

- private reader+writer (`private_attr`) → `NoMethodError`
- protected reader+writer (`protected_attr`) → `NoMethodError`
- public reader + private writer (`mixed_attr`) → `NoMethodError` on the writer; `mixed_attr` remains `:mixed`

A public reader is not enough.

### Unavailable on immediate classes

After defining `Object#with`, the method is undefined on the common immediate classes ([lines 47–51](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L47-L51)):

`NilClass`, `TrueClass`, `FalseClass`, `Integer`, `Float`, `Symbol`

Comment: `#with isn't usable on immediates, so we might as well undefine the method in common immediate classes to avoid potential confusion.`

[`basic immediates don't respond to #with`](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L100-L107) asserts `nil`, `true`, `false`, `1`, `1.0`, and `:sym` do not respond to `#with`. `String` is not in that list.
