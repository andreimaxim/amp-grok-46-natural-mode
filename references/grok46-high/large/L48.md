## Behavior-preservation verification for `rails/test_help`

Reorganizing [`railties/lib/rails/test_help.rb`](railties/lib/rails/test_help.rb) is not a file-structure change. `require "rails/test_help"` has process-global effects: production abort, eager requires, `defined?(ActiveRecord::Base)` branching at require time, `ActiveSupport.on_load` hooks that are **not** `run_once`, class-attribute writes, `before_setup` definitions, autorun, and schema maintenance. A split/extract can change timing, inheritance, idempotency, or path representation without a failing unit assertion on class variables.

There is currently **no** railties test that asserts the default `fixture_paths` / `file_fixture_path` assignment from this file. Existing coverage only exercises neighboring behavior.

### 1. Current observable contract (from source)

Generated apps always boot first, then require this file:

```ruby
## railties/lib/rails/generators/rails/app/templates/test/test_helper.rb.tt
ENV["RAILS_ENV"] ||= "test"
require_relative "../config/environment"
require "rails/test_help"
```

So in the normal path, `ActiveSupport::TestCase`, `ActionDispatch::IntegrationTest`, and `ActionController::TestCase` are already loaded; the `on_load` hooks run **immediately**.

#### Require-time (always)

From [`railties/lib/rails/test_help.rb`](railties/lib/rails/test_help.rb):

1. `abort("Abort testing: Your Rails environment is running in production mode!")` if `Rails.env.production?`.
2. `require "active_support/test_case"`.
3. `require "rails/generators/test_case"` (loads generator test helpers).
4. `require "active_support/testing/autorun"` (`Minitest.autorun`).
5. `require "rails/testing/maintain_test_schema"` — if AR is defined, calls `ActiveRecord::Migration.maintain_test_schema!` and may `exit 1` on pending migrations ([`railties/lib/rails/testing/maintain_test_schema.rb`](railties/lib/rails/testing/maintain_test_schema.rb)).
6. AR presence is `defined?(ActiveRecord::Base)` **at require time**, not inside the hooks.

#### With Active Record

```ruby
require "active_record/testing/query_assertions"
ActiveSupport.on_load(:active_support_test_case) do
  include ActiveRecord::TestDatabases
  include ActiveRecord::TestFixtures
  include ActiveRecord::Assertions::QueryAssertions

  self.fixture_paths = [*self.fixture_paths, "#{Rails.root}/test/fixtures/"].uniq
  self.file_fixture_path = "#{Rails.root}/test/fixtures/files"
end

ActiveSupport.on_load(:action_dispatch_integration_test) do
  self.fixture_paths += ActiveSupport::TestCase.fixture_paths
end
```

Observable effects:

- `ActiveSupport::TestCase` gains fixtures (`fixtures :all`, YAML accessors, transactional tests), query assertions (`assert_queries_count`, `assert_no_queries`, …), and parallel-test DB hooks (registered when `active_record/test_databases.rb` is autoloaded; `include` adds the ancestor).
- Including `TestFixtures` runs `ActiveSupport.run_load_hooks(:active_record_fixtures, self)` ([`activerecord/lib/active_record/test_fixtures.rb`](activerecord/lib/active_record/test_fixtures.rb) line 41). Engine initializer `:add_fixture_paths` already registered `self.fixture_paths |= ["#{fixtures}/"]` during boot ([`railties/lib/rails/engine.rb`](railties/lib/rails/engine.rb) 655–661). Those engine paths are therefore present **before** the default app path is appended.
- Default fixture path is an **absolute String with a trailing slash**: `"#{Rails.root}/test/fixtures/"`.
- Default file-fixture path is an **absolute String with no trailing slash**: `"#{Rails.root}/test/fixtures/files"`.
- `Array#uniq` is equality-based: identical strings are dropped; a relative and absolute form of the same directory are **not** dropped.
- The IntegrationTest copy is `+=` **without** `uniq`. Because `IntegrationTest < ActiveSupport::TestCase` and has not assigned `fixture_paths` yet, this assigns `inherited + ASTC.fixture_paths`, so the default path (and engine paths) appear **twice** on `ActionDispatch::IntegrationTest`. Existing behavior to preserve, not a bug to fix.
- Missing `test/fixtures` does not fail at require time; `Dir[]` in `fixtures :all` returns `[]`.

#### Without Active Record

Only:

```ruby
ActiveSupport.on_load(:active_support_test_case) do
  self.file_fixture_path = "#{Rails.root}/test/fixtures/files"
end
```

No `fixture_paths`, no `TestFixtures` / `QueryAssertions` / `TestDatabases`, no IntegrationTest fixture-path copy. `file_fixture` still works. Generated `--skip-active-record` helpers omit `fixtures :all` ([`railties/test/generators/shared_generator_tests.rb`](railties/test/generators/shared_generator_tests.rb)).

#### Always, after the AR branch

```ruby
ActiveSupport.on_load(:action_controller_test_case) do
  def before_setup
    @routes = Rails.application.routes
    super
  end
end

ActiveSupport.on_load(:action_dispatch_integration_test) do
  def before_setup
    @routes = Rails.application.routes
    super
  end
end
```

These `def` on the test class itself, not a prepended module. For an `ActionDispatch::IntegrationTest` instance the super-chain is:

1. `IntegrationTest#before_setup` (this file) — `@routes = Rails.application.routes` **at test time**
2. `ActiveSupport::Testing::SetupAndTeardown#before_setup` (prepended on `ActiveSupport::TestCase`)
3. `ActiveRecord::TestFixtures#before_setup` (included on ASTC, AR only)
4. Minitest

Moving this to `include`/`prepend` changes lookup order. `@routes` must follow the **current** `Rails.application`, not the application that was current at require time.

#### Hook / require semantics ([`activesupport/lib/active_support/lazy_load_hooks.rb`](activesupport/lib/active_support/lazy_load_hooks.rb))

- Hooks are not `run_once`.
- Repeated `require "rails/test_help"` is a no-op (`$LOADED_FEATURES`).
- `load "rails/test_help.rb"` re-registers and re-runs: ASTC `uniq` assignment stays stable; IntegrationTest `+=` **duplicates again**; `before_setup` is redefined identically.
- `#{Rails.root}` is interpolated when the hook **runs**, not when it is registered. After the first immediate run, later `Rails.root` changes do not rewrite paths unless hooks run again.

#### Inheritance (`class_attribute`)

`fixture_paths` and `file_fixture_path` are `class_attribute`s ([`activerecord/lib/active_record/test_fixtures.rb`](activerecord/lib/active_record/test_fixtures.rb), [`activesupport/lib/active_support/testing/file_fixtures.rb`](activesupport/lib/active_support/testing/file_fixtures.rb)).

- Subclass that **assigns** keeps its own value; parent writes do not clobber it.
- Subclass that does **not** assign inherits the parent value (same object until `+=`/`=`).
- **Precision vs a simplified “pre-require fixture_paths override” story:** before `test_help`, vanilla ASTC has `file_fixture_path` (FileFixtures is always included) but **not** `fixture_paths` (that is born when TestFixtures is included). A pre-require subclass can authoritatively override `file_fixture_path`. It can override `fixture_paths` only if TestFixtures is already included (unusual). Extra paths already on ASTC at hook time are preserved by `[*self.fixture_paths, default].uniq`.
- Plugin helpers assign **after** require and must still win:

```ruby
## railties/lib/rails/generators/rails/plugin/templates/test/test_helper.rb.tt
ActiveSupport::TestCase.fixture_paths = [ File.expand_path("fixtures", __dir__) ]
ActionDispatch::IntegrationTest.fixture_paths = ActiveSupport::TestCase.fixture_paths
ActiveSupport::TestCase.file_fixture_path = File.expand_path("fixtures", __dir__) + "/files"
```

### 2. Preservation traps (what a reorganization silently breaks)

| Trap | Why it hides |
|---|---|
| Hook moved behind `run_once` | Second `load` or a late-loaded IntegrationTest subclass stops getting paths/`before_setup`. |
| `defined?(ActiveRecord::Base)` moved into the hook | Skip-AR apps that later autoload AR would pick up fixtures/query assertions the old file never installed. |
| `uniq` added to IntegrationTest `+=` | Duplicate entries disappear; `fixtures :all` still works (it `uniq`s names), so only array inspection catches it. |
| Path built with `Rails.root.join(...)` / Pathname / no trailing slash | String equality and `file_fixture_path.to_s` prefix rejection in `fixtures :all` change. |
| `#{Rails.root}` captured at file load rather than hook run | Wrong if hooks are delayed until class load. |
| `before_setup` extracted to a prepended module | Super-chain vs SetupAndTeardown / TestFixtures changes; `@routes` may be set too late/early. |
| Engine `:active_record_fixtures` hook runs after default path assignment | Engine paths dropped or ordered differently; `uniq`/`|=` interaction changes. |
| In-process class-variable tests in the railties suite | Parent process already loaded test_help / ASTC / AR; `$LOADED_FEATURES` and load-hook registries hide regressions. |

### 3. Black-box verification strategy

Do **not** assert this contract inside the railties process. Drive a generated app, run `bin/rails test` (or `rails "test", ...`) in that app, and assert through **fixture load, `file_fixture` / `fixture_file_upload`, integration GET/POST, and query assertions**.

Place new coverage in `railties/test/application/test_help_test.rb`, modeled on [`railties/test/application/test_test.rb`](railties/test/application/test_test.rb): `ActiveSupport::Testing::Isolation`, `build_app` / `teardown_app`, `PARALLEL_WORKERS=0`, `assert_successful_test_run` via `rails "test", "#{app_path}/test/..."`.

Each scenario writes a tiny app test whose assertions **are** the preservation checks.

#### Scenario matrix

**A. Default AR app (happy path)**  
Model + YAML fixture `test/fixtures/users.yml`, file `test/fixtures/files/hello.txt`, route + controller that reads `users(:one).name` and an uploaded file.

In `ActiveSupport::TestCase`:
- `users(:one)` returns the record (YAML fixture path works, including trailing slash).
- `file_fixture("hello.txt").read` equals file contents (no trailing slash on the directory).
- `assert_queries_count` around `User.count` succeeds (QueryAssertions included).
- `fixtures :all` does not treat `test/fixtures/files/*` as a fixture set (`file_fixture_path` prefix skip in TestFixtures).

In `ActionDispatch::IntegrationTest`:
- `get "/users"` uses `@routes = Rails.application.routes` (success, body assertion).
- `users(:one)` still resolves (copied fixture paths, even with duplicates).
- `fixture_file_upload("hello.txt")` succeeds (`file_fixture_path` inherited; [`actionpack/lib/action_dispatch/testing/test_process.rb`](actionpack/lib/action_dispatch/testing/test_process.rb)).

Optional narrow exception to black-box: one assertion that `ActionDispatch::IntegrationTest.fixture_paths` contains the default path twice and `ActiveSupport::TestCase.fixture_paths` contains it once. Duplicate entries are otherwise invisible because `fixtures :all` uniqs names.

**B. Relative extra path**  
After require, `ActiveSupport::TestCase.fixture_paths << "test/extra_fixtures"` (relative) with `test/extra_fixtures/posts.yml`. `posts(:one)` loads. Confirms splat-preserve of non-absolute entries and that `uniq` does not collapse relative vs `"#{Rails.root}/test/fixtures/"`.

**C. Absolute extra path**  
`<< "#{Rails.root}/tmp/more_fixtures/"` (trailing slash, absolute). Same observable load.

**D. Duplicate extra path identical to default**  
`fixture_paths << "#{Rails.root}/test/fixtures/"`. ASTC remains uniq’d (one entry); IntegrationTest `+=` still duplicates. Fixtures still load once.

**E. Missing fixture directory**  
Delete `test/fixtures` (or never create it). Require must not abort. A test that only uses `file_fixture` / a plain assertion passes. `fixtures :all` with empty dirs must not raise `No fixture path found` (paths are set, just empty). A named `users(:one)` should fail at test time, not at require time.

**F. Subclass defined before `require "rails/test_help"`**  
Rewrite the executed file so environment is loaded, then:

```ruby
class PreRequireFileFixtureTest < ActiveSupport::TestCase
  self.file_fixture_path = "#{Rails.root}/tmp/pre_files"
end
require "rails/test_help"

class PostRequireTest < ActiveSupport::TestCase; end
```

- Pre-require class: `file_fixture("x")` reads from `tmp/pre_files`, **not** `test/fixtures/files`.
- Post-require class: default `test/fixtures/files`.
- Post-require class loads YAML from default fixture path.
- An `ActionDispatch::IntegrationTest` subclass defined before require still gets `@routes` via inherited `before_setup` (integration GET works). If that subclass defines its own `before_setup` without `super`, routes will **not** be set — preserve that too.

**G. Subclass defined after require with override**  
`self.fixture_paths = [custom]` / `self.file_fixture_path = custom` after require: only that class uses custom paths; siblings still use defaults. Matches plugin helper overwrite-wins.

**H. Repeated `require "rails/test_help"`**  
In the app test helper, `2.times { require "rails/test_help" }`. Fixtures, file fixtures, integration GET, query assertions still pass; ASTC default path still appears once.

**I. Application-configured extra paths (engines)**  
Mount a dummy engine with `test/fixtures/bukkits.yml` under a path that satisfies `fixtures_in_root_and_not_in_vendor_or_dot_dir?`. After boot + test_help, `bukkits(:one)` loads in both ASTC and IntegrationTest. This is the live version of [`railties/test/railties/engine_test.rb`](railties/test/railties/engine_test.rb) “adds its fixtures path to fixture_paths”, which today only runs `run_load_hooks(:active_record_fixtures)` on a stub class — it does **not** prove test_help’s later `[*paths, default].uniq` kept the engine path.

Also: an initializer that, at boot, does `ActiveSupport.on_load(:active_support_test_case) { self.fixture_paths = ["#{Rails.root}/tmp/init_fixtures/"] }` (ASTC already loaded, so this runs **before** test_help). After test_help, both init fixtures and default app fixtures must load.

**J. Active Record absent**  
`use_frameworks` without `:activerecord`, or comment out `active_record/railtie` like `--skip-active-record`. Assertions:
- `file_fixture("hello.txt")` works.
- `ActiveSupport::TestCase.respond_to?(:fixture_paths)` is false (or calling `fixtures :all` / `users(:one)` raises).
- `assert_queries_count` is not defined.
- Integration GET still works (`before_setup` routes are outside the AR branch).
- Require does not load `maintain_test_schema` AR work (no pending-migration abort).

**K. Multiple boots in one process**  
A runner script inside the generated app (not the railties process):
1. Boot app A, `require "rails/test_help"`, capture `ActiveSupport::TestCase.file_fixture_path` and succeed `file_fixture`.
2. Point `Rails.application` at app B with different `Rails.root` / routes (or `Rails.application = Class.new(Rails::Application).instance` + load routes).
3. Assert path strings are **still app A’s root** (hooks already ran).
4. Run an IntegrationTest (or call `before_setup`) and assert `@routes` / `get` follows **app B**.

Isolation already forks per test, but this scenario must stay in **one** child process.

**L. Production abort**  
`RAILS_ENV=production` + require test_help in a subprocess: abort message, non-zero status, no fixture assignment.

**M. `before_setup` super-chain**  
Controller test that uses named routes; integration test that uses fixtures **and** `get`. If `super` is dropped, either fixtures or Minitest setup breaks. If `@routes` is not set, `get` / named-route helpers fail. This is the observable stand-in for ancestor-chain inspection.

### 4. Isolation / cleanup (or regressions hide)

`test_help.rb` mutates global load-hook tables, `$LOADED_FEATURES`, ASTC/IntegrationTest class attributes, Minitest autorun, and AR schema state. In-process assertions against the railties suite are unsafe.

Required:
- `include ActiveSupport::Testing::Isolation` so each test forks (see [`activesupport/lib/active_support/testing/isolation.rb`](activesupport/lib/active_support/testing/isolation.rb)).
- `build_app` / `teardown_app` from [`railties/test/isolation/abstract_unit.rb`](railties/test/isolation/abstract_unit.rb); teardown restores `Rails.application`, `Rails.app_class`, `RAILS_ENV`, and `rm_rf` the tmp app.
- `ENV["PARALLEL_WORKERS"] = "0"` in setup (restore in teardown), as in `test_test.rb` — generated helpers call `parallelize`, which otherwise forks inside the already-forked isolation process and hides failures.
- Never `require "rails/test_help"` in the railties test process. Always `rails "test", ...` (or a `ruby -Itest` child) against the generated app.
- Do not leave extra `on_load` hooks registered on the parent; Isolation fork prevents that if you do not require test_help in setup.
- For AR schema scenarios, let `maintain_test_schema` run as it does today (`test_test.rb` already covers pending migrations). New tests should `rails("db:migrate")` / write `db/schema.rb` so schema maintenance is not a false failure.
- Skip-AR tests must not rely on `app_template` still having `config.active_record.*` lines; use `use_frameworks` / commented railtie like the generators.
- Engine-path tests must satisfy `fixtures.exist? && fixtures.to_s.start_with?(Rails.root.to_s)` and not live under `vendor/` or `#{Rails.root}/.`.
- Repeated-require tests must use `require`, not `load`, unless the point is re-hook duplication.

These do **not** replace the new file; they catch collateral damage (schema abort, integration boot, runner, generator templates, engine hook registration).

- [`railties/test/application/integration_test_case_test.rb`](railties/test/application/integration_test_case_test.rb) — IntegrationTest app/routes/mailer reset.

- Generator tests — `test_helper.rb` still `require "rails/test_help"`; skip-AR omits `fixtures :all`; plugins still overwrite paths after require.
- [`railties/test/application/active_storage/*`](railties/test/application/active_storage) — `file_fixture`, but they **set** `file_fixture_path` themselves, so they do not prove test_help’s default.

### 6. What “pass” means

A reorganization is behavior-preserving iff every scenario above still passes **without** changing assertions about path string shape, IntegrationTest duplication, pre-require `file_fixture_path` overrides, post-require overwrites, skip-AR absence of fixtures/query assertions, production abort, or `@routes` following the current application after a second boot.

Do not “fix” IntegrationTest duplicates, trailing slashes, or hook immediacy as part of the reorganization; those are the public effects.
