`LookupContext` holds the request’s view paths and mutable lookup details. It does not search the filesystem. `#find` / `#find_all` normalize the name, intern a cache key from those details, then ask `PathSet`, which walks resolvers until one returns a match. The resolver scores candidate files against `TemplateDetails::Requested` and binds locals last.

```text
LookupContext#find / #find_all / #find!
  normalize_name(name, prefixes)
  detail_args_for(options)  →  [details Hash, details_key or nil]
    PathSet#find / #find_all / #find!
      for each prefix, for each resolver:
        FileSystemResolver#find / #find_all
          requested = details_key || TemplateDetails::Requested.new(**details)
          unbound_templates_for(virtual_path, cached: !!details_key)
          match + rank by TemplateDetails
          UnboundTemplate#bind_locals(locals)
```

### `#find` vs `#find_all`

Both start the same way in [`lookup_context.rb`](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb):

1. `normalize_name` splits a `"dir/name"` into a basename plus prefixes (`"users/show"` with prefixes `["admin"]` becomes name `"show"`, prefixes `["admin/users"]`). A name with no slash keeps the given prefixes, or `[""]` if they are blank.
2. `detail_args_for(options)` returns `@details` and the interned `details_key` when `options` is empty. Otherwise it merges render options into a new details hash and, if caching is on, interns a new key for that hash. Per-call options **do not** go through `formats=` / `locale=`, so they skip JS→HTML fallback and format validation.
3. The pair is forwarded to `@view_paths`.

[`PathSet`](file:///home/user/workspace/repo/actionview/lib/action_view/path_set.rb) searches **prefix-outer, resolver-inner**. It does not merge hits across prefixes or resolvers:

- `#find` returns the first resolver’s first matching template, or `nil`.
- `#find!` is `#find` or `ActionView::MissingTemplate` ([`error.rb`](file:///home/user/workspace/repo/actionview/lib/action_view/template/error.rb)). A partial rewrites the basename with a leading `_` in the message (`parent/_foo, child/_foo`).
- `#find_all` returns **all** matches from the first prefix+resolver that returns a non-empty list, or `[]`. Later prefixes/resolvers are skipped.

`FileSystemResolver#find` is “best one”; `#find_all` is “every match, sorted”.

### Mutable details vs cache keys

Registered details live in a mutable `@details` hash. Generated setters wrap the value in `Array(...)`, or restore the detail’s default proc when the value is blank ([`register_detail`](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb)). Changing a detail copy-on-writes `@details` if a key was already computed, then nils `@details_key` and `@digest_cache`.

`details_key` is **not** that hash. When `@cache` is true it is an interned `TemplateDetails::Requested` from `DetailsKey.details_cache_key(@details)`:

- Interning is by hash contents, so `locale = :da` then back to `:en` reuses the original key object ([`lookup_context_test.rb`](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb) “generates a new details key…”).
- `Requested` builds an index hash `[*array, nil] → position`. `nil` (file omitted that detail) always matches and ranks last.
- If the formats list is not all valid `Template::Types` symbols, the **key** is interned with `formats & Types.symbols` (invalids dropped). Assignment validation is separate; this only affects cache identity ([`Template.normalized_formats`](file:///home/user/workspace/repo/actionview/lib/action_view/template.rb)).
- `details_key` is omitted entirely when `@cache` is false (`disable_cache`).

So: `@details` is the live request state; `details_key` is an immutable ranking object plus a resolver cache flag (`!!key`).

### Format / locale / variant normalization

`formats=` is special-cased before the generated setter:

1. Dup the array.
2. If it contains `"*/*"` **or** `Mime::ALL` (AllType’s `==` matches `"*/*"`), delete that entry and append `default_formats` (`Mime.symbols` when Action Dispatch is loaded).
3. `uniq!`, then `Template.validate_formats`.
4. Only if the result is exactly `[:js]`, append `:html` and set `@html_fallback_for_js = true`.
5. `super` writes the array. `formats = nil` skips the override body and the generated setter restores `default_formats`.

`locale` reads `@details[:locale].first`. `locale=` writes `I18n.config.locale`, then stores the default locale proc: `[I18n.locale] + fallbacks + I18n.default_locale`, uniqued. Fallbacks earlier in that array rank higher.

`variants = :any` is not a setter path used by `formats=`; it is passed as a requested detail (`detail_args_for_any`, or resolver calls). `Requested` then uses `ANY_HASH` (`nil => 0`, everything else `1`).

### Resolver matching

[`FileSystemResolver`](file:///home/user/workspace/repo/actionview/lib/action_view/template/resolver.rb) globs `prefix/name*` (or `prefix/_name*` for partials), parses `locale.format+variant.handler`, and keeps files whose virtual path matches exactly (case-sensitive). A name containing `.` returns no files (`find_all("hello_world.html")` → `[]`).

A candidate matches when every present detail is in the requested index. Rank / sort key is `[format, locale, variant, handler]` — lower index wins, which is **requested-list order**. `#find` picks the minimum rank; `#find_all` stable-sorts by that key.

`UnboundTemplate#bind_locals` does not change which file was selected. Locals are sorted symbols. Non-strict templates get one `Template` per locals set; strict-locals templates (`<%# locals: (...) %>`) bind once and reuse that object for any locals list.

Cache-on (`details_key` present): unbound templates are stored per virtual path; repeated finds return the same `Template` object, even across different requested locales that still match the same file.

Cache-off (`disable_cache` / `key == nil`): the directory is scanned again; new `UnboundTemplate` / `Template` objects are built. The virtual-path cache is not cleared.

### Edge cases and observable results

**`formats = [:js]`**  
Stored details become `[:js, :html]`. `@html_fallback_for_js` becomes true (and is never reset). `#find` can select an HTML template when no JS file exists. Test: “adds :html fallback to :js formats”.

**`formats = [:js, Mime::ALL]`** (explicit `*/*`)  
`Mime::ALL` is treated as `"*/*"`, removed, and `default_formats` / `Mime.symbols` are appended. Result: `[:js, *Mime.symbols].uniq`. Length is no longer 1, so the extra JS-only HTML append does not run (HTML is already in `Mime.symbols`). Test: “handles explicitly defined */* formats fallback to :js”.

**`formats = ["*/*"]`**  
Replaced by `Mime.symbols` (or `default_formats`). Test: “handles */* formats”.

**Invalid formats on assignment**  
`formats = [:html, :invalid, "also bad"]` raises `ArgumentError` with `Invalid formats: :invalid, "also bad"` **before** `@details` changes. No template is selected. Test: “raises on invalid format assignment”.  
Per-call `find(..., formats: ...)` skips this setter, so it does not raise; a bad symbol is only dropped from the interned key via `normalized_formats`.

**Locale ordering**  
Requested `[ :fr ]` with `hello_world.fr.text.erb` + `hello_world.text.erb`: `#find_all` → `[fr, generic]` (generic `locale=nil` ranks after `:fr`); `#find` → fr. Requested `[ :en ]` → only the generic file. Same bound `Template` object is shared for the generic file. Tests: `test_templates_with_optional_locale_shares_common_object`, `test_should_match_locales`. Arbitrary / underscored locales such as `:es_AR` and `:en_customer1` match when present in `I18n.available_locales` (parser includes those strings).

**Variant ordering**  
`#find` with `variants: [:tricorder]` vs `[:lcars]` returns that one file. `#find_all` with `[:tricorder, :lcars]` returns `[tricorder, lcars]`; reversed request reverses the array. `variants: []` matches **only** files with no `+variant`. `variants: :any` matches every variant; no-variant still ranks first (`nil => 0`). Tests: `test_finds_variants_in_order`, `test_should_return_all_variants_for_any`.

**Partial lookup**  
`find("foo", %w(parent child), true)` looks for `parent/_foo`, then `child/_foo` (prefix-major). Success: the matching `_foo` template. Failure of `#find!`: `Missing partial parent/_foo, child/_foo with {details}.` plus `Searched in:`. Test: `TestMissingTemplate`.

**Locals vs selection**  
Locals never change which file wins. They only choose/create the bound `Template`. Same file + same locals + cache on → same object. Same file + different non-strict locals → different objects (`[:post]` vs `[:post, :other]`; order does not matter after sort). Strict locals → one object for `[]` and `[:message]`. Tests: `test_strict_locals_reuses_same_template`, [`file_system_resolver_test.rb`](file:///home/user/workspace/repo/actionview/test/template/file_system_resolver_test.rb) locals cases.

**Cache enabled**  
`details_key` present. Filesystem glob cached per virtual path. `#find` twice → `assert_same`. Changing locale to a file that still matches the same path still returns that object; a locale-specific file (`_foo.da.erb`) is a different template. `disable_cache` inside a block does not drop the existing virtual-path cache.

**Cache disabled**  
`details_key` is `nil`; resolver rescans and builds new template objects (`assert_not_same`). After the block, `@cache` is restored and the next `#find` returns the previously cached object (`assert_same a, c`). Tests: “can disable the cache on demand”, `test_different_templates_when_cache_disabled`.

**Wrong details**  
`hello_world.html.erb` requested as `formats: [:xml]` → `#find_all` returns `[]`; `#find` returns `nil`; `#find!` raises `MissingTemplate`. Missing handler similarly yields empty. Test: `test_doesnt_find_template_with_wrong_details`.

**No extension / optional details**  
A file with no format/locale/variant still matches any requested format/locale/variant list because `nil` is in every index hash. Observable: one template, `format`/`variant` nil. Tests: `test_can_find_with_no_extensions`, `test_templates_no_format_with_variant`.
