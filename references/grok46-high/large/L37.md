**Block.** The claim is false. `enqueue_delivery` still serializes mailer class/action/delivery-method/`@args`, not a generated `Mail::Message`. Dropping the `processed?` guard would silently drop header/body mutations.

`processed?` is true once `#message` or any delegated `Mail::Message` API has run the mailer and built `@mail_message` ([message_delivery.rb L22–L50](file:///home/user/workspace/repo/actionmailer/lib/action_mailer/message_delivery.rb#L22-L50), [L34–L36](file:///home/user/workspace/repo/actionmailer/lib/action_mailer/message_delivery.rb#L34-L36)). The job later re-runs the mailer via [`MailDeliveryJob#perform`](file:///home/user/workspace/repo/actionmailer/lib/action_mailer/mail_delivery_job.rb#L21-L29). Active Job has no `Mail::Message` serializer ([arguments.rb L47–L54](file:///home/user/workspace/repo/activejob/lib/active_job/arguments.rb#L47-L54)); passing one would raise `SerializationError`.

`deliver_later` and `deliver_later!` share this path; they only differ in `deliver_now` vs `deliver_now!` ([L77–L105](file:///home/user/workspace/repo/actionmailer/lib/action_mailer/message_delivery.rb#L77-L105)). Custom `delivery_job` and queue options are unchanged and still get the same tuple, not a message.

Parameterized mail is worse under this patch: processed deliveries `super` and would enqueue **without** `params:` ([parameterized.rb L144–L151](file:///home/user/workspace/repo/actionmailer/lib/action_mailer/parameterized.rb#L144-L151)). After `mail.subject = "Changed"; mail.deliver_later`, the job would send the original subject.

Keep the raise. If the goal is “deliver this mutated message later,” persist the encoded message in a custom job, mutate inside the mailer action, or `deliver_now`. Do not pretend `MailDeliveryJob` already serializes `Mail::Message`.
