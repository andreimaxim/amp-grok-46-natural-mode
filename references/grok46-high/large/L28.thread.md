## Assistant

**Reject.** The claim is false: `safe_concat` is the trusted-append path. Escaping there does not make capture safer; it breaks HTML rendering.

### Contracts (current)

| API | Unsafe `"<x>"` | `html_safe` | `nil` | `OutputBuffer` |
|---|---|---|---|---|
| `OutputBuffer#<<` / `#concat` | escaped (`&lt;x&gt;`) | raw | no-op | `to_s` then raw (already safe) |
| `#safe_concat` / `#safe_append=` | **raw** | raw | `TypeError` | raw `to_s` content |
| `#raw <<` | raw | raw | no-op | raw `to_s` |
| `OutputBuffer#capture` | returns **written** bytes as `html_safe`; **discards** the block return | | | |
| `CaptureHelper#capture` | blank buffer → escape ordinary return; non-blank write wins as `SafeBuffer` | return `SafeBuffer` unchanged | `nil` | if return is the same buffer object, use captured write |

Observed:

- `<< "<script>alert(1)</script>"` → `"&lt;script&gt;alert(1)&lt;/script&gt;"`
- `safe_concat` of that same string → `"<script>alert(1)</script>"` (intentional)
- nested capture that writes `"<em>George</em>"` and returns `"returned"` → `"&lt;em&gt;George&lt;/em&gt;"` (`OutputBuffer#capture` ignores the return)
- `CaptureHelper` return-only `"<em>bar</em>"` → already escaped
- `CaptureHelper` write + return → written (already escaped by `<<`) wins; leftover return is dropped
- `CaptureHelper { nil }` → `nil`
- `safe_concat` of another `OutputBuffer` → its raw contents, mixed escaped/`safe` writes preserved

ERB compiles static HTML as `@output_buffer.safe_append='<div>...'` ([erubi.rb](actionview/lib/action_view/template/handlers/erb/erubi.rb)). `<%= %>` uses `#append=` (`<<`); `<%== %>` uses `#safe_expr_append=`. `cache` restores fragments with `safe_concat(fragment_for(...))`.

### Findings

**1. Critical — inverts the trusted-append contract; every HTML template breaks**

`#safe_concat` / `#safe_append=` exist so already-trusted markup is not escaped. That is documented by [buffers_test.rb](actionview/test/buffers_test.rb):

```ruby
test "#safe_append= bypasses HTML safety"
## "<p>This is fine</p>" must survive unescaped
```

Escaping ordinary strings here turns `<div class="x">` template text into `&lt;div class=&quot;x&quot;&gt;`. `html_safe` inputs still pass (`ERB::Util.html_escape` no-ops them), so the patch only “works” for values already marked safe — which is `#<<`’s job, not `#safe_concat`’s.

**2. Critical — fragment cache and helpers that `safe_concat` HTML**

[`CacheHelper#cache`](actionview/lib/action_view/helpers/cache_helper.rb) does `safe_concat(fragment_for(...))`. Cached HTML is a `String`; after this change it is escaped on restore. Same class of break for `TextHelper#safe_concat` and any helper that `safe_concat`s tags that are not `html_safe?`.

**3. High — capture is already the escaping boundary; this does not close a hole**

[`CaptureHelper#capture`](actionview/lib/action_view/helpers/capture_helper.rb) already:

- prefers written buffer content (which `#<<` already escaped);
- if the buffer is blank, `ERB::Util.html_escape`s an ordinary returned `String`;
- leaves `SafeBuffer` / `OutputBuffer` alone.

[`OutputBuffer#capture`](actionview/lib/action_view/buffers.rb) only snapshots `@raw_buffer` and marks it `html_safe`. It never uses the block return. Escaping inside `#safe_concat` therefore cannot make capture safer. It would **double-escape** trusted writes during capture (`safe_concat("<em>trusted</em>")` today returns `"<em>trusted</em>"`; proposed: `"&lt;em&gt;trusted&lt;/em&gt;"`).

**4. High — `StreamingBuffer` not updated; streaming vs buffered HTML diverge**

[`StreamingBuffer#safe_concat`](actionview/lib/action_view/buffers.rb) still does `@block.call(value.to_s)`. Same template would escape when buffered and not when streaming.

**5. Medium — `nil` and non-String coercion change**

Today `#safe_concat(nil)` is `TypeError` (`String#<<`). `ERB::Util.html_escape(nil)` is `""`. Integers would go through `to_s` instead of `String#<<` codepoints. `#<<` and `#raw <<` still skip `nil`; this would not.

**6. Medium — double-escape of escaped-but-unsafe strings**

`safe_concat("&lt;div&gt;")` today writes those characters. Proposed: `"&amp;lt;div&amp;gt;"`. `html_escape` is idempotent only for `html_safe?` values.

`RawOutputBuffer` is unaffected (no `safe_concat`); that is correct and should stay that way.

### Compatibility / security

This is a compatibility break, not a security fix. XSS for untrusted data is `#<<` / `<%= %>`. `#safe_concat` is `<%== %>`, `raw`, static ERB text, and cache restore. Making it escape ordinary strings reintroduces the bug `#safe_concat` exists to avoid: trusted HTML becomes visible source. No new capture XSS is closed; tests already cover return-value escaping ([capture_helper_test.rb](actionview/test/template/capture_helper_test.rb) `test_capture_escapes_html` / `test_capture_doesnt_escape_twice`).

### Tests that should exist (and would fail this patch)

```ruby
## buffers_test — keep: safe_append bypasses escaping
@buffer.safe_concat "<p>This is fine</p>"
assert_equal "<p>This is fine</p>", @buffer.to_s

## ordinary unsafe string must NOT be escaped by safe_concat
@buffer.safe_concat "<script>alert(1)</script>"
assert_equal "<script>alert(1)</script>", @buffer.to_s

## html_safe still raw (true today and after the patch — not a reason to land it)
@buffer.safe_concat "<b>ok</b>".html_safe
assert_equal "<b>ok</b>", @buffer.to_s

## nil: current contract
assert_raises(TypeError) { @buffer.safe_concat(nil) }

## OutputBuffer value: preserve already-processed contents
src = ActionView::OutputBuffer.new
src << "<x>"; src.safe_concat("<y>")
@buffer.safe_concat(src)
assert_equal "&lt;x&gt;<y>", @buffer.to_s

## CaptureHelper: write + return — write wins, return dropped
out = @av.capture { @av.output_buffer << "<em>w</em>"; "<script>r</script>" }
assert_equal "&lt;em&gt;w&lt;/em&gt;", out

## CaptureHelper: return-only ordinary string already escaped (no safe_concat change needed)
assert_equal "&lt;em&gt;bar&lt;/em&gt;", @av.capture { "<em>bar</em>" }

## ERB static text still round-trips (would fail)
## render inline: "<div>ok</div>" => "<div>ok</div>"
```

Do not land this. If capture of mixed write/return still confuses callers, document `OutputBuffer#capture` vs `CaptureHelper#capture`; do not teach `#safe_concat` to escape.
