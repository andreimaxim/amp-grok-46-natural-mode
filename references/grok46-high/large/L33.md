## ActiveModel::Dirty: `changes_applied`, `restore_attributes`, `clear_changes_information`

Dirty keeps two tracker slots. Current unsaved edits live in `@mutations_from_database`. The last applied edit lives in `@mutations_before_last_save`. Both start as `nil` in `init_internals` ([dirty.rb L351-L355](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L351-L355)).

Which tracker class is used depends on whether the model has `@attributes`:

```text
mutations_from_database
  ├─ @attributes defined  → AttributeMutationTracker.new(@attributes)
  └─ otherwise            → ForcedMutationTracker.new(self)

mutations_before_last_save
  └─ nil → NullMutationTracker.instance  (changed?=false, changes={}, original_value=nil)
```

([dirty.rb L371-L384](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L371-L384), [attribute_mutation_tracker.rb L7-L188](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L7-L188))

`DirtyTest::DirtyModel` has no `@attributes`, so it uses `ForcedMutationTracker` and **must** call `*_will_change!` ([dirty_test.rb L7-L43](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L7-L43)). `AttributesDirtyTest::DirtyModel` uses `ActiveModel::Attributes` and `AttributeMutationTracker`, which can detect string in-place mutation without `*_will_change!` ([attributes_dirty_test.rb L6-L16](file:///home/user/workspace/repo/activemodel/test/cases/attributes_dirty_test.rb#L6-L16), [attributes_dirty_test.rb L64-L70](file:///home/user/workspace/repo/activemodel/test/cases/attributes_dirty_test.rb#L64-L70)).

Generated methods are suffixes/affixes that forward to the dispatch targets below ([dirty.rb L240-L244](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L240-L244), [dirty.rb L291-L316](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L291-L316), [dirty.rb L391-L420](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L391-L420)):

| Generated | Dispatch | Tracker |
|---|---|---|
| `name_changed?` | `attribute_changed?` | from_database |
| `name_was` | `attribute_was` | from_database.original_value |
| `name_change` | `attribute_change` | from_database.change_to_attribute |
| `name_will_change!` | `attribute_will_change!` | from_database.force_change |
| `name_previously_changed?` | `attribute_previously_changed?` | before_last_save |
| `name_previously_was` | `attribute_previously_was` | before_last_save.original_value |
| `name_previous_change` | `attribute_previous_change` | before_last_save.change_to_attribute |
| `restore_name!` | `restore_attribute!` | assign `*_was`, then forget |
| `clear_name_change` | `clear_attribute_change` | forget_change |

Public readers: `changed?` → `any_changes?`; `changes` → current `[from, to]` hash; `previous_changes` → last-save `[from, to]` hash ([dirty.rb L286-L345](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L286-L345)).

### The three lifecycle methods

**`changes_applied`** ([dirty.rb L267-L276](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L267-L276)) — used as `save` in both tests. Returns `nil`.

1. If there is no `@attributes`, call `ForcedMutationTracker#finalize_changes`, which snapshots `changes` into `@finalized_changes` so later live writes cannot rewrite `previous_changes` ([attribute_mutation_tracker.rb L125-L127](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L125-L127), [L101-L107](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L101-L107)).
2. Move the current tracker to `@mutations_before_last_save`.
3. `forget_attribute_assignments` — with `@attributes`, remap each attribute through `forgetting_assignment` so the new current tracker sees no assignment history ([dirty.rb L379-L381](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L379-L381), [attribute.rb L74-L76](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute.rb#L74-L76)). No-op for ForcedMutationTracker models.
4. `@mutations_from_database = nil` so the next dirty query builds a fresh empty tracker.

**`restore_attributes(attr_names = changed)`** ([dirty.rb L318-L322](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L318-L322)). Returns `attr_names` (the `each` receiver). For each name, `restore_attribute!` ([dirty.rb L413-L420](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L413-L420)):

1. Skip unless currently dirty.
2. `self.name = name_was` (goes through the setter).
3. `clear_attribute_change` / `forget_change`.

It does **not** touch `@mutations_before_last_save`. `previous_changes` and `*_previously_was` survive a rollback.

**`clear_changes_information`** ([dirty.rb L324-L329](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L324-L329)). Returns `nil`. Nils both tracker ivars and forgets attribute assignments. Attribute values are left as they are; only dirty metadata is wiped. Next `previous_changes` comes from `NullMutationTracker` (`{}`).

### ForcedMutationTracker walkthrough (`DirtyTest`)

Model starts `@name = nil`, `@color = nil`, `@status = "initialized"`. `name=` always calls `name_will_change!`; `color=` only does if the value actually differs ([dirty_test.rb L21-L28](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L21-L28)).

`ForcedMutationTracker#force_change` clones the **current** value once and stores it as the original; later `force_change` calls are no-ops if already dirty ([attribute_mutation_tracker.rb L121-L123](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L121-L123)). `change_to_attribute` is `[cloned_original, live_value]`.

#### Stage 1 — in-place mutation needs `*_will_change!`

[dirty_test.rb L91-L101](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L91-L101) and module docs [dirty.rb L115-L122](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L115-L122):

```text
@name = +"Yam"
name.replace("Hadad")     # live value changes, but forced_changes is empty
name_changed?  => false   # ForcedMutationTracker.changed_in_place? is always false

name_will_change!         # clones "Hadad" into forced_changes
name_change    => ["Hadad", "Hadad"]
name.replace("Baal")
name_changed?  => true
name_change    => ["Hadad", "Baal"]
name_was       => "Hadad"
```

Without `name_will_change!`, Active Model cannot see in-place edits. Attribute models can: `Type::String#changed_in_place?` compares the raw original to the mutated string ([string.rb L16-L20](file:///home/user/workspace/repo/activemodel/lib/active_model/type/string.rb#L16-L20), [attributes_dirty_test.rb L64-L70](file:///home/user/workspace/repo/activemodel/test/cases/attributes_dirty_test.rb#L64-L70)).

| `changed?` | `true` |

| `name_was` | `"Dmitry"` |
| `color_was` | `"Red"` |
| `previous_changes` | unchanged from the save |

#### Changed back to the original value

This is the writer’s job, not the tracker’s. Recommended setter ([dirty.rb L38-L41](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L38-L41), [L98-L102](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L98-L102)):

```ruby
name_will_change! unless val == @name
```

`color=` follows that. After save of `"red"`, `color = "red"` does **not** call `color_will_change!`, so ([dirty_test.rb L109-L118](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L109-L118)):

| | |
|---|---|
| `color_changed?` / `changed?` | `false` |
| `color_change` / `changes["color"]` | `nil` |
| `previous_changes["color"]` | `["red"` pair from the save] |

`name=` in DirtyTest **always** calls `name_will_change!`, so assigning the same name **does** mark dirty (`[old, old]` until the live value differs). Attribute models compare **cast** values instead: `size = "2.3"` then `"2.1"` both become `2`, so `changed?` stays false ([attributes_dirty_test.rb L186-L199](file:///home/user/workspace/repo/activemodel/test/cases/attributes_dirty_test.rb#L186-L199)).

#### Mutable values and `*_will_change!`

ForcedMutationTracker: `changed_in_place?` is hardcoded `false` ([attribute_mutation_tracker.rb L97-L99](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L97-L99)). In-place `replace`/`<<` is invisible unless `force_change` cloned first. `clone_value` uses `value.clone` when `duplicable?`, else the raw value ([attribute_mutation_tracker.rb L147-L153](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L147-L153)).

AttributeMutationTracker: `force_change` only records the live value; in-place detection is `Attribute#changed_in_place?` → type (`String` returns true when the mutated string `!=` raw original). After `changes_applied`, `forgetting_assignment` writes the current serialized value as a new `FromDatabase` attribute, so the next in-place edit is compared against that snapshot.

### Control-flow summary

```text
*_will_change! / setter
  → mutations_from_database.force_change
      Forced: clone once into forced_changes
      Attributes: mark forced + Attribute#changed? / changed_in_place?

changed? / changes / *_was / *_change
  → mutations_from_database

changes_applied                        # returns nil
  → [Forced] finalize_changes snapshot
  → @mutations_before_last_save = current tracker
  → forget_attribute_assignments
  → @mutations_from_database = nil     # current dirty is empty
  previous_changes / *_previously_was / *_previous_change now read the saved tracker

second edit
  → new from_database tracker; before_last_save unchanged

restore_attributes(names = changed)    # returns names
  → for each dirty name: setter(original) + forget_change
  → omitted names stay dirty
  → previous_changes untouched

clear_changes_information              # returns nil
  → both trackers nil; values unchanged
```
