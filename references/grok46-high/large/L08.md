`Enumerable#sole` returns the only yielded item, or raises if the enumerable is empty or has more than one item. It never materializes the whole collection: it walks `each` once, keeps a `found` flag, and aborts on the second yield.

Source: [`activesupport/lib/active_support/core_ext/enumerable.rb`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/enumerable.rb) lines 230–256. Tests: [`activesupport/test/core_ext/enumerable_test.rb`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb) `test_sole` (431–438), `test_sole_returns_same_value_as_first_for_tuples` (441–444), `test_sole_keyword_arguments` (446–458). `GenericEnumerable` (35–45) only forwards `each`.

### Control flow

```
result = nil
found  = false

each do |*element|
  if found
    raise SoleItemExpectedError, "multiple items found"   # second yield: abort
  end
  result = (element.size == 1 ? element[0] : element)
  found  = true
end

found ? result : raise SoleItemExpectedError, "no item found"
```

`found` is the occupancy test, not `result`. `result` starts as `nil` and is overwritten only after a yield, so `nil` is a real element.

### Empty / one / many

| Input | What happens | Result |
|---|---|---|
| `[]` | `each` never yields; `found` stays false | `Enumerable::SoleItemExpectedError` `"no item found"` |
| `[1]` | one yield; unwrap `[1]` → `1`; `found` true; `each` ends | `1` |
| `[1, 2]` | first yield stores `1`; second yield sees `found` | `"multiple items found"` on the 2nd yield |
| `[1, nil]` | two yields; `nil` counts | `"multiple items found"` |
| `1..` via `GenericEnumerable` | yields `1` then `2`; raise on `2` | `"multiple items found"` without walking the rest of the range |

`test_sole` (431–438) covers all five. The empty and multi-item cases use `assert_raise(Enumerable::SoleItemExpectedError)` only; the messages themselves are established in source (244, 254) and the method docs (234–236).

Exception class: `Enumerable::SoleItemExpectedError < StandardError` (19–22), then moved to `ActiveSupport::EnumerableCoreExt::SoleItemExpectedError` (23–27) with `const_missing` so `Enumerable::SoleItemExpectedError` still resolves (8–14).

### Why an endless range does not require complete traversal

`GenericEnumerable.new(1..)` is not `Range#sole`. It includes `Enumerable` and forwards `each` to the range (35–45). `Enumerable#sole` therefore sees successive yields `1`, `2`, … and raises `"multiple items found"` on the second yield (242–245). Iteration stops there; the rest of `1..` is never consumed. That is why `assert_raise { GenericEnumerable.new(1..).sole }` (438) can finish.

(`Range#sole` is a different path: begin- or end-less ranges raise `"infinite range '#{inspect}' cannot represent a sole item"` before `super`. The enumerable test does not take that path.)

### `nil` is a real element

Because occupancy is `found`, not a nil-check on `result`:

- A sole `nil` would be stored and returned (`element.size == 1 ? element[0] : element` → `nil`, `found = true`).
- `[1, nil]` is two items: first yield sets `result = 1`, `found = true`; second yield (`nil`) raises `"multiple items found"` (437). `nil` is not treated as “no item.”

### How yields are represented

The block is `|*element|`. Ruby packs every positional yield into an Array. `sole` then unwraps only a 1-element array so a normal single yield is not wrapped:

```
result = element.size == 1 ? element[0] : element
```

That matches `Enumerable#first` in the tuple/kwarg tests.

1. **One positional value** (`each` yields `1`): `element == [1]`, size 1, unwrap → `1`. `test_sole` line 435: `GenericEnumerable.new([1]).sole == 1`.

2. **Multiple positional values** (`yielder.yield(1, "one")`): `element == [1, "one"]`, size ≠ 1, keep the array. `test_sole_returns_same_value_as_first_for_tuples` (441–444): `enum.sole == [1, "one"]` and `enum.sole == enum.first`.

3. **Positional value plus keywords** (`yield 1, two: 3`): Ruby presents the keywords as a trailing Hash, so `|*element|` is `[1, { two: 3 }]`, size ≠ 1, keep the array. `KeywordYielder` / `test_sole_keyword_arguments` (446–458): `yielder.sole == [1, { two: 3 }]` and `yielder.sole == yielder.first`.

Single-value unwrap is the only special case. Multi-value and kwarg yields stay as the packed array, which is why they agree with `first`.
