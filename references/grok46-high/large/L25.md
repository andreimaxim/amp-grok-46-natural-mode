`expect` is permit-then-require with two stricter defaults: hashes and arrays are not interchangeable, and unpermitted keys never raise. `permit` always returns a filtered `Parameters` wrapper. `expect` then `require`s every root filter key and unwraps a single result.

### Call path

```
expect(*filters)
  permit_filters(filters, on_unpermitted: nil, explicit_arrays: true)
    Symbol/String → permitted_scalar_filter
    Hash → hash_filter → permit_value
      []      → permit_array_of_scalars
      {}      → permit_hash (any permitted scalars)
      [[…]]   → permit_array_of_hashes → each_array_element
      else    → permit_hash          # hash only
    permit!
  keys = root keys of filters, in filter order
  values = params.require(keys)
  values.size == 1 ? values.first : values
```

[`permit`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L675-L677) uses the same [`permit_filters`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1189-L1208), but with `on_unpermitted: action_on_unpermitted_parameters` and `explicit_arrays: false`. Its last [`permit_value`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1454-L1466) branch is `permit_hash_or_array`. It does not `require` and does not unwrap.

[`require`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L526-L542) does no filtering. It returns `self[key]` when `present?` or `== false`; otherwise `ActionController::ParameterMissing`. An array of keys maps `require` over each and returns that array; the first miss raises.

`array_filter?` is only `filter.size == 1 && filter.first.is_a?(Array)`, i.e. `[[:text]]`. `[:text]` is not an array declaration.

`each_array_element`: a real `Array` keeps only `Parameters` elements; a `Parameters` object is treated as an array only when every kept key matches `nested_attribute?` (`/\A-?\d+\z/` and hash-valued) and the filter does not name numeric keys.

### Contrast with `require` + `permit`

| | `require` then `permit` | `permit` then `require` | `expect` |
|---|---|---|---|
| Missing/blank root | `ParameterMissing` | `ParameterMissing` | `ParameterMissing` |
| Scalar where hash expected | `NoMethodError` (`"hack".permit`) | root dropped, then `ParameterMissing` | `ParameterMissing` (never calls `permit` on a scalar) |
| Array where hash expected (`pies: [:flavor]`) | often succeeds; array kept | succeeds; array kept | `ParameterMissing` |
| Hash where array expected (`pies: [[:flavor]]`) | hash kept under `permit` | hash kept | `ParameterMissing` |
| Unpermitted keys | subject to `action_on_unpermitted_parameters` on `permit` | same | always dropped; never log/raise |
| Return | whatever `permit` returns on the required value | the required root, already permitted | required root value(s); unwrap if one key |

`expect!` is the same path, but rescues `ParameterMissing` and raises `ExpectedParameterMissing`.

### Return arity

Root keys are `filters.flatten.flat_map { |f| f.is_a?(Hash) ? f.keys : f }`. One key → that value. Two or more → array in filter order.

- `expect(:a)` → scalar `1`
- `expect(:a, :b)` and `expect([:a, :b])` → `[1, 2]`
- `expect(person: [:name])` → permitted person `Parameters` (not `{person: …}`)
- `expect(subject: [:name], object: [:pie])` → `[subject_params, object_params]`
- `expect(:name, pies: [[:type, :flavor]])` → `[name, pies_array]`

`permit` never unwraps: `permit(person: [:name])` is `{ "person" => {…} }`.

Tests: `array of key: returns single permitted param`, `array of keys: returns multiple permitted params`, `keys to arrays: returns permitted params in hash key order` in [`parameters_expect_test.rb`](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_expect_test.rb).

### Concrete examples

#### 1. Scalar vs hash (type confusion)

Input `{ user: "hack" }`, filter `user: [:name]`.

- `expect(user: [:name])` → `ActionController::ParameterMissing` (`user`). `permit_hash` requires `Parameters`; the string is dropped; `require` sees a missing root.
- `require(:user).permit(:name)` → `NoMethodError` (`permit` on String). `require` only checks `present?`.
- `permit(user: [:name]).require(:user)` → `ParameterMissing`. `permit` already dropped the scalar (`scalar values should be filtered when array or hash is specified` in [`parameters_permit_test.rb`](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_permit_test.rb)).

Input `{ user: { name: "Martin", pets: { name: "hack" } } }`.

- `require(:user).permit(:name, pets: [:name])` → permitted `{ "name" => "Martin", "pets" => { "name" => "hack" } }`. `pets` is a hash, not an array: `permit_hash_or_array` falls through to `permit_hash`.
- `expect(user: [:name, pets: [[:name]]])` → permitted `{ "name" => "Martin" }`; `[:pets]` is `nil`. `[[:name]]` is the explicit-array branch; a non-numeric-key hash is not an array.

Input `{ pies: [{ flavor: "pumpkin" }] }`.

- `expect(pies: [:flavor])` → `ParameterMissing` (`key to array of keys: raises when params is an array`).
- `permit(pies: [:flavor])` → `{ "pies" => [{ "flavor" => "pumpkin" }] }` permitted. `explicit_arrays: false` takes `permit_hash_or_array`.

#### 2. Array of scalars

Input `{ id: ["foo", "bar"] }`, filter `id: []`.

- `expect(id: [])` → `["foo", "bar"]` (unwrapped Array). `permitted?` does not apply to the Array; it is the required value.
- `permit(id: [])` → `#<Parameters {"id"=>["foo","bar"]} permitted: true>`.

Empty `{ id: [] }`: `permit` keeps `[]`; `expect` raises `ParameterMissing` (`require` treats empty as blank). Scalar `{ id: "foo" }` or `[{id:"1"}]` / `[[]]`: both drop the key; `expect` then raises `ParameterMissing`.

Tests: `key to empty array: arrays of permitted scalars pass`, `… on empty`, `… arrays of non-permitted scalar do not pass`.

#### 3. Array of parameter hashes

Input `{ pies: [{ flavor: "pumpkin" }, { flavor: "chicken pot" }] }`, filter `pies: [[:flavor]]`.

- `expect` → `[#<Parameters {"flavor"=>"pumpkin"} permitted: true>, #<Parameters {"flavor"=>"chicken pot"} permitted: true>]`.
- `permit(pies: [:flavor])` → wrapper `{ "pies" => [those hashes] }` permitted. `permit` has no `[[…]]` syntax; `[:flavor]` already allows arrays.

Hash `{ pies: { flavor: "pumpkin" } }` with `pies: [[:flavor]]` → `ParameterMissing`. Empty `pies: []` → `ParameterMissing` (test name says “returns empty array”; the assertion is a raise).

`each_array_element` on a real array uses `grep(Parameters)`, so non-hash elements are dropped. If every element is dropped, the stored value is `[]` and `require` still raises.

Tests: `key to explicit array: returns permitted array`, `… returns array when params is a hash`, `… returns empty array when params empty array`.

#### 4. Missing multiple required roots

Input `{ a: 1 }`.

- `expect(:a, :b)` / `expect([:a, :b])` → `ParameterMissing` for `:b`.
- `require([:a, :b])` → same (`require array when a required param is missing` in [`required_params_test.rb`](file:///home/user/workspace/repo/actionpack/test/controller/required_params_test.rb)).
- `permit(:a, :b)` → `{ "a" => 1 }` permitted; `:b` absent, no exception.

Input `{ a: 1, b: [] }`: `expect([:a, :b])` → `ParameterMissing` for `:b` (non-scalar fails `permitted_scalar_filter`, then `require`).

Both present: `expect(:a, :b)` → `[1, 2]`, not a `Parameters`.

#### 5. Numeric-key nested parameters

Input:

```
book: {
  authors_attributes: {
    "0" => { name: "William Shakespeare", age_of_death: "52" },
    "1" => { name: "Unattributed Assistant" },
    "2" => { name: ["injected", "names"] }
  }
}
```

`permit(book: { authors_attributes: [:name] })` → permitted

```
{ "book" => { "authors_attributes" => {
  "0" => { "name" => "William Shakespeare" },
  "1" => { "name" => "Unattributed Assistant" },
  "2" => {}
} } }
```

Numeric keys match `nested_attribute?`, so `permit_array_of_hashes` walks each child. `"2"`’s `name` is an array, not a scalar, so that child is empty but kept. `age_of_death` is dropped.

`expect(book: { authors_attributes: { "1": [:name] } })` → unwrapped permitted

```
{ "authors_attributes" => { "1" => { "name" => "Unattributed Assistant" } } }
```

Filter names numeric keys (`specify_numeric_keys?`), so this is `permit_hash`, not the nested-attribute array walk. Only `"1"` survives.

`expect(product: { properties: ["0"] })` with `properties: { "0" => "prop0", "1" => "prop1" }` → unwrapped product; `properties["0"] == "prop0"`, `properties["1"]` is `nil`. `["0"]` is a scalar-key list, not `[[…]]`.

Tests in [`nested_parameters_permit_test.rb`](file:///home/user/workspace/repo/actionpack/test/controller/parameters/nested_parameters_permit_test.rb): `nested params with numeric keys`, `… addressing individual numeric keys using require first`, `nested number as key`.

A numeric-key hash **does** satisfy `expect(pies: [[:flavor]])` when keys are `"0"`, `"1"`, … (docs in `each_array_element`). The stored value is a `Parameters` hash of those keys, not a Ruby Array. A non-numeric hash `{ flavor: "pumpkin" }` does not.

#### 6. Unpermitted keys

Input `{ id: "1234", injected: "injected" }`.

- `expect(:id)` → `"1234"`. `injected` dropped. No exception even when `action_on_unpermitted_parameters = :raise`.
- `permit(:id)` → `#<Parameters {"id"=>"1234"} permitted: true>` normally; with `:raise` → `ActionController::UnpermittedParameters` (`:injected`).

Nested extras: `{ book: { pages: 65, title: "…" }, fishing: "Turnips" }`.

- `expect(book: [:pages])` → `{ "pages" => 65 }` permitted. `title` and `fishing` dropped; no raise.
- `permit(book: [:pages])` with `:raise` → `UnpermittedParameters` (`:fishing` at the top; nested `:title` also raises in the nested `permit_filters` call).

Tests: `key: unknown keys are filtered out`; [`raise_on_unpermitted_params_test.rb`](file:///home/user/workspace/repo/actionpack/test/controller/parameters/raise_on_unpermitted_params_test.rb) `expect never raises on unexpected params`, `raises on unexpected params`.

`expect` passes `on_unpermitted: nil` into `permit_filters`, and `unpermitted_parameters!` returns immediately unless that value is truthy. Nested recursive `permit_filters` keep `nil`.

---

`expect` is `permit_filters` (strict hash-vs-array, no unpermitted action) + `require` of every root key + unwrap-if-one. `require`+`permit` either explodes on a scalar (`NoMethodError`) or, if `permit` runs first, still treats arrays and hashes as interchangeable.
