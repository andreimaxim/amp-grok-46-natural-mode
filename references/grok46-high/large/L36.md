### Claim

`#attach!` is not supposed to always `save!`. It is the bang counterpart to `#attach`: raise only when `#attach` actually attempted an immediate save and that save failed.

That is explicit in the method comment ([many.rb](file:///home/user/workspace/repo/activestorage/lib/active_storage/attached/many.rb#L59)): *“raises an exception if the record was meant to be saved but at least one of the validations failed.”*

Immediate save happens only when `record.persisted? && !record.changed?` ([many.rb](file:///home/user/workspace/repo/activestorage/lib/active_storage/attached/many.rb#L51-L57)). `changed?` is attribute dirty tracking ([dirty.rb](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L286-L288)), not `attachment_changes`. Assigning attachments does not mark the record changed; `changed_for_autosave?` does ([model.rb](file:///home/user/workspace/repo/activestorage/lib/active_storage/attached/model.rb#L313-L315)), but `#attach` does not use that.

Validation failures on that immediate-save path already raise. `#attach` does `return if !record.save` (nil), and `#attach!` does `attach(...) || raise(ActiveRecord::RecordNotSaved.new("Failed to save the record", record))` ([many.rb](file:///home/user/workspace/repo/activestorage/lib/active_storage/attached/many.rb#L65-L67)). Covered by [many_test.rb](file:///home/user/workspace/repo/activestorage/test/models/attached/many_test.rb#L811-L827).

### Why the diff is wrong

```ruby
def attach!(*attachables)
  attach(*attachables)
  record.save!
end
```

**Persisted + unchanged + valid (successful immediate save).** `#attach` already `save`s. Then `save!` runs again: second UPDATE, second `updated_at` touch, `after_save` / `after_commit` twice. Attachments are already persisted/uploaded on the first save ([model.rb](file:///home/user/workspace/repo/activestorage/lib/active_storage/attached/model.rb#L271-L273)).

**Persisted + unchanged + invalid.** Today: `RecordNotSaved`, message `"Failed to save the record"`. Test at [many_test.rb](file:///home/user/workspace/repo/activestorage/test/models/attached/many_test.rb#L820-L827). Proposed: `record.save!` raises `RecordInvalid` ([validations.rb](file:///home/user/workspace/repo/activerecord/lib/active_record/validations.rb#L52-L55)), not `RecordNotSaved`. Existing test fails. Callback abort still becomes `RecordNotSaved` via Persistence `#save!` ([persistence.rb](file:///home/user/workspace/repo/activerecord/lib/active_record/persistence.rb#L391-L393)), so exception class would now depend on *why* save failed.

**New records.** `#attach` does not save ([many.rb](file:///home/user/workspace/repo/activestorage/lib/active_storage/attached/many.rb#L53); [many_test.rb](file:///home/user/workspace/repo/activestorage/test/models/attached/many_test.rb#L836-L841)). Proposed `save!` would persist a valid new record immediately, or raise `RecordInvalid` on an invalid one. That breaks deferred/pending attachments.

**Persisted + changed.** Same deferral ([many_test.rb](file:///home/user/workspace/repo/activestorage/test/models/attached/many_test.rb#L47-L58), [L829-L834](file:///home/user/workspace/repo/activestorage/test/models/attached/many_test.rb#L829-L834)). Proposed `save!` would persist unrelated dirty attributes as a side effect, or raise if those attributes are invalid.

**Return value.** `#attach` returns the attachment proxy ([many_test.rb](file:///home/user/workspace/repo/activestorage/test/models/attached/many_test.rb#L805-L809)). `#save!` returns `true`. Callers of `#attach!` would get `true` instead of the attachments. No current `#attach!` return-value test, so this would ship silently.

**Empty / nested arrays.** `#attach` already does `blobs + attachables.flatten`; empty assign becomes `DeleteMany` ([model.rb](file:///home/user/workspace/repo/activestorage/lib/active_storage/attached/model.rb#L243-L251); empty-list tests at [many_test.rb](file:///home/user/workspace/repo/activestorage/test/models/attached/many_test.rb#L289-L303)). Nested arrays stay flattened. The extra `save!` still double-saves or newly persists/deletes on new/changed records.

**Duplicate / existing blobs.** `#attach` concatenates `blobs + attachables`. Existing blob identity is handled in `CreateOneOfMany#find_attachment` and `persisted_or_new_attachments`. The diff does not fix or worsen that, except via the extra save.

**Pending changes.** On new/changed records, pending `attachment_changes` stay until the record is saved. `save!` would commit them immediately. On the failed immediate-save path, changes remain pending either way.

**Callbacks.** Double callbacks on the success path; new/changed `#attach!` would start firing save callbacks.

### Attached::One

`Attached::One#attach` / `#attach!` is the same pattern ([one.rb](file:///home/user/workspace/repo/activestorage/lib/active_storage/attached/one.rb#L64-L80); [one_test.rb](file:///home/user/workspace/repo/activestorage/test/models/attached/one_test.rb#L135-L167)). Changing only Many makes the two APIs diverge.

### Smallest corrected direction

Do **not** always call `record.save!`. Keep `#attach!` as a bang wrapper that honors `#attach`’s save-or-defer contract.

If the only goal is “validation failure raises like `save!`” on the immediate-save path:

```ruby
def attach!(*attachables)
  record.public_send("#{name}=", blobs + attachables.flatten)
  record.save! if record.persisted? && !record.changed?
  record.public_send("#{name}")
end
```

That avoids double-save, preserves deferral and return value, and raises `RecordInvalid` on validation failure / `RecordNotSaved` on callback abort. It is still a breaking exception-class change vs current tests (`RecordNotSaved` at [many_test.rb](file:///home/user/workspace/repo/activestorage/test/models/attached/many_test.rb#L824)). Mirror it in `Attached::One` if you take it.

If the goal is just a reliable bang counterpart, **keep the current `attach(...) || raise(RecordNotSaved, ...)`**. It already matches `#attach` and the tests.

Missing tests if anything is changed: `#attach!` return value on success; `#attach!` on new records and changed records must not persist; exception class *and* message; no double-save/callbacks on persisted+valid; One/Many parity.
