## Assistant

`Rails::Application#config_for` is a small pipeline: resolve a YAML path, parse (ERB then Psych), symbolize, pick `env`/`shared`, optionally deep-merge, wrap hashes in `OrderedOptions`.

```text
config_for(name, env: Rails.env)
  resolve path
    Pathname → as-is
    else paths["config"].existent.first / "#{name}.yml"
  missing → raise RuntimeError
  present →
    ActiveSupport::ConfigurationFile.parse(yaml)
      read file; warn on U+00A0
      if content includes "<%" → ERB, then YAML.unsafe_load
      else YAML.unsafe_load_file
      nil/false → {}
      Psych::SyntaxError → ConfigurationFile::FormatError
    Hash#deep_symbolize_keys
    config = all[env.to_sym], shared = all[:shared]
    merge shared
    if Hash → OrderedOptions.new.update(config)
    else return as-is (nil, Array, scalar)
```

Public method: [`railties/lib/rails/application.rb`](railties/lib/rails/application.rb) ~292–318. Parse: [`activesupport/lib/active_support/configuration_file.rb`](activesupport/lib/active_support/configuration_file.rb). Behavior is pinned in [`railties/test/application/configuration_test.rb`](railties/test/application/configuration_test.rb) 2653–2888 (`set_custom_config` at 5502). ERB/YAML errors also in [`activesupport/test/configuration_file_test.rb`](activesupport/test/configuration_file_test.rb).

#### Path

A `Pathname` is used as-is. Anything else becomes `#{paths["config"].existent.first}/#{name}.yml` (`paths["config"]` from [`railties/lib/rails/engine/configuration.rb`](railties/lib/rails/engine/configuration.rb)). Tests: Pathname (2735); missing file raises `RuntimeError` with `Could not load configuration. No such file - …/config/custom.yml` (2746).

Contract: name or Pathname in; missing file is fatal. Incidental: interpolating `name` means `"custom.yml"` would look for `custom.yml.yml`; a nil `existent.first` produces the same missing-file error.

#### ERB, then YAML

`ConfigurationFile.parse` reads the file as text. ERB runs only if the raw content includes `"<%"`. `config_for` passes no `context:`, so `ERB#result` uses the default binding. Rendered source goes to `YAML.unsafe_load`; files without `<%` go to `YAML.unsafe_load_file`. Either result is `|| {}`.

- ERB: `key: <%= 'custom key' %>` → `"custom key"` (2820).
- ERB filename on backtrace: `ConfigurationFileTest`.
- `Psych::SyntaxError` → `ActiveSupport::ConfigurationFile::FormatError` with path (2831; same wrapping in `ConfigurationFileTest`).

Contract: ERB is evaluated; YAML syntax errors are `FormatError`. Incidental: `"<%"` substring as the ERB switch; `unsafe_load`; `|| {}` collapsing YAML `false`/`nil`; U+00A0 warning; no Rails-specific ERB binding.

#### Symbolized keys / parsers that reject `symbolize_names`

`config_for` always does `parse(yaml).deep_symbolize_keys` ([`activesupport/lib/active_support/core_ext/hash/keys.rb`](activesupport/lib/active_support/core_ext/hash/keys.rb) ~116). It does **not** pass `symbolize_names:` into Psych. Env lookup is `all_configs[env.to_sym]` and `all_configs[:shared]`.

Test 2856 stubs `YAML.load` and expects `{ key: "value" }`. Under the current parser (`unsafe_load` / `unsafe_load_file`) that stub is not on the call path; the assertion still holds because the real file is parsed and `deep_symbolize_keys` runs. The **contract** is “result keys are symbols even if YAML produced strings.” The **test name and `YAML.load` stub** describe a former `symbolize_names:` implementation. There is no current rescue of rejected `symbolize_names`.

Top-level string access still works because `OrderedOptions#[]` does `super(key.to_sym)` ([`activesupport/lib/active_support/ordered_options.rb`](activesupport/lib/active_support/ordered_options.rb) 42–44). Nested hashes are **not** wrapped; they only have symbol keys. That is the 6.1 change in `guides/source/upgrading_ruby_on_rails.md`. Test 2653 only exercises top-level OrderedOptions; 2665 walks nested hashes with symbols only.

#### `env:`

Keyword default is `Rails.env` at call time. Both string and symbol work (`env.to_sym`). Test 2843: `config_for('custom', env: 'production')` returns production while the process is not in that env. Test 2869 also uses `env: :test`.

#### `shared` and deep overrides

```ruby
config, shared = all_configs[env.to_sym], all_configs[:shared]

if shared
  config = {} if config.nil? && shared.is_a?(Hash)
  if config.is_a?(Hash) && shared.is_a?(Hash)
    config = shared.deep_merge(config)
  elsif config.nil?
    config = shared
  end
end
```

`Hash#deep_merge` is [`ActiveSupport::DeepMergeable`](activesupport/lib/active_support/deep_mergeable.rb): env wins on conflict; nested hashes recurse; arrays/scalars are replaced, not concatenated.

| Situation | Result | Test |
|---|---|---|
| both hashes, overlapping key | env wins | 2769 |
| both hashes, nested hashes | deep merge | 2795; same example in method RDoc and `guides/source/configuring.md` |
| env missing, shared hash | shared (then OrderedOptions) | 2782; empty `test:` in 2869 |
| env missing, shared array | the array | 2709 |
| env array and shared array | **env array only**, no concat | 2721 |
| env missing, no shared | `nil` | 2758 |

The `config = {} if config.nil? && shared.is_a?(Hash)` line exists so a missing env plus shared hash takes the both-hashes `deep_merge` path (then OrderedOptions). Shared array plus missing env uses `elsif config.nil?`. If env is present and not a Hash, shared is ignored.

Contract: `shared` is a Rails-level key; deep-merged under hashes; env overrides; missing env falls back to shared. Incidental: non-hash env values drop shared; YAML `shared:` (null) is falsy so skipped.

#### Return wrapping

Only a final Hash is wrapped: `ActiveSupport::OrderedOptions.new.update(config)`.

- Hash → OrderedOptions: method access, `[]` with string or symbol, Hash API (`keys`, `values`, `to_h`). Tests 2869, 2678, 2653.
- Nested hashes stay plain symbol-keyed Hashes. Tests walk `[:foo][:bar][:baz]`, never `config.foo.bar`.
- Array env root returned as Array (2697); array-only shared (2709).
- Empty file: parse `|| {}`, no env/shared → `nil` (2812).
- Absent env, no shared: `nil` (2758).

No test uses a **scalar** env root (`development: 42`). The same `is_a?(Hash)` gate would return that scalar unchanged. Array roots are the tested non-hash contract; scalar is implied, not pinned. `update` does not recursively wrap.

#### Contracts vs incidental mechanics

**Contracts** (RDoc, configuring guide, and/or tests): load `config/#{name}.yml` or a Pathname; ERB; current env or `env:`; `shared` deep-merged under hashes with env winning; missing env + shared → shared; missing env + no shared → nil; empty file → nil; missing file → RuntimeError; YAML syntax → FormatError; Hash result is OrderedOptions with symbol keys and top-level string `[]`; non-hash env roots are not forced into a Hash.

**Incidental / historical:** `"<%"` as the ERB switch; `unsafe_load*`; `|| {}`; U+00A0 warning; no recursive OrderedOptions; array/scalar env ignoring shared; `deep_symbolize_keys` as the replacement for a `symbolize_names` option (the 2856 test name/stub are leftover); document root is assumed to be a Hash of env names.

`Rails::Application::Configuration#database_configuration` also uses `ConfigurationFile` and a `shared` key, but a different merge (string keys, `reverse_merge!`, multi-DB). That is a sibling, not this method.
