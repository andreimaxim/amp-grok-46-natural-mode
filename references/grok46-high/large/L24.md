`RouteSet#recognize_path` is an offline recognizer. It fabricates a request, runs Journey, then returns **path parameters only** (`{ controller:, action:, ... }`) after proving the matched app is a dispatcher whose controller constantizes. It is not the live `Router#serve` path.

### Call flow

```
recognize_path(path, env)
  method = (env[:method] || "GET").upcase
  extras = env[:extras] || {}
  path = Utils.normalize_path(path)   unless path includes "://"
  Rack::MockRequest.env_for(path, method:)   # URI::InvalidURIError → RoutingError(e.message)
  req = make_request(env)             # ActionDispatch::Request (or TestSet wrapper)
  recognize_path_with_request(req, path, extras, raise_on_missing: true)
    Journey::Router#recognize(req) yield |route, params|
      params.merge!(extras)
      RFC2396 unescape every String value (2nd decode; + is not space)
      req.path_parameters = params
      if app.matches?(req) && app.dispatcher?
        req.controller_class            # NameError → RoutingError "A route matches … missing controller"
        return req.path_parameters
      elsif app.matches?(req) && app.engine?
        recurse with raise_on_missing: false; return if found
      # else: redirect / rack app → skip, try next route
    raise RoutingError "No route matches #{path.inspect}"   if raise_on_missing
```

Journey `#recognize` ([`actionpack/lib/action_dispatch/journey/router.rb`](actionpack/lib/action_dispatch/journey/router.rb)):

1. `filter_routes(path_info)` → GTG `simulator.memos(path)` (anchored routes).
2. Append `custom_routes` whose pattern matches (unanchored / non-anchored requirements).
3. Verb filter: HEAD uses `match_head_routes` (HEAD routes, else temporarily `REQUEST_METHOD=GET`). Else `r.matches?(req)` (verb + request constraints: host, protocol, …).
4. Sort by `precedence` if more than one.
5. For each: `r.path.match(path_info)`, merge `r.defaults`, capture names → `CGI.unescapeURIComponent` if `%` present, force UTF-8. Unanchored routes temporarily rewrite `script_name` / `path_info`.

`app.matches?` is a **second** constraint gate (`Mapper::Constraints` blocks/classes), after Journey already applied route-level verb/request constraints.

### Material steps ↔ source ↔ tests

**Relative vs absolute.** Relative paths (no `://`) go through [`Journey::Router::Utils.normalize_path`](actionpack/lib/action_dispatch/journey/router/utils.rb): leading `/`, squeeze `//`, strip trailing `/` except `"/"`, uppercase `%xx`. Absolute URLs skip that and are parsed by `env_for` into `PATH_INFO` / `QUERY_STRING` / host / scheme. Test: `RouteSetTest#test_route_with_subdomain_and_constraints_must_receive_params` recognizes `"http://subdomain.example.org/page/mypage"`. Trailing-slash equivalence is relative-path tests: `test_draw_default_route` (`/users/index/10/`), `test_default_route_recognition`, `RackMountIntegrationTests` `/api` vs `/api/`. Normalize unit tests: [`actionpack/test/journey/router/utils_test.rb`](actionpack/test/journey/router/utils_test.rb). Downcased unicode `%xx` is recovered by uppercasing: `test_downcased_unicode_path`.

**Query strings.** `env_for` puts `?…` in `QUERY_STRING`, not `PATH_INFO`. Returned hash is `path_parameters` only; query keys are **not** merged unless passed as `environment[:extras]` (`recognize_path_with_request` `params.merge!(extras)`). That extras channel is what `assert_recognizes` uses (`routing_assertions_test.rb#test_assert_recognizes_with_extras`). Constraint lambdas can still see query via `request.params` (`test_assert_recognizes_with_query_constraint`). Path `+` is not query-decoded to space (`test_paths_escaped`, `test_default_route_should_uri_escape_pluses`).

**Method constraints.** Default method is GET. Journey `Route#matches?` uses `VerbMatchers`. Array `via:` picks among routes (`test_recognize_array_of_methods`, `test_recognize_path` GET/POST/PUT/DELETE on `/admin/users`). Wrong verb with no other match → `"No route matches"` (`/get_or_post` PUT/DELETE; POST `/people/5`). HEAD matches a GET route (`journey/router_test.rb#test_recognize_head_request_as_get_route`); QUERY does not (`test_get_routes_do_not_match_query_requests`). Invalid verb: `Request#request_method` → `UnknownHttpMethod` (asserted on `request_path_params` with `:bacon`, same `check_method` on this path).

**URL-decoded dynamic segments.** Two decodes: Journey `CGI.unescapeURIComponent` on captures containing `%`, then RouteSet `URI::RFC2396_PARSER.unescape` on every String (RFC2396 unescape does **not** turn `+` into space). Tests: reserved chars (`UriReservedCharactersRoutingTest#test_route_recognition_unescapes_path_components`); `%20` → space, `+` stays (`test_paths_escaped`); `%0A` → newline for both `:dynamic` and `*wildcard` (`test_escapes_newline_character_for_*`); `%2B` and `+` both yield `"hello+world"` (`test_default_route_should_uri_escape_pluses`). Regex constraints run on the **encoded** path (`test_recognize_with_encoded_id_and_regex`).

**Unmatched route vs missing controller.** After the yield loop, no dispatcher/engine hit → `ActionController::RoutingError` `"No route matches #{path.inspect}"` (the **input** `path`, post-normalize or the absolute URL). Tests: `/none`, `/optional` without segment, `/admin/products` vs regexp controller, `/page/davidjamis`, `/`, too many segments. That is “no matching dispatcher/engine route,” including wrong verb and failed constraints.

If a dispatcher **did** match, `req.controller_class` runs (`action ||= "index"` as a side effect, then `controller.camelize << "Controller"` `#constantize`). `NameError` whose missing name is that constant is re-raised as `RoutingError` **`"A route matches #{path.inspect}, but references missing controller: #{params[:controller].camelize}Controller"`**. That is the recognize_path-specific distinction. `test_non_controllers_cannot_be_matched` (`/not_a/show/10` on `:controller/:action/:id`) exercises this via `recognize_path`.

**Live dispatch is different.** `Request#controller_class_for` raises `ActionDispatch::MissingController` (a `NameError`). `Dispatcher#serve` does not rewrite that. `test_route_error_with_missing_controller` uses `request_path_params` (full `routes.call`), so it expects `MissingController` / `uninitialized constant DoesNotExistsController`, not the `"A route matches"` RoutingError. `recognize_path` never surfaces `MissingController`; it always wraps it.

Engines recurse with `raise_on_missing: false` so a mount that doesn’t match internally falls through. Redirects and bare Rack apps are skipped (`dispatcher?`/`engine?` false) and do not count as a recognition. Lazy route sets only reload then `super` ([`railties/lib/rails/engine/lazy_route_set.rb`](railties/lib/rails/engine/lazy_route_set.rb)).

### Edge-case results

| Input / situation | Observable |
|---|---|
| `"/pages/show/10/"` | Same params as without slash (normalize) |
| `"http://host/page/x"` | Host/scheme on `req`; path from URI; no normalize |
| `"/foo?bar=1"` | Match on `/foo`; `bar` not in return value unless `extras:` |
| `extras: { page: "1" }` | Merged into returned path params |
| Bad URI | `RoutingError` with `URI::InvalidURIError` message |
| Wrong HTTP verb | `RoutingError` `"No route matches …"` |
| Unknown verb (`:bacon`) | `UnknownHttpMethod` when `request_method` is read |
| Encoded segment `%20` / `%0A` / `%3F` | Decoded in params; `+` remains `+` |
| No route | `RoutingError` `"No route matches #{path.inspect}"` |
| Route matches, controller missing (`recognize_path`) | `RoutingError` `"A route matches … missing controller: XController"` |
| Same, live `Dispatcher#serve` | `ActionDispatch::MissingController` |
| Engine miss | Continue; maybe later `"No route matches"` |
