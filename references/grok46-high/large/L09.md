**PR verdict: reject. The change is not safe.** The claim that `separator ||= ""` is redundant because the keyword defaults to `"-"` is false. The default only applies when the argument is omitted. An explicit `separator: nil` still reaches the method body as `nil`.

### Current contract

`separator: nil` is documented and tested as equivalent to `separator: ""`: strip unwanted characters instead of replacing them.

- Docs: [transliterate.rb](file:///home/user/workspace/repo/activesupport/lib/active_support/inflector/transliterate.rb#L124-L128) — “pass an empty separator. `nil` is treated the same way.”
- Coercion: [transliterate.rb](file:///home/user/workspace/repo/activesupport/lib/active_support/inflector/transliterate.rb#L150-L151) — `separator ||= ""`
- Tests: [string_ext_test.rb](file:///home/user/workspace/repo/activesupport/test/core_ext/string_ext_test.rb#L204-L225) — `test_string_parameterized_no_separator`, `test_string_parameterized_nil_separator`, and the `preserve_case` variants.

`String#parameterize` forwards to `ActiveSupport::Inflector.parameterize` ([inflections.rb](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/string/inflections.rb#L242-L244)), so those tests hit this implementation.

### `separator: nil` vs `separator: ""`

Today both produce the same result, e.g. `"Donald E. Knuth"` → `"donaldeknuth"` (or `"DonaldEKnuth"` with `preserve_case: true`).

After deleting the line they diverge:

| Call | Current | After deletion |
|---|---|---|
| omitted / `separator: "-"` | `"donald-e-knuth"` | unchanged |
| `separator: ""` | `"donaldeknuth"` | unchanged |
| `separator: nil` | `"donaldeknuth"` (same as `""`) | **raises** |

### First downstream operation affected

The first failure is not `separator.empty?`. It is the next use of `separator` after `transliterate`:

```ruby
parameterized_string.gsub!(/[^a-z0-9\-_]+/i, separator)
```

at [transliterate.rb:157](file:///home/user/workspace/repo/activesupport/lib/active_support/inflector/transliterate.rb#L157).

Verified with Ruby: `gsub!(regex, nil)` raises `TypeError: no implicit conversion of nil into String`. `gsub!(regex, "")` deletes the match. If that line were skipped, `unless separator.empty?` at [line 159](file:///home/user/workspace/repo/activesupport/lib/active_support/inflector/transliterate.rb#L159) would then raise `NoMethodError: undefined method 'empty?' for nil`.

### Normalization / `preserve_case` regression scope

Not in the blast radius of this deletion:

- Single-char squeeze (`separator.length == 1` → `squeeze!`) at [161–162](file:///home/user/workspace/repo/activesupport/lib/active_support/inflector/transliterate.rb#L161-L162)
- Multi-char collapse (`/#{re_sep}{2,}/`) at [163–165](file:///home/user/workspace/repo/activesupport/lib/active_support/inflector/transliterate.rb#L163-L165)
- Leading/trailing trim at [168–169](file:///home/user/workspace/repo/activesupport/lib/active_support/inflector/transliterate.rb#L168-L169)

Those run only inside `unless separator.empty?`. For `nil`/`""` that block is skipped after coercion. `preserve_case` is independent (`downcase!` at [172](file:///home/user/workspace/repo/activesupport/lib/active_support/inflector/transliterate.rb#L172)); it does not change the nil-vs-empty contract.

Existing tests already cover the regression. No extra squeeze/multi-char cases are needed for this PR.

### Smallest tests to request (already present)

Keep these; they fail if the line is removed:

1. `"Donald E. Knuth".parameterize(separator: nil)` → `"donaldeknuth"`
2. `"Donald E. Knuth".parameterize(separator: "")` → `"donaldeknuth"` (nil must stay equal to empty, not to `"-"`)
3. `"Donald E. Knuth".parameterize(separator: nil, preserve_case: true)` → `"DonaldEKnuth"`
4. Optional Inflector-level twin: `ActiveSupport::Inflector.parameterize("Donald E. Knuth", separator: nil)` → `"donaldeknuth"` (current coverage is only via `String#parameterize`)

Do not land this deletion without an explicit, documented breaking-change decision that `separator: nil` should raise instead of stripping.
