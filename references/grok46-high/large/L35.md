Pub/sub is a named online queue. `broadcast` encodes a payload onto that name. `stream_from` attaches a handler that later receives whatever was published. The channel is only a connector unless the app supplies a callback.

```text
client subscribe
  Connection#handle_incoming
    Subscriptions#add
      Channel#subscribe_to_channel
        subscribed → stream_from
          String(broadcasting)
          defer_subscription_confirmation!
          worker_pool_stream_handler → streams[name] = handler
          pubsub.subscribe(name, handler, on_success)
            on_success → ensure_confirmation_sent
        ensure_confirmation_sent → confirm_subscription (counter hits 0)

ActionCable.server.broadcast(name, message, coder:)
  Broadcaster#broadcast
    instrument "broadcast.action_cable"
    encoded = coder ? coder.encode(message) : message
    pubsub.broadcast(name, encoded)
      handler.call(encoded)
        default: JSON.decode → Channel#transmit → socket JSON envelope
        user callback: worker pool → optional decode → app code
```

### Subscribe path

[`stream_from`](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/streams.rb#L90-L108) is a no-op if the channel is already unsubscribed ([`unsubscribed?`](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/base.rb#L219-L221), set in [`unsubscribe_from_channel`](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/base.rb#L210-L214)). Otherwise it:

1. Coerces the broadcasting name with `String(broadcasting)`.
2. Calls `defer_subscription_confirmation!`.
3. Builds a handler and stores it in `streams[broadcasting]`.
4. Subscribes that handler to pubsub, with a success lambda that calls `ensure_confirmation_sent` and logs `is streaming from`.

[`subscribe_to_channel`](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/base.rb#L197-L206) runs `subscribed` (unless already rejected), then `reject_subscription` if rejected, then `ensure_confirmation_sent`.

### Broadcast path

[`Server::Broadcasting#broadcast`](file:///home/user/workspace/repo/actioncable/lib/action_cable/server/broadcasting.rb#L35-L36) defaults `coder:` to `ActiveSupport::JSON` and delegates to [`broadcaster_for`](file:///home/user/workspace/repo/actioncable/lib/action_cable/server/broadcasting.rb#L42-L43), which also does `String(broadcasting)`.

[`Broadcaster#broadcast`](file:///home/user/workspace/repo/actioncable/lib/action_cable/server/broadcasting.rb#L54-L61) logs, instruments `broadcast.action_cable` with `{ broadcasting:, message:, coder: }`, then:

- `coder` present → `coder.encode(message)` onto pubsub
- `coder` nil → raw `message` onto pubsub

Evidence: [`broadcasting_test.rb` L15–L37](file:///home/user/workspace/repo/actioncable/test/server/broadcasting_test.rb#L15-L37) (string coercion + notification payload with `coder: ActiveSupport::JSON`).

### Default handler vs user callback

[`stream_handler`](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/streams.rb#L179-L184) / [`worker_pool_stream_handler`](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/streams.rb#L163-L172):

| | Default (no callback) | User callback / block |
|---|---|---|
| Handler | [`default_stream_handler`](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/streams.rb#L195-L198): decode then [`stream_transmitter`](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/streams.rb#L215-L222) → `transmit message, via: "streamed from #{broadcasting}"` | [`stream_decoder`](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/streams.rb#L200-L213) wrapping the proc. **Does not transmit** unless the callback does. |
| Worker pool | Handler returned as-is; runs on the pubsub/event-loop thread | Outer lambda calls `connection.perform_work handler, :call, message` → [`Socket#perform_work`](file:///home/user/workspace/repo/actioncable/lib/action_cable/server/socket.rb#L57-L59) → [`Worker#async_invoke`](file:///home/user/workspace/repo/actioncable/lib/action_cable/server/worker.rb#L51-L66) |
| `coder: nil` | **Overridden** to `ActiveSupport::JSON` (`coder \|\|= ActiveSupport::JSON`) | Honored: decoder is a no-op, raw pubsub payload is passed through |

Evidence:

- Default delivers `{ "foo" => "bar" }` and does **not** call `perform_work`: [`stream_test.rb` L380–L390](file:///home/user/workspace/repo/actioncable/test/channel/stream_test.rb#L380-L390).
- User callback is **not** run on the broadcasting thread (`Thread.current[:ran_callback]` stays unset): [`stream_test.rb` L332–L377](file:///home/user/workspace/repo/actioncable/test/channel/stream_test.rb#L332-L377).

### `coder: nil` vs `ActiveSupport::JSON` vs custom encode

Two independent knobs: **publish encode** and **subscribe decode**.

- **Publish** ([`Broadcaster#broadcast` L59](file:///home/user/workspace/repo/actioncable/lib/action_cable/server/broadcasting.rb#L59)): default JSON-encodes; `coder: nil` publishes the Ruby object unchanged.
- **Subscribe, no callback**: always JSON-decodes, even if `stream_from` was called with `coder: nil`.
- **Subscribe, with callback**: `coder: nil` (the method default) passes the raw pubsub string/object; `coder: ActiveSupport::JSON` decodes before the callback. Docs at [`streams.rb` L86–L88](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/streams.rb#L86-L88).

**Custom server-side encoding** is the broadcast-side coder. [`stream_test.rb` L38–L41, L356–L365](file:///home/user/workspace/repo/actioncable/test/channel/stream_test.rb#L38-L41):

```ruby
server.broadcast "test_room_1", { foo: "bar" }, coder: DummyEncoder
## DummyEncoder.encode => '{ "foo": "encoded" }'
## ChatChannel streams with default JSON decoder (params[:coder] unset)
## client message => { "foo" => "encoded" }
```

`DummyEncoder.decode` is unused there. The default stream handler JSON-parses whatever the custom encoder wrote. A custom encoder must emit something that decoder understands (JSON text, in the default pairing).

`pick_coder("none")` returns `nil` ([`stream_test.rb` L26–L35](file:///home/user/workspace/repo/actioncable/test/channel/stream_test.rb#L26-L35)), but no test in this revision actually subscribes with `coder: "none"`.

### Deferred confirmation

Counter starts at **1** ([`base.rb` L168–L172](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/base.rb#L168-L172)). Each `stream_from` increments; each `ensure_confirmation_sent` decrements and transmits only when the value is no longer `> 0` ([`base.rb` L253–L264](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/base.rb#L253-L264)). [`transmit_subscription_confirmation`](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/base.rb#L322-L330) is also gated on `@subscription_confirmation_sent`.

With `SuccessAdapter`, the pubsub success callback runs inside `subscribe`, so the final decrement in `subscribe_to_channel` actually sends. With the Async adapter, confirmation waits until subscribe succeeds on the executor.

Evidence: confirmation arrives ([`stream_test.rb` L139–L147](file:///home/user/workspace/repo/actioncable/test/channel/stream_test.rb#L139-L147)); duplicate `send_confirmation` is a no-op ([L149–L162](file:///home/user/workspace/repo/actioncable/test/channel/stream_test.rb#L149-L162)); two `stream_from`s still emit one confirm ([L392–L401](file:///home/user/workspace/repo/actioncable/test/channel/stream_test.rb#L392-L401)). Rejected subscriptions skip confirmation (`ensure_confirmation_sent` returns immediately).

### Rejected subscriptions

[`stream_or_reject_for`](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/streams.rb#L146-L152) streams if the model is present, else `reject`. That sets `@reject_subscription`. Then `subscribe_to_channel` calls [`reject_subscription`](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/base.rb#L333-L336): remove from connection subscriptions (which unsubscribes/stops streams) and transmit `{ type: "reject_subscription" }`. No confirm is sent.

Evidence: [`stream_test.rb` L125–L137](file:///home/user/workspace/repo/actioncable/test/channel/stream_test.rb#L125-L137); also [`rejection_test.rb` L23–L51](file:///home/user/workspace/repo/actioncable/test/channel/rejection_test.rb#L23-L51) (rejected channels do not run later actions).

### Decode / encode failures

This revision has **no tests** for encode/decode errors. Observed from implementation:

- [`stream_decoder`](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/streams.rb#L200-L213) and [`Broadcaster#broadcast`](file:///home/user/workspace/repo/actioncable/lib/action_cable/server/broadcasting.rb#L59) have no rescue.
- Default handler runs via [`SubscriberMap#invoke_callback`](file:///home/user/workspace/repo/actioncable/lib/action_cable/subscription_adapter/subscriber_map.rb#L56-L58) (`callback.call message`) with no rescue — a `JSON::ParserError` (or custom decode error) propagates on the pubsub/event-loop thread.
- User-callback errors are rescued in [`Worker#invoke`](file:///home/user/workspace/repo/actioncable/lib/action_cable/server/worker.rb#L57-L65): log class/message/backtrace, then `receiver.handle_exception` if that method exists. The stream is not automatically stopped.
- Inbound WebSocket envelope decode is a separate path ([`Socket#dispatch_websocket_message`](file:///home/user/workspace/repo/actioncable/lib/action_cable/server/socket.rb#L77-L84)) and does rescue; that is not the broadcast/stream coder.

### String coercion of broadcasting names

Both sides stringify so symbols and other `to_s` objects hit the same pubsub key:

- `stream_from` / `stop_stream_from`: `broadcasting = String(broadcasting)`
- `broadcaster_for`: `Broadcaster.new(self, String(broadcasting), ...)`

Evidence: symbol `:channel` subscribes as `"channel"` ([`stream_test.rb` L78–L92](file:///home/user/workspace/repo/actioncable/test/channel/stream_test.rb#L78-L92)); `:room_one` start/stop match ([L228–L237](file:///home/user/workspace/repo/actioncable/test/channel/stream_test.rb#L228-L237)); broadcaster stores `"test_queue"` ([`broadcasting_test.rb` L15–L17](file:///home/user/workspace/repo/actioncable/test/server/broadcasting_test.rb#L15-L17)).

`stream_for` is only `stream_from(broadcasting_for(broadcastables), ...)`; `broadcast_to` is `ActionCable.server.broadcast(broadcasting_for(...), message)` with the default JSON coder.
