## Behavior-preservation verification for `ActionText::Content#to_plain_text` / `#render_attachments`

This is a verification strategy only. It pins this revision’s observable contract, then says which tests already prove it and which boundary cases need characterization tests before a refactor.

Pipeline under test:

```
Content#to_plain_text
  → render_attachments(with_full_attributes: false, &:to_plain_text)
      → Fragment#replace("action-text-attachment")  [dup of source]
      → Content.new(..., canonicalize: false)
  → Fragment#to_plain_text
      → PlainTextConversion.node_to_plain_text
```

Sources: [`actiontext/lib/action_text/content.rb`](actiontext/lib/action_text/content.rb) L99–L133, L216–L219; [`fragment.rb`](actiontext/lib/action_text/fragment.rb) L33–L51; [`plain_text_conversion.rb`](actiontext/lib/action_text/plain_text_conversion.rb); [`attachment.rb`](actiontext/lib/action_text/attachment.rb) L111–L117.

Doc vs code (do **not** pin the comments):
- RDoc on `Content#to_plain_text` L118 says “HTML entities encoded”. Observed: entities are **decoded**.
- `RichText` RDoc L26 says `<script>` text survives as `"safeunsafe"`. Observed via `Content#to_plain_text`: `"safe"`. Pin the code, not those comments.

### Observable contract (this revision)

**`#to_plain_text`**
- Returns a non-`html_safe` UTF-8 String.
- Does not mutate the receiver: `#to_html`, fragment source object_id, and attachment `content` attributes stay the same after the call.
- Replaces every `action-text-attachment` node with that attachment’s plain-text representation **before** walking the tree, using `with_full_attributes: false`.
- Builds the replacement `Content` with `canonicalize: false` (so replacements are not minified / gallery-rewritten / raw-markdown-unwrapped).
- Then walks the fragment bottom-up (`BottomUpReducer`) and joins child text.

**Block / line-break markup** (`PlainTextConversion`)
- `p`, `h1`–`h6`: child text, trailing newlines stripped, then `"\n\n"`.
- `div`: child text + `"\n"`.
- `br`: `"\n"`.
- `ul`/`ol`: block (`"\n\n"`) plus an extra leading `"\n"` when nested inside another list.
- `li`: `"#{indent}#{bullet} #{text}\n"`; `•` for `ul` or parentless `li`; `"#{index+1}."` for `ol`; indent is two spaces per extra list depth.
- `blockquote`: wrap first/last non-whitespace in `“` / `”`; whitespace-only → `"“”"`.
- `figcaption`: `"[#{text}]"`.
- `script` / `style`: `""` (inner text dropped). Other unknown elements pass children through (so `<strong>Hello </strong>world!` → `"Hello world!"`).
- Trailing newlines of the whole result are chomped.
- Deep nesting is converted (10_000 levels in the existing test).

**Entities / script-like text**
- Named/numeric entities in text nodes decode: `"<p>asdf &lt; asdf &amp; asdf &gt; asdf</p>"` → `"asdf < asdf & asdf > asdf"`; `"Hello&nbsp;world"` → `"Hello\u00A0world"`; `"&lt;script&gt;alert()&lt;/script&gt;"` → `"<script>alert()</script>"` (not html_safe).
- Real `<script>` / `<style>` elements are omitted: `"<div>safe<script>unsafe</script></div>"` → `"safe"`.
- `#to_plain_text` does **not** run the HTML sanitizer. `onclick` is irrelevant to the string. Sanitization is a `#to_s` / layout concern.

**Attachment captions / filenames** (`Attachment#to_plain_text`)
- If attachable implements `attachable_plain_text_representation(caption)`, that return value is used as the replacement string.
- Else the node `caption` attribute, or `""` if absent. Caption is **not** wrapped in `[]` unless the attachable does it.
- ActiveStorage::Blob ([`engine.rb`](actiontext/lib/action_text/engine.rb) L59–L61): `"[#{caption || filename}]"`. Observed: caption `"Vroom vroom"` → `"[Vroom vroom]"`; no caption → `"[racecar.jpg]"`.
- RemoteImage ([`remote_image.rb`](actiontext/lib/action_text/attachables/remote_image.rb) L43–L45): `"[#{caption || "Image"}]"`. Filename on the node is **ignored**. Observed: caption `"Cat"` → `"[Cat]"`; no caption → `"[Image]"` even with `filename="photo.jpg"`.
- MissingAttachable ([`missing_attachable.rb`](actiontext/lib/action_text/attachables/missing_attachable.rb) L24–L26): always `"☒"`, caption ignored. Observed for missing sgid, destroyed blob (even with caption `"Gone"`), and non-URL image path `url="image.png"`.
- ContentAttachment ([`content_attachment.rb`](actiontext/lib/action_text/attachables/content_attachment.rb) L20–L22): the inner HTML reparsed as `Content`, then that fragment’s source is returned and then run through plain-text conversion. Observed: `content="&lt;p&gt;abc&lt;/p&gt;"` and `content="<p>abc</p>"` both canonicalize to `content="<p>abc</p>"` on the node and `#to_plain_text` → `"abc"`; `content="<p>Hello</p><p>World</p>"` → `"Hello\n\nWorld"`.
- Attachable without the hook (dummy `Page`, `Person`): caption only. Observed: Page with `"Captioned"` → `"Captioned"` (no brackets); Page/Person with no caption → `""`.

**Duplicate attachables**
- Each node is converted independently. Same blob twice, one with caption: `"Hello [racecar.jpg] world [Again]"`. No dedup in plain text (dedup exists only for `RichText` embeds, [`model_test.rb`](actiontext/test/unit/model_test.rb) L55–L61).

**Galleries**
- Canonicalization unwraps `.attachment-gallery` to a plain `<div>` keeping inner attachments ([`attachment_gallery.rb`](actiontext/lib/action_text/attachment_gallery.rb) L13–L17; [`content_test.rb`](actiontext/test/unit/content_test.rb) L127–L143).
- `#to_plain_text` does **not** call `render_attachment_galleries`. Adjacent gallery attachments concatenate with no extra separator.
- Observed: two missing gallery attachments with captions A/B → `"☒☒"` (captions ignored because missing).
- Same shape with real blobs, caption A and filename `report.txt` → `"[A][report.txt]"`.
- Gallery markup that preserved whitespace around children: `"\n  ☒\n  ☒"` (div contributes a trailing newline that the final chomp removes; interior whitespace/newlines remain).

**Nested attachment nodes**
- `fragment_by_minifying_attachments` clears inner HTML of every attachment on initialize ([`minification.rb`](actiontext/lib/action_text/attachments/minification.rb) L13–L17). Observed: `<action-text-attachment sgid="outer"><action-text-attachment sgid="inner" …></…></…>` canonical `#to_html` is `<action-text-attachment sgid="outer"></action-text-attachment>`, plain text `"☒"`. Inner node never reaches `#to_plain_text`.

**`with_full_attributes: false`**
- `#to_plain_text` always passes this.
- Default of `#render_attachments` / `attachment_for_node` is `true`: replacement attachment node is rebuilt from `full_attributes` (sgid + caption + attachable `content-type`/`filename`/`filesize`/`previewable`/…).
- `false` leaves the original node attributes. Observed for a blob node that only had `sgid` + `caption="Cap"`:
  - `render_attachments { |a| a }` → node gains `content-type`, `filename`, `filesize`, `previewable`.
  - `render_attachments(with_full_attributes: false) { |a| a }` → original attributes only.
- For Blob/RemoteImage/Missing, plain-text **string** is the same either way because caption/filename come from the attachable object, not from those extra attributes. The flag still matters: (1) identity of the object yielded to the block, (2) HTML of any replacement that serializes the attachment node, (3) attachables whose plain text would read filename/content-type off the node rather than the Ruby object.

**`#render_attachments` itself**
- Returns a **new** `Content`; original `#to_html` unchanged (observed).
- Dup’s the fragment (`Fragment#update`).
- If a node has a `content` attribute: sanitize it; write back only when present after sanitize. Observed: `content="<img src=&quot;.&quot; onerror=alert>"` → rendered node drops `onerror`; original keeps it. `content="<script></script>"` → attribute removed on the **result**; original keeps `content="<script></script>"`.
- Replacement is `node.replace(replacement.to_s)` unless `replacement.equal?(node)`. Returning the same node object (the default HTML render path) mutates that dup’d node in place and does not string-replace.
- Result is `Content.new(content, canonicalize: false)`. Existing proof: [`markdown_conversion_test.rb`](actiontext/test/unit/markdown_conversion_test.rb) L1124–L1136 (`RAW_MARKDOWN_TAG` survives).

### Assertion categories

1. **Exact string equality** of `#to_plain_text` (newlines, bullets, quotes, `☒`, brackets). Prefer `assert_equal`, not regex, except for sgids.
2. **Non-mutation**: before/after `#to_html` on the original; `fragment.source.object_id`; attachment `content` attribute.
3. **Replacement Content identity**: `#render_attachments` returns a different `Content`; `canonicalize: false` (raw markdown tags / inner HTML that canonicalize would strip must survive).
4. **`with_full_attributes`**: compare `attachment.to_html` / node attributes of the object yielded to the block, not only the plain-text string.
5. **Attachable class**: `MissingAttachable` vs `RemoteImage` vs `Blob` vs `ContentAttachment` vs app model, because that chooses the representation.
6. **Safety**: result is not `html_safe?`; encoded `<script>` decodes to a real script string.
7. **Canonical HTML** of the original: gallery unwrap, attachment minification, Trix figure conversion — assert `#to_html` still matches current canonicalize, then assert plain text derived from that.
8. **Repeatability**: `content.to_plain_text == content.to_plain_text`.

**Integration (do not use as the primary oracle for the refactor)**

### Checks that `#to_html` / canonical content are not mutated

On every characterization example, and as dedicated tests:

1. `html_before = content.to_html.dup`; `oid = content.fragment.source.object_id`; `content.to_plain_text`; then `assert_equal html_before, content.to_html` and `assert_equal oid, content.fragment.source.object_id`.
2. Same around `content.render_attachments(...) { ... }`: result is a different object; original HTML unchanged.
3. Attachment `content` attribute: original keeps unsanitized value; only the **returned** Content is sanitized / has empty content removed (mirror [`content_test.rb`](actiontext/test/unit/content_test.rb) L182–L203 which today only checks `to_trix_html`).
4. Canonical gallery/minify: `#to_html` still matches [`content_test.rb`](actiontext/test/unit/content_test.rb) L120–L143 (`minifies attachment markup`, gallery unwrap including nested `<blockquote>` and whitespace). `#to_plain_text` must run **after** that canonicalize, not skip it.
5. `render_attachments` must keep `canonicalize: false` on the result — already asserted for markdown tags at [`markdown_conversion_test.rb`](actiontext/test/unit/markdown_conversion_test.rb) L1124–L1136. Add a plain-text analogue: replacement string `"<div>x</div>"` must remain a div in `rendered.to_html`, not be rewritten.
6. Repeat `#to_plain_text` twice; also `#to_html` then `#to_plain_text` then `#to_html` again.

`Fragment#replace` already dups (`fragment.rb` L33–L47). A refactor that walks nodes in place on `source` would fail (1)–(3).
