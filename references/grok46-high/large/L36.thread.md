Proposed: `record.save!` raises `RecordInvalid` ([validations.rb](file:///home/user/workspace/repo/activerecord/lib/active_record/validations.rb#L52-L55)), not `RecordNotSaved`. Existing test fails. **Persisted + changed.** Same deferral ([many_test.rb](file:///home/user/workspace/repo/activestorage/test/models/attached/many_test.rb#L47-L58), [L829-L834](file:///home/user/workspace/repo/activestorage/test/models/attached/many_test.rb#L829-L834)). Proposed `save!` would persist unrelated dirty attributes as a side effect, or raise if those attributes are invalid.

**Return value.** `#attach` returns the attachment proxy ([many_test.rb](file:///home/user/workspace/repo/activestorage/test/models/attached/many_test.rb#L805-L809)). `#save!` returns `true`. Callers of `#attach!` would get `true` instead of the attachments. No current `#attach!` return-value test, so this would ship silently.

**Empty / nested arrays.** `#attach` already does `blobs + attachables.flatten`; empty assign becomes `DeleteMany` ([model.rb](file:///home/user/workspace/repo/activestorage/lib/active_storage/attached/model.rb#L243-L251); empty-list tests at [many_test.rb](file:///home/user/workspace/repo/activestorage/test/models/attached/many_test.rb#L289-L303)). Nested arrays stay flattened. The extra `save!` still double-saves or newly persists/deletes on new/changed records.

**Duplicate / existing blobs.** `#attach` concatenates `blobs + attachables`. Existing blob identity is handled in `CreateOneOfMany#find_attachment` and `persisted_or_new_attachments`. The diff does not fix or worsen that, except via the extra save.

**Pending changes.** On new/changed records, pending `attachment_changes` stay until the record is saved. `save!` would commit them immediately. On the failed immediate-save path, changes remain pending either way.

**Callbacks.** Double callbacks on the success path; new/changed `#attach!` would start firing save callbacks.

### Smallest corrected direction

Do **not** always call `record.save!`. Keep `#attach!` as a bang wrapper that honors `#attach`’s save-or-defer contract.

If the only goal is “validation failure raises like `save!`” on the immediate-save path:

```ruby
def attach!(*attachables)
  record.public_send("#{name}=", blobs + attachables.flatten)
  record.save! if record.persisted? && !record.changed?
  record.public_send("#{name}")
end
```

That avoids double-save, preserves deferral and return value, and raises `RecordInvalid` on validation failure / `RecordNotSaved` on callback abort. It is still a breaking exception-class change vs current tests (`RecordNotSaved` at [many_test.rb](file:///home/user/workspace/repo/activestorage/test/models/attached/many_test.rb#L824)). Mirror it in `Attached::One` if you take it.

If the goal is just a reliable bang counterpart, **keep the current `attach(...) || raise(RecordNotSaved, ...)`**. It already matches `#attach` and the tests.

Missing tests if anything is changed: `#attach!` return value on success; `#attach!` on new records and changed records must not persist; exception class *and* message; no double-save/callbacks on persisted+valid; One/Many parity.
