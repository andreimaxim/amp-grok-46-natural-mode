A refactor of `ActionController::ConditionalGet#fresh_when` and `#stale?` is safe only if the HTTP wire contract stays the same: validators on the response, 304 vs 200, empty vs rendered body, and Cache-Control. Do not assert private helpers (`combine_etags`, `etag_matches?`, `handle_conditional_get!`, etagger arrays). Drive every check from request headers in and status/body/headers out.

### Current behavior

`fresh_when` always writes validators first, then maybe short-circuits. `stale?` is that same write plus the inverted freshness boolean, which is what skips expensive work.

```text
fresh_when(object, etag:/weak_etag:/strong_etag:, last_modified:, public:, cache_control:, template:)
  response.cache_control.delete(:no_store)
  weak_etag ||= etag || object   unless strong_etag
  last_modified ||= object.updated_at || object.maximum(:updated_at)
  if strong_etag
    response.strong_etag = combine_etags(...)     # ETag: "hex"
  elsif weak_etag || template
    response.weak_etag   = combine_etags(...)     # ETag: W/"hex"
  end
  response.last_modified = last_modified          # HTTP-date, second precision
  response.cache_control[:public] = true if public
  response.cache_control.merge!(cache_control)
  head :not_modified if request.fresh?(response)  # 304, empty body

stale?(...)
  fresh_when(...)
  !request.fresh?(response)   # true => run the render block
```

Request freshness lives in `ActionDispatch::Http::Cache::Request#fresh?`:

- `If-None-Match` is split on commas and compared as opaque strings. `*` matches any non-nil response ETag. Weak (`W/"…"`) and strong (`"…"`) never match each other. A nil response ETag never matches, including `*`.
- `If-Modified-Since` is parsed with `Time.httpdate` (IMF-fixdate, RFC 850, asctime). Invalid/missing ⇒ no IMS condition. `not_modified?` is `if_modified_since >= response.last_modified`.
- `Last-Modified` is stored via `Time#httpdate`, so subsecond values truncate to whole seconds. Freshness compares the header value, not the original Time.
- Default (`strict_freshness = false`, pre-8.0): if both conditional headers are present, **both** must succeed (AND). One matching validator cannot rescue the other.
- `strict_freshness = true` (8.1+ default): if `If-None-Match` is present, **only** ETag is used; IMS is ignored. Else IMS is used.
- No request-method gate. GET, HEAD, QUERY, and POST all take the 304 path today if the request is fresh.

Cache-Control is a response-commit concern, not a freshness input:

- Validators with no other directive → `max-age=0, private, must-revalidate`.
- `public: true` → `public` instead of `private`.
- `cache_control:` merges after that (e.g. `{ no_cache: true }` → `no-cache`, optionally `public, no-cache`).
- `fresh_when` clears a prior `no_store`. A later `no_store` replaces the validator default with `no-store`. `no_store` does not by itself prevent a 304.

ETags are not just the object. `combine_etags` appends controller `etag { }` blocks (including `EtagWithTemplateDigest` on `ActionController::Base`, not on `ActionController::API`). `template: false` omits the digest; a named template or the implicit action template is part of the validator. Changing the template changes the ETag and busts 304.

`head :not_modified` sets status 304 and an empty body (304 is a no-content code). Validators already on the response stay there.

Existing tests already pin much of this: [`actionpack/test/controller/render_test.rb`](actionpack/test/controller/render_test.rb) (IMS, record/collection, weak/strong, `*`, template digest, `http_cache_forever`, `no_store` ordering), [`actionpack/test/controller/api/conditional_get_test.rb`](actionpack/test/controller/api/conditional_get_test.rb) (strict vs AND precedence, `*`), [`actionpack/test/dispatch/request_test.rb`](actionpack/test/dispatch/request_test.rb) (INM parsing, `*`, HTTP-date formats). Gaps worth targeting in a refactor suite: HTTP method, subsecond `Last-Modified`, and an explicit stale-block side effect (body presence is only an indirect proxy).

### Test matrix

Use `ActionController::TestCase` as the primary level: one tiny fixture controller per concern, `ActionView::FixtureResolver` when a template digest matters, and a `Struct` with `updated_at` / `cache_key` when a record is the validator. Capture ETags from a first unconditioned GET instead of reconstructing hex digests. Optionally keep a few `ActionDispatch::Request` / `Response` unit cases for header parsing/serialization only.

Do not stub `request.fresh?` or `combine_etags`. For block execution, increment a controller counter inside the `if stale?` branch.

### How this catches semantic drift

Each row is an input/output pair a client or cache would see. Weak/strong prefix and cross-strength INM catch a hasher that forgets `W/` or treats weak and strong as equal. `*` vs IMS-only catches matching against a nil ETag. Dual-header rows catch flipping AND vs ETag-precedence, including an accidental global `strict_freshness` change. Subsecond IMS catches comparing a usec Time to an HTTP-date. GET/HEAD/POST catches introducing or removing a method gate. public/private/`no_store` catch commit-order changes that alter caching without changing 304. Template mutate-and-replay catches dropping the digest or hashing the wrong template. The counter catches `stale?` returning the wrong boolean even if status happens to look right.

Reuse the existing files as the regression baseline; add only the gap rows (method, subsecond, block counter) rather than a parallel suite. If a candidate refactor needs a new private structure, these checks still pass as long as the table’s status, body, and headers do not move.
