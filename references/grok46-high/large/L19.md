**Verdict: reject.** Do not merge. The claim is false at this revision.

A deterministic equality predicate is not “current-scheme ciphertext only.” `ExtendedDeterministicQueries` exists to bind every stored form SQL can see. `EncryptedAttributeType#deserialize` can try current, then `previous:`, then plaintext. `WHERE`/`find_by` cannot. Removing expansion leaves reads of legacy rows working and lookups of those same rows returning nil.

Expansion already no-ops when `previous_types` is empty (no `previous:` and `support_unencrypted_data` off). The proposed cut only deletes the documented `extend_queries` contract.

Verified by disabling the `previous_types` expansion in `EncryptedQuery.process_arguments` and running the encryption tests (sqlite3_mem). Existing failures: `extended_deterministic_queries_test.rb` lines 12, 29, 71, 83. Probe cases for arrays, `find_by` cache, `previous:` with `fixed: false`, and downcase/unencrypted also failed. Source restored after the run.

### Query vs read

- **Read/decrypt:** `deserialize` → current decrypt → `previous_types` → plaintext if `support_unencrypted_data?`. `find(id)`, `reload`, and attribute readers keep working.
- **Query:** `where` / `exists?` / `Base.find_by` rewrite hash predicates to `[value, AdditionalValue(previous_type)...]`. Previous types include configured `previous:` schemes plus a `NullEncryptor` clean-text type when unencrypted data is supported. That is what makes `IN (current, old ciphertext, plaintext)` match mixed rows.

`downcase` / `ignore_case` encrypted rows already match via current `serialize` (both downcase before encrypt). They do not justify dropping expansion. Unencrypted rows and `previous:` rows do.

`ignore_case`’s `original_<column>` is a **read** path (`preserve_original_encrypted`). Queries hit `name`, not `original_name`.

### Minimal failing examples

Models as in `activerecord/test/models/book_encrypted.rb`; `extend_queries` on.

**1. `where(email: value)` / unencrypted**

```ruby
ActiveRecord::Encryption.config.support_unencrypted_data = true
UnencryptedBook.create!(name: "jorge@hey.com")
EncryptedBook.where(name: "jorge@hey.com").first # => nil after the change
EncryptedBook.find(id).name                      # => "jorge@hey.com" (read still works)
```

Existing: `test_Finds_records_when_data_is_unencrypted`.

**2. Array predicates**

```ruby
EncryptedBook.create!(name: "encrypted@hey.com")
UnencryptedBook.create!(name: "plain@hey.com")
EncryptedBook.where(name: ["encrypted@hey.com", "plain@hey.com"]).map(&:name)
## current: both; after change: ["encrypted@hey.com"]
```

**3. `find_by`**

```ruby
UnencryptedBook.create!(name: "jorge@hey.com")
EncryptedBook.find_by(name: "jorge@hey.com") # => nil
```

`CoreQueries.find_by` expands *before* statement cache so the SQL becomes `IN (...)`. Without expansion, cache stays `name = $1` bound to current ciphertext.

**4. Prepared/bound `find_by`**

```ruby
EncryptedBook.create!(name: "cached@hey.com")
EncryptedBook.find_by(name: "cached@hey.com")      # caches current-scheme equality
UnencryptedBook.create!(name: "later-plain@hey.com")
EncryptedBook.find_by(name: "later-plain@hey.com") # => nil after change
```

**5. Per-attribute `support_unencrypted_data` overrides global**

```ruby
## global false, attribute true — existing test line 83
ActiveRecord::Encryption.config.with(support_unencrypted_data: false) do
  UnencryptedBook.create!(name: "plain@hey.com")
  EncryptedBookWithUnencryptedDataOptedIn.find_by(name: "plain@hey.com") # => nil
  EncryptedBookWithUnencryptedDataOptedIn.find(id).name                  # still "plain@hey.com"
end

## global true, attribute false — still nil (opt-out remains correct)
EncryptedBookWithUnencryptedDataOptedOut.find_by(name: "plain@hey.com") # nil before and after
```

Clean-text previous type is gated by `scheme.support_unencrypted_data?`, not only the global flag.

**6. `previous:` key rotation (query ≠ decrypt)**

Use `deterministic: { fixed: false }` so new writes use the new key. Default `fixed: true` encrypts with the oldest scheme, which can hide the bug.

```ruby
old = Class.new(ActiveRecord::Base) do
  self.table_name = "encrypted_books"
  encrypts :name, deterministic: true, key: "old secret key!!!!"
end
row = old.create!(name: "Dune")

new = Class.new(ActiveRecord::Base) do
  self.table_name = "encrypted_books"
  encrypts :name, deterministic: { fixed: false }, key: "new secret key!!!!",
           previous: [{ deterministic: true, key: "old secret key!!!!" }]
end

new.find(row.id).name        # => "Dune"  (decrypt via previous:)
new.find_by(name: "Dune")    # => nil after change
new.where(name: "Dune").first
```

`encryption_schemes_test` “use global previous schemes when performing queries” is not enough: with `fixed: true`, query serialize already uses the oldest scheme.

**7. `downcase`**

```ruby
EncryptedBookWithDowncaseName.create!(name: "Dune")
EncryptedBookWithDowncaseName.find_by(name: "DUNE") # still works (current serialize downcases)

UnencryptedBook.create!(name: "dune")
EncryptedBookWithDowncaseName.find_by(name: "DUNE") # => nil after change
```

**8. `ignore_case` + `original_name`**

```ruby
book = EncryptedBookThatIgnoresCase.create!(name: "Dune")
book.name; book.original_name # "Dune" / "Dune" — read path, independent of expansion
EncryptedBookThatIgnoresCase.find_by(name: "DUNE") # still works when row is encrypted

## unencrypted stored value (support_unencrypted_data true):
create_unencrypted_book_ignoring_case(name: "Dune")
EncryptedBookThatIgnoresCase.find(id).name # => "Dune" (reader)
## query still needs clean-text expansion; even today clean-text serialize downcases,
## so find_by(name: "dune") may miss stored "Dune". Regression should query the stored case
## and assert read of original_name is unchanged.
EncryptedBookThatIgnoresCase.find_by(name: "Dune") # nil if expansion removed
```

### Focused regressions (add, don’t redesign)

Keep them in `extended_deterministic_queries_test.rb` (or schemes test for rotation):

1. `where(name: plaintext)` finds unencrypted row; `find(id)` still decrypts/returns plaintext.
2. `where(name: [encrypted_value, plaintext])` returns both.
3. `find_by(name: plaintext)` on `Base` and on a relation.
4. Encrypted `find_by` then later plaintext `find_by` (statement cache).
5. Attribute `support_unencrypted_data: true` with global false finds plaintext; attribute false with global true does not; both still `find(id)`.
6. `previous:` + `deterministic: { fixed: false }`: `find(id)` reads old ciphertext; `where`/`find_by` match; control without `previous:` does not match.
7. `downcase: true` + unencrypted stored downcased value is found; encrypted mixed-case still found.
8. `ignore_case: true`: encrypted `find_by` ignores case; `original_name` still holds original case on read; unencrypted stored original case is found via `where(name: stored_value)` when support is on.

Do not replace expansion with a new query API. Either keep it, or drop `extend_queries` and document that mixed plaintext / rotated-key lookup is unsupported. The patch as proposed is the latter without the documentation.
