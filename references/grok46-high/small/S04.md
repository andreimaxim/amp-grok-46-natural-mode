`content_for` is a write-or-read helper over `@view_flow` (`ActionView::OutputFlow`). A call is a **write** when it has a content argument or a block; otherwise it is a **read**. Writes always return `nil`. Reads return `@view_flow.get(name).presence`, so missing or blank stored content is `nil`.

### Write path: block vs direct content

```ruby
def content_for(name, content = nil, options = {}, &block)
  if content || block_given?
    if block_given?
      options = content if content
      content = capture(&block)
    end
    if content
      options[:flush] ? @view_flow.set(name, content) : @view_flow.append(name, content)
    end
    nil
  else
    @view_flow.get(name).presence
  end
end
```

- **Direct content** (`content_for :title, "foo"`): the second argument is stored as-is after `to_s`. No `capture`.
- **Block** (`content_for :title do ... end`): the second argument, if present, is treated as **options**, not content. The block is run through `capture`, and only a truthy capture result is stored.

`capture` temporarily replaces `@output_buffer`’s raw string (same buffer object), yields, then restores the parent buffer. Template output written inside the block therefore does not leak into the view body.

What `capture` stores:

- If the block returns the output buffer itself, use the captured chunk, not the parent buffer.
- Else `buffer.presence || value`. Whitespace-only buffer output is `blank?`, so `presence` is `nil`. A whitespace ERB block that returns `nil` therefore stores **nothing**.
- Then coerce: `OutputBuffer#to_s` (html_safe), pass through `SafeBuffer`, or `ERB::Util.html_escape` a raw `String`. Non-strings become `nil` and are not stored.

### Append order vs `flush: true`

`OutputFlow` keeps a Hash of `SafeBuffer`s, defaulting missing keys to empty safe buffers.

- Default write: `@view_flow.append` → `SafeBuffer#<<` in call order. `content_for :title, "foo"` then `content_for :title, :bar` reads as `"foobar"`.
- `flush: true`: `@view_flow.set` **replaces** the buffer with a new `SafeBuffer`. Earlier writes for that name are discarded.
- A write whose captured/direct content is falsy (`nil`, `false`) is a no-op even with `flush: true`. Flushing a whitespace-only block that captures to `nil` leaves previous content in place. Flushing `""` does replace with an empty buffer.

### Read vs write returns, and `content_for?`

| Call | Returns |
|---|---|
| Write (content or block) | always `nil` |
| Read, content present | the `SafeBuffer` |
| Read, missing/blank | `nil` |

`content_for?(name)` is `@view_flow.get(name).present?`. Empty or whitespace stored content is not “present”.

Layout `yield :name` is **not** the same as `content_for(:name)`: `_layout_for` does `view_flow.get(name).html_safe` and does **not** apply `presence`, so a missing name yields an empty safe buffer rather than `nil`.

### Safety for the view buffer

Captured output is already a `SafeBuffer` before it is stored:

1. Block path: `capture` escapes raw strings and marks buffer output html_safe.
2. Direct append: `SafeBuffer#<<` HTML-escapes anything that is not already `html_safe?`.
3. `set` (`flush: true`) wraps `value.to_s` in a new `SafeBuffer` (marks safe; block content was already escaped by `capture`).
4. On read, the stored `SafeBuffer` is returned. When the layout buffer does `<<`, `html_safe?` is true, so it is concatenated without a second escape.

That is why `<%= content_for :title %>` / `<%= yield :title %>` can splice named content into the layout without double-escaping, and why a raw string passed as direct content is escaped on append unless it was already marked safe (`raw`, `content_tag`, etc.).
