`travel_to` freezes “now” for the rest of the test (or for a block) by replacing four class methods. It lives in [`activesupport/lib/active_support/testing/time_helpers.rb`](file:///home/user/workspace/repo/activesupport/lib/active_support/testing/time_helpers.rb). `travel` and `freeze_time` are thin wrappers around it. Stubs are always cleared in `after_teardown` via `travel_back`.

```text
travel_to(date_or_time, with_usec: false)
  reject nested block-form travel_to
  normalize date_or_time → now (a Time)
  zero usec unless with_usec
  now = now.getlocal          # system TZ
  stub Time.now, Time.new, Date.today, DateTime.now
  if block
    in_block = true
    yield
    restore previous travel or travel_back
    in_block = false
```

### Input normalization

Three branches, then one shared finish.

**`Date` (not `DateTime`)** — treated as midnight in the **application** time zone:

```ruby
now = date_or_time.midnight.to_time
```

`Date#midnight` is `in_time_zone`, so `Date.new(2023, 12, 1)` becomes `2023-12-01 00:00` in `Time.zone`. `Time.current` / `Date.current` then agree with that date. `Time.now` / `Date.today` may not, if system TZ and app TZ disagree — which is why the docs tell you to prefer `*.current`.

**`String`** — parsed in the application zone:

```ruby
now = Time.zone.parse(date_or_time)
```

`"2004-11-24 01:04:44"` means that wall time in `Time.zone`, not in `ENV["TZ"]`. Fractional seconds in the string are still dropped later unless `with_usec: true`.

**Everything else** (`Time`, `DateTime`, `TimeWithZone`, …):

```ruby
now = date_or_time
now = now.to_time unless now.is_a?(Time)
```

`TimeWithZone` counts as `Time` (it overrides `is_a?`), so it is left alone. `DateTime` is a `Date` but also a `DateTime`, so it misses the Date branch and is converted with `DateTime#to_time` (same UTC offset).

Then:

1. `now = now.change(usec: 0)` unless `with_usec: true`
2. `now = now.getlocal` so the stubs below see **system** local time

`Time.at(now)` and `now.to_date` both follow `now`’s zone. That is why the getlocal step exists: stubbed `Time.now` is always a process-local `Time`, even if you passed a UTC `Time`, a zoned `DateTime`, or an app-zone string.

### What is stubbed

`SimpleStubs` aliases each method on the object’s singleton class, then defines a new singleton method. If this helper instance already stubbed that method, it unstubs first so the “original” is always real Ruby, not a stub chain. Subsequent non-block `travel_to` calls therefore replace, they do not nest.

| Call | Stub |
|---|---|
| `Time.now` | `Time.at(now)` |
| `Time.new` | see below |
| `Date.today` | `Date.jd(now.to_date.jd)` |
| `DateTime.now` | `DateTime.jd(date, hour, min, sec + subsec, offset as day fraction)` |

Subclasses (`TimeSubclass.now`, `DateSubclass.today`, …) are **not** stubbed. They keep their own class methods and only happen to match if they delegate to the stubbed `Time` / `Date` / `DateTime` methods.

`Time.current`, `Date.current`, and `Time.zone.now` are not stubbed directly. They pick up the freeze because they call `Time.now` (or equivalent) underneath.

### `Time.new` with arguments

```ruby
stubs.stub_object(Time, :new) do |*args, **options|
  if args.empty? && options.empty?
    at(now)
  else
    Time.send(stub.original_method, *args, **options)
  end
end
```

- `Time.new` with no args and no kwargs → same frozen instant as `Time.now`.
- Any positional args (`Time.new(2021)`, `Time.new(2004, 11, 25)`) → real `Time.new`.
- Any kwargs, including `Time.new(precision: 3)` → real `Time.new`, **not** the frozen clock.

That last case is easy to miss: `precision:` is enough to bypass the stub.

### `with_usec`

Default `false` zeros microseconds **before** stubbing, on purpose: MySQL rounds fractional seconds instead of flooring, which otherwise produced off-by-one-second failures.

```ruby
travel_to Time.utc(2014, 10, 10, 10, 10, 50, 999999)
## Time.now.usec      => 0
## DateTime.now.usec  => 0
```

`with_usec: true` keeps the fraction. `DateTime.now` uses `now.sec + now.subsec`, so it preserves usec too. `travel` / `freeze_time` forward the same flag.

### Block cleanup

Before installing stubs, `travel_to` snapshots whether `Time.now` is **already** stubbed by this helper:

```ruby
stubbed_time = Time.now if stubs.stubbing(Time, :now)
```

After the block (`ensure`, so it runs on raise too):

```diagram
┌─────────────────────────┐
│ already traveling?      │
└────────────┳────────────┘
      no     ┃      yes
             ┃
     ┌───────▼───────┐   ┌──────────────────────┐
     │ travel_back   │   │ travel_to stubbed_time│
     │ (real clock)  │   │ (restore outer freeze)│
     └───────────────┘   └──────────────────────┘
```

So:

```ruby
travel_to outer_time          # non-block: freeze stays
travel_to inner_time do
  # inner_time
end
## outer_time again, not real time
```

If there was no prior freeze, the block ends on the real clock. `in_block` is cleared after restore.

`travel_back` itself unstubs everything this helper installed. In a block it temporarily unstubs, yields, then re-`travel_to`s the time it captured.

### Why nested block-form `travel_to` is rejected

```ruby
if block_given? && in_block
  raise <<~MSG
    Calling `travel_to` with a block, when we have previously already made a call to `travel_to`, can lead to confusing time stubbing.
    ...
  MSG
end
```

`in_block` is set only while a **block-form** `travel_to` on **this** object is running. A second block-form call on the same object raises `RuntimeError`.

The failure mode the message describes: the inner argument is evaluated against the already-frozen clock.

```ruby
travel_to 2.days.from_now do
  travel_to 3.days.from_now do
    # 5 days from real now, not 3
  end
end
```

Cleanup would also fight itself: each block’s `ensure` either `travel_back`s or restores a snapshot, so nested blocks would restore the wrong clock.

What **is** allowed:

| Pattern | Result |
|---|---|
| Block inside block (same helper) | `RuntimeError` |
| Non-block `travel_to` inside a block | Inner time wins until the **outer** block `ensure` restores |
| Block `travel_to` while a non-block travel is active | Allowed; outer freeze restored after the block |
| Sequential non-block `travel_to` | Last call wins |
| Nested blocks on a **different** `TimeHelpers` object | Allowed; each object has its own `in_block` and `SimpleStubs` |

For a Rails test author: use one block-form `travel_to` per scope, or `travel 2.days` / `travel 5.days` as separate blocks. Inside a freeze, `Time.new` without arguments is frozen; `Time.new(...)` with any args is not.
