Verification of a claimed `#touch` refactor has to be public: same exceptions and messages, same in-memory and persisted attributes, same dirty/saved-change sets, same `lock_version` rules, same user callbacks, same UPDATE row counts. Do not prove preservation by comparing `_touch_row`, `_update_row`, `@_trigger_update_callback`, or other private helpers.

Documented contract: no validation; only `after_touch`, `after_commit`, and `after_rollback` run; the record must be persisted and not readonly; extra names share the touch time with `updated_at`/`updated_on`; aliases resolve to real columns. Useful fixtures: `Developer` (aliased timestamps), `Topic`/`Person` (real timestamps; locking on `Person`), `Task` (custom `starting`/`ending`), `Car` (no timestamps), `Company` (new-record error).

**Persisted / new / destroyed / readonly.** On a found record, `touch` is truthy (typically `1`), timestamps advance in memory and after `reload`, and persistence flags stay the same. `Model.new.touch` and `destroyed_record.touch` both raise `ActiveRecord::ActiveRecordError` with `Cannot touch on a new or destroyed record object…`; no SQL, no callbacks, and destroy must not resurrect the row. `readonly!` then `touch` raises `ReadOnlyRecord` (`"#{Model} is marked as readonly"`). Touching a readonly attribute (`person.touch(:born_at)`) raises `ActiveRecordError` (`"born_at is marked as readonly"`).

**Default timestamps, custom attrs, aliases.** Bare `touch` on `Topic` updates `updated_at`/`updated_on` only; `created_*` stay put; `saved_changes` and the UPDATE SET list match those columns. On `Developer`, alias readers and real columns (`legacy_updated_at`/`legacy_updated_on`) both advance, but `saved_changes.keys` are the real names. `task.touch(:ending)` writes only that column (plus update timestamps if present). `Car.first.touch` does not raise; `after_touch` still runs if registered, `after_commit(on: :update)` does not.

**Explicit `time:`.** `touch(time: Time.utc(2015, 2, 16, 0, 0, 0))` and `touch(:created_at, time: …)` write that exact time to every touched column in memory and after reload. Omitted `time:` follows `travel`.

**Optimistic locking (`Person`).** Fresh `touch` bumps `lock_version` in memory and DB, clears `#changed?`, and puts `lock_version` plus timestamps in `saved_changes`. A stale copy raises `StaleObjectError`, leaves `#saved_changes?` false, and does not keep an incremented lock. Inside `preserve_lock_version_on_touch`, `lock_version` does not change, a stale copy does not raise, and a later `touch` outside the block still bumps.

**Dirty tracking.** With an unsaved `salary` change, `touch` keeps `#changed?` / `#salary_changed?`, does not mark timestamps dirty, puts only touched columns in `saved_changes`, and `reload` restores `salary` — dirty attributes must not be written.

**Callbacks.** User `after_touch` runs once on success (and still runs on rollback). `after_commit` / `after_commit(on: :update)` run only on outermost commit; `after_rollback` / `after_rollback(on: :update)` run on `Rollback`. `before_validation`, `after_save`, `after_update`, etc. stay silent. `Model.no_touching { touch }` changes nothing and skips `after_touch`.

**No row updated.** Without locking, delete the row then `touch` the still-`persisted?` object: no exception, return `0` (truthy, so the implicit transaction commits), in-memory timestamps assigned, no INSERT, `after_touch` runs, `after_commit(on: :update)` does not. With locking, the same situation is `StaleObjectError`. A default scope that excludes the record is the inverse: `becomes(DeveloperCalledJamis).touch` must still persist new timestamps.
