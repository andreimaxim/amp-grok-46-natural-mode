## Assistant

`Rails::Engine.isolate_namespace` is class-definition setup, not request dispatch. It stamps the engine as isolated, rewrites `engine_name` from the namespace module, installs a RouteSet `default_scope` of `{ module: underscored_name }` (controller lookup only — no path/`as` prefix), and defines namespace methods used later by controllers, helpers, models, and mount. Request-time effects are consequences of that stamp: engine routes resolve `foo#index` to `Namespace::FooController`, isolated controllers get the engine’s url helpers instead of the app’s, mount helpers default to the rewritten `engine_name`, and `main_app` is a separate mounted helper defined on the application.

### Class-level setup vs request-time dispatch

Two clocks:

- **Class definition / boot.** `isolate_namespace` runs while the engine class body is evaluating. Initializers later copy that state into a RouteSet, register the set with the app reloader, and wire controller/mailer inheritance.
- **Request / URL generation.** `Engine#call` builds a request, sets `req.routes`, and hands off to `endpoint` (custom Rack app or the RouteSet). Journey then constantizes `params[:controller]`. URL helpers and mount proxies run on that already-configured RouteSet.

### What `isolate_namespace` actually does

[`Rails::Engine.isolate_namespace`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L384-L421) is a class method. `Rails::Application#isolate_namespace` only forwards to it ([`application.rb:391-392`](file:///home/user/workspace/repo/railties/lib/rails/application.rb#L390-L392)).

In order:

1. `engine_name(generate_railtie_name(mod.name))`
2. `config.default_scope = { module: ActiveSupport::Inflector.underscore(mod.name) }`
3. `self.isolated = true`
4. If `mod` does not already `respond_to?(:railtie_namespace)`, define on `mod.singleton_class`:
   - `railtie_namespace` → the engine class
   - `table_name_prefix` unless already defined
   - `use_relative_model_naming?` → `true` unless already defined
   - `railtie_helpers_paths` → `railtie.helpers_paths`
   - `railtie_routes_url_helpers` → `railtie.routes.url_helpers(include_path_helpers)`

`isolated?` is just an alias of the class attribute `isolated` ([`engine.rb:354-355, 437`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L354-L356)). Default is `nil`/falsey until `isolate_namespace` runs. The only boot use is [`prepend_helpers_path`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L663-L667): isolated engines do **not** push `app/helpers` onto the application, unless `app == self` (an application isolating itself).

Calling `isolate_namespace` twice on the **same module** does not replace `railtie_namespace` / `table_name_prefix` / url-helper methods. The second engine still gets its own `engine_name`, `isolated = true`, and `default_scope`. Test: [`engine_test.rb` “using namespace more than once…”](file:///home/user/workspace/repo/railties/test/railties/engine_test.rb#L1226-L1251) — `AppTemplate.railtie_namespace` stays `AppTemplate::LoadedFirst::Engine`.

### `engine_name`

[`engine_name` is an alias of `railtie_name`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L356). [`Railtie.railtie_name`](file:///home/user/workspace/repo/railties/lib/rails/railtie.rb#L178-L181) setter/getter; default `generate_railtie_name(self.name)` = `underscore(class_name).tr("/", "_")` ([`railtie.rb:250-252`](file:///home/user/workspace/repo/railties/lib/rails/railtie.rb#L250-L252)).

Without isolation, `MyEngine::Engine` → `"my_engine_engine"`. `isolate_namespace MyEngine` **overwrites** that with `generate_railtie_name("MyEngine")` → `"my_engine"`. Nested: `isolate_namespace Bukkits::Awesome` → `"bukkits_awesome"`.

That name is used as:

- default `mount` `:as` (see mount helpers)
- rake namespace `#{railtie_name}:install:migrations`
- captured `name` in the `table_name_prefix` closure (`"#{name}_"`)

**Explicit `engine_name`:** docs show `engine_name "my_engine"` as a manual override ([`engine.rb:184-190`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L184-L190)). There is **no** test combining an explicit `engine_name` with `isolate_namespace`. Order matters in the source: `isolate_namespace` always assigns `engine_name(...)` first, then captures that value for `table_name_prefix`. An `engine_name` call **before** `isolate_namespace` is overwritten. A call **after** changes `railtie_name` / mount `:as` / rake task name, but **not** the already-closed-over table-name prefix.

Evidence of the isolated rewrite: [`engine_test.rb:951-952`](file:///home/user/workspace/repo/railties/test/railties/engine_test.rb#L951-L952) `assert_equal "bukkits", Bukkits::Engine.engine_name`.

### `railtie_routes_url_helpers` and controller lookup wiring

This method is **not** used at dispatch. It is used when a controller/mailer class is inherited.

[`AbstractController::Railties::RoutesHelpers.with(app.routes)`](file:///home/user/workspace/repo/actionpack/lib/abstract_controller/railties/routes_helpers.rb#L10-L21) is extended onto Action Controller ([`action_controller/railtie.rb:81`](file:///home/user/workspace/repo/actionpack/lib/action_controller/railtie.rb#L81)) and Action Mailer (`include_path_helpers = false`, [`action_mailer/railtie.rb:41`](file:///home/user/workspace/repo/actionmailer/lib/action_mailer/railtie.rb#L41)). On `inherited`:

- if some `module_parents` responds to `railtie_routes_url_helpers`, include **that** engine’s `routes.url_helpers`
- else include **application** `routes.url_helpers`

So `Bukkits::FooController` gets `foo_path` from `Bukkits::Engine.routes`, not `bar_path` from the app. Test: mailer `respond_to?(:foo_url)` / not `bar_url`; `/bukkits/from_app` body `"false"` for `bar_path` and app helper `something` ([`engine_test.rb:954-958`](file:///home/user/workspace/repo/railties/test/railties/engine_test.rb#L954-L958)).

Helpers follow the same parent walk via [`ActionController::Railties::Helpers`](file:///home/user/workspace/repo/actionpack/lib/action_controller/railties/helpers.rb#L8-L21): isolated controllers set `helpers_path` to `namespace.railtie_helpers_paths` (the engine’s `app/helpers`), not the application list. Combined with `prepend_helpers_path` skipping isolated engines, app helpers are not in the isolated controller. Engine helpers can still be pulled into the app with `helper Engine.helpers` (documented; gathered in [`Engine#helpers`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L507-L516), test [`engine_test.rb:1413`](file:///home/user/workspace/repo/railties/test/railties/engine_test.rb#L1413)).

Every Action Controller still `include app.routes.mounted_helpers` ([`railtie.rb:80`](file:///home/user/workspace/repo/actionpack/lib/action_controller/railtie.rb#L80)), so `main_app` and other engines’ mount helpers exist even on isolated controllers.

### Route-set creation and controller lookup (the routing effect)

[`Engine::Configuration`](file:///home/user/workspace/repo/railties/lib/rails/engine/configuration.rb#L9-L48) starts with `route_set_class = ActionDispatch::Routing::RouteSet`, `default_scope = nil`. Isolation sets `default_scope`.

[`Engine#routes`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L552-L570) lazily does `config.route_set_class.new_with_config(config)`. [`RouteSet.new_with_config`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/route_set.rb#L369-L388) copies `default_scope` onto the set.

When routes are drawn, [`eval_block`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/route_set.rb#L476-L484):

```ruby
if default_scope
  mapper.with_default_scope(default_scope, &block)
else
  mapper.instance_exec(&block)
end
```

[`with_default_scope`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/mapper.rb#L655-L659) is `scope(**scope)` — here `scope(module: "bukkits")`. [`merge_module_scope`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/mapper.rb#L1222-L1224) concatenates with `/`. That is **not** `namespace :bukkits`: no path prefix, no `as` prefix. Isolated `resources :posts` is still `/posts` inside the engine, targeting `bukkits/posts#…`.

Nested namespace: `isolate_namespace Bukkits::Awesome` → `module: "bukkits/awesome"`. Test [`engine_test.rb:1035-1068`](file:///home/user/workspace/repo/railties/test/railties/engine_test.rb#L1035-L1068): `get "/foo" => "foo#index"` serves `Bukkits::Awesome::FooController` at `/bukkits/foo` after mount.

**Request-time** lookup is ordinary constantize. [`Request#controller_class_for`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/http/request.rb#L91-L110) takes `params[:controller]` (`"bukkits/foo"`), camelizes, appends `Controller`. Isolation already wrote that module into the route defaults at draw time. [`Engine#call` / `build_request`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L540-L542) only sets `req.routes = routes` and `req.engine_script_name`.

### Engine with no route file

[`routes?`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L706-L708) is `@routes` truthiness. Unit test [`railties/test/engine_test.rb:6-14`](file:///home/user/workspace/repo/railties/test/engine_test.rb#L6-L14) asserts false when `@routes` is forced nil.

At boot, [`make_routes_lazy`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L616-L619) **always calls `routes`**, which instantiates the RouteSet. Then [`add_routing_paths`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L621-L632):

```ruby
if routes? || routing_paths.any?
  app.routes_reloader.paths.unshift(*routing_paths)  # empty if no config/routes.rb
  app.routes_reloader.route_sets << routes
  app.routes_reloader.external_routes.unshift(*external_paths)
end
```

So after boot, an engine with no `config/routes.rb` still has an (empty) RouteSet registered as default endpoint. Mounting it without drawing routes yields no matches. Isolation’s `default_scope` is still on that empty set and would apply if something later calls `routes.draw`.

### Mount helpers and `main_app`

[`Mapper#mount`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/mapper.rb#L605-L657): if `as:` was omitted (`DEFAULT`), `as = app_name(app, rails_app)`. For a Railtie, that is `app.railtie_name` — i.e. isolated `engine_name`. Then `define_generate_prefix` installs a `script_namer` on **the engine’s** RouteSet via `app.routes.define_mounted_helper(name, script_namer)` so engine-generated URLs include the mount point (and dynamic segments like `:user`).

[`RouteSet#define_mounted_helper`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/route_set.rb#L520-L538) defines methods on the **shared** `RouteSet::MountedHelpers` module (`return if method_defined?(name)`). [`RoutesProxy`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/routes_proxy.rb) merges `script_name` from the namer with the request `SCRIPT_NAME`.

[`Finisher#define_main_app_helper`](file:///home/user/workspace/repo/railties/lib/rails/application/finisher.rb#L60-L62) is `app.routes.define_mounted_helper(:main_app)` with no script_namer — application routes, no extra mount prefix.

### Lazy vs eager route loading

[`make_routes_lazy`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L616-L619) (before `bootstrap_hook`, on **every** engine including the application):

```ruby
config.route_set_class = LazyRouteSet if Rails.env.local?
routes
```

[`Rails.env.local?`](file:///home/user/workspace/repo/activesupport/lib/active_support/environment_inquirer.rb#L14-L39) is development or test. So local boot instantiates `Rails::Engine::LazyRouteSet`; production keeps `ActionDispatch::Routing::RouteSet`.

[`Finisher#set_routes_reloader_hook`](file:///home/user/workspace/repo/railties/lib/rails/application/finisher.rb#L160-L180):

```ruby
reloader.execute_unless_loaded if !app.routes.is_a?(Engine::LazyRouteSet) || app.config.eager_load
```

Eager (production, or `config.eager_load`): routes drawn during boot. Lazy: first touch calls [`Application#reload_routes_unless_loaded`](file:///home/user/workspace/repo/railties/lib/rails/application.rb#L168-L170) → [`RoutesReloader#execute_unless_loaded`](file:///home/user/workspace/repo/railties/lib/rails/application/routes_reloader.rb#L50-L76).

[`LazyRouteSet`](file:///home/user/workspace/repo/railties/lib/rails/engine/lazy_route_set.rb) wraps `call`, `draw`, `recognize_path`, `routes`, `polymorphic_mappings`, url-helper `method_missing` (only `_path`/`_url` suffixes), and a parallel `MountedHelpers` that reloads on missing **non**-`_path`/`_url` methods (so `plugin_engine` can be defined by `mount` during the delayed draw). Isolation does not change this; an isolated engine in a local app gets a LazyRouteSet with the isolated `default_scope` already in config.

Tests in [`railties/test/engine/lazy_route_set_test.rb`](file:///home/user/workspace/repo/railties/test/engine/lazy_route_set_test.rb): app and engine url helpers missing until invoked; request to `/` and `/plugin/` loads; mounted helpers lazy; `execute_unless_loaded` only the first caller draws.

### Externally visible routing summary

After `isolate_namespace Bukkits` and `mount Bukkits::Engine => "/bukkits"`:

| Surface | Isolated engine | Non-isolated engine |
|---|---|---|
| Route helper names inside engine | `foo_path` | often app helpers too |
| Controller for `get "/foo" => "foo#index"` | `Bukkits::FooController` | `FooController` unless you `namespace` |
| URL path inside engine | `/foo` (plus mount SCRIPT_NAME → `/bukkits/foo`) | same mount behavior |
| App reaching engine URLs | `bukkits.foo_path` (default `:as` = `"bukkits"`) | `bukkits_engine.foo_path` unless `engine_name`/`as:` set |
| Engine reaching app URLs | `main_app.bar_path` | `main_app` still defined; also raw app helpers if not isolated |
| Form/param keys | `post[title]` | `bukkit_post[title]` without relative naming |
| App helpers in engine views | absent | present via `prepend_helpers_path` |

Isolation never itself mounts the engine or adds a URL prefix. The prefix is `mount`. Isolation only changes how the engine’s own RouteSet interprets `controller: "foo"` and which helper module controllers inherit.
