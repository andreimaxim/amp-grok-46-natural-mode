**Reject.** Escaping in `safe_concat` inverts the trusted-append contract, would break every HTML ERB template, and does not make capture safer. `CaptureHelper#capture` already escapes returned ordinary strings.

### Contracts

| API | Escapes? | Nil | Role |
|---|---|---|---|
| [`OutputBuffer#<<`](file:///home/user/workspace/repo/actionview/lib/action_view/buffers.rb#L42-L53) | Yes unless `html_safe?` (`unwrapped_html_escape`) | ignored | untrusted append |
| [`#safe_concat` / `#safe_append=`](file:///home/user/workspace/repo/actionview/lib/action_view/buffers.rb#L56-L58) | **No** | `TypeError` | trusted append |
| [`#capture`](file:///home/user/workspace/repo/actionview/lib/action_view/buffers.rb#L72-L79) | N/A | N/A | swap `@raw_buffer`; return **writes** as `html_safe`; **ignore block return** |
| [`RawOutputBuffer#<<`](file:///home/user/workspace/repo/actionview/lib/action_view/buffers.rb#L97-L101) | **No** | ignored | explicit raw bypass |
| [`CaptureHelper#capture`](file:///home/user/workspace/repo/actionview/lib/action_view/helpers/capture_helper.rb#L47-L66) | Yes for returned `String`; pass-through for `SafeBuffer` / `OutputBuffer#to_s` | `nil` | writes if present, else return value |

Erubi compiles static HTML onto `safe_append=` as a **plain frozen String**, not `html_safe`:

```ruby
@output_buffer.safe_append='<div>'.freeze; @output_buffer.append=( name ); @output_buffer.safe_append='</div>'.freeze;
```

That matches [`SafeBuffer#safe_concat`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/string/output_safety.rb#L66-L69): concatenate without escaping. `#<<` is the escaping path.

### Observable output

Current vs proposed `@raw_buffer << ERB::Util.html_escape(value)`:

| Input | Current `safe_concat` | Proposed |
|---|---|---|
| `"<script>x</script>"` | `"<script>x</script>"` | `"&lt;script&gt;x&lt;/script&gt;"` |
| `"<p>ok</p>".html_safe` | `"<p>ok</p>"` | `"<p>ok</p>"` (`html_escape` no-ops `html_safe?`) |
| `"<div>".freeze` + `<< "alice"` + `"</div>".freeze` | `"<div>alice</div>"` | `"&lt;div&gt;alice&lt;/div&gt;"` |
| `nil` | `TypeError` | `""` |
| `65` | `"A"` (`String#<<` codepoint) | `"65"` |
| other `OutputBuffer` that `<< "<b>x</b>"` | `"&lt;b&gt;x&lt;/b&gt;"` | same (`OutputBuffer#html_safe?` is always true) |
| other `OutputBuffer` filled via `#raw << "<script>raw</script>"` | `"<script>raw</script>"` | **same — still unescaped** |

`CaptureHelper#capture`:

| Block | Result |
|---|---|
| `output_buffer << "<em>x</em>"; nil` | `"&lt;em&gt;x&lt;/em&gt;"` (`<<` already escaped) |
| `output_buffer.safe_concat "<em>x</em>"; nil` | `"<em>x</em>"` |
| return `"<em>x</em>"` | `"&lt;em&gt;x&lt;/em&gt;"` — **already escaped** |
| write `"<b>written</b>"` **and** return `"<script>returned</script>"` | `"&lt;b&gt;written&lt;/b&gt;"` — writes win; return discarded |
| write `""` and return `"<script>returned</script>"` | escaped return (`buffer.presence` blank) |
| return `@output_buffer` after writing | captured writes via `equal?`, no re-escape |
| nested write + return | only non-blank **writes** of each capture |

Capture of ordinary returned strings is already safe. Nested write+return is not a `safe_concat` problem.

### Findings

#### 1. Critical — inverts trusted append; breaks every HTML ERB template

`safe_concat` / `safe_append=` is the compiled-template path for literal markup. Ordinary strings here are author HTML, not untrusted input. Escaping them turns `<div>alice</div>` into `&lt;div&gt;alice&lt;/div&gt;`.

Callers that would regress:

- Erubi/Herb `add_text` ([erubi.rb](file:///home/user/workspace/repo/actionview/lib/action_view/template/handlers/erb/erubi.rb#L29-L39))
- annotate-filenames preamble/postamble
- `cache` → `safe_concat(fragment_for(...))` ([cache_helper.rb](file:///home/user/workspace/repo/actionview/lib/action_view/helpers/cache_helper.rb#L180))
- streaming: `output.safe_concat view._layout_for` ([streaming_template_renderer.rb](file:///home/user/workspace/repo/actionview/lib/action_view/renderer/streaming_template_renderer.rb#L85))

`html_escape` leaving `html_safe?` values alone does **not** save ERB: compiled literals are plain frozen Strings.

Existing contract test:

```14:19:actionview/test/buffers_test.rb
    test_case.test "#safe_append= bypasses HTML safety" do
      @buffer.safe_append = "<p>This is fine</p>"
      assert_predicate @buffer, :html_safe?
      assert_predicate output, :html_safe?
      assert_equal "<p>This is fine</p>", output
```

#### 2. High — capture claim is wrong; this is not a security fix

[`CaptureHelper#capture`](file:///home/user/workspace/repo/actionview/lib/action_view/helpers/capture_helper.rb#L47-L66) already isolates writes, prefers captured writes if present, and escapes only a returned ordinary `String`. Tests: `test_capture_escapes_html`, `test_capture_doesnt_escape_twice`.

Escaping in `safe_concat` would **worsen** `capture do %> <div><%= user %></div> <% end`: the `<div>` would be escaped while user text was already escaped by `<<`. XSS from `safe_concat(user_input)` is API misuse. The patch does not even close `safe_concat(output_buffer_with_raw)` because `OutputBuffer#html_safe?` is always true.

#### 3. High — `StreamingBuffer#safe_concat` left unchanged

[buffers.rb](file:///home/user/workspace/repo/actionview/lib/action_view/buffers.rb#L121-L123) still does `@block.call(value.to_s)`. Shared tests would then disagree across buffer types; streaming vs buffered rendering would diverge on the same template.

#### 4. Medium — silent contract changes for `nil` and Integer

- `nil`: `TypeError` → append `""`. `<<` and `RawOutputBuffer` ignore nil.
- Integer: `String#<<` codepoint (`65` → `"A"`) → `"65"`.
- Extra allocation: `html_escape` wraps a SafeBuffer; `<<` uses `unwrapped_html_escape` for a reason.

#### 5. Low — helpers that `safe_concat` SafeBuffers would limp along

`button_to`, `grouped_options_for_select`, `time_zone_options_for_select` mostly `safe_concat` `content_tag` / `options_for_select` results. Those would still work and hide the ERB break. `safe_concat "\n"` is a no-op under escape.

---

### Compatibility / security

- **Compatibility:** breaking for all HTML ERB/Herb templates, fragment cache contents, annotated views, streaming layouts without a layout template.
- **Security:** does not fix a capture bug. Slightly reduces misuse of `safe_concat` on plain strings, while leaving `html_safe?` / `OutputBuffer` / `#raw` holes open and encouraging people to treat `safe_concat` as “the escaping concat,” which it is not (`<<` is).
- **Correct layer:** `CaptureHelper#capture` (already there). If a hole exists, it is “writes via `safe_concat` of untrusted ordinary strings,” the same hole as doing that outside capture.
