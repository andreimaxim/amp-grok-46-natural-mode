**Verdict: reject.** The keyword default does not make `separator ||= ""` redundant. Explicit `separator: nil` is a documented empty-separator path; deleting the line turns it into a `TypeError`.

### Why the claim is wrong

`separator: "-"` only applies when the keyword is omitted. Passing `separator: nil` still arrives as `nil`. The line is the conversion of that `nil` to `""`, not a restatement of the default.

Current contract:

```124:128:activesupport/lib/active_support/inflector/transliterate.rb
## To remove the unwanted characters instead of replacing them, pass an
## empty separator. `nil` is treated the same way.
#
## ```
## parameterize("Donald E. Knuth", separator: '') # => "donaldeknuth"
```

```150:157:activesupport/lib/active_support/inflector/transliterate.rb
def parameterize(string, separator: "-", preserve_case: false, locale: nil)
  separator ||= ""
  parameterized_string = transliterate(string, locale: locale)
  parameterized_string.gsub!(/[^a-z0-9\-_]+/i, separator)
```

`String#parameterize` just forwards the keyword, so the same `nil` hits Inflector:

```242:244:activesupport/lib/active_support/core_ext/string/inflections.rb
def parameterize(separator: "-", preserve_case: false, locale: nil)
  ActiveSupport::Inflector.parameterize(self, separator: separator, preserve_case: preserve_case, locale: locale)
end
```

### Observable behavior

| call | today | after deletion |
|---|---|---|
| omitted / `separator: "-"` | `"donald-e-knuth"` | unchanged |
| `separator: ""` | `"donaldeknuth"` | unchanged |
| `separator: nil` | same as `""` → `"donaldeknuth"` | **TypeError** |

First downstream break: `gsub!(regex, nil)` raises `TypeError: no implicit conversion of nil into String` (confirmed in Ruby). If that were skipped, `unless separator.empty?` would then raise `NoMethodError`.
