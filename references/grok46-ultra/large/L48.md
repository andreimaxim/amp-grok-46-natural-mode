## Behavior-preservation verification strategy for `railties/lib/rails/test_help.rb`

Reorganizing this file is not a structural refactor. Requiring it mutates process-global test-framework state through `ActiveSupport.on_load`, `include`, `class_attribute` assignment, and method definition. Ruby `require` is idempotent; the hooks are not `run_once`. Verification must pin **observable test execution**, not ancestor lists or class-variable dumps.

Source of truth: [`railties/lib/rails/test_help.rb`](file:///home/user/workspace/repo/railties/lib/rails/test_help.rb), [`activesupport/lib/active_support/lazy_load_hooks.rb`](file:///home/user/workspace/repo/activesupport/lib/active_support/lazy_load_hooks.rb), [`activerecord/lib/active_record/test_fixtures.rb`](file:///home/user/workspace/repo/activerecord/lib/active_record/test_fixtures.rb), [`activesupport/lib/active_support/testing/file_fixtures.rb`](file:///home/user/workspace/repo/activesupport/lib/active_support/testing/file_fixtures.rb), [`railties/lib/rails/engine.rb`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb) (`:add_fixture_paths`), generated [`test_helper.rb.tt`](file:///home/user/workspace/repo/railties/lib/rails/generators/rails/app/templates/test/test_helper.rb.tt).

### 1. Current public effects (from source)

At require time the file:

1. `abort`s if `Rails.env.production?`.
2. Requires `active_support/test_case`, `rails/generators/test_case`, `active_support/testing/autorun`, `rails/testing/maintain_test_schema`.
3. Branches on `defined?(ActiveRecord::Base)` **at require time**, not at hook-run time.

#### With Active Record

On `:active_support_test_case` (runs immediately: `test_help` requires `active_support/test_case`, which already called `run_load_hooks`):

- `include ActiveRecord::TestDatabases`
- `include ActiveRecord::TestFixtures` → defines `class_attribute :fixture_paths, default: []` and runs `:active_record_fixtures` hooks (engines append here)
- `include ActiveRecord::Assertions::QueryAssertions`
- `self.fixture_paths = [*self.fixture_paths, "#{Rails.root}/test/fixtures/"].uniq`
- `self.file_fixture_path = "#{Rails.root}/test/fixtures/files"`

On `:action_dispatch_integration_test`:

- `self.fixture_paths += ActiveSupport::TestCase.fixture_paths` — **no `uniq`**

#### Without Active Record

Only `file_fixture_path` is set on `ActiveSupport::TestCase`. No `TestFixtures`, no `fixture_paths`, no IntegrationTest path copy, no query assertions, no test-database parallel hooks. `maintain_test_schema.rb` is a no-op.

#### Always

Both `ActionController::TestCase` and `ActionDispatch::IntegrationTest` get:

```ruby
def before_setup
  @routes = Rails.application.routes
  super
end
```

This is evaluated **per test**, so it follows `Rails.application` across boots. Path assignment is not.

#### Path shape that must not change

| Setting | Form |
|---|---|
| `fixture_paths` entry | `"#{Rails.root}/test/fixtures/"` — **String, trailing slash** |
| `file_fixture_path` | `"#{Rails.root}/test/fixtures/files"` — **String, no trailing slash** |

`Rails.root` is a Pathname; interpolation yields an absolute string. Engine extra paths from `:add_fixture_paths` are also `"#{fixtures}/"` strings.

#### Load-hook / `require` semantics that must not change

- Hooks are **not** `run_once: true`.
- `require "rails/test_help"` is a no-op the second time (`$LOADED_FEATURES`).
- `load` of the same file re-registers hooks and **re-runs them on already-loaded bases**.
- `on_load` on an already-loaded class runs the block immediately against that class, then stores it for future `run_load_hooks`.
- Path interpolation uses `Rails.root` at **hook execution**, not at file parse time.

#### Inheritance (`class_attribute`)

- Subclass that never assigned `fixture_paths` / `file_fixture_path` reads the parent after `test_help` assigns.
- Subclass that assigned before `require` keeps its own value; parent assignment does not overwrite it.
- `fixture_paths +=` on `IntegrationTest` **assigns a new array on that class**, copying parent paths even though they were already inherited. Current result when parent is `["#{root}/test/fixtures/"]`:

  `ActionDispatch::IntegrationTest.fixture_paths == ["#{root}/test/fixtures/", "#{root}/test/fixtures/"]`

  That duplication is current behavior. ASTC uses `.uniq`; IntegrationTest does not. Do not “fix” this in a no-public-effect reorganization.

#### Engine / extra paths

`Rails::Engine` initializer `:add_fixture_paths` (skipped for `Rails::Application`) registers:

```ruby
ActiveSupport.on_load(:active_record_fixtures) { self.fixture_paths |= ["#{fixtures}/"] }
```

Those hooks run when `TestFixtures` is included, **before** `test_help`’s `fixture_paths = [*…, app_path].uniq`. Extra engine paths therefore survive and then get copied (and duplicated) onto `IntegrationTest`.

Generated plugin `test_helper.rb` **overwrites** both after `require "rails/test_help"`:

```ruby
ActiveSupport::TestCase.fixture_paths = [ File.expand_path("fixtures", __dir__) ]
ActionDispatch::IntegrationTest.fixture_paths = ActiveSupport::TestCase.fixture_paths
ActiveSupport::TestCase.file_fixture_path = File.expand_path("fixtures", __dir__) + "/files"
```

Preserve that post-require overwrite still winning.

#### Multiple boots in one process

First `require` freezes paths to the then-current `Rails.root`. A later boot does **not** refresh `fixture_paths` / `file_fixture_path`. `@routes` in `before_setup` **does** follow the new `Rails.application`. `maintain_test_schema!` has already run against the first boot.

#### Missing fixture directory

`test_help` does not stat the directory. A missing `test/fixtures` still gets the path string. `fixtures :all` uses `Dir[]` (empty). `file_fixture("x")` raises `ArgumentError` with `the directory '%s' does not contain a file named '%s'`. Named YAML fixtures fail later in `FixtureSet`, not at require.

#### Relative vs absolute vs duplicates

- Default paths are absolute because `Rails.root` is absolute.
- Pre-set relative entries are kept; the absolute app path is appended; ASTC `.uniq` is **string** uniqueness (`"test/fixtures/"` ≠ `"/abs/test/fixtures/"`).
- Exact-string duplicates are collapsed on ASTC only.
- Pathname vs String of the same location are **not** collapsed by `uniq`.

### 2. What “behavior preservation” means here

A reorganization is safe iff a generated app’s tests still:

- load YAML fixtures by name (`users(:david)`),
- resolve file fixtures (`file_fixture("hello.txt").read`),
- upload via `fixture_file_upload` in an integration test,
- dispatch integration requests using app routes (`get posts_path` / `get "/posts"`),
- expose `assert_queries_count` when AR is present and **not** when AR is absent,
- abort in production,
- autorun,
- call `maintain_test_schema!` when AR is present.

Inspecting `ActiveSupport::TestCase.fixture_paths` is supporting evidence only. It can stay green while `fixtures :all` stops seeing YAML, while `file_fixture` points at the wrong tree, or while IntegrationTest duplicates change load order.

### 3. Observable assertions (black-box)

Put these in a **fresh app subprocess** (`build_app` + `rails test`), not in the railties test process. Pattern already used in [`railties/test/application/test_test.rb`](file:///home/user/workspace/repo/railties/test/application/test_test.rb) and [`integration_test_case_test.rb`](file:///home/user/workspace/repo/railties/test/application/integration_test_case_test.rb).

Shared app setup:

```ruby

## test/fixtures/users.yml          → david: { name: David }
## test/fixtures/files/hello.txt    → hello
## config/routes.rb                 → resources :users
## UsersController#index            → render plain: User.find_by!(name: "David").name
```

#### A. Default ASTC + IntegrationTest (AR present)

```ruby
class FixtureAccessTest < ActiveSupport::TestCase
  fixtures :users
  test "yaml fixture" do
    assert_equal "David", users(:david).name
  end
  test "file fixture" do
    assert_equal "hello", file_fixture("hello.txt").read
  end
  test "query assertion is available" do
    assert_queries_count(1) { User.find_by!(name: "David") }
  end
end

class FixtureIntegrationTest < ActionDispatch::IntegrationTest
  fixtures :users
  test "routes + yaml + upload" do
    get users_path
    assert_response :success
    assert_equal "David", response.body
    file = fixture_file_upload("hello.txt", "text/plain")
    assert_equal "hello", File.read(file.path)
  end
end
```

Expect `0 failures, 0 errors`. This is the primary regression net.

#### B. Inherited / subclass settings

```ruby
class ParentOwnsPaths < ActiveSupport::TestCase; end

class ChildOverrides < ActiveSupport::TestCase
  self.fixture_paths = ["#{Rails.root}/test/alt_fixtures/"]
  self.file_fixture_path = "#{Rails.root}/test/alt_fixtures/files"
end
## alt_fixtures/items.yml and alt_fixtures/files/alt.txt exist

class ChildOverridesTest < ChildOverrides
  fixtures :items
  test "override is not clobbered by parent" do
    assert_equal "alt", items(:one).name
    assert_equal "alt-file", file_fixture("alt.txt").read
  end
end

class ParentOwnsPathsTest < ParentOwnsPaths
  fixtures :users
  test "inherits parent paths set by test_help" do
    assert_equal "David", users(:david).name
  end
end
```

Do **not** assert array equality as the only check. Assert which records/files resolve.

#### C. Class defined before vs after `require`

In a one-off `test_helper.rb` (do not use the generated one):

```ruby
require_relative "../config/environment"

class BeforeRequireTest < ActiveSupport::TestCase
  # body filled after require, or use class_eval after
end

require "rails/test_help"

class BeforeRequireTest
  fixtures :users
end

class AfterRequireTest < ActiveSupport::TestCase

end
```

Both tests must load `users(:david)`. Same matrix for `ActionDispatch::IntegrationTest` subclasses: `get users_path` must work (the `before_setup` `@routes` hook is on the parent class, so both before and after subclasses see it).

If a before-require subclass **assigned** `fixture_paths` to a custom dir, that assignment must still win after require (override case in B).

#### D. Repeated `require`

```ruby
require "rails/test_help"
require "rails/test_help" # no-op
fixtures :users
assert_equal "David", users(:david).name
get users_path # integration
```

Must not double-include in a way that breaks `before_setup` super chains, must not make `fixtures :all` load each YAML twice, must not change `file_fixture` resolution.

Optional negative: `load File.expand_path(".../rails/test_help.rb")` a second time. Current IntegrationTest behavior **appends again** (`+=` without `uniq`). Preserve that if the reorganization still allows `load`; if the file becomes split, `load` of a new entrypoint is a public-effect change and needs an explicit decision.

#### E. Application-configured extra fixture paths

Three distinct setups; all must keep resolving **both** trees:

1. **Pre-require append** via the supported extension point:

   ```ruby
   # config/initializers/extra_fixtures.rb
   ActiveSupport.on_load(:active_record_fixtures) do
     self.fixture_paths |= ["#{Rails.root}/test/extra_fixtures/"]
   end
   ```

   `test/extra_fixtures/items.yml` + default `users.yml`. A test with `fixtures :all` (generated helper) must see both `users(:david)` and `items(:one)`.

2. **Mounted engine** with `test/fixtures/bukkits.yml`. Existing coverage: [`railties/test/railties/engine_test.rb`](file:///home/user/workspace/repo/railties/test/railties/engine_test.rb) `"adds its fixtures path to fixture_paths"` — that only checks the `:active_record_fixtures` hook, **not** `test_help`. Add an isolation test that boots the engine, requires `rails/test_help`, and loads `bukkits(:one)` from an `ActiveSupport::TestCase`.

3. **Post-require overwrite** (plugin helper). After `test_help`, assign engine fixture dir. Default app `users.yml` must **stop** resolving; engine fixtures must resolve. IntegrationTest must follow because plugin helper assigns it explicitly.

#### F. Relative vs absolute vs duplicate vs missing dir

| Case | Setup | Observable |
|---|---|---|
| Absolute (default) | stock `test_help` | `users(:david)` + `file_fixture("hello.txt")` |
| Relative extra path | initializer `fixture_paths \|= ["test/extra_fixtures/"]` (relative) | `items(:one)` loads **only if cwd is `Rails.root`** during `rails test` — that is how `Dir[File.join(path, …)]` works. Assert load succeeds under `rails test`. |
| Duplicate exact string | initializer adds `"#{Rails.root}/test/fixtures/"` again | ASTC `.uniq` → `fixtures :all` still loads each set once; no double-insert error. IntegrationTest may contain the path twice; `fixtures :users` must still load once. |
| Duplicate via `+=` on IntegrationTest | stock | Integration test `fixtures :users` still works. Do not assert “paths are unique” on IntegrationTest. |
| Missing `test/fixtures` | delete/rename the dir; keep `files/` or not | require succeeds; `file_fixture("hello.txt")` raises `ArgumentError` matching the interpolated `file_fixture_path`; `fixtures :users` fails at load, not at require. A test that never calls fixtures still runs. |
| Missing `test/fixtures/files` | YAML present, `files/` absent | `users(:david)` works; `file_fixture("hello.txt")` raises the ArgumentError naming that path. |

#### G. Active Record absent

`build_app` then comment out `active_record/railtie` (or generate with `--skip-active-record`). Generated helper already omits `fixtures :all` ([`shared_generator_tests.rb`](file:///home/user/workspace/repo/railties/test/generators/shared_generator_tests.rb)).

Assert:

- `file_fixture("hello.txt").read == "hello"` still works.
- `ActiveSupport::TestCase.respond_to?(:fixture_paths)` is false (or `fixtures :users` raises) — supporting check.
- `refute_respond_to` on `assert_queries_count`.
- Integration `get "/posts"` still succeeds (routes hook is AR-independent).
- No `PendingMigrationError` abort from `maintain_test_schema`.

#### H. Multiple boots in one process

Single test file, **one process**, no Isolation fork between boots:

```ruby
require "test_helper" # boots app A, require test_help, paths → A

class AfterFirstBoot < ActiveSupport::TestCase
  fixtures :users
  test "uses first root" do
    assert_equal "David", users(:david).name
  end
end

## boot app B with a different Rails.root and different users.yml ("Eve")
## do not re-require test_help

class AfterSecondBoot < ActiveSupport::TestCase
  test "paths still point at first root" do
    assert_equal "David", users(:david).name  # still A's fixture
  end
end

class RoutesFollowNewApp < ActionDispatch::IntegrationTest
  test "before_setup uses current Rails.application.routes" do
    get "/b_only_route"
    assert_response :success
  end
end
```

This is the assertion that catches a reorganization that re-runs path hooks on boot. Current code must keep A’s paths and B’s routes.

Practical note: booting two apps in one process is hostile; if full dual-boot is too brittle in railties isolation tests, a weaker in-process probe is: after `require "rails/test_help"`, stub `Rails.root` to a new Pathname and `require` again, then assert `file_fixture_path` is **unchanged**. That matches `require` idempotency. The dual-boot test is the stronger pin for “hooks don’t re-fire.”

### 4. Isolation / cleanup (or regressions hide)

`test_help` writes process-global state: `$LOADED_FEATURES`, `on_load` hook arrays, `class_attribute` values on `ActiveSupport::TestCase` / `ActionDispatch::IntegrationTest` / `ActionController::TestCase`, `Minitest.autorun`, `ActiveRecord::TestFixtures` `@@already_loaded_fixtures`, `Rails.application`, `ENV["RAILS_ENV"]`.

**Do this:**

- Every new case lives in `railties/test/application/` and `include ActiveSupport::Testing::Isolation` so each test forks (see [`activesupport/lib/active_support/testing/isolation.rb`](file:///home/user/workspace/repo/activesupport/lib/active_support/testing/isolation.rb)).
- `build_app` / `teardown_app` from [`railties/test/isolation/abstract_unit.rb`](file:///home/user/workspace/repo/railties/test/isolation/abstract_unit.rb). `teardown_app` restores `Rails.app_class`, `Rails.application`, `RAILS_ENV`, and deletes `tmp`.
- Run the assertions **inside the generated app** via `rails test` (`assert_successful_test_run` / `assert_match /0 failures, 0 errors/`). That gives a clean `$LOADED_FEATURES` and hook table.
- `ENV["PARALLEL_WORKERS"] = "0"` in setup (as `test_test.rb` does). Parallel workers plus fixture-path mutations hide ordering bugs.
- Never `require "rails/test_help"` in the railties test process itself when testing require effects.
- Production-abort and dual-boot cases: extra subprocess, not the forked isolation child that still shares the point of requiring AR.

**Do not:**

- Mutate `ActiveSupport::TestCase.fixture_paths` in a non-isolated railties test and restore it — `class_attribute` plus `@@already_loaded_fixtures` plus already-included modules will leak.
- Rely on `Object#with` here; these are not `cattr_accessor` config flags.
- Clear `@load_hooks` / `@loaded` manually; that is more invasive than the code under test.
- Run these next to `test_runner_test.rb` parallelization cases in the same process.

### 7. Reorganization traps this strategy is meant to catch

| Change that looks equivalent | Observable break |
|---|---|
| Combine ASTC `uniq` into IntegrationTest `+=` | IntegrationTest path list changes; `fixtures :all` set identity / cache key (`@fixture_cache_key` includes `fixture_paths.dup`) |
| Use `Rails.root.join("test/fixtures")` (Pathname, no slash) | `uniq` vs engine strings; `fixtures :all` slice math; cache keys |
| `run_once: true` on hooks | `load` / future second boot behavior |
| Move AR branch inside the hook (`defined?` at run vs require) | App that loads AR after `test_help` suddenly gets fixtures |
| Set paths in an initializer instead of `on_load` | Classes defined before boot miss assignment; IsolationTest copy order changes |
| Include `TestFixtures` before engine `:active_record_fixtures` hooks are registered | Engine fixtures disappear |
| Refresh paths on every boot | Dual-boot test (H) fails |
| Drop IntegrationTest `+=` because “it inherits” | Plugin helpers and any code that mutates ASTC paths after IntegrationTest assigned would diverge; also the duplicated array is a distinct object (in-place `<<` on ASTC would no longer show up on IntegrationTest — which is the *point* of `+=`) |
| Set `file_fixture_path` only in the AR branch | skip-AR apps lose `file_fixture` |
| `before_setup` via `setup { @routes = ... }` instead of overriding | super/callback order vs `Runner#before_setup` (`@app = nil`) and `TestFixtures#before_setup` |

The last IntegrationTest row is the one class-variable tests miss most easily: `+=` copies, so later `ActiveSupport::TestCase.fixture_paths << extra` does **not** appear on IntegrationTest. Preserve that copy-on-assign.

### 8. Pass/fail bar

The reorganization is behavior-preserving when:

1. All commands in §5 stay green.
2. New isolation tests for A–I stay green, asserting fixture records, file contents, HTTP responses, query-assertion availability, and abort text — not `assert_equal` on the path arrays except as a secondary diagnostic.
3. A skip-AR app still runs an integration test and `file_fixture`.
4. `require` twice in one app process does not change those observables.
5. A second boot in one process does **not** retarget fixture paths but **does** retarget `@routes`.

If a reorganization wants to change any of those (especially IntegrationTest duplication or dual-boot path freeze), that is a public-effect change and needs its own changelog, not a silent reshape of `test_help.rb`.
