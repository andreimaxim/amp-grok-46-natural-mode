`ActionView::LookupContext` holds view paths plus a mutable details hash (locale, formats, variants, handlers). Find does not search from that hash directly. It builds a `Requested` details object, walks `ActionView::PathSet`, and lets `FileSystemResolver` pick `UnboundTemplate`s whose filename details match, then bind locals.

```text
LookupContext#find(name, prefixes, partial, keys, options)
  normalize_name
  detail_args_for(options) → [details_hash, details_key]
  PathSet#find
    for each prefix, then each resolver:
      FileSystemResolver#find
        requested = details_key || TemplateDetails::Requested.new(**details)
        unbound_templates_for(name, prefix, partial, cached: !!details_key)
        find_best_by_details → UnboundTemplate
        UnboundTemplate#bind_locals(keys)
```

`#find_all` is the same until the resolver: it returns every matching template, sorted, instead of the single best. `#find!` is `#find` or `ActionView::MissingTemplate`.

### Mutable details versus cache keys

`@details` on LookupContext is a Hash. Setters (`formats=`, `locale=`, `variants=`) write it in place. After a `details_key` or `digest_cache` has been materialized, `_set_detail` dups the hash first so interned keys stay immutable.

The resolver cache key is not that Hash. `DetailsKey.details_cache_key` interns a `TemplateDetails::Requested` from the hash (`Concurrent::Map`, keyed by Hash equality). `Requested` holds index maps: earlier list entries get a lower integer, so they rank first. `nil` (no locale/format/variant/handler in the filename) is always appended and therefore always matches, last.

`LookupContext#details_key` returns that interned object only when `@cache` is true. Cache off → `details_key` is `nil`. The resolver then rebuilds `Requested` per call and skips the unbound-template map.

Same details content reuses the same `Requested` object. That is why toggling locale `:en` → `:da` → `:en` reuses the original key, and why `formats = nil` (reset to defaults) reuses the key from before `formats = [:html]`.

Handlers are still inside `@details` and inside `Requested`, despite a comment on `details_key` that claims they are omitted.

### Normalization before lookup

**Name.** `normalize_name` stringifies the name. A `/` splits off a path prefix: `"admin/foo"` with prefixes `["users"]` becomes name `"foo"`, prefixes `["users/admin"]`. No prefixes → `[path_prefix]`. Leading `/` on the prefix is stripped.

**Formats** (`formats=`):

- Dup, then `values.delete "*/*"`. `Mime::ALL` is `Mime::AllType` with string `"*/*"`, so `==` matches and it is removed.
- If `"*/*"` / `Mime::ALL` was present, concatenate `default_formats` (`ActionView::Base.default_formats`, which Action Pack sets to `Mime.symbols`).
- `uniq!`, then `Template.validate_formats`.
- If the list is exactly `[:js]`, append `:html` and set `@html_fallback_for_js = true`.

`DetailsKey` also filters formats when building a key: `Template.normalized_formats` returns `formats & Types.symbols` only when the list is not already valid symbols; otherwise it returns nil and the hash is used as-is. Invalid symbols are therefore dropped from the interned key, not raised there.

**Locale.** The registered default is `[I18n.locale] + I18n.fallbacks[locale] + [I18n.default_locale]`, uniqued. The getter `locale` returns `@details[:locale].first`. The setter writes `I18n.config.locale` (skipping `I18nProxy` to avoid recursion) then replaces the details array with that default-locale list.

**Variants** default to `[]`. Empty/`nil` assignment resets to the registered default.

### PathSet into the resolver

PathSet typecasts strings/Pathnames to `FileSystemResolver`. Search order is prefix-major, then resolver order. `#find` returns the first template any resolver yields. `#find_all` returns the first non-empty array; it does not merge hits across prefixes or resolvers. Miss: `find` → `nil`, `find_all` → `[]`, `find!` → `MissingTemplate` listing `prefix/name` or `prefix/_name` plus `details.inspect`.

`FileSystemResolver`:

- Virtual path from `TemplatePath.virtual`: partial `"foo"` + prefix `"test"` → `"test/_foo"`.
- Names containing `.` yield no templates.
- Glob `#{virtual_path}*`, parse each file with PathParser (`locale`, `format+variant`, `handler`), keep exact virtual-path matches (case-sensitive).
- If `key` is present, those UnboundTemplates are cached by virtual path. If `key` is nil (cache disabled), the directory is globbed again.
- Match/rank with `TemplateDetails#matches?` / `#rank_for` / `#sort_key_for`. Rank tuple is `[format_idx, locale_idx, variant_idx, handler_idx]`; lower wins. `#find` takes the minimum; `#find_all` sorts the full matching set.

Locals never choose the file. After ranking, `UnboundTemplate#bind_locals(keys)` returns a `Template`. Non-strict templates cache one Template per normalized locals (`map(&:to_sym).sort`). Strict-locals templates (`<%# locals: (...) %>`) bind once and reuse that same Template for any locals list.

### Edge cases and observable results

`formats = [:js]`. Stored formats become `[:js, :html]`, `@html_fallback_for_js == true`. Lookup prefers a `.js` template, then `.html`. Test: [lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L64-L67).

`formats = [:js, Mime::ALL]`. `Mime::ALL` is deleted as `"*/*"`, then `default_formats` are appended: `[:js, *Mime.symbols].uniq`. Length is no longer 1, so the special JS→HTML fallback flag is not set (HTML is still present via Mime.symbols). Test: [lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L59-L62).

`formats = ["*/*"]`. Becomes `Mime.symbols` (or `default_formats`). Test: [lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L54-L57).

Invalid formats. `formats = [:html, :invalid, "also bad"]` raises `ArgumentError` with message `Invalid formats: :invalid, "also bad"` at assignment, before any find. Test: [lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L69-L75).

Locale ordering. Requested locales are tried in list order; a filename with no locale still matches, last. `find("hello_world", %w(test))` at `:en` selects `hello_world.erb` (“Hello world!”). After `locale = :da`, `hello_world.da.html.erb` (“Hey verden”) ranks above the generic file. `find_all` with `locale: [:fr]` when both `hello_world.fr.text.erb` and `hello_world.text.erb` exist returns `[fr, generic]`; `locale: [:en]` returns only the generic, and that generic object is `equal?` to the second French result. Tests: [lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L100-L107), [resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L124-L147). Arbitrary locales such as `:es_AR` and `:en_customer1` match if I18n knows them (PathParser unions `I18n.available_locales`).

Variant ordering. `variants = [:phone]` with `formats = [:html]` selects `hello_world.html+phone.erb` (“Hello phone!”); with `formats = [:text]` selects `hello_world.text+phone.erb` (“Hello texty phone!”). `find_all(..., variants: [:tricorder, :lcars])` returns `[tricorder, lcars]`; reversed variants reverse the array. `find` with a single variant returns only that file. `variants: :any` (used by `any?`) matches every variant; a file with no variant ranks first (`ANY_HASH` gives `nil => 0`, everything else 1). Tests: [lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L109-L121), [resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L187-L204).

Format list order. `find_all` with `formats: [:json, :html]` returns `[json, html]`; `[:html, :json]` returns `[html, json]`. Wrong details (e.g. format `:xml` against an `.html.erb`) return `[]`. Tests: [resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L92-L173).

Partial lookup. Third argument `true` looks for `_name`. `find("foo", %w(test), true)` uses virtual path `test/_foo`. `find!("foo", %w(parent child), true)` raises `MissingTemplate` with `Missing partial parent/_foo, child/_foo`. A name containing a dot (`hello_world.html`) returns no templates. Tests: [lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L275-L280), [resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L230-L234).

Locals. Locals do not change which UnboundTemplate wins. They only select the bound Template instance. Different non-strict locals → different Template objects; same locals (even different order, after sort) → same object. Strict-locals templates: `find_all(..., [:message])` and `find_all(..., [])` return the same Template, `strict_locals?` true, `locals` nil. Tests: [resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L258-L268), [file_system_resolver_test.rb](file:///home/user/workspace/repo/actionview/test/template/file_system_resolver_test.rb#L95-L121).

Cache on. Default `@cache = true`. Repeated `find` of the same name/details/locals returns the identical Template (`assert_same`). Changing locale invalidates `details_key` and can select a different UnboundTemplate; restoring locale restores the original object. `disable_cache` does not clear that cache. Tests: [lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L153-L177), [resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L102-L122).

Cache off. `disable_cache` sets `@cache = false` for the block, so `details_key` is nil, unbound templates are not stored, and `find` returns a new Template object (`assert_not_same`). After the block, `@cache` is restored and a later `find` returns the originally cached object. Tests: [lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L179-L194), [resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L110-L122).
