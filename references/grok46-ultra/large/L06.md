## `Array.wrap` control flow

`Array.wrap` is a class method on `Array` in [activesupport/lib/active_support/core_ext/array/wrap.rb](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/array/wrap.rb) (lines 39–46). It does not walk Ruby’s `Kernel#Array` conversion protocol. It is a three-branch predicate:

```
object.nil?                  → []
object.respond_to?(:to_ary)  → object.to_ary || [object]
else                         → [object]
```

```diagram
          object
             │
             ▼
      ┌─────────────┐  yes
      │ object.nil? ├──────────▶ []
      └──────┬──────┘
             │ no
             ▼
   ┌─────────────────────┐
   │ respond_to?(:to_ary)│
   └──────────┬──────────┘
         yes  │  no
              │   └──────────▶ [object]
              ▼
        object.to_ary
              │
         ┌────┴────┐
      truthy     falsy (nil)
         │          │
         ▼          ▼
   that value    [object]
```

`respond_to?(:to_ary)` is the gate. The method is never called unless that query is true. There is no `to_a` fallback, and the result of `to_ary` is not type-checked.

### Cases

#### `nil` → `[]`

First branch. `nil` never reaches `to_ary`.

- Implementation: wrap.rb:40–41
- Test: `test_nil` in [activesupport/test/core_ext/array/wrap_test.rb](file:///home/user/workspace/repo/activesupport/test/core_ext/array/wrap_test.rb):35–37
- Observable: `Array.wrap(nil) # => []`

#### Actual `Array` — same object

An Array is not `nil` and `respond_to?(:to_ary)`. `Array#to_ary` returns `self`, which is truthy, so the `|| [object]` arm is skipped.

- Implementation: wrap.rb:42–43
- Test: `test_array` wrap_test.rb:30–33
- Observable: `assert_same ary, Array.wrap(ary)` — identity preserved, not a copy

#### Ordinary object → `[object]`

`Object.new` does not `respond_to?(:to_ary)`, so the else branch wraps it. Same for String (`test_string`, `test_string_with_newline`) and Struct (`test_struct`).

- Implementation: wrap.rb:44–45
- Tests: wrap_test.rb:39–42, 44–50, 66–69
- Observable: `Array.wrap(o) # => [o]`

#### `Hash`

No focused test. The method comment documents the Hash case as the reason `wrap` does not call `to_a`:

```
Array(foo: :bar)      # => [[:foo, :bar]]
Array.wrap(foo: :bar) # => [{:foo=>:bar}]
```

Hash is not `nil` and does not `respond_to?(:to_ary)`, so it takes the else branch and is wrapped as a single element. Contrast with `Kernel#Array` is source-documented here (wrap.rb:23–29): `Kernel#Array` would call `to_a` and produce pairs.

- Implementation: wrap.rb:44–45, documented at wrap.rb:26–29
- Observable: `Array.wrap(foo: :bar) # => [{:foo=>:bar}]`

#### Object whose `to_ary` returns an Array

`FakeCollection#to_ary` returns `["foo", "bar"]`. That value is truthy, so wrap returns it as-is.

- Implementation: wrap.rb:42–43
- Test: `test_object_with_to_ary` wrap_test.rb:52–54
- Observable: `Array.wrap(FakeCollection.new) # => ["foo", "bar"]`

#### Object whose `to_ary` returns `nil`

`NilToAry` responds to `to_ary` but returns `nil`. `nil || [object]` takes the right-hand side, so the original object is wrapped. This is the documented difference from `Kernel#Array`, which would then try `to_a` (wrap.rb:18–20).

- Implementation: wrap.rb:43 (`object.to_ary || [object]`)
- Test: `test_wrap_returns_wrapped_if_to_ary_returns_nil` wrap_test.rb:71–74
- Observable: `Array.wrap(o) # => [o]` where `o` is the `NilToAry` instance

The comment at wrap.rb:8–10 (“if it responds to `to_ary` … its result returned”) is slightly looser than the code: a `nil` result is not returned; the object is wrapped instead.

#### Object whose `to_ary` returns a non-Array

`DoubtfulToAry#to_ary` returns `:not_an_array`. That symbol is truthy, so wrap returns it with no Array check and no exception. Documented contrast with `Kernel#Array` (wrap.rb:21–22): `Kernel#Array` raises if `to_ary` returns neither `nil` nor an Array.

- Implementation: wrap.rb:43
- Test: `test_wrap_does_not_complain_if_to_ary_does_not_return_an_array` wrap_test.rb:76–78
- Observable: `Array.wrap(DoubtfulToAry.new) # => :not_an_array` (equal to `DoubtfulToAry.new.to_ary`, not wrapped)

#### Proxy that does not expose the target’s `to_ary`

`Proxy` forwards via `method_missing` but does not define `respond_to_missing?`. `respond_to?(:to_ary)` is therefore false even when the target implements `to_ary`. Wrap never calls `to_ary` on the proxy (or the target) and wraps the proxy itself.

- Implementation: wrap.rb:42 (`respond_to?(:to_ary)` is the only dispatch check)
- Tests:
  - `test_proxy_object` wrap_test.rb:56–59 — proxy of a plain Object → `[p]`
  - `test_proxy_to_object_with_to_ary` wrap_test.rb:61–64 — proxy of `FakeCollection` → `[p]`, not `["foo", "bar"]`
- Observable: `Array.wrap(Proxy.new(FakeCollection.new)) # => [proxy]`, not the collection’s array

That last test is the proof that wrap consults the receiver’s `respond_to?(:to_ary)`, not a hidden target.

### Contrast with `Kernel#Array` (only what wrap.rb documents)

The method comment (wrap.rb:16–38) states three differences; nothing else in this source claims more:

1. If `to_ary` returns `nil`, `Kernel#Array` continues to `to_a`; `Array.wrap` immediately returns `[object]` (wrap.rb:18–20; `NilToAry` test).
2. If `to_ary` returns a non-nil non-Array, `Kernel#Array` raises; `Array.wrap` returns that value (wrap.rb:21–22; `DoubtfulToAry` test).
3. `Array.wrap` never calls `to_a`. No `to_ary` → `[object]`. Hash is the documented example: `Array(foo: :bar) # => [[:foo, :bar]]` vs `Array.wrap(foo: :bar) # => [{:foo=>:bar}]` (wrap.rb:23–29).

The splat idiom `[*object]` is mentioned (wrap.rb:31–38) as related: it yields `[]` for `nil`, otherwise `Array(object)`, so the same `Kernel#Array` differences apply. The tests never exercise `Kernel#Array` or splat; those contrasts live only in the comment.
