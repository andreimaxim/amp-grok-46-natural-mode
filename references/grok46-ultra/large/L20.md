## Behavior-preservation verification for `ActiveRecord::Base.connected_to_many`

Derived from current source and existing tests. Verification strategy only; no implementation changes.

### Derived contract

`connected_to_many` is a Base-only, class-scoped stack push. It is not a global role switch.

```ruby
def connected_to_many(*classes, role:, shard: nil, prevent_writes: role == ActiveRecord.reading_role)
  classes = classes.flatten
  if self != Base || classes.include?(Base)
    raise NotImplementedError, "connected_to_many can only be called on ActiveRecord::Base."
  end
  if role == ActiveRecord.reading_role && !prevent_writes
    raise ArgumentError, "cannot set `prevent_writes` to false when `role` is `reading`."
  end
  append_to_connected_to_stack(role: role, shard: shard, prevent_writes: prevent_writes, klasses: classes)
  begin
    yield
  ensure
    connected_to_stack.pop
  end
end
```

Sources: [activerecord/lib/active_record/connection_handling.rb](file:///home/user/workspace/repo/activerecord/lib/active_record/connection_handling.rb) L160–L190, L420–L437; [activerecord/lib/active_record/core.rb](file:///home/user/workspace/repo/activerecord/lib/active_record/core.rb) L160–L224.

Invariants that must survive a refactor:

1. **Receiver.** Only `ActiveRecord::Base` may call it. Any other receiver raises `NotImplementedError` with `"connected_to_many can only be called on ActiveRecord::Base."` The raise happens before any stack mutation.
2. **Forbidden klass.** After flatten, if `classes` includes `ActiveRecord::Base`, same `NotImplementedError`. Nested arrays that contain Base also fail (`classes.flatten` then `include?(Base)`).
3. **Flattening.** `*classes` then `flatten`. A bare class, several splatted classes, `[A, B]`, and `[[A, B]]` are equivalent. Flattening happens before validation and before the stack entry is built.
4. **Required kwargs.** `role:` is required (Ruby `ArgumentError` if omitted). `shard:` defaults to `nil`. `prevent_writes:` defaults to `role == ActiveRecord.reading_role`.
5. **Reading + writable is illegal.** `role == ActiveRecord.reading_role && !prevent_writes` raises `ArgumentError` with `"cannot set `prevent_writes` to false when `role` is `reading`."` This is evaluated after flatten/Base checks, still before push. `prevent_writes: nil` is also rejected here because `!nil` is true.
6. **Scoped stack entry.** One hash `{ role:, shard:, prevent_writes:, klasses: classes }` is appended. Lookup walks `connected_to_stack` **from the top** (`reverse_each`). A class matches if `hash[:klasses]` includes `Base` **or** that class’s `connection_class_for_self`. Because `connected_to_many` forbids Base in `klasses`, its entries never match unrelated connection classes.
7. **Nil shard does not override.** `current_shard` only returns `hash[:shard]` when it is present/truthy. Role-only `connected_to_many` therefore keeps the prior shard for those klasses. Role-only also does not clear a parent shard.
8. **Nil prevent_writes does not override.** `current_preventing_writes` skips entries where `prevent_writes` is `nil`. The reading-role guard usually prevents that from being pushed, but writing + omitted prevent_writes pushes `false`.
9. **Unrelated models.** A model whose `connection_class_for_self` is not in `klasses` keeps its previous role, shard, prevent_writes, and pool. Concrete subclasses of a listed abstract class *do* switch, because lookup uses `connection_class_for_self`, which walks to the connection class.
10. **Restore.** `ensure { connected_to_stack.pop }` runs on normal return, `raise`, and `throw`. Failed `append_to_connected_to_stack` (e.g. `ShardSwapProhibitedError`) happens *before* `begin`, so the previous stack is left untouched — a refactor that wraps append in the same `begin`/`ensure` would pop the parent entry.
11. **Isolation.** The stack lives in `ActiveSupport::IsolatedExecutionState[:active_record_connected_to_stack]` as a `Concurrent::Array`. Default isolation is `:thread`. Fibers share the stack unless isolation is `:fiber`.
12. **Writes.** `prevent_writes: true` makes matching connections raise `ActiveRecord::ReadOnlyError` on INSERT/UPDATE/DELETE (`Write query attempted while in readonly mode:`). Reads still succeed. Unrelated connection classes must still be writable unless they independently have prevent_writes or `replica: true`. Adapter `preventing_writes?` is also true for replicas regardless of the stack.

### Observables and instrumentation

Prefer public observables. Use the stack only as a leak detector.

| Observable | How to read | Detects |
|---|---|---|
| `Klass.current_role` / `current_shard` / `current_preventing_writes` | Public class methods | Wrong match, leak, unrelated contamination |
| `Klass.connected_to?(role:, shard:)` | Combines role+shard; default shard is `Base.default_shard` | Role/shard mismatch. Do not use it as the only check when the expected shard is a non-default parent shard and the call omitted `shard:` — `connected_to?(role: :reading)` would compare against `:default` and false-fail. |
| `Klass.connection_pool.db_config.name` | Selected pool | Role/shard actually changed the handler lookup |
| `Klass.lease_connection.preventing_writes?` | Adapter flag (`replica?` OR stack) | Accidental writes / prevent_writes not applied |
| INSERT/UPDATE/DELETE vs SELECT | `assert_raises ActiveRecord::ReadOnlyError` / successful create | Real write barrier, not just the flag |
| `ActiveRecord::Base.connected_to_stack.dup` (size, object_id of entries, klasses) | Before / inside / after | Leaked or extra pop; capture **before** the call, compare after restore. Do not mutate the live stack in assertions. |
| Exception class + exact message | `assert_raises` + `assert_equal` | Guard regressions |
| Return value of the block | `assert_equal :ok, connected_to_many(...) { :ok }` | Accidental Relation `#load` behavior (current `connected_to_many` does **not** auto-load, unlike `connected_to`/`with_role_and_shard`) |

Fixture shape (match `connection_swapping_nested_test`, skip with `unless in_memory_db?` for file SQLite):

- `PrimaryBase` / `SecondaryBase` / `TertiaryBase`: independent abstract connection classes.
- Concrete `PrimaryModel` etc. for write attempts and `connection_class_for_self` walking.
- Distinct writer/replica (and shard) db_config names so pool name is a precise oracle.
- For prevent_writes tests that must not be confounded by `replica?`, omit `replica: true` (as `test_prevent_writes_can_be_changed_granularly` already does).
- `self.use_transactional_tests = false` and `clean_up_connection_handler` in teardown, same as the nested swapping tests.
- Snapshot `ActiveRecord::Base.configurations`, `ENV["RAILS_ENV"]`, and re-`establish_connection(:arunit)` in `ensure`.

Each test that enters a block must assert the **pre** state, **in**-block state for listed *and* unlisted classes, and **post** state. Post-state is the leak oracle.

#### F. Nesting with `connected_to`

| ID | Nesting | Expect |
|---|---|---|
| F1 | Outer `Base.connected_to(role: :writing, shard: :default)` → inner `connected_to_many([Secondary, Tertiary], role: :reading)` | Primary writing/default; Secondary+Tertiary reading/default; all restore to writing/default |
| F2 | Same inner, then `TertiaryBase.connected_to(role: :writing)` | Tertiary writing (and its prevent_writes false); Secondary still reading; Primary writing |
| F3 | Outer `connected_to_many([Secondary, Tertiary], role: :reading)` → inner `SecondaryBase.connected_to(role: :writing, shard: :shard_one)` | Secondary writing/shard_one; Tertiary reading/prior shard; Primary untouched |
| F4 | Outer `connected_to_many(..., role: :reading)` → inner `Base.connected_to(role: :writing)` | Base entry matches **everyone** (klasses include Base), so Primary/Secondary/Tertiary all writing while inner is active; after inner, listed classes return to reading |
| F5 | Existing nested `connected_to_many([Tertiary], role: :writing)` inside `[Secondary, Tertiary], role: :reading` | keep current three-pool assertions |

F4 is the important override rule: a Base `connected_to` is global because lookup prefers `klasses.include?(Base)` on the newest entry.

#### G. Restoration after return, raise, and throw

Snapshot `stack_before = ActiveRecord::Base.connected_to_stack.dup` (and `stack_before.map(&:object_id)`).

| ID | Block | After |
|---|---|---|
| G1 | `connected_to_many(...) { :ok }` | returns `:ok`; roles/shards/prevent_writes/pools == pre; stack size and entry identities == `stack_before` |
| G2 | `raise RuntimeError, "boom"` | exception propagates; same restore as G1 |
| G3 | `throw :done, :token` inside `catch(:done)` | catch receives `:token`; same restore as G1 |
| G4 | Nested F2, raise inside innermost | each level restored; no leftover reading on Secondary |
| G5 | `append_to_connected_to_stack` fails: `prohibit_shard_swapping` then `connected_to_many([PrimaryBase], shard: :shard_two, role: :writing)` | `ShardSwapProhibitedError`; stack **identical** to pre (not one entry shorter). This guards moving append inside `begin`/`ensure`. |
| G6 | Successful inner `connected_to_many`, then another call after the block | second call sees the original parent, not a leftover inner entry |

G3 matters because `throw` is not `raise`; only `ensure` restores it. G5 is the extra-pop bug.

#### H. Concurrent execution-context isolation

Default `ActiveSupport::IsolatedExecutionState.isolation_level` is `:thread`. Use the restore pattern from [activerecord/test/cases/connection_pool_test.rb](file:///home/user/workspace/repo/activerecord/test/cases/connection_pool_test.rb) if temporarily switching to `:fiber`.

| ID | Harness | Act | Expect |
|---|---|---|---|
| H1 | `Thread.new` (always valid) | Parent: `connected_to_many([Secondary, Tertiary], role: :reading)` and wait. Child thread: read Secondary/Tertiary/Primary roles **without** entering the block. | Child sees defaults (writing / default / false), not the parent’s reading. Parent still reading while blocked inside. After join + block exit, parent restored. |
| H2 | Two threads each enter their own `connected_to_many` with **different** roles/shards | No cross-talk; each thread’s post-state is its own pre-state | stack object_ids differ across threads (`IsolatedExecutionState` per thread) |
| H3 | Only if the file already switches isolation (do not change global isolation for the whole suite): `isolation_level = :fiber` | Fiber A inside `connected_to_many(reading)`; Fiber B on same thread reads roles | B does not see A’s reading. Restore isolation_level in `ensure`. |
| H4 | Default `:thread`, `Fiber.new` inside the block | Child fiber **does** see the parent reading (shared thread state). This documents current isolation, not a bug. Skip if you only want isolation *guarantees*; include it if a refactor might “fix” this and silently change request/fiber behavior. |

Do not use `IsolatedExecutionState.share_with` unless the refactor claims to preserve streaming-thread copies; that API is unrelated to `connected_to_many`.

Barrier: `Queue` or `CountDownLatch` (already required in `base_test.rb`) so the parent is observably inside the block while the child samples.

### Minimum set that still catches the dangerous refactors

If the matrix must be cut, keep this order:

1. B1 + B2 (scoped role/shard, unrelated stays, nil shard does not clobber)
2. C1 + C4 (default reading blocks writes; explicit writing+prevent_writes blocks only listed classes)
3. G2 + G3 + G5 (raise, throw, failed append)
4. F4 (Base `connected_to` inside `connected_to_many` is global; unwind restores listed reading)
5. H1 (thread isolation)
6. A3 + E4 (flatten then Base rejection)
7. D1 (already present; keep)

That set is enough to detect leaked role/shard state and accidental writes without depending on a particular implementation of the stack push.
