## Assistant

`reload` refreshes one Ruby object in place. It always issues a SELECT after busting the query cache, then copies internal state onto `self`. It never replaces the record. If the SELECT finds nothing, it raises and leaves that internal state untouched.

### Persistence#reload

From [`activerecord/lib/active_record/persistence.rb`](file:///home/user/workspace/repo/activerecord/lib/active_record/persistence.rb):

```ruby
def reload(options = nil)
  self.class.connection_pool.clear_query_cache

  fresh_object = if apply_scoping?(options)
    _find_record((options || {}).merge(all_queries: true))
  else
    self.class.unscoped { _find_record(options) }
```

#### Lookup: `_find_record` and query constraints

```ruby
def _find_record(options)
  all_queries = options ? options[:all_queries] : nil
  base = if all_queries
    self.class.all_queries_scope
  else
    self.class.all
  end
  base = base.preload(strict_loaded_associations)

  if options && options[:lock]
    base.lock(options[:lock]).find_by!(_in_memory_query_constraints_hash)
  else
    base.find_by!(_in_memory_query_constraints_hash)
  end
end
```

`find_by!` is `where(...).take!`, which raises `ActiveRecord::RecordNotFound` when no row matches.

The WHERE hash uses **in-memory** values, not `id_in_database`:

```ruby
def _in_memory_query_constraints_hash
  if self.class.query_constraints_list.nil?
    { @primary_key => id }
  else
    self.class.query_constraints_list.index_with { |column_name| attribute(column_name) }
  end
end
```

`strict_loaded_associations` preloads associations already in `@association_cache` whose owner is `strict_loading?` and not `strict_loading_n_plus_one_only?`. #### Scoped versus unscoped, including `all_queries: true`

```ruby
def apply_scoping?(options)
  !(options && options[:unscoped]) &&
    (self.class.default_scopes?(all_queries: true) || self.class.global_current_scope)
end
```

`default_scopes?(all_queries: true)` is true only if some `default_scope` was declared with `all_queries: true` ([`Scoping::Default`](file:///home/user/workspace/repo/activerecord/lib/active_record/scoping/default.rb)). Ordinary default scopes do not trip this.

`global_current_scope` is set only by `Relation#scoping(all_queries: true)` ([`_scoping`](file:///home/user/workspace/repo/activerecord/lib/active_record/relation.rb)). `Model.where(...).scoping { }` without that flag sets `current_scope` only.

Two paths:

1. **Unscoped path** (default): `self.class.unscoped { _find_record(options) }`. `unscoped` with a block is `relation.scoping(&block)` — `current_scope` becomes an empty relation. `_find_record` then calls `self.class.all`, which returns that empty scope. Ordinary default scopes and non-`all_queries` `scoping` blocks do **not** appear in the SQL.

2. **Scoped path**: `_find_record(..., all_queries: true)` uses [`all_queries_scope`](file:///home/user/workspace/repo/activerecord/lib/active_record/scoping/named.rb):

```ruby
def all_queries_scope
  scope = if default_scopes?(all_queries: true)
    default_scoped(all_queries: true)
  else
    relation
  end
  if current_scope = global_current_scope
    scope = scope.merge!(current_scope)
  end
  scope
end
```

`build_default_scope(..., all_queries: true)` keeps only default scopes whose `all_queries` flag is true (`execute_scope?`). A mixed model therefore applies the `all_queries: true` firm scope on reload and skips the ordinary mentor scope ([`test_default_scope_with_all_queries_runs_on_reload_but_default_scope_without_all_queries_does_not`](file:///home/user/workspace/repo/activerecord/test/cases/scoping/default_scoping_test.rb)).

### Association cache: replace and rebind owner

After a successful find:

```ruby
@association_cache = fresh_object.instance_variable_get(:@association_cache)
@association_cache.each_value { |association| association.owner = self }
```

`fresh_object` is a new record. Its `@association_cache` is empty unless `_find_record` preloaded `strict_loaded_associations` (or `after_initialize` built an association, as `Publication` does).

So a previously loaded association on `self` is dropped. The cache hash and the `Association` objects inside it are the ones from `fresh_object`, not the old ones.

Those `Association` objects still have `owner` pointing at `fresh_object` (the discarded instance). The loop rebinds `association.owner = self` ([`Association` `attr_accessor :owner`](file:///home/user/workspace/repo/activerecord/lib/active_record/associations/association.rb)).

[`test_reload_sets_correct_owner_for_association_cache`](file:///home/user/workspace/repo/activerecord/test/cases/persistence/reload_association_cache_test.rb) is the regression: `Publication` `after_initialize` builds `editor_in_chief`, so reload’s `fresh_object` already has an association in cache. After reload, a transaction assigns `editors` / `editor_in_chief` and `save!`. `after_save_commit :touch_name` mutates `name` on whatever object the association thinks is owner. Without rebinding, that is the discarded `fresh_object` and `publication.name` stays `"Rails Way"`; with rebinding it becomes `"Rails Way (touched)"` on the original object.
