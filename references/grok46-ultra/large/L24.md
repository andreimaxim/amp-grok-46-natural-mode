`recognize_path` is offline recognition, not live dispatch. It builds a fake request, asks Journey for matching routes, then returns `req.path_parameters` only if the matched app is a dispatcher whose controller constantizes. Query-string keys never become path params unless they are injected as `environment[:extras]`.

### Compact call flow

```text
RouteSet#recognize_path(path, environment)
  method = (environment[:method] || "GET").upcase
  extras = environment[:extras] || {}
  path = Utils.normalize_path(path)   unless path includes "://"
  env  = Rack::MockRequest.env_for(path, method:)   # URI::InvalidURIError → RoutingError
  req  = make_request(env)            # ActionDispatch::Request
  RouteSet#recognize_path_with_request(req, path, extras, raise_on_missing: true)
    Journey::Router#recognize(req) { |route, params|
      params.merge!(extras)
      unescape every String value (URI::RFC2396_PARSER)
      req.path_parameters = params
      app = route.app
      if app.matches?(req) && app.dispatcher?
        req.controller_class            # NameError → RoutingError (missing controller)
        return req.path_parameters
      elsif app.matches?(req) && app.engine?
        recurse with raise_on_missing: false
        return those params if present
      end                               # redirect / rack app / failed constraint: keep iterating
    }
    raise RoutingError "No route matches" if raise_on_missing
```

Journey’s inner match:

```text
Router#recognize(req)
  candidates = GTG::Simulator#memos(path_info)     # anchored routes
             + custom_routes whose path.match?(path_info)
  filter by Route#matches?(req)                    # verb + request constraints
  HEAD with no HEAD routes: retry as GET
  sort by Route#precedence
  for each candidate:
    MatchData = Path::Pattern#match(path_info)
    params = req.path_parameters.merge(route.defaults)
    named captures: CGI.unescapeURIComponent if they contain "%", force UTF-8
    yield route, params
    unanchored (mount): temporarily rewrite SCRIPT_NAME / PATH_INFO, then restore
```

### 2. Relative path vs absolute URL vs `nil`

**Relative.** `Journey::Router::Utils.normalize_path` ([utils.rb:19-39](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/router/utils.rb#L19-L39)):

- `nil` / empty → `"/"`
- guarantee a leading `/`
- squeeze `//`
- strip trailing `/` except for `"/"`
- uppercase percent-escapes (`/%ab` → `/%AB`)

Tests: [utils_test.rb](file:///home/user/workspace/repo/actionpack/test/journey/router/utils_test.rb#L29-L48); trailing-slash recognition in [test_draw_default_route](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L1212-L1213) (`/users/index/10` == `/users/index/10/`); [test_recognize_path](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L2076-L2134) (`/api` == `/api/`, `recognize_path(nil)` → `{controller: "news", action: "index"}`).

Unicode percent-escapes are uppercased here, which is why both escaped and downcased-escaped Japanese paths recognize: [test_unicode_path / test_downcased_unicode_path](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L2176-L2181).

**Absolute.** Normalization is skipped. `env_for("http://subdomain.example.org/page/mypage")` fills host/scheme so request constraints (`protocol`, `ssl?`, subdomain lambdas) see a real request. Test: [test_route_with_subdomain_and_constraints_must_receive_params](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L1691-L1700). Same pattern in [routing_assertions_test.rb](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_assertions_test.rb#L108-L167) for `http://` vs `https://`.

The original `path` string is still the one interpolated into error messages, not the normalized PATH_INFO.

### 3. Query strings

Journey matches `req.path_info` only ([router.rb:43-46](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/router.rb#L43-L46)). QUERY_STRING is not merged into the returned hash.

The supported way to inject query-like keys is `environment[:extras]`, merged in `recognize_path_with_request` before unescape. That is exactly how `assert_recognizes` works ([routing.rb:154-157, 332](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/testing/assertions/routing.rb#L154-L157)):

```ruby
## extras become path_parameters; "?view=print" on the path would not
assert_recognizes({..., view: "print"}, "items/list/1", { view: "print" })
```

Tests: [test_assert_recognizes_with_query_constraint](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_assertions_test.rb#L122-L126) and [engine extras](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_assertions_test.rb#L146-L147) (`page: "1"` appears in recognized params only because it was passed as extras).

If a caller does pass `"/foo?bar=baz"`, Rack splits PATH_INFO/QUERY_STRING, Journey still matches `/foo`, and `:bar` is absent from the result.

### 4. Journey matching

Source: [journey/router.rb](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/router.rb#L43-L99), [routes.rb partition](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/routes.rb#L53-L58), [gtg/simulator.rb#memos](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/gtg/simulator.rb#L23-L59).

- Anchored routes with anchored requirements go through the GTG simulator (NFA-style chunk match on PATH_INFO, memos are the candidate `Route`s).
- Everything else (`custom_routes`: unanchored mounts, non-anchored requirements) is appended if `path.match?(path_info)`.
- `Route#matches?` ([journey/route.rb:172-187](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/route.rb#L172-L187)) is verb matcher plus request-method constraints (`protocol`, `subdomain`, etc. via `request.send(method)`).
- Verb table: [VerbMatchers](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/route.rb#L13-L73). Tests: [test_recognize_array_of_methods](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L873-L881); PUT/DELETE on `via: [:get, :post]` raise `RoutingError` ([test_recognize_path:2101-2103](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L2101-L2103)).
- HEAD: dedicated HEAD routes win; otherwise the request method is temporarily set to GET ([match_head_routes](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/router.rb#L115-L125)). Covered in [journey/router_test.rb](file:///home/user/workspace/repo/actionpack/test/journey/router_test.rb#L403-L426).
- Multiple hits are sorted by `precedence` (insertion order). First *accepted* dispatcher/engine in `recognize_path_with_request` wins, not necessarily the first Journey yield.

Path regex match: [Path::Pattern#match](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/path/pattern.rb#L171-L174). Defaults are merged first; optional captures that did not match stay as the default (`nil` months/days in `/blog/2009`, integer `id: 1` default vs string `"1"` from the URL — [test_recognize_path:2098-2100](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L2098-L2100)).

Unanchored yield rewrites `script_name`/`path_info` so a mounted engine sees the remainder, then restores so later parent routes can still match ([router.rb:85-96](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/router.rb#L85-L96)). Test: [test_assert_recognizes_continue_to_recognize_after_it_tried_engines](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_assertions_test.rb#L184-L185) (`/shelf/foo` misses the engine, then matches the parent `get "/shelf/foo"`).

### 5. Two unescape layers for dynamic segments

**Layer 1 — Journey captures** ([router.rb:73-81](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/router.rb#L73-L81)): if the capture contains `%`, `CGI.unescapeURIComponent`, then `force_encoding(UTF_8)`. `+` is *not* a space. Tests:

- [test_paths_escaped](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L587-L601): `hello+world` stays `hello+world`; `%20` becomes space; `%3F` becomes `?`
- [test_default_route_should_uri_escape_pluses](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L1874-L1883): `hello+world` and `hello%2Bworld` both yield `"hello+world"`; `%20` yields `"hello world"`
- [test_escapes_newline_character_for_dynamic_path / wildcard](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L651-L665): `%0A` → `"\n"`
- [UriReservedCharactersRoutingTest](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L37-L46): reserved path bytes round-trip through percent-decoding

**Layer 2 — RouteSet** ([route_set.rb:928-933](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/route_set.rb#L928-L933)): after extras merge, every String (captures, string defaults, extras) is BINARY then `URI::RFC2396_PARSER.unescape`. Non-strings (`:as_symbol`, `ws: true`, integer defaults) are left alone ([test_recognize_path:2097, 2109](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L2097-L2109)).

Consequence of the double pass: a still-percent-encoded value after Journey (`%2520` → `%20`) is decoded again by RouteSet (`%20` → space). Values without `%` are unchanged by both layers.

Then `req.path_parameters = params` runs encoding checks ([parameters.rb:67-76](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/http/parameters.rb#L67-L76)): invalid encoding → `ActionController::BadRequest`.

### 6. App-level constraints, dispatcher vs engine

`route.app` is usually `Dispatcher`, `Mapper::Constraints`, or a mounted engine ([mapper.rb Mapping#app](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/mapper.rb#L290-L298)).

`app.matches?(req)` here is *not* `Route#matches?`. It is the Constraints wrapper’s callables/objects ([mapper.rb:52-57](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/mapper.rb#L52-L57)), re-checked now that `req.path_parameters` is populated — so lambdas can read `request.params[:name]` ([test_route_with_subdomain_and_constraints_must_receive_params](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L1691-L1700)).

Only then:

- **dispatcher?** → try `req.controller_class`, return `req.path_parameters`
- **engine?** → recurse `recognize_path_with_request(..., raise_on_missing: false)`. A miss returns `nil` and the parent keeps iterating. A hit returns the engine’s path params. Tests: [engine recognition](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_assertions_test.rb#L137-L185).
- Redirect / plain Rack / failed `app.matches?` → do not return; try the next Journey yield.

### 7. Missing controller vs unmatched route

`Request#controller_class` ([request.rb:85-106](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/http/request.rb#L85-L106)): `#{controller.underscore.camelize}Controller`.constantize. Missing constant becomes `ActionDispatch::MissingController < NameError`.

`recognize_path_with_request` rescues `NameError` and raises:

```text
ActionController::RoutingError
  "A route matches #{path.inspect}, but references missing controller: #{params[:controller].camelize}Controller"
```

If Journey yields nothing that is an accepted dispatcher/engine, the outer call with `raise_on_missing: true` raises:

```text
ActionController::RoutingError
  "No route matches #{path.inspect}"
```

Engine recursion uses `raise_on_missing: false`, so an engine miss is `nil`, not an exception.

Observable matrix:

| Case | Result |
|---|---|
| Path matches a dispatcher and controller exists | Hash of symbol keys: `controller`, `action`, captures, defaults, extras |
| Path matches, controller cannot constantize | `RoutingError` “A route matches … missing controller: FooController” |
| No route / verb mismatch / request constraint fail / optional segment missing | `RoutingError` “No route matches …” |
| Engine prefix matches but inner routes don’t, and a later parent route does | Parent route’s params |
| Engine prefix matches, inner routes don’t, nothing else matches | “No route matches” (parent, not the engine) |
| `nil` path with a root route | `{controller:, action: "index"}` (normalized to `/`) |
| Invalid URI | `RoutingError` wrapping `URI::InvalidURIError` message |
| Invalid encoding in a path param | `ActionController::BadRequest` from `path_parameters=` |

- Live dispatch is a different exception: [test_route_error_with_missing_controller](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L1278-L1284) uses `request_path_params` → `RouteSet#call` → `Dispatcher#serve` → `MissingController`, not `recognize_path`. ### Return value

Success returns `req.path_parameters`: a Hash with **symbol keys**, stored under `action_dispatch.request.path_parameters`. It is not `request.params` (no QUERY_STRING / body). `action` is whatever Journey merged from defaults/captures; `controller_class` may set `params[:action] ||= "index"` on the same hash as a side effect of the constantize check.
