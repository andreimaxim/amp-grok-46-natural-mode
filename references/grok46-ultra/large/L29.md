## Behavior-preserving verification for `fresh_when` / `stale?`

No production-code changes. The public HTTP contract is: validators go on the response, `request.fresh?(response)` decides 304 vs 200, and Cache-Control / 304 body rules stay as they are today.

### Current behavior (traced)

```
GET/HEAD/POST/… action
  fresh_when / stale?
    response.cache_control.delete(:no_store)
    set ETag (weak default, or strong if strong_etag:)
    set Last-Modified (httpdate, second precision)
    merge public / cache_control
    head :not_modified  if request.fresh?(response)
  stale? → !request.fresh?(response)   # block runs only when stale
    │
    ▼
request.fresh?(response)
  strict_freshness=false (legacy AND): both headers, if present, must succeed
  strict_freshness=true  (Rails 8.0): If-None-Match wins; Last-Modified only if INM absent
  etag_matches?: exact string, or "*" matches any non-nil ETag (weak and strong do not alias)
  not_modified?: If-Modified-Since >= Last-Modified after httpdate round-trip
    │
    ▼
Response#before_committed
  merge_and_normalize_cache_control!
  handle_conditional_get!   # default "max-age=0, private, must-revalidate" if ETag/LM set
  handle_no_content!        # 304 drops Content-Type and Content-Length, empty body
```

Sources: [conditional_get.rb](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/conditional_get.rb), [cache.rb](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/http/cache.rb), [etag_with_template_digest.rb](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/etag_with_template_digest.rb), [head.rb](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/head.rb), [response.rb](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/http/response.rb).

Facts the refactor must not change:

- `fresh_when` does not gate on HTTP method. GET, HEAD, QUERY, and POST all 304 when validators match.
- Weak ETag is `W/"<hex>"`; strong is `"<hex>"`. Matching is exact string equality. A weak INM does not 304 a strong response (and vice versa). `"*"` 304s any non-nil ETag.
- `Last-Modified` is `Time#httpdate` (seconds). Subseconds are dropped before compare, so `12:00:00.999` vs `If-Modified-Since: 12:00:00 GMT` is fresh.
- Default (`strict_freshness=false`): both headers, if present, must succeed (AND). Rails 8.0 (`true`): INM alone decides when present.
- `stale?` is `fresh_when` then `!request.fresh?(response)`. Fresh → 304 and the block does not run. Stale → 200 and the block runs.
- `fresh_when` clears `:no_store` then may restore the default Cache-Control. Later `no_store` wins.
- 304 keeps ETag, Last-Modified, Cache-Control; drops body, Content-Type, Content-Length.

Existing coverage (keep these green): [render_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/render_test.rb) `LastModifiedRenderTest` / `EtagRenderTest` / `HttpCacheNoStoreTest`; [conditional_get_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/api/conditional_get_test.rb); [request_test.rb](file:///home/user/workspace/repo/actionpack/test/dispatch/request_test.rb) `RequestEtag` / `RequestIfModifiedSince`; [response_test.rb](file:///home/user/workspace/repo/actionpack/test/dispatch/response_test.rb) 304 empty-body / no Content-Type.

Gaps the matrix below fills: subsecond Last-Modified, HEAD vs POST, weak `"*"` plus weak/strong mismatch at controller level, public vs default private on `fresh_when` itself, and an explicit `stale?` side-effect probe.

### Test matrix

Two levels only.

- **C** — `ActionController::TestCase` against a tiny fixture controller. Assert status, body, `ETag`, `Last-Modified`, `Cache-Control`, Content-Type/Length on 304. This is the contract.
- **R** — request-unit in `RequestEtag` / `RequestIfModifiedSince` only for header parsing (`*`, httpdate formats). Do not assert `combine_etags`, `etaggers`, or `generate_weak_etag`.

#### Fixture controller (C)

```ruby
class ConditionalGetContractController < ActionController::Base
  self.view_paths = [ActionView::FixtureResolver.new(
    "conditional_get_contract/show.erb" => "SHOW",
    "conditional_get_contract/other.erb" => "OTHER"
  )]

  @@expensive = 0
  def self.expensive; @@expensive; end
  def self.reset!; @@expensive = 0; end

  def show_weak
    fresh_when(etag: "123", last_modified: lm, template: false)
    render plain: "stale" unless performed?
  end

  def show_strong
    fresh_when(strong_etag: "strong", last_modified: lm, template: false)
    render plain: "stale" unless performed?
  end

  def show_stale
    if stale?(etag: "123", last_modified: lm, template: false)
      @@expensive += 1
      render plain: "expensive"
    end
  end

  def show_public
    fresh_when(etag: "123", public: true, template: false)
    render plain: "stale" unless performed?
  end

  def show_private
    fresh_when(etag: "123", template: false) # public: false default
    render plain: "stale" unless performed?
  end

  def show_template
    fresh_when(etag: "123") # implicit template digest
    render :show unless performed?
  end

  def show_other_template
    fresh_when(etag: "123", template: "conditional_get_contract/other")
    render :other unless performed?
  end

  def show_no_template
    fresh_when(etag: "123", template: false)
    render plain: "stale" unless performed?
  end

  def no_store_then_fresh
    no_store
    fresh_when(etag: "123", template: false)
    render plain: "stale" unless performed?
  end

  def fresh_then_no_store
    fresh_when(etag: "123", template: false)
    no_store
    render plain: "stale" unless performed?
  end

  def show_subsecond
    fresh_when(last_modified: Time.utc(2024, 1, 15, 12, 0, 0, 999_999), template: false)
    render plain: "stale" unless performed?
  end

  private
    def lm; Time.utc(2024, 1, 15, 12, 0, 0); end
end
```

Capture ETags from an unconditional GET rather than recomputing hexdigests. That survives a digest-algorithm change and still fails if weak/strong prefix or validator composition changes.

Toggle `ActionDispatch::Http::Cache::Request.strict_freshness` with `Object#with` (or save/restore) around precedence rows. Default in this suite is `false` unless a row says otherwise.

`stale?` instrumentation: `ConditionalGetContractController.expensive` counter. Fresh must leave it at 0; stale must increment by 1. That is an observable side effect, not a private call.

#### Rows

Each row: method, headers, expected status/body/headers. “blank body” means `response.body.blank?` and no `Content-Type` / `Content-Length` on 304.

**1. Weak ETag (C)** — `GET show_weak`

| Headers | Status | Body | Headers to observe |
|---|---|---|---|
| none | 200 | `"stale"` | `ETag` starts with `W/"`, `Last-Modified: Mon, 15 Jan 2024 12:00:00 GMT` |
| `If-None-Match: <that weak ETag>` | 304 | blank | same ETag + Last-Modified kept |
| `If-None-Match: <same hex, no W/>` | 200 | `"stale"` | weak/strong do not alias |
| `If-None-Match: W/"nomatch"` | 200 | `"stale"` | |
| `If-None-Match: *` | 304 | blank | `*` matches weak |

**2. Strong ETag (C)** — `GET show_strong`

| Headers | Status | Body |
|---|---|---|
| none | 200 | `"stale"`; `ETag` is `"…"` with no `W/` |
| `If-None-Match: <strong ETag>` | 304 | blank |
| `If-None-Match: W/<same hex>` | 200 | `"stale"` |
| `If-None-Match: *` | 304 | blank |
| `If-None-Match: "strong"` (raw validator) | 200 | `"stale"` — opaque quoted digest, not the input string |

**3. `If-None-Match: *` (C + R)**

- C: `*` + weak, `*` + strong → 304; `*` with only Last-Modified (no ETag set) → 200, because `etag_matches?(nil)` is false.
- R: keep `RequestEtag#always matches *` (`*` matches `"strong"` and `W/"weak"`, not `nil`).

**4. Precedence when both headers present (C)** — `GET show_weak`, matching ETag `W`, matching LM `2024-01-15 12:00:00 GMT`, old LM `2010-01-01`.

| `strict_freshness` | INM | IMS | Status |
|---|---|---|---|
| false | match | match | 304 |
| false | match | old | **200** (AND) |
| false | nomatch | match | **200** (AND) |
| false | absent | match | 304 |
| false | match | absent | 304 |
| true | match | old | **304** (INM wins) |
| true | nomatch | match | **200** (INM wins) |
| true | absent | match | 304 |
| true | absent | old | 200 |

Existing API tests cover a subset; keep them and add the missing AND/OR corners on one controller so a refactor cannot “fix” only the API class.

**5. Subsecond `Last-Modified` (C)** — `GET show_subsecond`

| `If-Modified-Since` | Status | `Last-Modified` |
|---|---|---|
| absent | 200 | `Mon, 15 Jan 2024 12:00:00 GMT` (usec stripped) |
| that same httpdate | **304** | same — truncation makes `.999999` fresh at `12:00:00` |
| `Mon, 15 Jan 2024 11:59:59 GMT` | 200 | still `12:00:00 GMT` |

Do not assert Ruby `Time` equality. Assert the HTTP date string and 304/200.

**6. GET vs HEAD vs non-safe (C)** — matching weak ETag on `show_weak`

| Method | Status | Body |
|---|---|---|
| GET | 304 | blank |
| HEAD | 304 | blank (Rails HEAD is not a special case here) |
| POST | 304 | blank — **current behavior has no method gate** |
| QUERY | 304 | blank — already in `EtagRenderTest#test_query_conditional_request` |

A 200 on POST after a matching INM is drift. Also send a matching GET with a *non-matching* ETag → 200 `"stale"`, to prove the method rows are about freshness, not “always 304”.

**7. public / private Cache-Control (C)** — unconditional GET

| Action | `Cache-Control` |
|---|---|
| `show_private` | `max-age=0, private, must-revalidate` |
| `show_public` | contains `public`, not `private` |

On a subsequent matching INM, 304 must keep that same Cache-Control. Drift: default flipping public/private, or 304 stripping Cache-Control.

**8. `no_store` (C)** — unconditional GET

| Action | `Cache-Control` |
|---|---|
| `no_store_then_fresh` | `max-age=0, private, must-revalidate` (`fresh_when` clears no-store) |
| `fresh_then_no_store` | `no-store` |

Already in `HttpCacheNoStoreTest`; re-run as characterization. A matching INM on `no_store_then_fresh` still 304s — no-store does not disable validators.

**9. Template-derived ETags (C)** — two-pass, capture ETag from first GET

| Action | Pass 2 `If-None-Match` | After template mutate | Extra |
|---|---|---|---|
| `show_template` | 304 | 200, ETag changed | implicit digest |
| `show_other_template` | 304 | mutating `show.erb` keeps 304; mutating `other.erb` → 200 | explicit template |
| `show_no_template` | 304 | mutating `show.erb` still 304, ETag unchanged | `template: false` |

Use existing `TemplateModificationHelper`. Do not assert digest values.

**10. `stale?` block execution (C)** — reset counter each row

| Headers | Status | Body | `expensive` |
|---|---|---|---|
| none | 200 | `"expensive"` | 1 |
| matching weak ETag | 304 | blank | **0** |
| matching IMS only | 304 | blank | **0** |
| mismatch ETag | 200 | `"expensive"` | 1 |

This is the highest-leverage `stale?` check: a refactor that 304s after the block, or that returns true on a fresh request, moves the counter.

### How this catches semantic drift (without private structure)

Assert only bytes on the wire and one action-level counter:

- Weak/strong prefix and exact INM match → ETag header shape + 304 vs 200. A switch from exact match to RFC weak-comparison, or hashing the raw string instead of `expand_cache_key`, fails rows 1–2.
- `"*"` → 304 only when an ETag exists. Matching `*` against a Last-Modified-only response would pass a looser `fresh?` and fail row 3.
- Dual headers → the 8-cell strict/legacy table. Flipping AND to OR, or always preferring ETag, fails a named cell.
- Subsecond → 304 against the truncated httpdate. Keeping usec in compare, or rounding the other way, fails row 5.
- Method → POST 304. Introducing RFC 9110 “only GET/HEAD” gating fails row 6; that would be a contract change, not a preservation.
- Cache-Control → exact default string and `public` vs `no-store` order. Moving `delete(:no_store)` or `handle_conditional_get!` fails 7–8.
- Template → 304/200 after fixture mutate. Dropping the digest etagger, or ignoring `template: false`, fails row 9.
- Block → counter 0 on 304. Computing freshness after the yield, or double-yielding, fails row 10.

Do **not** assert `combine_etags`, `etaggers`, `generate_weak_etag`, `request.fresh?` call counts, or header hash internals. If two implementations emit the same status, body, ETag, Last-Modified, and Cache-Control, they are equivalent for this refactor.

Reuse `EtagHelper` only as a convenience for building INM values in isolation tests; prefer captured `@response.etag` in controller tests so the oracle is the first response, not the hasher.
