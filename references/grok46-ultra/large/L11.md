## Behavior-preservation strategy for `TimeZone#local` → `TimeWithZone`

No implementation changes. This is a public-behavior gate for a refactor of `ActiveSupport::TimeZone#local` and the local-time constructor of `TimeWithZone`.

### Conversion contract (current source)

`TimeZone#local` does not interpret `*args` as a UTC instant. It builds a **UTC-valued Time whose civil fields are the wall clock**, then asks `TimeWithZone` to attach a TZInfo period:

```text
TimeZone#local(*args)
  Time.utc(*args)                         # wall clock, utc?=true
  TimeWithZone.new(nil, zone, time)
    get_period_and_ensure_valid_local_time
      transfer_time_values_to_utc_constructor   # drop any system-TZ Time.local DST
      period_for_local(time, dst=true)
        TZInfo::PeriodNotFound  → @time += 1.hour; retry     # spring gap
        ambiguous              → prefer DST; else periods.last
    utc = local_time - period.observed_utc_offset
    zone abbr = period.abbreviation
    dst?      = period.dst?
```

Evidence:

- [`activesupport/lib/active_support/values/time_zone.rb`](file:///home/user/workspace/repo/activesupport/lib/active_support/values/time_zone.rb) `local` L370–378; `period_for_local` L578–580 (`dst = true`, block `{ |periods| periods.last }`)
- [`activesupport/lib/active_support/time_with_zone.rb`](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb) `initialize` L50–60; `get_period_and_ensure_valid_local_time` L565–575; `transfer_time_values_to_utc_constructor` L577–581; `time` L63–65; `utc` L68–71; `dst?` L98–101; `utc_offset` L116–118; `zone` L138–140; `<=>` L246–248 (compares **UTC instant**)

Invariant that refactors must not invert: **`twz.time` is the wall clock stored as `Time.utc(...)`; `twz.utc` is the instant.** `#<=>` / `#eql?` / `#hash` use only the instant.

### Case 1 — Ordinary Hawaii date (no DST)

**Call:** `ActiveSupport::TimeZone["Hawaii"].local(2007, 2, 5, 15, 30, 45)`  
Hawaii maps to `Pacific/Honolulu` (MAPPING L38).

| Observable | Assert |
|---|---|
| Local components | `twz.time == Time.utc(2007, 2, 5, 15, 30, 45)` and `twz.time.utc?` |
| UTC instant | `twz.utc == Time.utc(2007, 2, 6, 1, 30, 45)` |
| Abbreviation | `twz.zone == "HST"` |
| DST | `twz.dst? == false` |
| Offset (supports the above) | `twz.utc_offset == -36000` |
| Identity | `twz.time_zone == ActiveSupport::TimeZone["Hawaii"]` |

**Detects:** treating args as a UTC instant (would yield 05:30 HST); applying system `Time.local` DST; dropping the UTC-valued wall-clock representation; wrong Pacific/Honolulu offset.

**Evidence:** `test_local` L202–205 (partial); rdoc example at `time_zone.rb` L372–376.  
**Command:** `cd activesupport && bin/test test/time_zone_test.rb -i test_local$`

### Case 2 — US Eastern 2006 spring-forward, 01:59:59 (last valid EST second)

**Call:** `ActiveSupport::TimeZone["Eastern Time (US & Canada)"].local(2006, 4, 2, 1, 59, 59)`  
Zone maps to `America/New_York` (MAPPING L54). In 2006 DST started 02:00 → 03:00 on Apr 2.

| Observable | Assert |
|---|---|
| Local | `twz.time == Time.utc(2006, 4, 2, 1, 59, 59)` |
| UTC | `twz.utc == Time.utc(2006, 4, 2, 6, 59, 59)` |
| Abbr | `twz.zone == "EST"` |
| DST | `twz.dst? == false` |

**Detects:** off-by-one into the gap; always preferring DST; applying the +1h gap retry to a valid pre-transition time.

**Evidence:** `test_local_enforces_spring_dst_rules` L215–218; arithmetic twin at `time_with_zone_test.rb` L474–478.  
**Command:** `cd activesupport && bin/test test/time_zone_test.rb -i test_local_enforces_spring_dst_rules`

### Case 3 — Spring-forward gap, 02:00 (does not exist)

**Call:** `zone.local(2006, 4, 2, 2)`  
`TZInfo::PeriodNotFound` → `@time += 1.hour; retry` (`time_with_zone.rb` L571–574).

| Observable | Assert |
|---|---|
| Local | `twz.time == Time.utc(2006, 4, 2, 3)` — **3:00, not 2:00** |
| UTC | `twz.utc == Time.utc(2006, 4, 2, 7)` |
| Abbr | `twz.zone == "EDT"` |
| DST | `twz.dst? == true` |

**Detects:** raising on the gap; leaving 02:00 in `twz.time`; shifting UTC without shifting the wall clock (or the reverse); picking EST for the skipped hour.

**Evidence:** L220–223; same path via `TimeWithZone.new` at `time_with_zone_test.rb` L676–680.  
**Command:** same as Case 2.

### Case 4 — Spring-forward gap, 02:30 (interior of skipped hour)

**Call:** `zone.local(2006, 4, 2, 2, 30)`  
Retry adds one hour to the **whole** local time, so minutes are preserved: 02:30 → 03:30.

| Observable | Assert |
|---|---|
| Local | `twz.time == Time.utc(2006, 4, 2, 3, 30)` |
| UTC | `twz.utc == Time.utc(2006, 4, 2, 7, 30)` |
| Abbr | `twz.zone == "EDT"` |
| DST | `twz.dst? == true` |

**Detects:** snapping every gap time to 03:00:00; adding 1h to UTC instead of the wall clock; a one-shot 02:00 special case that misses 02:30.

**Evidence:** L225–228.  
**Command:** same as Case 2.

### Case 5 — Ambiguous US Eastern fall-back hour (prefer DST)

**Call:** `zone.local(2006, 10, 29, 1)`  
1:00 occurs twice (EDT then EST). Comment at L233–234: *“Mirroring Time.local behavior, this method selects the DST time.”* `period_for_local(..., dst=true)` makes that unique.

| Observable | Assert |
|---|---|
| Local | `twz.time == Time.utc(2006, 10, 29, 1)` (wall clock stays 1:00) |
| UTC | `twz.utc == Time.utc(2006, 10, 29, 5)` — **EDT −4h, not EST −5h (06:00Z)** |
| Abbr | `twz.zone == "EDT"` |
| DST | `twz.dst? == true` |

**Detects:** `periods.last` / post-transition EST (UTC 06:00, `dst? == false`, `"EST"`); inventing a 02:00-style skip; changing wall-clock hour while disambiguating.

**Evidence:** `test_local_enforces_fall_dst_rules` L232–240; `time_with_zone_test.rb` L683–687.  
**Command:** `cd activesupport && bin/test test/time_zone_test.rb -i test_local_enforces_fall_dst_rules`

### Case 6 — Moscow 2014 ambiguous local time (no DST period; last period)

**Call:** `ActiveSupport::TimeZone["Moscow"].local(2014, 10, 26, 1, 0, 0)`  
Moscow maps to `Europe/Moscow` (MAPPING L117). On 2014-10-26 clocks fell back from UTC+4 to permanent UTC+3; 01:00 is ambiguous. Neither period is DST, so `dst=true` does not unique-select and the block `{ |periods| periods.last }` wins (`time_zone.rb` L578–580). That is the **later** UTC+3 / MSK occurrence, **not** the Eastern-style DST occurrence.

| Observable | Assert |
|---|---|
| Local | `twz.time == Time.utc(2014, 10, 26, 1, 0, 0)` |
| UTC | `twz.utc == Time.utc(2014, 10, 25, 22, 0, 0)` |
| Abbr | `twz.zone == "MSK"` |
| DST | `twz.dst? == false` |
| Offset | `twz.utc_offset == 10800` |
| Period helper | `zone.period_for_local(Time.utc(2014, 10, 26, 1, 0, 0)) == zone.period_for_local(Time.utc(2015, 1, 1))` |

Existing `test_local_with_ambiguous_time` only checks UTC, because `assert_equal Time.utc(...), twz` uses `#<=>` on the instant (L246–248). A refactor could keep UTC and still change wall clock / abbr / DST.

**Detects:** blindly applying the Eastern “prefer DST” story (would pick UTC+4 → `2014-10-25 21:00:00Z`); using `periods.first`; treating 01:00 as a spring gap (+1h); MSK vs MSD mix-up.

**Evidence:** `test_local_with_ambiguous_time` L243–246; `test_period_for_local_with_ambiguous_time` L61–65; same instant from `parse`/`iso8601`/`strptime` L376–378, L539–541, L745–747.  
**Command:** `cd activesupport && bin/test test/time_zone_test.rb -i "/test_local_with_ambiguous_time|test_period_for_local_with_ambiguous_time/"`

### Case 7 — Pre-1900 Hawaii date (TZInfo LMT, not HST)

**Call:** `ActiveSupport::TimeZone["Hawaii"].local(1850, 2, 5, 15, 30, 45)`  
Civil fields survive; the period is **LMT**, not HST. Offset on this checkout: **−37886** (−10:31:26).

| Observable | Assert |
|---|---|
| Local | `twz.to_a[0, 6] == [45, 30, 15, 5, 2, 1850]` (and `twz.time` year/month/day/hour/min/sec match) |
| UTC | `twz.utc == Time.utc(1850, 2, 6, 2, 2, 11)` |
| Abbr | `twz.zone == "LMT"` — **not** `"HST"` |
| DST | `twz.dst? == false` |
| Offset | `twz.utc_offset == -37886` |
| Identity | `twz.time_zone == ActiveSupport::TimeZone["Hawaii"]` |

Existing `test_local_with_old_date` only pins civil fields + zone object (L208–211). That would still pass if a refactor hard-coded HST/−10:00 for all Hawaii locals.

**Detects:** `Time.utc` range/calendar failures before 1900; assuming a constant −36000 Hawaii offset; forcing abbreviation `"HST"`; using Unix-epoch-only conversion.

**Evidence:** `test_local_with_old_date` L208–211; `to_a` definition L460–462. LMT/UTC values measured via `TimeZone#local` on this checkout (tzdata-dependent; pin them).  
**Command:** `cd activesupport && bin/test test/time_zone_test.rb -i test_local_with_old_date`

### How to run the gate

Narrowest existing suite (must stay green):

```bash
cd activesupport && bin/test test/time_zone_test.rb -i "/test_local$|test_local_with_old_date|test_local_enforces_spring_dst_rules|test_local_enforces_fall_dst_rules|test_local_with_ambiguous_time|test_period_for_local_with_ambiguous_time/"
```

Same conversion without `TimeZone#local`:

```bash
cd activesupport && bin/test test/core_ext/time_with_zone_test.rb -i "/test_instance_created_with_local_time_enforces_spring_dst_rules|test_instance_created_with_local_time_enforces_fall_dst_rules/"
```

If the refactor only rewrites `TimeZone#local` / `get_period_and_ensure_valid_local_time` / `period_for_local`, those two commands are the preservation gate. Cases 1, 6, and 7 need the extra UTC/abbr/DST assertions above; Cases 2–5 are already fully pinned in `test_local_enforces_*`.

**Pass rule:** every case keeps wall-clock `time`, UTC instant, abbreviation, and `dst?` (where applicable). Failures in `time` vs `utc` are different bugs: `time` is civil fields; `utc` is the instant.
