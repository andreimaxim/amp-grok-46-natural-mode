`SignedKeyRotatingCookieJar#parse` verifies with the primary digest/secret first. `ActiveSupport::Messages::Rotator#read_message` only fires `on_rotation` after a fallback rotation succeeds. That flag is passed into `SerializedCookieJars#parse`:

```608:608:actionpack/lib/action_dispatch/middleware/cookies.rb
            self[name] = { value: value } if force_reserialize || reserialize?(dumped)
```

`self[]=` re-signs with the current verifier (`@verifier.generate` plus `cookie_metadata`) and `CookieJar#[]=` queues `Set-Cookie` because the blob changed.

Existing tests plant an old-secret / old-digest cookie, `get :get_signed_cookie` (read only), then verify the *response* cookie with the current verifier:

- `test_signed_cookie_rotating_secret_and_digest` ([cookies_test.rb:641](file:///home/user/workspace/repo/actionpack/test/dispatch/cookies_test.rb#L641)) — old SHA1 + raw secret → SHA256 + derived key on `@response.cookies["user_id"]`
- `test_rotating_signed_cookies_digest` ([cookies_test.rb:1000](file:///home/user/workspace/repo/actionpack/test/dispatch/cookies_test.rb#L1000)) — same secret, SHA1 → SHA256 rewrite

With the proposed change those two error:

```

    test/dispatch/cookies_test.rb:655

CookiesTest#test_rotating_signed_cookies_digest
ActiveSupport::MessageVerifier::InvalidSignature: invalid message string
    test/dispatch/cookies_test.rb:1014
```

`@response.cookies["user_id"]` is nil, so `verifier.verify` fails. Current-key / tamper / expiry / serializer-migration tests in the same filter still passed — the patch only kills rotation upgrade.

`railties/test/application/middleware/cookies_test.rb` (SHA512 with rotated SHA256/SHA1) asserts the same rewrite after `read_signed`. Without it, old-key cookies never get a current signature, so the rotation can never be dropped.

### High — “unnecessary rewrite” cases already do not rewrite

`on_rotation` does not fire on the primary codec (`activesupport/test/messages/message_rotator_tests.rb`). So `force_reserialize` is already false for a current signature.

| Input | Verify | Rewrite today? | After patch |
|---|---|---|---|
| Current secret/digest | value | No | No |
| Old secret and/or old digest, rotation configured | value | **Yes** via `on_rotation` | **No — broken** |
| Old serializer (hybrid Marshal→JSON, JSON→MessagePack) | value | Yes via `reserialize?(dumped)`, independent of `rotated` | Still yes |
| Marshal serializer reading JSON dump | value | No (`assert_nil @response.cookies["user_id"]`) | No |
| Tampered / unsigned | `nil` | No | No |
| Expired metadata | `nil` | No (`invalid_message_content` / `"expired"` swallowed by `verified`) | No |

Serializer upgrades are a separate gate. The patch does not avoid serializer churn; it only disables key/digest upgrade.

Expiry is also independent: `cookie_metadata` stamps `expires_in`/`expires_at` and optional `purpose` only on `commit`. Skipping the rotation rewrite leaves the cookie on the old key *and* without a purpose upgrade. `AbstractCookieJar#[]` retrying without purpose is not a substitute for re-signing.

### High — signed-only change diverges from the encrypted jar

Same pattern at [cookies.rb:694](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/middleware/cookies.rb#L694):

```694:696:actionpack/lib/action_dispatch/middleware/cookies.rb
          rotated = false
          data = @encryptor.decrypt_and_verify(encrypted_message, purpose: purpose, on_rotation: -> { rotated = true })

```

`test_encrypted_cookie_rotating_secret` and the HMAC-CBC → AEAD upgrades assert a rewritten response cookie. Changing only the signed jar would make signed and encrypted rotation diverge with no stated reason. The patch also leaves `rotated` assigned but unused (Ruby warning once applied).

### Tests this change would need

Do not weaken the two rotation tests. If the intent is a narrower “no rewrite” case, pin that case without dropping upgrade-on-read:

1. **Keep:** `test_signed_cookie_rotating_secret_and_digest`, `test_rotating_signed_cookies_digest` — old blob in, current verifier can read `Set-Cookie`.
2. **Current signature, no `Set-Cookie`:** plant a cookie generated with the current derived key + digest; `get :get_signed_cookie`; `assert_nil @response.cookies["user_id"]`. That is the actual “no unnecessary rewrite” assertion; it is not covered as such today.
3. **Old digest/secret still readable if rewrite is skipped:** would assert the request cookie remains and the old verifier still verifies it. That is the opposite of Rails’ rotation model and means old rotations can never be dropped.
4. **Tamper / expiry:** already covered; must stay nil + no `Set-Cookie`.
5. **Serializer vs rotation:** hybrid Marshal→JSON and JSON→MessagePack must still rewrite via `reserialize?` even if `force_reserialize` is false.
6. **Encrypted twin:** if signed behavior changes, encrypted needs a matching decision (`test_encrypted_cookie_rotating_secret`).
7. **`test_cookie_with_hash_value_not_modified_by_rotation`** only checks the deserialized Hash is not mutated; it does *not* assert absence of rewrite.

Active Support rotator tests already prove `on_rotation` semantics. Action Pack is the layer that turns that callback into a cookie write.

**Recommendation:** leave `force_reserialize: rotated`. Current code already skips rewrite for a current signature, a tampered cookie, an expired cookie, and a same-format serializer. The only rewrite this patch removes is the one rotation is for.
