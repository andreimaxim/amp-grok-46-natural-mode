### Why an endless range does not need complete traversal

`GenericEnumerable.new(1..).sole` (438) is `Enumerable#sole`, not `Range#sole`. `1..`’s `each` yields `1`, then `2`, then `3`, … forever.

After the first yield, `found` is true. The second yield hits the `if found` branch and raises `"multiple items found"` (243–244). `each` is aborted by the exception; later integers are never requested.

That is sequential short-circuit, not a size check. An enumerator that yielded one item and then blocked forever would hang. An endless range does not, because a second item arrives immediately.

`Range#sole` is a different, earlier exit: if `begin` or `end` is `nil`, it raises `"infinite range '#{inspect}' cannot represent a sole item"` without calling `super` ([range/sole.rb](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/range/sole.rb) 15–20).
