## Behavior-preservation verification for `SchemaCache`

No refactor design. This pins current behavior from [`schema_cache.rb`](file:///home/user/workspace/repo/activerecord/lib/active_record/connection_adapters/schema_cache.rb) and [`schema_cache_test.rb`](file:///home/user/workspace/repo/activerecord/test/cases/connection_adapters/schema_cache_test.rb), plus sqlite3_mem query traces on `ARUnit2Model` (`courses` / `professors` / `colleges`).

### Harness

- Keep `self.use_transactional_tests = false`.
- Drive the public surface through `BoundSchemaReflection` (what the existing tests use) and `SchemaCache` directly for `dup` / `marshal_*` / `init_with`.
- Count with `assert_queries_count` / `assert_no_queries` **`include_schema: true`**. Metadata uses `name: "SCHEMA"` and is invisible without that flag.
- Pin SQL shape with `assert_queries_match` / `capture_sql(include_schema: true)` when two different metadata reads have the same count (full `data_sources` list vs per-name `data_source_exists?`).
- Default exact counts below are **sqlite3_mem / SQLite**. Treat them as the preservation baseline for that adapter. PostgreSQL and MySQL keep the same cache-hit zeros and result values; first-hit counts differ (see Portability).

`courses` is the fixture: 3 columns (`id`, `name`, `college_id`), PK `"id"`, 1 index (`index_courses_on_college_id`). `colleges` has 0 indexes. `courses_professors` has no PK. `professors` is the ignored-table target.

### Lazy population and repeat access

All five readers miss-fill their own hash and then hit. `columns_hash` is derived from `columns` and does not query on its own. `primary_keys` and `indexes` call `data_source_exists?` first, so a cold cache pays for the data-source list.

#### sqlite3_mem exact counts (`include_schema: true`)

| Call | Cold cache | Repeat / already filled |
|---|---|---|
| `data_source_exists?("courses")` | **1** — `SELECT name FROM pragma_table_list …` (all tables, no `name =`) | **0** |
| `data_source_exists?("foo")` after the list is cached | **1** — same SQL with `AND name = 'foo'` | **0** |
| `columns("courses")` | **1** — `table_structures` / `pragma_table_info` | **0** |
| `columns_hash("courses")` | **1** (via `columns`) | **0** |
| `columns_hash` after `columns` | **0** | **0** |
| `columns` after `columns_hash` | **0** | **0** |
| `primary_keys("courses")` | **2** — full data-source list + `table_structures` | **0** |
| `primary_keys` after `data_source_exists?` | **1** — `table_structures` only | **0** |
| `indexes("courses")` (table has indexes) | **3** — list + `pragma_index_list` + `pragma_index_info` | **0** |
| `indexes("colleges")` (no indexes) | **2** — list + `pragma_index_list` (no details query) | **0** |

Assertions that catch extra round trips:

- Repeat of any successful lookup: `assert_no_queries(include_schema: true)`.
- Cold `columns("courses")` / `columns_hash("courses")`: `assert_queries_count(1, include_schema: true)` on SQLite.
- Cold `primary_keys("courses")`: **exactly 2** on SQLite. A third query is an extra metadata trip.
- Cold `indexes("courses")`: **exactly 3** on SQLite. A fourth is extra. `indexes("colleges")` must stay **2**, not 3 — the details query is skipped when no index names come back.
- After `data_source_exists?`, `primary_keys("courses")` must be **1**, not 2. Re-listing tables is a regression.
- `assert_queries_match(/pragma_table_list/i, count: 1, include_schema: true)` on the first `data_source_exists?`, and `count: 0` on the second. The second existing-table lookup must not emit `AND name = 'courses'`.
- First unknown table after a list: match `name = 'foo'` (or adapter equivalent), **not** a second full list.

Result values to keep:

- `assert_equal 3, cache.columns("courses").size`
- `assert_equal 3, cache.columns_hash("courses").size`
- `assert_equal "id", cache.primary_keys("courses")`
- `assert_equal 1, cache.indexes("courses").size`
- `assert cache.data_source_exists?("courses")`
- `assert_equal false, cache.data_source_exists?("foo")` — **`false`, not `nil`**. Ignored tables return `nil` (below). `assert_not` would hide that.

Isolation of derived maps:

- `columns_hash?("courses")` is false until `columns_hash` runs. `columns` and `data_source_exists?` must not set it.
- `cached?("courses")` is `@columns.key?`. True after `columns` / `add`; still false after only `data_source_exists?`.

`size` after `add("courses")` is **8** on arunit2: `@columns` 1 + `@columns_hash` 1 + `@primary_keys` 1 + `@data_sources` 5. First `data_source_exists?` inserts every arunit2 table (`courses`, `colleges`, `professors`, `courses_professors`, `dogs`). **`size` does not count `@indexes`.** Preserve that.

### `add` and `clear!`

#### `add("courses")` on a cold cache — SQLite **exactly 5**

1. full `data_sources` list
2. `table_structures` for `primary_keys`
3. `table_structures` again for `columns` (not shared today)
4. `pragma_index_list`
5. `pragma_index_info`

Then `add("courses")` again and all five readers: **0** queries.

`columns_hash` is filled from the in-memory column array; it must not add a 6th query.

A coalescing refactor that drops the duplicate `table_structures` would change 5 → 4. That is a behavior change relative to this baseline; keep 5 if the goal is preservation.

#### `add("omgponies")` — SQLite **2** (list + per-name exists), returns nil, fills no `@columns` / `@primary_keys` / `@indexes`. Repeat: **0**.

#### `clear!`

- 0 queries.
- `assert_equal 0, cache.size`.
- Next `columns("courses")` is a cold miss again (**1** on SQLite).
- `BoundSchemaReflection#clear!` replaces the whole `SchemaCache` with a new empty one, not hash-by-hash delete.

#### `clear_data_source_cache!("courses")` after `add("courses")` and `add("professors")`

- 0 queries to clear.
- Next `data_source_exists?("courses")`: **exactly 1**, SQL is the **per-name** exists query (`name = 'courses'`), not a full list. Other tables remain in `@data_sources`, so `@data_sources` is not empty.
- `columns("professors")`: **0** (other table untouched).
- `columns("courses")`: **1** (that table’s columns were dropped).
- If the entry were stale-left in `@data_sources`, exists? would be 0 queries. If the whole `@data_sources` hash were wiped, SQLite would still be 1 query but the SQL would be the full list — `assert_queries_match` catches that.

### Nonexistent tables

| Call | Result | Queries (SQLite) |
|---|---|---|
| `primary_keys("omgponies")` | `nil` | first **2** (list + by-name exists); repeat **0** |
| `indexes("omgponies")` | `[]` | first **2**; repeat **0** |
| `columns("omgponies")` | `ActiveRecord::StatementInvalid` (`Could not find table 'omgponies'` on SQLite) | **1 every call** |
| `columns_hash("omgponies")` | same raise | **1 every call** |
| `data_source_exists?("omgponies")` | `false` | **1** by-name if the list is already cached; **2** if cold (list + by-name) |

Negative `primary_keys` / `indexes` are **not** stored. Repeat is 0 only because `@data_sources["omgponies"] = false` is stored. After `clear_data_source_cache!("omgponies")`, `primary_keys` / `indexes` query again.

`columns` never caches a miss: the raise happens inside `connection.columns`, so a refactor that caches the exception or returns `[]` is a fail.

Do not use `assert_raises` alone for columns — also assert the query still happens on the second call.

### Composite primary keys and no PK

Keep the existing `add_all` tests:

- `courses_professors` → `primary_keys` is `nil`.
- Table created with `primary_key: [:one, :two]` → `["one", "two"]` (array, not joined string).

`add_all` uses `connection.primary_keys(tables)` (plural, bulk). For each table it stores the array when `primary_keys.size > 1`, otherwise `.first` (which may be `nil`). Lazy `primary_keys` goes through `connection.primary_key` (singular), which uses the same rule. Both paths must agree.

After `add_all`, `primary_keys(pool, table)` for those tables is **0** queries.

### Schema-ignored tables (string and regexp)

`ActiveRecord.schema_ignored_table?` is `ignored === table_name` over `schema_ignored_tables`. Cover `["professors"]` and `[/^profess/]`. Both must be identical.

On an ignored name, **every** reader is **0** queries:

| Call | Result |
|---|---|
| `data_source_exists?("professors")` | `nil` (not `false`) |
| `columns` / `columns_hash` | `StatementInvalid` message `Table 'professors' doesn't exist` — raised in `SchemaCache#columns` before the adapter |
| `primary_keys` | `nil` |
| `indexes` | `[]` |
| `add` | no-op, still 0 queries |
| `cached?` | `false` |

`data_source_exists?("courses")` while `professors` is ignored still **1** (full list with `professors` filtered out of `tables_to_cache`). The dumped cache must contain `courses` and must not contain `professors`.

Dump/load under the ignore list (existing `assert_professors_ignored`): after Marshal dump/load, courses accessors work with **0** queries; professors still ignored as above. String and regexp configs must both produce that dump.

Deprecated `schema_cache_ignored_tables` / `schema_cache_ignored_table?` still delegate and warn; keep those tests, they are not cache-query behavior.

### Duplicate-cache independence

`initialize_dup` dups `@columns`, `@columns_hash`, `@primary_keys`, `@data_sources`, `@indexes` only.

- `dup`’s five hashes are different objects (`refute_same`).
- Values inside (column arrays, Column objects) **are** shared until a hash slot is rewritten. That is current behavior; columns are frozen, so in-place mutation is not the independence test.
- After `a.add(pool, "courses")`; `b = a.dup`; `b.clear_data_source_cache!(pool, "courses")`:
  - `a.columns(pool, "courses")` → **0** queries, still 3 columns.
  - `b.columns(pool, "courses")` → **1** query (SQLite).
- `b.add(pool, "professors")` must not make `a.cached?("professors")` true. Test this **without** calling `a.columns("professors")` first.

### Frozen / deduplicated cached values

On a live fill (`columns` / `columns_hash`, not dump-derived):

- The columns **array** is not frozen; each `Column` is frozen; `column.name` is frozen (`-value` / `Deduplicable#-@`).
- `columns_hash` **hash** is frozen; values are the same objects as in the columns array (`assert_same`).
- Second `columns("courses")` returns the same array object (`assert_same`).
- Column names are interned: `cache.columns("courses").first.name.equal?(cache.columns("courses").first.name)`.
- `init_with` with `"deduplicated" => true` must not rewrite `coder["columns"]` (`assert_same`).
- `init_with` without that flag rebuilds `@columns_hash` from `@columns` and runs `deep_deduplicate` on columns, primary keys, data sources, indexes.
- YAML/Marshal **load** path does **not** freeze the per-table `columns_hash`; only the lazy `columns_hash` writer does `.freeze`. Preserve that split.
- Marshal `_load_from` uses `Marshal.load(file, freeze: true)` for `*.dump`. YAML uses `YAML.unsafe_load` (not freeze).

Reset Deduplicable registries around dump/load the way the current tests do (`reset_deduplicable!`), or interned objects from a previous cache leak into assertions.

### Deterministic YAML / Marshal dump/load

`dump_to` always builds a **fresh** cache via `add_all` + `version`, then writes it. It does not dump the lazily populated in-memory subset. Dumping an unused `BoundSchemaReflection` still snapshots every non-ignored table.

Formats:

- path containing `.dump` → Marshal; otherwise YAML.
- extension `.gz` → `Zlib::GzipWriter` with **`mtime = 0`**, which is why two dumps a second apart have identical MD5 (`test_gzip_dumps_identical`).
- YAML `encode_with` writes **sorted** `columns`, `primary_keys`, `data_sources`, `indexes`, plus `version`. It does **not** write `columns_hash` or `deduplicated`.
- `marshal_dump` is `[@version, @columns, {}, @primary_keys, @data_sources, @indexes]` — empty hash in the columns_hash slot, rebuilt on load.

After dump/load (YAML, Marshal, each with and without `.gz`), for `courses`:

```
assert_no_queries(include_schema: true) do
  assert_equal 3, cache.columns("courses").size
  assert_equal 3, cache.columns("courses").map { |c| c.cast_type }.compact.size
  assert_equal 3, cache.columns_hash("courses").size
  assert cache.data_source_exists?("courses")
  assert_equal "id", cache.primary_keys("courses")
  assert_equal 1, cache.indexes("courses").size
end
```

`load!` with `check_schema_cache_dump_version` still enabled issues **exactly 1** schema-version query (`schema_migrations` exists on SQLite). The `assert_no_queries` block is the accessors **after** `load!`, not `load!` itself.

Gzip: MD5(file_a) == MD5(file_b) after `sleep 1`. Also unzip manually (`Zlib::GzipReader` + `YAML.unsafe_load` / `Marshal.load`) and hit the same 0-query accessor block on the raw `SchemaCache` (pool-taking API).

`#encode_with` sorts members: feed unsorted pairs, assert keys `== keys.sort`, and `coder.key?("version")`.

`dump_to` creates parent directories (`test_cache_path_can_be_in_directory`).

### Schema version and dump-version checking

`SchemaCache#version` is `@version ||= connection.schema_version`. First call **1** query on SQLite (`schema_migrations` exists); repeat **0**. Dumped files store `version: 0` in this suite.

`SchemaReflection` load, `check_schema_cache_dump_version` **true** (default):

- Compares `new_cache.version(connection)` (cached in the file, 0 queries) to `connection.schema_version` (**1** query).
- Match → keep dump. Accessors: 0 queries.
- Mismatch → stderr warning `Ignoring <path> because it has expired. The current schema version is X, but the one in the schema cache file is Y.` Load returns nil; empty cache is used. Next `columns("courses")` **1** query (cold).
- `ActiveRecordError` during the check: warn `Failed to validate the schema cache because of …` and skip the dump.

`cached?(table)` with check **enabled** and `@cache` nil: **does not** load the file (would need a DB). Returns `nil`.

`check_schema_cache_dump_version` **false**:

- `cached?("courses")` loads the dump with **no pool** and returns true.
- `BoundSchemaReflection.new(reflection, :__unused_pool__)` can serve `columns` / `primary_keys` / `indexes` with **0** queries.
- Expired / unhealthy DB must still load (covered in railties; at the AR layer, skip the version query entirely).

`use_schema_cache_dump = false` or missing file: `load_cache` returns nil, empty cache, lazy population as in the first table.

`lazily_load_schema_cache`: skip on `in_memory_db?`. Otherwise `@cache` stays nil until first connection when the flag is on; stays nil across `establish_connection` when the flag is off until something calls `schema_cache.version` / `load!`.

### Stale-entry assertions (these catch a cache that starts bypassing itself)

Exact query counts do not catch “always re-read the adapter.” Pair them with a mutation:

1. `cache.columns("courses")` → 3.
2. `connection.add_column(:courses, :extra, :string)` (or `change_table`).
3. `cache.columns("courses").map(&:name)` still **excludes** `extra` and is **0** queries.
4. `cache.clear_data_source_cache!("courses")` then `columns("courses")` **includes** `extra` and is **1** query (SQLite).
5. `professors` columns unchanged through step 4.

Same pattern for indexes (add an index, cached list stays old until clear) and `data_source_exists?` (drop table: cached `true` until `clear_data_source_cache!` or `clear!`).

`test_insert_uses_schema_cache_for_primary_key`: after one insert to warm the cache, a second `insert` is **exactly 1** query (`INSERT …`, no schema). A 2nd query is an extra metadata trip through `schema_cache.primary_keys` / `columns_hash`.

### Adapter portability boundaries

Portable (assert on sqlite3, postgresql, mysql2, trilogy):

- Repeat / dump-hit / ignored-table query counts of **0**.
- Result values for `courses` / `professors` / missing tables / ignored tables / composite PK / `columns_hash?` / `cached?` / `size` after `clear!`.
- `false` vs `nil` for exists?.
- `columns` / `columns_hash` miss never caches; always raises and always queries.
- Dump format, sort order, gzip MD5, 5.1 indexes miss, marshal 5-element load.
- Version-check on/off and expired-dump warning.
- Dup hash independence.
- `insert` after warm = 1.

Adapter-specific first-hit counts (do **not** hard-code SQLite’s 5/3/2 onto PostgreSQL/MySQL):

- **SQLite:** numbers in the tables above. `indexes` is 2 or 3 depending on whether any index names exist. `add` is 5 because PK and columns each call `table_structures`.
- **PostgreSQL / MySQL:** `fetch_column_definitions`, `fetch_primary_keys`, `fetch_indexes` are typically **one** catalog query per call (per schema group). Cold `columns` / `columns_hash` = 1; cold `primary_keys` = 2 (exists list + PK); cold `indexes` = 2 (exists list + indexes); cold `add` ≈ 4 (list + PK + columns + indexes), not 5. Confirm with `capture_sql` per adapter rather than copying SQLite.
- `schema_statements_test` already allows adapters that still do one read per table (`skip` if no reader is cheaper than N tables). Do not require bulk-read query counts from `SchemaCache` tests on those adapters.
- `schema_version` SQL differs; only assert **1** query on first `version` / dump-version check, **0** after.
- Qualified names / search_path: PostgreSQL may add a schema query in `fetch_by_schema` when names span schemas. Stay on unqualified arunit2 names in this suite.
- `in_memory_db?` skips the lazily-load connection test.
- 5.1 fixture is an **arunit** dump (`posts`); `indexes("courses")` on it hits **arunit2** live schema. That cross-DB mismatch is current behavior — keep using `courses` for the “missing indexes still query” case.

When asserting first-hit counts in a multi-adapter run: either `if current_adapter?(:sqlite3)` exact numbers, or `assert_queries_count` with no `count:` (at least one) plus `assert_no_queries` on repeat. The extra-round-trip net is the **repeat = 0** and **clear_data_source_cache! = 1 per-name** checks, which are portable.
