2. Immediately assign the replacement with `public_send("#{key}=", value)`.
3. Only after every pair succeeds: `yield self`.
4. `ensure` then walks `old_values` in the same insertion order and writes each captured old value back, again via `public_send("#{key}=", old_value)`.

A key is in `old_values` only if its **reader** returned. A later writer raising does not un-record earlier keys, and does not prevent the failed attribute’s own old value from being recorded (the read already happened).

### Block: receiver in, block result out

`yield self` ([with.rb:38](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L38)) passes the receiver. The method’s result is the block’s result: `begin`/`ensure` returns the `begin` body when `ensure` finishes without raising.

- Yield: `@object.with(public_attr: "1", &:public_attr)` equals `"1"` ([with_test.rb:91–93](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L91-L93)).
- Return: `@object.with(public_attr: "1") { :block_result }` equals `:block_result` ([with_test.rb:95–98](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L95-L98)).

The happy path is [with_test.rb:32–43](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L32-L43): both attrs change inside the block and both originals are back after.

### `ensure` when the block raises

If every assignment finished, `old_values` holds every attribute. The block raising still runs `ensure`, which writes every captured old value back. The original exception then propagates (`assert_raise RuntimeError` around the `raise "Oops"`). Afterward both attrs are originals ([with_test.rb:45–59](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L45-L59)).

The block never runs if an assignment raises: that test’s body is `assert false` ([with_test.rb:66–68](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L66-L68)).

### Two attributes: first writer succeeds, second writer raises

Fixture: `public_attr` is a public accessor; `mixed_attr` has a public reader and a **private** writer ([with_test.rb:16–25](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L16-L25)). Call:

```ruby
@object.with(public_attr: :changed, mixed_attr: :changed_too)
```

([with_test.rb:61–73](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L61-L73))

Start: `public_attr == :public`, `mixed_attr == :mixed`.

| Step | Action | `old_values` | Object state |
|---|---|---|---|
| 1 | `public_send(:public_attr)` → `:public` | `{public_attr: :public}` | unchanged |
| 2 | `public_send("public_attr=", :changed)` succeeds | same | `public_attr == :changed` |
| 3 | `public_send(:mixed_attr)` → `:mixed` | `{public_attr: :public, mixed_attr: :mixed}` | `public_attr` still `:changed` |
| 4 | `public_send("mixed_attr=", :changed_too)` raises `NoMethodError` (private writer) | same | `mixed_attr` still `:mixed` (never assigned) |
| 5 | skip `yield` | | |
| 6 | `ensure`: `public_send("public_attr=", :public)` | | **`public_attr` restored to `:public`** |
| 7 | `ensure`: `public_send("mixed_attr=", :mixed)` | | also `NoMethodError`; `mixed_attr` still `:mixed` |

**Exactly what is restored:** `public_attr` is restored to `:public`. `mixed_attr` is not mutated by the method at all; it stays `:mixed`.

`ensure` *attempts* to restore both keys because both readers succeeded. The `mixed_attr=` restore fails for the same private-writer reason. In Ruby, an exception from `ensure` replaces the original, so the propagating `NoMethodError` is the restore’s, not the assignment’s. The test only asserts `NoMethodError` plus both final values ([with_test.rb:65–72](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L65-L72)).

Solo `mixed_attr` is the same pattern: read records the old value, write raises, `ensure` write raises again, value never changes ([with_test.rb:84–88](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L84-L88)).

If the **reader** raises first (`private_attr` / `protected_attr`), that key never enters `old_values`, later keys are not visited, `ensure` is a no-op ([with_test.rb:75–82](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L75-L82)).

### Public reader and public writer

Both legs use `public_send` ([with.rb:35–36, 41](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L35-L41)). The comment states the contract: usable “as long as both the reader and writer methods are public” ([with.rb:29–30](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L29-L30)). Private accessor, protected accessor, and public-reader/private-writer all raise `NoMethodError` ([with_test.rb:75–89](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L75-L89)).

### Immediates: method removed

`#with` is undefined on `NilClass`, `TrueClass`, `FalseClass`, `Integer`, `Float`, and `Symbol` ([with.rb:47–51](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L47-L51)), “to avoid potential confusion” because it isn’t usable on immediates. Tests: `nil`, `true`, `false`, `1`, `1.0`, `:sym` do not respond to `#with` ([with_test.rb:100–107](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L100-L107)). `String` is not in that list.
