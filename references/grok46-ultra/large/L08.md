`Enumerable#sole` returns the only yielded item, or raises. It never uses `nil` as a “missing” sentinel, and it stops as soon as a second item appears.

### Contract

Defined in [activesupport/lib/active_support/core_ext/enumerable.rb](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/enumerable.rb) at 230–256. Docs at 230–237: exactly one item, otherwise `Enumerable::SoleItemExpectedError`.

The exception class is `Enumerable::SoleItemExpectedError < StandardError` (19–21). For MRI constant-cache reasons it is immediately moved to `ActiveSupport::EnumerableCoreExt::SoleItemExpectedError` (23–26); `Enumerable::SoleItemExpectedError` still resolves via `const_missing` (7–13, 26). Tests look it up as `Enumerable::SoleItemExpectedError`.

Messages established in source:

- `"multiple items found"` (244)
- `"no item found"` (255)

`Range#sole` in [activesupport/lib/active_support/core_ext/range/sole.rb](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/range/sole.rb) is a separate guard. It is not the path the focused enumerable tests exercise for `1..`.

### Control flow

```text
sole
  result = nil
  found  = false
  each do |*element|
    if found → raise SoleItemExpectedError, "multiple items found"
    result = (element.size == 1 ? element[0] : element)
    found  = true
  end
  found ? result : raise SoleItemExpectedError, "no item found"
```

Two flags, not one: `found` is “have we seen an item?”, `result` is the item itself (which may be `nil`).

Empty, one, many — from [activesupport/test/core_ext/enumerable_test.rb](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb) `test_sole` at 431–438, using `GenericEnumerable` (35–45), whose `each` just forwards to the wrapped collection:

| Input | What happens | Result |
|---|---|---|
| `[]` | `each` never yields; `found` stays false | `SoleItemExpectedError`, `"no item found"` (434, 255) |
| `[1]` | one yield; unwrap; `found = true`; loop ends | `1` (435) |
| `[1, 2]` | second yield sees `found` | `SoleItemExpectedError`, `"multiple items found"` (436, 243–244) |
| `[1, nil]` | `nil` is a second real element | same multiple-items error (437) |
| `1..` (endless range, via GenericEnumerable) | yields `1`, then `2`, then raises on that second yield | multiple-items error (438) — **does not walk the rest of the range** |

`nil` as a real element is why `found` exists. If absence were encoded as `result.nil?`, a sole `nil` would look empty, and `[1, nil]` could look like a single item. The `[1, nil]` case (437) proves the second `nil` counts. A lone `nil` is not asserted in these tests, but the same `found` flag would return it.

### Why an endless range does not need complete traversal

`GenericEnumerable.new(1..).sole` (438) is `Enumerable#sole`, not `Range#sole`. `1..`’s `each` yields `1`, then `2`, then `3`, … forever.

After the first yield, `found` is true. The second yield hits the `if found` branch and raises `"multiple items found"` (243–244). `each` is aborted by the exception; later integers are never requested.

That is sequential short-circuit, not a size check. An enumerator that yielded one item and then blocked forever would hang. An endless range does not, because a second item arrives immediately.

`Range#sole` is a different, earlier exit: if `begin` or `end` is `nil`, it raises `"infinite range '#{inspect}' cannot represent a sole item"` without calling `super` ([range/sole.rb](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/range/sole.rb) 15–20). Tests in [activesupport/test/core_ext/range_ext_test.rb](file:///home/user/workspace/repo/activesupport/test/core_ext/range_ext_test.rb) 335–349 cover `(1..1)`, empty `(2..1)` → `"no item found"`, `(..1)` and `(1..)` → the infinite-range message. The enumerable test’s `1..` never takes that path.

### How yields are represented

The block is `each do |*element|` (242). Everything `each` yields is packed into an array, then optionally unwrapped (247):

```ruby
result = element.size == 1 ? element[0] : element
```

That matches `Enumerable#first`’s packing, which the tests assert.

**One value** (`test_sole`, 435): `each` yields `1`. `|*element|` → `[1]`. `size == 1`, so `sole` returns `1`, not `[1]`.

**Multiple positional values** (`test_sole_returns_same_value_as_first_for_tuples`, 441–444):

```ruby
enum = Enumerator.new(1) { |yielder| yielder.yield(1, "one") }
assert_equal [1, "one"], enum.sole
assert_equal enum.first, enum.sole
```

`yield(1, "one")` → `|*element|` → `[1, "one"]`. `size != 1`, so the array is kept. Same value as `first`.

**Positional value plus keywords** (`KeywordYielder` / `test_sole_keyword_arguments`, 447–458):

```ruby
def each
  yield 1, two: 3
end
assert_equal [1, { two: 3 }], yielder.sole
assert_equal yielder.first, yielder.sole
```

`|*element|` has no `**`. The keyword hash is packed as the last splat element: `[1, { two: 3 }]`. Again `size != 1`, so `sole` returns that array, equal to `first`.

So: single yield → unwrap; two or more positionals, or a positional plus keywords → keep the packed array. `sole` does not distinguish “one array element” from “one yielded value”: an `each` that yields a single array still unwraps because `element.size == 1`. The focused tests only cover the three cases above.
