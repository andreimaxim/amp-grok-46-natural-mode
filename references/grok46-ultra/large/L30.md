### Current behavior (what must not change)

#### `send_stream`

Public contract: `send_stream(filename:, disposition: "attachment", type: nil, &block)`.

1. Builds a notification payload `{ filename:, disposition:, type: }` using the **original** `type` argument, not the resolved Content-Type.
2. Instruments `send_stream.action_controller` around header assignment and the yielded block. `response.stream.close` is in `ensure`, **outside** the instrumented block.
3. Content-Type, first match wins:
   - `type` is a Symbol → `Mime[type].to_s`
   - else `type` if truthy (explicit string)
   - else `Mime::Type.lookup_by_extension(File.extname(filename).downcase.delete("."))&.to_s`
   - else `"application/octet-stream"`
4. Content-Disposition is `ActionDispatch::Http::ContentDisposition.format(disposition:, filename:)` (ASCII `filename=` plus RFC 5987 `filename*=UTF-8''`).
5. Yields `response.stream` (a `Live::Buffer`).
6. Closes the stream on every exit, including exceptions from the block.

`writeln` is Buffer behavior, not `send_stream`: write the string, appending `"\n"` only when it does not already end with one.

#### `Live::Buffer` and commit/close

`Live::Buffer` is a queued `ActionDispatch::Response::Buffer`:

- First `write`/`close` commits the response. On first write, if not yet committed: `Cache-Control` defaults to `"no-cache"` (does not overwrite an existing value) and `Content-Length` is deleted.
- `write` pushes a **dup of unfrozen strings**, returns `bytesize`, then if `!connected?` (`@aborted`) clears the queue and either raises `ActionController::Live::ClientDisconnected` (`ignore_disconnect` false, default) or discards (`true`).
- `close` (producer finished): commit, mark closed, push `nil` terminator, broadcast.
- `abort` (client gone): `@aborted = true`, clear queue, push `nil` terminator, broadcast. Duplicate terminator after close is harmless.
- `each_chunk` pops until `nil`.
- Default queue is `SizedQueue` of size 10; `queue_size = nil` uses unbounded `Queue`.

Response roles:

- `Response#close` = producer done → `stream.close`.
- `Response#abort` = client gone → `stream.abort`.
- `RackBody#close` maps to **abort**, not close.
- `process` always `commit!`s in the child-thread `ensure`, then the caller `await_commit`s. Exception **before** commit is stored and re-raised on the caller after `await_commit`. Exception **after** commit is not re-raised: HTML writes `ActionView::Base.streaming_completion_on_exception`, `call_on_error` runs, the error is logged, and the stream is closed.

#### Executor / thread

`Live#process` snapshots `Thread.current` keys and `IsolatedExecutionState.context`, posts work to `Concurrent::CachedThreadPool` named `"action_controller.live"`, copies those locals onto the worker, then `IsolatedExecutionState.share_with(context, except: live_streaming_excluded_keys)`. After the action it nils the copied thread-local keys so the pooled thread can be reused.

**Test-env trap:** `ActionController::TestCase` makes `new_controller_thread` yield inline, no-ops `clean_up_thread_locals`, and sets `Buffer.queue_size = nil`. [`LiveStreamTest#setup`](file:///home/user/workspace/repo/actionpack/test/controller/live_stream_test.rb) restores the real thread spawn and cleanup. Thread-pool and disconnect checks must keep that restore. Buffer unit tests that need a bounded queue must set `queue_size` themselves and restore it.

Functional `get` always ends in `process_controller_response` calling `prepare!` then `sent!`. After `get`, `response.sent?` is not independent proof that Live’s send path ran. Prefer `stream.closed?` + `committed?` plus drained body.

### Checks

For each: seam (how to drive it) and assertion (what is observable). All controller actions belong on `LiveStreamTest::TestController` unless noted.

#### 1. Inferred content type

**Seam:** `get :send_stream_with_inferred_content_type` (`filename: "sample.csv"`, `type` omitted). Also one unknown extension (`"export.bin"` / `"file.unknownext"`) and a no-extension name (`"export"`).

**Assert:** `headers["Content-Type"]` is a `String` equal to `"text/csv"` for `.csv`. Unknown/missing extension → `"application/octet-stream"`. Body still drains. `assert_stream_closed`.

Existing `test_send_stream` / `test_send_stream_with_inferred_content_type` cover csv; the fallback is the gap.

#### 2. Explicit content type

**Seam:** existing `send_stream_with_explicit_content_type` (`type: "text/csv"`) and `send_stream_with_implicit_content_type` (`type: :csv`). Add one where explicit type **overrides** a conflicting extension, e.g. `filename: "sample.csv", type: "application/json"` or `type: :json`.

**Assert:** header is the resolved string (`"text/csv"` / `"application/json"`), class `String`, not a Mime object. Symbol `:json` → `"application/json"` even when filename says `.csv`. `assert_stream_closed`.

Do not assert `Mime[type]` identity; only the header string.

#### 3. RFC-compatible filename disposition

**Seam:** `get` of send_stream actions. Compute expected with the public formatter, do not copy encoding rules into the test:

```ruby
expected = ActionDispatch::Http::ContentDisposition.format(
  disposition: "attachment", filename: "my.csv"
)
assert_equal expected, @response.headers["Content-Disposition"]
```

Cases: default `attachment` + ASCII name (`test_send_stream`); `disposition: "inline"` (`test_send_stream_with_options`); non-ASCII filename (e.g. `"råcëçâr.csv"` or `"автомобиль.csv"`).

**Assert:** exact header equality, not `assert_match`. That pins both `filename=` and `filename*=UTF-8''`. `content_disposition_test.rb` stays the formatter unit suite; these tests only pin that `send_stream` uses it.

#### 4. Chunk order

**Seam:** a new action that yields the stream and writes several distinct chunks (`"A"`, `"B"`, `"C"`, optionally `writeln`). Consume **without** collapsing via `response.body` first:

```ruby
get :ordered_send_stream
response.await_commit
chunks = []
response.stream.each { |c| chunks << c }
assert_equal ["A", "B", "C"], chunks
```

Or, if using functional `get` after the action has already closed: `response.body == "ABC"` is a weaker but acceptable check **plus** a parallel consumer like `test_async_stream` / `live_response_test.rb#test_parallel`.

**Assert:** FIFO order, no extra/missing chunks, no coalescing requirement (Buffer yields one write per chunk). After close, `each` terminates (the `nil` terminator is not yielded).

**Sync:** if the producer writes across the consumer, use `CountDownLatch` per chunk as in `test_async_stream`. `await_commit` before `each`. `Thread.join(3)` and fail on timeout. Never `sleep`.

#### 5. Exception before commit

**Seam:** send_stream action that raises **before any `stream.write`/`close`** (the block raises immediately). Functional `get` is enough because `process` re-raises pre-commit errors on the caller.

**Assert:** `assert_raises(ThatError) { get :... }`. After the raise: if the test harness still has `@response`, stream is closed (`send_stream` ensure) and the response was committed by `process`’s ensure `commit!` (status/headers may still be the unrescued error path). Do **not** expect `streaming_completion_on_exception` in the body. Do **not** expect `on_error` to run. Notification still fires (see §11) with `:exception` / `:exception_object`.

Mirror of `test_exception_in_controller_before_streaming`, but the raise is inside the `send_stream` block so the ensure-close path is exercised.

#### 6. Exception after commit

**Seam:** send_stream action that writes at least once (commits), then raises. Drive with `get` + `capture_log_output`, same as `test_exception_handling_html` / `test_exception_in_view_after_commit`.

**Assert:**

- `get` does **not** raise to the test thread.
- HTML format: body ends with `ActionView::Base.streaming_completion_on_exception`; log includes the exception; `assert_stream_closed`.
- Non-HTML (`format: :json`): body is the bytes written before the error (or empty if the only write was `""`); no completion script; log still has the error; `assert_stream_closed`.
- Optional: `on_error` callback can write a sentinel, as in `exception_with_callback`.

`send_stream`’s ensure `close` and `process`’s post-commit `close` must not deadlock or leave `each` blocked.

#### 7. Client disconnect, `ignore_disconnect: false` (default)

**Seam:** restore real threads (already in `LiveStreamTest#setup`). Temporarily set `Buffer.queue_size = 10` so a write can block. Action: `send_stream(...)` writes enough to fill the queue **without** setting `ignore_disconnect`. Consumer: `await_commit`, `resp.to_a`, `body.each { body.close; break }` — `RackBody#close` → `abort`.

Pattern: `test_abort_with_full_buffer`.

**Assert:** producer surfaces `ClientDisconnected` (via `on_error` latch and/or log, not an uncaught thread exception — `new_controller_thread` sets `abort_on_exception = true`). After abort, further writes raise rather than enqueue. Stream ends for the reader (`each` returns). `error_latch.wait` with `Timeout.timeout(3)`.

**Sync / cleanup:**

- Save/restore `Buffer.queue_size` in `ensure`.
- Latches: one for “filled and about to block”, one for “on_error ran”.
- Join the consumer thread; `Timeout` around latch waits.
- Do not call `response.body` on the test thread while the consumer holds `each` (double-reader on the same queue).
- If a producer thread might still be in `SizedQueue#push`, abort/close must unblock it; join with timeout, then `kill` only in `ensure` if join failed.

#### 8. Client disconnect, `ignore_disconnect: true`

**Seam:** same consumer-close pattern as `test_ignore_client_disconnect`, but inside `send_stream`. Action sets `stream.ignore_disconnect = true`, writes to commit, then more writes after the client has closed, then a log sentinel / `latch.count_down`.

**Assert:** producer completes (`latch.wait` within 3s). Log contains the sentinel (`"Work complete"`). No `ClientDisconnected`. Extra writes are discarded (body may be empty/short). `send_stream` ensure still closes. Bounded queue must not deadlock: with ignore on, writes after abort clear the buffer and return; filling before abort still needs the consumer to `close` so `abort` unblocks a blocked `push`.

**Cleanup:** same queue_size restore if you set it; join consumer; timeout on latch.

#### 9. Stream closure on every path

**Seam:** `assert_stream_closed` after each `get` that returns normally. Paths to cover with send_stream actions:

| Path | Drive |
|---|---|
| Happy path, writes then block ends | existing basic/inferred/explicit actions |
| Block ends with no writes | new action: `send_stream(...) { }` |
| `writeln` only | inferred action already writes lines |
| Exception before commit | `assert_raises` then check `response.stream.closed?` |
| Exception after commit | existing after-commit pattern |
| Client abort, ignore false | after latches fire |
| Client abort, ignore true | after work-complete latch |
| `on_error` itself raises | mirror `exception_in_exception_callback` |

**Assert:** `response.stream.closed?`, `response.committed?`. Treat `sent?` as valid only after functional `get` (harness calls `sent!`). A `each` started after close must return (not hang) — `Timeout.timeout(5) { response.each {} }` or `reader.join(5)` as in `BufferTest#test_close_then_abort_still_terminates_the_reader`.

Unit-level complement (no controller): `BufferTest` already pins abort-unblocks-reader and close-then-abort. Keep those; they are layout-independent (`write`/`close`/`abort`/`each`).

#### 10. Copied thread-local state

**Seam:** `LiveStreamTest` already restores real `new_controller_thread`. Set `Thread.current[:setting] = "aaron"` and `CurrentState.id = "..."` / `IsolatedExecutionState[:key] = ...` on the test thread. New send_stream action asserts **inside the yielded block** (that is the worker):

```ruby
def send_stream_sees_locals
  send_stream(filename: "x.csv") do |stream|
    tc.assert_equal "aaron", Thread.current[:setting]
    tc.assert_equal "isolated", CurrentState.id
    stream.write "ok"
  end
end
```

**Assert:** assertions in the block pass (they run on the worker). After `get`, follow with `test_thread_locals_get_reset` / `test_isolated_state_get_reset` style: next request on a pooled thread does not see leftover locals (`no_thread_locals`). Fiber isolation level: copy `test_isolated_state_with_isolation_level_fiber` and restore `isolation_level` in `ensure`. Excluded keys: `live_streaming_excluded_keys` restore in `ensure`; default still inherits `active_record_connected_to_stack`.

**Do not** assert from the test thread during `get` that worker locals equal parent locals — check inside the action. `LiveControllerThreadTest` documents the opposite: with the TestCase bypass, locals are **not** reset; do not use that class for copy/reset checks.

**Cleanup:** `IsolatedExecutionState.delete` / `.clear`; restore `live_streaming_excluded_keys` and `isolation_level`.

#### 11. `send_stream.action_controller` payload and timing

**Payload (existing `test_send_stream_instrumentation` is incomplete).**

Subscribe with `capture_notifications("send_stream.action_controller")` or `assert_notification`.

| Call | Payload keys |
|---|---|
| `type: "text/csv"` | `{ filename: "sample.csv", disposition: "attachment", type: "text/csv" }` |
| `type: :json` | `type:` is the **symbol** `:json`, not `"application/json"` |
| `type` omitted | `type:` is `nil` |
| custom `disposition:` | original string, e.g. `"inline"` |

`assert_notification` matches a **subset**; also assert the captured event has exactly those three keys plus whatever AS adds (`:exception` only on error). Do not expect resolved MIME in the payload.

**Timing — use a subscriber, not private methods:**

```ruby
events = []
ActiveSupport::Notifications.subscribe("send_stream.action_controller") do |name, start, finish, id, payload|
  events << { at: :finish, committed: response.committed?, closed: response.stream.closed?, payload: payload.dup }
end
```

Better, instrument from inside the action with a test latch/probe:

- In the controller block, before any write: the notification has **started** (headers already set — assert `response.headers["Content-Type"]` inside the block).
- After the block, `ensure` close runs. Subscriber `finish` callback: stream may still be open because close is outside `instrument`. Pin that: **finish happens before close**, so a subscriber must not observe `stream.closed? == true` as a required condition at finish. Conversely, after `get` returns, the stream **is** closed.
- Duration: `finish >= start`; for a block that `latch.wait`s until the test records `start`, then count_down, duration is positive. Skip tight millisecond bounds.

**Exception timing:** raise inside the block (before or after write). Notification still emitted (AS `instrument` finishes in `ensure`). Payload includes `:exception => [class_name, message]` and `:exception_object`. Close still runs after finish.

**Count:** `assert_notifications_count("send_stream.action_controller", 1)` per request.

Unsubscribe via `subscribed(...)` / `capture_notifications` so the subscriber does not leak across tests.

### Race-proof synchronization and cleanup (global)

These are required wherever a second thread is involved. Copy the existing suite; do not invent `sleep`.

1. **`await_commit` before consume.** Writing commits; `process` also commits in ensure. Consumers (`each`, `to_a`) wait on the condvar. Missing this races “empty each” vs “first write”.
2. **`CountDownLatch` for each handoff** (producer filled buffer, consumer closed body, `on_error` ran, work complete). One latch per event; do not reuse across phases without replacing it (`test_async_stream` allocates a new latch per chunk).
3. **Timeouts:** `Timeout.timeout(3)` around `latch.wait`; `thread.join(3)` / `join(5)` and `assert` the result. Hung joins fail the test instead of hanging CI.
4. **`Buffer.queue_size`:** save, set, restore in `ensure`. TestCase sets `nil` globally; disconnect/full-buffer tests must not leak size 10.
5. **Single reader.** The queue has one consumer. Don’t drain `response.body` on the test thread while another thread is in `each`.
6. **Abort unblocks `SizedQueue#push` and `pop`.** After `body.close`, join producer and consumer. `reader&.kill` only in `ensure` after a failed join (`BufferTest`).
7. **Logger restore** via `capture_log_output`’s `ensure`.
8. **Thread/IE state restore:** `isolation_level`, `live_streaming_excluded_keys`, `IsolatedExecutionState` keys, `Thread.current[:setting]`.
9. **Keep `LiveStreamTest#setup`’s restore of `original_new_controller_thread` / `original_clean_up_thread_locals`.** Clearing that silently serializes on the test thread and hides copy/reset/disconnect bugs. Conversely, `LiveControllerThreadTest` is the place that documents bypass behavior — don’t mix the two.
10. **`Thread.abort_on_exception = true`** is already set in the test file; unrescued producer errors fail loudly. For expected `ClientDisconnected`, handle via `on_error` or a rescue inside the action so the pool thread does not abort the process.
11. **No private-method spies** (`new_controller_thread`, `clean_up_thread_locals`, `each_chunk`, `build_queue`). Observable surfaces: headers, body/chunks, `closed?`/`committed?`, raised errors, logs, notifications, assertions inside the controller action, latches.

### Independence from private layout

Assert only:

- HTTP headers and body/chunk sequence
- `response.stream.closed?` / `committed?`
- exceptions (`assert_raises` vs swallowed-after-commit)
- `ClientDisconnected` vs ignored writes
- notification name, payload, start/finish ordering relative to headers/block/close
- values observed inside the `send_stream` block (thread locals, isolated state)
- logs from `capture_log_output`

Do not assert call order of private methods, thread-pool class, queue class, or Monitor internals. A refactor that preserves the above can move helpers freely.
