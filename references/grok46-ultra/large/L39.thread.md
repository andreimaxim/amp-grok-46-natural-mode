## Non-negotiable design constraints

- `to_plain_text` must use `with_full_attributes: false`; do **not** silently switch to full attachment expansion.
- `render_attachments` must operate on a duplicate and return a **new `Content`**, leaving the receiver intact.
- Construct the rendered result with `canonicalize: false`; otherwise replacement content can be minified, gallery-rewritten, or raw-markdown-unwrapped again.
- Preserve renderer-free plain-text conversion. Do not route this through `to_s`, layouts, controller rendering, or attachment-gallery rendering.
- `render_attachments` sanitizes an attachment node’s `content` attribute only in the duplicated/result content. The original retains that attribute unchanged.
- If the replacement is the same node object, retain the existing special case rather than string-replacing it; otherwise replace with `replacement.to_s`.
- Canonicalization belongs to `Content.new`, not to `to_plain_text`: it clears attachment inner HTML, converts gallery wrappers to bare `<div>`, and unwraps raw markdown.

## Observable behavior to retain

### HTML-to-text

- Return a UTF-8, **non-`html_safe`** `String`.
- `p` and `h1`–`h6` produce paragraph spacing (`"\n\n"`); root trailing newlines are chomped.
- Sibling `div`s separate with one newline; `<br>` is `"\n"`.
- Lists retain bullets/numbering, nesting indentation (two spaces per extra depth), and list spacing.
- `<blockquote>` uses `“…”`, including whitespace-only content becoming `“”`.
- `<figcaption>` becomes `[caption]`.
- Inline/unknown tags drop tags but preserve children; comments drop.
- Real `<script>` and `<style>` nodes and their contents disappear.
- Entities are **decoded**, not encoded:
  - `&amp;` → `&`
  - `&nbsp;` → U+00A0
  - `&lt;script&gt;alert()&lt;/script&gt;` → literal `"<script>alert()</script>"`.
- Plain text does not sanitize arbitrary HTML attributes; it is not safe to render the returned string as HTML.
- Preserve deep-tree behavior (existing coverage uses 10,000 nested `<div>`s).

### Attachments

`Attachment#to_plain_text` is applied before DOM reduction:

- An attachable implementing `attachable_plain_text_representation(caption)` controls the string.
- Otherwise use raw `caption.to_s`, with **no automatically added brackets**.
- Blob: `[caption]`, or `[filename]` when no caption.
- Remote image: `[caption]`, or `[Image]` when absent; node `filename` does not substitute.
- Missing attachable, missing SGID, destroyed blob, or invalid non-URI image: `☒`, ignoring caption.
- Content attachment injects its inner content into the tree for normal plain-text reduction: `<p>abc</p>` → `abc`.
- Dummy Page/Person without the hook: raw caption or empty string.
- Duplicate attachment nodes are converted independently—no plain-text deduplication.
- Gallery attachments concatenate; gallery whitespace text nodes remain significant.
- Nested attachment behavior must stay: normal canonicalization removes the inner attachment; with `canonicalize: false`, replacing the outer attachment still discards descendants, so only outer output remains.

### `with_full_attributes`

This is especially important because text equality alone can miss regressions:

- `to_plain_text` passes `false`.
- `render_attachments` default/`attachment_for_node` behavior is `true`.
- With `false`, a blob node stays at its original attributes.
- With `true`, serialized replacement attachment HTML gains fields such as `content-type`, `filename`, `filesize`, and `previewable`.
- Blob/missing/remote plain-text strings may be identical either way, so test yielded attachment/node HTML—not only the final text.

#### 2. Entities and script-like text

Executed on this revision. Existing tests cover real `<script>`/`<style>` **nodes** (L156–178), not encoded text.

#### 3. Attachment captions and filenames

`Attachment#to_plain_text` runs **before** DOM reduction. Hook: `attachable_plain_text_representation(caption)` if present, else raw `caption.to_s` with **no automatic brackets**.

| Kind | Expected |
|---|---|

| Blob, no caption | `"[racecar.jpg]"` |
| Blob + caption + filename attr | `"[Cap]"` (caption wins) |
| Remote image + caption | `"[Cat]"` (already L120–125) |
| Remote image, no caption | `"[Image]"` |

| Page / Person (no hook) + caption | `"The caption"` (raw, no brackets) |
| Page, no caption | `""` |
| ContentAttachment `<p>abc</p>` | `"abc"` (inner HTML injected, then reduced) |
| ContentAttachment two `<p>`s | `"abc\n\ndef"` |

Existing [attachment_test.rb L55–58](file:///home/user/workspace/repo/actiontext/test/unit/attachment_test.rb#L55-L58) tests `Attachment.from_attachable` only, not the Content path. Surrounding markup executed: `<p>Hello</p><attachment caption=Cap><p>world</p>` → `"Hello\n\n[Cap]world"`.

#### 4. Missing attachables

Always `☒`; caption is ignored.

- `sgid="missing"` with caption → `"☒"`
- destroyed blob, with or without caption → `"☒"` ([content_test.rb L91–97](file:///home/user/workspace/repo/actiontext/test/unit/content_test.rb#L91-L97) covers destroyed **without** caption)
- `content-type="image/*" url="image.png"` (non-URI) → MissingAttachable → `"☒"` (L58–66 classifies, does **not** assert plain text)

#### 5. Duplicate attachables

Two nodes, same blob sgid, captions A and B → `"[A][B]"`. No plain-text deduplication. **Needs characterization.** (`model_test.rb` L55–61 only covers embed extraction / save.)

#### 6. Attachment galleries

Canonical HTML already evidenced ([content_test.rb L127–143](file:///home/user/workspace/repo/actiontext/test/unit/content_test.rb#L127-L143)): gallery wrapper classes stripped to `<div>…</div>`, whitespace inside preserved in HTML.

Plain text **needs characterization**. Executed:

| Input | `to_plain_text` |
|---|---|
| two gallery blobs, no extra whitespace | `"[One][Two]"` |
| same with `"\n  "` between nodes | `"\n  [One]\n  [Two]"` |
| same inside `<blockquote>` | `"\n  “[One]\n  [Two]”"` |
| gallery with bogus sgids `1`/`2` | `"☒☒"` / `"\n  ☒\n  ☒"` |

Gallery whitespace text nodes are significant. Do not normalize them away.

#### 7. Nested attachment nodes

Executed; **needs characterization.**

| Construction | `to_html` | `to_plain_text` |
|---|---|---|
| default canonicalize | inner child minified away | `"☒"` (missing sgid) |
| `canonicalize: false` | inner child retained in HTML | still `"☒"` — replacing the **outer** node discards descendants |
| inner `<div>INNER</div>`, `canonicalize: false` | inner HTML kept on original | render result HTML is just `☒` |

#### 8. `with_full_attributes: false`

Text equality is **not** a sufficient oracle. Executed for a blob node with only `sgid` + `caption="Cap"`:

- both flag values yield `"[Cap]"`
- `false`: yielded node HTML stays at original attributes (`sgid`, `caption`)
- default `true`: expands to `content-type`, `filename`, `filesize`, `previewable`

Assert **yielded node HTML / attribute keys**. Existing analogue: [markdown_conversion_test.rb L1124–1136](file:///home/user/workspace/repo/actiontext/test/unit/markdown_conversion_test.rb#L1124-L1136).

#### 9. Non-mutation of `#to_html` / canonical content

Executed: html equal, source oid equal, not html_safe, repeatable.

```ruby
html_before = content.to_html.dup
source_oid  = content.fragment.source.object_id
plain = content.to_plain_text

assert_equal html_before, content.to_html
assert_equal source_oid, content.fragment.source.object_id
assert_not plain.html_safe?
assert_equal plain, content.to_plain_text
assert_not_equal content.object_id, content.render_attachments { |a| a }.object_id
```

`render_attachments` sanitizes `content="…"` **only on the duplicate**:

| Original | Rendered (`{ |a| a }`) |
|---|---|
| `content="<img … onerror=alert>"` | `onerror` stripped; original still has it |
| `content=""` | attribute removed on result |
| `content="<script></script>"` | attribute removed on result |

Existing sanitization tests go through `to_trix_html`, not this path. Renderer may be nil; blob `to_plain_text` still returns `"[racecar.jpg]"`.
