### The three mutators

#### `changes_applied` ([dirty.rb:272-277](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L272-L277))

Call tree:

```text
changes_applied
  ForcedMutationTracker#finalize_changes   # only if no @attributes
  @mutations_before_last_save = mutations_from_database
  forget_attribute_assignments             # no-op without @attributes
  @mutations_from_database = nil           # returns nil
```

It does **not** write attribute values. It promotes the current tracker to “previous” and drops the current one so the next read builds a fresh tracker.

`finalize_changes` is required on the Forced path: that tracker reads live model ivars. Without a snapshot, a later `name=` would rewrite `previous_changes` ([attribute_mutation_tracker.rb:100-107](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L100-L107), [124-126](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L124-L126)). The Attributes path keeps the *old* `AttributeSet` inside the promoted tracker and replaces the model’s `@attributes` with `forgetting_assignment` copies ([dirty.rb:394-396](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L394-L396), [attribute.rb:74-76](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute.rb#L74-L76)).

Tests: [dirty_test.rb:120-151](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L120-L151), [138-146](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L138-L146) (second edit must not clobber `previous_changes`).

#### `restore_attributes` ([dirty.rb:320-322](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L320-L322), [417-422](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L417-L422))

```text
restore_attributes(attr_names = changed)
  attr_names.each -> restore_attribute!(name)
    if attribute_changed?(name)
      public_send("#{name}=", attribute_was(name))
      clear_attribute_change(name)   # forget_change
```

Default `attr_names` is `changed` (currently dirty names only). Return value is that array (`Enumerable#each`). Unchanged names are skipped. Restoring **does not** touch `@mutations_before_last_save`.

`restore_name!` is the same path for one attribute.

Tests: [dirty_test.rb:103-108](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L103-L108), [211-237](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L211-L237).

#### `clear_changes_information` ([dirty.rb:325-329](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L325-L329))

```text
@mutations_before_last_save = nil
forget_attribute_assignments
@mutations_from_database = nil    # returns nil
```

Drops **both** current and previous tracking. Attribute values stay put. This is reload-style, not rollback-style.

Test: [dirty_test.rb:196-209](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L196-L209).

### Edge cases

#### Attribute omitted from `restore_attributes`

[dirty_test.rb:225-237](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L225-L237): after save of `name="Dmitry"`, `color="Red"`, then `name="Bob"`, `color="White"`:

```ruby
restore_attributes(["name"])
```

| | `name` | `color` |
|---|---|---|
| value | `"Dmitry"` | `"White"` |
| `*_changed?` | `false` | `true` |
| `*_was` | `"Dmitry"` | `"Red"` |
| `*_change` | `nil` | `["Red", "White"]` |

`changed?` is `true`. `changes == { "color" => ["Red", "White"] }`. `previous_changes` still has the save (`name`/`color` from nil/initialized → Dmitry/Red). Passing a name that is not dirty is a no-op (`restore_attribute!` guards on `attribute_changed?`).

#### Attribute changed back to its original value

**Re-assign the persisted value** ([dirty_test.rb:110-118](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L110-L118)): `color = "red"; save; color = "red"`. The setter skips `color_will_change!`, so `color_changed?` is `false`, `color_change` is `nil`, `changed?` is `false`.

**Assign current value with an unguarded setter:** `name=` always calls `name_will_change!`. After save, `name = name` still inserts a forced snapshot. `name_changed?` is `true` and `name_change` is `[current, current]`. Forced tracking is set membership, not `!=`.

**Change away then back** (not asserted in these tests; follows the tracker):

- Forced + typical `unless val == current` setter: `Red → White → Red` still dirty, `color_change == ["Red", "Red"]`, because the first `will_change!` is never forgotten.
- Attributes path: `Attribute#changed?` is `type.changed?(original, current)` ([attribute.rb:66-72](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute.rb#L66-L72), [155-157](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute.rb#L155-L157)). Setting back to the original (or to a value that casts equal) clears dirt. Integer `"2.3"` then `"2.1"` both cast to `2` → `changed? == false`; `"5.1"` → `changes == { "size" => [2, 5] }` ([attributes_dirty_test.rb:186-200](file:///home/user/workspace/repo/activemodel/test/cases/attributes_dirty_test.rb#L186-L200)).

#### Mutable values and `*_will_change!`

Classic Dirty **cannot** see in-place edits unless you call `*_will_change!` first so it clones ([dirty_test.rb:93-101](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L93-L101), [attribute_mutation_tracker.rb:141-148](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L141-L148)). Non-duplicable values are stored as-is; `TypeError`/`NoMethodError` from `clone` is swallowed.

Attributes + `Type::String` **can** see in-place edits after the value has been read: `Attribute#changed_in_place?` delegates to `type.changed_in_place?` ([attribute.rb:70-72](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute.rb#L70-L72), [type/string.rb:16-20](file:///home/user/workspace/repo/activemodel/lib/active_model/type/string.rb#L16-L20)). After `name = "Yam"; save; name.replace("Hadad")`, `name_changed?` is `true` with no `will_change!` ([attributes_dirty_test.rb:73-77](file:///home/user/workspace/repo/activemodel/test/cases/attributes_dirty_test.rb#L73-L77)). Default `Type::Value#changed_in_place?` is `false` ([type/value.rb:105-107](file:///home/user/workspace/repo/activemodel/lib/active_model/type/value.rb#L105-L107)); only mutable types opt in.

On the Attributes tracker, `*_will_change!` still forces dirt even when the value has not changed (`forced_changes.include?` short-circuits) ([attribute_mutation_tracker.rb:63-65](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L63-L65), [77-79](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L77-L79)) — same `"Bill"/"Bill"` docs behavior.
