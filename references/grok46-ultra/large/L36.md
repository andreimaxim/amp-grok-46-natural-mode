**Verdict: BLOCK.** The claim is false and the tiny diff is incorrect for this revision.

`Attached::Many#attach!` is not “always `record.save!`”. It is a bang wrapper around `#attach`: raise only when an immediate save was attempted and failed. Validation failures already raise on that path. Unconditional `save!` after `#attach` changes when records persist, which exception is raised, the return value, and callback/upload behavior. `Attached::One` uses the same contract and is left untouched.

### Current contract (this revision)

`#attach` always assigns, then saves **only** if the record is persisted and has no attribute dirty state:

```51:57:activestorage/lib/active_storage/attached/many.rb
    def attach(*attachables)
      record.public_send("#{name}=", blobs + attachables.flatten)
      if record.persisted? && !record.changed?
        return if !record.save
      end
      record.public_send("#{name}")
    end
```

Assignment writes `attachment_changes` ([model.rb](file:///home/user/workspace/repo/activestorage/lib/active_storage/attached/model.rb) `has_many_attached` setter ~271–276). That does **not** set `record.changed?`. Immediate save is gated on *attribute* dirty state, not pending attachments.

`#attach!` documents and implements “raise if the record was **meant to be saved** and validations failed”:

```59:67:activestorage/lib/active_storage/attached/many.rb
    # Calls attach, and raises an exception if the record was meant to be saved but at least one of the validations failed.
    def attach!(*attachables)
      attach(*attachables) || raise(ActiveRecord::RecordNotSaved.new("Failed to save the record", record))
    end
```

`Attached::One` is the same pattern ([one.rb](file:///home/user/workspace/repo/activestorage/lib/active_storage/attached/one.rb) 64–70, 78–80). CHANGELOG “bang counterpart to attach” matches this, not “always persist.”

Successful `#attach` returns the Many proxy (truthy). Failed immediate `record.save` returns `nil`. So `#attach!` raises iff that immediate save failed.

### Path-by-path vs the proposed diff

```ruby
def attach!(*attachables)
  attach(*attachables)
  record.save!
end
```

**Persisted, unchanged, valid (immediate save).** `#attach` already `save`s; attachments are applied in `after_save` and uploaded in `after_commit`, which deletes `attachment_changes`. Extra `save!` is a second validations/callbacks pass and changes the return value from the Many proxy to `true` (`Persistence#save!` “returns true”).

**Persisted, unchanged, invalid.** Today `#attach` returns `nil`; `#attach!` raises `ActiveRecord::RecordNotSaved` with `"Failed to save the record"` (`many.rb` 66; `errors.rb` 166–173). Tests pin that class:

```820:827:activestorage/test/models/attached/many_test.rb
  test "raises error when calling attach! to attach blobs to a persisted, unchanged, and invalid record" do
    @user.update_attribute(:name, nil)
    assert_not @user.valid?

    assert_raises(ActiveRecord::RecordNotSaved) do
      @user.highlights.attach! create_blob(filename: "racecar.jpg"), create_blob(filename: "funky.jpg"), create_blob(filename: "town.jpg")
    end
  end
```

Same for One ([one_test.rb](file:///home/user/workspace/repo/activestorage/test/models/attached/one_test.rb) 148–155). After the diff, `#attach` still fails `save`, then `save!` raises **`RecordInvalid`** (`validations.rb` 53–55, 86–87) with a validation message, not `RecordNotSaved` / `"Failed to save the record"`. That test fails. Callback `throw :abort` can still be `RecordNotSaved` via `save!` (`persistence.rb` 391–393), so exception class would **split** by failure kind.

**New record.** `#attach` does not save (`many_test.rb` 836–841). `#attach!` currently succeeds and leaves pending changes. Proposed `save!` **inserts the whole record**. Invalid new records would start raising; valid ones would persist as a side effect.

**Persisted + changed (`name = "Tina"`).** `#attach` does not save; attachments stay unpersisted until later `save!` (`many_test.rb` 47–60, 829–834). Proposed `save!` persists the record **and** unrelated attribute changes. Invalid dirty records would raise; valid ones would commit `name` plus highlights immediately.

**Empty / nested arrays / duplicate / existing blobs.** Still go through `#attach` (`flatten`, `blobs + attachables`, setter `compact_blank` → empty becomes `DeleteMany`). Those assignment rules are unchanged; the regression is the extra save and return/exception contract.

**Pending changes / callbacks.** Immediate-save success already runs `after_save` → `attachment_changes.save` and `after_commit` → delete + upload (`model.rb` ~271–276). A second `save!` re-enters callbacks with changes already cleared. On new/dirty records, `#attach!` would start firing create/update callbacks that today do not run.

### Missing tests (current suite does not protect the contract)

Covered: persisted + unchanged + invalid → `RecordNotSaved` (`many_test.rb` 820–827); `#attach` return values for valid/invalid/changed/new (`806–841`).

Not covered for `#attach!`: success return value; new record; changed record; exception **message** / `exception.record`; empty args; nested arrays; duplicates; `before_save` abort vs validation; One/Many symmetry. The diff would regress several of those with no failing test except the `RecordNotSaved` assertion.

### Smallest corrected direction

Do **not** land `attach(...); record.save!`.

Keep:

```ruby
attach(*attachables) || raise(ActiveRecord::RecordNotSaved.new("Failed to save the record", record))
```

Validation failures on the immediate-save path already raise. New/changed records are not “meant to be saved” by `#attach` / `#attach!`.

If the real goal is `save!` exception types **only** on that same path, duplicate `#attach`’s gate and call `save!` **instead of** `save`, return the proxy, and do not save after `#attach`:

```ruby
def attach!(*attachables)
  record.public_send("#{name}=", blobs + attachables.flatten)
  if record.persisted? && !record.changed?
    record.save!
  end
  record.public_send("#{name}")
end
```

That is still an intentional API change (`RecordNotSaved` → `RecordInvalid` on validation failure, message change). Update `many_test.rb` 820–827 and the One twin; change One the same way or leave both alone. Do not do this as an untested Many-only one-liner.

If the goal is “`#attach!` always persists,” that is a new method contract (force-save including new/dirty records), not a correctness fix. It needs explicit tests for those records, return value, One/Many, and a doc/CHANGELOG change. This diff is not that.
