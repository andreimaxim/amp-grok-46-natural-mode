`ActionController::Parameters#expect` is a two-step operation: a **strict** permit pass, then `require` of every named root. `permit` is the same filter with both knobs flipped. Source: [strong_parameters.rb](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb). Tests: [parameters_expect_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_expect_test.rb), [parameters_permit_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_permit_test.rb), [nested_parameters_permit_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/parameters/nested_parameters_permit_test.rb), [raise_on_unpermitted_params_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/parameters/raise_on_unpermitted_params_test.rb), [log_on_unpermitted_params_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/parameters/log_on_unpermitted_params_test.rb).

```text
expect(*filters)
  permit_filters(filters, on_unpermitted: nil, explicit_arrays: true)
    Symbol/String → permitted_scalar_filter
    Hash         → hash_filter → permit_value
    unpermitted_parameters!   # no-op (on_unpermitted is nil)
    params.permit!            # always permitted: true
  require(extracted_root_keys)
  unwrap if exactly one value
```

```ruby
def expect(*filters)
  params = permit_filters(filters)
  keys = filters.flatten.flat_map { |f| f.is_a?(Hash) ? f.keys : f }
  values = params.require(keys)
  values.size == 1 ? values.first : values
end

def permit(*filters)
  permit_filters(filters,
    on_unpermitted: self.class.action_on_unpermitted_parameters,
    explicit_arrays: false)
end
```

`require` does not permit. It returns the value if `value.present? || value == false`; otherwise it raises `ActionController::ParameterMissing`. An Array of keys maps to an Array of required values; the first failure wins. `expect!` re-raises that as `ExpectedParameterMissing`.

`permit_value` is where the type rules live:

- `filter == []` → array of permitted scalars only
- `filter == {}` → hash, then `permit_any_in_parameters`
- `array_filter?` (`[[:text]]`) → array of hashes (or numeric-key nested attrs)
- `explicit_arrays` (`expect`) → `permit_hash` only; a real Array is dropped
- else (`permit`) → `permit_hash_or_array` (array of hashes **or** a hash)

`array_filter?` is `filter.is_a?(Array) && filter.size == 1 && filter.first.is_a?(Array)`. So `[:text]` is a hash schema; `[[:text]]` is an explicit array of hashes. `each_array_element` keeps only `Parameters` elements from a real Array (`grep(Parameters).filter_map`). A Parameters object is treated as an array only when `nested_attributes?` (keys matching `/\A-?\d+\z/` whose values are hashes) **and** the filter does not itself name numeric keys. That path returns a Parameters hash, not an Array.

`hash_filter` skips falsy values and omits a key when `permit_value` returns nil. `require` then sees a missing/empty key and raises.

### Contrast with `require` + `permit`

- **Order.** `permit(...).require(:root)` keeps a Parameters wrapper. `require(:root).permit(...)` raises `NoMethodError` if the root is a String (the documented 500). `expect` filters first, so a scalar root becomes missing and raises `ParameterMissing` (400).
- **Type strictness.** `permit(comment: [:text])` accepts a hash **or** an array of hashes. `expect(comment: [:text])` accepts only a hash. An array of hashes needs `expect(comments: [[:text]])`.
- **Return shape.** `permit` returns the filtered Parameters including the root key. `expect` requires the root and returns the inner value — or an Array of inner values when several roots are listed.
- **Unpermitted keys.** `permit` honors `action_on_unpermitted_parameters` (`:log` / `:raise`). `expect` / `expect!` pass `on_unpermitted: nil` at every nesting level, so extra keys are dropped silently.
- **Empty vs missing.** `permit(ids: [])` keeps `[]`. `expect(ids: [])` then requires it; empty is not `present?`, so `ParameterMissing`. Same for `{}` and blank strings.
- **Numeric-key hashes.** `permit(person: [:email])` expands numeric-key nested attributes via `permit_hash_or_array`. `expect(person: [:email])` does not; that needs `expect(person: [[:email]])`.

**Arity.** Root keys = `filters.flatten.flat_map { |f| f.is_a?(Hash) ? f.keys : f }`, then `require` in that order. One key unwraps to the single value. Several keys (`expect(:a, :b)`, `expect([:a, :b])`, `expect(subject: [:name], object: [:pie])`) return an Array in filter order. `[:a, :b]` and `:a, :b` are equivalent because of `flatten`. If any required root is missing/empty/wrong type after filtering, `ParameterMissing` is raised for the first such key.

### Concrete examples

#### 1. Scalar-versus-hash type confusion

Input `{ comment: "hello" }`, filter `comment: [:text]`:

- `expect` — `permit_hash` rejects the String, key dropped, `ActionController::ParameterMissing` (`param … : comment`). Test: “key to non-scalar: raises ParameterMissing on scalar”.
- `permit` — `permit_value` falls through (scalar, not `non_scalar?`); `:comment` absent, `permitted: true`. Test: “scalar values should be filtered when array or hash is specified”.
- `require(:comment).permit(:text)` — `require` returns `"hello"`, then `NoMethodError` on `String#permit`. That is the 500 `expect` exists to avoid.

Input `{ comment: { text: "hello" } }`: `expect(comment: [:text])` → `#<Parameters {"text"=>"hello"} permitted: true>`.

Input `{ comment: [{ text: "hello" }, { text: "world" }] }`:

- `expect(comment: [:text])` → `ParameterMissing` (array is not a Parameters hash). Test: “key to array of keys: raises when params is an array”.
- `permit(comment: [:text])` → keeps an array of permitted hashes. Root still present.

#### 2. Array of scalars

`{ tags: ["rails", "parameters"] }` / `expect(tags: [])` → `["rails", "parameters"]` (plain Array, not Parameters). Test: “key to empty array: arrays of permitted scalars pass”.

Same input, `permit(tags: [])` → `#<Parameters {"tags"=>["rails", "parameters"]} permitted: true>` — same inner array, wrapped under the root.

`{ ids: [] }` / `expect(ids: [])` → `ParameterMissing` (empty is not present). Test: “key to empty array: raises ParameterMissing on empty”. `permit(ids: [])` → `{ "ids" => [] }`, permitted.

`{ id: "foo" }` with `id: []`: both drop the scalar; `expect` then `ParameterMissing`. Tests: expect “raises ParameterMissing on scalar”; permit “permitted scalar values do not pass”.

`{ id: [Object.new] }` / `[[]]` / `[{ id: "1" }]`: both reject (not all permitted scalars); `expect` → `ParameterMissing`. Tests: “arrays of non-permitted scalar do not pass”.

#### 3. Array of parameter hashes

`{ pies: [{ flavor: "pumpkin" }, { flavor: "chicken pot" }] }` / `expect(pies: [[:flavor]])` → Array of two permitted Parameters. Test: “key to explicit array: returns permitted array”.

`{ pies: { flavor: "pumpkin" } }` / `expect(pies: [[:flavor]])` → `ParameterMissing` (hash is not an array / not numeric-key nested attrs). Test: “returns array when params is a hash”.

`{ pies: [] }` / `expect(pies: [[:flavor]])` → empty Array assigned, then `require` → `ParameterMissing`. Test: “returns empty array when params empty array”.

`permit(pies: [:flavor])` on either a hash or an array of hashes succeeds (legacy dual match). `expect(pies: [:flavor])` on an array fails.

Numeric-key hash with an explicit array filter, from the `array_filter?` comment: `{ pies: { "0" => { flavor: "key lime" }, "1" => { flavor: "mince" } } }` / `expect(pies: [[:flavor]])` → `#<Parameters {"0"=>{"flavor"=>"key lime"}, "1"=>{"flavor"=>"mince"}} permitted: true>` via `each_nested_attribute` (hash, not Array).

#### 4. Missing multiple required roots

`{ a: 1 }` / `expect([:a, :b])` or `expect(:a, :b)` → `ParameterMissing` for `:b`. Test: “raises ParameterMissing when one is missing”.

`{ a: 1, b: [] }` / `expect([:a, :b])` → `ParameterMissing` for `:b` (empty array is not present). Test: “raises ParameterMissing when one is non-scalar”.

`{ a: 1, b: 2 }` / `expect(:a, :b)` → `[1, 2]`. Test: “returns multiple permitted params”. `expect(:a)` → `1` (unwrapped). Test: “returns single permitted param”.

`{ subject: { name: "Martin" }, object: { pie: "pumpkin" } }` / `expect(subject: [:name], object: [:pie])` → `[subject_params, object_params]` in hash-key order.

`require([:user, :profile])` on `{ user: {}, profile: {} }` raises on the first empty key (`:user`) without returning later values — same first-failure rule `expect` reuses.

#### 5. Numeric-key nested parameters

From “nested params with numeric keys”:

```
book: { authors_attributes: {
  "0" => { name: "William Shakespeare", age_of_death: "52" },
  "1" => { name: "Unattributed Assistant" },
  "2" => { name: ["injected", "names"] } } }
```

`permit(book: { authors_attributes: [:name] })` expands numeric keys; `"0"`/`"1"` keep `:name`; `"2"` becomes `{}` because the array value is not a permitted scalar. Shape includes the `:book` root. `permitted: true`.

`expect(book: { authors_attributes: [:name] })` does **not** expand numeric keys (`explicit_arrays` → `permit_hash` looking for a key `"name"` on `authors_attributes`). After filtering, `authors_attributes` is empty → `require(:book)` → `ParameterMissing`.

To address one numeric key with expect (test “using require first”): `expect(book: { authors_attributes: { "1": [:name] } })` → `#<Parameters {"authors_attributes"=>{"1"=>{"name"=>"Unattributed Assistant"}}} permitted: true>`. `specify_numeric_keys?` is true, so no array expansion; slice keeps only `"1"`.

`expect(product: { properties: ["0"] })` on `{ "0" => "prop0", "1" => "prop1" }` → inner `{ "0" => "prop0" }`; `"1"` dropped. Test: “nested number as key”. Filter `["0"]` is **not** `array_filter?` (first element is not an Array); it is a scalar-key list on the hash.

#### 6. Unpermitted keys

`{ id: "1234", injected: "injected" }` / `expect(:id)` → `"1234"`; `:injected` dropped, no log/raise. Test: “key: unknown keys are filtered out”. `permit(:id)` → `{ "id" => "1234" } permitted: true`; `:injected` dropped.

With `action_on_unpermitted_parameters = :raise`:

- `permit(book: [:pages])` on `{ book: { pages: 65, title: "…" }, fishing: "Turnips" }` → `ActionController::UnpermittedParameters`.
- `expect(book: [:pages])` → `#<Parameters {"pages"=>65} permitted: true>` and does **not** raise. Test: “expect never raises on unexpected params”.
- `expect!` also does not raise `UnpermittedParameters`.

With `:log`, `expect` / `expect!` emit no unpermitted-parameter log even for nested extras (“does not log on unexpected nested params with expect”).

`expect(person: [:age, :name, :addresses])` on a person whose `:name` is a hash and `:addresses` is an array of hashes: only scalar `:age` survives (`"32"`). Test: “key to array: returns only permitted scalar keys”. Wrong-type keys are omitted, not errors.

`expect(person: {})` permits arbitrary nested scalars (`permit_any_in_parameters`). Test: “key to empty hash: permits all params”. Empty `{}` or a scalar still `ParameterMissing`.

---

Observable pattern: `permit` filters and always returns a permitted Parameters (possibly empty, possibly the wrong collection type). `expect` uses the strict filter, then `require`s every named root, so wrong type / empty / missing becomes `ParameterMissing`, a single root is unwrapped, and several roots are an Array in filter-key order.
