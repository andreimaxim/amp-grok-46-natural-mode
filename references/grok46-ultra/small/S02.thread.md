**Hash / Parameters.** Nested `Hash` + non-Hash DeepMergeable (e.g. `Parameters`, custom wrapper): today `Hash#deep_merge?` is false. Afterward `Hash#merge!` is invoked with a non-Hash. That can `TypeError` (no implicit `to_hash`) or, for permitted Parameters, convert via `to_hash`. Nested Parameters + Hash is already allowed by Parameters’ override; that path is not a reason to delete the hook.

> Please don’t land this. Compatibility is owned by `this_val.deep_merge?(other_val)`, not by a symmetric `DeepMergeable` type check. The default is `other.is_a?(self.class)`; Hash narrows to Hash, Parameters widens to DeepMergeable, and the tests lock both “non-subclass replaces” and “override to expand”. This change drops that hook, skips the block for incompatible DeepMergeable pairs, and turns replacement into `this_val.deep_merge` (left-typed copy). Keep the `deep_merge?` call.
