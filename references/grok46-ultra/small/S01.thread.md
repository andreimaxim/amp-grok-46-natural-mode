## `ActiveSupport::Testing::TimeHelpers#travel_to`

`travel_to` freezes "now" for the rest of the test (or for a block) by stubbing four class methods on `Time`, `Date`, and `DateTime`. `travel` and `freeze_time` are thin wrappers around it. Non-block travels are also unwound in `after_teardown` via `travel_back`.

Source: [activesupport/lib/active_support/testing/time_helpers.rb](file:///home/user/workspace/repo/activesupport/lib/active_support/testing/time_helpers.rb)

```text
travel_to(date_or_time, with_usec: false)
  reject if block given AND in_block
  normalize date_or_time → now (a Time)
  now = now.change(usec: 0) unless with_usec
  now = now.getlocal
  remember stubbed_time = Time.now if Time.now already stubbed
  stub Time.now / Time.new / Date.today / DateTime.now
  if block
    in_block = true
    yield
    ensure: travel_to(stubbed_time) or travel_back; in_block = false
```

### Input normalization

Three branches, then two always-on steps (`usec` + `getlocal`):

**Date (not DateTime).** `DateTime < Date`, so a true `Date` is detected with `is_a?(Date) && !is_a?(DateTime)`. That becomes `date.midnight.to_time`. `Date#midnight` is `beginning_of_day` → `in_time_zone`, so the instant is **midnight in the application time zone**, not the system zone. Docs: `Time.current` / `Date.current` follow that application-zone midnight; `Time.now` / `Date.today` follow the later `getlocal` conversion and can land on a different calendar date.

**String.** `Time.zone.parse(date_or_time)` — parsed in the application time zone. A string with fractional seconds still has usec zeroed afterward unless `with_usec: true` (`"2004-11-24T01:04:44.123-05:00"` compares equal to the whole second).

**Everything else (Time, DateTime, other `#to_time` objects).** Kept if it is already a `Time`; otherwise `to_time`. DateTime takes this branch, not the Date branch.

Then:

1. `now = now.change(usec: 0) unless with_usec`
2. `now = now.getlocal` — **must** be system-local, because the stubs use `Time.at(now)` and `now.to_date`, which inherit `now`'s zone. Application-zone inputs (Date midnight, `Time.zone.parse`, a Time with a non-local offset) are converted to the equivalent local wall time. Tests with system TZ `US/Eastern` and app TZ `Ekaterinburg` show `Time.new(2023, 12, 1, 5, 6, 7, +5h)` becoming local `2023-11-30 19:06:07 -05:00`.

### What is stubbed

`SimpleStubs` aliases the original singleton method aside and `define_singleton_method`s a replacement. Re-stubbing the same method unstubs first, so the recorded original is always the real implementation, not an intermediate stub.

| Call | Stub |
|---|---|
| `Time.now` | `Time.at(now)` |
| `Time.new` with no args and no kwargs | `Time.at(now)` (same as `Time.now`) |
| `Time.new` with any args or kwargs | original `Time.new` |
| `Date.today` | `Date.jd(now.to_date.jd)` |
| `DateTime.now` | `DateTime.jd(now.to_date.jd, now.hour, now.min, now.sec + now.subsec, Rational(now.utc_offset, 86400))` |

`Time.current`, `Date.current`, `Time.zone.now` are **not** stubbed; they read through `Time.now` / zone conversion.

`TimeSubclass.now` / `DateSubclass.today` / `DateTimeSubclass.now` keep their class: the stubs are on the base classes, and subclasses still inherit a working `now`/`today`.

### `Time.new` with arguments

Only the zero-argument, zero-kwarg form is frozen:

- `Time.new` → stubbed instant
- `Time.new(2004, 11, 25)` → real constructor
- `Time.new(precision: 3)` → real constructor (kwargs count)
- `Time.new("2000-12-31 23:59:59.56789", precision: 3)` → real constructor

The stub forwards with `Time.send(stub.original_method, *args, **options)`, where `original_method` is the aliased real `new`.

### `with_usec`

Default `false` zeros microseconds with `change(usec: 0)` **before** stubbing. That is deliberate: MySQL rounds fractional seconds instead of flooring, so `10:10:50.999999` can persist as `10:10:51`. With the default, both `Time.now.usec` and `DateTime.now.usec` are 0.

`with_usec: true` keeps the fraction. `DateTime.now` sees it because the stub passes `now.sec + now.subsec` (`999999` usec → `Rational(999999, 1000000)`). `travel` and `freeze_time` forward the flag.

### Block cleanup: real time vs. a pre-existing non-block travel

Before installing new stubs, if `Time.now` is already stubbed:

```ruby
stubbed_time = Time.now if stubs.stubbing(Time, :now)
```

After a block, `ensure`:

- **No prior stub** → `travel_back` (`simple_stubs.unstub_all!`) — real clock.
- **Prior stub** (typically a non-block `travel_to` still in effect) → `travel_to stubbed_time` — re-freeze at that captured instant, not "now" and not the inner target.

That is why this works:

```ruby
travel_to outer_time          # non-block, stays in effect
travel_to(inner_time) do
  # Time.now == inner_time
end
## Time.now == outer_time again
```

`in_block` is set only around the yield, then cleared in the same `ensure`.

Nested **non-block** `travel_to` inside a block is allowed: it overwrites the stubs; the outer `ensure` still restores via `stubbed_time` or `travel_back`. Sequential non-block `travel_to` calls also just replace stubs.

### Why nested block-form `travel_to` is rejected

At the top:

```ruby
if block_given? && in_block
  raise <<~MSG
    Calling `travel_to` with a block, when we have previously already made a call to `travel_to`, can lead to confusing time stubbing.
    ...
  MSG
end
```

`in_block` is true only inside an active **block-form** `travel_to` on **this** helper instance. So:

- block inside block → `RuntimeError`
- non-block inside block → ok
- block after a non-block travel → ok (not `in_block`)
- another object's `travel_to` → its own `in_block`; does not trip this guard

The documented confusion: `3.days.from_now` inside an outer travel is evaluated against the already-stubbed clock, so it is "3 days from the frozen time" (5 days from real today), which is easy to misread.

A second mechanical reason: the inner `ensure` always does `self.in_block = false`. If nested blocks were allowed, the inner cleanup would clear the outer's `in_block` flag while the outer block was still running, and would either `travel_back` or `travel_to stubbed_time` under the outer yield.

The error suggests sibling `travel N.days do ... end` blocks instead of nesting.
