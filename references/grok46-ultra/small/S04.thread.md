```text
  ┃      flush? → @view_flow.set(name, content)     # replace
  ┃      else   → @view_flow.append(name, content)  # concat
  ┃    return nil
  ┗━ else read
       @view_flow.get(name).presence
```

Layout `yield :title` is not this method. The renderer passes `{ |*name| view._layout_for(*name) }` into the layout, and `_layout_for` does `view_flow.get(name).html_safe`. Same store, different read: `yield :title` returns the empty `SafeBuffer` for a missing key; `content_for(:title)` returns `nil` via `.presence`.

### Block capture versus direct content

**Direct** (`content_for :title, "Putting stuff in the title!"`): the second argument is stored as-is. `capture` is not called. The current `@output_buffer` is untouched. Non-string values are later `to_s`'d in the flow (`content_for :title, :bar` stores `"bar"`).

**Block** (`content_for :title do ... end`): the second argument, if present, is treated as `options` (`content_for :title, flush: true do`). The block is run through `capture`:

```ruby
buffer = @output_buffer.capture { value = yield }
string = @output_buffer.equal?(value) ? buffer : (buffer.presence || value)
## OutputBuffer → to_s (html_safe)
## SafeBuffer   → kept
## String       → ERB::Util.html_escape(string)  # also html_safe
```

`OutputBuffer#capture` swaps `@raw_buffer` to a fresh string, yields, then restores. ERB `<%= %>` / `<% %>` inside the block therefore write into the temporary buffer, not the page. After restore, the page buffer is unchanged.

Which of buffer vs return value wins:

- ERB typically writes to the buffer and returns something else → `buffer.presence` wins.
- Builder / a Ruby block that returns a string and never writes the buffer → return value wins (`non_erb_block_content_for.builder`).
- If the block returns the output buffer object itself, the captured buffer is used (avoids storing the buffer object).
- A whitespace-only buffer is `blank?`, so `buffer.presence` is `nil` and the return value is used. Tests that `output_buffer << "  \n  "; nil` therefore store nothing.

`if content` after capture skips the store when capture returns `nil`/`false`. `""` is truthy, so an explicit empty string does store.

Fixture proof: `content_for.erb` uses a block; `content_for_with_parameter.erb` uses a string; both produce `<title>Putting stuff in the title!</title>\nGreat stuff!` through `talk_from_action.erb` (`<%= @title || yield(:title) %>` then `<%= yield -%>`). The write itself is `<% ... -%>`, so `"Great stuff!"` is the only thing that hits the view body.

### Append order across repeated writes

Default is concatenate in call order, not last-write-wins:

```ruby
@content = Hash.new { |h, k| h[k] = ActiveSupport::SafeBuffer.new }

def append(key, value)
  @content[key] << value.to_s
end
```

`content_for :title, "foo"` then `content_for :title, :bar` → `"foobar"`. Two blocks, same key, same rule. `content_for_concatenated.erb` does two direct writes (`"Putting stuff "` + `"in the title!"`) and matches the single-write fixtures.

`Hash` default proc means `get` of a never-written key inserts an empty `SafeBuffer`. That empty buffer is still `blank?`.

---

### `flush: true` replacement

`options[:flush]` is truthy → `set`, not `append`:

```ruby
def set(key, value)
  @content[key] = ActiveSupport::SafeBuffer.new(value.to_s)
end
```

The previous value is discarded. `content_for :title, "foo"` then `content_for :title, :bar, flush: true` → `"bar"`. Same with blocks (`flush: true do "bar" end`). `flush: false` is ordinary append (`"foobar"`).

`content_for :title, nil, flush: true do "bar" end` still flushes: `content` is `nil`, so the `options = content if content` overwrite does not run, and the third-argument hash stays `{ flush: true }`.

Flush only runs when `content` is truthy after capture. A whitespace-only block with `flush: true` captures `nil`, skips `set`, and leaves the previous value in place. The test then does `content_for :title, "bar", flush: true` to actually replace.

`content_for :title, "", flush: true` does replace with an empty `SafeBuffer` (`""` is truthy). Later appends start from that empty safe buffer (`test_content_for_should_be_html_safe_after_flush_empty`).

### Write versus read returns

| Call | Returns |
|---|---|
| write (content and/or block) | always `nil` |
| read (`content_for(:name)` only) | `@view_flow.get(name).presence` |
| missing / empty / whitespace-only stored | `nil` |

That is why `<%= content_for :title do %>...<% end %>` does not print the captured markup: the write returns `nil`, and capture already diverted buffer writes. Use `<% content_for :title do %>`. Read with `<%= content_for :title %>` or `<%= yield :title %>`.

`test_content_for_returns_nil_when_writing` covers direct, block, whitespace block, and flushed writes — all `nil`. `test_content_for_returns_nil_when_content_missing` covers the read of an unset key.

---

### `content_for?`

```ruby
def content_for?(name)
  @view_flow.get(name).present?
end
```

True only when the stored `SafeBuffer` is `present?` (non-blank). Empty or whitespace-only stored content is false. A key that was never written is also false (get still materializes an empty `SafeBuffer` via the default proc).

This is the layout branch used as `content_for?(:right_col) ? 'two-column' : 'one-column'`. It does not distinguish “never written” from “written then flushed to empty”.

---

### Why captured output stays safe for the view buffer

Two layers, then a safe read.

**1. Capture / direct input**

- ERB inside a block goes through `OutputBuffer#<<`, which `unwrapped_html_escape`s anything not `html_safe?`.
- `capture` then: `OutputBuffer` → `to_s` (`@raw_buffer.html_safe`); existing `SafeBuffer` kept; plain `String` → `ERB::Util.html_escape` (returns html_safe). Non-strings return `nil` and are not stored.
- Direct arguments are not pre-escaped here. They hit the flow next.

**2. Flow store is always a `SafeBuffer`**

- `append` → `SafeBuffer#<<` → unsafe strings are escaped; already-safe strings (helpers, `raw`, capture results) concat as-is.
- `set` (`flush: true`) → `SafeBuffer.new(value.to_s)`, which marks the whole string html_safe. Capture results are already escaped/safe. A raw unsafe direct argument on `flush: true` is marked safe without a second escape (append would have escaped it).

**3. Read into the layout/page**

- `content_for(:name)` returns that `SafeBuffer` (or `nil`).
- `yield :name` / `_layout_for` returns `get(name).html_safe`.
- `<%= %>` therefore `<<`s an html_safe value and does not escape again.

Write returning `nil` is the other half of buffer safety: the captured bytes never also land in the current template’s `@output_buffer`.

`provide` is the streaming cousin: `append!` (aliased to `append` on `OutputFlow`; `StreamingFlow#append!` also resumes the layout fiber). Same store, so `content_for?` / `content_for` / `yield :name` see it. Repeated `provide` still concatenates; it does not replace.

Fragment-cache warning in the RDoc still applies: `content_for` is ignored inside caches, so layout slots filled from a cached fragment will not see those writes.
