## Deterministic verification strategy for a `String#truncate_bytes` refactor

Ground truth is the current method in [`activesupport/lib/active_support/core_ext/string/filters.rb`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/string/filters.rb) plus the existing tests in [`activesupport/test/core_ext/string_ext_test.rb`](file:///home/user/workspace/repo/activesupport/test/core_ext/string_ext_test.rb). Do not treat “looks equivalent” as proof. Pin the current contract with a fixed fixture matrix, then run that matrix and the existing tests against the refactored code.

### Current contract (what “unchanged” means)

```ruby
def truncate_bytes(truncate_to, omission: "…")
  omission ||= ""

  case
  when bytesize <= truncate_to
    dup
  when omission.bytesize > truncate_to
    raise ArgumentError, "Omission #{omission.inspect} is #{omission.bytesize}, larger than the truncation length of #{truncate_to} bytes"
  when omission.bytesize == truncate_to
    omission.dup
  else
    self.class.new.force_encoding(encoding).tap do |cut|
      cut_at = truncate_to - omission.bytesize
      each_grapheme_cluster do |grapheme|
        if cut.bytesize + grapheme.bytesize <= cut_at
          cut << grapheme
        else
          break
        end
      end
      cut << omission
    end
  end
end
```

Four paths, in this order:

1. Receiver already within budget → `dup`
2. Omission larger than budget → `ArgumentError`
3. Omission exactly the budget → `omission.dup` (not `self.class`)
4. Otherwise → walk `each_grapheme_cluster`, keep whole clusters that fit in `truncate_to - omission.bytesize`, then append omission

Default omission is U+2026 `"…"` (3 UTF-8 bytes). `omission: nil` is treated as `""`.

Invariants that must hold on every non-raising path:

- Result `bytesize <= truncate_to`
- Result is valid in its encoding (no split multibyte sequence)
- Result does not split a grapheme cluster
- Receiver is not mutated (`equal?` false; content/encoding/frozen? unchanged)
- Result is a different object even when the text is unchanged (`dup`, not the receiver)

### How to run it

Existing tests first (they already cover several of the cases below):

```bash
cd activesupport && bin/test test/core_ext/string_ext_test.rb -i "/truncate_bytes/"
```

Then a single deterministic Ruby probe with frozen literals, explicit encodings, and `assert_equal` / `assert_same` / `assert_not_same` / `assert_raise`. Do not use locale, clocks, hashes, or unordered iteration. Use these UTF-8 fixtures (byte sizes are stable):

| Fixture | bytesize | notes |
|---|---|---|
| `"abcdefghij"` | 10 | 1-byte ASCII clusters |
| `"éééé"` | 8 | 2-byte UTF-8 (`é` = c3 a9) |
| `"中文测试"` | 12 | 3-byte CJK |
| `"👍👍👍👍"` | 16 | 4-byte emoji, 4 clusters |
| `"…"` | 3 | default omission |
| `"🖖"` | 4 | custom 4-byte omission |
| `"a ❤️ b"` | 10 | clusters: `a`(1) ` `(1) `❤️`(6) ` `(1) `b`(1) |
| `"👩‍❤️‍👩"` | 20 | one 20-byte cluster |
| `"e\u0301e\u0301e\u0301"` | 9 | three 3-byte combining clusters |

### Case-by-case observations and what they prove

#### 1. Within-budget strings

```ruby
s = +"abcdefghij"          # 10 bytes, unfrozen
assert_equal s, s.truncate_bytes(10)
assert_equal s, s.truncate_bytes(11)
assert_equal s, s.truncate_bytes(10, omission: "UNUSED")
assert_equal s, s.truncate_bytes(10, omission: nil)
assert_not_same s, s.truncate_bytes(10)

empty = +""
assert_equal "", empty.truncate_bytes(0)
assert_equal "", empty.truncate_bytes(5)
assert_not_same empty, empty.truncate_bytes(5)
```

What this proves:

- The method is a no-op on content when `bytesize <= truncate_to`, including exact equality of budget and bytesize.
- Omission is ignored on this path (`"UNUSED"` must not appear).
- `nil` omission does not change the within-budget path.
- Result is a copy (`dup`), not the receiver. A refactor that returns `self` when nothing is truncated is a behavior change (callers can mutate the result).

Also assert the empty string at budget 0: both sizes are 0, so this must take path 1, not the “omission larger than budget” path.

#### 2. ASCII truncation

```ruby
s = "abcdefghij"  # 10 bytes
assert_equal "abcdef…", s.truncate_bytes(9)   # 6 + 3 = 9
assert_equal "a…",      s.truncate_bytes(4)   # 1 + 3 = 4
assert_equal "…",       s.truncate_bytes(3)   # omission fills the budget
assert_equal "abc",     s.truncate_bytes(3, omission: nil)
assert_equal "abcde",   s.truncate_bytes(5, omission: nil)
```

What this proves:

- Room for content is `truncate_to - omission.bytesize`.
- Default omission is the 3-byte ellipsis, not `"."` / `"..."`.
- With a 1-byte alphabet, truncation lands on an exact character boundary.
- `omission: nil` means hard cut with no suffix (`""`), not “use the default”.

If a refactor counted characters (`size`) instead of bytes, ASCII would still pass. The multibyte cases below are what catch that.

#### 3. Multibyte truncation (2-, 3-, and 4-byte codepoints)

```ruby
e = "éééé"                # 8 bytes, 4×2
assert_equal "éééé", e.truncate_bytes(8)
assert_equal "éé…",  e.truncate_bytes(7)      # 4 + 3 = 7
assert_equal "é…",   e.truncate_bytes(5)      # 2 + 3 = 5
assert_equal "…",    e.truncate_bytes(4)      # 2-byte char does not fit in remaining 1
assert_equal "é",    e.truncate_bytes(2, omission: nil)
assert_equal "",     e.truncate_bytes(1, omission: nil)

c = "中文测试"             # 12 bytes, 4×3
assert_equal "中文…", c.truncate_bytes(9)      # 6 + 3 = 9
assert_equal "…",    c.truncate_bytes(5)      # 3-byte char does not fit in remaining 2
assert_equal "中",   c.truncate_bytes(3, omission: nil)
assert_equal "",     c.truncate_bytes(2, omission: nil)

t = "👍👍👍👍"            # 16 bytes, 4×4
assert_equal "👍👍👍👍", t.truncate_bytes(16)
assert_equal "👍👍👍…",  t.truncate_bytes(15)  # 12 + 3 = 15
assert_equal "👍👍👍",   t.truncate_bytes(15, omission: nil)
assert_equal "…",       t.truncate_bytes(5)
assert_equal "👍",      t.truncate_bytes(5, omission: nil)
assert_equal "👍",      t.truncate_bytes(4, omission: nil)
assert_equal "…",       t.truncate_bytes(4)
```

What this proves:

- Truncation is in **bytes**, not characters: `"éééé".size` is 4, but budget 7 still truncates.
- A character that does not fit in the remaining byte budget is dropped whole. `"éééé".truncate_bytes(4)` is `"…"`, not a dangling `c3` byte and not `"é"` plus a truncated second character.
- The result remains a valid UTF-8 string. Assert `result.valid_encoding?` and `result.encoding` on every row.
- Codepoints are preserved as units (this is what `test_truncate_bytes` / `test_truncate_bytes_preserves_codepoints` already encode).

The 4-byte-budget / 2-byte-char and 5-byte-budget / 3-byte-char rows are the sharp tests: remaining room is strictly smaller than one character, so only the omission (or empty, if `omission: nil`) may appear.

#### 4. Grapheme clusters

A cluster can be multiple codepoints. The method iterates `each_grapheme_cluster`, not `each_char`.

```ruby
h = "a ❤️ b"
## clusters: "a"(1), " "(1), "❤️"(6), " "(1), "b"(1)
assert_equal "a ",   h.truncate_bytes(2, omission: nil)
assert_equal "a ",   h.truncate_bytes(3, omission: nil)
assert_equal "a ",   h.truncate_bytes(7, omission: nil)  # 2 + 6 = 8 > 7, heart dropped
assert_equal "a ❤️", h.truncate_bytes(8, omission: nil)  # heart fits exactly

assert_equal "a ", h.truncate_bytes(13, omission: nil)   # "a 👩‍❤️‍👩", cluster is 20 bytes
assert_equal "",   "👩‍❤️‍👩".truncate_bytes(13, omission: nil)

cc = "e\u0301e\u0301e\u0301"  # three (e + combining acute) clusters, 3 bytes each
assert_equal "e\u0301", cc.truncate_bytes(3, omission: nil)
assert_equal "e\u0301", cc.truncate_bytes(4, omission: nil)  # leftover 1 byte cannot take next cluster
assert_equal "",        cc.truncate_bytes(2, omission: nil)  # must not return "e"
```

What this proves:

- ZWJ / emoji-presentation clusters (`❤️` = U+2764 + U+FE0F, `👩‍❤️‍👩`) are atomic. A budget that can hold `"a "` plus part of the heart still returns `"a "`.
- A cluster larger than the entire budget yields `""` when omission is empty — not a prefix of the cluster’s codepoints.
- Combining marks stay attached. `truncate_bytes(2, omission: nil)` on `e\u0301…` must be `""`, never `"e"`. Returning `"e"` would mean the refactor switched to codepoints or bytes.

If a refactor used `each_char`, `byteslice`, or `force_encoding("BINARY")` cuts, these rows fail while ASCII still passes.

#### 5. Exact byte boundaries

These are the rows where `cut.bytesize + grapheme.bytesize == cut_at`, or `bytesize == truncate_to`, or `omission.bytesize == truncate_to`.

```ruby
t = "👍👍👍👍"
assert_equal "👍👍👍👍", t.truncate_bytes(16)                 # bytesize == truncate_to
assert_equal "👍👍",     t.truncate_bytes(8, omission: nil)    # 4+4 == 8
assert_equal "👍…",      t.truncate_bytes(8)                   # cut_at = 5; one 4-byte thumb fits; 7 <= 8
assert_equal "👍👍👍…",  t.truncate_bytes(15)                  # cut_at = 12; three thumbs fit exactly

e = "éééé"
assert_equal "éé…", e.truncate_bytes(7)                        # cut_at = 4; two é fit exactly
assert_equal "é",   e.truncate_bytes(2, omission: nil)         # one é == budget
```

What this proves:

- The fit check is `<=`, not `<`. A cluster that lands exactly on `cut_at` is kept.
- When the receiver’s bytesize equals the budget, path 1 (`dup`) is taken even if an omission was passed.
- Off-by-one in `cut_at = truncate_to - omission.bytesize` shows up here immediately: dropping the last fitting cluster, or keeping one too many and exceeding the budget.

Always assert `result.bytesize <= truncate_to` on these rows. `"👍…"` at budget 8 is 7 bytes; that is correct (cannot fit another 4-byte thumb into the leftover byte).

#### 6. Custom and nil omissions

```ruby
t = "👍👍👍👍"
assert_equal "👍👍👍👍", t.truncate_bytes(16, omission: "🖖")
assert_equal "👍👍🖖",   t.truncate_bytes(15, omission: "🖖")  # 8 + 4 = 12 <= 15
assert_equal "👍👍👍 ",  t.truncate_bytes(15, omission: " ")
assert_equal "👍👍👍",   t.truncate_bytes(15, omission: nil)
assert_equal "👍 ",      t.truncate_bytes(5,  omission: " ")
assert_equal " ",        t.truncate_bytes(4,  omission: " ")
assert_equal "🖖",       t.truncate_bytes(4,  omission: "🖖")
assert_equal "abc",      "abcdefghij".truncate_bytes(3, omission: nil)
assert_equal "ab--",     "abcdefghij".truncate_bytes(4, omission: "--")
```

What this proves:

- Omission is appended after the kept prefix, and its bytes count toward the budget.
- `omission: nil` is `""`, not the default `"…"`.
- A 1-byte custom omission (`" "`) leaves more room for content than the 3-byte default; a 4-byte omission (`"🖖"`) leaves less.
- The omission string’s content is used as-is (`"--"`, `" "`, `"🖖"`), not normalized to ellipsis.

Also assert that the returned omission on the equal-budget path is a copy:

```ruby
om = +"…"
r = ("x" * 10).truncate_bytes(3, omission: om)
assert_equal "…", r
assert_not_same om, r
```

That proves path 3 is `omission.dup`, so mutating the result cannot mutate the caller’s omission string.

#### 7. Omission equal to or larger than the budget

```ruby
t = "👍👍👍👍"

assert_equal "…",    t.truncate_bytes(3)                       # equal, default
assert_equal "hello", ("x" * 10).truncate_bytes(5, omission: "hello")
assert_equal "🖖",   t.truncate_bytes(4, omission: "🖖")

err = assert_raise(ArgumentError) { t.truncate_bytes(3, omission: "🖖") }
assert_match(/Omission "🖖" is 4, larger than the truncation length of 3 bytes/, err.message)

err = assert_raise(ArgumentError) { t.truncate_bytes(2) }      # default "…" is 3
assert_match(/larger than the truncation length of 2 bytes/, err.message)

err = assert_raise(ArgumentError) { t.truncate_bytes(0) }
assert_match(/larger than the truncation length of 0 bytes/, err.message)

assert_equal "", t.truncate_bytes(0, omission: nil)            # nil → "", 0 == 0, omission.dup
```

What this proves:

- Equal bytesize takes path 3 and returns only the omission, discarding the receiver.
- Larger omission takes path 2 and raises `ArgumentError` with the current message shape (inspect of omission, both sizes). A refactor that silently returns `""` or the omission anyway is a behavior change.
- Default omission at budget 0/1/2 raises; `omission: nil` at budget 0 does not, because `""` is not larger than 0.
- Path order matters: within-budget is checked before omission size. `"".truncate_bytes(0)` returns `""` and does not raise, even though default omission is 3 bytes.

#### 8. Encoding and subclass preservation

```ruby
class MyString < String; end

## encoding, within budget
utf8 = String.new("a" * 10, encoding: Encoding::UTF_8)
assert_equal Encoding::UTF_8, utf8.truncate_bytes(20).encoding
assert_equal Encoding::UTF_8, utf8.truncate_bytes(5).encoding
assert_equal Encoding::UTF_8, utf8.truncate_bytes(5, omission: nil).encoding
assert_equal Encoding::UTF_8, utf8.truncate_bytes(5, omission: " ").encoding
assert_equal Encoding::UTF_8, utf8.truncate_bytes(5, omission: "🖖").encoding

ascii = String.new("abcdefghij", encoding: Encoding::US_ASCII)
assert_equal Encoding::US_ASCII, ascii.truncate_bytes(20).encoding   # dup
assert_equal Encoding::UTF_8,    ascii.truncate_bytes(5).encoding    # default omission is UTF-8
assert_predicate ascii.truncate_bytes(5), :valid_encoding?

## subclass
ms = MyString.new("hello world")
assert_instance_of MyString, ms.truncate_bytes(20)                  # path 1: dup
assert_instance_of MyString, ms.truncate_bytes(5)                   # path 4: self.class.new
assert_instance_of MyString, ms.truncate_bytes(5, omission: nil)
assert_instance_of String,   ms.truncate_bytes(3)                   # path 3: omission.dup
assert_instance_of String,   ms.truncate_bytes(1, omission: "x")
```

What this proves:

- Path 1 (`dup`) and path 4 (`self.class.new.force_encoding(encoding)`) preserve the receiver’s class and starting encoding.
- Path 3 (`omission.dup`) does **not** preserve subclass; it returns the omission’s class (normally `String`). A refactor that “always returns `self.class`” would change this path.
- Appending a UTF-8 omission to a US-ASCII receiver promotes encoding to UTF-8. That is current behavior; preserving US-ASCII by transcoding or rejecting the omission would be a change.
- Existing `test_truncates_bytes_preserves_encoding` only checks UTF-8 on the truncation path; the US-ASCII and subclass rows above close that gap.

#### 9. Receiver mutation (and frozen / identity)

```ruby
s = +"hello world"
before = s.dup
r = s.truncate_bytes(5)
assert_equal "hello world", s
assert_equal before, s
assert_equal before.encoding, s.encoding
assert_not_same s, r
assert_equal "he…", r

frozen = "hello world".freeze
r = frozen.truncate_bytes(5)
assert_predicate frozen, :frozen?
assert_not_predicate r, :frozen?
assert_equal "hello world", frozen

frozen_short = "hi".freeze
r = frozen_short.truncate_bytes(10)
assert_not_same frozen_short, r
assert_not_predicate r, :frozen?
assert_equal "hi", r
assert_predicate frozen_short, :frozen?
```

What this proves:

- Every path is non-destructive. The receiver’s bytes, encoding, and frozen flag are untouched.
- The result is never the same object as the receiver, including the within-budget path.
- The result is unfrozen even when the receiver is frozen (`dup` of a frozen string in Ruby is unfrozen). Returning a frozen string, or returning `self` for frozen inputs, is a change.
- Mutation of the result must not affect the receiver (and, from case 6, must not affect the omission argument).

### Cross-cutting checks on every successful row

For each non-raising call `(receiver, budget, omission)` record:

1. `result.bytesize <= budget` — budget is a hard ceiling.
2. `result.valid_encoding?` — no mid-character cut.
3. `result.each_grapheme_cluster.to_a` is a prefix of `receiver.each_grapheme_cluster.to_a`, optionally followed by a single omission cluster sequence — no torn clusters.
4. `receiver` equals a snapshot taken before the call — no mutation.
5. `!result.equal?(receiver)` — always a copy.

### What would *not* prove the claim

- Green ASCII-only tests (character-based truncation still passes).
- Equality of `.to_s` without checking `bytesize`, `encoding`, `class`, and object identity.
- Re-running only `test_truncate_bytes` (it does not cover combining marks, US-ASCII promotion, subclass, frozen, or `dup` identity).
- A property test with a random RNG seed.

The matrix above is closed and repeatable: fixed literals, fixed encodings, explicit expected strings. If every row matches current HEAD, the refactor preserved behavior on the public contract. If any row differs, the claim is false, and the failing row names the path that changed.
