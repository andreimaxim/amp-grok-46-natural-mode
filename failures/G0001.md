## Patterns

**Generalizing from one path to the whole contract (both misses, plus the one shortcoming on a matched case).** The candidate traced one path through a method — one branch, one option value, one concrete implementer of a hook, one input class — verified the claim on that path, and then wrote it as a statement about the method as a whole ("cannot reach", "still returns self", "covers X"). The other path was not unread: in one case the candidate quoted the very line of the other branch in its own answer and described that branch correctly a few lines earlier, then stated a universal that only the first branch supports. In the other, every implementer of the hook it happened to read returned the same thing, so it stated that as the abstraction's guarantee, where the abstraction itself only promises what the hook returns. The minor shortcoming on a matched case had the same shape: an input class that overrides a type predicate takes a different branch than the candidate assigned it. The references either stated which path the claim holds on, or phrased the contract in terms of the varying part.

**Missing fixture for a branch-ordering interaction (one-off, matched case).** The proposed test matrix covered each condition alone but not the case where two conditions hold at once and the order of checks decides the result. Same root as above (one path at a time), lower stakes.

**Overstating what existing tests miss (one-off, matched case).** Claimed a gap that existing assertions already cover. Not a failure cause.

## Hypothesis check

G0001 targeted unexecuted concrete claims for specific inputs. That part improved: the verification strategy now executed its probe and its expected values matched the checkout, the review that had dismissed a rationale with an unread negative no longer did so, and the nested-value outcome that G0000 stated wrongly is now stated with its condition. The "categorical claim needs the same check" sentence did not stop the remaining errors, because the candidate believes it has checked: it read the code and verified the claim on a path. The gap is not verification versus guessing but one path versus all paths the sentence covers.

## Next target

Path-complete general statements. Rather than restating "check categorical claims", the next edit should make the check operational: before writing a statement that covers a method as a whole, name each path the statement spans (branches, option values, callers, implementers of a hook) and confirm it on each, or restrict the statement to the path actually traced; where the behavior is supplied by a part that varies, state the contract in terms of that part rather than the one implementation read.
