`content_for` is a dual-purpose helper over `@view_flow` (`ActionView::OutputFlow`). A call is a **write** if it has a block or a truthy `content` argument; otherwise it is a **read**. Writes always return `nil`. Reads return `@view_flow.get(name).presence` (missing or blank → `nil`).

## Write vs read

```ruby
def content_for(name, content = nil, options = {}, &block)
  if content || block_given?
    if block_given?
      options = content if content
      content = capture(&block)
    end
    if content
      options[:flush] ? @view_flow.set(name, content) : @view_flow.append(name, content)
    end
    nil
  else
    @view_flow.get(name).presence
  end
end
```

`<%= content_for :title do ... %>` stores the slot and emits nothing. `<%= content_for :title %>` emits the stored string. Layouts usually read with `<%= yield :title %>`, which goes through `_layout_for` → `view_flow.get(name).html_safe`, not through `content_for` itself.

## Block capture versus direct content

**Direct content** skips `capture`. The second argument is stored after `to_s` in the flow (`:bar` becomes `"bar"`).

**Block form** always runs `capture(&block)`. If a block is given, the second argument is **options**, not content — so `content_for :title, flush: true do ... end` and `content_for :title, nil, flush: true do ... end` are equivalent.

`capture` prefers the temporary output buffer, then the block return. `OutputBuffer#capture` swaps `@raw_buffer`, yields, and returns that string marked `html_safe`. If the buffer is blank (`""` / whitespace), it falls back to the return value. A non-string return yields `nil`, and `content_for` stores nothing.

```ruby
content_for :title do
  output_buffer << "foo" << "bar"
  nil
end
# stored: "foobar"   (buffer wins)

content_for :title do
  "foo"
end
# stored: "foo"      (blank buffer, return value used)

content_for :title do
  output_buffer << "  \n  "
  nil
end
# stored: nothing    (whitespace buffer is blank; nil return dropped)
```

Whitespace-only ERB blocks therefore do **not** append.

## Append order and `flush: true`

Default write is append, in call order: `"foo"` then `:bar` reads as `"foobar"`.

`OutputFlow` keeps a Hash of `SafeBuffer`s. `append` does `@content[key] << value.to_s`. `flush: true` calls `set`, which **replaces** the slot with a new SafeBuffer (`SafeBuffer.new(value.to_s)`), not clear-then-append on the old object.

A flushed write whose captured content is blank is a no-op: `if content` fails, so `set` never runs. Empty string **is** truthy, so `content_for :title, "", flush: true` does replace the slot with an empty SafeBuffer.

## Write versus read returns

| Call | Returns |
|---|---|
| Write (direct or block, flush or not) | always `nil` |
| Write whose capture is blank | still `nil`; slot unchanged |
| Read of populated slot | the SafeBuffer |
| Read of missing / empty / whitespace-only slot | `nil` (via `.presence`) |

`provide` is different: it always `append!` (streaming can resume the layout fiber). `content_for` concatenates; `provide` means “this named slot is done” for streaming.

## `content_for?`

```ruby
def content_for?(name)
  @view_flow.get(name).present?
end
```

This is presence of stored content, not “was this key ever written?”. Missing keys auto-vivify an empty SafeBuffer (`present?` false). Flushed-to-`""` and whitespace-only content are also false.

## Why captured output stays safe for the view buffer

Safety is applied **on the way in**, then preserved by storing only SafeBuffers.

1. **Block writes** go through `capture`. `OutputBuffer#<<` already escapes unsafe strings. `capture` then: `OutputBuffer` → `to_s` (html_safe); `SafeBuffer` → unchanged (no second escape); plain `String` → `ERB::Util.html_escape` (escaped and marked safe); anything else → `nil`.
2. **Direct writes** skip `capture`. `SafeBuffer#<<` escapes interpolated arguments that are not already `html_safe?`. `set` always wraps with `SafeBuffer.new(value.to_s)`.
3. **Reads** return that SafeBuffer, so `<%= content_for :title %>` and `<%= yield :title %>` do not escape again.
4. **Flush of `""`** still allocates a SafeBuffer, so a later `content_tag` append remains html_safe (`test_content_for_should_be_html_safe_after_flush_empty`).

When debugging a layout slot: was the call a write or a read; did `capture` return nil (whitespace block / non-string); did `flush: true` actually `set`, or did a blank capture skip it; is the stored object a SafeBuffer so `yield` will not double-escape.
