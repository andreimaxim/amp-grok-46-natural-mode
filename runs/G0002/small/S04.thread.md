## Assistant

`content_for` is a write-or-read helper over `@view_flow`, not over `@output_buffer`. Writes always return `nil`. Reads return the stored buffer only when it is present.

```172:184:actionview/lib/action_view/helpers/capture_helper.rb
      def content_for(name, content = nil, options = {}, &block)
        if content || block_given?
          if block_given?
            options = content if content
            content = capture(&block)
          end
          if content
            options[:flush] ? @view_flow.set(name, content) : @view_flow.append(name, content)
          end
          nil
        else
          @view_flow.get(name).presence
        end
      end
```

```diagram
template / helper
      │
      ▼
content_for(name, ...)
      │
      ├── write (content || block) ──► capture? ──► OutputFlow set/append ──► nil
      │
      └── read  (name only) ────────► OutputFlow#get(name).presence
                                              │
layout `yield :name` ──► _layout_for ──► get(name).html_safe
```

### Write vs read

The first positional argument is always the slot name. Everything after that chooses the mode:

- **Write** if `content` is truthy **or** a block is given. The method returns `nil` even when the write is a no-op.
- **Read** only for `content_for(:name)` with no second argument and no block. That is `get(name).presence`, so a missing or blank slot is `nil`, not `""`.

`<%= content_for :title %>` is a read. `<% content_for :title do %>…<% end %>` is a write; the `<%` (no `=`) is what keeps the `nil` return out of the template. `content_for :title, flush: true` with no block and no string is also a write: the hash is the `content` argument.

Layout `yield :title` does not call `content_for`. It goes through [`_layout_for`](file:///home/user/workspace/repo/actionview/lib/action_view/context.rb#L27-L30), which reads the same `OutputFlow` slot and marks it html-safe. Named `yield` and `content_for(:name)` share storage; `yield` is not available in helpers.

### Block capture vs direct content

Two write shapes, one store:

**Direct content** skips `capture`. The value is stored as-is after `to_s` in the flow (`"foo"`, `:bar` → `"bar"`, a helper return, `raw(...)`).

**Block** always replaces `content` with `capture(&block)`. If the second argument is present, it is reused as `options`, which is how `content_for :title, flush: true do` works. `content_for :title, nil, flush: true do` keeps the explicit options hash because `content` is nil.

`capture` does not swap the `OutputBuffer` object. It swaps the buffer’s internal `@raw_buffer` for an empty string, yields, then restores:

```72:79:actionview/lib/action_view/buffers.rb
    def capture(*args)
      new_buffer = +""
      old_buffer, @raw_buffer = @raw_buffer, new_buffer
      yield(*args)
      new_buffer.html_safe
    ensure
      @raw_buffer = old_buffer
    end
```

Then `CaptureHelper#capture` decides which string wins:

```47:65:actionview/lib/action_view/helpers/capture_helper.rb
      def capture(*, **, &block)
        value = nil
        @output_buffer ||= ActionView::OutputBuffer.new
        buffer = @output_buffer.capture { value = yield(*, **) }

        string = if @output_buffer.equal?(value)
          buffer
        else
          buffer.presence || value
        end
        # OutputBuffer → to_s, SafeBuffer → as-is, String → html_escape
      end
```

That produces three debugging-relevant cases:

1. **ERB / buffer writes.** Markup goes through `output_buffer <<`. The captured buffer is used. If the block returns `@output_buffer` itself (common compiled-ERB accident), that return is ignored so the outer template is not leaked into the slot.
2. **Non-ERB / return value.** If the temporary buffer is blank, the block’s return is used. A non-string return becomes `nil` (`capture { 1 }` → `nil`).
3. **Whitespace-only ERB.** `buffer.presence` treats `"  \n  "` as blank, so a block that only writes whitespace and returns `nil` captures `nil`.

`if content` after that is Ruby truthiness. `nil` (and `false`) skip the store; `""` is stored.

### Append order and `flush: true`

Default is concatenate in call order, via `OutputFlow#append`:

```23:26:actionview/lib/action_view/flows.rb
    def append(key, value)
      @content[key] << value.to_s
    end
```

`content_for :title, "foo"` then `content_for :title, :bar` reads as `"foobar"`. Same for two blocks. Later writes do not prepend.

`flush: true` is replacement, not a buffer flush to the client:

```18:20:actionview/lib/action_view/flows.rb
    def set(key, value)
      @content[key] = ActiveSupport::SafeBuffer.new(value.to_s)
    end
```

The previous slot is discarded and a new `SafeBuffer` is installed. `flush: false` is append.

Flush still goes through `if content`. A flushed write whose captured value is `nil` does **not** clear the slot:

```
content_for :title, "foo"
content_for :title, flush: true do   # whitespace + nil → capture nil → no-op
  output_buffer << "  \n  "
  nil
end
## slot is still "foo"
content_for :title, "bar", flush: true
## slot is "bar"
```

Empty string **does** replace: `content_for :title, "", flush: true` leaves an empty html-safe buffer.

### `content_for?`

```215:217:actionview/lib/action_view/helpers/capture_helper.rb
      def content_for?(name)
        @view_flow.get(name).present?
      end
```

This is `present?` on the stored buffer, not “was this key ever written?”. Blank (empty or whitespace-only) is false. `content_for?(:title)` can be false while a later `content_for(:title)` is also `nil`; they agree on blankness, not on “key exists”.

`OutputFlow` uses `Hash.new { |h, k| h[k] = ActiveSupport::SafeBuffer.new }`. `get` of a missing name **assigns** an empty `SafeBuffer`. For the non-streaming flow that is just an empty present? → false. Under streaming, `StreamingFlow#get` waits on a missing key, so `content_for?` can block until `provide` / `append!` supplies it.

### Safety relative to the view buffer

Two invariants, both enforced before anything is written back to the template buffer.

**Isolation.** Because `OutputBuffer#capture` swaps `@raw_buffer`, a `<% content_for :x do %>` block cannot leak into the current template. The outer buffer is restored in `ensure`. The write path then returns `nil`, so a non-`=` ERB tag inserts nothing.

**HTML safety.** Escaping happens on the way *in*, so a later `<%= content_for :x %>` or `<%= yield :x %>` can treat the slot as safe and not double-escape.

| Source | What happens |
|---|---|
| ERB inside the block | `OutputBuffer#<<` escapes non-`html_safe?` chunks as they are written |
| Block returns a plain `String` | `ERB::Util.html_escape` |
| Block returns `SafeBuffer` / `OutputBuffer` | kept marked safe |
| Direct append of unsafe string | `SafeBuffer#<<` escapes (`"<p>"` → `&lt;p&gt;`) |
| Direct append of `raw(...)` | concatenated unescaped |
| `flush: true` / `set` | `SafeBuffer.new(value.to_s)` — copies bytes and marks the whole slot safe |

That last row is the append/set split: append re-escapes unsafe input; `set` trusts `value.to_s`. Block capture normally feeds `set` an already-safe string, which is why `content_tag` inside a flushed block stays html-safe (see `test_content_for_should_be_html_safe_after_flush_empty`). A flushed **direct** unsafe string is stored as trusted.

On read, `<%= content_for :title %>` pushes a `SafeBuffer` (or `nil`) through `OutputBuffer#<<`, which does not escape `html_safe?` values. `_layout_for` does `view_flow.get(name).html_safe` so `yield :title` is the same.

The documented fragment-cache caveat is separate: a cached fragment never re-runs the `content_for` write, so the layout slot stays empty even though the cached HTML is served.
