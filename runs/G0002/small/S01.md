`travel_to` freezes “now” for the rest of the test (or for a block) by replacing `Time.now`, `Time.new`, `Date.today`, and `DateTime.now` on those classes. It lives in [`ActiveSupport::Testing::TimeHelpers`](file:///home/user/workspace/repo/activesupport/lib/active_support/testing/time_helpers.rb), which `ActiveSupport::TestCase` includes. `travel` and `freeze_time` are wrappers around it. `after_teardown` always calls `travel_back`, so a non-block travel cannot leak into the next test.

```text
travel_to(date_or_time, with_usec: false)
  reject nested block-form if in_block
  normalize date_or_time → now (a Time)
  zero usec unless with_usec
  now = now.getlocal          # system TZ, not Time.zone
  stub Time.now / Time.new / Date.today / DateTime.now
  if block
    in_block = true
    yield
    restore prior travel or travel_back
    in_block = false
```

## What it actually stubs

[`SimpleStubs`](file:///home/user/workspace/repo/activesupport/lib/active_support/testing/time_helpers.rb#L8-L64) aliases the current singleton method aside (`__simple_stub__now__<id>`), then `define_singleton_method`s the replacement. Re-stubbing the same method first restores the real original, then stubs again — so a later `travel_to` does not nest aliases.

Four methods are replaced, all closed over the same local `now`:

| Call | Stub |
|---|---|
| `Time.now` | `Time.at(now)` |
| `Time.new` | `Time.at(now)` if **no** args and **no** kwargs; otherwise the real `Time.new` |
| `Date.today` | `Date.jd(now.to_date.jd)` |
| `DateTime.now` | `DateTime.jd(...)` with `now`’s hour/min/sec+subsec and `Rational(now.utc_offset, 86400)` |

`Time.current` / `Date.current` / `DateTime.current` are **not** stubbed. They keep working because they read the stubbed `now`/`today` and then apply `Time.zone`.

`now` is forced through `getlocal` before stubbing. The stubs therefore answer in the **process / `ENV["TZ"]` timezone**, even when the argument was in `Time.zone`. That is why a `Time` at `2023-12-01 05:06:07 +05` becomes `2023-11-30 19:06:07 -05` for `Time.now`, `Date.today`, and `DateTime.now` when the system zone is US/Eastern.

## How Date, String, and Time are normalized

```133:175:activesupport/lib/active_support/testing/time_helpers.rb
      def travel_to(date_or_time, with_usec: false)
        # ... nested-block guard ...

        if date_or_time.is_a?(Date) && !date_or_time.is_a?(DateTime)
          now = date_or_time.midnight.to_time
        elsif date_or_time.is_a?(String)
          now = Time.zone.parse(date_or_time)
        else
          now = date_or_time
          now = now.to_time unless now.is_a?(Time)
        end

        now = now.change(usec: 0) unless with_usec
        now = now.getlocal
```

Three branches, then one shared finish (`change` + `getlocal`):

**Date (not DateTime).** `Date#midnight` is `beginning_of_day` → `in_time_zone`, so the instant is midnight in **`Time.zone`** (or process local time if no zone is set). `.to_time` then yields a `Time` for that instant. `Time.current` will show that midnight; `Time.now` will show the same instant in system TZ. `Date.today` can disagree with `Date.current` when those zones differ — the rdoc’s warning is this path.

**String.** `Time.zone.parse` (application zone, `Date._parse`). Needs `Time.zone` set. Fractional seconds in the string survive parse and are then dropped unless `with_usec: true`. `"2004-11-24T01:04:44.123-05:00"` therefore freezes at `:44` with usec 0 by default.

**Everything else** (`Time`, `ActiveSupport::TimeWithZone`, `DateTime`, …). Keep it if `is_a?(Time)`; otherwise `to_time`. `TimeWithZone` overrides `is_a?` so it reports as `Time` and skips `to_time`. `DateTime` is a `Date` subclass but is excluded from the Date branch, so it goes through `to_time`.

## `Time.new` with arguments

```181:189:activesupport/lib/active_support/testing/time_helpers.rb

          if args.empty? && options.empty?

          else
            stub = stubs.stubbing(Time, :new)
            Time.send(stub.original_method, *args, **options)
          end

```

`Time.new` with no positional args **and** no keywords is `Time.now`. Any argument — `Time.new(2004, 11, 25)`, `Time.new(precision: 3)`, `Time.new("2000-12-31 23:59:59.567")` — is forwarded to the real constructor via the saved alias. Construction of other times is not frozen; only the no-arg “what time is it?” form is.

## What `with_usec` changes

Default `with_usec: false` runs `now.change(usec: 0)` after conversion. That is the MySQL-rounding guard: a usec of `999999` would otherwise round up a second on insert. The zeroing applies to `Time.now` **and** `DateTime.now` (`sec + subsec` is then a whole second).

`with_usec: true` skips that `change`. Subseconds from a `Time`, a `DateTime`, or a parsed string are kept, and `DateTime.now.sec_fraction` matches them.

`travel(duration, with_usec:)` forwards the flag into `travel_to Time.now + duration`. After a usec-preserving freeze, `travel 0.5, with_usec: true` advances by a true half-second instead of snapping to whole seconds.

## Block cleanup: real time vs. a prior non-block travel

Before installing stubs, `travel_to` snapshots the previous freeze **only if this instance already stubbed `Time.now`**:

```177:209:activesupport/lib/active_support/testing/time_helpers.rb
        stubs = simple_stubs
        stubbed_time = Time.now if stubs.stubbing(Time, :now)
        # ... install stubs ...
        if block_given?
          begin
            self.in_block = true
            yield
          ensure
            if stubbed_time
              travel_to stubbed_time
            else
              travel_back
            end
            self.in_block = false
          end
        end
```

Two restore paths:

```diagram
          travel_to T do ... end
                    │
        Time.now already stubbed
         on this helper instance?
           │                 │
          no                yes
           │                 │
           ▼                 ▼
     travel_back      travel_to stubbed_time
     (real clock)     (re-freeze the outer
                       non-block travel)
```

- First freeze in the test, block form → `stubbed_time` is `nil` → `travel_back` → `unstub_all!` → real `Time.now` / `Date.today` / `DateTime.now`.
- Non-block `travel_to outer` already active, then `travel_to(inner) { ... }` → `stubbed_time` is `Time.now` under the outer stub → after the block, `travel_to stubbed_time` re-freezes at `outer`. That is [`test_time_helper_travel_with_subsequent_block`](file:///home/user/workspace/repo/activesupport/test/time_travel_test.rb#L435-L451).

The restore `travel_to stubbed_time` is called **without** a block and **without** `with_usec: true`, so the re-freeze zeros usec even if the outer freeze had kept it.

`ensure` always runs, including on exception or `return` from the block. `in_block` is cleared after restore.

## Why nested block-form `travel_to` is rejected

The first thing `travel_to` does:

```ruby
if block_given? && in_block
  raise <<~MSG
    Calling `travel_to` with a block, when we have previously already made a call to `travel_to`, can lead to confusing time stubbing.
    ...
  MSG
end
```

`in_block` is a per-helper-instance flag, true only while that instance is inside a block-form `travel_to`. So:

| Pattern | Result |
|---|---|
| `travel_to t1 do; travel_to t2 do; end; end` | `RuntimeError` |
| `travel_to t1 do; travel_to t2; end` | allowed (inner has no block) |
| `travel_to t1` then `travel_to t2 do; end` | allowed (`in_block` is false) |
| two successive non-block `travel_to`s | allowed (last stub wins) |

The raise exists because a nested block evaluates its argument **under the outer freeze**. `travel_to 2.days.from_now { travel_to 3.days.from_now { } }` does not mean “3 days from today”; `3.days.from_now` is 5 days from today. Cleanup would also fight: the inner `ensure` would `travel_to` the outer frozen time (or `travel_back`), then the outer `ensure` would `travel_back` again. The helper refuses that combination instead of defining a stack.

The suggested substitute in the error is sibling `travel` blocks (`travel 2.days do … end` then `travel 5.days do … end`), each of which starts from real time, not from an already-stubbed clock.
