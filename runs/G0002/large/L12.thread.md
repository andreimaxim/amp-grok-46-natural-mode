### Security invariants vs String compatibility

**Security (must not drift; XSS / double-escape):**

- Safe receiver + unsafe arg: escape, stay `html_safe?`.
- Safe receiver + `html_safe` arg: no escape, stay `html_safe?` (no double-escape of `&amp;`).
- Unsafe receiver: never re-escape; stay not `html_safe?`.
- `safe_concat` is raw append on a safe receiver; it is forbidden once dirty.
- Dirty flag must survive `dup`/`*`/`%`. A copy that looks `html_safe?` while holding `<>` is a regression.
- `gsub!`/`sub!` dirties **before** mutation, even if the replacement looks like tags.
- Slicing a dirty buffer must not re-wrap as a safe `SafeBuffer`.

**String compatibility (behavior, not XSS):**

- `concat`/`<<` mutate and return `self`; `%`/`*`/`+` allocate.
- `concat(nil)` is a no-op ([`concat`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/string/output_safety.rb#L80-L86)).
- Bang mutators return the receiver; non-bang `sub`/`gsub` go through `to_str` and return a plain `String`.
- `slice!` on a still-safe buffer returns `SafeBuffer`; on a dirty buffer, `String#slice!`’s `String` (or `nil`).
- Dirty `gsub!("", "<>")` on `"hello"` yields `"<>h<>e<>l<>l<>o<>"` because the empty pattern matches every gap. That is Ruby `String` behavior; tests use it only as a dirtier.

`concat` escapes with `arg.to_str` ([`implicit_html_escape_interpolated_argument`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/string/output_safety.rb#L212-L218)); `%` does not ([`explicit_html_escape_interpolated_argument`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/string/output_safety.rb#L208-L210)).
