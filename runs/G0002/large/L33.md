`ActiveModel::Dirty` keeps two mutation-tracker slots. Unsaved edits live in `@mutations_from_database`; the last applied changeset lives in `@mutations_before_last_save`. Generated `*_changed?` / `*_was` methods read the current tracker; `*_previously_*` methods read the last-save tracker.

Which tracker class you get depends on whether the object has `@attributes`:

```382:396:activemodel/lib/active_model/dirty.rb
      def mutations_from_database
        @mutations_from_database ||= if defined?(@attributes)
          ActiveModel::AttributeMutationTracker.new(@attributes)
        else
          ActiveModel::ForcedMutationTracker.new(self)
        end
      end
      # ...
      def mutations_before_last_save
        @mutations_before_last_save ||= ActiveModel::NullMutationTracker.instance
      end
```

The focused tests split on that boundary. [`DirtyTest::DirtyModel`](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L7-L44) has no `@attributes`, so it uses `ForcedMutationTracker` and must call `*_will_change!`. [`AttributesDirtyTest::DirtyModel`](file:///home/user/workspace/repo/activemodel/test/cases/attributes_dirty_test.rb#L6-L17) includes `ActiveModel::Attributes` and uses `AttributeMutationTracker`, which can see in-place string mutation on its own.

Generated dirty methods are suffixes/affixes that dispatch to the private `attribute_*` methods in [dirty.rb](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L241-L245):

## The three methods

**`changes_applied`** ([dirty.rb L270–L279](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L270-L279)) is what `save` calls in both test models. It does not write attributes; it rebases dirty bookkeeping.

```text
changes_applied
  if no @attributes
    mutations_from_database.finalize_changes   # snapshot [old, new]
  @mutations_before_last_save = mutations_from_database
  forget_attribute_assignments                 # rebase @attributes, else no-op
  @mutations_from_database = nil
```

`ForcedMutationTracker` must snapshot. It reads live ivars through `_read_attribute`, so after apply “original vs current” would collapse to the new values. `finalize_changes` stores `changes` in `@finalized_changes` ([attribute_mutation_tracker.rb L125–L127](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L125-L127), [L101–L106](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L101-L106)).

`AttributeMutationTracker` does not snapshot. It holds the pre-rebase `@attributes` set. `forget_attribute_assignments` then replaces the model’s `@attributes` with `forgetting_assignment` copies, so the next current tracker sees the saved values as originals ([dirty.rb L390–L392](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L390-L392), [attribute.rb L74–L76](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute.rb#L74-L76)).

**`restore_attributes`** ([dirty.rb L319–L322](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L319-L322), [L413–L419](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L413-L419)) rolls **unsaved** attributes back to `*_was`, not to `previous_changes`. The default argument is `changed`, evaluated once before the loop.

```text
restore_attributes(attr_names = changed)
  for each attr_name
    restore_attribute!
      if attribute_changed?(attr_name)
        #{attr_name}= attribute_was(attr_name)
        clear_attribute_change(attr_name)   # forget_change
```

Unchanged names are skipped. Restoration goes through the writer, then forgets the change so the writer’s `*_will_change!` does not leave the attribute dirty.

**`clear_changes_information`** ([dirty.rb L324–L329](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L324-L329)) drops both trackers and rebases `@attributes` if present. Attribute values are left as they are. Next read of `previous_changes` hits `NullMutationTracker`, whose `changes` is `{}` ([attribute_mutation_tracker.rb L156–L188](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L156-L188)).

## Edge cases

**Attribute omitted from `restore_attributes`.** Covered above. The method never inspects attributes you did not pass. Default `changed` is a snapshot, so restoring `name` inside the loop cannot drop `color` from that list.

**Changed back to the original value.** This depends on the writer, not on `Dirty` comparing current vs original for `ForcedMutationTracker`.

`ForcedMutationTracker#attribute_changed?` is only `forced_changes.include?(attr_name)` ([L136–L138](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L136-L138)). There is no “values became equal again” check.

- `color=` skips `color_will_change!` when `val == @color` ([dirty_test.rb L26–L29](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L26-L29), [L111–L120](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L111-L120)). After save, `color = "Red"` again: `color_changed? == false`, `changed? == false`, `color_change == nil`.
- `name=` always calls `name_will_change!` ([L21–L24](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L21-L24)). After save, `name = "Baal"` again: still dirty, `name_change == ["Baal", "Baal"]`. That matches the documented `*_will_change!` example ([dirty.rb L116–L119](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L116-L119)).
- The RDoc `Person#name=` uses `name_will_change! unless val == @name`, so assigning the same value stays clean ([dirty.rb L37–L40](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L37-L40), [L98–L102](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L98-L102)).

On the Attributes path, assignment creates a `FromUser` attribute and `type.changed?` decides dirtiness. Reassigning the same cast value is clean; `"2.3"` then `"2.1"` for an integer `size` is also clean because both cast to `2` ([attributes_dirty_test.rb L82–L90](file:///home/user/workspace/repo/activemodel/test/cases/attributes_dirty_test.rb#L82-L90), [L188–L199](file:///home/user/workspace/repo/activemodel/test/cases/attributes_dirty_test.rb#L188-L199)).

**Mutable values and `*_will_change!`.** Required on the Forced path; optional on Attributes for types that implement `changed_in_place?` (String does; the generic `Type::Value` returns `false` ([type/value.rb L105–L107](file:///home/user/workspace/repo/activemodel/lib/active_model/type/value.rb#L105-L107))). `force_change` on Forced clones with `value.clone` so the stored original does not share identity with `@name`. On Attributes, `force_change` only records the current fetched value in `forced_changes` and does not clone ([attribute_mutation_tracker.rb L63–L65](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L63-L65)); in-place detection then uses the type, not that hash, unless you forced it.
