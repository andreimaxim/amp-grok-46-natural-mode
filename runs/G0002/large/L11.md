`TimeZone#local` never converts the arguments itself. It packs wall-clock fields into a UTC `Time` carrier and lets `TimeWithZone` resolve the period. That handoff is the contract to preserve.

```text
TimeZone#local(*args)
  Time.utc(*args)                         # carrier, not an instant
  TimeWithZone.new(nil, zone, carrier)
    get_period_and_ensure_valid_local_time
      period_for_local(carrier, dst=true)
        AmbiguousTime -> periods.last
      PeriodNotFound  -> carrier += 1.hour; retry
    utc = carrier + (-observed_utc_offset)
```

I ran the six existing `#local` tests; they pass (`6 runs, 22 assertions`). Values below are from that current checkout, not inferred.

## Invariants from source

**`#local` is a local-time constructor.** [`TimeZone#local`](file:///home/user/workspace/repo/activesupport/lib/active_support/values/time_zone.rb#L370-L378) builds `Time.utc(*args)` and calls `TimeWithZone.new(nil, self, time)`. Passing `utc_time = nil` is what selects the local path in [`TimeWithZone#initialize`](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L50-L58).

**Gap times are shifted, not rejected.** [`get_period_and_ensure_valid_local_time`](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L565-L575) rescues `TZInfo::PeriodNotFound`, adds one hour to `@time`, and retries. The wall clock stored on the object is the post-shift clock, not the requested invalid clock.

**Ambiguous local times prefer DST, then the last period.** [`TimeZone#period_for_local`](file:///home/user/workspace/repo/activesupport/lib/active_support/values/time_zone.rb#L578-L580) calls TZInfo with `dst = true` and `{ |periods| periods.last }`. That matches TZInfo’s documented DST preference, and the block is the fallback when `dst` cannot choose (Moscow 2014 is that case).

**Observables are period-derived, not ENV['TZ'].** After period resolution:

- `#time` is the (possibly shifted) wall-clock carrier ([L64–L66](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L64-L66))
- `#utc` is that carrier minus `period.observed_utc_offset` ([L69–L71](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L69-L71), [L555–L563](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L555-L563))
- `#dst?` is `period.dst?` ([L99–L101](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L99-L101))
- `#zone` is `period.abbreviation` ([L126–L128](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L126-L128))
- `#utc_offset` is `period.observed_utc_offset` ([L115–L118](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L115-L118))
- `#to_a` is `[sec, min, hour, day, mon, year, wday, yday, dst?, zone]` from `#time` plus the period ([L456–L461](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L456-L461))

**`#time` is not the instant.** For every case below, `twz.time` is a UTC-constructed `Time` whose *fields* are the local wall clock. The instant is `twz.utc`. A refactor that stores a real zoned `Time` in `@time` would break every `assert_equal Time.utc(...)` comparison in these tests even if the instant were right.

## How to use this as a gate

Treat the six-test filter above as the behavioral oracle: run it on the unrefactored tree, refactor `#local` / `TimeWithZone.new(nil, …)` / `get_period_and_ensure_valid_local_time` / `period_for_local`, run the same filter. Do not accept a green suite that only checks `#time` or only checks `#utc`.

Failure-to-invariant map:

- `#time` fields change, `#utc` does not → wall-clock rewrite (gap path, or carrier no longer UTC-constructed)
- `#utc` changes, `#time` does not → wrong period/offset (DST vs standard, `periods.last` vs `first`, LMT vs HST)
- `#zone` / `#dst?` disagree with `#utc` → period object and instant came from different resolutions
- exception on 02:00/02:30 → lost `PeriodNotFound` retry
- exception on Eastern 1:00 or Moscow 1:00 → lost `dst=true` or `periods.last`
- Hawaii 2007 `#utc` off by 10 hours → args treated as UTC instead of local
- Hawaii 1850 wall clock preserved but `#utc` is `01:30:45Z` next day → modern HST offset applied to LMT

`parse` / `iso8601` / `strptime` share the same `TimeWithZone.new(nil, zone, time)` entry ([time_zone.rb L448–L451](file:///home/user/workspace/repo/activesupport/lib/active_support/values/time_zone.rb#L448-L451) via `parts_to_time`). They are not extra constructors to re-derive; if `#local` preserves the cases above, those parsers keep the same conversion as long as they still pass `utc_time = nil`.
