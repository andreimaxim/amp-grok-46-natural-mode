**Request changes.** The leak claim is wrong for the embedding path Rails actually provides, and the proposed `ensure` restore does not match how runner is invoked or tested.

## Verdict

Do not merge this as a fix for “embedding the command leaks runner arguments.” [`Rails::Command.invoke`](file:///home/user/workspace/repo/railties/lib/rails/command.rb#L56-L72) already saves/restores `ARGV` in [`with_argv`](file:///home/user/workspace/repo/railties/lib/rails/command.rb#L140-L146). [`runner_test.rb`](file:///home/user/workspace/repo/railties/test/commands/runner_test.rb) never observes post-`perform` `ARGV` because every case goes through the forking [`rails`](file:///home/user/workspace/repo/railties/test/isolation/abstract_unit.rb#L408-L457) helper.

The inner `ARGV.replace(command_argv)` in [`RunnerCommand#perform`](file:///home/user/workspace/repo/railties/lib/rails/commands/runner/runner_command.rb#L24-L65) is intentional: it is how the executed code sees trailing args, not the command name or the Ruby snippet/filename.

## What the code actually does

```24:50:railties/lib/rails/commands/runner/runner_command.rb
def perform(code_or_file = nil, *command_argv)
  unless code_or_file
    help
    exit 1
  end

  boot_application!
  Rails.application.load_runner

  ARGV.replace(command_argv)
  # then stdin / file / eval
```

Dispatch is:

```diagram
┌─────────────┐   ARGV.shift    ┌─────────────────────┐
│ bin/rails   │───────────────▶│ Rails::Command.invoke│
└─────────────┘                 └──────────┬──────────┘
                                           │ with_argv: save ARGV
                                           ▼
                                ┌─────────────────────┐
                                │ RunnerCommand#perform│
                                │ ARGV.replace(argv)  │
                                └──────────┬──────────┘
                                           │ eval / Kernel.load
                                           ▼
                                with_argv ensure restores ARGV
```

[`railties/test/command/base_test.rb`](file:///home/user/workspace/repo/railties/test/command/base_test.rb#L127-L141) already asserts that mutations inside a command do not escape `invoke`. Inline generator embedding uses the same path ([`rails_command(..., inline: true)`](file:///home/user/workspace/repo/railties/lib/rails/generators/actions.rb#L388-L402)).

CLI `bin/rails runner` exits after `perform`, so a leftover `ARGV` is irrelevant.

## Case-by-case

**Inline code.** `eval(code_or_file, TOPLEVEL_BINDING, __FILE__, __LINE__)`. `command_argv` becomes `ARGV` for the duration of the snippet. [`test_should_set_argv_when_running_code`](file:///home/user/workspace/repo/railties/test/application/runner_test.rb#L40-L43) depends on that. Restoring after eval does not change in-eval behavior; it also does not fix anything those tests can see.

**Ruby filename.** `File.exist?` then `$0 = expanded_file_path` and `Kernel.load`. Trailing args are already covered by [`test_passes_extra_args_to_file`](file:///home/user/workspace/repo/railties/test/application/runner_test.rb#L78-L83). The proposed restore leaves `$0` / `$PROGRAM_NAME` mutated ([`test_should_set_dollar_0_to_file`](file:///home/user/workspace/repo/railties/test/application/runner_test.rb#L61-L75)). If in-process isolation is the goal, this is the larger leak, and the PR does not touch it.

**stdin (`-`).** Matched before `File.exist?`, so a file named `-` is not loaded. `ARGV.replace` still runs, so stdin scripts can see extra args. Tests never pass extra args to `-`. Restore would not affect the eval.

**Syntax errors / missing files.** `ARGV.replace` happens before `eval`. Missing `*.rb` uses the file-not-found branch and `exit 1`; other bad input uses the syntax/name-error branch and `exit 1`. An `ensure` would run before `exit`, which is harmless and untested. [`runner_test.rb`](file:///home/user/workspace/repo/railties/test/commands/runner_test.rb#L34-L70) only checks stderr and status.

**Nested / in-process invocation.** Through `Rails::Command.invoke`, isolation already exists. Direct `RunnerCommand.perform(...)` or Thor dispatch that skips `invoke` does leak `ARGV`. That is not how Rails embeds commands, and no test exercises it. The proposed restore would help only that unsupported path, and it would restore *perform-entry* `ARGV` (under `invoke`, the full runner args including the code/file), not “the process ARGV before runner,” which `with_argv` already does.

**`$0` / `$PROGRAM_NAME`.** Set only for files, never restored. Unrelated to the proposed diff; incomplete if the PR is about embedding hygiene.

**Executor wrapping.** `ARGV.replace` is outside [`conditional_executor`](file:///home/user/workspace/repo/railties/lib/rails/command/base.rb). Scripts inside the executor correctly see runner args. [`test_rails_runner_with_conditional_executor`](file:///home/user/workspace/repo/railties/test/commands/runner_test.rb#L47-L54) is about `executor.active?`, not `ARGV`. No interaction with restore.

**Args beginning with `-`.** Runner does not enable Thor `stop_on_unknown_option!`. Unknown dashed tokens after the code/file are passed through (`--foo`, `-b`, `--moo` in [`test_should_set_argv_when_running_code`](file:///home/user/workspace/repo/railties/test/application/runner_test.rb#L40-L43)). Known options (`-e`, `--skip-executor` / `-w`) can still be consumed by Thor wherever they appear. Restore does not change parsing.

## Compatibility / missing tests

- **Redundant double-restore** on the real embedding API (`invoke` → `with_argv` → `perform`). Same pattern as [`GenerateCommand`](file:///home/user/workspace/repo/railties/lib/rails/commands/generate/generate_command.rb#L24) (`ARGV.replace` with no inner restore).
- **Behavior change** only for callers of `perform` that skip `invoke` and then read `ARGV`. That is not a documented contract, but it is also not a demonstrated bug.
- **No test in `runner_test.rb` can fail today and pass after this change.** Isolation tests fork/`load bin/rails` and then the child exits.
- **Script mutations of `ARGV` during eval/load** are already discarded by outer `with_argv`; an inner restore would discard them even on a direct `perform` call.

## More precise change, if any

None for `Command.invoke` / `bin/rails runner`. If the intent is “`perform` itself must not mutate process globals,” restore `$0` as well and add an **in-process** test that stubs `boot_application!` / `load_runner`, calls `perform` (or `invoke`), and asserts `ARGV` and `$0` after return. Do not describe that as fixing embedding through `Rails::Command.invoke`; that is already covered by [`base_test.rb`](file:///home/user/workspace/repo/railties/test/command/base_test.rb#L127-L141).
