Requiring `rails/test_help` is a one-shot load-hook installer, not a function you can call again. Preserve that, not the file’s internal layout.

## What `require "rails/test_help"` actually does

The public surface is the whole file, not just path assignment. From [railties/lib/rails/test_help.rb](file:///home/user/workspace/repo/railties/lib/rails/test_help.rb):

1. Abort if `Rails.env.production?`.
2. Require `active_support/test_case`, `rails/generators/test_case`, `active_support/testing/autorun`, and `rails/testing/maintain_test_schema`.
3. If `ActiveRecord::Base` is defined:
   - include `ActiveRecord::TestDatabases`, `ActiveRecord::TestFixtures`, `ActiveRecord::Assertions::QueryAssertions` on `ActiveSupport::TestCase`
   - `self.fixture_paths = [*self.fixture_paths, "#{Rails.root}/test/fixtures/"].uniq`
   - `self.file_fixture_path = "#{Rails.root}/test/fixtures/files"`
   - on `ActionDispatch::IntegrationTest`: `self.fixture_paths += ActiveSupport::TestCase.fixture_paths` (no `uniq`)
4. If Active Record is absent: set only `file_fixture_path` on `ActiveSupport::TestCase`. Do not include TestFixtures. Do not touch integration `fixture_paths`.
5. Define `before_setup` on controller and integration tests so `@routes = Rails.application.routes` and `super`.

`ActiveSupport::TestCase` and `ActionDispatch::IntegrationTest` are already loaded by a normal `require "rails/test_help"` (test_help requires ASTC; a bootstrapped app already loaded IntegrationTest). [Lazy load hooks](file:///home/user/workspace/repo/activesupport/lib/active_support/lazy_load_hooks.rb) therefore run the blocks **immediately**, and keep them for any later `run_load_hooks`. `require` will not re-run the file.

Engine extra paths are not assigned in test_help. They arrive first: including TestFixtures runs `:active_record_fixtures`, and [engine.rb](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L655-L661) does `self.fixture_paths |= ["#{fixtures}/"]`. Only then does test_help append `"#{Rails.root}/test/fixtures/"` with `uniq`.

```text
require "rails/test_help"
  abort if production
  require ASTC, generators/test_case, autorun, maintain_test_schema
  if ActiveRecord::Base
    on_load(:active_support_test_case)  # runs now
      include TestDatabases, TestFixtures, QueryAssertions
        TestFixtures.included → on_load(:active_record_fixtures)
          engines: fixture_paths |= [engine/test/fixtures/]
      fixture_paths = [*fixture_paths, "#{Rails.root}/test/fixtures/"].uniq
      file_fixture_path = "#{Rails.root}/test/fixtures/files"
    on_load(:action_dispatch_integration_test)  # runs now
      fixture_paths += ASTC.fixture_paths     # duplicates parent paths
  else
    on_load(:active_support_test_case)
      file_fixture_path = "#{Rails.root}/test/fixtures/files"
  on_load(:action_controller_test_case / :action_dispatch_integration_test)
    def before_setup; @routes = Rails.application.routes; super; end
```

Two current quirks that a cleanup will want to “fix” and must not:

- `Array#uniq` is string equality. `"/abs/test/fixtures/"` and `"test/fixtures/"` stay both. A Pathname and a String of the same path also stay both.
- IntegrationTest `+=` copies the parent list onto a subclass that already inherited it, so IntegrationTest paths are **duplicated** relative to ASTC. Snapshot that. Do not `uniq` it.

`file_fixture_path` is assigned even if `test/fixtures/files` does not exist. Access, not assignment, is what fails.

## Verification approach

Use the railties isolation app pattern from [test_test.rb](file:///home/user/workspace/repo/railties/test/application/test_test.rb): `include ActiveSupport::Testing::Isolation`, `build_app` / `teardown_app`, write a real `test/test_helper.rb` that requires `rails/test_help`, write a real test file, run it with `rails test`, assert process exit and stdout.

Each case below is one forked test. Do not boot two of these in the parent process.

Proof is always: a test method that loads a YAML fixture row, reads a file fixture, or issues an integration request that depends on that data. After that, optionally print `fixture_paths` / `file_fixture_path` for exact-list snapshots.

### Matrix (one isolated run each)

**Relative vs absolute.** After require, `fixture_paths` entries are `"#{Rails.root}/test/fixtures/"` with trailing slash, i.e. an absolute string from Pathname interpolation. A later `fixture_paths << "test/fixtures/"` must remain a **second** entry; `people(:one)` must still resolve (FixtureSet searches every path). Do not normalize.

**Duplicates already present.** Before require, an engine/hook path equal to `"#{Rails.root}/test/fixtures/"` must collapse on ASTC because of `uniq`. A **different spelling** of the same directory must not. IntegrationTest must still `+=` the ASTC list, so duplicates that `uniq` removed on ASTC reappear there if they were on ASTC, and ASTC’s whole list is appended again.

**Application extra paths.** Two legal sources:

1. Engine initializer (`fixture_paths |= [engine_root/test/fixtures/]`), which runs during `include TestFixtures`, **before** test_help appends app fixtures. Order on ASTC: engine paths, then app path. Load `engine/test/fixtures/things.yml` and `test/fixtures/people.yml` in one test via `things(:x)` and `people(:one)`.
2. After require, the documented `ActiveSupport::TestCase.fixture_paths << "component1/test/fixtures"`. That append must survive; it is not part of test_help. A reorganization that resets `fixture_paths = [app_path]` later would wipe it if user code ran between — user code in the generated helper runs after require, so the child test_helper should do: require test_help, append extra path, `fixtures :all`. Assert both fixture sets load.

**Missing fixture directory.** Delete `test/fixtures` and `test/fixtures/files` (or never create them). Require must still succeed. `file_fixture("hello.txt")` must raise `ArgumentError` matching [FileFixtures](file:///home/user/workspace/repo/activesupport/lib/active_support/testing/file_fixtures.rb) (`the directory '%s' does not contain a file named '%s'`). `fixtures :all` must not raise solely because the directory is absent (`Dir[...]` is empty). Named `fixtures :people` should fail when the YAML is missing — assert that failure, not a boot failure.

**Class defined before require.** In the child:

```ruby
class BeforeHelpTest < ActiveSupport::TestCase; end
require "rails/test_help"
class AfterHelpTest < ActiveSupport::TestCase; end
class BeforeIntegrationTest < ActionDispatch::IntegrationTest; end  # if IntegrationTest already loaded
```

`BeforeHelpTest` must still load `people(:one)` and `file_fixture`. It inherits the class_attribute assigned on ASTC after it was defined. A subclass that **assigns its own** `fixture_paths = ["/only/mine"]` before require cannot do so (`fixture_paths` does not exist until TestFixtures is included). After require, a subclass assignment must not change `ActiveSupport::TestCase.fixture_paths` ([class_attribute copy-on-write](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/class/attribute.rb)); mutating with `<<` **does** leak to the parent — assert both, because test_help uses `=` / `+=`, not `<<`.

**Repeated require.** `require "rails/test_help"` twice must be a no-op: same object_id of the fixture_paths array on ASTC, IntegrationTest list not grown, `before_setup` still one override that sets `@routes` and calls `super`. Contrast with `load` of the same file: ASTC stays uniq-stable; IntegrationTest `+=` grows again. Preserve require-idempotency; do not make `load` newly idempotent unless you are willing to call that a behavior change.

**Active Record absent.** `build_app` then comment out `require "active_record/railtie"` (the skip-AR generator shape). Child helper is `require "rails/test_help"` only. Assert:

- `file_fixture("hello.txt").read` works (create the files dir even without AR)
- `ActiveSupport::TestCase.respond_to?(:fixture_paths)` is false
- `ActionDispatch::IntegrationTest.respond_to?(:fixture_paths=)` is false
- ancestors do not include TestFixtures / QueryAssertions
- `get "/posts"` still works (`@routes` hook is outside the AR branch)
- `rails test` does not run `maintain_test_schema!`

**Multiple boots in one process.** This is the trap. test_help interpolates `Rails.root` **at require time** and stores strings on the class. A second `Rails.application =` in the same process does not rewrite those strings, because `$LOADED_FEATURES` blocks a second require. Assert that explicitly in one forked process:

1. Boot app A, require test_help, snapshot paths (A’s root).
2. Point `Rails.application` at app B (different root), do **not** `load` test_help.
3. Paths must still be A’s. `file_fixture` must still look under A. That is current behavior.

A lazy `Rails.root` read on each test would be a silent behavior change. If the reorganization introduces a helper method, it must close over the root from first require, or you are not preserving effects.

Also assert the production abort and that `maintain_test_schema!` still exits 1 on pending migrations ([maintain_test_schema.rb](file:///home/user/workspace/repo/railties/lib/rails/testing/maintain_test_schema.rb)) — those are public effects of the same require.

## Isolation / cleanup (or regressions hide)

`fixture_paths` and `file_fixture_path` are process-global class_attributes. `:active_support_test_case` / `:action_dispatch_integration_test` / `:active_record_fixtures` hook arrays are append-only. `ActiveRecord::TestFixtures`’s `@@already_loaded_fixtures` is a class variable. `$LOADED_FEATURES` makes in-process re-require useless.

So:

- Every case that boots an app and requires test_help runs under `ActiveSupport::Testing::Isolation` (fork), same as [test_test.rb](file:///home/user/workspace/repo/railties/test/application/test_test.rb).
- `ENV["PARALLEL_WORKERS"] = "0"` in setup/teardown of the parent file so the isolation tests are not themselves parallelized into a soup of fixture DBs.
- `build_app` / `teardown_app` restores `Rails.application`, `Rails.app_class`, `RAILS_ENV`, and deletes `tmp_path`. That is necessary but **not sufficient** without the fork: load hooks and ASTC attributes would leak.
- Do not mutate `ActiveSupport::TestCase.fixture_paths` in the parent railties process. If a non-isolated unit test is added, wrap with save/restore of `fixture_paths`, `file_fixture_path`, and do not `include TestFixtures` onto ASTC in that process.
- Child `rails test` processes are naturally isolated; prefer asserting through them over requiring test_help inside the railties test process at all.
- Do not stub `Rails.root` in the parent and then require test_help. First require wins for the whole VM.
- Keep `$LOADED_FEATURES` alone in the parent. Removing `"rails/test_help"` to re-require looks clever and re-registers hooks on already-loaded classes (IntegrationTest `+=` would duplicate for real).

Class-variable-only tests in the parent will green while child `people(:one)` breaks (wrong path, relative vs absolute, missing trailing slash, IntegrationTest duplicate list changing FixtureSet lookup order). That is why the primary assertions are fixture access and `get`.
