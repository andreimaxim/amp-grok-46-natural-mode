`stream_from` attaches a channel to a named pubsub queue. `broadcast` puts a payload on that queue. The client only sees a message if a live stream handler is subscribed at the moment of the broadcast — it is not a backlog.

┌──────────────┐     encode      ┌─────────┐     invoke callback
│ broadcast()  │━━━━━━━━━━━━━━━━▶│ pubsub  │━━━━━━━━━━━━━━━━━━━━┓
└──────────────┘                 └─────────┘                    ┃
                                                                ▼
┌──────────────┐  String() name  ┌─────────┐     success λ     ┌───────────────────┐
│ stream_from  │────────────────▶│ pubsub  │──────────────────▶│ confirm_subscription │
└──────┬───────┘                 │subscribe│                   └───────────────────┘
       │                         └─────────┘
       │
       ▼
  handler pipeline
       ┃
       ┣━ no callback ──▶ JSON decode ──▶ transmit (event-loop / adapter thread)

## Subscribe path

A client `subscribe` command becomes a channel instance, then [`subscribe_to_channel`](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/base.rb#L199-L206):

```text
Subscriptions#add
  Channel#subscribe_to_channel
    subscribed                    # typically calls stream_from
    reject_subscription if rejected
    ensure_confirmation_sent
```

[`stream_from`](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/streams.rb#L90-L108) then:

1. Returns immediately if [`unsubscribed?`](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/base.rb#L219-L221) is true.
2. Coerces the broadcasting with `String(broadcasting)`.
3. Increments the deferred-confirmation counter.
4. Builds a handler, stores it in `streams[broadcasting]`.
5. Calls `pubsub.subscribe(broadcasting, handler, success_lambda)`.

The success lambda is what actually confirms:

```90:108:actioncable/lib/action_cable/channel/streams.rb
def stream_from(broadcasting, callback = nil, coder: nil, &block)
  return if unsubscribed?

  broadcasting = String(broadcasting)

  # Don't send the confirmation until pubsub#subscribe is successful
  defer_subscription_confirmation!

  handler = worker_pool_stream_handler(broadcasting, callback || block, coder: coder)
  streams[broadcasting] = handler

  pubsub.subscribe(broadcasting, handler, lambda do
    ensure_confirmation_sent
    logger.info "#{self.class.name} is streaming from #{broadcasting}"
  end)
end
```

Inline/Success adapters fire that lambda synchronously ([`SuccessAdapter#subscribe`](file:///home/user/workspace/repo/actioncable/test/stubs/test_adapter.rb#L14-L18), [`SubscriberMap#add_subscriber`](file:///home/user/workspace/repo/actioncable/lib/action_cable/subscription_adapter/subscriber_map.rb#L12-L24)). The Async adapter posts subscribe and later `invoke_callback` onto the executor ([`SubscriberMap::Async`](file:///home/user/workspace/repo/actioncable/lib/action_cable/subscription_adapter/subscriber_map.rb#L59-L74)).

## Broadcast path

[`Server::Broadcasting#broadcast`](file:///home/user/workspace/repo/actioncable/lib/action_cable/server/broadcasting.rb#L35-L37) is a one-shot wrapper around a `Broadcaster`. The name is coerced once in [`broadcaster_for`](file:///home/user/workspace/repo/actioncable/lib/action_cable/server/broadcasting.rb#L42-L44).

```54:62:actioncable/lib/action_cable/server/broadcasting.rb
def broadcast(message)
  server.logger.debug { "[ActionCable] Broadcasting to #{broadcasting}: #{message.inspect.truncate(300)}" }

  payload = { broadcasting: broadcasting, message: message, coder: coder }
  ActiveSupport::Notifications.instrument("broadcast.action_cable", payload) do
    encoded = coder ? coder.encode(message) : message
    server.pubsub.broadcast broadcasting, encoded
  end
end
```

Default `coder:` is `ActiveSupport::JSON`. A truthy coder encodes before pubsub; `coder: nil` publishes the object unchanged. Tests pin the notification payload, including the coder, in [actioncable/test/server/broadcasting_test.rb](file:///home/user/workspace/repo/actioncable/test/server/broadcasting_test.rb#L18-L39).

The adapter then fans out to every handler registered on that string name ([`SubscriberMap#broadcast`](file:///home/user/workspace/repo/actioncable/lib/action_cable/subscription_adapter/subscriber_map.rb#L39-L47) → `callback.call message`).

## Default handler vs user callback

Handler construction is two layers: [`stream_handler`](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/streams.rb#L179-L185) chooses the body; [`worker_pool_stream_handler`](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/streams.rb#L163-L173) decides the thread.

```163:198:actioncable/lib/action_cable/channel/streams.rb
def worker_pool_stream_handler(broadcasting, user_handler, coder: nil)
  handler = stream_handler(broadcasting, user_handler, coder: coder)

  if user_handler
    -> message do
      connection.perform_work handler, :call, message
    end
  else
    handler
  end
end

def stream_handler(broadcasting, user_handler, coder: nil)
  if user_handler
    stream_decoder user_handler, coder: coder
  else
    default_stream_handler broadcasting, coder: coder
  end
end

def default_stream_handler(broadcasting, coder:)
  coder ||= ActiveSupport::JSON
  stream_transmitter stream_decoder(coder: coder), broadcasting: broadcasting
end
```

| | Default (no callback/block) | User callback or block |
|---|---|---|
| Decode | Always JSON unless you pass another coder (`coder \|\|= ActiveSupport::JSON`) | Decode only if `coder` is truthy |
| Transmit | Always [`transmit`](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/base.rb#L240-L250) with `via: "streamed from #{broadcasting}"` | Not wrapped; the callback must `transmit` itself if the client should see it |
| Thread | Runs on the adapter callback thread — **not** the worker pool | [`Socket#perform_work`](file:///home/user/workspace/repo/actioncable/lib/action_cable/server/socket.rb#L57-L59) → [`Worker#async_invoke`](file:///home/user/workspace/repo/actioncable/lib/action_cable/server/worker.rb#L52-L66) |

Evidence:

- Default path delivers `{ "foo" => "bar" }` and never calls `perform_work` ([stream_test.rb L381–389](file:///home/user/workspace/repo/actioncable/test/channel/stream_test.rb#L381-L389)).
- A user block that sets `Thread.current[:ran_callback]` does **not** set that flag on the test thread ([stream_test.rb L332–336, L368–377](file:///home/user/workspace/repo/actioncable/test/channel/stream_test.rb#L368-L377)). The broadcast ran, but on a worker.

`transmit` does not JSON-encode the inner payload itself. It hands `{ identifier:, message: data }` to the socket, which JSON-encodes the envelope ([`Socket#transmit`](file:///home/user/workspace/repo/actioncable/lib/action_cable/server/socket.rb#L45-L49)). So the default path is: pubsub JSON string → decode to Ruby → wrap in cable envelope → encode again.

## `coder: nil` vs `ActiveSupport::JSON` vs custom encode

[`stream_decoder`](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/streams.rb#L200-L215) is the only decode site:

```200:215:actioncable/lib/action_cable/channel/streams.rb
def stream_decoder(handler = nil, coder:)
  if coder
    -> message do
      message = coder.decode(message)

      if handler
        handler.(message)
      else
        message
      end
    end
  else
    handler
  end
end
```

Three contracts, from this revision:

**`stream_from` keyword default is `coder: nil`.** Docs and the method signature say a user callback then gets the raw pubsub payload. That matches `stream_decoder` returning `handler` unchanged when `coder` is falsy.

**The default (no-callback) handler ignores that nil.** It substitutes `ActiveSupport::JSON` before decoding, then transmits. Passing `coder: nil` to `stream_from` without a callback is therefore still a JSON retransmitter.

**Server `broadcast` defaults the other way:** `coder: ActiveSupport::JSON`. `coder: nil` skips `encode` and publishes `message` as-is ([broadcasting.rb L59](file:///home/user/workspace/repo/actioncable/lib/action_cable/server/broadcasting.rb#L59)).

Custom server-side encoding is covered by [`DummyEncoder`](file:///home/user/workspace/repo/actioncable/test/channel/stream_test.rb#L38-L41) and the `"custom encoder"` test ([L356–365](file:///home/user/workspace/repo/actioncable/test/channel/stream_test.rb#L356-L365)):

```text
broadcast({ foo: "bar" }, coder: DummyEncoder)
  DummyEncoder.encode → '{ "foo": "encoded" }'   # ignores the hash
  pubsub payload is that JSON string
  default stream handler JSON-decodes it
  client message == { "foo" => "encoded" }
```

`ChatChannel` in that test always passes `coder: pick_coder(params[:coder])`, and `pick_coder(nil)` is `ActiveSupport::JSON` ([L16–35](file:///home/user/workspace/repo/actioncable/test/channel/stream_test.rb#L16-L35)). The test therefore exercises **custom encode on broadcast + JSON decode on the default stream handler**, not a custom stream decoder.

There is no test in this revision that passes `coder: nil` through a user callback, or that uses `pick_coder("none"|"custom")` on `stream_from`. Those branches exist only in the implementation and the unused test helper.

## Deferred subscription confirmation

The counter starts at 1 so confirmation waits for `subscribe_to_channel` itself ([base.rb L167–172](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/base.rb#L167-L172)). Each `stream_from` increments it; each `ensure_confirmation_sent` decrements and sends only when the counter hits 0 and the subscription was not rejected ([L253–264](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/base.rb#L253-L264)). `transmit_subscription_confirmation` also no-ops after the first send ([L322–331](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/base.rb#L322-L331)).

## Decode / encode failures

This revision has **no tests** for encode or decode exceptions. Behavior follows the lack of rescue at those call sites.

- **Broadcast encode** (`coder.encode(message)`) runs in the caller of `broadcast`. A failing coder raises out of `Broadcaster#broadcast`. Instrumentation still wraps the call, so a raised encode still emits `broadcast.action_cable`.
- **Default-handler decode** runs on the pubsub callback thread (`handler.call message`). There is no rescue in `stream_decoder` or `stream_transmitter`. A bad JSON payload raises there; the client gets no `transmit`.
- **User-callback decode** runs inside the worker-pool invocation. [`Worker#invoke`](file:///home/user/workspace/repo/actioncable/lib/action_cable/server/worker.rb#L58-L66) rescues `Exception`, logs class/message/backtrace, and calls `handle_exception` if the receiver defines it. A `Proc` does not, so a decode failure is logged and swallowed; the callback never runs.

`coder: nil` on either side skips that `encode`/`decode` call entirely, so those failures cannot occur on that hop.
