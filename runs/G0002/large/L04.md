`Array#extract_options!` is the pre-kwargs convention for “last argument may be an options hash.” It lives in [`activesupport/lib/active_support/core_ext/array/extract_options.rb`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/array/extract_options.rb) and is the whole contract:

```ruby
def extract_options!
  if last.is_a?(Hash) && last.extractable_options?
    pop
  else
    {}
  end
end
```

**Trailing-only.** The method inspects `last` and nothing else. There is no scan, no reverse search, no “first hash that looks like options.” If the last element is not an extractable hash, extraction fails even if an earlier element is a `Hash`.

**`Hash` versus subclasses.** Qualification is two-step:

1. `last.is_a?(Hash)` — must be in the `Hash` hierarchy (so `nil` on an empty array fails immediately).
2. `last.extractable_options?` — `Hash` defines this as `instance_of?(Hash)`.

A plain `Hash` (including a kwargs-style `{ a: :b }` at the end of `*args`) extracts. A subclass that only inherits `Hash` does not: `HashSubclass.new` is `is_a?(Hash)` but not `instance_of?(Hash)`, so it is treated as a positional value. That is deliberate; domain hashes (`HashWithIndifferentAccess` aside) are often real arguments, not method options.

**Subclass opt-in.** A subclass that *should* be treated as options overrides `extractable_options?` to return `true`. Rails does this for [`HashWithIndifferentAccess`](file:///home/user/workspace/repo/activesupport/lib/active_support/hash_with_indifferent_access.rb), [`OrderedOptions`](file:///home/user/workspace/repo/activesupport/lib/active_support/ordered_options.rb), and [`ActiveSupport::OrderedHash`](file:///home/user/workspace/repo/activesupport/lib/active_support/ordered_hash.rb). The tests in [`extract_options_test.rb`](file:///home/user/workspace/repo/activesupport/test/core_ext/array/extract_options_test.rb) encode the three cases: plain `Hash` extracts, anonymous `Hash` subclass does not, opt-in subclass does.

**Receiver mutation.** On success the last element is `pop`ped. The same array object is shorter afterward; the popped object is returned as-is (same identity, not a dup). On failure the receiver is left unchanged.

**Nothing qualifies.** Empty array, last element not a `Hash`, or last element a non-extractable `Hash` subclass: the method returns a **new** `{}` and does not touch the receiver. Callers can always `options = args.extract_options!` and treat the result as a hash.

**Why an earlier hash stays positional.** Because only `last` is a candidate. In `[:name, { foo: 1 }, :other]`, `{ foo: 1 }` is just another argument. In `[user, { as: :admin }]`, the trailing hash is options and `user` stays positional. That split is how `def foo(*args)` APIs (validates, callbacks, asset tags, generators, cache reads) separate values from options without kwargs. Moving a hash off the end, or using a non-opted-in subclass, is how you pass a hash as data rather than as options.
