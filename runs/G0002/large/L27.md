The proposed one-line change is **incorrect** at this revision. Current-key signed cookies already do not rewrite; `force_reserialize: rotated` exists to upgrade cookies that only verified under a fallback secret/digest. I applied the patch locally: `test_signed_cookie_rotating_secret_and_digest` and `test_rotating_signed_cookies_digest` error; then restored the file.

## Verdict

**Do not merge.** The claim that this “safely avoids unnecessary signed-cookie rewrites after key rotation” is false. Rotation rewrites are the upgrade path. Without them, old secrets and digests cannot be retired.

## Findings

### 1. High — Rotation upgrades are dropped; old secrets never leave the wire

[`SignedKeyRotatingCookieJar#parse`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/middleware/cookies.rb#L640-L647) sets `rotated` only when `MessageVerifier#verified` succeeds on a **fallback**, then forces a write:

```640:647:actionpack/lib/action_dispatch/middleware/cookies.rb
        def parse(name, signed_message, purpose: nil)
          rotated = false
          data = @verifier.verified(signed_message, purpose: purpose, on_rotation: -> { rotated = true })
          super(name, data, force_reserialize: rotated)
        end
```

[`SerializedCookieJars#parse`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/middleware/cookies.rb#L599-L612) turns that into a jar write:

```608:608:actionpack/lib/action_dispatch/middleware/cookies.rb
            self[name] = { value: value } if force_reserialize || reserialize?(dumped)
```

That assignment goes through [`commit`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/middleware/cookies.rb#L649-L653) (current digest + current derived key) and [`CookieJar#[]=`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/middleware/cookies.rb#L439-L458), which queues `Set-Cookie` when the signed string changed.

[`Messages::Rotator#read_message`](file:///home/user/workspace/repo/activesupport/lib/active_support/messages/rotator.rb#L29-L47) calls `on_rotation` **only after a fallback succeeds**. Primary success never sets `rotated`.

Hard evidence: with `force_reserialize: false`, these tests still **read** the old cookie, then fail because no upgraded `Set-Cookie` is written:

- [`test_signed_cookie_rotating_secret_and_digest`](file:///home/user/workspace/repo/actionpack/test/dispatch/cookies_test.rb#L641-L656) — old secret + SHA1 → expect SHA256 + current key
- [`test_rotating_signed_cookies_digest`](file:///home/user/workspace/repo/actionpack/test/dispatch/cookies_test.rb#L1000-L1015) — SHA1 → SHA256, same derived key

Both raised `ActiveSupport::MessageVerifier::InvalidSignature: invalid message string` at `verifier.verify(@response.cookies["user_id"])` because `@response.cookies["user_id"]` was nil.

That is the opposite of “safe.” After this patch, every request can still *read* rotated cookies, but clients keep presenting the old signature forever.

### 2. High — The “unnecessary rewrite” case already does not rewrite

Current signature, same digest, same serializer: primary `verified` succeeds, `on_rotation` is not called.

Active Support already locks that in:

- [`on_rotation is not called when no rotation is necessary`](file:///home/user/workspace/repo/activesupport/test/messages/message_rotator_tests.rb#L59-L62)
- [`on_rotation is called on successful rotation`](file:///home/user/workspace/repo/activesupport/test/messages/message_rotator_tests.rb#L42-L45)
- [`on_rotation is not called when no rotation is successful`](file:///home/user/workspace/repo/activesupport/test/messages/message_rotator_tests.rb#L65-L73) (tampered / unknown secret)

Cookie tests that **read** a still-current payload and assert **no** `Set-Cookie`:

- [`test_signed_cookie_using_marshal_serializer_can_read_from_json_dumped_value`](file:///home/user/workspace/repo/actionpack/test/dispatch/cookies_test.rb#L715-L728) — `assert_nil @response.cookies["user_id"]`
- [`test_signed_cookie_using_hybrid_serializer_can_read_from_json_dumped_value`](file:///home/user/workspace/repo/actionpack/test/dispatch/cookies_test.rb#L748-L761) — same

Serializer upgrades are a **separate** gate, [`reserialize?`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/middleware/cookies.rb#L591-L596), not `rotated`. Hybrid marshal→JSON and JSON→MessagePack still rewrite with the patch applied; those tests stayed green. Hard-coding `false` does not touch that path, so it is not a serializer-migration fix either.

### 3. Medium — Tamper / expiry already skip writes; the patch does not change them

[`MessageVerifier#verified`](file:///home/user/workspace/repo/activesupport/lib/active_support/message_verifier.rb#L225-L233) swallows `:invalid_message_format` and `:invalid_message_content` as `nil`. [`SerializedCookieJars#parse`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/middleware/cookies.rb#L599-L612) returns immediately when `dumped` is nil, so it never assigns.

Rotator’s `catch_rotation_error` only catches format/serialization throws, not content (expiry / purpose). An expired fallback therefore never sets `rotated`.

### 4. Low — Dead local and an inconsistent encrypted twin

The patched method still assigns `rotated` and never uses it (`assigned but unused variable - rotated` when I ran the tests). [`EncryptedKeyRotatingCookieJar#parse`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/middleware/cookies.rb#L690-L697) keeps `force_reserialize: rotated`; [`test_encrypted_cookie_rotating_secret`](file:///home/user/workspace/repo/actionpack/test/dispatch/cookies_test.rb#L1118-L1136) still expects a rewrite. If rotation rewrites were “unnecessary,” this would be incomplete; they are necessary, so signed/encrypted should stay aligned.

## Tests this change would need (and currently cannot pass)

Do not add these as “new behavior.” They already exist or would document the regression:

1. **Old secret, current digest** — inbound cookie verifies only with the rotated secret; response cookie must verify with the *current* derived key. Already [`test_signed_cookie_rotating_secret_and_digest`](file:///home/user/workspace/repo/actionpack/test/dispatch/cookies_test.rb#L641-L656).
2. **Same secret, old digest** — SHA1 inbound, SHA256 outbound. Already [`test_rotating_signed_cookies_digest`](file:///home/user/workspace/repo/actionpack/test/dispatch/cookies_test.rb#L1000-L1015).
3. **Current signature, no serializer change** — GET must not emit `Set-Cookie`. Missing as a first-class signed-jar test; the two `assert_nil @response.cookies["user_id"]` cases above are the closest. This is the test the author’s claim would need, and it already matches current code **without** the patch.
4. **Tampered** — `signed[]` is nil and no `Set-Cookie`. Already present.
5. **Expired inbound signed cookie** — `signed[]` is nil and no rewrite. Relative-expires test covers read-side nil; a GET of an already-expired Cookie header asserting `assert_nil @response.cookies[...]` is still a gap.
6. **Serializer upgrade without rotation** — hybrid/message_pack migrate tests. Must keep rewriting via `reserialize?` even if someone later changes the rotation flag.

[`test_cookie_with_hash_value_not_modified_by_rotation`](file:///home/user/workspace/repo/actionpack/test/dispatch/cookies_test.rb#L1138-L1146) only checks the decoded Hash. It would **not** catch this regression.

## What is actually happening on a signed read

```text
cookies.signed[:user_id]
  AbstractCookieJar#[]
    parse(..., purpose: "cookie.user_id")
      MessageVerifier#verified(..., on_rotation: -> { rotated = true })
        Rotator#read_message
          primary current secret/digest  ──success──► rotated=false
          else fallback rotate(*)        ──success──► on_rotation; rotated=true
          else format/content failure    ──► nil
    SerializedCookieJars#parse
      serializer.load
      write parent jar iff rotated || reserialize?(payload)
        SignedKeyRotatingCookieJar#commit
          current verifier.generate + metadata
        CookieJar#[]= → @set_cookies → Set-Cookie
```

The proposed `force_reserialize: false` cuts only the `rotated` branch. That branch is the key/digest upgrade. It is not a no-op, and it is not “unnecessary.”
