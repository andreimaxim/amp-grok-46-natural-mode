## What must be preserved

`connected_to_many` is a Base-only, block-scoped push of one stack entry `{ role:, shard:, prevent_writes:, klasses: }`. It does not switch global `ActiveRecord::Base`. Lookup walks `connected_to_stack` newest-first and applies an entry only when `klasses` includes `Base` or the model’s `connection_class_for_self`. A `nil` shard does not override an outer shard. `prevent_writes` defaults to `role == ActiveRecord.reading_role`. The stack lives in `ActiveSupport::IsolatedExecutionState[:active_record_connected_to_stack]`.

Order that matters for leak tests: flatten → reject bad receiver / `Base` in `klasses` → reject `role: reading, prevent_writes: false` → `append_to_connected_to_stack` (may raise `ShardSwapProhibitedError` *before* push) → `yield` → `ensure` pop. `append` is outside `begin`, so a rejected call must leave the stack untouched. Pop must run on return, `raise`, and `throw`.

Existing tests already pin: splat vs one array, reading defaulting `prevent_writes` on the named class only, the two `NotImplementedError` / `ArgumentError` rejects, two-class reading while a third stays on writing, and nested `connected_to_many` restoring the inner class. They do **not** pin flattening of nested arrays, explicit `prevent_writes` on writing, shard selection for two independent connection classes, nesting with `connected_to`, restore after `raise`/`throw`, or IsolatedExecutionState isolation.

## How to score a refactor

A preservation run fails if any of these fire:

- After any return/raise/throw/reject, any of `{Primary, Secondary, Tertiary}` disagrees with the pre-call `(role, shard, prevent_writes, db_config.name)` triple.
- `connected_to_stack.size` after the call is not the pre-call size (extra frame = leak; missing frame = popped an outer `connected_to`).
- A class not in `klasses` ever reports the inner role/shard, or its `create!` starts raising `ReadOnlyError`.
- A class in `klasses` with default or explicit `prevent_writes: true` successfully INSERTs.
- A writing class with `prevent_writes: false` raises `ReadOnlyError`.
- Another thread/fiber observes or mutates this context’s stack.
