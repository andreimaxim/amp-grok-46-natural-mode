## Assistant

`LookupContext` does not search the filesystem itself. It holds a mutable details hash, optionally interns that hash into a `DetailsKey` (`TemplateDetails::Requested`), and asks a `PathSet` of resolvers to return the matching template(s). Format and variant changes matter only after they have been turned into that requested-details object.

```diagram
┌─────────────────────┐
│ LookupContext       │
│ @details (mutable)  │
│ @cache (default on) │
└──────────┳──────────┘
           ┃ find / find_all
           ▼
┌─────────────────────┐
│ detail_args_for     │
│ details + details_key│
└──────────┳──────────┘
           ▼
┌─────────────────────┐
│ PathSet             │
│ prefix × resolver   │  first non-empty hit wins
└──────────┳──────────┘
           ▼
┌─────────────────────┐
│ FileSystemResolver  │
│ glob → UnboundTemplate│
│ rank by Requested   │
└──────────┳──────────┘
           ▼
     bind_locals(keys)
```

```text
LookupContext#find / #find_all / #find!
  normalize_name(name, prefixes)
  detail_args_for(options) → [details, details_key]
  PathSet#find / #find_all / #find!
    search_combinations(prefixes)
      FileSystemResolver#find / #find_all
        requested = details_key || TemplateDetails::Requested.new(**details)
        unbound_templates_for(..., cached: !!details_key)
        find_best_by_details  or  filter_and_sort_by_details
```

### What `#find` and `#find_all` actually pass down

[`LookupContext::ViewPaths#find`](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L145-L159) / `#find_all` / `#find!` share the same argument pipeline.

1. [`normalize_name`](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L231-L252) stringifies the name. A slash splits `"dir/name"` into prefix `dir` and name `name`. Existing prefixes become `"#{prefix}/dir"`. No slash and empty prefixes become `[""]`. A name containing `"."` is not rewritten here; the resolver later returns no files for it.
2. [`detail_args_for`](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L202-L211) is the empty-options fast path: `@details` plus the interned `details_key`. Non-empty `options` (the 5th argument to `#find`) merge into a new hash and intern a separate key. That merge does **not** run `formats=` or `variants=`.
3. The 4th argument `keys` is the locals list. It is not part of details and does not affect which file is chosen.
4. `partial` is forwarded unchanged. [`TemplatePath.virtual`](file:///home/user/workspace/repo/actionview/lib/action_view/template_path.rb#L17-L26) turns it into `prefix/_name`.

[`PathSet`](file:///home/user/workspace/repo/actionview/lib/action_view/path_set.rb#L40-L75) walks **prefixes outer, resolvers inner**. The first resolver+prefix that returns anything wins. Later prefixes and later view paths are not merged.

| Method | Observable result on miss | Observable result on hit |
|---|---|---|
| `#find` | `nil` | one bound `Template`, the best rank from that first resolver+prefix |
| `#find_all` | `[]` | every matching bound `Template` from that first resolver+prefix, sorted |
| `#find!` | [`ActionView::MissingTemplate`](file:///home/user/workspace/repo/actionview/lib/action_view/template/error.rb#L41-L67) | same as `#find` |

The missing-template message rewrites a partial path to `_foo` and lists `prefix/name` for every prefix. That is covered by [lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L260-L287).

### Mutable details versus the cache key

Registered details are `locale`, `formats`, `variants`, `handlers`. Accessors wrap each value in `Array(...)` or restore the default proc when the value is blank.

`@details` is a plain Hash. It is the live lookup configuration. [`DetailsKey.details_cache_key`](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L63-L73) interns a **different** object: `TemplateDetails::Requested`. That interned object is what the resolver uses as `key`.

```text
@details  →  mutable Hash on this LookupContext
details_key → interned TemplateDetails::Requested (identity-stable for equal hashes)
              only computed when @cache is true
```

[`_set_detail`](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L133-L138) copy-on-writes `@details` if a key or digest cache already exists, then nils both. That keeps the `Concurrent::Map` from being keyed by a Hash that is later mutated. Changing locale to `:da` and back to `:en` reuses the original `details_key` object ([lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L131-L150)).

`Requested` is not a copy of the array values. It is four index maps:

```ruby
[*requested_values, nil].each_with_index.to_h
```

Lower index wins. `nil` is always appended, so a file that omits locale, format, variant, or handler still matches, as the least-preferred candidate. [`variants: :any`](file:///home/user/workspace/repo/actionview/lib/action_view/template_details.rb#L8-L17) replaces the variant map with `ANY_HASH`: `nil => 0`, every other variant `=> 1`.

Format normalization inside `details_cache_key` is **not** the same as `formats=`:

- [`Template.validate_formats`](file:///home/user/workspace/repo/actionview/lib/action_view/template.rb#L204-L207) raises.
- [`Template.normalized_formats`](file:///home/user/workspace/repo/actionview/lib/action_view/template.rb#L210-L212) returns `formats & Types.symbols` only when the list is not already valid; otherwise `nil`, so the hash is left alone.

The setter validates. The cache-key path silently intersects.

### `formats=` edge cases (assignment, before any find)

[`formats=`](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L287-L303) is the only place that expands wildcards, validates, and injects the JS HTML fallback.

**`formats = [:js]`**  
The array becomes `[:js, :html]` and `@html_fallback_for_js` becomes `true`. Subsequent finds with empty options therefore request both formats, JS first. Test: [lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L64-L66).  
This fallback is **not** applied if you pass `formats: [:js]` as a `#find` option. `detail_args_for` merges that array as-is. `ActionView::Base#in_rendering_context` repeats the `[:js] << :html` rule only when `html_fallback_for_js` is not already set ([base.rb](file:///home/user/workspace/repo/actionview/lib/action_view/base.rb#L330-L335)).

**`formats = [:js, Mime::ALL]`**  
`Mime::ALL` is `"*/*"` ([mime_type.rb](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/http/mime_type.rb#L433-L447)). `values.delete "*/*"` removes it because `Mime::ALL == "*/*"`. Then `default_formats` (in a full Rails process, `Mime.symbols`) are concatenated and uniqued, preserving `:js` at the front. Observable formats: `[:js, *Mime.symbols].uniq`. Test: [lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L59-L61).  
`formats = ["*/*"]` alone becomes `Mime.symbols`.

**Invalid formats on the setter**  
`formats = [:html, :invalid, "also bad"]` raises `ArgumentError` with `Invalid formats: :invalid, "also bad"` **before** any resolver runs ([lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L68-L74)). No template set is produced.

Passing invalid formats through `#find` options does not go through `formats=`. With cache on, `Requested` is built from `formats & Types.symbols`. With cache off, the raw list is used as the index map. There is no test that this path raises.

`formats = nil` restores `default_formats` and reuses the original `details_key`.

### Locale and variant ordering

Ranking is always `[format, locale, variant, handler]` ([`TemplateDetails#rank_for` / `#sort_key_for`](file:///home/user/workspace/repo/actionview/lib/action_view/template_details.rb#L42-L62)). A template that fails any index lookup is dropped.

`#find` uses [`find_best_by_details`](file:///home/user/workspace/repo/actionview/lib/action_view/template/resolver.rb#L218-L232): one pass, keep the smallest rank. `#find_all` uses [`filter_and_sort_by_details`](file:///home/user/workspace/repo/actionview/lib/action_view/template/resolver.rb#L234-L246): filter then `sort_by` the same key.

Locale on the context is not a single symbol in `@details`. The getter returns `@details[:locale].first`. The setter writes `I18n.locale`, then stores the **fallback chain** from `default_locale`: current, I18n fallbacks if present, then `I18n.default_locale`, uniqued ([lookup_context.rb](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L46-L51)).

Observable sets from tests:

- Context locale `:en` vs `:da` on the fixture file set: `hello_world.erb` → `"Hello world!"`; `hello_world.da.html.erb` → `"Hey verden"` ([lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L100-L106)).
- Optional locale file plus generic file: `locale: [:en]` → only the generic template; `locale: [:fr]` → `[french, generic]`, and `en[0]` is the same object as `fr[1]` ([resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L123-L146), [fixture_resolver_test.rb](file:///home/user/workspace/repo/actionview/test/template/testing/fixture_resolver_test.rb#L31-L41)).
- Format order is the first sort key: `formats: [:json, :html]` returns JSON then HTML; reversed request reverses the array ([resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L149-L171)).
- Variant order is the third key. `find` with `{ variants: [:tricorder] }` vs `[:lcars]` returns different templates. `find_all` with `[:tricorder, :lcars]` vs the reverse returns those two templates in request order ([resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L187-L204)).
- `variants: []` matches only files with **no** `+variant`. `variants: :any` matches every variant, unvarianted files first ([fixture_resolver_test.rb](file:///home/user/workspace/repo/actionview/test/template/testing/fixture_resolver_test.rb#L44-L51)).
- Context `formats = [:html], variants = [:phone]` selects `hello_world.html+phone.erb` (`"Hello phone!"`). Switching formats to `[:text]` selects `hello_world.text+phone.erb` (`"Hello texty phone!"`) ([lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L109-L120)).

A file whose details are not in the request is omitted, not ranked last. Wrong format or handler → empty list ([resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L91-L99)).

Filename parsing is [`Resolver::PathParser`](file:///home/user/workspace/repo/actionview/lib/action_view/template/resolver.rb#L12-L46): `action(.locale)?(.format)?(+variant)?(.handler)?`. Unknown format symbols never parse as formats. A lookup name that already contains a dot (`"hello_world.html"`) makes [`unbound_templates_from_path`](file:///home/user/workspace/repo/actionview/lib/action_view/template/resolver.rb#L196-L199) return `[]` ([resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L229-L233)).

### Partial lookup

`partial: true` only changes the virtual path (`test/_foo`, not `test/foo`). Details, ranking, and locals binding are the same. Cache-key tests use `find("foo", %w(test), true)` against `_foo.erb` / `_foo.da.erb` and get `"Foo"` then `"Bar"` as locale changes ([lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L152-L176)). `#find!` with `partial: true` raises `Missing partial parent/_foo, child/_foo ...`.

### Locals do not select a file

Resolver matching is on virtual path + `TemplateDetails`. After a winner is chosen, [`UnboundTemplate#bind_locals`](file:///home/user/workspace/repo/actionview/lib/action_view/unbound_template.rb#L21-L34) builds or reuses a `Template`.

- Non-strict template: locals are sorted, frozen, and used as a bind cache key. `[:post]` and `[:post, :other]` are different bound templates; `[:other, :post]` reuses the latter ([file_system_resolver_test.rb](file:///home/user/workspace/repo/actionview/test/template/file_system_resolver_test.rb#L95-L107)).
- Strict locals (`<%# locals: (...) %>`): the first bind wins; later locals lists return that same object. `find_all(..., [:message])` and `find_all(..., [])` are `assert_same` ([resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L258-L267), [file_system_resolver_test.rb](file:///home/user/workspace/repo/actionview/test/template/file_system_resolver_test.rb#L111-L119)).
- Two different detail requests that pick the **same file** also return the same bound object when cache is on ([resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L117-L121)).

Locals never appear in `Requested` and never change rank.

### Cache on versus cache off

`LookupContext` starts with `@cache = true`. [`details_key`](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L118-L122) is `nil` when cache is off.

[`FileSystemResolver#unbound_templates_for`](file:///home/user/workspace/repo/actionview/lib/action_view/template/resolver.rb#L175-L181) treats `!!key` as “cached”:

| `LookupContext#cache` | `details_key` passed | Resolver glob cache | Bound `Template` identity |
|---|---|---|---|
| `true` (default) | interned `Requested` | `@unbound_templates.compute_if_absent(virtual_path)` | same object on repeat find |
| `disable_cache` | `nil` | recrawl every call | new object; existing glob cache is **not** cleared |
| after `disable_cache` returns | interned again | cached entry still there | original object again |

Tests: [lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L178-L191), [resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L101-L115).

The two caches are independent:

- **Details key cache**: intern `Requested` by details-hash value. Controls ranking input and whether the resolver considers the lookup cached.
- **Unbound template cache**: per virtual path, the globbed files. Controlled by whether a key was passed, not by whether details changed.
- **Bound template cache**: per locals list on an `UnboundTemplate`.

`disable_cache` only suppresses the first. It does not drop `@unbound_templates` and does not call `DetailsKey.clear`.

The generic `Resolver#find_all` (used by `NullResolver`) ignores `key` entirely and just calls `find_templates`. Caching behavior above is `FileSystemResolver` / `FixtureResolver` specifically.

That is the whole selection contract: mutate `@details` or merge find-options → intern a `Requested` only if caching → `PathSet` stops at the first resolver+prefix with matches → rank by format, locale, variant, handler → bind locals after the file is chosen.
