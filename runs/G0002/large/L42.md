`Rails::Application#config_for` is a small pipeline: resolve a YAML path, parse it (ERB then Psych), symbolize the whole document, pick `env` plus `shared`, optionally deep-merge, wrap a Hash in `ActiveSupport::OrderedOptions`, and return that value.

The public method is [`Rails::Application#config_for`](file:///home/user/workspace/repo/railties/lib/rails/application.rb#L292-L320). Parsing lives in nodoc [`ActiveSupport::ConfigurationFile`](file:///home/user/workspace/repo/activesupport/lib/active_support/configuration_file.rb). The contract is pinned in [`railties/test/application/configuration_test.rb`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2653-L2891), with parse-level behavior in [`activesupport/test/configuration_file_test.rb`](file:///home/user/workspace/repo/activesupport/test/configuration_file_test.rb).

```diagram
name / env:          config_for(:foo, env: Rails.env)
                          ┃
                     resolve path
                     Pathname? → as-is
                     else paths["config"].existent.first/name.yml
                          ┃
                     yaml.exist?
                     no ──▶ RuntimeError
                     yes
                          ┃
                     ConfigurationFile.parse
                     read file → optional ERB → YAML.unsafe_load(_file)
                     Psych::SyntaxError → FormatError
                     false/nil YAML → {}
                          ┃
                     Hash#deep_symbolize_keys   (whole document)
                          ┃
                     config  = all_configs[env.to_sym]
                     shared  = all_configs[:shared]
                          ┃
                     if shared
                       nil env + Hash shared → {} then deep_merge
                       both Hash → shared.deep_merge(config)
                       nil env, shared not Hash → config = shared
                       else leave env value (arrays, scalars)
                          ┃
                     Hash? → OrderedOptions.new.update(config)
                     else return as-is (Array, scalar, nil)
```

```text
config_for(name, env: Rails.env)
  resolve yaml path
  ActiveSupport::ConfigurationFile.parse(yaml)
    File.read
    ERB.new(content).result          # only if content includes "<%"
    YAML.unsafe_load_file | unsafe_load
  Hash#deep_symbolize_keys
  all_configs[env.to_sym], all_configs[:shared]
  Hash#deep_merge                    # both sides Hash
  ActiveSupport::OrderedOptions.new.update(config)  # Hash only
```

Most isolation tests go through [`set_custom_config`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L5502-L5510): write `config/custom.yml`, then `config.my_custom_config = config_for(...)` in the dummy app. A few call `Rails.application.config_for` after boot.

---

Path resolution

```292:293:railties/lib/rails/application.rb
    def config_for(name, env: Rails.env)
      yaml = name.is_a?(Pathname) ? name : Pathname.new("#{paths["config"].existent.first}/#{name}.yml")
```

A `Pathname` is the file. Anything else is interpolated as `#{config_dir}/#{name}.yml` — `:custom` and `"custom"` both become `config/custom.yml`. `paths["config"]` is added in [`Rails::Engine::Configuration`](file:///home/user/workspace/repo/railties/lib/rails/engine/configuration.rb#L95); [`existent`](file:///home/user/workspace/repo/railties/lib/rails/paths.rb#L220-L228) keeps only filesystem-existing entries and takes `.first`.

Intentional: Pathname bypass, established by [`config_for uses the Pathname object if it is provided`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2735-L2744).

Incidental: `.yml` is unconditional for non-Pathname names; `.yaml` is not a contract. `existent.first` rather than `root.join("config")` is path-set mechanics, not independently tested for `config_for`.

ERB, then YAML

[`ConfigurationFile#parse`](file:///home/user/workspace/repo/activesupport/lib/active_support/configuration_file.rb#L22-L34) does not take a binding from `config_for`. ERB runs only if the raw file contains `"<%"`:

```22:34:activesupport/lib/active_support/configuration_file.rb
    def parse(context: nil, **options)
      source = @content.include?("<%") ? render(context) : @content

      if source == @content
        YAML.unsafe_load_file(@content_path, **options) || {}
      else
        YAML.unsafe_load(source, **options) || {}
      end
    rescue Psych::SyntaxError => error
      raise FormatError, "YAML syntax error occurred while parsing #{@content_path}. " \
            "Please note that YAML must be consistently indented using spaces. Tabs are not allowed. " \
            "Error: #{error.message}"
    end
```

[`render`](file:///home/user/workspace/repo/activesupport/lib/active_support/configuration_file.rb#L47-L51) sets `erb.filename = @content_path` so ERB errors point at the YAML path ([`backtrace contains YAML path`](file:///home/user/workspace/repo/activesupport/test/configuration_file_test.rb#L6-L29)). No `context:` means `erb.result` uses the top-level binding.

Intentional, via `config_for`:

- ERB interpolation: [`config_for containing ERB tags should evaluate`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2820-L2829) (`<%= 'custom key' %>` → `"custom key"`).
- Psych syntax errors become `ActiveSupport::ConfigurationFile::FormatError` with `YAML syntax error occurred while parsing`: [`config_for with syntax error show a more descriptive exception`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2831-L2841), same wrapping in [`raises FormatError for malformed YAML`](file:///home/user/workspace/repo/activesupport/test/configuration_file_test.rb#L42-L52).

Incidental to the `config_for` return-value contract:

- `unsafe_load` / `unsafe_load_file` (aliases, Psych types) rather than `safe_load`.
- Skip ERB unless `"<%"` is present; then `unsafe_load_file` vs `unsafe_load`.
- Invisible `\u00A0` warning in [`read`](file:///home/user/workspace/repo/activesupport/lib/active_support/configuration_file.rb#L37-L45).
- `parse` accepting `context:` and `**options` that `config_for` never passes.

Raw YAML without ERB keeps string keys at this layer ([`load raw YAML`](file:///home/user/workspace/repo/activesupport/test/configuration_file_test.rb#L31-L39)). Symbolization is the next step.

Symbolized access, and parsers that reject `symbolize_names`

```296:296:railties/lib/rails/application.rb
        all_configs    = ActiveSupport::ConfigurationFile.parse(yaml).deep_symbolize_keys
```

`config_for` does not pass `symbolize_names:` into Psych. [`Hash#deep_symbolize_keys`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/hash/keys.rb#L116-L118) walks hashes and arrays after parse (`key.to_sym rescue key`). That is the compatibility mechanism for YAML engines that cannot take `symbolize_names`.

[`config_for handles YAML patches (like safe_yaml) that disable the symbolize_names option`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2856-L2867) asserts the document still comes back as `{ key: "value" }`. The `YAML.stub :load` in that test does not intercept today’s `unsafe_load_file` path; the assertion still holds because `deep_symbolize_keys` runs on the Hash parse actually returns. The stub is leftover mechanics. The contract is: string keys from YAML become symbols without asking the parser to symbolize.

Top-level Hash results are then copied into `OrderedOptions`, whose [`[]` / `[]=`](file:///home/user/workspace/repo/activesupport/lib/active_support/ordered_options.rb#L37-L44) call `key.to_sym`. That is why [`config_for loads custom configuration from YAML accessible as symbol or string`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2653-L2663) can use both `[:foo]` and `["foo"]` at the root.

Nested hashes are not wrapped. [`config_for loads nested custom configuration from YAML as symbol keys`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2665-L2676) only exercises `[:foo][:bar][:baz]`. Nested string keys are not a tested contract. Rails 6.0 deprecated non-symbol access; the [6.0→6.1 upgrade guide](file:///home/user/workspace/repo/guides/source/upgrading_ruby_on_rails.md#L885-L905) documents that nested hashes are symbol-keyed. `guides/source/configuring.md` still shows `payment["merchant_id"]`, which happens to work only because the root is `OrderedOptions`.

[`config_for makes all hash methods available`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2678-L2695) is the Hash subclass contract: `#keys`, `#values`, `#to_h`, Hash equality. Nested values in that test remain plain hashes (`{ baz: 1 }`), not `OrderedOptions`.

[`config_for returns an ActiveSupport::OrderedOptions`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2869-L2889) is the method-access contract: `config.some_key` after `OrderedOptions.new.update(config)`.

Intentional: document-wide symbolize, root `OrderedOptions` (method + string/symbol `[]`), Hash API on the root. Incidental: `OrderedOptions` wrapping is root-only; nested hashes stay `Hash`.

`shared`, deep overrides, missing env

```297:307:railties/lib/rails/application.rb
        config, shared = all_configs[env.to_sym], all_configs[:shared]

        if shared
          config = {} if config.nil? && shared.is_a?(Hash)
          if config.is_a?(Hash) && shared.is_a?(Hash)
            config = shared.deep_merge(config)
          elsif config.nil?
            config = shared
          end
        end
```

`shared` is truthy, not “present as a key”. Both Hash → [`shared.deep_merge(config)`](file:///home/user/workspace/repo/activesupport/lib/active_support/deep_mergeable.rb#L34-L51): shared is the base, env wins on conflict, nested hashes merge, non-hashes are replaced.

Established:

| Behavior | Source branch | Test |
|---|---|---|
| Env hash overrides shared scalar | `shared.deep_merge(config)` | [`shared config is overridden`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2769-L2780) (`:from_env` beats `:from_shared`) |
| Nested hashes merge, env adds keys | same | [`merges shared configuration deeply`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2795-L2810) and the method docstring (`baz: 1` + `qux: 2`) |
| Missing env, shared Hash | `config = {}` then `deep_merge` | [`shared config is returned when environment is missing`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2782-L2793); also OrderedOptions test `env: :test` with empty `test:` → `"default"` |
| Missing env, no shared | `config` stays `nil`, skip wrap | [`without the environment configured returns nil`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2758-L2767) |

The `config = {} if config.nil? && shared.is_a?(Hash)` line forces the deep-merge path so a missing env with a Hash `shared` is a merged copy, not a special case. `YAML` `test:` with no value is `nil`, so it is the same as a missing env key.

`if shared` is a truthiness check. `shared: false` / `shared: ~` / empty `shared:` do not enter the merge. That is incidental; tests only use non-empty shared hashes or arrays.

---

Scalar and array roots

Wrapping is only `if config.is_a?(Hash)`. Arrays and other non-Hashes return as parsed.

- Env root array: [`does not assume config is a hash`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2697-L2707) → `%w(foo bar)`.
- Only `shared:` as an array, env missing: `elsif config.nil?; config = shared` → [`works with only a shared root array`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2709-L2719).
- Both env and shared are arrays: neither is Hash, env is not nil, shared is ignored → [`returns only the env array when shared is an array`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2721-L2733). Arrays are not concatenated.

A non-Hash env with a Hash shared also skips merge (first branch requires both Hash). Not separately tested; it follows the same predicates.

A YAML *document* that is not a Hash would fail at `.deep_symbolize_keys`. `config_for` assumes a Hash of env names. That is an implicit input shape, not a return-value test.

---

Empty file, missing file

Empty file: Psych `unsafe_load_file` falls back to `false`; parse does `|| {}`; `{}[:development]` and `{}[:shared]` are nil; no wrap; return nil. [`config_for with empty file returns nil`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2812-L2818). Comment-only files also load as `false` in Psych; that is parse mechanics, not a `config_for` test.

Missing file: no parse, `raise "Could not load configuration. No such file - #{yaml}"` (a `RuntimeError`). [`config_for raises an exception if the file does not exist`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2746-L2756) asserts that exact message including the resolved path.

What is the contract vs the machinery

Documented / tested return-value contract:

1. Load `config/<name>.yml` for `Rails.env`, or a Pathname, or `env:`.
2. Evaluate ERB in that file.
3. Require the file to exist; otherwise that RuntimeError.
4. Empty file or absent env without usable `shared` → `nil`.
5. Hash result → `ActiveSupport::OrderedOptions` with symbol keys, Hash methods, root string/symbol/`#some_key` access.
6. `shared` Hash deep-merges under the env Hash; env wins; missing env yields shared.
7. Non-Hash env values (arrays) are returned unchanged; a shared array is used only when env is nil; two arrays do not merge.
8. Symbolization does not depend on Psych/`symbolize_names`.
9. YAML syntax errors are `ConfigurationFile::FormatError`.

Implementation details that produce those results but are not themselves the contract: `unsafe_load*`, `"<%"` ERB gate, `|| {}` on false/nil YAML, `env.to_sym` after whole-document `deep_symbolize_keys`, `if shared` truthiness, root-only `OrderedOptions`, `deep_merge` dup behavior, `paths["config"].existent.first`.
