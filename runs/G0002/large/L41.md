## Who owns the queue

A mailer class has two inheritable settings: `delivery_job` (default `ActionMailer::MailDeliveryJob`) and `deliver_later_queue_name` (default `:mailers`). They are `class_attribute`s, so a subclass can change either without changing the parent.

- [actionmailer/lib/action_mailer/queued_delivery.rb](file:///home/user/workspace/repo/actionmailer/lib/action_mailer/queued_delivery.rb#L3-L11)
- [actionmailer/test/message_delivery_test.rb](file:///home/user/workspace/repo/actionmailer/test/message_delivery_test.rb#L119-L128) (subclass `:throttled_mailers` leaves `ActionMailer::Base` at `:mailers`)
- [actionmailer/test/mailers/delayed_mailer.rb](file:///home/user/workspace/repo/actionmailer/test/mailers/delayed_mailer.rb#L5-L6)

Public docs state the split of ownership:

- With the **default delivery job**, the mailer’s `deliver_later_queue_name` is the queue.
- With a **custom `delivery_job`**, that job’s queue is the queue. The mailer’s `deliver_later_queue_name` does not apply.

That is stated in [actionmailer/lib/action_mailer/message_delivery.rb](file:///home/user/workspace/repo/actionmailer/lib/action_mailer/message_delivery.rb#L90-L105), [actionmailer/lib/action_mailer/base.rb](file:///home/user/workspace/repo/actionmailer/lib/action_mailer/base.rb#L472-L476), and [guides/source/configuring.md](file:///home/user/workspace/repo/guides/source/configuring.md#L3086-L3104).

The default job reads the mailer from the first job argument and uses that class’s `deliver_later_queue_name`:

```13:17:actionmailer/lib/action_mailer/mail_delivery_job.rb
    queue_as do
      mailer_class = arguments.first.constantize
      mailer_class.deliver_later_queue_name
    end
```

A custom job that sets its own `queue_as` replaces that. Tests encode both: [CustomQueueMailer](file:///home/user/workspace/repo/actionmailer/test/test_helper_test.rb#L49-L51) uses `deliver_later_queue_name = :custom_queue`; [CustomQueueDeliveryMailer](file:///home/user/workspace/repo/actionmailer/test/test_helper_test.rb#L41-L47) uses a job with `queue_as :delivery_job_queue`.

## Symbol / string / nil, and prefixes

Active Job turns a queue “part” into the name it stores:

- `nil` (or omitted part) becomes `ActiveJob::Base.default_queue_name` (`"default"` unless the app changed it).
- A prefix, if set, is joined in front with `queue_name_delimiter` (default `_`).
- The result is a frozen string (`Array#join` stringifies a symbol).

- [activejob/lib/active_job/queue_name.rb](file:///home/user/workspace/repo/activejob/lib/active_job/queue_name.rb#L39-L65)
- [activejob/lib/active_job/core.rb](file:///home/user/workspace/repo/activejob/lib/active_job/core.rb#L175-L181) (`set(queue:)` only applies when `options[:queue]` is present and truthy)

So for the **default delivery job**:

| Mailer setting | Enqueued queue name (no prefix) |
|---|---|
| unset / `:mailers` | `"mailers"` |
| `"sample_mailer_queue_name"` | `"sample_mailer_queue_name"` |
| `nil` | Active Job’s default queue name (`"default"` unless configured otherwise) |
| `deliver_later(queue: :another_queue)` | `"another_queue"` (call option wins) |

Tests that encode this: [message_delivery_test.rb](file:///home/user/workspace/repo/actionmailer/test/message_delivery_test.rb#L94-L117) (class queue `"delayed_mailers"`, override `"another_queue"`), [test_helper_test.rb](file:///home/user/workspace/repo/actionmailer/test/test_helper_test.rb#L339-L400) (`nil`, string, symbol, prefix, custom mailer queue).

App-level default depends on `load_defaults`: original default `:mailers`; from 6.1, `nil` (Active Job default queue). Apps can still set `config.action_mailer.deliver_later_queue_name`.

- [railties/lib/rails/application/configuration.rb](file:///home/user/workspace/repo/railties/lib/rails/application/configuration.rb#L204-L220)

## How tests select those queues

`deliver_enqueued_emails(queue:, at:)` performs only jobs whose class is some loaded mailer’s `delivery_job`. If `queue:` is given, only those jobs. If `at:` is given, only jobs with no run-at time or a run-at time at or before that time.

- [actionmailer/lib/action_mailer/test_helper.rb](file:///home/user/workspace/repo/actionmailer/lib/action_mailer/test_helper.rb#L186-L253)
- Tests: no filter delivers the mail ([604-614](file:///home/user/workspace/repo/actionmailer/test/test_helper_test.rb#L604-L614)); `queue:` of one mailer leaves the other enqueued ([616-628](file:///home/user/workspace/repo/actionmailer/test/test_helper_test.rb#L616-L628)); `at:` delivers immediate mail and leaves later mail ([630-638](file:///home/user/workspace/repo/actionmailer/test/test_helper_test.rb#L630-L638))

Queue matching in the test adapter and job list is **string equality after `queue.to_s`**:

- Adapter, while a block is running: `job.queue_name != queue.to_s` ([test_adapter.rb](file:///home/user/workspace/repo/activejob/lib/active_job/queue_adapters/test_adapter.rb#L68-L71))
- After the fact (no block / flush): `queue.to_s == job.fetch(:queue, …)` ([activejob/lib/active_job/test_helper.rb](file:///home/user/workspace/repo/activejob/lib/active_job/test_helper.rb#L685-L700))

`assert_enqueued_email_with` infers the queue from `mailer.delivery_job.new(mailer.name).queue_name` unless the caller passes `queue:`, then compares with `queue.to_s`. Active Job also stringifies a symbol expected queue.

- [actionmailer/lib/action_mailer/test_helper.rb](file:///home/user/workspace/repo/actionmailer/lib/action_mailer/test_helper.rb#L148-L165)
- [activejob/lib/active_job/test_helper.rb](file:///home/user/workspace/repo/activejob/lib/active_job/test_helper.rb#L730-L734)

So in the **test adapter**, `:custom_queue` and `"custom_queue"` select the same jobs. Production adapters are not required to do that. They receive `job.queue_name` as Active Job computed it (a string after `queue_name_from_part`). Guides warn that if the adapter is not processing that queue, delivery jobs may be silently ignored ([configuring.md](file:///home/user/workspace/repo/guides/source/configuring.md#L3102-L3104)).

`delivery_job_filter` only sees mailer classes already loaded as descendants of `ActionMailer::Base` ([test_helper.rb](file:///home/user/workspace/repo/actionmailer/lib/action_mailer/test_helper.rb#L248-L253)). An unloaded mailer is outside this contract.

# Product shaping brief

This is a first draft of the desired product behavior. It is not an implementation plan. Correct the problem frame if the pain is different.

## Problem frame

**Actor:** An application team that sends mail through `deliver_later` and checks that behavior with Action Mailer’s test helpers.

**Situation:** They split mail across queues (urgent vs bulk, internal vs external, a custom delivery job, a one-off `queue:` on the call). They need tests to deliver or assert **that** mail, not every enqueued mail.

**Pain today:** The knobs exist (`deliver_later_queue_name`, `deliver_later(queue:)`, custom `delivery_job`, `deliver_enqueued_emails(queue:)`, `at:`), but which name actually landed on the job is easy to misread. Symbol vs string, `nil` meaning “Active Job default,” a subclass vs the parent, a custom job ignoring the mailer setting, a prefix, and an adapter that rewrites names all change the name people must use to select mail. Tests then deliver the wrong mail, skip the mail under test, or pass while production workers listen on a different queue.

**Why it matters:** Queue splits are how teams keep MFA / receipt mail from sitting behind bulk mail. If tests cannot target the same queue the app uses, the split is untrustworthy.

**Hypothesis (not supplied by you):** appetite is a bounded reliability fix — same knobs, selection and assertion match the queue the job actually used — not a new queue API.

## Desired outcome

A person who names a queue on a mailer, on a `deliver_later` call, or on a custom delivery job can later **select** that mail in tests and **see** it delivered or still waiting, using the name they already use for that queue.

Concretely, after this work:

1. Naming a queue on a mailer, on the call, or on a custom delivery job has one meaning for enqueue and for test selection.
2. Writing that name as a symbol or as a string does not change which mail is selected.
3. Setting the mailer queue to `nil` is the Active Job default queue, and tests can select that mail the same way.
4. Several mailers in one test stay isolated when the tester asks for one queue.
5. Parameterized mail and scheduled mail follow the same queue rules as ordinary mail.
6. If a backend rewrites queue names (prefix, stringify, case), test selection still hits the mail that backend would process for the name the team used.

## Appetite

**Hypothesis:** small-to-medium. Keep the existing ways to name a queue. Make targeting and test selection agree. Do not add a new queue model.

If the real appetite is “document current behavior only” or “change defaults again,” the outcomes above are the wrong work.

## Scope

In:

- Delayed delivery via `deliver_later` / `deliver_later!` and the test helper that performs those jobs (`deliver_enqueued_emails`), including its `queue:` and `at:` filters.
- Mailer-level queue name, per-call `queue:`, custom delivery jobs, inheritance, parameterized mail, and mixed mailers in one test.
- The name teams use in tests vs the name the job carried after symbol/string/`nil` handling and after adapter-visible normalization.

Out of this brief’s “must change” set unless you expand it: `assert_enqueued_email_with` is already the assertion twin of the same names; keep it consistent with whatever selection rule we lock, but it is not a separate product.

## Non-goals

- New ways to send mail, new adapters, or changing SMTP / `deliver_now`.
- Changing the historical defaults (`:mailers` vs `nil` under `load_defaults`).
- Redesigning Active Job queues, priorities, or `wait` / `wait_until`.
- Making unloaded mailer classes visible to the test helper.
- Allowing `deliver_later` after the message was already built (that remains disallowed).
- Guaranteeing delivery if production workers are not listening on the named queue (the guide warning stays).

## Risks

- **Silent over-delivery in tests.** If selection becomes looser (e.g. treating every adapter spelling as equal), a filter can send mail the tester meant to leave queued.
- **Silent under-delivery.** If selection stays exact-string and adapters rewrite names, tests miss mail that production would send.
- **Custom jobs.** Teams who set `queue_as` on a delivery job expect the mailer setting to be ignored. If we “help” by applying `deliver_later_queue_name` anyway, their production queue changes.
- **`nil` vs `"mailers"`. ** Apps on 6.1+ defaults already share the Active Job default queue. Teaching tests a special `mailers` name would deselect their mail.
- **Prefixes.** A test that passes `:mailers` while the app has `queue_name_prefix` is naming a queue that was never enqueued.
- **Wrong-problem risk.** If the real incidents are “workers not subscribed to `mailers`,” matching names in tests will not fix production.

**Steering evidence**

- Success: a tester who copies the queue name from the mailer, the `deliver_later` call, or the custom job can deliver only that mail; leftover mail from other mailers stays enqueued; scheduled mail past `at:` stays enqueued.
- Investigate: tests pass with a queue filter, but a production adapter’s dashboard shows a different queue spelling for the same mail.
- Reconsider the frame: teams still miss mail because workers are not subscribed, not because tests selected the wrong jobs.

## Acceptance examples

Required unless marked illustrative.

**1. Two mailers, one filter (core)**  
Customer mail is configured for `external_mailers`. Employee mail is configured for `internal_mailers`. In one test both are delayed. The tester asks to deliver only `external_mailers`. Customer mail is sent. Employee mail is still waiting.

**2. Per-call override**  
A mailer’s usual queue is `mailers`. This call uses `deliver_later(queue: :another_queue)`. A filter for `another_queue` sends that mail. A filter for `mailers` does not.

**3. Symbol and string are the same target**  
The mailer is set with `:custom_queue`. The tester filters with `"custom_queue"` (or the reverse). That mail is sent. A different spelling (`custom-queue`, `CustomQueue`) is a different queue.

**4. `nil` means the Active Job default**  
The mailer’s delayed-delivery queue is `nil`. Delayed mail lands on the app’s Active Job default queue. A test that selects that default queue delivers it. A test that selects `"mailers"` does not, unless that default is actually `"mailers"`.

**5. Inheritance**  
A child mailer sets its own delayed-delivery queue. The parent’s queue is unchanged. Filtering on the child’s queue sends only the child’s mail.

**6. Custom delivery job owns the queue**  
A mailer uses a custom delivery job that names `delivery_job_queue`. Delayed mail from that mailer is on `delivery_job_queue`, not on the mailer’s `deliver_later_queue_name`. Filters and assertions use `delivery_job_queue`. The tester can still override with `deliver_later(queue:)`.

**7. Parameterized mail**  
`SomeMailer.with(…).welcome.deliver_later` uses the same queue rules as `SomeMailer.welcome.deliver_later`. A queue filter that would send the ordinary mail sends the parameterized mail too.

**8. Scheduled mail**  
One mail is delayed immediately. Another is delayed for two hours. The tester delivers delayed mail due by one hour from now. Only the immediate mail is sent. The two-hour mail is still waiting. Both still obey `queue:` when it is also passed.

**9. Adapter-normalized names**  
Illustrative until we confirm a backend in scope. A backend stores Active Job’s `"mailers"` as its own spelling (for example a stringified symbol or a prefixed name the app already configured). The tester still identifies that mail with the name they configured on the mailer or call. They do not have to know the backend’s private spelling. If the backend’s rewrite is an app-level prefix, the configured prefix is part of the public name, not a hidden alias.

**10. Counterexample: other jobs**  
A non-mail job sits on `external_mailers`. `deliver_enqueued_emails(queue: :external_mailers)` sends delayed **mail** on that queue, not the unrelated job.

**11. Counterexample: no filter**  
Several mailers delay mail on several queues. `deliver_enqueued_emails` with no `queue:` sends all of that delayed mail (still only mail delivery jobs).
