# What must be preserved

`connected_to_many` is a Base-only, block-scoped push of one stack entry `{ role:, shard:, prevent_writes:, klasses: }`. It does not switch global `ActiveRecord::Base`. Lookup walks `connected_to_stack` newest-first and applies an entry only when `klasses` includes `Base` or the model’s `connection_class_for_self`. A `nil` shard does not override an outer shard. `prevent_writes` defaults to `role == ActiveRecord.reading_role`. The stack lives in `ActiveSupport::IsolatedExecutionState[:active_record_connected_to_stack]`.

Order that matters for leak tests: flatten → reject bad receiver / `Base` in `klasses` → reject `role: reading, prevent_writes: false` → `append_to_connected_to_stack` (may raise `ShardSwapProhibitedError` *before* push) → `yield` → `ensure` pop. `append` is outside `begin`, so a rejected call must leave the stack untouched. Pop must run on return, `raise`, and `throw`.

Existing tests already pin: splat vs one array, reading defaulting `prevent_writes` on the named class only, the two `NotImplementedError` / `ArgumentError` rejects, two-class reading while a third stays on writing, and nested `connected_to_many` restoring the inner class. They do **not** pin flattening of nested arrays, explicit `prevent_writes` on writing, shard selection for two independent connection classes, nesting with `connected_to`, restore after `raise`/`throw`, or IsolatedExecutionState isolation.

# Shared fixture and instrumentation

Reuse the three-base pattern from `ConnectionSwappingNestedTest` (`PrimaryBase` / `SecondaryBase` / `TertiaryBase`, each `connects_to` its own writing/reading/shards). Keep `use_transactional_tests = false`. Skip physical multi-DB pool assertions when `in_memory_db?`; role/stack assertions can still run against `:arunit` as in `base_test.rb`.

Snapshot **before** the call and assert equality **after** every path (success, reject, raise, throw, nested exit):

- `ActiveRecord::Base.connected_to_stack` — size, and for the top entry `:role`, `:shard`, `:prevent_writes`, `:klasses` (identity of the class list, not a mutated caller array).
- Per class: `current_role`, `current_shard`, `current_preventing_writes`, `connected_to?(role:, shard:)`.
- `connection_pool.db_config.name` for each connection class (which physical pool).
- `lease_connection.preventing_writes?` (adapter-visible flag; this is what blocks SQL).

Write probes (the leak/accident oracle):

- On a class that should be readonly: `Model.create!` / `update!` must raise `ActiveRecord::ReadOnlyError` matching `/\AWrite query attempted while in readonly mode: INSERT /`.
- On a class that should still write (unrelated model, or `prevent_writes: false` on writing): the same `create!` must succeed, then delete the row in `ensure`.
- Do not treat `current_preventing_writes` alone as proof of write safety; always hit the adapter.

Do not inspect internals beyond the stack snapshot. Do not call `connected_to_stack.pop` in test `ensure` unless the case is a rejected call that must not have pushed.

# Test matrix

Each row is one focused test. “Detects” is the refactor failure it is for.

**1. Flatten nested class arguments**
Call `connected_to_many([SecondaryBase, [TertiaryBase]], role: :reading)` and the splat form `connected_to_many(SecondaryBase, TertiaryBase, role: :reading)`.
Observables: both produce the same top stack entry `klasses: [SecondaryBase, TertiaryBase]`; both classes `connected_to?(role: :reading)`; `PrimaryBase` unchanged; caller arrays not mutated (`classes.flatten` not `flatten!`).
Detects: dropping `flatten`, mutating the caller, wrapping klasses as nested arrays so lookup misses.

**2. Two independent connection classes switch role+shard; unrelated stays**
Outer: `ActiveRecord::Base.connected_to(role: :writing, shard: :default)`. Inner: `connected_to_many(SecondaryBase, TertiaryBase, role: :reading, shard: :shard_one)`.
Observables inside: Secondary/Tertiary pools are `*_shard_one_replica`, `current_preventing_writes == true`; Primary pool still `"primary"`, writing, `preventing_writes == false`. Write probe: Secondary/Tertiary `create!` raise `ReadOnlyError`; Primary (or a Primary model) `create!` succeeds.
Detects: applying the entry to `Base`, sharing one connection class, or swapping shard globally.

**3. `shard: nil` does not override an outer shard**
Outer `connected_to`/`connected_to_many` with `shard: :shard_one` on Secondary. Inner `connected_to_many(SecondaryBase, role: :reading)` with shard omitted.
Observables: Secondary `current_role == :reading` and `current_shard == :shard_one` (nil shard is skipped in lookup); Primary shard still `:default`.
Detects: treating missing shard as `:default`, or writing `shard: shard` into lookup without the `hash[:shard]` truthiness check.

**4. Default `prevent_writes` from role**
`role: :reading` → Secondary `current_preventing_writes` and `lease_connection.preventing_writes?` true; Primary false.
`role: :writing` → both false; Secondary `create!` succeeds.
Detects: hard-coding `prevent_writes: true`, or coupling the flag to Base.

**5. Explicit `prevent_writes` on writing**
`connected_to_many(SecondaryBase, TertiaryBase, role: :writing, prevent_writes: true)`.
Observables: `current_role == :writing` but both named classes prevent writes; Primary still writes. Write probe: Secondary/Tertiary INSERT raise; Primary INSERT succeeds.
Detects: ignoring the keyword, or tying prevent_writes solely to `reading_role`.

**6. Reject `role: :reading, prevent_writes: false` without mutating state**
Snapshot stack, then `assert_raises(ArgumentError)` with message `"cannot set \`prevent_writes\` to false when \`role\` is \`reading\`."` for both splat and array forms, with and without a block if the raise happens before `yield`.
Observables after: stack size/contents identical to snapshot; no class changed role/shard/prevent_writes.
Detects: validating after push, or `ensure` pop on a path that never pushed (would pop an outer entry — a leak in the other direction).

**7. Non-Base receiver**
`SecondAbstractClass.connected_to_many([SecondAbstractClass], role: :writing)` and the same with a block.
Observables: `NotImplementedError`, message `"connected_to_many can only be called on ActiveRecord::Base."`; stack unchanged. Do not yield.
Detects: moving the method to connection classes, or checking `abstract_class?` instead of `self == Base`.

**8. `klasses` includes `ActiveRecord::Base`**
`connected_to_many([ActiveRecord::Base], role: :writing)`, `connected_to_many(ActiveRecord::Base, SecondaryBase, role: :reading)`, and flattened `[[ActiveRecord::Base]]`.
Observables: same `NotImplementedError` / message; stack unchanged; flatten happens *before* the include check so nested Base still rejects.
Detects: only checking `self`, or checking include before flatten.

**9. Nesting with `connected_to`**
Sequence: Base `connected_to(role: :writing, shard: :default)` → `connected_to_many(SecondaryBase, TertiaryBase, role: :reading, shard: :shard_one)` → `SecondaryBase.connected_to(role: :writing)` (no shard) → inner `connected_to_many(TertiaryBase, role: :writing, shard: :default)`.
Observables at each depth, then after each exit:
- After Secondary `connected_to`: Secondary writing on `shard_one` (nil shard does not clobber), Tertiary still reading/`shard_one`, Primary writing/default.
- After inner `connected_to_many`: Tertiary writing/default; Secondary still writing/`shard_one`.
- After each block: exact restore of the outer triple (role, shard, prevent_writes, pool name) for all three classes.
Write probes at the reading depths.
Detects: one shared stack key, popping more than one frame, or `connected_to`’s `klasses: [self]` being replaced by a many-entry.

**10. Restore after normal return**
Capture stack dup and the three-class triple before the call. Inside, assert the switch. After, `assert_equal` the snapshot. Also assert the block’s return value is yielded unchanged (`connected_to_many` does not `Relation#load`, unlike `connected_to` / `with_role_and_shard`).
Detects: missing pop, popping twice, or unifying with `with_role_and_shard` and auto-loading.

**11. Restore after `raise`**
Inside the block, after asserting the switch, `raise RuntimeError`. `assert_raises` outside. Then snapshot equality for stack + all three classes, including that Primary never picked up reading/prevent_writes.
Detects: `rescue` instead of `ensure`, or pop only on the success path.

**12. Restore after `throw`**
`catch :done` around `connected_to_many(...) { assert switch; throw :done }`. After catch: same snapshot equality. This is the case `ensure` covers and `rescue` does not.
Detects: wrapping yield in `rescue Exception` without pop, or using a helper that does not run on `throw`.

**13. Concurrent IsolatedExecutionState isolation**
Default `isolation_level` is `:thread`. Parent enters `connected_to_many(SecondaryBase, TertiaryBase, role: :reading)` and waits on a latch. Child `Thread.new` snapshots its own stack and the three-class triple, then itself calls `connected_to_many(SecondaryBase, role: :writing, prevent_writes: true)` and probes writes.
Observables: child starts from empty/default stack (does not see parent’s reading); parent remains reading while child is writing+prevent_writes; after both join/exit, parent snapshot restored and child did not leave entries on the parent stack. Write probe on parent thread still readonly for Secondary; child’s prevent_writes does not leak.
If the harness already toggles `ActiveSupport::IsolatedExecutionState.isolation_level` (as `connection_pool_test` does), repeat with `:fiber`: parent Fiber vs child Fiber must not share the stack; two `Fiber.yield`s on the *same* fiber must still see the same stack. Save/restore `isolation_level` around the test. Do not require a fiber case when the suite never sets `:fiber`.
Detects: class-level `@@stack`, a process-global array, or pushing onto a shared `Concurrent::Array` that other contexts can see.

**14. Rejected shard swap does not pop an outer frame** *(leak-adjacent; keep if the refactor touches `append_to_connected_to_stack`)*
`PrimaryBase.prohibit_shard_swapping` then `connected_to_many([PrimaryBase], shard: :shard_two, role: :writing)`.
Observables: `ShardSwapProhibitedError`; outer Primary shard unchanged; stack size unchanged. This guards the “append is outside `begin`” ordering.

# How to score a refactor

A preservation run fails if any of these fire:

- After any return/raise/throw/reject, any of `{Primary, Secondary, Tertiary}` disagrees with the pre-call `(role, shard, prevent_writes, db_config.name)` triple.
- `connected_to_stack.size` after the call is not the pre-call size (extra frame = leak; missing frame = popped an outer `connected_to`).
- A class not in `klasses` ever reports the inner role/shard, or its `create!` starts raising `ReadOnlyError`.
- A class in `klasses` with default or explicit `prevent_writes: true` successfully INSERTs.
- A writing class with `prevent_writes: false` raises `ReadOnlyError`.
- Another thread/fiber observes or mutates this context’s stack.

Run the new cases next to the existing `base_test` and `test_connected_to_many` examples; passing the old tests is necessary and not sufficient for the restore/`throw`/isolation holes.
