Verification should treat `send_stream` as a public streaming contract: headers, chunks, close, notifications, and Live process exceptions. Do not pin private helper order.

Current `send_stream` is a thin public wrapper. Live still owns commit, the worker thread, disconnect, and after-commit errors.

```text
GET action
  Live#process
    copy Thread locals + IsolatedExecutionState
    post Concurrent::CachedThreadPool ("action_controller.live")
      IsolatedExecutionState.share_with(except: live_streaming_excluded_keys)
        super(action)
          send_stream
            Notifications.instrument("send_stream.action_controller")
              set Content-Type
              set Content-Disposition
              yield response.stream   # Live::Buffer
            ensure stream.close       # outside the instrument block
      rescue: committed? → after-commit path; else stash error
      ensure: commit!
    await_commit
    raise stashed error if any
```

`Live::Buffer#write` commits on first write (`Cache-Control: no-cache`, drop `Content-Length`). `#close` commits if needed and enqueues a terminator. `#abort` (Rack client disconnect) marks disconnected and wakes a blocked reader. `ignore_disconnect` only changes the next `write` after abort.

## Exception before commit

Commit happens on first `Buffer#write` or on `close`. `send_stream` always `close`s in `ensure`, so an exception inside the yielded block still commits before `Live#process` sees it.

That is the contract to preserve:

```text
raise in send_stream block
  instrument records :exception / :exception_object, re-raises
  ensure close → commit, stream closed
  Live#process rescue sees committed? == true
    does not stash/re-raise to the test thread
    after-commit path: HTML completion write, on_error, log, close
```

| Check | Seam | Assertion |
|---|---|---|
| Raise in the block before any write | New action: `send_stream(...) { raise }` with no `write` | `get` does **not** raise; `assert_stream_closed`; body empty (HTML completion write hits a closed stream and is swallowed); logs contain the original exception; for HTML, logs also contain `IOError` / `"closed stream"` from the failed completion write |
| Raise in the action before `send_stream` | Existing `exception_in_controller` / `bad_request_error` | `get` **does** raise; response was not streamed; this is the only true uncommitted path |

Do not assert private `error = e` assignment. Assert whether `get` raises, whether the stream is closed, and log text via `capture_log_output`.

Cleanup: restore logger; do not leave a reader blocked — there are no chunks.

| Check | Seam | Assertion |

| Raise after write, HTML | Same action, default HTML format | Body is `"partial"` plus `ActionView::Base.streaming_completion_on_exception` **only if** the stream is still open when Live writes it. Today `send_stream` already closed it, so completion is **not** appended and the failed write is logged. Preserve that. |
| `on_error` after commit | Existing `exception_with_callback` is the Live seam; optional send_stream twin that sets `response.stream.on_error` then writes then raises | Callback body appears only if it runs before `send_stream` ensure close. If the callback is registered inside the block after write, `send_stream` close still runs on the way out. Assert actual body + closed stream, not callback invocation count. |

`test_exception_in_view_after_commit` is the non-send_stream analog (`write ""` then missing template). Use it as the oracle for log + `assert_stream_closed`, not as a private-call template.

## Client disconnect

Disconnect is `RackBody#close` → `Response#abort` → `Buffer#abort`, not `stream.close`. Next `write` either raises `ActionController::Live::ClientDisconnected` or discards bytes.

| Check | Seam | Assertion |
|---|---|---|
| `ignore_disconnect` default false | New send_stream action: write to commit, latch, write again after abort | Reader: `await_commit`, `to_a`, `body.each` then `body.close`. Producer’s second write raises `ClientDisconnected`. That exception is handled as after-commit (logged, not re-raised by `get`). Stream closed. Do not expect discarded writes in the body. |
| `ignore_disconnect` true | Existing `ignore_client_disconnect` pattern inside `send_stream` | After abort, further writes do not raise; log `"Work complete"` (or equivalent); latch counts down; `Timeout.timeout(3) { latch.wait }`; body may be empty/partial. |

Race-proofing (from `test_ignore_client_disconnect` / `test_abort_with_full_buffer` / `BufferTest`):

- Latch after the committing write so abort cannot win the race before commit.
- For a reader blocked in `each_chunk`, wait until a chunk was received **and** `reader.status == "sleep"` before `abort` (see `test_abort_terminates_a_reader_blocked_on_the_buffer`).
- If using a bounded queue, save/restore `Buffer.queue_size`.
- `ensure` kill the reader; restore logger.
- Never assert on `@aborted` or queue contents.

## Stream closed on every path

`send_stream`’s `ensure` is part of the public contract: the stream is closed after success, after a raise in the block, and if the block already called `close`.

Use the existing helper:

```ruby
assert_predicate response.stream, :closed?
assert_predicate response, :committed?
assert_predicate response, :sent?
```

Call it on: inferred/explicit type actions, RFC disposition, chunk-order, both exception paths, both disconnect paths. `process_controller_response` already `prepare!`s and `sent!`s, so `sent?` is true after `get` even when the producer only `close`d.

Double-close: a block that `stream.close`s itself must still finish `get` without error and remain `closed?`. Do not assert how many terminators were pushed.

## Notification payload and timing

Event: `"send_stream.action_controller"`. Payload is the **argument** hash `{ filename:, disposition:, type: }`, not resolved Content-Type. `instrument` wraps header assignment + `yield` only. `stream.close` runs after the event finishes.

| Check | Seam | Assertion |
|---|---|---|
| Happy-path payload | Existing `test_send_stream_instrumentation` | `assert_notification("send_stream.action_controller", filename: "sample.csv", disposition: "attachment", type: "text/csv")` around `get` |
| Payload `type` is the argument | New: subscribe around `send_stream_with_implicit_content_type` (`type: :csv`) | Payload `type` is `:csv`, while `Content-Type` is `"text/csv"` |
| Payload `type` is nil when inferred | New: inferred action | Payload `type` is `nil` |
| One event per call | `assert_notifications_count("send_stream.action_controller", 1)` | Exactly one |
| Timing vs close | `ActiveSupport::Notifications.subscribed` 5-arg listener around `get` | On finish: payload has filename/disposition/type; `response.stream.closed?` is still false unless the block closed it. After `get` returns, stream is closed. |
| Timing vs headers | Same subscriber, or a start listener | `Content-Type` / `Content-Disposition` are set by the time the event finishes (they are assigned before yield). |
| Exception payload | `capture_notifications` around an action that raises inside the block | Event still emitted; payload includes `:exception` (`[class_name, message]`) and `:exception_object`; `get` does not re-raise (committed path). |
| Close not inside the duration of work you can observe | Compare: subscriber finish happens before test-thread `assert_stream_closed` if you snapshot `closed?` in the subscriber | Preserve “finish, then ensure close”. Do not assert monotonic timestamps beyond “finish callback runs while ensure has not closed”. |

`assert_notification` matches with `payload.slice(*keys)`, so extra keys (`:exception`) do not fail a partial expected hash. For exception tests, assert those keys explicitly.

Unsubscribe is handled by `subscribed` / `capture_notifications`; do not leak subscribers.
