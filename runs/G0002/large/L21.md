# Lazy population and repeat access

Empty cache, table `"courses"`. First miss must hit the adapter; the second call must be `assert_no_queries(include_schema: true)`.

| Call | SQLite first | Repeat | Also assert |
|---|---|---|---|
| `data_source_exists?("courses")` | **1** (full `data_sources` list) | **0** | returns `true` |
| `data_source_exists?("foo")` after the list is warm | **1** (targeted exists) | **0** | returns `false`; does not re-list all sources |
| `columns("courses")` | **1** | **0** | size `3`; same object on repeat (`equal?`) |
| `columns_hash("courses")` after `columns` | **0** | **0** | size `3`; **frozen**; values are the same `Column` objects |
| `columns_hash("courses")` alone | **1** (via `columns`) | **0** | `columns_hash?` becomes `true` only here |
| `primary_keys("courses")` | **2** (list + PK) | **0** | `"id"` (String, not `["id"]`) |
| `indexes("courses")` | **3** (list + index list + index details) | **0** | size `1` |

`columns_hash` must never issue its own metadata SQL. `columns_hash?` must stay `false` after `data_source_exists?` and after `columns`; only `columns_hash` flips it. `cached?` is `@columns`-only: `false` after exists/PK/indexes, `true` only after `columns`.

Catch extras:

- After a warm `columns` call, `columns` / `columns_hash` / `columns_hash?` together must be `0` queries.
- After a warm exists list, a second `data_source_exists?` on a **known** name must not emit a targeted exists query.
- `primary_keys` / `indexes` on a known table may not call `columns` (assert with `assert_no_queries_match(/table_xinfo\|SHOW FULL FIELDS\|pg_attribute/i, include_schema: true)` on that path).

# `add` and `clear!`

`add("courses")` on an empty cache is the four lazy fills, not a coalesced dump. On SQLite that is **5** statements (list + PK structure + columns structure + 2 index queries). A refactor that merges PK and columns into one SQL would fail this pin; that is current behavior.

```ruby
assert_queries_count(5, include_schema: true) { cache.add("courses") }  # sqlite3 only
assert_no_queries(include_schema: true) { cache.add("courses") }
assert_no_queries(include_schema: true) do
  cache.columns("courses")
  cache.columns_hash("courses")
  cache.primary_keys("courses")
  cache.indexes("courses")
  cache.data_source_exists?("courses")
end
assert cache.cached?("courses")
assert cache.columns_hash?("courses")
```

On other adapters: first `add` count must equal the sum of first-miss counts for exists + PK + columns + indexes on that adapter; second `add` is `0`.

`clear!` must drop every internal hash. After populating columns, columns_hash, exists, PK, and indexes for `courses`, `size` is **8** on ARUnit2 (5 data sources + columns + columns_hash + PK). `@indexes` is **not** in `size`. Then:

```ruby
cache.clear!
assert_equal 0, cache.size
assert_not cache.cached?("courses")
assert_not cache.columns_hash?("courses")
assert_queries_count(1, include_schema: true) { cache.columns("courses") }  # sqlite3
```

`clear_data_source_cache!("courses")` after a warm exists list must leave other tables cached and force **exactly 1** targeted exists query (existing `test_clear_data_source_cache`). A full re-list here is an extra round trip. Clearing must also drop columns, columns_hash, PK, and indexes for that name so a later `columns("courses")` queries again.

# Nonexistent tables

Names like `"omgponies"`:

| Call | Result | SQLite first | Repeat |
|---|---|---|---|
| `data_source_exists?` | `false` | 1 list, then 1 targeted if already listed | **0** |
| `primary_keys` | `nil` | **2** (list + targeted exists); does **not** store a PK entry | **0** (exists miss is cached) |
| `indexes` | `[]` | **2**; does **not** store `[]` | **0** |
| `columns` / `columns_hash` | `ActiveRecord::StatementInvalid` | **1** columns query; **does not cache the failure** | queries **again** and raises again |
| `add` | no-op | **2** (same as exists miss) | **0**; `cached?` stays `false` |

The columns miss is the stale-negative check: a refactor that memoizes the exception would drop the second query and fail “repeat still raises **and** still queries.” PK/indexes must not raise.

# Schema-ignored tables (string and regexp)

`ActiveRecord.schema_ignored_table?` is `ignored === table_name` over `schema_ignored_tables`. Cover both `["professors"]` and `[/^profess/]`.

On a **fresh** cache, every ignored-table call is **0** queries:

- `data_source_exists?("professors")` → `nil` (not `false`)
- `columns` / `columns_hash` → `StatementInvalid` (`Table 'professors' doesn't exist`)
- `primary_keys` → `nil`
- `indexes` → `[]`
- `add("professors")` → no-op, `cached?` false

`data_source_exists?("courses")` under the same config still lists sources (**1** query) and returns `true`. The list must omit `professors`.

Dump path (existing `assert_professors_ignored`): `dump_to` + `load!` with the ignore list active. Loaded cache has `courses` fully populated (0 queries) and treats `professors` as ignored (`nil` / raise / `[]`) with **0** queries. A dump that still contains `professors` is a stale-entry failure.

Deprecated `schema_cache_ignored_tables` / `schema_cache_ignored_table?` remain aliases; keep the deprecation tests, they are not query-count tests.

# Duplicate-cache independence

`initialize_dup` copies the five hashes, not the `SchemaCache` identity. Values inside (column arrays) are shared until one side deletes the key.

```ruby
c1 = SchemaCache.new.tap { |c| c.add(pool, "courses") }
c2 = c1.dup
assert c1.columns(pool, "courses").equal?(c2.columns(pool, "courses"))

c2.clear_data_source_cache!(nil, "courses")
assert_no_queries(include_schema: true) { c1.columns(pool, "courses") }   # original live
assert_queries_count(1, include_schema: true) { c2.columns(pool, "courses") }  # sqlite3

c1.clear_data_source_cache!(nil, "courses")
assert_no_queries(include_schema: true) { c2.columns(pool, "courses") }   # dup still populated
```

Also dup `@columns_hash`, `@primary_keys`, `@data_sources`, `@indexes` the same way. A shared-hash dup would make the first clear empty both caches (stale miss on the original).

# Frozen / deduplicated values

Live `columns("courses")` (not Marshal):

- returned array is the same object on repeat
- each `Column` is frozen; `name` is a frozen, interned string (`-value`)
- `columns_hash` is frozen; `cols.first.equal?(hash[cols.first.name])`
- PK string is frozen
- `IndexDefinition` is **not** `Deduplicable`; do not assert frozen indexes

YAML `init_with` without `"deduplicated"` must rebuild `@columns_hash` from `@columns` via `index_by(&:name)` and run `deep_deduplicate`. With `"deduplicated" => true`, `@columns` is the same object as the coder (existing test). Marshal load reconstructs `@columns_hash` and does not freeze it; do not assert freeze on Marshal-loaded hashes.

# YAML / Marshal dump/load, gzip, older dumps

Formats: `.yml`, `.dump`, `.yml.gz`, `.dump.gz`. `dump_to` always `add_all`s a **fresh** cache, then writes. After `load!`:

```ruby
assert_no_queries(include_schema: true) do
  assert_equal 3, cache.columns("courses").size
  assert_equal 3, cache.columns("courses").map { |c| c.cast_type }.compact.size
  assert_equal 3, cache.columns_hash("courses").size
  assert cache.data_source_exists?("courses")
  assert_equal "id", cache.primary_keys("courses")
  assert_equal 1, cache.indexes("courses").size
end
```

Any query here is an extra metadata round trip (failed load or dropped indexes/columns_hash).

Determinism:

- `encode_with` writes **sorted** `columns`, `primary_keys`, `data_sources`, `indexes`, plus `version`. It does **not** emit `columns_hash`.
- Gzip writer sets `mtime = 0`; two dumps one second apart must have identical MD5 (`test_gzip_dumps_identical`).
- `marshal_dump` is `[@version, @columns, {}, @primary_keys, @data_sources, @indexes]` — third slot always empty `{}`.

Older dumps:

1. **YAML 5.1** ([schema_dump_5_1.yml](file:///home/user/workspace/repo/activerecord/test/assets/schema_dump_5_1.yml)): has `columns`, `columns_hash`, `primary_keys`, `data_sources`, `version`; **no `indexes`**. `columns("posts")` / `columns_hash` / exists / PK are **0** queries (11 columns, PK `"id"`). First `indexes("courses")` **must query** (`assert_queries_count(include_schema: true)` ≥ 1; SQLite **3** because `@data_sources` is non-empty and lacks `courses`). Repeat indexes is **0**. `@indexes` starts as `{}`.
2. **Marshal payload missing the indexes slot** (`marshal_load` of 5-element array): `@indexes` becomes `{}`; first `indexes` queries, repeat is 0.
3. **YAML without `columns_hash`**: `init_with` derives it; `columns_hash` is **0** queries.
4. **8.0 YAML** ([schema_dump_8_0.yml](file:///home/user/workspace/repo/activerecord/test/assets/schema_dump_8_0.yml)): has indexes, no `columns_hash`; all five accessors for `courses` are **0** queries.

`init_with` must treat missing `indexes` as `{}`, not `nil`, or `indexes` will raise instead of lazy-filling.

# Schema version and dump-version checking

`version` on an empty cache is **1** query (`schema_migrations` exists / current version) then **0**. `schema_version` is the memoized `@version` and does not query.

Default `SchemaReflection.check_schema_cache_dump_version = true`:

- `cached?("courses")` on an unloaded dump is falsey **without** opening a connection (cannot load the dump yet).
- `load!` issues **1** version query. Matching version keeps the dump; later accessors are **0** queries.
- Mismatched version: stderr matches `/Ignoring .* because it has expired. The current schema version is .*, but the one in the schema cache file is .* /`, dump is discarded, and `columns("courses")` queries live SQL (SQLite **1**). That is the stale-dump catch.
- `ActiveRecordError` during validation: warn `Failed to validate the schema cache because of ...` and discard; do not raise.

`SchemaReflection.with(check_schema_cache_dump_version: false)`:

- `cached?("courses")` is `true` with **no** pool and **0** queries.
- `BoundSchemaReflection.new(reflection, :__unused_pool__)` can serve columns, columns_hash, exists, PK, and indexes with **0** queries.
- A version query here is an extra round trip.

`use_schema_cache_dump = false` must skip file load (empty cache, first `columns` queries).

# Adapter portability boundaries

Portable across sqlite3, sqlite3_mem, postgresql, mysql2, trilogy:

- Repeat-hit `0` queries for every accessor.
- Ignored-table accessors `0` queries and the `nil` / raise / `[]` results above.
- Nonexistent PK `nil`, indexes `[]`, columns raise `StatementInvalid`.
- Composite PK array vs single-column string vs missing `nil`.
- Dump/load of a current dump: **0** queries for the five accessors.
- 5.1 dump: 0 queries for columns/hash/exists/PK; indexes **does** query once.
- `clear_data_source_cache!` then exists: **exactly 1** query, not a full re-list, if `@data_sources` is still non-empty.
- `size` ignores `@indexes`; `cached?` is columns-only.
- Gzip byte identity; YAML key sort.

Adapter-specific (pin only on SQLite or derive via `capture_sql`):

- Absolute first-miss counts (`columns` 1, `primary_keys` 2, `indexes` 3, `add` 5). PostgreSQL/MySQL `indexes`/`columns` are different SQL and often different statement counts; MySQL may still `SHOW FULL FIELDS` per table on some paths.
- `data_sources` SQL (`pragma_table_list` vs `information_schema` vs `pg_class`).
- `lazily_load_schema_cache` test is already skipped for `in_memory_db?`.
- Column `cast_type` presence after YAML/Marshal load.

Do not assert on ARUnit (`posts`) unless loading the 5.1 fixture; `SchemaCacheTest` is ARUnit2.

# Assertions that catch extra trips or stale entries

1. **Repeat is zero.** After any successful fill, wrap the same call in `assert_no_queries(include_schema: true)`. A second `PRAGMA` / `information_schema` / `pg_attribute` is an extra round trip.
2. **First miss is exact, not “at least one.”** `assert_queries_count(n, include_schema: true)` with sqlite `n` from the table above, or `n = adapter_queries { connection.<method> } (+ exists queries the cache adds)`. `assert_queries_count(include_schema: true)` without `n` only checks ≥ 1 and will not catch doubles.
3. **`add` budget = sum of independent fills.** Fewer queries means coalescing that today’s code does not do; more means a duplicate fill (today’s SQLite `add` already issues PK and columns separately — preserve that).
4. **Warm exists list must not re-list.** After `data_source_exists?("courses")`, `data_source_exists?("foo")` is one **targeted** query; `clear_data_source_cache!("courses")` then exists is one targeted query. A full `data_sources` scan is extra.
5. **Ignored names never touch the adapter.** `assert_no_queries` around exists/columns/PK/indexes/add. A dump that still has `professors` under an ignore list is stale.
6. **Expired dump never serves.** After version mismatch, `columns` must query; `assert_no_queries` here would mean the expired file was kept.
7. **Failed `columns` is not cached.** Two `columns("omgponies")` both raise and both query.
8. **Dup isolation.** Clearing the copy must not force the original to query; clearing the original must not force the copy to query.
9. **`columns_hash?` / `cached?` do not populate.** Calling them must be 0 queries and must not flip the other flag.
10. **Cross-accessor pollution.** Filling indexes must not fill `cached?`; filling columns must not fill `columns_hash?`.
