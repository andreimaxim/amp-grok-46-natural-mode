`Array.wrap` is a three-branch class method. It never special-cases `Array` or `Hash`; those outcomes fall out of `nil?`, `respond_to?(:to_ary)`, and `to_ary || [object]`.

```41:49:activesupport/lib/active_support/core_ext/array/wrap.rb
  def self.wrap(object)
    if object.nil?
      []
    elsif object.respond_to?(:to_ary)
      object.to_ary || [object]
    else
      [object]
    end
  end
```

```text
Array.wrap(object)
  object.nil?                    → []
  object.respond_to?(:to_ary)
    object.to_ary  truthy        → that value (not re-wrapped, not type-checked)
    object.to_ary  nil/false     → [object]
  else                           → [object]
```

The first comment bullet (“responds to `to_ary` → return its result”) is coarser than the code. The `||` is the real contract: a `nil` `to_ary` result is discarded and the original object is wrapped.

### `Kernel#Array`, only as the comment states

The method comment lists three differences and one Hash example ([wrap.rb:16-29](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/array/wrap.rb#L16-L29)). Nothing else in this revision’s wrap source or wrap tests specifies `Kernel#Array` behavior:

1. `to_ary` returning `nil`: `Kernel#Array` tries `to_a`; wrap returns `[object]`.
2. `to_ary` returning a non-`Array`: `Kernel#Array` raises; wrap returns that value.
3. No `to_ary`: wrap does not call `to_a`; it returns `[object]` — illustrated with a Hash.

The comment also notes `[*object]` as a related idiom (`[]` for `nil`, otherwise `Array(object)`). That is not part of `Array.wrap`’s control flow.
