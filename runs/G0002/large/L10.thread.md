The discussed refactor was to replace `Hash#compact_blank!`’s blank-value deletion with Ruby’s nil-only `compact!`:

```ruby
# original
def compact_blank!
  delete_if { |_key, value| value.blank? }
end

# proposed
def compact_blank!
  compact!
end
```

The author’s claim was that this was an equivalent simplification—i.e., that `compact_blank!` only removed `nil` values.

That claim is incorrect. `Hash#compact` / `compact!` remove only entries whose values are `nil`; Active Support’s `compact_blank` / `compact_blank!` remove entries with `value.blank?`, including `nil` but also `false`, empty or whitespace-only strings, and empty collections. It also changes the bang-method return behavior: the original `delete_if` returns the hash, while `compact!` can return `nil` when nothing is removed.

The author’s “equivalent to Ruby compact, therefore same API” claim is false. Ruby `Hash#compact` / `compact!` drop only `nil` values. Active Support’s method drops values for which `Object#blank?` is true.

### Contract at this revision

[`Hash#compact_blank!`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/enumerable.rb#L265-L276) is documented as “Removes all blank values … Uses `Object#blank?`”:

```265:276:activesupport/lib/active_support/core_ext/enumerable.rb

  # Uses Object#blank? for determining if a value is blank.
  #
  # ```
  # h = { a: "", b: 1, c: nil, d: [], e: false, f: true }
  # h.compact_blank!
  # # => { b: 1, f: true }

  def compact_blank!
    # use delete_if rather than reject! because it always returns self even if nothing changed
    delete_if { |_k, v| v.blank? }
  end

### Return value / identity

The implementation comment at [274](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/enumerable.rb#L274) is the bang contract: **always return `self`**, including when nothing is deleted. That is why it uses `delete_if` instead of `reject!`.

Verified in this orb:

- `Hash#delete_if` always returns the same object, whether or not entries were deleted.
- `Hash#compact!` returns `nil` when nothing was `nil` (`{a: 1}.compact! # => nil`) and `self` only when at least one `nil` was removed.

This specific proposal (`delete_if` + `nil?`) **does** preserve identity/`self`. It does **not** match Ruby `compact!`’s `nil`-on-no-change return. Existing Hash tests never assert return value or `equal?`; they only assert post-mutation contents. A silent swap to `compact!` would therefore also change the return contract without failing [`test_hash_compact_blank!`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L385-L388).

(`ActionController::Parameters#compact_blank!` at [1051–1053](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1051-L1053) uses `reject!` and can return `nil`; that is a different class and is not this API.)

### Minimal regression matrix (do not land without these)

Keep the current fixture, then add the gaps the Hash tests miss:

1. **Contents, in-place:** `{ a: nil, b: false, c: "", d: " ", e: "\u00a0", f: [], g: {}, h: 0, i: 1, j: true }` → `{ h: 0, i: 1, j: true }`; same object (`assert_same`).
2. **Non-bang twin:** same input to `compact_blank` yields the same hash, original unchanged.
3. **Return when nothing blank:** `{ a: 1, b: true }.compact_blank!` returns that same hash, not `nil`.
4. **Return when something blank:** `{ a: nil }.compact_blank!` returns that same hash.
5. **Do not confuse with `compact`:** `{ a: false, b: "" }` must become `{}` under `compact_blank!` and stay unchanged under `compact!`.

**Verdict: block.** The predicate change is a breaking API change, not a compact-equivalent cleanup. Existing tests already prove it.
