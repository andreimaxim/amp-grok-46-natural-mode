The no-observable-change bar is **set membership, loader ownership, reload vs once lifetime, `$LOAD_PATH` membership, freeze timing, and callback cardinality** — not the private concatenation/unshift order that `_all_autoload_paths` and `set_load_path` happen to use.

```diagram
config.autoload_paths + paths.autoload_paths     → all_autoload_paths
config.autoload_once_paths + paths.autoload_once → all_autoload_once_paths
config.eager_load_paths + paths.eager_load       → all_eager_load_paths
        │
        ▼
Engine#_all_autoload_paths
  (all_autoload ∪ all_eager) − all_once, then uniq
Engine#_all_autoload_once_paths
  all_once.uniq
        │
        ▼
set_load_path          → $LOAD_PATH (existent dirs only)
set_autoload_paths     → AS::Dependencies.* ; freeze config arrays
set_eager_load_paths   → AS::Dependencies._eager_load_paths
        │
        ▼
setup_once_autoloader  → Rails.autoloaders.once  (before bootstrap_hook)
setup_main_autoloader  → Rails.autoloaders.main  (finisher)
        │
        ▼
reloader.prepare! / eager_load! / to_run class_unload
```

# Invariants the refactor must keep

These are derived from [railties/lib/rails/engine/configuration.rb](file:///home/user/workspace/repo/railties/lib/rails/engine/configuration.rb), [railties/lib/rails/engine.rb](file:///home/user/workspace/repo/railties/lib/rails/engine.rb), [railties/lib/rails/application/bootstrap.rb](file:///home/user/workspace/repo/railties/lib/rails/application/bootstrap.rb), and [railties/lib/rails/application/finisher.rb](file:///home/user/workspace/repo/railties/lib/rails/application/finisher.rb). Treat them as the contract; do not assert the `+`/`unshift`/`reverse_each` implementation.

**I1. Three-collection merge.** For each engine and the application, the published collections are:

- `all_autoload_paths` = custom `config.autoload_paths` ∪ path-registry autoload dirs
- `all_autoload_once_paths` = custom `config.autoload_once_paths` ∪ path-registry autoload-once dirs
- `all_eager_load_paths` = custom `config.eager_load_paths` ∪ path-registry eager dirs

Default registry flags: `app` and `app/{controllers,channels,helpers,models,mailers}` are eager; `lib` and `vendor` are load-path only; `test/mailers/previews` is autoload-only. `app/assets` and `config.javascript_path` stay out of autoload.

**I2. Main vs once partition.** Main roots are `(all_autoload ∪ all_eager) − all_once`. Once roots are `all_once`. A path in both autoload and autoload-once is **once-owned**. A path that is only eager is still a main autoload root. Duplicates collapse (`uniq`); missing directories stay in the `ActiveSupport::Dependencies` arrays but are never `push_dir`’d.

**I3. Eager-load overlay is independent of ownership.** `ActiveSupport::Dependencies._eager_load_paths` is the union of every engine’s `all_eager_load_paths`. `eager_load?(path)` decides `do_not_eager_load`. A path in **both** eager-load and autoload-once is once-owned **and** eager-loaded in production. A once path not in eager-load is autoloadable from initializers and never eager-loaded.

**I4. Loader ownership.** After boot, every existent once dir is a root of `Rails.autoloaders.once` and is absent from `Rails.autoloaders.main.dirs`. Every existent main autoload dir is a root of `main` and is absent from `once.dirs`. User `push_dir` with a custom namespace, if already present, is not overwritten (`already_configured_dirs`). `main.tag == "rails.main"`, `once.tag == "rails.once"`. Reloading: `main.reloading_enabled?` iff `config.enable_reloading`; `once` never reloads.

**I5. Freeze points.** After `:set_autoload_paths` (before `:bootstrap_hook`): `config.autoload_paths` and `config.autoload_once_paths` are frozen. After `:set_eager_load_paths`: `config.eager_load_paths` is frozen. After `:setup_once_autoloader`: `ActiveSupport::Dependencies.autoload_once_paths` is frozen (once loader is already `setup`, so initializer bodies can autoload from it). After `:setup_main_autoloader`: `ActiveSupport::Dependencies.autoload_paths` is frozen. Later `<<` raises `FrozenError`. Reading the config arrays earlier must not snapshot them ([issue 49629](https://github.com/rails/rails/issues/49629)).

**I6. `$LOAD_PATH`.** `Rails::Application.add_lib_to_load_path!` always unshifts `lib` if it exists. `set_load_path` always unshifts existent `paths.load_paths` (`lib`, `vendor`). Autoload/once dirs join `$LOAD_PATH` **only** when `config.add_autoload_paths_to_load_path` is true (false since `load_defaults "7.1"`). Action Mailer preview paths are autoload dirs and are **not** required to appear on `$LOAD_PATH`. `$LOAD_PATH.uniq!` after the unshifts.

**I7. Engine vs application.** Each engine runs the same three initializers. Engine `app/*` constants resolve. Engine `lib` is on `$LOAD_PATH`. Application and engine dirs that exist as directories are both loader roots. Isolation/namespace is unchanged; do not require a specific interleaving of app vs engine roots.

**I8. Reloader hooks.** `config.to_prepare` blocks are registered on `app.reloader` and run at boot via `prepare!` **before** `eager_load!`. `after_initialize` runs once after eager load. With reloading on and `reload_classes_only_on_change`, `to_run(prepend: true)` unloads main (not once), then routes reload. `watchable_args` dirs are `main.dirs` plus `config.watchable_dirs` — once dirs are not watched. `ActiveSupport::Dependencies.clear` reloads `main` only.

# New black-box probes

Put them next to the existing isolation tests (same `build_app` / `app(env)` style). Each probe boots a tiny app, mutates files or config, and asserts **observables**. Do not call `_all_autoload_paths`, `all_autoload_paths`, or inspect initializer order.

**Helper (shared):** after boot, classify a loaded constant with `Zeitwerk::Loader.for(klass)` (or `main.cpath_expected_at` / `once.cpath_expected_at` on the file). That is loader ownership without depending on dir-array order.

## 1. Duplicate and overlapping paths

Setup: `config.autoload_paths << extras` twice; also `config.paths.add "vendor/x", autoload: true` pointing at the same expanded extras dir; engine that adds the same `app/models` style dir only if it is a distinct tree.

Assert:

- `ActiveSupport::Dependencies.autoload_paths.count { |p| File.expand_path(p) == extras } == 1` after freeze (uniq).
- `Rails.autoloaders.main.dirs` includes extras **once**.
- `assert_nothing_raised { Extra }` and `assert_same Extra, Extra` (one autoload, no `Zeitwerk::Error` about overlapping roots).
- Nested overlap (parent `app` eager glob vs `app/models`) must still load `app/models/user.rb` as `User` with **one** owner; do not assert which glob entry “won.”

## 2. Path in both eager-load and autoload-once

Setup: `app/serializers/money.rb` defining `Money`; both `config.autoload_once_paths` and `config.eager_load_paths` include that dir. Mirror of the existing once-eager test, extended.

Development boot (`eager_load = false`):

- `assert Rails.autoloaders.once.dirs.include?(dir)`
- `assert_not_includes Rails.autoloaders.main.dirs, dir`
- `assert ActiveSupport::Dependencies.eager_load?(dir)` **or** `assert_includes ActiveSupport::Dependencies._eager_load_paths, dir`
- `Money` autoloads; `assert_same Zeitwerk::Loader.for(Money), Rails.autoloaders.once`
- `id = Money.object_id`; `Rails.application.reloader.reload!`; `assert_same Money, Object.const_get(:Money)` and `assert_equal id, Money.object_id` (once does not unload)

Production boot (`eager_load = true`):

- `assert Object.const_defined?(:Money)` without touching the constant first (eager, not lazy)
- same loader ownership
- `assert_not Rails.autoloaders.once.reloading_enabled?`

Negative sibling: once dir **not** in eager-load stays undefined until referenced (`assert_not Object.const_defined?(:WebsocketHacks)` then `assert WebsocketHacks`) — already in zeitwerk_integration_test; keep it.

## 3. `config.add_autoload_paths_to_load_path = false` (default)

Setup: custom `autoload_paths`, `autoload_once_paths`, default `app/models`. Explicitly set the flag false (and a second app with true).

False:

- `assert_not_includes $LOAD_PATH, "#{app_path}/app/models"`
- `assert_not_includes $LOAD_PATH, custom_autoload`
- `assert_not_includes $LOAD_PATH, custom_once`
- `assert_includes $LOAD_PATH, "#{app_path}/lib"` (always)
- `assert_includes $LOAD_PATH, "#{app_path}/vendor"` if that dir exists (`paths.load_paths`)
- `assert User` still autoloads (Zeitwerk, not `$LOAD_PATH`)
- `assert_raises(LoadError) { require "user" }` for a model file that is only an autoload root

True:

- custom autoload and once dirs that exist **are** on `$LOAD_PATH`
- mailer preview paths may still be absent; do not require them
- membership only: `assert_empty (custom_dirs - $LOAD_PATH)` — not `assert_equal` against the whole `$LOAD_PATH`

## 4. Development reloads after edits and removals

Boot with `enable_reloading = true`. Three files: `app/models/user.rb` (main), `extras/once_const.rb` on `autoload_once_paths`, engine `app/models/engine_post.rb`.

Edit main file (`counter 1 → 2`), then `get` or `reloader.reload!`:

- `assert_equal 2, User.counter`
- `assert_not_equal old_id, User.object_id`
- `assert_equal 1, once_id` / `assert_equal old_once_id, OnceConst.object_id`
- `EnginePost` identity changes (engine main path is reloadable)
- `to_prepare` count += 1; `after_initialize` count unchanged

Remove `app/models/user.rb`, reload:

- `assert_raises(NameError) { User }`
- `assert Object.const_defined?(:OnceConst)`

Remove the once file, reload:

- `OnceConst` still defined (stale once constant is the current contract)

`to_prepare` / `to_run` cardinality: register one `config.to_prepare` and one `ActiveSupport::Reloader.to_complete`. After boot, prepare count is 1. After one `reload!`, prepare count is 2 and complete count is 1. Do not assert hook list order beyond “prepare ran, then autoloaded constants are gone, then a subsequent autoload sees the new file.”

## 5. Eager-loaded production

`boot("production")` (or `eager_load = true`, `enable_reloading = false`).

- Side-effect flags in `app/models`, engine `app/models`, and once+eager dir are true **before** constant reference
- once-without-eager flag is false until reference
- `assert_not Rails.autoloaders.main.reloading_enabled?`
- `reloader.check` is effectively no-op: editing `user.rb` and calling `reload!` leaves `User.object_id` unchanged
- `before_eager_load` ran once; `to_prepare` ran once; `after_initialize` ran once
- Manual `Rails.application.eager_load!` in development still loads app code (existing regression)

## 6. Engine versus application paths

Engine gem with `app/models/from_engine.rb` and `lib/from_engine_lib.rb`; app with `app/models/from_app.rb`. Optional second engine.

- `assert FromEngine`, `assert FromApp`, `require "from_engine_lib"`
- `Zeitwerk::Loader.for(FromEngine)` and `for(FromApp)` are both `Rails.autoloaders.main`
- both `.../app/models` dirs are in `main.dirs` (membership, not position)
- engine once path (`config.autoload_once_paths` in the engine class) is in `once.dirs` and survives app reload
- bootstrap-time initializer (`after: :bootstrap_hook`) still sees engine controllers in `ActiveSupport::Dependencies.autoload_paths` (existing engine_test)

Do not assert that the application’s models dir appears before the engine’s, or the reverse. `unshift` + reverse railties order is private. If two engines define the same constant name, that is already an error; do not add a probe that depends on who wins.

## 7. Path arrays freeze after initialization

Use initializers with `after:` to pin the **public** freeze windows, not internal method names.

```ruby
initializer :after_bootstrap, after: :bootstrap_hook do
  assert config.autoload_paths.frozen?
  assert config.autoload_once_paths.frozen?
  assert config.eager_load_paths.frozen?
  assert ActiveSupport::Dependencies.autoload_once_paths.frozen?
  OnceFromInitializer # must autoload
  assert_raises(FrozenError) { config.autoload_paths << "/nope" }
  assert_raises(FrozenError) { ActiveSupport::Dependencies.autoload_once_paths << "/nope" }
end
```

After full boot (finisher has run):

- `assert ActiveSupport::Dependencies.autoload_paths.frozen?`
- `assert_raises(FrozenError) { ActiveSupport::Dependencies.autoload_paths << "/nope" }`
- `assert_raises(FrozenError) { config.eager_load_paths << "/nope" }`

Also keep the 49629 probe: read `config.autoload_paths` / `once` / `eager_load_paths`, then `config.paths.add(...)`; after boot those added dirs **are** in the Dependencies collections.

# Exact observables (what to assert, what to ignore)

**Assert**

- Constant defined / undefined: `Object.const_defined?(:X)`, `assert_raises(NameError)`, `assert_raises(Zeitwerk::NameError)` on eager mismatch
- Identity: `object_id` before/after `reloader.reload!` (changes for main, stable for once)
- Loader ownership: `Zeitwerk::Loader.for(klass)` or `include?` on `main.dirs` / `once.dirs`
- Set membership: `assert_includes` / `assert_not_includes` / `assert_equal 1, array.count { ... }`
- `$LOAD_PATH` membership, never full-array equality
- `FrozenError` at the freeze windows above
- Callback counts: `to_prepare`, `after_initialize`, `before_eager_load` (0 or 1 at boot; prepare increments per reload)
- `main.reloading_enabled?` vs `once.reloading_enabled?`
- `watchable_args` includes main autoload dirs, excludes once dirs and files like `app/README.md`

**Do not assert**

- Exact order of `ActiveSupport::Dependencies.autoload_paths`, `main.dirs`, or `$LOAD_PATH`
- That custom `config.autoload_paths` appear before path-registry dirs (that is just `array + registry`)
- Engine/application interleaving
- Internal memo ivars (`@_all_autoload_paths`)
- That `all_*` methods remain public or keep those names — they are `:nodoc:`

The one order that **is** user-visible: if `add_autoload_paths_to_load_path` is true and two load-path dirs both contain `foo.rb`, `require "foo"` loads the earlier `$LOAD_PATH` entry. Probe that only under the true flag, with two custom load-path dirs, not autoload-only dirs.
