**Block.** The claim is wrong for this revision, and the diff is not a bang counterpart to `#attach`. It changes when records are saved, which exception is raised, what is returned, and how many times callbacks run.

`#attach!` is documented as “call `#attach`, and raise if the record **was meant to be saved** and validation failed”:


## What the two-liner actually does

```ruby
attach(*attachables)
record.save!
```

That is not “use `save!` instead of `save` on the immediate path.” It always performs a second persist after `#attach`, including when `#attach` already saved and when `#attach` intentionally did **not** save.

## Path-by-path

**Persisted, unchanged, valid (immediate save).** `#attach` already calls `record.save` and returns the Many proxy ([many_test.rb:805–809](file:///home/user/workspace/repo/activestorage/test/models/attached/many_test.rb#L805-L809)). After the first commit, `attachment_changes` is already cleared, so the second save is a no-op for attachments but not for callbacks/SQL.

**Persisted, unchanged, invalid.** Today `#attach` returns `nil` and `#attach!` raises `ActiveRecord::RecordNotSaved` with `"Failed to save the record"` ([many_test.rb:820–827](file:///home/user/workspace/repo/activestorage/test/models/attached/many_test.rb#L820-L827), [errors.rb](file:///home/user/workspace/repo/activerecord/lib/active_record/errors.rb#L166-L176)). The existing test fails. Message changes from `"Failed to save the record"` to the I18n validation summary.

**New record.** `#attach` does not persist; it queues `CreateMany` until the caller saves ([many_test.rb:836–841](file:///home/user/workspace/repo/activestorage/test/models/attached/many_test.rb#L836-L841)). `record.save!` would insert the record and attachments as a side effect of `#attach!`. That contradicts the method comment.

**Persisted but changed.** Same deferral so unsaved attribute edits are not flushed ([many_test.rb:46–58](file:///home/user/workspace/repo/activestorage/test/models/attached/many_test.rb#L46-L58), [831–835](file:///home/user/workspace/repo/activestorage/test/models/attached/many_test.rb#L831-L835)). `save!` would persist those attributes and the attachments immediately. If the dirty record is also invalid, current `#attach!` does not raise; the PR would raise `RecordInvalid` and still have already mutated `attachment_changes`.

**Return value.** Current `#attach!` returns the Many proxy (`attach(...) || raise`). `save!` returns `true` ([persistence.rb:370–392](file:///home/user/workspace/repo/activerecord/lib/active_record/persistence.rb#L370-L392)). `user.highlights.attach!(blob)` becoming `true` is a contract break.

**Empty / nested arrays.** `#attach` already does `attachables.flatten`. `[]` after flatten hits the setter’s `compact_blank` / `none?` branch and builds `DeleteMany` ([model.rb:243–251](file:///home/user/workspace/repo/activestorage/lib/active_storage/attached/model.rb#L243-L251)). The PR does not fix that; on a persisted unchanged record it would still double-save (and could persist a replace-with-empty).

**Duplicate / existing blobs.** `#attach` assigns `blobs + attachables.flatten`, so existing blobs are kept and new ones appended. The extra `save!` does not fix duplicates; on the success path it only re-saves the parent.

**Pending changes.** On new/dirty records, pending `CreateMany` is the point of `#attach`. Unconditional `save!` commits them. On the success path, `after_commit` already deleted the change, so the second save does not re-upload, but it does re-enter save callbacks.

**Callbacks / `throw :abort`.** Validation failure: two save attempts, then `RecordInvalid`. `before_save { throw :abort }`: first `save` returns false, second `save!` raises `RecordNotSaved` from persistence — still a double callback run. Current code raises `RecordNotSaved` once without a second save.
