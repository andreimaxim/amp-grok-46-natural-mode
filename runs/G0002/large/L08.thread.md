## Assistant

`Enumerable#sole` returns the only yielded item, or raises. It never walks the rest of the collection once a second item appears, which is why an endless range does not hang.

### Contract

[`Enumerable#sole`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/enumerable.rb#L229-L256) is “exactly one item”:

- empty → `Enumerable::SoleItemExpectedError` (`"no item found"`)
- one item → that item
- two or more → `Enumerable::SoleItemExpectedError` (`"multiple items found"`)

The exception class is declared as `Enumerable::SoleItemExpectedError < StandardError` at [enumerable.rb:19-22](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/enumerable.rb#L19-L22), then moved to `ActiveSupport::EnumerableCoreExt::SoleItemExpectedError` ([enumerable.rb:23-26](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/enumerable.rb#L23-L26)). Tests still name it `Enumerable::SoleItemExpectedError` ([enumerable_test.rb:432](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L432)).

### Control flow

```ruby
result = nil
found = false

each do |*element|
  if found
    raise SoleItemExpectedError, "multiple items found"
  end

  result = element.size == 1 ? element[0] : element
  found = true
end

found ? result : raise(SoleItemExpectedError, "no item found")
```

Source: [enumerable.rb:238-256](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/enumerable.rb#L238-L256).

```diagram

     │
     ▼
┌─────────────┐  found already?  ┯
│ first yield │──────── no ─────▶ store result, found=true
└─────────────┘                   │
     │                            ▼
     │                       next yield?
     │                    ┌─────┴──────┐
     │                    │ none       │ ≥1 more
     │                    ▼            ▼
```

`found` is the occupancy flag. `result` starts as `nil` and is not used to mean “empty”.

### Endless range: no full traversal

[`GenericEnumerable.new(1..).sole`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L438) still uses `Enumerable#sole`. `1..` is infinite under `each`, but it yields `1` then `2`. On `2`, `found` is already true, so the method raises `"multiple items found"` and never asks for `3`, `4`, ….

That is the short-circuit: **stop at the second item**, not “consume until `each` returns.” An enumerator that yields one value and then blocks forever would still hang; an endless range does not, because it yields a second value.

(`Range#sole` in [range/sole.rb:15-22](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/range/sole.rb#L15-L22) is a different path: beginless/endless ranges raise before `super`. The enumerable test does not use that override.)

### `nil` is a real element

Because emptiness is `found`, not `result.nil?`:

- `[nil]` would store `result = nil`, set `found = true`, and return `nil` (not tested directly; follows from [enumerable.rb:239-251](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/enumerable.rb#L239-L251)).
- `[1, nil]` is two items. `nil` is the second yield, so it raises ([enumerable_test.rb:437](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L437)).

`nil` is never treated as “no item.”

### How yields become the return value

The block is `|*element|` ([enumerable.rb:241-247](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/enumerable.rb#L241-L247)):

```ruby
result = element.size == 1 ? element[0] : element
```

One yielded value is unwrapped; more than one stays an array. That matches `Enumerable#first`, which the tests assert.

**One positional value** — `each` yields `1`:

- `element` is `[1]`
- size 1 → return `1`
- [enumerable_test.rb:435](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L435)

**Multiple positional values** — `yielder.yield(1, "one")`:

- `element` is `[1, "one"]`
- size ≠ 1 → return `[1, "one"]`
- [`test_sole_returns_same_value_as_first_for_tuples`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L441-L444): `enum.sole == [1, "one"]` and `enum.sole == enum.first`

**Positional plus keywords** — `yield 1, two: 3` in [`KeywordYielder`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L447-L452):

- `|*element|` does not take keywords, so Ruby packs them as a hash in the splat: `[1, { two: 3 }]`
- size 2 → return that array
- [`test_sole_keyword_arguments`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L455-L458): `yielder.sole == [1, { two: 3 }]` and `yielder.sole == yielder.first`

So `sole` does not reconstruct a kwarg call; it returns the same packed object `each`/`first` would give you.
