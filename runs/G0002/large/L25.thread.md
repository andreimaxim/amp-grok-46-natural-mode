## Assistant

`expect` is permit-then-require, but it permits with a stricter type contract than `permit` and then unwraps the required roots. `require` + `permit` are the same two operations composed by the caller, with looser array/hash matching and with unpermitted-key logging/raising still on.

### `expect` permits first, then requires the filter roots

[`expect`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L779-L790) does three things:

```779:790:actionpack/lib/action_controller/metal/strong_parameters.rb
    def expect(*filters)
      params = permit_filters(filters)
      keys = filters.flatten.flat_map { |f| f.is_a?(Hash) ? f.keys : f }
      values = params.require(keys)
      values.size == 1 ? values.first : values
    end
```

1. Filter through [`permit_filters`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1189-L1206) with its defaults: `explicit_arrays: true`, `on_unpermitted: nil`.
2. Collect every root key from the filters, in filter order.
3. [`require`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L526-L544) those keys on the already-filtered object. One key unwraps to that value; more than one key returns an array.

`require` itself is unchanged: a value passes if `present?` or it is `false`; otherwise it raises `ActionController::ParameterMissing`. Empty hashes, empty arrays, `nil`, and blank strings fail. An array of keys maps `require` over each key and re-raises the first miss.

[`permit`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L675-L677) is the same filter engine with the opposite defaults:

```675:677:actionpack/lib/action_controller/metal/strong_parameters.rb
    def permit(*filters)
      permit_filters(filters, on_unpermitted: self.class.action_on_unpermitted_parameters, explicit_arrays: false)
    end
```

So `params.permit(...).require(:person)` still returns a permitted `Parameters` object, but it accepts array-or-hash confusion that `expect` rejects, and it still honors `action_on_unpermitted_parameters`. `params.require(:person).permit(...)` is the unsafe order: `require` returns the raw nested value, and a scalar there becomes `NoMethodError` on `permit`.

```diagram

  require([:person])

```

[`expect!`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L793-L798) is `expect` with `ParameterMissing` rewritten to `ExpectedParameterMissing`.

### `permit_value` is the type fork

[`permit_filters`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1189-L1206) builds a new `Parameters`, walks flattened filters, then calls `permit!`. A `Symbol`/`String` filter only copies a permitted scalar ([`permitted_scalar_filter`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1421-L1436)). A `Hash` filter goes to [`hash_filter`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1442-L1451):

```1442:1466:actionpack/lib/action_controller/metal/strong_parameters.rb
      def hash_filter(params, filter, on_unpermitted: self.class.action_on_unpermitted_parameters, explicit_arrays: false)
        filter = filter.with_indifferent_access
        slice(*filter.keys).each do |key, value|
          next unless value
          next unless has_key? key
          result = permit_value(value, filter[key], on_unpermitted:, explicit_arrays:)
          params[key] = result unless result.nil?
        end
      end

      def permit_value(value, filter, on_unpermitted:,  explicit_arrays:)
        if filter == EMPTY_ARRAY
          permit_array_of_scalars(value)
        elsif filter == EMPTY_HASH
          permit_hash(value, filter, on_unpermitted:, explicit_arrays:)
        elsif array_filter?(filter)
          permit_array_of_hashes(value, filter.first, on_unpermitted:, explicit_arrays:)
        elsif explicit_arrays
          permit_hash(value, filter, on_unpermitted:, explicit_arrays:)
        elsif non_scalar?(value)
          permit_hash_or_array(value, filter, on_unpermitted:, explicit_arrays:)
        end
      end
```

A `nil` result drops the key. `expect` later `require`s that key and raises `ParameterMissing`. `permit` just omits it.

The explicit-array predicate is `filter.is_a?(Array) && filter.size == 1 && filter.first.is_a?(Array)` — the `[[:text]]` spelling. [`each_array_element`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1356-L1363) then accepts either a real `Array` of `Parameters`, or a `Parameters` object whose keys look like nested attributes (`/\A-?\d+\z/` and hash values) unless the filter itself names numeric keys.

```diagram
permit_value(value, filter)
  filter []        ━▶ Array of permitted scalars, else nil
  filter {}        ━▶ Parameters of any nested scalars
  filter [[...]]   ━▶ array of hashes / numeric-key hash
  explicit_arrays  ━▶ Parameters hash only     (expect)
  otherwise        ━▶ hash or array of hashes  (permit)
```

`expect` never reaches the last branch.

### Scalar-versus-hash type confusion

Input: `{ user: "hack" }`.

`params.require(:user).permit(:name)` — `require` returns the string `"hack"`, then `permit` raises `NoMethodError`. That is the failure `expect` exists to avoid ([docs around](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L759-L768) this example).

`params.permit(user: [:name]).require(:user)` — `permit_value` sees a scalar, `non_scalar?` is false, the method returns `nil`, `:user` is omitted, `require(:user)` raises `ParameterMissing`. Same observable exception as `expect`, different path.

`params.expect(user: [:name])` — `explicit_arrays` sends the value to [`permit_hash`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1478-L1486), which returns unless `value.is_a?(Parameters)`. The string is dropped; `require(:user)` raises `ParameterMissing`. Covered by [key to non-scalar: raises ParameterMissing on scalar](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_expect_test.rb#L159-L180).

The inverse confusion is a hash where an array of hashes was intended:

```ruby
params = ActionController::Parameters.new(user: { name: "Martin", pets: { name: "hack" } })
params.require(:user).permit(:name, pets: [:name])[:pets]
## => Parameters { "name" => "hack" } permitted: true
```

`permit` uses `permit_hash_or_array`, so a single hash matches `pets: [:name]`. `expect` with an explicit array does not:

```ruby
params.expect(user: [:name, pets: [[:name]]])[:pets]
## => nil
```

`pets` is a non-numeric-key hash, so [`each_array_element`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1356-L1363) returns `nil`; the key is omitted. The parent `user` hash is still present, so `expect` succeeds and `pets` is simply gone. That is the documented expect behavior, not a `ParameterMissing`.

A hash filter on a scalar key is the same drop: [`key to array: returns only permitted scalar keys`](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_expect_test.rb#L22-L25) keeps `:age` and drops `:name` / `:addresses` because those values are not scalars.

### Multiple filters and return arity

Root keys are `filters.flatten.flat_map { |f| f.is_a?(Hash) ? f.keys : f }`. One collected key unwraps; two or more return an array in that key order.

| Call | Collected keys | Return |
| --- | --- | --- |
| `expect(:a)` | `[:a]` | the scalar/`Parameters` value |
| `expect(:a, :b)` | `[:a, :b]` | `[value_a, value_b]` |
| `expect([:a, :b])` | `[:a, :b]` | same array (`flatten`) |
| `expect(subject: [:name], object: [:pie])` | `[:subject, :object]` | `[subject_params, object_params]` |
| `expect(person: [:name])` | `[:person]` | the inner `person` `Parameters`, not `{ person: ... }` |

Tests: [array of key / array of keys](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_expect_test.rb#L101-L113), [keys to arrays: hash key order](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_expect_test.rb#L40-L44), [chain of keys](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_expect_test.rb#L93-L98).

`permit(*filters)` always returns one `Parameters` covering every listed root. `require(:person)` after that returns only the nested value. Arity of `expect` is therefore “required roots,” not “the filtered hash.”

A permitted empty nested hash still fails `require`: `expect(person: {})` on `{ person: {} }` raises `ParameterMissing` ([key to empty hash](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_expect_test.rb#L182-L191)). `permit(person: {}).require(:person)` raises the same exception; `permit` alone would return `{ "person" => {} }` permitted.
