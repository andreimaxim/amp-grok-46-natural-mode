## Assistant

`Object#with` temporarily overwrites public attributes, yields the receiver, and restores only the attributes whose **readers** already succeeded. Reads and writes are interleaved per keyword, not batched.

### Per-key snapshot, then yield, then restore

The method lives on `Object` in [activesupport/lib/active_support/core_ext/object/with.rb](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb):

```31:43:activesupport/lib/active_support/core_ext/object/with.rb
  def with(**attributes)
    old_values = {}
    begin
      attributes.each do |key, value|
        old_values[key] = public_send(key)
        public_send("#{key}=", value)
      end
      yield self
    ensure
      old_values.each do |key, old_value|
        public_send("#{key}=", old_value)
      end
    end
  end
```

Control flow:

```text
with(**attributes)
  old_values = {}
  begin
    for each [key, value] in attributes   # caller keyword order
      old_values[key] = public_send(key)  # read first
      public_send("#{key}=", value)       # then assign
    end
    yield self                            # block runs only if every assign succeeded
  ensure
    for each [key, old_value] in old_values
      public_send("#{key}=", old_value)   # restore in the same order
    end
  end
```

`old_values` starts empty ([with.rb L32](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L32)). A key is inserted only after its reader returns ([L35](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L35)). The matching write is the next statement ([L36](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L36)). There is no “read all, then write all” pass.

If the first reader raises, `old_values` stays `{}` and `ensure` is a no-op. If a later step raises, `ensure` still runs, but it only walks keys already stored ([L40–L42](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L40-L42)).

Exactly one mutated value is rolled back: **`public_attr` → `:public`**. `mixed_attr` is in `old_values` because its reader ran, but it was never assigned the new value. `ensure` still attempts `mixed_attr=` via `public_send` ([with.rb L41](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L41)); that writer is not public, so that restore call raises `NoMethodError` as well. The test only asserts the raised class and the two final attribute values, not which `NoMethodError` surfaces.

          │
          ▼
read public_attr ──▶ old_values={public_attr: :public}

          │
          ▼

          ▼

### Public reader and public writer are both required

Both the snapshot and the restore go through `public_send` ([L35–L36](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L35-L36), [L41](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L41)). The comment states the same contract ([L29–L30](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L29-L30)).

[L75–L89](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L75-L89) enumerates the failures:

- `private_attr` — private reader and writer ([L23–L24](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L23-L24)) → `NoMethodError` on the read
- `protected_attr` — protected pair ([L20–L21](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L20-L21)) → same
- `mixed_attr` — public reader, private writer → read would succeed; write raises. After that failed `with`, `mixed_attr` is still `:mixed` ([L84–L88](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L84-L88))

A public reader alone is not enough.

### `#with` is removed on common immediates

After defining the method on `Object`, these classes undefine it ([L47–L51](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L47-L51)):

`NilClass`, `TrueClass`, `FalseClass`, `Integer`, `Float`, `Symbol`

The comment: `#with` isn’t usable on immediates, so it is undefined there to avoid confusion. [L100–L107](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L100-L107) checks `nil`, `true`, `false`, `1`, `1.0`, and `:sym` with `assert_not_respond_to`. `String` and other non-immediates keep `Object#with`.
