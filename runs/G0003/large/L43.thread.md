[`routes?`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L706-L708) is just `@routes`. The unit test constructs an engine that leaves `@routes` nil and asserts `routes?` is false ([`railties/test/engine_test.rb`](file:///home/user/workspace/repo/railties/test/engine_test.rb#L6-L14)). Engine with no route file: [`add_routing_paths`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L621-L632) still runs `if routes? || routing_paths.any?`. When the set *is* drawn, [`eval_block`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/route_set.rb#L475-L485) wraps the block:

### Mount helpers and `main_app`

[`Mapper#mount`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/mapper.rb#L605-L667) defaults `:as` to [`app.railtie_name`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/mapper.rb#L701-L708) for a Rails engine — i.e. `engine_name`. Isolation therefore changes the default helper from `my_engine_engine` to `my_engine`.

For a Rails app it then [`define_generate_prefix`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/mapper.rb#L710-L739):

- builds a `script_namer` from the mount’s named route
- [`app.routes.define_mounted_helper(name, script_namer)`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/route_set.rb#L520-L541) on the *engine* route set
- extends the engine route set so `find_script_name` uses that prefix

[`define_main_app_helper`](file:///home/user/workspace/repo/railties/lib/rails/application/finisher.rb#L60-L62) does `app.routes.define_mounted_helper(:main_app)` on the *application* set, with no script namer.

Because every controller includes `app.routes.mounted_helpers`, an isolated engine action can call `main_app.bar_path`, and an application action can call `bukkits.foo_path`. SCRIPT_NAME is composed at helper-call time, not at `isolate_namespace` time. Evidence:

- engine `main_app.bar_path` with `SCRIPT_NAME=/foo` → `/foo/bar` ([`engine_test.rb`](file:///home/user/workspace/repo/railties/test/railties/engine_test.rb#L1659-L1703))
- application `bukkits.bukkit_path` under the same SCRIPT_NAME → `/foo/bukkits/bukkit`
- Blog mounted at `/:user` (default `"anonymous"`) generates `/anonymous/blog/posts` from the app and `/john/blog/posts/1` from inside the engine; Metrics (also isolated) uses `blog.post_path(1)` → `/anonymous/blog/posts/1` ([`mounted_engine_test.rb`](file:///home/user/workspace/repo/railties/test/railties/mounted_engine_test.rb#L220-L268))
- engine mounted at `"/"` keeps `script_name` empty ([`engine_test.rb`](file:///home/user/workspace/repo/railties/test/railties/engine_test.rb#L1609-L1657))

`main_app` is not created by `isolate_namespace`. Isolation only makes it necessary: engine named routes no longer include the application’s.

### Lazy versus eager route loading

[`make_routes_lazy`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L616-L619) (before `:bootstrap_hook`) sets `config.route_set_class = LazyRouteSet` when `Rails.env.local?` (development/test, [`EnvironmentInquirer::LOCAL_ENVIRONMENTS`](file:///home/user/workspace/repo/activesupport/lib/active_support/environment_inquirer.rb#L14-L38)) and then instantiates `routes`.

[`set_routes_reloader_hook`](file:///home/user/workspace/repo/railties/lib/rails/application/finisher.rb#L160-L180) loads immediately when the application set is not a `LazyRouteSet` **or** `config.eager_load` is true. Otherwise the first use loads them.

[`LazyRouteSet`](file:///home/user/workspace/repo/railties/lib/rails/engine/lazy_route_set.rb) calls `Rails.application.reload_routes_unless_loaded` from `call`, `draw`, `recognize_path`, `url_helpers` (`ProxyUrlHelpers`), named-route `method_missing` (only `_path`/`_url`), and a separate [`MountedHelpers`](file:///home/user/workspace/repo/railties/lib/rails/engine/lazy_route_set.rb#L47-L74) that lazy-defines mount helpers but leaves `_path`/`_url` to the named-route module. [`reload_routes_unless_loaded`](file:///home/user/workspace/repo/railties/lib/rails/application.rb#L168-L170) is a no-op until the application is initialized.

[`lazy_route_set_test.rb`](file:///home/user/workspace/repo/railties/test/engine/lazy_route_set_test.rb) pins the externally visible split:

- engine `root_path` is not in `methods` until invoked, then `"/plugin/"`
- `GET /plugin/` loads on the request
- engine `url_for(controller: :posts, ...)` loads
- `mounted_helpers` does not define `:plugin_engine` until use; then `helpers.plugin_engine.posts_path` and `helpers.main_app.root_path`
- after an explicit reload, both `:main_app` and `:plugin_engine` are `method_defined?`
- a plain `RouteSet.new` still uses the shared `MountedHelpers` module with no lazy `method_missing`

Eager path: production, or `eager_load`, runs `execute_unless_loaded` during finish so the same helpers exist before the first request. Isolation does not change that policy; it only supplies `default_scope` and the module hooks that the eventually-loaded set and controllers use.

### Class setup versus request dispatch

| When | What isolation already did | What still happens later |
| --- | --- | --- |
| Engine class body | `engine_name`, `isolated?`, `default_scope`, module methods | no RouteSet, no mount helper, no dispatch |
| Boot | `prepend_helpers_path` skips isolated engine helpers; `make_routes_lazy` allocates the set (possibly `LazyRouteSet`) | routes file not necessarily loaded |
| Route load | `eval_block` applies `scope(module:)`; mappings store `"ns/controller"` | mount defines helpers and script namers |
| Controller/mailer class load | `inherited` includes engine url helpers and helper paths | autoload may defer this until first request |
| Request | Journey looks up the already-compiled controller; `Engine#call` sets `req.routes` and `engine_script_name` | URL helpers / mounted helpers may trigger lazy load, then generate with SCRIPT_NAME |

`isolate_namespace` never looks at the request. The externally visible routing effects — unprefixed engine routes pointing at namespaced controllers, `foo_path` instead of `bukkits_foo_path`, `main_app` / mount proxies, polymorphic names without the engine prefix, and `bukkits_*` tables — are those later phases reading the class-level stamps.
