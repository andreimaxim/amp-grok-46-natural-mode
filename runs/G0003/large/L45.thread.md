### Compatibility

Breaking for every `config.api_only = true` app that did not disable the session store: Cookies enters the default stack. Guide/generator comments become wrong and, if followed, harmful. No changelog/guide updates in the proposed diff.

### Narrower alternative

Do not key Cookies off `config.session_store` while the default initializer always sets CookieStore.

If the product goal is “API-only sessions work from `config.session_store` alone”:

1. Skip `setup_default_session_store` when `api_only` (treat unconfigured API apps as no store).
2. When `config.session_store` is present, insert **Cookies and the session store** in the default slot (including the `force_ssl` secure-cookie assignment). Leave Flash opt-in.
3. Update [`api_app.md`](file:///home/user/workspace/repo/guides/source/api_app.md) and the generator comment so users stop `middleware.use`-ing Cookies/Session.

If the goal is only “don’t run Session without Cookies,” keep the documented opt-in; the current `unless config.api_only` already keeps them paired on full-stack apps.
