The live contract is a two-stage pipeline: `to_plain_text` replaces every `action-text-attachment` via `render_attachments(with_full_attributes: false, &:to_plain_text)`, then `Fragment#to_plain_text` reduces the resulting HTML. Both stages must stay observationally identical. I ran those cases against this checkout; expected forms below are from that run, not from the YARD comments.

# Pipeline

```diagram
ActionText::Content#to_plain_text
  │
  ├─ render_attachments(with_full_attributes: false)
  │     fragment.replace(tag_name) on a duped source
  │       sanitize node["content"] on the dup
  │       yield Attachment.from_node(node)  ← no with_full_attributes merge
  │       node.replace(block_result.to_s)
  │     return Content.new(..., canonicalize: false)
  │
  └─ .fragment.to_plain_text
        PlainTextConversion.node_to_plain_text
```

`#to_html` and the original `fragment` / `fragment.source` are not on this path. Canonicalization (Trix conversion, attachment minification, gallery unwrap) already happened in `Content.new`.

# Observable contract

## `render_attachments`

From [content.rb L99-L107](file:///home/user/workspace/repo/actiontext/lib/action_text/content.rb#L99-L107) and [fragment.rb L34-L47](file:///home/user/workspace/repo/actiontext/lib/action_text/fragment.rb#L34-L47):

- Returns a **new** `Content` with `canonicalize: false`.
- Walks every `ActionText::Attachment.tag_name` node (default `action-text-attachment`).
- If the node has `content`, sanitizes it on the **duped** node; empty-after-sanitize drops the attribute.
- Yields `attachment_for_node(node, **options)`. Default `with_full_attributes: true`; `#to_plain_text` passes `false`.
- Replacement is `block_result.to_s`. Same-node return (`node != replacement` is false) keeps the duped node, which is how HTML rendering fills `inner_html`.
- Does not re-run gallery canonicalization or attachment minification.

`with_full_attributes: false` (this is the `#to_plain_text` contract, [content.rb L216-L219](file:///home/user/workspace/repo/actiontext/lib/action_text/content.rb#L216-L219), [attachment.rb L76-L83](file:///home/user/workspace/repo/actiontext/lib/action_text/attachment.rb#L76-L83)):

- Yielded attachment’s **node** keeps stored attributes only (`sgid`, `caption`, …).
- Attachable is still resolved (`Attachable.from_node`), so blob `filename` / Person records are still available via delegation.
- Returning `attachment.node` therefore does **not** write `filename`, `content-type`, `filesize`, `previewable` onto the replacement.
- `with_full_attributes: true` (default) builds a new node that **does** write those attributes. Observed on this revision: sparse node in, full node out, original `Content` unchanged.

`#to_plain_text` of a blob is the same under both flags because caption is on the node and `[filename]` comes from the attachable, not the node attribute. The flag still matters: a refactor that starts merging full attributes during plain-text conversion would change `#render_attachments`’s HTML result even if the plain string matched.

## Reducer (after replacement)

[plain_text_conversion.rb L9-L100](file:///home/user/workspace/repo/actiontext/lib/action_text/plain_text_conversion.rb#L9-L100):

- `p` / `h1`–`h6`: child text + `\n\n`
- `div`: child text + `\n`
- `br`: `\n`
- `blockquote`: wrap first/last non-whitespace with `“` `”`; whitespace-only → `“”`
- `ul`/`ol`/`li`: `• ` or `n. `, nested lists indented two spaces per extra depth
- `figcaption`: `[child text]`
- `script` / `style`: `""`
- other elements: concatenate children
- trailing newlines stripped at the end
- text nodes keep non-linebreak whitespace; entities are **decoded** in the returned String

The YARD line “HTML entities encoded” is wrong relative to this revision. The example at [content.rb L128-L130](file:///home/user/workspace/repo/actiontext/lib/action_text/content.rb#L128-L130) is the contract: `"<script>alert()</script>"`, not HTML-safe (`html_safe? == false`).

Stale conflict: [rich_text.rb L26](file:///home/user/workspace/repo/actiontext/app/models/action_text/rich_text.rb#L21-L26) claims `safe<script>` → `"safeunsafe"`. Live `Content#to_plain_text` on this revision is `"safe"`. Preserve `"safe"`.

# Mutation checks (every fixture)

On the **same** `content` object, before and after `to_plain_text` / `render_attachments`:

1. `content.to_html` byte-identical to the pre-call snapshot.
2. `content.fragment.equal?(original_fragment)`.
3. `content.fragment.source.equal?(original_source)` — `Fragment#replace` must keep duping ([fragment.rb L34-L47](file:///home/user/workspace/repo/actiontext/lib/action_text/fragment.rb#L34-L47)).
4. `content.to_plain_text` is pure: second call equals first.
5. `render_attachments` result is a different object; `canonicalize: false` so a block that inserts non-canonical markup survives (markdown test).
6. Sanitizing `content="<script></script>"` in the block must drop the attribute on the **result** only. Observed original stayed `content="<script></script>"`; result was `<action-text-attachment sgid="123"></action-text-attachment>`.

Do not assert `to_s` / `to_rendered_html_with_layout` equality as a substitute: those sanitize. The stored canonical HTML is `to_html`.

# How to judge the refactor

A change is behavior-preserving iff:

1. Every exact string in the tables still matches.
2. Mutation triples still hold.
3. `with_full_attributes: false` still yields a sparse node even if plain strings would match under `true`.
4. Galleries remain concatenated sibling replacements inside a `div`, not a separate gallery renderer.
5. Duplicates remain two replacements.
6. Neighbor tests above stay green.

I assumed the refactor keeps the public methods and only rewrites internals; if `render_attachments`’s `canonicalize: false` or content-attribute sanitization were considered out of scope, the markdown and Trix sanitization tests would still fail and should stay in the neighbor set.
