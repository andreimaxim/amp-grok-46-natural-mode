`ActionController::Live#send_stream` is a header + yield + always-close wrapper around `response.stream`. Live’s thread, commit, and disconnect behavior lives in `Live#process` and `Live::Buffer`. A behavior-preserving suite should pin those public effects, not private method shape.

## Runtime contract to preserve

```diagram
request thread                         live pool thread
──────────────                         ────────────────
Live#process
  copy Thread locals
  post to CachedThreadPool ─────────▶ share IsolatedExecutionState
  await_commit                        super(action)
       ▲                                send_stream
       │                                  instrument start
       │                                  set Content-Type / Content-Disposition
       │                                  yield response.stream
       │                                    Buffer#write ──commit!──▶
       │                                    …chunks via SizedQueue…
       │                                  instrument finish (even on raise)
       │                                  ensure: stream.close (nil terminator)
       │                                rescue:
       │                                  uncommitted → stash error, re-raise after await
       │                                  committed   → optional HTML trailer, on_error, log, close
       │                                ensure: clear copied locals, commit!
Rack/test drains body.each
client drop → RackBody#close → Buffer#abort
```

Source of truth: [`live.rb`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/live.rb) (`send_stream` at 397–411, `process` at 322–364, `Buffer` at 197–288). Existing coverage lives mainly in [`live_stream_test.rb`](file:///home/user/workspace/repo/actionpack/test/controller/live_stream_test.rb); disconnect/buffer races also in [`live_response_test.rb`](file:///home/user/workspace/repo/actionpack/test/dispatch/live_response_test.rb).

Do not spy on `new_controller_thread`, `clean_up_thread_locals`, `each_chunk`, or payload mutation inside `send_stream`. Observe headers, body chunks, `closed?` / `committed?` / `sent?`, notifications, exceptions, and in-action thread state.

## Test seams (use these, not internals)

| Seam | What it is allowed to see |
|---|---|
| `ActionController::TestCase` action that calls `send_stream` | Headers, concatenated body, stream/response predicates after `get` |
| Same class with `original_new_controller_thread` restored (already in `LiveStreamTest#setup`) | Real pool thread, copied locals, concurrent reader |
| `response.await_commit` + `response.to_a` / `body.each` + `body.close` | Chunk order, client abort (`RackBody#close` → `Buffer#abort`) |
| `ActiveSupport::Notifications.subscribed` (start/finish or `capture_notifications`) | Event name, payload, timing vs first write / vs `close` |
| Direct `Live::Response` + `response.stream` | Buffer write/abort/close only; not a `send_stream` substitute |
| `ActionDispatch::Http::ContentDisposition.format` | Oracle for the disposition string `send_stream` must emit |

`ActionController::TestCase` inlines the live thread and sets `Buffer.queue_size = nil`. Any check that depends on a second thread, backpressure, or disconnect must keep `LiveStreamTest`’s restore of `original_new_controller_thread`. Restore `Buffer.queue_size` when a test sets it.

## Checks

### 1. Inferred content type

**Seam.** `get` of `send_stream(filename: "sample.csv")` with `type` omitted (existing `send_stream_with_inferred_content_type`). Add the two fallbacks the method actually implements: unknown extension (`"file.unk"`) and no extension (`"export"`).

**Assert.** `headers["Content-Type"]` is a `String` equal to `"text/csv"`, or `"application/octet-stream"` for the fallbacks. Do not assert `Mime` objects. Do not read the private lookup call.

**Sync.** None. `get` + `response.body` is enough; first write/close commits before the test sees headers.

### 2. Explicit content type (symbol and string)

**Seam.** Existing `type: :csv` and `type: "text/csv"` actions; keep `type: :json` from `send_stream_with_options`.

**Assert.** Header is the resolved string (`"text/csv"`, `"application/json"`), class `String`. Pin that a string is used as-is and is not re-looked-up. Observed current behavior for an unregistered symbol: `Mime[type].to_s` is `""`, which is truthy, so `Content-Type` is `""` rather than the octet-stream fallback — pin it only if you want that exact branch preserved; it is not in the RDoc.

**Sync.** None.

### 3. RFC-compatible filename disposition

**Seam.** `send_stream` actions with (a) ASCII `"attachment"` default, (b) `"inline"`, (c) a non-ASCII filename (reuse cases from [`content_disposition_test.rb`](file:///home/user/workspace/repo/actionpack/test/dispatch/content_disposition_test.rb)).

**Assert.** Exact header, not `assert_match` on the raw filename:

```text
ActionDispatch::Http::ContentDisposition.format(disposition:, filename:)
```

That is `disposition; filename="…"; filename*=UTF-8''…` (RFC 6266 / 5987). Match [`send_file_test.rb`](file:///home/user/workspace/repo/actionpack/test/controller/send_file_test.rb) (`filename=` plus `filename*=`), not the current live tests’ substring checks, which would still pass if one form were dropped.

**Sync.** None. Header is set before yield, so it is visible after `await_commit` even if the body is unread.

### 4. Chunk order

**Seam.** `send_stream` block that `write`s/`writeln`s several distinct chunks. Consume with a reader thread: `resp.await_commit` then `resp.stream.each` (pattern: `test_async_stream` / `live_response_test.rb#test_parallel`). Include at least one `writeln` without a trailing newline (`"world"` → `"world\n"`).

**Assert.** Chunk sequence equals write order. Concatenated body equals the same bytes. `writeln` does not double an existing `"\n"`. Do not assert queue size or `Monitor` internals.

**Sync / cleanup.** `CountDownLatch` (or equivalent) between each expected chunk and the next write if you need to prove order under a live producer, not just the drained string. `assert thread.join(timeout)`. `ensure` `reader&.kill`. If you fill the default 10-slot `SizedQueue`, set `Buffer.queue_size` and restore it; otherwise leave the test-case unlimited queue so the producer cannot block the test thread.

### 5. Exception before commit

Two different public behaviors; both must stay.

**A. Controller raises with no write and no `send_stream` (existing `exception_in_controller`).**  
**Seam.** `get` that action.  
**Assert.** The original exception is re-raised on the test/request thread (`assert_raises`). That is `Live#process`’s uncommitted path (`error = e` then `raise error` after `await_commit`).

**B. Raise inside the `send_stream` block before any `write`.**  
**Seam.** Action: `send_stream(...) { raise ... }`.  
**Assert (observed current order, not an idealization):** `instrument` finishes with `:exception` / `:exception_object`; `ensure` still `close`s, and `close` **commits**. `Live#process` therefore takes the *committed* path: exception is **not** re-raised to `get`, stream ends closed, HTML format may append `ActionView::Base.streaming_completion_on_exception`. Pin that combination; a refactor that closed without committing, or that re-raised to the request thread, would be a behavior change.

**Sync.** `capture_log_output` if you assert the fatal log. After `get`, `assert_stream_closed`. No extra threads.

### 6. Exception after commit

**Seam.** `send_stream` block: `stream.write ""` (or any byte) then `raise`. Mirror `exception_in_view_after_commit` / `exception_with_callback`.

**Assert.** `get` does not re-raise. HTML: body ends with the streaming completion script; other formats: no extra trailer from that helper. `on_error` still runs if registered on `response.stream`. Logger receives the original exception. Stream closed, response committed and sent. Notification still emitted (see §10) with exception payload.

**Sync.** Drain `response.body` so the reader is not left in `each_chunk`. `assert_stream_closed`. Keep logger restore in `ensure`.

### 7. Client disconnect, `ignore_disconnect` false (default)

**Seam.** `send_stream` block that writes, then keeps writing after the client is gone. Reader: `await_commit`; `_, _, body = resp.to_a`; `body.each { body.close; break }`. That is `RackBody#close` → `Response#abort` → `Buffer#abort` (`@aborted`, queue cleared, nil terminator). Next `write` raises `ActionController::Live::ClientDisconnected`.

**Assert.** Producer surfaces `ClientDisconnected` (via `on_error`, log, or a latch set from `rescue` inside the action). Further chunks are not delivered. Stream still closed — `send_stream`’s `ensure` and/or `process`’s committed-exception `ensure` both call `close`. Duplicate nil terminators are harmless; do not assert queue contents.

**Sync / cleanup.** Two latches: one after first chunk (reader may abort), one for producer-side error/completion. `Timeout.timeout` on waits. `t.join` with timeout. `ensure`: `reader&.kill`, restore logger, restore `Buffer.queue_size` if you used the full-buffer variant (`test_abort_with_full_buffer`). Never `sleep` to “wait for disconnect.”

### 8. Client disconnect, `ignore_disconnect` true

**Seam.** Same reader abort, but `response.stream.ignore_disconnect = true` before or at the start of the `send_stream` block (existing `ignore_client_disconnect`, moved through `send_stream` so `ensure close` still runs).

**Assert.** Producer does **not** raise. Post-abort `write`s return bytesize and are discarded (`connected?` is false). Producer can finish and log/latch “work complete”. Stream closed afterward. Notification still finishes (block returned normally).

**Sync.** Latch counted down only after the ignored writes. `Timeout.timeout(3)` around `latch.wait`, as today. Join the reader. If ignored writes would fill a 10-slot queue, either abort before filling or keep `queue_size` nil so the producer cannot block forever on `SizedQueue#push`.

### 9. Stream closure on every path

**Seam.** One `send_stream` action per path; after the request, `assert_stream_closed` (stream `closed?`, response `committed?` and `sent?`).

Paths to hit:

- normal yield + writes
- yield with zero writes (close alone commits)
- exception before write (path 5B)
- exception after write (path 6)
- disconnect, ignore false and true (paths 7–8)
- `on_error` that itself raises (`exception_in_exception_callback` analog)

**Assert.** Closed on all of the above. Do not assert how many times `close` ran. A second `close` after `abort` must not leave a reader blocked (`test_close_then_abort_still_terminates_the_reader` is the Buffer-level analog; keep it).

**Sync.** Any test that opens `body.each` must abort or close the body in `ensure`. Otherwise `each_chunk` waits on `@buf.pop` and the suite hangs.

### 10. Copied thread-local state

`send_stream` does not spawn the thread; `Live#process` does. The refactor must not start running the block on the request thread or drop the copy.

**Seam.** `LiveStreamTest` (real `original_new_controller_thread`) action whose `send_stream` block asserts:

- `Thread.current[:setting]` equals the value set on the request thread (`test_thread_locals_get_copied`)
- `ActiveSupport::CurrentAttributes` / `IsolatedExecutionState` values visible inside the block (`test_isolated_state_get_copied`)
- after the action, a *later* request on a reused pool thread does not see leftover locals (`test_thread_locals_get_reset`, `test_isolated_state_get_reset`)
- fiber isolation level still copies (`test_isolated_state_with_isolation_level_fiber`)
- `live_streaming_excluded_keys` still omits listed keys (`test_connected_to_stack_not_inherited`) and default remains inherit-all

**Assert.** Those values **inside the `send_stream` block**, plus `assert_stream_closed`. Do not assert `t1.keys` or `share_with` arguments.

**Sync / cleanup.** Restore `IsolatedExecutionState.isolation_level`, `live_streaming_excluded_keys`, and `IsolatedExecutionState.delete` / `.clear` in `ensure`. Assertions inside the action should use the test case (`tc.assert_*`) so a failure on the pool thread is `abort_on_exception` rather than a silent mismatch after `join`.

`LiveControllerThreadTest` pins the opposite: in the default test-case environment (inline thread, no local cleanup), request-thread locals are not cleared. Do not “fix” that while verifying a `send_stream` refactor.

### 11. Notification payload and timing

**Seam.** `ActiveSupport::Notifications.subscribed` around `get`, not only `assert_notification`. Existing `test_send_stream_instrumentation` is too weak: it passes `type: "text/csv"` which equals both the argument and the header.

**Assert.**

- Name: `"send_stream.action_controller"`.
- Payload subset is the **arguments**, not the resolved header: `{ filename:, disposition:, type: }` where `type` may be `nil`, `:json`, or `"text/csv"`. `assert_notification` is subset-match; pin `payload[:type]` exactly so a refactor that overwrites it with `"application/json"` fails.
- Exactly one event per `send_stream` (`assert_notifications_count`).
- Timing: subscribe to start/finish (or record `event.time` / `event.end`). Start occurs before the first `stream.write` is visible to a reader waiting on `await_commit`. Finish occurs after the user block returns and **before** the test can observe a post-close state if you order a `close`-detecting probe inside the block’s last line vs after `get` — more robust: in the action, write a chunk, then return; the finish callback must have run before `send_stream` returns to `process`, while `stream.closed?` is still false until `ensure`. A monotonic subscriber that records `[:start, :write, :finish, :closed]` from (1) notification start, (2) first `body.each` chunk, (3) notification finish, (4) a `stream.on_error`/`close` probe is enough if you only assert `start` before first chunk and `finish` after the block. Do not require `finish` after `close`; current code finishes the instrumenter **then** closes.
- On raise inside the block: event still published; payload includes `:exception` (`[class_name, message]`) and `:exception_object` (Notifications instrumenter contract). Duration still covers header setup + block.

**Sync.** Register the subscriber **before** `get`. `subscribed` already unsubscribes in `ensure`. If you correlate with chunks, wait on `await_commit` in the reader so you do not race the child thread. Do not assert wall-clock duration.

## Cross-cutting anti-flake rules

- Prefer `CountDownLatch` + `Timeout.timeout` + `join(seconds)` over `sleep`.
- `await_commit` before any `each` / `to_a`.
- Every spawned reader: `ensure reader&.kill`.
- Restore `Buffer.queue_size`, logger, `IsolatedExecutionState`, `live_streaming_excluded_keys`, isolation level.
- Keep `Thread.abort_on_exception = true` (already file-level).
- Do not fill the 10-slot queue unless the test is specifically about blocking write + abort; unlimited queue in `TestCase` is the default for a reason.
- `get` in `TestCase` calls `@response.sent!` after dispatch; `assert_stream_closed`’s `sent?` is about that, not about the live body having finished unless you also drain `response.body`.
- Treat `send_stream`’s `ensure close` as part of the commit/exception story, not as an implementation detail you can ignore when classifying “before commit.”

Existing send_stream tests already cover happy-path types and a single notification payload. The gaps that actually protect an internal refactor are: exact RFC disposition, argument-vs-resolved notification `type`, finish-before-close ordering, send_stream-block exceptions (commit via `ensure`), disconnect through the yielded stream with both `ignore_disconnect` values, and thread-local assertions **inside** the `send_stream` block on the real live pool thread.
