### What a green run actually means

The six methods above are the regression net for this refactor:

```bash
cd activesupport && bin/test test/time_zone_test.rb -i "/test_local$|test_local_with_old_date|test_local_enforces_spring_dst_rules|test_local_enforces_fall_dst_rules|test_local_with_ambiguous_time/"
```

That command is necessary and not sufficient. Today it checks 22 assertions. Gaps:

- Hawaii 2007 never asserts `.utc`, `.zone`, or `.dst?`.
- Hawaii 1850 never asserts `.utc` or `"LMT"`.
- Moscow 2014 never asserts `.time`, `.zone`, or `.dst?`.
- Eastern `02:00` is also covered via `TimeWithZone.new(nil, zone, Time.utc(...))` in `time_with_zone_test.rb`; `02:30` is only on `#local`.

A behavior-preserving refactor of `#local` / the nil-`utc_time` constructor should add those missing four-surface asserts on the same methods (or adjacent `test_local_*` methods) before changing code. Do not fold Eastern fall-back and Moscow into one “ambiguous → DST” rule: source uses `dst=true` then `periods.last`, and the two cases select opposite periods.

Related but out of this net: `#now`, `#iso8601`, `#parse`, and `+/-` on an already-constructed `TimeWithZone` ([`test_now_enforces_*`](file:///home/user/workspace/repo/activesupport/test/time_zone_test.rb#L104-L125), [`test_plus_and_minus_enforce_*`](file:///home/user/workspace/repo/activesupport/test/core_ext/time_with_zone_test.rb#L474-L504)). They share DST policy but not the `#local` → `new(nil, zone, Time.utc(*args))` path.

No implementation changes in this turn. Next step, if you want it, is to add the unlocked UTC/abbr/DST asserts on the Hawaii, Moscow, and 1850 methods before touching `#local`.
