## Assistant

The public contract is loader ownership and reload/eager-load behavior, not how Railties concatenates arrays. Treat path-array order as private unless two roots would otherwise define the same constant.

### What “no externally observable change” means

After boot, a path is observable only as:

- which Zeitwerk loader roots it (`Rails.autoloaders.main.dirs` vs `.once.dirs`)
- whether its constants survive `Rails.application.reloader.reload!`
- whether production/`config.eager_load` defines them before first use
- whether it appears in `$LOAD_PATH`
- whether mutation of the config/Dependencies arrays raises `FrozenError` after the documented freeze points

Do not oracle on `_all_autoload_paths` memoization, `unshift` order across engines, or `assert_equal` of full `dirs` arrays. Those are assembly accidents. The existing order-sensitive tests in [railties/test/application/zeitwerk_integration_test.rb](file:///home/user/workspace/repo/railties/test/application/zeitwerk_integration_test.rb) (`autoload_paths not in autoload_once_paths are set as root dirs of main, and in the same order` and `autoload_once_paths go to the once autoloader, and in the same order`) are regression tripwires, not the contract.

Assembly to preserve, not to re-assert as arrays:

```text
config.all_autoload_paths       = custom autoload_paths      + paths.autoload_paths
config.all_autoload_once_paths  = custom autoload_once_paths + paths.autoload_once
config.all_eager_load_paths     = custom eager_load_paths    + paths.eager_load

_all_autoload_once_paths = uniq(all_autoload_once_paths)
_all_autoload_paths      = uniq(all_autoload ∪ all_eager − all_once)
_all_load_paths          = uniq(paths.load_paths
                                ∪ (autoload ∪ autoload_once if add_autoload_paths_to_load_path))
```

Sources: [railties/lib/rails/engine/configuration.rb](file:///home/user/workspace/repo/railties/lib/rails/engine/configuration.rb#L121-L135), [railties/lib/rails/engine.rb](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L596-L769), [railties/lib/rails/paths.rb](file:///home/user/workspace/repo/railties/lib/rails/paths.rb#L85-L110).

### Invariants (derived, not restated as implementation)

**I1 — custom + `paths`, computed at initializer time.** `all_*` are methods, not cached on Configuration. Mutating `config.paths` after reading `config.autoload_paths` still takes effect (issue 49629). Custom entries precede `paths.*` in the concatenated array; that order is not a public promise.

**I2 — once wins over main for a given engine.** `_all_autoload_paths` subtracts `all_autoload_once_paths`. A directory listed as both autoload and once is a once root. `ActiveSupport::Dependencies` documents that the two collections may intersect and that the intersection is not reloaded ([activesupport/lib/active_support/dependencies.rb](file:///home/user/workspace/repo/activesupport/lib/active_support/dependencies.rb#L48-L62)); the engine assembler tries to keep them disjoint per engine.

**I3 — eager implies autoload unless once.** Eager-only dirs are merged into main autoload. Eager+once dirs stay on `once` and are *not* `do_not_eager_load`’d ([railties/lib/rails/application/bootstrap.rb](file:///home/user/workspace/repo/railties/lib/rails/application/bootstrap.rb#L101-L121)).

**I4 — freeze points.**

| Collection | Frozen in | After which you may observe FrozenError |
|---|---|---|
| `config.autoload_paths`, `config.autoload_once_paths` | engine `:set_autoload_paths` | any initializer after that engine’s `:set_autoload_paths` |
| `config.eager_load_paths` | engine `:set_eager_load_paths` | same |
| `Dependencies.autoload_once_paths` | `:setup_once_autoloader` (before `:bootstrap_hook`) | initializers after bootstrap |
| `Dependencies.autoload_paths` | `:setup_main_autoloader` (Finisher) | after full init |

`Dependencies._eager_load_paths` is a Set and is **not** frozen. `all_*` return fresh arrays and are not frozen.

**I5 — once is live during initialization; main is not.** `:setup_once_autoloader` runs after `:set_eager_load_paths` and before `:bootstrap_hook`. `:setup_main_autoloader` is a Finisher. Constants in once dirs must resolve from `config/initializers` and from initializers after `:bootstrap_hook`. App/engine `app/*` constants must not be required to resolve that early.

**I6 — loader push rules.** Existing directories only; skip dirs already on that loader (custom namespaces). `do_not_eager_load(path)` unless `Dependencies.eager_load?(path)`. User `push_dir(..., namespace:)` is not overwritten.

**I7 — reload vs once.** `main.enable_reloading` iff `config.reloading_enabled?`. `once` never reloads. `Dependencies.clear` / `reloader.reload!` call `main.reload` only. `watchable_args` watches `main.dirs` only ([railties/lib/rails/application.rb](file:///home/user/workspace/repo/railties/lib/rails/application.rb#L458-L465)).

**I8 — `$LOAD_PATH`.** `:set_load_path` unshifts existent dirs from `_all_load_paths`, then `$LOAD_PATH.uniq!`. With `config.add_autoload_paths_to_load_path = false` (7.1+ default), autoload/eager dirs stay off `$LOAD_PATH`. `lib` is still on `$LOAD_PATH` via `Application.add_lib_to_load_path!` and `paths["lib"]` `load_path: true`. Vendor too if it exists.

**I9 — engines and the application both contribute.** Every `Rails::Engine` (including the app) runs `:set_load_path` / `:set_autoload_paths` / `:set_eager_load_paths` and `unshift`s its own sets. Engine `app/models` etc. are first-class autoload roots, not a special case.

**I10 — eager production vs development reload.** Production `Zeitwerk::Loader.eager_load_all` plus `Rails.eager_load!` defines eager constants before first reference. Once dirs *not* in `_eager_load_paths` stay lazy. If `eager_load && reloading_enabled?`, Finisher registers `after_class_unload { Rails.autoloaders.main.eager_load }` so a reload re-eager-loads **main only**.

|---|---|---|
| Loader ownership | `assert_includes loader.dirs, absdir`; disjointness `main.dirs ∩ once.dirs` empty for dirs you added | `assert_equal deps.autoload_paths, main.dirs` (order + mailer-preview + missing-dir noise) |
| Constant identity (once) | `assert_same before, after_reload` | file mtime / inode |
| Constant identity (main) | `assert_not_same before, after_reload`; same name still `const_defined?` after edit | |
| Constant removal | `assert_not Object.const_defined?(:X)` after delete+reload; `assert_raises(NameError) { X }` | `remove_const` internally |
| `$LOAD_PATH` | membership / disjointness of specific dirs | position, `uniq!` call count |
| Callbacks | once `on_unload` count `0`; main `> 0`; eager-load body counter `1→2` when `eager_load` in development | exact `to_run` arity, hook order vs i18n |
| Errors | `FrozenError` on post-init `<<`; `Zeitwerk::Error` on overlapping roots if that is current; `NameError` for removed main const; `LoadError` for `require` of autoload-only file when flag is false | exact exception messages |
| Types | Pathname in `eager_load_paths` still eager-loads ([load_path_test.rb](file:///home/user/workspace/repo/railties/test/application/initializers/load_path_test.rb) already) | that `eager_load?(path)` matches Pathname vs String internally |

### How to avoid private-ordering tests

1. Membership (`assert_includes` / `assert_not_includes`) on `loader.dirs`, `Dependencies.*`, `$LOAD_PATH`.
2. Prove once-vs-main with **reload identity**, which is the user-visible meaning of “once.”
3. If two relative orders could change (engine unshift vs application unshift), pick constants that exist in only one root so order cannot affect resolution.
4. When existing tests use `assert_equal existing_autoload_paths, main.dirs`, keep them as optional extras: a green run there is nice; a failure is only a behavior change if a corresponding constant/reload/`$LOAD_PATH` probe also fails. Gate a refactor on the probes, not on slice equality.
5. `uniq` is observable as “push_dir not called twice” (no Zeitwerk double-root error, `dirs` count 1), not as array index of the survivor.

Assumptions: the refactor stays inside Railties path assembly / initializer wiring and does not change Zeitwerk. Probes above are specified, not added to the tree. I did not run the listed tests in this checkout.
