### 1. Record state: persisted, new, destroyed, readonly

**Persisted.** `record = Topic.first` (or `Developer`/`Person` as needed). `#touch` returns a truthy value and does not raise. `updated_at` on the instance moves forward; `Topic.find(record.id).updated_at` matches. `persisted?` stays true.

That pair — instance reader plus a second find — is the persistence contract. In-memory assignment alone is not.

**New.** `Company.new.touch` (or `Topic.new.touch`) raises `ActiveRecord::ActiveRecordError` whose message says a new or destroyed record cannot be touched. `new_record?` stays true. No row appears. No `after_touch`. Existing test: `test_touch_should_raise_error_on_a_new_object`.

**Destroyed.** `topic.destroy` then `topic.touch` raises the same error as new. `destroyed?` stays true. `Topic.find_by(id: topic.id)` stays gone. No `after_touch`. This is the same `persisted?` gate as new; it is not currently given its own test, so it must be asserted directly. Do not infer it from the new-record case.

**Readonly record.** `developer.readonly!` then `developer.touch` raises `ActiveRecord::ReadOnlyRecord` with `"Developer is marked as readonly"`. Timestamps on a second find are unchanged. Existing test: `test_cant_touch_readonly_record`.

**Readonly attribute** (adjacent, same method). `Person.find(1).touch(:born_at)` raises `ActiveRecord::ActiveRecordError` with `"born_at is marked as readonly"`. Other columns on a second find are unchanged. Existing test: `test_cant_touch_readonly_column`.

`no_touching` is a silent skip, not an error: timestamps, dirty/saved-change sets, and `after_touch` all stay put. That is a different public branch (`test_touching_a_no_touching_object`, `test_no_touching_with_callbacks`).

### 2. Default timestamp columns, custom names, aliases

**Default `updated_at` / `updated_on`.** On a model whose table actually has those columns (`Topic`, `Person`), `#touch` with no names changes both that exist, and does not change `created_at` / `created_on`. Prove it with the instance readers and with `Model.find(id)` (or `reload` on a clone, not the same object if you also care about in-memory dirtiness).

**Aliased timestamps.** `Developer` maps `updated_at` → `legacy_updated_at` and `updated_on` → `legacy_updated_on`. After `#touch`:

- `developer.updated_at` / `updated_on` (alias readers) move
- `saved_changes.keys` are the real column names `"legacy_updated_at"`, `"legacy_updated_on"`
- a raw read of `legacy_updated_at` / `legacy_updated_on` matches

`developer.touch(:updated_at)` is the same write, not a second column. That is `test_touching_a_record_updates_its_timestamp` and `test_touching_update_at_attribute_as_symbol_updates_timestamp`.

**Custom attributes.** `task.touch(:ending)` and `task.touch(:starting, :ending)` set those columns to the touch time *and* still set default update timestamps when the table has them. Observe `task.ending`, `task.starting`, and the timestamp readers, then a second find. Existing tests: `test_touching_an_attribute_updates_it`, `test_touching_many_attributes_updates_them`, `test_touching_an_attribute_updates_timestamp`.

**No timestamp columns and no names.** `Car.first.touch` (or equivalent) does not raise. That is `test_touching_a_record_without_timestamps_is_unexceptional`. If you need a true no-column model, use a table with neither `updated_at`/`updated_on` nor names; the public result is a truthy return and no UPDATE.

**Default scope must not hide the row.** A persisted record that a default scope would exclude still has its row updated (`DeveloperCalledJamis` / `test_touching_a_record_with_default_scope_that_excludes_it_updates_its_timestamp`). That is persistence identity, not “no row updated.”

### 3. Explicit `time:`

`record.touch(time: t)` and `record.touch(:created_at, time: t)` write `t` to every touched column, including default update timestamps. Equality on the instance and on a second find establishes it (`test_touching_updates_timestamp_with_given_time`, `test_touching_an_attribute_updates_timestamp_with_given_time`).

Without `time:`, bound the write with `travel` or `assert_in_delta Time.now, ...`. Do not read `current_time_from_proper_timezone`.

`time:` is one value for all names. There is no public per-column time.

### 4. Optimistic locking

On `Person` (has `lock_version`):

**Successful touch.** `lock_version` increases by 1 in memory and in the database. `changed?` is false. `saved_changes` includes `"lock_version"` and `"updated_at"`. `test_touch_existing_lock`.

**Stale instance.** Update the same id through another instance, then `stale.touch` raises `ActiveRecord::StaleObjectError` (`attempted_action` is `"touch"` if you read the message: `"Attempted to touch a stale object: Person."`). `saved_changes?` is false. In-memory `lock_version` is left as it was before the call. `test_touch_stale_object`.

**`preserve_lock_version_on_touch`.** Inside the block, `#touch` still updates `updated_at` but does not bump `lock_version`, does not raise on a stale row, and `saved_changes` is only `["updated_at"]`. Outside the block, the bump returns. Those are `test_preserve_lock_version_on_touch_*`.

Locking is a public write of `lock_version` plus the stale exception. Do not assert that the locking column was appended to a private name list.

### 5. Dirty tracking and saved changes

Setup a persisted record with an unsaved attribute change that is not a touch target (`developer.salary += 1`), then `#touch`.

Public contract, from `test_touching_a_record_updates_its_timestamp`:

- Unrelated dirt stays dirty: `salary_changed?`, `changed?`, `changed == ["salary"]`
- Touched columns are not dirty: `updated_at_changed?` is false
- `saved_changes?` is true and `saved_changes` contains only the touched persisted columns (aliases appear under real names)
- `reload` restores the unsaved attribute (`salary`); touch did not write it

So `#touch` persists only the touch set, then records that set as saved changes, without clearing unrelated in-memory dirt. `changes_applied` is not an observation.

On a clean record, `#touch` leaves `changed?` false and `saved_changes` equal to the touch set (`test_touching_an_attribute_updates_timestamp`).

On stale/lock failure, `saved_changes?` stays false (`test_touch_stale_object`). That is the dirty contract for the failed path.

### 6. `after_touch`, `after_commit`, `after_rollback`

Register counters on a dedicated subclass. Also register `before_validation`, `after_save`, and `after_update` — they must not run. That last check is the documented “only `after_touch`, `after_commit`, and `after_rollback`” clause.

**`after_touch`.** Runs on a successful persisted `#touch`, once, inside the implicit transaction (it can see the new timestamps; it must not see a committed-only side effect as already committed). Does not run for new, destroyed, readonly, or `no_touching`. Does not run when `StaleObjectError` is raised. `Topic#after_touch_called` and `test_no_touching_with_callbacks` already use this counter.

**`after_commit` / `after_update_commit`.** A successful `#touch` of a persisted row is an update commit: history is `[:commit_on_update]`, not create/destroy. Nested `requires_new` does not fire until the outermost commit. `test_only_call_after_commit_on_update_after_transaction_commits_for_existing_record_on_touch`, `test_only_call_after_commit_on_top_level_transactions`.

**`after_rollback` / `after_rollback on: :update`.**

```ruby
Topic.transaction do
  record.touch
  raise ActiveRecord::Rollback
end
```

History is `[:rollback_on_update]`. DB timestamps match the pre-touch second-find snapshot. In-memory state follows whatever `restore_transaction_record_state` already does for updates — observe readers, do not inspect the restore helper. `test_only_call_after_rollback_on_update_after_transaction_rollsback_for_existing_record_on_touch`.

Bare `after_commit` / `after_rollback` without `on:` follow the same commit vs rollback split. `on: :create` / `on: :destroy` must stay silent.

### 7. No row updated

This is not “default scope excludes the record” (that path still updates). Force `UPDATE` to return 0 while the instance still reports `persisted?`:

```ruby
record = Topic.find(id)          # no locking
Topic.delete(record.id)          # or equivalent unscoped delete
record.touch                     # instance still persisted?
```

**Without optimistic locking**, public contract:

- No exception; return value is truthy (`0` is truthy in Ruby, so the implicit transaction still commits)
- `after_touch` still ran (the callback wrapper does not key off affected rows)
- `after_update_commit` / bare `after_commit` did **not** run — those key off “exactly one row”
- Instance timestamps were assigned; a find by id returns `nil` (or the old row if you used a WHERE miss other than delete)
- Unrelated dirty attributes remain dirty; `saved_changes` still reports the touch set if the write path completed

**With optimistic locking** (`Person.delete(person.id)` then `person.touch`, or a true stale `lock_version`):

- `ActiveRecord::StaleObjectError`, action `"touch"`
- `after_touch` did not run
- `saved_changes?` is false
- `lock_version` reader equals the pre-call value
- `after_rollback on: :update` is not implied: the update-trigger flag is only set after a returning write, so a raise may produce no update transactional callbacks. Assert the callbacks you registered; do not assume `on: :update` fired.

Preserve-lock-version-on-touch plus a missing row is the remaining public corner: no `StaleObjectError`, timestamps assigned, lock column unchanged, update commit callbacks still require `affected_rows == 1`.
