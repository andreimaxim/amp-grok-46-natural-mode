`Object#with` is a per-attribute read-then-write around a `begin`/`ensure`. It never snapshots all attributes first. It yields the receiver, returns the block’s value, and restores only keys that made it into `old_values`.

The method lives on `Object` in [`activesupport/lib/active_support/core_ext/object/with.rb`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb):

```31:43:activesupport/lib/active_support/core_ext/object/with.rb
  def with(**attributes)
    old_values = {}
    begin
      attributes.each do |key, value|
        old_values[key] = public_send(key)
        public_send("#{key}=", value)
      end
      yield self
    ensure
      old_values.each do |key, old_value|
        public_send("#{key}=", old_value)
      end
    end
  end
```

## Assignment order

`**attributes` is insertion-ordered. For each pair the method:

1. Reads the current value with `public_send(key)` and stores it in `old_values[key]` ([with.rb:35](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L35)).
2. Writes the replacement with `public_send("#{key}=", value)` ([with.rb:36](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L36)).

Then it moves to the next pair. It is not “read all, then write all.” After a two-key call `with(a: x, b: y)` the order is: read `a`, write `a`, read `b`, write `b`. Only then does it `yield self` ([with.rb:38](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L38)).

If a reader raises, that key is never inserted, later keys are not touched, and `ensure` has nothing for that key. If a writer raises, the key is already in `old_values` (the read succeeded), later keys are skipped, and the block never runs.

Happy-path coverage is [`with_test.rb:32-43`](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L32-L43): both public attributes change inside the block and are back to `:public` / `:another_public` afterward.

## What the block receives and returns

The block is `yield self` ([with.rb:38](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L38)). The docs say the same ([with.rb:15](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L15)).

- Receives the original receiver, not a copy. [`with_test.rb:91-93`](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L91-L93) uses `&:public_attr`, so the yielded object is `@object` with the temporary value already applied.
- Returns the block’s value. The `begin`/`ensure` expression’s value is `yield self`; `ensure` has no `return`. [`with_test.rb:95-98`](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L95-L98) asserts `{ :block_result }` comes back as `:block_result`.

If no block is given, `yield` raises `LocalJumpError` and `ensure` still restores. The tests do not cover a missing block.

## `ensure` when the block raises

`ensure` always walks `old_values` and writes each saved value back with `public_send("#{key}=", old_value)` ([with.rb:39-42](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L39-L42)).

When the block raises after a full assignment pass, every requested key is in `old_values`, so every attribute is restored, and the original exception still propagates. [`with_test.rb:45-59`](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L45-L59) raises `"Oops"` after both writes; afterward both attributes are the originals and the `RuntimeError` still surfaces.

```diagram
with(a:, b:)
  old_values = {}
  begin
    read a  →  old_values[a]
    write a
    read b  →  old_values[b]
    write b
    yield self          ← block may raise here
  ensure
    write a ← old_values[a]
    write b ← old_values[b]
  end
```

## Two attributes: first write succeeds, second writer raises

This is [`with_test.rb:61-73`](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L61-L73), using `Record` from [`with_test.rb:7-26`](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L7-L26):

- `public_attr` — public reader and writer ([with_test.rb:16](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L16)).
- `mixed_attr` — public reader ([with_test.rb:18](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L18)), private writer ([with_test.rb:25](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L25)).

Start: `public_attr == :public`, `mixed_attr == :mixed`. Call:

```ruby
@object.with(public_attr: :changed, mixed_attr: :changed_too)
```

Runtime:

1. `old_values[:public_attr] = public_send(:public_attr)` → `:public`.
2. `public_send("public_attr=", :changed)` succeeds. Object is now `:changed`.
3. `old_values[:mixed_attr] = public_send(:mixed_attr)` → `:mixed` (reader is public).
4. `public_send("mixed_attr=", :changed_too)` raises `NoMethodError` (writer is private).
5. `each` stops. `yield self` never runs — the `assert false` in the test block is unreachable ([with_test.rb:66-68](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L66-L68)).
6. `ensure` sees `{ public_attr: :public, mixed_attr: :mixed }` and writes in that order:
   - `public_send("public_attr=", :public)` restores the first attribute.
   - `public_send("mixed_attr=", :mixed)` raises `NoMethodError` again (same private writer).

What is actually restored:

- `public_attr` was mutated, then restored to `:public`.
- `mixed_attr` never changed (`:mixed` throughout). It is in `old_values`, so restore is *attempted*, but the public writer does not exist, so that restore write fails.

After the call the test asserts both attributes match the originals ([with_test.rb:71-72](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L71-L72)). The raised error is `NoMethodError` ([with_test.rb:65](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L65)). Because `ensure`’s second write also raises, the exception that escapes is that restore `NoMethodError`, not the assignment one; the test only checks the class.

```diagram
public_attr=:public   mixed_attr=:mixed
            │
            ▼
read public_attr → old_values[:public_attr]=:public
write public_attr=:changed          ← succeeds
read mixed_attr  → old_values[:mixed_attr]=:mixed
write mixed_attr=:changed_too       ← NoMethodError (private writer)
            │
            ▼  ensure (insertion order)
write public_attr=:public           ← restored
write mixed_attr=:mixed             ← NoMethodError again
            │
            ▼
public_attr=:public   mixed_attr=:mixed (never assigned)
```

Contrast: if the *reader* is not public, the key never enters `old_values`, so `ensure` does not touch it. That is the `private_attr` / `protected_attr` path below.

## Public reader and public writer

The comment states both methods must be public ([with.rb:29-30](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L29-L30)). The implementation only uses `public_send`, so private/protected readers and writers are invisible.

[`with_test.rb:75-89`](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L75-L89) checks three cases on `Record`:

- `private_attr` — private reader and writer ([with_test.rb:24](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L24)): `public_send(key)` raises before any write; `old_values` stays `{}`; `ensure` is a no-op.
- `protected_attr` — same with `protected` ([with_test.rb:21](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L21)).
- `mixed_attr` — public reader, private writer: read succeeds, write raises, value stays `:mixed` before and after ([with_test.rb:84-88](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L84-L88)).

A public reader alone is not enough. A public writer alone is not enough either: a private reader fails on the first `public_send(key)`.

## Immediate classes where `#with` is removed

After defining `Object#with`, Active Support undefines it on common immediates ([with.rb:47-51](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L47-L51)):

```47:51:activesupport/lib/active_support/core_ext/object/with.rb
# #with isn't usable on immediates, so we might as well undefine the
# method in common immediate classes to avoid potential confusion.
[NilClass, TrueClass, FalseClass, Integer, Float, Symbol].each do |klass|
  klass.undef_method(:with)
end
```

[`with_test.rb:100-107`](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L100-L107) asserts `nil`, `true`, `false`, `1`, `1.0`, and `:sym` do not respond to `#with`. `String` is not in that list; it still inherits `Object#with`.
