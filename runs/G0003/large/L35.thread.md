### `coder: nil` vs JSON vs server custom encoding

Three independent coder sites:

1. **Broadcast coder** (default JSON): `coder.encode(message)` or skip if `coder` is nil.
2. **Stream coder** (default nil in the method signature): applied only in `stream_decoder`.
3. **Socket coder** (always JSON in tests): wraps `{ identifier:, message: }` for the WebSocket.

Default round-trip, which the default-handler test observes:

```text
broadcast({ foo: "bar" }, coder: JSON)
  → '{"foo":"bar"}' on the pubsub queue
default_stream_handler (coder ||= JSON)
  → decode to { "foo" => "bar" }
  → Channel#transmit → Connection#transmit
  → Socket#encode of { identifier, message: { "foo" => "bar" } }
```

User callback + `coder: nil` (the method default, [streams.rb L84–L90](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/streams.rb#L84-L90)): `stream_decoder` returns the callback unchanged ([L211–L213](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/streams.rb#L211-L213)). #### Encode / decode failures

There is **no** dedicated rescue in `Broadcaster#broadcast` or `stream_decoder`. Behavior is therefore:

- **Encode failure** on `server.broadcast` raises to the caller. The `broadcast.action_cable` notification still wraps the encode ([broadcasting.rb L58–L60](file:///home/user/workspace/repo/actioncable/lib/action_cable/server/broadcasting.rb#L58-L60)).

- **Decode failure on a user callback** runs inside `Worker#invoke`, which logs and calls `handle_exception` if the receiver defines it ([worker.rb L58–L66](file:///home/user/workspace/repo/actioncable/lib/action_cable/server/worker.rb#L58-L66)). The client gets no message from that broadcast.

### Deferred subscription confirmation

The counter starts at 1 so confirmation waits for `subscribe_to_channel` to finish ([base.rb L168–L172](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/base.rb#L168-L172), [L253–L264](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/base.rb#L253-L264)):

pubsub on_success → ensure_confirmation_sent → decrement

`transmit_subscription_confirmation` is idempotent via `@subscription_confirmation_sent` ([base.rb L322–L331](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/base.rb#L322-L331)). Evidence:

### String coercion of broadcasting names

Both ends stringify:

- `stream_from` / `stop_stream_from`: `broadcasting = String(broadcasting)` ([streams.rb L93](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/streams.rb#L93), [L122](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/streams.rb#L122))
- `broadcaster_for`: `String(broadcasting)` ([broadcasting.rb L43](file:///home/user/workspace/repo/actioncable/lib/action_cable/server/broadcasting.rb#L43))

So `stream_from :channel` and `broadcast "channel", …` hit the same queue. Tests: [`"stream from non-string channel"`](file:///home/user/workspace/repo/actioncable/test/channel/stream_test.rb#L76-L91) expects pubsub `"channel"`; [`"stop_stream_from with a non-string broadcasting matches stream_from"`](file:///home/user/workspace/repo/actioncable/test/channel/stream_test.rb#L222-L235) starts and stops with `:room_one`; [`"fetching a broadcaster converts the broadcasting queue to a string"`](file:///home/user/workspace/repo/actioncable/test/server/broadcasting_test.rb#L15-L17).

`stream_for` / `broadcast_to` names are a separate serialization (`channel_name` plus `to_gid_param` / `to_param`, [channel/broadcasting.rb L78–L91](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/broadcasting.rb#L78-L91)), already a String before `stream_from` coerces again.

### Observable client messages

| Event | Client payload |
|---|---|
| Streams ready | `{ "identifier" => …, "type" => "confirm_subscription" }` |
| Rejected (`stream_or_reject_for nil` / `reject`) | `{ "identifier" => …, "type" => "reject_subscription" }` |
| Default stream + JSON broadcast of `{ foo: "bar" }` | `{ "identifier" => …, "message" => { "foo" => "bar" } }` |
| Default stream + `DummyEncoder` broadcast | `{ "message" => { "foo" => "encoded" } }` |
| User callback that does not `transmit` | No `message` frame from that broadcast |
| Stopped / never subscribed name | Nothing |

Instrumentation: `broadcast.action_cable` carries `{ broadcasting, message, coder }` even when encoding is skipped ([broadcasting_test.rb L19–L38](file:///home/user/workspace/repo/actioncable/test/server/broadcasting_test.rb#L19-L38)); each client push is `transmit.action_cable` with `via: "streamed from #{broadcasting}"` for the default transmitter ([streams.rb L216–L221](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/streams.rb#L216-L221), [base.rb L240–L250](file:///home/user/workspace/repo/actioncable/lib/action_cable/channel/base.rb#L240-L250)).
