`Array#extract_options!` is the splat-args convention that peels a trailing options hash off `*args`. It lives in [activesupport/lib/active_support/core_ext/array/extract_options.rb](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/array/extract_options.rb).
```ruby
def extract_options!
  if last.is_a?(Hash) && last.extractable_options?
    pop
  else
    {}
  end
end
```

```text
            true  → pop      # receiver loses last; return that object
            false → return {} # receiver unchanged
```

### Trailing-only

The method never walks the array. `last` is the only candidate. An earlier hash is a positional argument, even if it is a real `Hash` and even if nothing after it would qualify as options.

```ruby
[{ a: 1 }, :x].extract_options!  # => {}
## receiver still [{ a: 1 }, :x]
```

That is the whole reason an earlier hash stays positional: there is no search, no “first hash wins,” no merge. The options slot is the last slot, or it is empty.

### `Hash#extractable_options?`

`is_a?(Hash)` is only a cheap gate. The real policy is `extractable_options?`:

```ruby
class Hash
  def extractable_options?
    instance_of?(Hash)
  end
end
```

Plain `Hash` opts in. A subclass does not, even though `is_a?(Hash)` is true. `HashSubclass.new` at the end of an array is left in place and the call returns `{}`. That is the documented default: only instances of `Hash` itself are extractable.

`instance_of?` is the point. Inheritance does not inherit extractability.

### Subclass opt-in

A subclass that wants to be treated as options overrides and returns true:

```ruby
class ExtractableHashSubclass < Hash
  def extractable_options?
    true
  end
end
```

Framework hashes that already do this: `ActiveSupport::HashWithIndifferentAccess`, `ActiveSupport::OrderedOptions`, `ActiveSupport::OrderedHash`. Each returns `true` so they pop the same way a literal `{ a: :b }` does.

A subclass that does not override is positional data that happens to be a hash, not an options bag.

### Mutation and the empty case

The bang is accurate. A qualifying last element is `pop`ped: the receiver shrinks, and the return value is that same object, not a copy.

If the last element is missing, not a `Hash`, or a non-extractable `Hash` subclass, the array is not mutated. The return value is a new empty `Hash` (`{}`), not `nil`, not the last element.

```ruby
[].extract_options!   # => {}, receiver still []
[1].extract_options!  # => {}, receiver still [1]
[{ a: :b }].extract_options!      # => { a: :b }, receiver []
[1, { a: :b }].extract_options!   # => { a: :b }, receiver [1]
```

Callers can always treat the result as a hash. They cannot tell “no options” from “empty options hash at the end” except by inspecting the receiver before the call.
