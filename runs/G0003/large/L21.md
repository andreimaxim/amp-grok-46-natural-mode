Behavior-preserving verification for a `SchemaCache` refactor should pin **observable results and schema-query counts**, not internal hash layout. All query assertions must use `include_schema: true`; `SQLCounter` otherwise drops `name == "SCHEMA"` events.

Counts below were measured on **sqlite3_mem** against current [schema_cache.rb](file:///home/user/workspace/repo/activerecord/lib/active_record/connection_adapters/schema_cache.rb) and [schema_cache_test.rb](file:///home/user/workspace/repo/activerecord/test/cases/connection_adapters/schema_cache_test.rb). Portable bounds are listed first; sqlite exact counts are the regression oracles for extra round trips.

## How to count

Use a fresh `BoundSchemaReflection.new(SchemaReflection.new(nil), ARUnit2Model.connection_pool)` per case unless the case is dump/load.

- Hit / ignored / dump-hit: `assert_no_queries(include_schema: true)`.
- Known miss: `assert_queries_count(N, include_schema: true)` on sqlite; on other adapters `assert_queries_count(include_schema: true)` (≥1) unless that adapter’s count is measured in-process.
- Catch extra trips by wrapping **only** the accessor under test; warm-up belongs outside the assertion.
- `assert_queries_match` on adapter SQL (`pragma_table_list` / `sqlite_master`, `information_schema`, `pg_attribute`) when you need to prove *which* metadata was fetched, not just how many statements.

`SchemaCacheTest` already sets `use_transactional_tests = false`. Keep that for cache tests.

## Lazy population and repeat access

Warm table is `courses` (3 columns, PK `"id"`, 1 index). Empty cache, each accessor in isolation:

| Call | sqlite3 first | sqlite3 repeat | Value |
|---|---|---|---|
| `data_source_exists?("courses")` | **1** (full `data_sources` list into `@data_sources`) | **0** | `true` |
| `columns("courses")` | **1** | **0** | size `3` |
| `columns_hash("courses")` | **1** (via `columns`) | **0** | size `3`, frozen hash |
| `columns` after `columns_hash` | **0** | **0** | same column objects |
| `primary_keys("courses")` | **2** (list + PK/structure) | **0** | `"id"` |
| `indexes("courses")` | **3** (list + index list + index details) | **0** | size `1` |
| `add("courses")` | **5** (exists + PK + columns + 2 index queries; `columns_hash` is derived) | **0** | — |
| all five accessors after `add` | **0** | **0** | same values |

Portable contract: first miss ≥1 schema query; every later call on that cache for that table is **0**. A refactor that re-hits `connection.columns` / `primary_key` / `indexes` / `data_source_exists?` on the second call fails `assert_no_queries(include_schema: true)`.

Coupling that must stay:

- `columns_hash` populates `@columns`; later `columns` is a hit.
- `columns` does **not** populate `columns_hash?`. After `columns("courses")` only: `assert_not cache.columns_hash?("courses")`. After `columns_hash("courses")`: `assert cache.columns_hash?("courses")`.
- `data_source_exists?` does **not** populate `columns_hash?` or `cached?`. `cached?` is `@columns.key?(table_name)` only.
- First `data_source_exists?` on an empty cache fills **all** non-ignored data sources as `true`. A later `data_source_exists?("colleges")` is **0** queries. A name **absent** from that list (`"foo"`) costs **1** named exists query, then **0**. Negative results are stored; `assert_not cache.data_source_exists?("foo")` twice is one query then zero.

`size` after populating the five accessors for `courses` is **8** on arunit2 (1+1+1 columns/hash/pk + 5 data sources). `size` **excludes** `@indexes`. Assert `size == 0` after `clear!`; do not start counting indexes without changing this contract.

## `add` and `clear!`

`add` on an existing table is the union of exists + PK + columns + columns_hash + indexes. After `add("courses")`:

```ruby
assert_no_queries(include_schema: true) do
  assert_equal 3, cache.columns("courses").size
  assert_equal 3, cache.columns_hash("courses").size
  assert cache.data_source_exists?("courses")
  assert_equal "id", cache.primary_keys("courses")
  assert_equal 1, cache.indexes("courses").size
end
```

`add` on a missing table only warms `@data_sources` (sqlite: **2** queries), then returns. It must not write columns/PK/indexes.

`add` on an ignored table is **0** queries and a no-op.

`clear!` (on `BoundSchemaReflection` / `SchemaReflection`, not a `SchemaCache` instance method) replaces the cache. After warming then `clear!`:

- `assert_equal 0, cache.size`
- `columns("courses")` is a miss again (sqlite **1**)
- `cached?("courses")` is false
- `version` is a miss again

`clear_data_source_cache!("courses")` after a full list populate must delete that name from **all five** maps. Existing oracle, keep exact:

```ruby
assert_queries_count(1, include_schema: true) { cache.data_source_exists?("courses") }
```

That **1** is a named exists query, not a full list (`@data_sources` is not empty). Other tables stay cached: `data_source_exists?("professors")` remains **0**. A refactor that only deletes `@columns` leaves a stale `true` in `@data_sources` and this count goes to **0**.

Insert path already pins the warm-cache contract: after one insert, the next `INSERT INTO courses` is `assert_queries_count(1, include_schema: true)` — the DML only, no PK metadata.

## Duplicate-cache independence

`initialize_dup` dups the five hashes, not the values.

```ruby
a = SchemaCache.new
a.add(pool, "courses")
b = a.dup
```

Exact assertions:

- `b.columns(pool, "courses")` is **0** queries (shared warmed keys).
- `a.columns(pool, "colleges")` is a miss; `b.columns(pool, "colleges")` is still a miss (**1** each on sqlite). A shared inner hash would make the second **0**.
- `a.clear_data_source_cache!(nil, "courses")` then `b.columns(pool, "courses")` is **0** — eviction must not punch through the dup.
- Column **objects** may be shared (`assert_same` on `a.columns(...).first` vs `b` before eviction). Hashes must not be `assert_same`.

## Frozen / deduplicated cached values

After `columns(pool, "courses")` / `columns_hash(pool, "courses")`:

- Same array object on repeat: `assert_same cache.columns(pool, "courses"), cache.columns(pool, "courses")`
- Array itself is **not** frozen; each `Column` is frozen; `column.name` is frozen
- `columns_hash` return is frozen; `hash["id"]` is `equal?` to the matching `columns` entry
- Table-name keys are interned via `deep_deduplicate` (`-string`); two caches that both loaded `"courses"` may share the key object after `-`
- `init_with("deduplicated" => true)` must `assert_same` the coder’s `columns` (skip `derive_columns_hash_and_deduplicate_values`)
- Without that flag, YAML load rebuilds `columns_hash` from `columns` and re-deduplicates; Column/SqlTypeMetadata (and PG/MySQL TypeMetadata) registries are the identity pool — tests already `reset_deduplicable!` before load

`encode_with` must sort keys. Existing oracle: unsorted pairs `[["z",nil],["y",nil],["x",nil]]` round-trip to `{"x"=>nil,"y"=>nil,"z"=>nil}` for `columns`, `primary_keys`, `data_sources`, `indexes`, and `coder` has `"version"`. It does **not** persist `columns_hash`.

## Deterministic YAML / Marshal dump/load

Run `DumpAndLoadTests` for both `.yml` and `.dump`, plain and `.gz`. After `dump_to` + `load!`:

```ruby
assert_no_queries(include_schema: true) do
  assert_equal 3, cache.columns("courses").size
  assert_equal 3, cache.columns("courses").map(&:cast_type).compact.size
  assert_equal 3, cache.columns_hash("courses").size
  assert cache.data_source_exists?("courses")
  assert_equal "id", cache.primary_keys("courses")
  assert_equal 1, cache.indexes("courses").size
end
```

Gzip path: load via `Zlib::GzipReader` + `YAML.unsafe_load` / `Marshal.load`, **and** via `SchemaCache._load_from` / `load!`. Same assertions, **0** queries.

Determinism: two `.yml.gz` dumps one second apart must have equal MD5 (`test_gzip_dumps_identical`). That is `GzipWriter#mtime = 0` plus sorted YAML keys. A mtime leak or unsorted hashes fails this.

Format split:

- filename includes `.dump` → Marshal; else YAML
- `File.extname == ".gz"` → gzip wrap
- Marshal dump is `[@version, @columns, {}, @primary_keys, @data_sources, @indexes]` — third slot **always empty**; load rebuilds `columns_hash` with `index_by(&:name)`
- YAML `encode_with` omits `columns_hash`; `init_with` rebuilds it unless `deduplicated`

Older dumps:

1. **5.1 YAML** (`test/assets/schema_dump_5_1.yml`): has `columns_hash`, **no** `indexes`. After `load!`:
   - `assert_no_queries` for `columns("posts")` size 11, `columns_hash("posts")` size 11, `data_source_exists?("posts")`, `primary_keys("posts") == "id"`
   - `indexes("courses")` **does** query (`assert_queries_count(include_schema: true)`); sqlite measured **3**; then repeat **0** and size `1`
2. Marshal array **without** indexes: `@indexes ||= {}` so `indexes` is a miss, not `NoMethodError`.
3. Extra trailing `database_version` element is ignored.
4. YAML missing `indexes` → `{}`. YAML missing `columns_hash` → derived from `columns`.

`dump_to` on `SchemaReflection` builds a **fresh** cache via `add_all` then writes; the in-memory `@cache` becomes that snapshot. Creating parent directories is required (`test_cache_path_can_be_in_directory`).

## Schema version and dump-version checking

`version(pool)` is `@version ||= connection.schema_version`. sqlite empty schema: **1** query (`schema_migrations` exists check), then **0**. `schema_version` is the stored value and must not query.

Default `SchemaReflection.check_schema_cache_dump_version == true`:

- `cached?` on a path-only reflection is **false** without a pool (must not load the dump).
- `load!` opens a connection, compares `connection.schema_version` to dump `@version`.
- Mismatch: stderr `Ignoring #{path} because it has expired. The current schema version is X, but the one in the schema cache file is Y.`, dump discarded, empty cache used. sqlite: load+`columns("courses")` is **2** (version check + columns miss).
- `ActiveRecordError` during check: `Failed to validate the schema cache because of ...`, dump discarded.

`SchemaReflection.with(check_schema_cache_dump_version: false)`:

- `cached?("courses")` is **true** with **no** pool and **0** queries
- `BoundSchemaReflection.new(reflection, :__unused_pool__).cached?("courses")` is true
- Expired dump still serves columns/indexes with **0** queries
- Version mismatch must **not** warn and must **not** open the DB to validate

Also: `use_schema_cache_dump == false` or missing file → no load, empty cache, lazy populate as above.

## Adapter portability boundaries

Safe to pin on **every** adapter:

- Hit path: `assert_no_queries(include_schema: true)`
- Ignored tables: **0** queries, `data_source_exists?` → `nil`, columns raise, PK `nil`, indexes `[]`
- Nonexistent: columns raise every time; PK `nil` cached; exists `false` cached; indexes `[]`
- Composite PK array vs missing PK `nil`
- Dump/load **0** queries for tables present in the dump
- 5.1 dump: **0** for columns/hash/exists/PK; **≥1** for indexes, then **0**
- `clear_data_source_cache!` then exists: **1** query on sqlite/mysql/pg (named `data_source_exists?`)
- Dup independence, frozen `columns_hash`, sorted YAML, gzip MD5, version-check on/off

**Do not** pin sqlite’s 3-query `indexes` / 5-query `add` / 6-query `add_all` on MySQL or PostgreSQL. Those adapters typically use one `information_schema` / `pg_catalog` statement per metadata kind; MariaDB may add a `SHOW FULL FIELDS` fallback when the bulk columns query returns empty. Gate exact integers with `if current_adapter?(:SQLite3Adapter)` or measure per adapter in setup.

`lazily_load_schema_cache` is skipped for `in_memory_db?`. On file-backed sqlite/mysql/pg: cache ivar nil until first use; with the flag, `lease_connection.verify!` loads it. Not a `SchemaCache` internals test; keep it as a pool-integration check.

PostgreSQL/MySQL `TypeMetadata` descendants must stay in the dedup registry reset used around dump/load, or identity/frozen assertions flake only on those adapters.

## Assertions that catch extra round trips or stale entries

Extra trips (must fail the refactor):

- Second `columns`/`columns_hash`/`primary_keys`/`indexes`/`data_source_exists?`/`add`/`version` inside `assert_no_queries(include_schema: true)`
- Any SQL on ignored-table accessors
- Dump/load accessors inside `assert_no_queries(include_schema: true)`
- Warm insert: more than **1** query
- `clear_data_source_cache!` then exists: not exactly **1** (0 = didn’t evict; ≥2 = full relist or extra metadata)
- 5.1 `indexes` inside `assert_no_queries` (missing-indexes dump must still query once)
- Version-check **on** + expired dump: `columns` with **0** queries (dump was used instead of discarded)
- Version-check **off** + expired dump: any SQL (dump must be used; `cached?` must not connect)

Stale entries (must fail the refactor):

- `clear!` then `size != 0` or `cached?` still true
- `clear_data_source_cache!("courses")` then `columns("courses")` still **0** queries
- Evict `courses`, `professors` still a hit
- Dup: evict on `a`, `b` still a hit; populate `colleges` on `a`, `b` still a miss
- Ignore list applied at dump time, load without ignore still missing `professors` (dump never contained it) — assert from the dump, not from a cache that re-queries
- `primary_keys`/`indexes` for a table dropped in the DB still returning old values until `clear_data_source_cache!` — current behavior is **stale until explicit clear**; a refactor that auto-refreshes on every call is a behavior change, caught by the hit-path `assert_no_queries`
