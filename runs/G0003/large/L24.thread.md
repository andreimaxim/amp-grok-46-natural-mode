## Assistant

`recognize_path` is a test/tools API, not the live dispatcher. It builds a fake request, asks Journey for candidate routes, then keeps only a **dispatcher** (or mounted engine) whose controller can be constantized. The return value is `req.path_parameters` — a Hash with **symbol keys**. Query-string keys are not in that Hash unless they were passed as `extras`.

```text
recognize_path(path, environment)
  normalize relative path (skip if "://")
  Rack::MockRequest.env_for(path, method:)
  make_request(env)
  recognize_path_with_request(req, path, extras)
    Journey::Router#recognize(req)  ── yields each surviving (route, params)
      merge extras
      unescape string values
      req.path_parameters = params
      if app.matches?(req) && dispatcher?
        req.controller_class          # constantize; may rewrite RoutingError
        return path_parameters
      elsif app.matches?(req) && engine?
        recurse with raise_on_missing: false
    raise RoutingError "No route matches …"   # if raise_on_missing
```

### 1. `recognize_path` — input → fake request

```911:924:actionpack/lib/action_dispatch/routing/route_set.rb
      def recognize_path(path, environment = {})
        method = (environment[:method] || "GET").to_s.upcase
        path = Journey::Router::Utils.normalize_path(path) unless path&.include?("://")
        extras = environment[:extras] || {}

        begin
          env = Rack::MockRequest.env_for(path, method: method)
```

Only `:method` and `:extras` are read. Other keys in `environment` are ignored.

**Relative path.** `normalize_path` runs first. It is `/` for `nil`/`""`, adds a leading `/`, squeezes `//`, strips a trailing `/` (except `/` itself), and uppercases `%xx` escapes. Fast path: already `/…` with no trailing slash and no `%` or `//`.

Settled by [actionpack/test/journey/router/utils_test.rb](file:///home/user/workspace/repo/actionpack/test/journey/router/utils_test.rb) (`nil` → `/`, `%aa` → `%AA`) and recognition tests that treat `/pages/show/10` and `/pages/show/10/` as equal, `/api` and `/api/` as equal ([actionpack/test/controller/routing_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb) `test_default_route_recognition`, `test_recognize_path`). `recognize_path(nil)` hits the root route as `{ controller: "news", action: "index" }`.

**Absolute URL.** If the string contains `://`, normalization is skipped. `env_for` parses scheme/host/port/path/query into Rack env. That is how protocol/host constraints see `https://…`. [actionpack/test/controller/routing_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb) `test_route_with_subdomain_and_constraints_must_receive_params` recognizes `"http://subdomain.example.org/page/mypage"`. [actionpack/test/dispatch/routing_assertions_test.rb](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_assertions_test.rb) `test_assert_recognizes_with_hash_constraint` succeeds for `https://test.host/secure/articles` and fails for `http://…` on a `protocol: "https://"` scope.

**Query strings.** `env_for` splits `PATH_INFO` / `QUERY_STRING`. Journey matches `req.path_info` only. The Hash that `recognize_path` returns is path parameters, not `request.params`. Query keys appear in the result only if passed as `extras` and merged later. That is why `assert_recognizes` documents that appending `?view=print` to the path does not work and requires the extras argument ([actionpack/lib/action_dispatch/testing/assertions/routing.rb](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/testing/assertions/routing.rb) around the `assert_recognizes` comment; [actionpack/test/dispatch/routing_assertions_test.rb](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_assertions_test.rb) `test_assert_recognizes_with_extras`).

`extras` still matter for constraints that read `request.params`: the query-constraint tests pass `use_query: "true"` as extras, not as a query string on the path.

**Bad URI.** `URI::InvalidURIError` from `env_for` becomes `ActionController::RoutingError` with the URI message. No Action Pack test asserts that rewrite; the rescue is in the method above.

Live dispatch is different: `RouteSet#call` always normalizes `req.path_info` (including after an absolute request URL has already been parsed). `recognize_path` normalizes the input string only when it is not an absolute URL.

### 2. Journey `Router#recognize` — candidates and captures

### 3. `recognize_path_with_request` — second gate, controller, return

```926:954:actionpack/lib/action_dispatch/routing/route_set.rb
      def recognize_path_with_request(req, path, extras, raise_on_missing: true)
        @router.recognize(req) do |route, params|
          params.merge!(extras)
          params.each do |key, value|
            if value.is_a?(String)
              value = value.dup.force_encoding(Encoding::BINARY)
              params[key] = URI::RFC2396_PARSER.unescape(value)
            end
          end
          req.path_parameters = params
          app = route.app
          if app.matches?(req) && app.dispatcher?
            begin
              req.controller_class
            rescue NameError
              raise ActionController::RoutingError, "A route matches #{path.inspect}, but references missing controller: #{params[:controller].camelize}Controller"
            end

            return req.path_parameters
          elsif app.matches?(req) && app.engine?
            path_parameters = app.rack_app.routes.recognize_path_with_request(req, path, extras, raise_on_missing: false)
            return path_parameters if path_parameters
          end
        end

        if raise_on_missing
          raise ActionController::RoutingError, "No route matches #{path.inspect}"
        end
      end
```

**Second unescape.** After Journey’s `CGI.unescapeURIComponent`, every **String** value (captures, string defaults, extras) is `URI::RFC2396_PARSER.unescape`’d as BINARY. Non-strings are left alone.

|---|---|
| `/file/hello+world/how+are+you%3F` | `path: "hello+world/how+are+you?"` (`+` kept, `%3F` → `?`) |
| `/file/hello%20world/how%20are%20you%3F` | spaces |
| `/pages/show/hello%2Bworld` | `id: "hello+world"` |
| `/dynamic/a%0Anewline` | `"a\nnewline"` |
| percent-escaped `こんにちは/世界`, including downcased `%e3…` | root/news route (normalize uppercases `%xx`) |

**`app.matches?` (phase 2).** This is `Mapper::Constraints#matches?` for proc/class constraints, not `Route#matches?` (already applied). Hash/proc/class constraints must not leak across candidates: after each yield Journey restores `path_parameters`, and this method assigns the current candidate’s params before `app.matches?`. [actionpack/test/dispatch/routing_test.rb](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_test.rb) `test_hash_constraints_dont_leak_between_routes` and the proc/class siblings.

A dispatcher with no constraint block is `RouteSet::Dispatcher`: `matches?` is always true, `dispatcher?` is true.

A rack app (`to:` lambda / `Constraints` with `CALL`) is neither `dispatcher?` nor `engine?`. A matching rack route is **skipped**. If nothing else matches, the result is `"No route matches"`, not the rack app’s params.

**Engines.** `engine?` is `rack_app.is_a?(Class) && rack_app < Rails::Engine`. Recursion uses `raise_on_missing: false`, so an engine miss returns `nil` and the parent continues. [actionpack/test/dispatch/routing_assertions_test.rb](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_assertions_test.rb) `test_assert_recognizes_with_engine`, `test_assert_recognizes_continue_to_recognize_after_it_tried_engines` (`/shelf/foo` misses the engine, then hits the app route).

**Controller constantize.** `Request#controller_class` does `params[:action] ||= "index"` on the same hash, then `controller_class_for`:

### 4. Unmatched route vs missing controller

These are different failures that both surface as `ActionController::RoutingError`.

**No route matched** (or every match was a non-dispatcher, failed `app.matches?`, or an engine that returned nil):

```text
ActionController::RoutingError: No route matches "/none"
```

`path.inspect` is the string after the relative-path normalize (or the original absolute URL). Tests: `/none`, `/`, extra default-route segments, `/admin/products` when the controller regexp is `admin/(accounts|users)`, verb mismatch, constraint mismatch, empty set after redraw ([actionpack/test/dispatch/routing/route_set_test.rb](file:///home/user/workspace/repo/actionpack/test/dispatch/routing/route_set_test.rb)).

**A route matched, controller cannot be constantized:**

```text
ActionController::RoutingError: A route matches "/not_a/show/10", but references missing controller: NotAController
```

The pattern matched (`:controller/:action/:id`), Journey yielded, `dispatcher?` was true, `NotAController` does not exist. [actionpack/test/controller/routing_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb) `test_non_controllers_cannot_be_matched` only asserts the exception class; the message is from the rescue above.

A NameError whose `missing_name` is **not** the controller constant is not converted to `MissingController` and is not rewritten; it propagates as `NameError`.

If `raise_on_missing:` is false (engine recursion only), a total miss returns `nil` instead of raising.

### Edge-case cheat sheet

| Case | Observable result |
|---|---|
| Relative path, trailing slash, `nil` | Normalized; `nil` → `/`; trailing `/` stripped except `/` |
| Absolute URL (`://`) | Not normalized; host/scheme from `env_for`; used by protocol/subdomain constraints |
| `?query` on the path | On the mock request; **not** in the returned Hash |
| `extras:` | Merged into returned path parameters (and thus `request.params` for constraints) |
| `%20` / `%2B` / `+` / `%0A` / `%3F` | Space / `+` / literal `+` / newline / `?` |
| Downcased `%e3` unicode path | Matches after `%XX` uppercasing |
| Wrong HTTP method | `RoutingError` `"No route matches …"` |
| Path regexp / request constraint fail | Same `"No route matches …"` |
| No matching route | Same |
| Matching rack endpoint only | Same (`dispatcher?`/`engine?` false) |
| Matching dispatcher, missing constant | `RoutingError` `"A route matches … missing controller: FooController"` |
| Matching engine, inner miss | Continue; success if a later app route matches |
| Invalid URI | `RoutingError` with `URI::InvalidURIError` message |
| Invalid path-param encoding | `ActionController::BadRequest` from `path_parameters=` |

`Rails::Engine::LazyRouteSet` only inserts `reload_routes_unless_loaded` before the same two methods; recognition itself is unchanged.
