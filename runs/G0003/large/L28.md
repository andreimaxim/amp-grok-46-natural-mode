**Reject.** `safe_concat` is the trusted-HTML write path. Escaping ordinary strings there does not make capture safer; it escapes every ERB static chunk and collapses `safe_concat` into `<<`.

I ran the current APIs and a monkey-patch of the proposed body. Results below are from that execution, not from reading neighbors.

## Contracts (current)

[`OutputBuffer#<<`](file:///home/user/workspace/repo/actionview/lib/action_view/buffers.rb#L42-L54) is the escaping write. It skips `nil`, calls `to_s`, then `unwrapped_html_escape` unless `html_safe?`.

[`OutputBuffer#safe_concat`](file:///home/user/workspace/repo/actionview/lib/action_view/buffers.rb#L56-L60) (`safe_append=`) is the opposite: append the value as already-safe HTML. No escape, no `to_s`, no `nil` guard. That is also [`SafeBuffer#safe_concat`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/string/output_safety.rb#L66-L69) and [`StreamingBuffer#safe_concat`](file:///home/user/workspace/repo/actionview/lib/action_view/buffers.rb#L121-L124).

ERB depends on that split. Static text is an ordinary frozen String:

```text
"Hello <%= name %> <b>ok</b> <%== raw_html %>"
  @output_buffer.safe_append='Hello '.freeze
  @output_buffer.append=( name )
  @output_buffer.safe_append=' <b>ok</b> '.freeze
  @output_buffer.safe_expr_append=( raw_html )
```

[`RawOutputBuffer#<<`](file:///home/user/workspace/repo/actionview/lib/action_view/buffers.rb#L97-L101) is the other explicit unescaped write (`to_s`, skip `nil`, never escape).

[`OutputBuffer#capture`](file:///home/user/workspace/repo/actionview/lib/action_view/buffers.rb#L72-L80) swaps `@raw_buffer`, yields, returns only the written bytes marked `html_safe`. The block return value is discarded.

[`CaptureHelper#capture`](file:///home/user/workspace/repo/actionview/lib/action_view/helpers/capture_helper.rb#L47-L70) is where return-value safety lives: use captured writes if present, else the return value; then `OutputBuffer` → `to_s`, `SafeBuffer` → pass through, ordinary `String` → `html_escape`.

The existing test already states the contract the patch inverts: [`#safe_append= bypasses HTML safety`](file:///home/user/workspace/repo/actionview/test/buffers_test.rb#L14-L19).

## Proposed body, same cases

`ERB::Util.html_escape` skips `html_safe?` values, so `html_safe` strings, `SafeBuffer`s, and other `OutputBuffer`s still pass through. Ordinary strings and ERB static text do not:

```text
safe_concat("<script>")                    => "&lt;script&gt;"
safe_append = '<div class="foo">'          => "&lt;div class=&quot;foo&quot;&gt;"
safe_concat(nil)                           => no error, appends ""
safe_concat(5)                             => "5"   (today: "\u0005")
StreamingBuffer#safe_concat("<div…>")      => still "<div…>"  (unpatched)
```

That last line is a non-streaming vs streaming split.

## Findings

### Blocker — ERB static HTML is escaped

`safe_append=` is `safe_concat`. Template source is a normal frozen String, not `html_safe`. After this patch, `<div class="foo">` in an `.html.erb` file renders as `&lt;div class=&quot;foo&quot;&gt;`. I observed that on `safe_append = '<div class="foo">'`.

This is not a capture tweak. It is the main view-rendering write.

### Blocker — inverts a documented, tested contract

[`buffers_test.rb`](file:///home/user/workspace/repo/actionview/test/buffers_test.rb#L14-L19) asserts `#safe_append= bypasses HTML safety` and expects `"<p>This is fine</p>"`. The patch makes that test fail and makes `safe_concat` the same as `<<` for ordinary strings.

Rails’ name means “this value is already safe,” matching `SafeBuffer#safe_concat`. It does not mean “escape this so it becomes safe.” That is `<<` / `concat` / `append=`.

### High — the capture claim is wrong

CaptureHelper already escapes ordinary String returns (`test_capture_escapes_html`). `OutputBuffer#capture` never sees the return value. Nested write+return uses the captured writes (`buffer.presence || value`); `<<` already escaped those writes.

The only “unsafe capture” left is an explicit trusted write (`safe_concat` / `raw`). That is the API. Changing `safe_concat` does not close a hole in capture; it removes the trusted-write primitive ERB and [`cache`](file:///home/user/workspace/repo/actionview/lib/action_view/helpers/cache_helper.rb#L180) use (`safe_concat(fragment_for(...))`).

Most helper `safe_concat` calls (`select_tag`, `grouped_options_for_select`, `button_to`) are on `SafeBuffer` (`"".html_safe` / `content_tag`), not `OutputBuffer`. This patch would not touch them.

### High — StreamingBuffer and helper `safe_concat` diverge / break

[`StreamingBuffer#safe_concat`](file:///home/user/workspace/repo/actionview/lib/action_view/buffers.rb#L121-L123) still does `@block.call(value.to_s)`. Streaming templates would keep real HTML; buffered ones would show entities.

[`TextHelper#safe_concat`](file:///home/user/workspace/repo/actionview/lib/action_view/helpers/text_helper.rb#L67-L68) and the test helper [`safe_concat render(plain: "<ul><li>foo</li></ul>")`](file:///home/user/workspace/repo/actionview/test/template/test_case_test.rb#L331) would start escaping HTML that callers currently inject on purpose.

### Medium — silent contract changes on `nil` and non-strings

Today `safe_concat(nil)` raises `TypeError`. `html_escape(nil)` is `""`, so the patch swallows it.

Today `safe_concat(5)` is `String#<<` of an integer (`"\u0005"`). After the patch it is `"5"`. [`OutputBuffer`’s own comment](file:///home/user/workspace/repo/actionview/lib/action_view/buffers.rb#L8-L19) exists because `<<` already special-cases this vs `SafeBuffer`; `safe_concat` is the raw `String#<<` path.

### Medium — extra `SafeBuffer` on the hottest path

`#<<` uses `unwrapped_html_escape` into a plain `@raw_buffer`. `html_escape` allocates a `SafeBuffer` per call. ERB emits one `safe_append=` per static run. Compatibility aside, this is a needless allocation on every template chunk.

## Compatibility / security

- **Compatibility:** every HTML template, annotation comments (`safe_append='<!-- BEGIN …'`), `cache`’s write-back only stays correct because fragments are already `html_safe`, and any `safe_concat "html…"` of a non-`html_safe` string.
- **Security:** no capture XSS is fixed. Ordinary returns are already escaped. Trusted writes remain trusted for `html_safe` values. `RawOutputBuffer` is unchanged. The patch trades a naming confusion (`safe_concat` vs `concat`) for mass HTML breakage and double-escaping of already-escaped ordinary strings (`html_escape("&lt;em&gt;")` → `&amp;lt;em&amp;gt;`).

If a helper passes user input to `safe_concat`, that helper should use `<<` (or escape, then pass a `html_safe` string). That is not a buffer-contract change.
