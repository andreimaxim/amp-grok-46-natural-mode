`expect` is `permit_filters` with strict types, then `require` of every declared root. It unwraps those roots. `permit` + `require` uses the same filter engine with looser array/hash matching, and `require` only unwraps what you ask for.

The tests in [parameters_expect_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_expect_test.rb), [nested_parameters_permit_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/parameters/nested_parameters_permit_test.rb), [raise_on_unpermitted_params_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/parameters/raise_on_unpermitted_params_test.rb), and [required_params_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/required_params_test.rb) all passed (56 runs). The numeric-key `expect` shapes below were also executed against this checkout.

## What `expect` does

```text
params.expect(*filters)
  permit_filters(filters)                    # on_unpermitted: nil, explicit_arrays: true
    Symbol/String  -> permitted_scalar_filter
    Hash           -> hash_filter
                      permit_value
                        []      -> permit_array_of_scalars
                        {}      -> permit_hash / permit_any_in_parameters
                        [[...]] -> permit_array_of_hashes / each_array_element
                        else    -> permit_hash only   (expect)
                                   permit_hash_or_array (permit)
    unpermitted_parameters!                  # no-op: on_unpermitted is nil
    params.permit!
  keys = filters.flatten.flat_map { Hash ? keys : filter }
  values = params.require(keys)              # always an Array
  values.size == 1 ? values.first : values   # unwrap single root
```

[`expect`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L779-L783) is three steps:

```779:783:actionpack/lib/action_controller/metal/strong_parameters.rb
    def expect(*filters)
      params = permit_filters(filters)
      keys = filters.flatten.flat_map { |f| f.is_a?(Hash) ? f.keys : f }
      values = params.require(keys)
      values.size == 1 ? values.first : values
    end
```

[`permit`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L675-L677) calls the same filter method with the opposite defaults:

```675:677:actionpack/lib/action_controller/metal/strong_parameters.rb
    def permit(*filters)
      permit_filters(filters, on_unpermitted: self.class.action_on_unpermitted_parameters, explicit_arrays: false)
    end
```

So `expect` vs `permit` + `require` differs in four places: type strictness (`explicit_arrays`), unpermitted-key handling (`on_unpermitted`), which keys get required, and whether a single result is unwrapped.

## Filter engine: `permit_filters` → `hash_filter` → explicit arrays

[`permit_filters`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1189-L1206) copies into a new `Parameters`, then `permit!`. A top-level `Symbol`/`String` only keeps a [permitted scalar](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1390-L1408). A `Hash` goes to [`hash_filter`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1442-L1451), which slices to declared keys, skips falsy values (`nil`/`false`), and writes the key only if `permit_value` returns non-`nil`.

[`permit_value`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1454-L1465) is the type switch:

```1454:1465:actionpack/lib/action_controller/metal/strong_parameters.rb
      def permit_value(value, filter, on_unpermitted:,  explicit_arrays:)
        if filter == EMPTY_ARRAY # Declaration { comment_ids: [] }.
          permit_array_of_scalars(value)
        elsif filter == EMPTY_HASH # Declaration { preferences: {} }.
          permit_hash(value, filter, on_unpermitted:, explicit_arrays:)
        elsif array_filter?(filter) # Declaration { comments: [[:text]] }
          permit_array_of_hashes(value, filter.first, on_unpermitted:, explicit_arrays:)
        elsif explicit_arrays # Declaration { user: { address: ... } } or { user: [:name, ...] } (only allows hash value)
          permit_hash(value, filter, on_unpermitted:, explicit_arrays:)
        elsif non_scalar?(value) # Declaration { user: { address: ... } } or { user: [:name, ...] }
          permit_hash_or_array(value, filter, on_unpermitted:, explicit_arrays:)
        end
      end
```

[`array_filter?`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1383-L1385) is the double-array form `[[...]]`. [`each_array_element`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1388-L1397) then accepts either a real `Array` of `Parameters`, or a `Parameters` object whose keys all look like `"0"`, `"1"`, `"-1"` (see [`nested_attribute?`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L268-L270)).

`permit` takes the last branch (`permit_hash_or_array`): a filter like `pies: [:flavor]` matches a hash **or** an array of hashes. `expect` takes the `explicit_arrays` branch: that same filter matches **only** a hash. An array of hashes requires `pies: [[:flavor]]`.

After filtering, [`require`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L526-L535) runs on every declared root. A value must be `present?` or exactly `false`; `nil`, `""`, `{}`, and `[]` raise `ActionController::ParameterMissing`. That is why `expect` turns a type mismatch into a missing-param error: the filter drops the key, then `require` sees blank.

## Contrast with `#require` combined with `#permit`

Typical `permit` then `require`:

```ruby
params.permit(person: [:name, :age]).require(:person)
```

| | `permit` + `require` | `expect` |
|---|---|---|
| Filter | `explicit_arrays: false` — hash filter also matches arrays and numeric-key hashes | `explicit_arrays: true` — hash filter matches only a hash; arrays need `[[...]]` |
| Unpermitted keys | honors `action_on_unpermitted_parameters` (`:log` / `:raise`) | always `on_unpermitted: nil` — drop, never log/raise |
| Require | only the keys you then `require` | every declared root |
| Return | `permit` keeps the outer wrapper; `require(:person)` unwraps that one key | unwraps all declared roots; one root is a value, two or more an `Array` |
| `person: "tampered"` then `.permit` | `require` first: `NoMethodError` on `String#permit`. `permit` first: key dropped, then `ParameterMissing` | `ParameterMissing` |

`require` alone does not permit. `params.require(:person)` returns unpermitted `Parameters` ([required_params_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/required_params_test.rb) `require array when all required params are present`).

## Concrete examples

### 1. Scalar vs hash type confusion

Input `{ comment: { text: "hello" } }`, filter `comment: [:text]`.

- `expect`: `#<Parameters {"text"=>"hello"} permitted: true>` — hash matched, root unwrapped ([parameters_expect_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_expect_test.rb) `key to hash`).
- `permit` then `require(:comment)`: same inner hash, also permitted.

Input `{ comment: "hello" }`, same filter.

- `expect`: `ActionController::ParameterMissing` (`comment`) — `permit_hash` rejects a `String` ([parameters_expect_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_expect_test.rb) `key to non-scalar: raises ParameterMissing on scalar`).
- `params.require(:comment).permit(:text)`: `NoMethodError` (`String#permit`).
- `params.permit(comment: [:text]).require(:comment)`: `ParameterMissing` — `permit` dropped the scalar, then `require` failed.

Input `{ comment: [{ text: "hello" }] }`, filter `comment: [:text]` (hash-shaped, not `[[...]]`).

- `expect`: `ParameterMissing` (`comment`) — explicit-array branch never runs ([parameters_expect_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_expect_test.rb) `key to array of keys: raises when params is an array`).
- `permit(comment: [:text])`: keeps `comment` as an array of permitted hashes (`permitted: true`), because `permit_hash_or_array` accepts both. Executed: `{ "comment" => [{ "text" => "hello" }] }`.

Input `{ user: { name: "Martin", pets: { name: "hack" } } }`, filter `user: [:name, pets: [[:name]]]`.

- `expect`: `{ "name" => "Martin" }` permitted; `[:pets]` is `nil`. `[[ :name ]]` requires an array (or numeric-key nested hash); a plain hash is dropped, and `require(:user)` still succeeds on `:name`. Documented on `expect`; same drop happens inside `permit` for that nested `[[...]]` filter.

### 5. Numeric-key nested parameters

Input:

```ruby
book: {
  authors_attributes: {
    "0" => { name: "William Shakespeare", age_of_death: "52" },
    "1" => { name: "Unattributed Assistant" },
    "2" => { name: ["injected", "names"] }
  }
}
```

Filter `book: { authors_attributes: [:name] }` (`permit`-style, not `[[...]]`):

- `permit`: `{ "book" => { "authors_attributes" => { "0" => { "name" => "William Shakespeare" }, "1" => { "name" => "Unattributed Assistant" }, "2" => {} } } }` permitted. Numeric keys are treated as nested attributes; `"2"`’s `name` is not a scalar so that child is `{}` ([nested_parameters_permit_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/parameters/nested_parameters_permit_test.rb) `nested params with numeric keys`).
- `expect`: `{ "authors_attributes" => {} }` permitted. Executed. With `explicit_arrays: true`, `[:name]` is a hash filter on `authors_attributes` itself, not on children `"0"`/`"1"`. Those children are not named `:name`, so the nested hash is emptied. `require(:book)` still succeeds because `book` is a non-empty `Parameters`.

Filter `book: { authors_attributes: [[:name]] }`:

- `expect`: `{ "authors_attributes" => { "0" => { "name" => "William Shakespeare" }, "1" => { "name" => "Unattributed Assistant" }, "2" => {} } }` permitted. Executed. `each_array_element` walks numeric-key hashes and returns a `Parameters` hash, not an `Array`.

Root-level `{ pies: { "0" => { flavor: "key lime" }, "1" => { flavor: "mince" } } }`:

- `expect(pies: [[:flavor]])`: `{ "0" => { "flavor" => "key lime" }, "1" => { "flavor" => "mince" } }` permitted — still a hash, unwrapped.
- `expect(pies: [:flavor])`: `ParameterMissing` (`pies`).
- `permit(pies: [:flavor])`: `{ "pies" => { "0" => ..., "1" => ... } }` permitted.

Addressing one numeric key: `expect(book: { authors_attributes: { "1": [:name] } })` → `{ "authors_attributes" => { "1" => { "name" => "Unattributed Assistant" } } }` ([nested_parameters_permit_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/parameters/nested_parameters_permit_test.rb) `nested params with numeric keys addressing individual numeric keys using require first`).

Non-numeric extra keys (`"new_record"`) are dropped by the nested-attribute walk ([nested_parameters_permit_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/parameters/nested_parameters_permit_test.rb) `nested params with non_numeric keys`).

- `permit(:id)`: `{ "id" => "1234" }` permitted, `:injected` gone ([parameters_permit_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_permit_test.rb) `key: unknown keys are filtered out`).

- `permit(book: [:pages])` on extra keys: `ActionController::UnpermittedParameters`.
- `expect(book: [:pages])` and `expect!(book: [:pages])`: no raise; extra keys dropped. ### 7. Multiple filters and return arity

Arity is `values.size == 1 ? values.first : values` after `require(keys)`. `keys` is every Symbol plus every Hash key, in filter order.

| Call | `keys` | Return |
|---|---|---|
| `expect(:a)` on `{a: 1, b: 2}` | `[:a]` | `1` (unwrapped scalar) |
| `expect(:a, :b)` | `[:a, :b]` | `[1, 2]` |
| `expect([:a, :b])` | `[:a, :b]` (`flatten`) | `[1, 2]` |
| `expect(person: [:name, :age])` | `[:person]` | one `Parameters`, unwrapped |
| `expect(subject: [:name], object: [:pie])` | `[:subject, :object]` | `[subject_params, object_params]` both permitted |
| `expect(name: [:first, :last], addresses: [[:city]])` | `[:name, :addresses]` | `[name_params, addresses_array]` ([parameters_expect_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_expect_test.rb) `keys to arrays: returns permitted params in hash key order`) |

`permit(:a, :b)` always returns one `Parameters` wrapping the kept keys. `require([:a, :b])` always returns an `Array`, even for one key if you pass an Array.

A later `.expect(:name)` on already-permitted params yields the scalar (`chain of keys` in the expect tests). `false` is kept: it is a permitted scalar and `require` treats `false` as present.

The type contract is in `permit_value`’s `explicit_arrays` branch; the 400-vs-500 contract is `require` after a failed match instead of calling `permit` on a `String`.
