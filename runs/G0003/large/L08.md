`Enumerable#sole` returns the only element of an enumerable. It raises `Enumerable::SoleItemExpectedError` unless iteration yields exactly once. The empty/one/many distinction is a `found` flag plus an early raise, not a nil sentinel, so `nil` is a real element.

The implementation is in [`activesupport/lib/active_support/core_ext/enumerable.rb`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/enumerable.rb#L238-L260):

```238:260:activesupport/lib/active_support/core_ext/enumerable.rb
  def sole
    result = nil
    found = false

    each do |*element|
      if found
        raise SoleItemExpectedError, "multiple items found"
      end

      result = element.size == 1 ? element[0] : element
      found = true
    end

    if found
      result
    else
      raise SoleItemExpectedError, "no item found"
    end
  end
```

Control flow:

```text
result = nil, found = false
each |*element|
  if found already          → raise "multiple items found"   # 2nd yield
  pack element into result
  found = true
after each
  found                     → return result                  # exactly 1 yield
  else                      → raise "no item found"          # 0 yields
```

`found` is the emptiness test. `result` starts as `nil` only as a placeholder; after the loop, `found` decides whether that `nil` means “never yielded” or “the sole element was `nil`”.

## Empty, one, many

[`test_sole`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L431-L438) drives `GenericEnumerable`, whose `each` forwards to the wrapped collection ([`enumerable_test.rb` lines 35–45](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L35-L45)):

- Empty (`[]`): `each` never yields, `found` stays `false`, raises `Enumerable::SoleItemExpectedError` with `"no item found"`.
- One element (`[1]`): first yield sets `result = 1` and `found = true`; the loop ends; returns `1`.
- Two or more (`[1, 2]`): first yield records the item; second yield hits `if found` and raises `"multiple items found"` without reading the rest.

The tests assert only the exception class, `Enumerable::SoleItemExpectedError` ([lines 19–21](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/enumerable.rb#L19-L21) and [line 432](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L432)). The two messages come from the method body above. Docs at [lines 230–236](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/enumerable.rb#L230-L236) show the same class and messages.

## `nil` is an element

`[1, nil]` raises the multi-item error ([line 437](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L437)). The second yield is `nil`, which still counts: `found` is already true, so `sole` raises `"multiple items found"`.

A lone `nil` would return `nil`, because `found` would be true and `result` would be that `nil`. Using `result.nil?` after the loop as an empty check would collapse those two cases; the flag keeps them apart. The tests do not cover `[nil].sole` itself; that return path is from the `found`/`result` split in source.

## Endless range: stop on the second yield

[`GenericEnumerable.new(1..).sole`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L438) does not hang. `GenericEnumerable#each` calls `(1..).each`, which can yield forever, but `sole` never asks it to.

Yield 1 stores `1` and sets `found`. Yield 2 (`2`) raises `"multiple items found"` and unwinds `each`. Traversal stops there. Complete consumption (`to_a`, `count`, a full `find`/`detect` over the rest) would not return.

This is `Enumerable#sole` over an enumerable whose `each` is an endless range, not `Range#sole`. Direct `(1..).sole` is a different method.

## How yields are packed

The block is `|*element|`. Every yield becomes an Array. Then:

```ruby
result = element.size == 1 ? element[0] : element
```

One positional value unwraps; anything else stays an Array. That matches `Enumerable#first` in the tuple tests.

**One value.** `each` yields `1` → `element` is `[1]` → size 1 → return `1` ([line 435](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L435)).

**Several positional values.** [`test_sole_returns_same_value_as_first_for_tuples`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L441-L444):

```441:444:activesupport/test/core_ext/enumerable_test.rb
  def test_sole_returns_same_value_as_first_for_tuples
    enum = Enumerator.new(1) { |yielder| yielder.yield(1, "one") }
    assert_equal [1, "one"], enum.sole
    assert_equal enum.first, enum.sole
```

`yield(1, "one")` → `element` is `[1, "one"]` → size ≠ 1 → return that array. Same object shape as `first`.

**One positional value plus keywords.** [`KeywordYielder`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L447-L458) does `yield 1, two: 3`. `sole` returns `[1, { two: 3 }]`, again equal to `first`. In this block the keyword hash is the last entry of the rest array, so size is 2 and it is not unwrapped.

`sole` does not special-case hashes or keywords. The rest parameter plus the size-1 unwrap is the whole contract: a single yielded object is returned as-is; a multi-value yield is returned as the array of those values.
