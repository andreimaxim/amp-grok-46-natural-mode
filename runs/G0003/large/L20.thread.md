### Derived contract

`ActiveRecord::Base.connected_to_many(*classes, role:, shard: nil, prevent_writes: role == ActiveRecord.reading_role)` is a **scoped stack push**, not a connection checkout.

```text
connected_to_many(*classes, role:, shard: nil, prevent_writes:)
  classes = classes.flatten
  reject unless receiver is Base
  reject if flattened classes include Base
  reject if role == reading_role && prevent_writes == false
  append { role, shard, prevent_writes, klasses: classes }
  yield
ensure
  connected_to_stack.pop
```

Lookup walks the stack newest-first. An entry applies to a model only if `klasses` includes `ActiveRecord::Base` or that model’s `connection_class_for_self`. Shard is applied only when `hash[:shard]` is present; `prevent_writes` is applied when it is not `nil` (so `false` is a real override). The stack lives in `IsolatedExecutionState[:active_record_connected_to_stack]`, so it is per thread (default) or per fiber.

Consequences that a refactor must keep:

- Nested arrays flatten before the Base-inclusion check.
- Two named connection classes switch together; a third connection class is untouched.
- Descendants follow their connection class (e.g. `SecondaryModel` follows `SecondaryBase`).
- `role: :reading` defaults `prevent_writes` to true; `role: :writing` defaults it to false.
- `role: :reading, prevent_writes: false` never pushes.
- Receiver other than `Base`, or `Base` in `klasses`, never pushes.
- `ensure` pops on return, `raise`, and `throw`.
- Unlike `connected_to`, the method does **not** call `Relation#load` on the block result.

Existing tests already cover receiver/`Base` rejection, reading-role default `prevent_writes`, splat vs one array, nested `connected_to_many` role swap with an untouched third class, and shard-swap prohibition. They do **not** cover nested flattening, two-class shard swap, explicit `prevent_writes` on writing, nesting with `connected_to`, restore-after-raise/throw, or concurrent isolation for this method.

### Shared observables and instrumentation

Use three layers. Do not treat stack internals as the only oracle.

**Selection (did the right classes move?)**

- `Klass.current_role`, `Klass.current_shard`, `Klass.connected_to?(role:, shard:)`
- `Klass.connection_pool.db_config.name` (and replica flag when configured)
- Concrete descendants (`PrimaryModel` / `SecondaryModel`) as well as the abstract connection classes

**Writes (did prevent_writes actually bite?)**

- `Klass.current_preventing_writes` (class-identity lookup)
- `Klass.lease_connection.preventing_writes?` (name lookup used by the adapter)
- A real write: `Model.create!` or `INSERT`, expecting `ActiveRecord::ReadOnlyError` vs success
- For writing-role `prevent_writes` tests, omit `replica: true` so the adapter does not short-circuit on `replica?` (same setup as `test_prevent_writes_can_be_changed_granularly`)

**Leak / restore (did the stack go back?)**

- Snapshot **before** the call: `stack_size = ActiveRecord::Base.connected_to_stack.size` plus `{role, shard, prevent_writes, pool_name}` for every connection class under test, including the unrelated one
- Assert the same snapshot after the block, and in `ensure` of raise/throw cases
- Assert the block’s return value is yielded unchanged (no extra `Relation#load`)

Fixture shape for the selection/write cases: three independent abstract connection classes (`PrimaryBase`, `SecondaryBase`, `TertiaryBase`) with writing/reading (and shards when needed), plus one concrete model each. Disable transactional tests and skip in-memory SQLite, matching the existing swapping tests. Restore `configurations` / `establish_connection(:arunit)` in `ensure`.

| **S1** | `connected_to_many([A, B], role: :reading)` | reading, **same shard** (`:default`) | same | writing/default |

S1 is the important nil-shard rule: a missing shard must not clobber an outer shard. S2/S3 are the two-class swap. U must never change pool name, role, shard, or `preventing_writes?`.

| ID | Nesting | Inside inner | After inner, still in outer | After outer |
|---|---|---|---|---|
| **X1** | `connected_to_many([A, B], role: :reading) { A.connected_to(role: :writing) { ... } }` | A writing, not preventing writes; B reading, preventing writes; U writing | A and B reading again | all writing |

|---|---|---|

Also assert A is writable after Z3/Z4 (`create!` succeeds). That is the accidental-write leak: a stuck `prevent_writes: true` frame.

#### 9. Isolation across concurrent contexts

The stack is in `IsolatedExecutionState`, default `:thread`. Follow the latch pattern in [`test_swapping_shards_and_roles_in_a_multi_threaded_environment`](file:///home/user/workspace/repo/activerecord/test/cases/connection_adapters/connection_handlers_sharding_db_test.rb#L471-L557). Only add a fiber variant if the harness already sets `isolation_level = :fiber` (as `connection_pool_test` does).

| ID | Contexts | Expect |
|---|---|---|
| **C1** | Thread T0: `connected_to_many([A, B], role: :reading, shard: :one, prevent_writes: true)` held across two latches. Thread T1: never enters the block. | While T0 is inside, T1 still sees writing/default and can `create!` on A. T0 sees reading/one and `ReadOnlyError` on A. After join, T0 restored. |
| C2 | Two threads each call `connected_to_many` on different class sets (T0: `[A]`, T1: `[B]`) | No cross-talk: T0 must not switch B; T1 must not switch A; U unchanged in both |
| C3 (optional) | Same as C1 with `isolation_level = :fiber` and two Fibers | same as C1 |

**Observables:** each context reads its own `current_role` / `current_shard` / `lease_connection.preventing_writes?` and attempts a write on A. **Instrumentation:** `CountDownLatch` so T1 samples **while** T0 is still inside the block (a post-join-only test cannot catch leaked sharing). Lease a connection on each thread before the handshake, as the existing shard tests do.

Do not share a `Concurrent::Array` assertion across threads as proof of isolation; the array is per-context. The proof is T1’s observables while T0 is inside.

### Priority order after a refactor

1. **Z3, Z4, Z5** — leftover stack frames (raise/throw).
2. **C1, C2** — cross-context leak of role/shard/`prevent_writes`.
3. **P1, P3, P5** — accidental writes on switched classes; writes still allowed on U.
4. **S1, S2, S3, S4** — two-class role/shard selection; U frozen; nil shard does not clobber.
5. **X1, X2, X3** — inner `connected_to` pop must not eat the `connected_to_many` frame.
6. **R1, N1, B1, B2, F5** — rejection paths that must not push.
7. **F4** — nested flatten.
8. Z1/Z2/P2/P4/F1–F3 — happy-path completeness.

A refactor is behavior-preserving only if every bold row keeps both the in-block selection/write behavior **and** the post-exit snapshot. The unrelated class’s pool name, role, shard, and successful write in the same block are the cheapest signals that `klasses` filtering still works.
