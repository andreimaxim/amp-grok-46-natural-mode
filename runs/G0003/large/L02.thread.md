## Assistant

`#none` is a Null Object `Relation`, not an empty Array. The empty-result behavior is a boolean on the relation (`@none`), with `WHERE (1=0)` as SQL-facing backup. Those two are not the same mechanism as `where_clause.contradiction?`.

### Construction and chainability

[`none`](file:///home/user/workspace/repo/activerecord/lib/active_record/relation/query_methods.rb#L1352-L1366) is `spawn.none!`. `none!` is idempotent: first call does `where!("1=0")` and sets `@none = true`; later calls are no-ops.

```text
Relation#none
  spawn                    # clone (or model.all inside _exec_scope)
    none!
      unless @none
        where!("1=0")      # string predicate, not a column equality
        @none = true
```

`@none` is an instance variable, not a `@values` key. [`initialize`](file:///home/user/workspace/repo/activerecord/lib/active_record/relation.rb#L81-L96) sets it false. [`initialize_copy`](file:///home/user/workspace/repo/activerecord/lib/active_record/relation.rb#L98-L101) dups `@values` and `reset`s loaded state, but does not touch `@none`. So every `spawn`/`clone` (`where`, `limit`, `merge` of a non-null relation, `except`/`only`, …) keeps the flag.

That is why `Developer.none.where(name: "David")` is still a `Relation`, still `@none`, and still fires no SELECT. Extensions survive (`Topic.anonymous_extension.none.one`). `null_relation?` is just `@none`.

[`Merger`](file:///home/user/workspace/repo/activerecord/lib/active_record/relation/merger.rb#L58-L80) copies it explicitly: `relation.none! if other.null_relation?`. So `scope.merge(Post.none)` becomes null even if `scope` was not.

`1=0` does not show up in [`where_values_hash`](file:///home/user/workspace/repo/activerecord/test/cases/null_relation_test.rb#L73-L80) / `scope_for_create` (those only hash column equalities). Further `.where(salary: 100_000)` still populates the hash; `@none` stays true.

[`or`](file:///home/user/workspace/repo/activerecord/lib/active_record/relation/query_methods.rb#L1233-L1245) is the chain that *drops* nullness on the left:

```text
none.or(other)  →  other.spawn     # @none discarded
other.or(none)  →  spawn.or!       # 1=0 stays in the AST as OR 1=0
none.or(none)   →  none
```

`unscope(:where)` / `except(:where)` / `invert_where` / `rewhere` change `@values` but leave `@none` set. Load still short-circuits.

### Two empty-load paths

[`exec_main_query`](file:///home/user/workspace/repo/activerecord/lib/active_record/relation.rb#L1497-L1527):

```text
exec_main_query
  if @none
    async ? FutureResult.wrap([]) : []     # no Arel, no adapter
  else
    skip_query_cache_if_necessary
      if where_clause.contradiction?
        [].freeze
      elsif eager_loading?
        apply_join_dependency
          if relation.null_relation? then [].freeze else SELECT
      else
        SELECT
```

`@none` is checked first and returns a plain `[]` (or a wrapped future for `load_async`). [`contradiction?`](file:///home/user/workspace/repo/activerecord/lib/active_record/relation/where_clause.rb#L99-L108) is different: empty `IN ([])` or an equality whose bind is `unboundable?`. `WHERE 1=0` is a SQL literal, so it is **not** a contradiction.

`where(id: [])` therefore uses the contradiction path; `#none` uses `@none`. Both avoid a SELECT on load. Differences that matter:

- contradiction returns `[].freeze`; `@none` returns `[]`
- `load_async` on `#none` gets `FutureResult.wrap([])` and is `scheduled?`; contradiction gets an Array and is not
- eager-load join rewrite rechecks `null_relation?` on the rewritten relation

`exec_queries` still instantiates/preloads on the empty rows; `instantiate_records` bails on `rows.empty?`.

### Query-cache skip state

[`skip_query_cache`](file:///home/user/workspace/repo/activerecord/lib/active_record/relation.rb#L61) is a `SINGLE_VALUE_METHODS` entry (`skip_query_cache_value` in `@values`). [`skip_query_cache_if_necessary`](file:///home/user/workspace/repo/activerecord/lib/active_record/relation.rb#L1539-L1544) is `model.uncached(&block)` vs `yield`. [`values_for_queries`](file:///home/user/workspace/repo/activerecord/lib/active_record/relation.rb#L1344-L1346) strips it (and `:extending`, `:strict_loading`) so preload grouping ignores execution flags.

`@none` short-circuits **before** that helper on `exists?`, `calculate`, `pluck`, `delete_all`, `update_all`, and inside `exec_main_query`. No cache key is written because no SQL runs.

`load` still enters the *outer* `uncached` in `exec_queries` if the flag is set, then `exec_main_query` returns `[]` without the inner helper. `load_async` calls `exec_main_query` directly, so `#none` never consults `skip_query_cache_value`. Contradiction is the opposite: it lives *inside* the inner helper.

The skip flag clones independently of `@none`. On a null relation it is preserved state that does not affect the short-circuit paths above.
