`TimeZone#local` does not convert by itself. It packs wall-clock fields into a UTC `Time` and hands that to `TimeWithZone` with `utc_time = nil`. Period selection, the spring-forward +1 hour rewrite, and the later UTC instant all live on that constructor path. I ran the six existing `#local` tests (6 runs, 22 assertions, 0 failures) and probed the extra observables those tests leave unlocked.

## Conversion that must stay observationally identical

```text
TimeZone#local(*args)
  Time.utc(*args)                          # wall clock, stored as UTC Time
  TimeWithZone.new(nil, zone, time)
    @utc = nil
    @period = get_period_and_ensure_valid_local_time
      unless time.utc? → rewrite via Time.utc(y,m,d,h,min,sec+subsec)
      period_for_local(time, dst=true) { periods.last }
        empty periods → TZInfo::PeriodNotFound
          @time += 1.hour; retry
    utc  = @time + (-period.observed_utc_offset)
    time = @time                           # wall clock, possibly +1h
    zone = period.abbreviation
    dst? = period.dst?
```

Evidence: [`TimeZone#local`](file:///home/user/workspace/repo/activesupport/lib/active_support/values/time_zone.rb#L375-L378), [`TimeWithZone#initialize`](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L50-L70), [`#time` / `#utc`](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L63-L70), [`#dst?` / `#zone`](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L99-L116) and [`#zone`](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L138-L140), [`get_period_and_ensure_valid_local_time`](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L565-L576), [`period_for_local`](file:///home/user/workspace/repo/activesupport/lib/active_support/values/time_zone.rb#L578-L580). TZInfo raises `PeriodNotFound` when `periods_for_local` is empty ([`tzinfo/timezone.rb` 499–500](file:///home/user/.local/share/mise/installs/ruby/4.0.6/lib/ruby/gems/4.0.0/gems/tzinfo-2.0.6/lib/tzinfo/timezone.rb#L499-L500)); `dst=true` is tried first, then the block.

Locked invariants from that path:

1. `#local` arguments are wall-clock fields, not a UTC instant. `.time` is a `Time` whose `year/month/day/hour/min/sec` equal those fields (or those fields plus one hour on a gap).
2. `.time` is UTC-constructed (`Time.utc(*args)`), so system `TZ` must not leak in. Comment at [time_with_zone.rb:566-567](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L566-L567).
3. Nonexistent local times do not raise. They add exactly `1.hour` to `@time` and retry. Minutes and seconds are preserved; the clock is not snapped to the next valid hour.
4. Ambiguous local times do not raise. `dst=true` is tried first; if that does not reduce to one period, `{ |periods| periods.last }` wins. Eastern fall-back therefore prefers EDT; Moscow 2014 prefers the later standard period (see below).
5. `.utc` is derived from the (possibly rewritten) local `Time` minus `period.observed_utc_offset`. Comparable equality of a `TimeWithZone` against a `Time.utc(...)` only checks this instant, not `.time`.
6. `.zone` is `period.abbreviation`; `.dst?` is `period.dst?`; `.time_zone` is the `TimeZone` passed to `#local`.

### 2. Eastern 2006 spring-forward — `01:59:59`, `02:00`, `02:30`

Existing: [`test_local_enforces_spring_dst_rules`](file:///home/user/workspace/repo/activesupport/test/time_zone_test.rb#L213-L230). Same constructor path is also hit from [`test_instance_created_with_local_time_enforces_spring_dst_rules`](file:///home/user/workspace/repo/activesupport/test/core_ext/time_with_zone_test.rb#L676-L681) for `02:00` only.

**`zone.local(2006, 4, 2, 1, 59, 59)`** — last valid pre-gap second

| Surface | Assert |
|---|---|
| local | `.time == Time.utc(2006, 4, 2, 1, 59, 59)` |
| UTC | `.utc == Time.utc(2006, 4, 2, 6, 59, 59)` |
| abbr | `.zone == "EST"` |
| DST | `.dst? == false` |

Detects: advancing a valid time; using the post-gap offset (`-4h` would make `.utc` `05:59:59`); reporting `EDT`/`dst? true` one second early.

**`zone.local(2006, 4, 2, 2)`** — exact gap start

| Surface | Assert |
|---|---|
| local | `.time == Time.utc(2006, 4, 2, 3)` |
| UTC | `.utc == Time.utc(2006, 4, 2, 7)` |
| abbr | `.zone == "EDT"` |
| DST | `.dst? == true` |

Detects: leaking `PeriodNotFound`; leaving `.time` at 02:00; snapping without updating period (02:00 EST vs 03:00 EDT); using EST offset on the rewritten time (`.utc` would be `08:00`).

**`zone.local(2006, 4, 2, 2, 30)`** — interior of the gap

| Surface | Assert |
|---|---|
| local | `.time == Time.utc(2006, 4, 2, 3, 30)` |
| UTC | `.utc == Time.utc(2006, 4, 2, 7, 30)` |
| abbr | `.zone == "EDT"` |
| DST | `.dst? == true` |

Detects the rewrite rule itself: `+ 1.hour` then retry, not “jump to 03:00”. A snap-to-next-valid-hour implementation passes `02:00` and fails here (`.time` would be `03:00`, `.utc` `07:00`). Also detects applying the +1h to UTC instead of to the wall-clock `Time`.

These three must be asserted together. `01:59:59` vs `02:00` is the gap boundary; `02:00` vs `02:30` is +1h vs snap.

## What a green run actually means

The six methods above are the regression net for this refactor:

```bash
cd activesupport && bin/test test/time_zone_test.rb -i "/test_local$|test_local_with_old_date|test_local_enforces_spring_dst_rules|test_local_enforces_fall_dst_rules|test_local_with_ambiguous_time/"
```

That command is necessary and not sufficient. Today it checks 22 assertions. Gaps:

- Hawaii 2007 never asserts `.utc`, `.zone`, or `.dst?`.
- Hawaii 1850 never asserts `.utc` or `"LMT"`.
- Moscow 2014 never asserts `.time`, `.zone`, or `.dst?`.
- Eastern `02:00` is also covered via `TimeWithZone.new(nil, zone, Time.utc(...))` in `time_with_zone_test.rb`; `02:30` is only on `#local`.

A behavior-preserving refactor of `#local` / the nil-`utc_time` constructor should add those missing four-surface asserts on the same methods (or adjacent `test_local_*` methods) before changing code. Do not fold Eastern fall-back and Moscow into one “ambiguous → DST” rule: source uses `dst=true` then `periods.last`, and the two cases select opposite periods.

Related but out of this net: `#now`, `#iso8601`, `#parse`, and `+/-` on an already-constructed `TimeWithZone` ([`test_now_enforces_*`](file:///home/user/workspace/repo/activesupport/test/time_zone_test.rb#L104-L125), [`test_plus_and_minus_enforce_*`](file:///home/user/workspace/repo/activesupport/test/core_ext/time_with_zone_test.rb#L474-L504)). They share DST policy but not the `#local` → `new(nil, zone, Time.utc(*args))` path.

No implementation changes in this turn. Next step, if you want it, is to add the unlocked UTC/abbr/DST asserts on the Hawaii, Moscow, and 1850 methods before touching `#local`.
