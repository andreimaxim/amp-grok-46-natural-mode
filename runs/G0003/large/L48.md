Current `require "rails/test_help"` is a one-shot boot hook, not a live config object. Paths are snapshotted when the `on_load` blocks run; Ruby `require` makes a second require a no-op. Preserve those effects, including the odd ones.

## What `rails/test_help` actually does

From [railties/lib/rails/test_help.rb](file:///home/user/workspace/repo/railties/lib/rails/test_help.rb):

1. `abort` if `Rails.env.production?`.
2. Load `ActiveSupport::TestCase`, `Rails::Generators::TestCase`, Minitest autorun, and [railties/lib/rails/testing/maintain_test_schema.rb](file:///home/user/workspace/repo/railties/lib/rails/testing/maintain_test_schema.rb) (pending migrations `exit 1` only when AR is defined).
3. **With `ActiveRecord::Base` defined** (the generated app path: environment first, then `require "rails/test_help"`):
   - `ActiveSupport.on_load(:active_support_test_case)` includes `ActiveRecord::TestDatabases`, `ActiveRecord::TestFixtures`, `ActiveRecord::Assertions::QueryAssertions`, then:
     - `self.fixture_paths = [*self.fixture_paths, "#{Rails.root}/test/fixtures/"].uniq`
     - `self.file_fixture_path = "#{Rails.root}/test/fixtures/files"`
   - `ActiveSupport.on_load(:action_dispatch_integration_test)` does `self.fixture_paths += ActiveSupport::TestCase.fixture_paths` (no `uniq`).
4. **Without AR**: only `file_fixture_path` on `ActiveSupport::TestCase`. No `fixture_paths`, no TestFixtures/QueryAssertions/TestDatabases, no IntegrationTest path copy.
5. Always: `on_load` for `ActionController::TestCase` and `ActionDispatch::IntegrationTest` defines `before_setup` that sets `@routes = Rails.application.routes` then `super`.

`ActiveSupport::TestCase` is required first, so its hook runs immediately on that class ([activesupport/lib/active_support/test_case.rb](file:///home/user/workspace/repo/activesupport/lib/active_support/test_case.rb) already called `run_load_hooks`). In a booted app, `ActionDispatch::IntegrationTest` is also already loaded, so its hooks run immediately too ([actionpack/lib/action_dispatch/testing/integration.rb](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/testing/integration.rb) `run_load_hooks` inside `Behavior`).

Path strings are interpolations, not Pathnames: fixture dir has a trailing slash, file-fixture dir does not. Existence is not checked at require time.

Engine extra paths are not added by `test_help` itself. [railties/lib/rails/engine.rb](file:///home/user/workspace/repo/railties/lib/rails/engine.rb) registers `on_load(:active_record_fixtures) { self.fixture_paths |= ["#{fixtures}/"] }`. That hook fires when TestFixtures is included, *before* the `[*self.fixture_paths, app_path].uniq` assignment. So engine paths survive and the app path is appended.

```text
require "rails/test_help"          # $LOADED_FEATURES; second require is a no-op
  on_load :active_support_test_case   # runs now (TestCase already loaded)
    include TestFixtures
      run_load_hooks :active_record_fixtures
        fixture_paths |= [engine/test/fixtures/]   # engines only
    fixture_paths = [*fixture_paths, "#{Rails.root}/test/fixtures/"].uniq
    file_fixture_path = "#{Rails.root}/test/fixtures/files"
  on_load :action_dispatch_integration_test
    fixture_paths += TestCase.fixture_paths        # copy-on-write; duplicates
    def before_setup; @routes = Rails.application.routes; super; end
```

`class_attribute` copy-on-write matters: `IntegrationTest.fixture_paths += TestCase.fixture_paths` assigns on the subclass. If IntegrationTest was still inheriting TestCase’s array, the result is **parent paths concatenated with themselves**. `fixtures :all` later `uniq`s names, so loads still work; the array itself can contain duplicates. Re-running that `+=` (a `load`, or extracting the body so it runs on every require) would grow the array. TestCase’s own assignment is idempotent because of `.uniq`.

## Public effects to freeze

| Effect | With AR | Without AR |
|---|---|---|
| `ActiveSupport::TestCase.fixture_paths` includes `"#{Rails.root}/test/fixtures/"` | yes | method may not exist |
| Engine/`on_load(:active_record_fixtures)` paths kept, then app path appended | yes | n/a |
| `file_fixture_path` = `"#{Rails.root}/test/fixtures/files"` on TestCase | yes | yes |
| IntegrationTest `fixture_paths` is TestCase’s list plus itself (duplicates possible) | yes | no `+=` |
| Subclasses without their own `fixture_paths=` see the parent value | yes | n/a |
| Subclasses that already assigned `fixture_paths` keep that value | yes | n/a |
| `fixtures :all` / named fixtures load from those dirs | yes | n/a |
| `file_fixture` / `fixture_file_upload` resolve under `file_fixture_path` | yes | yes |
| `assert_queries_count` available | yes | no |
| `@routes` set in controller and integration `before_setup` | yes | yes |
| Second `require "rails/test_help"` does not re-run hooks | yes | yes |
| Paths captured at first hook run; later `Rails.root` / second app boot does not refresh them | yes | yes |

Relative vs absolute: `uniq` is string identity. `"test/fixtures/"`, `"/abs/test/fixtures/"`, and `"/abs/test/fixtures"` (no slash) all stay. Missing fixture dir: require succeeds; `fixtures :all` uses `Dir[]` and gets `[]`; `file_fixture("x")` raises `ArgumentError` (`the directory '%s' does not contain a file named '%s'`).

Generated [app test_helper](file:///home/user/workspace/repo/railties/lib/rails/generators/rails/app/templates/test/test_helper.rb.tt) relies on this: it does not set `fixture_paths` itself; it only calls `fixtures :all` when AR is present. Plugin helpers *overwrite* both classes after the require — that is user/template code, not `test_help`.

## Isolation so global state cannot hide a regression

`test_help` mutates process-global state: `$LOADED_FEATURES`, `ActiveSupport` load hooks, modules included on `ActiveSupport::TestCase`, `class_attribute` values, Minitest autorun, `Rails.application` / `Rails.root`, AR schema maintenance.

- **One scenario per forked test** (`include ActiveSupport::Testing::Isolation`). Do not share a booted app across cases.
- **Never assert against the railties suite’s own `ActiveSupport::TestCase`**. That class is already loaded and may already have TestFixtures included; a hook registered in-process will fire immediately and pollute later tests.
- **Do not `load "rails/test_help.rb"`** in the parent process to simulate a refactor. That re-registers `on_load` blocks and, if IntegrationTest is loaded, re-runs `fixture_paths +=` and redefines `before_setup`.
- **Repeated-require and double-boot must happen inside the child** after the dummy environment is loaded, then the child exits.
- Restore `ENV["RAILS_ENV"]` and `ENV["PARALLEL_WORKERS"]` (`test_test.rb` already forces `PARALLEL_WORKERS=0`). `teardown_app` restores `Rails.application` and deletes `tmp`.
- If you must inspect arrays, snapshot before/after in the child; still also load a fixture or `file_fixture` so a “same object, wrong directory” bug fails.
- Parallel railties workers: Isolation forks anyway; keep the new file in the Isolation style so it is not order-dependent with `test_runner_test.rb`.

## Reorganization hazards this strategy is meant to catch

- Moving hook bodies into methods called from a file that is `load`ed or required via a new path → IntegrationTest path duplication grows; `before_setup` redefined twice.
- Looking up `Rails.root` lazily at test time → second app boot in one process changes paths (behavior change).
- Setting `file_fixture_path` only in the AR branch → skip-AR `file_fixture` breaks.
- Using `Pathname` or dropping the trailing slash → string `uniq` and engine `|=` stop matching; `fixtures :all` prefix stripping can break ([activerecord/lib/active_record/test_fixtures.rb](file:///home/user/workspace/repo/activerecord/lib/active_record/test_fixtures.rb) uses `f[path.to_s.size..-5]`).
- Applying `uniq` to IntegrationTest’s `+=` → array shape changes even if loads still work. Treat current duplication as preserved unless you explicitly decide otherwise; if you change it, the observable load tests should still pass and the array-equality snapshot should be updated on purpose.
- Defining `before_setup` without `super` → fixture setup or `@app = nil` disappears; integration tests fail first.

Baseline: run the existing railties commands above on current `test_help.rb`, then the new isolation matrix, then the same commands after the move. Any pass that only inspects `fixture_paths` without opening a yml or `file_fixture` is insufficient.
