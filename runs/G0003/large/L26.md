`ActionView::LookupContext` does not search the filesystem itself. It holds mutable lookup details, turns them into a cache key when caching is on, then asks `ActionView::PathSet` for the first matching resolver result. The resolver ranks files; locals only bind a `Template` after that ranking.

I ran `actionview/bin/test test/template/lookup_context_test.rb test/template/file_system_resolver_test.rb test/template/testing/fixture_resolver_test.rb`: 63 runs, 0 failures.

```text
LookupContext#find / #find_all / #find!
  normalize_name(name, prefixes)
  detail_args_for(options) → [details, details_key]
  PathSet#find / #find_all / #find!
    for each prefix, then each resolver:   # first non-empty / first hit wins
      FileSystemResolver#find / #find_all
        requested = details_key || TemplateDetails::Requested.new(**details)
        unbound_templates_for(name, prefix, partial, cached: !!details_key)
        rank / filter+sort by Requested indices
        UnboundTemplate#bind_locals(locals)
```

## What `#find` and `#find_all` actually do

[`LookupContext::ViewPaths`](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L145-L160) is the public lookup surface:

```145:160:actionview/lib/action_view/lookup_context.rb
      def find(name, prefixes = [], partial = false, keys = [], options = {})
        name, prefixes = normalize_name(name, prefixes)
        details, details_key = detail_args_for(options)
        @view_paths.find(name, prefixes, partial, details, details_key, keys)
      end
      # find! → PathSet#find!  (MissingTemplate on miss)
      # find_all → PathSet#find_all
```

`keys` is the locals list. It is not part of format/variant matching.

[`normalize_name`](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L229-L248) splits a `/` in the template name into a prefix. `"users/show"` with prefixes `["app"]` becomes name `"show"`, prefixes `["app/users"]`. No slash and empty prefixes becomes prefixes `[""]`.

[`detail_args_for`](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L201-L213) is the cache-key boundary:

- empty `options` (the common path): use the live `@details` hash and `details_key`
- non-empty `options`: `@details.merge(options)` for this call only; intern a key only if `@cache`
- `@cache == false`: `details_key` is `nil`

[`PathSet`](file:///home/user/workspace/repo/actionview/lib/action_view/path_set.rb#L40-L80) walks **prefix outer, resolver inner** and stops at the first success:

- `#find` → first non-nil template
- `#find_all` → first **non-empty** template array (not a union across prefixes/resolvers)
- `#find!` → `#find` or [`MissingTemplate`](file:///home/user/workspace/repo/actionview/lib/action_view/template/error.rb#L41-L65)

A miss from `#find` is `nil`. A miss from `#find!` is `ActionView::MissingTemplate` whose message lists `prefix/name` (or `prefix/_name` for partials) plus `details.inspect` and the searched path set. That is covered by [`TestMissingTemplate`](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L268-L288).

## Mutable details vs interned cache keys

Registered details are `:locale`, `:formats`, `:variants`, `:handlers`. The live state is `@details`, a Hash on the lookup context.

Setters from [`register_detail`](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L25-L41) coerce `value.present? ? Array(value) : default_*`. [`_set_detail`](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L132-L137) then:

1. dups `@details` if a key or digest cache already exists (so interned hashes are not mutated)
2. clears `@details_key` and `@digest_cache`
3. writes the new array

`details_key` is **not** that Hash. When `@cache` is true it is a [`TemplateDetails::Requested`](file:///home/user/workspace/repo/actionview/lib/action_view/template_details.rb#L5-L25) interned by [`DetailsKey.details_cache_key`](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L65-L76):

- `Requested#eql?` is identity (`alias :eql? :equal?`)
- the map key is the details Hash; identical content reuses the same `Requested`
- formats may be rewritten **only for the interned key** via `Template.normalized_formats` (`formats & Types.symbols` when the list is not all valid symbols). Assignment through `formats=` never reaches that path because it raises first.

Observable intern behavior from [`lookup_context_test.rb`](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L123-L143): `locale = :da` yields a new key; `locale = :en` restores the original object; `formats = [:html]` is a third key; `formats = nil` restores defaults and reuses an existing interned key.

`locale` is special: the getter returns `@details[:locale].first`, but the stored array is the default proc (`I18n.locale`, fallbacks, `I18n.default_locale`). `locale=` writes `I18n` then that full list.

## Resolver ranking

[`FileSystemResolver#find_all` / `#find`](file:///home/user/workspace/repo/actionview/lib/action_view/template/resolver.rb#L156-L174) always rank against a `Requested`:

```
requested_details = key || TemplateDetails::Requested.new(**details)
```

`!!key` is the unbound-template cache switch. A `Requested` key means “cache the glob”; `nil` means glob again.

Filename parse is [`Resolver::PathParser`](file:///home/user/workspace/repo/actionview/lib/action_view/template/resolver.rb#L12-L48): `prefix/_?action(.locale)?(.format)?(+variant)?(.handler)?`. A name containing `.` is rejected before glob ([`unbound_templates_from_path`](file:///home/user/workspace/repo/actionview/lib/action_view/template/resolver.rb#L196-L211)); `find_all("hello_world.html", ...)` is `[]` even if `hello_world.html.erb` exists ([`test_returns_no_results_with_dot`](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L228-L233)).

[`Requested`](file:///home/user/workspace/repo/actionview/lib/action_view/template_details.rb#L10-L25) builds index hashes `[*arr, nil]`. `nil` on a template (no locale/format/variant/handler in the filename) always matches, at the lowest priority for that axis.

[`matches?` / `rank_for` / `sort_key_for`](file:///home/user/workspace/repo/actionview/lib/action_view/template_details.rb#L36-L62) use the same order:

1. format
2. locale
3. variant
4. handler

Lower index wins. `#find` returns the single best unbound template; `#find_all` returns every match, sorted.

`variants: :any` uses `ANY_HASH`: `nil => 0`, every other variant `1`. All variants match; a no-variant file ranks first.

## Edge cases: selected set or error

### `formats = [:js]`

[`formats=`](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L287-L304) is the only setter that rewrites the live array before `_set_detail`.

If the array is exactly `[:js]` after `*/*` expansion and uniq:

- live `formats` become `[:js, :html]`
- `@html_fallback_for_js = true`

Observable: [`test "adds :html fallback to :js formats"`](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L64-L67) asserts `[:js, :html]`. Lookup then matches both `.js` and `.html` (and format-less files). `#find` prefers `:js` (index 0) over `:html` (index 1). If only an HTML file exists, that file is selected, not a miss. Renderer code later skips a second JS→HTML prepend when `html_fallback_for_js` is already set.

### Explicit `Mime::ALL`

`Mime::ALL` is `"*/*"`. `values.delete "*/*"` uses `==`, so the `Mime::ALL` object is removed and `default_formats` (`Mime.symbols` in this suite) is concatenated.

[`test "handles explicitly defined */* formats fallback to :js"`](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L59-L62):

```ruby
@lookup_context.formats = [:js, Mime::ALL]
# => [:js, *Mime.symbols].uniq
```

The length-1 JS fallback does **not** run. HTML is present because it is in `Mime.symbols`, not because of the JS special case. `@html_fallback_for_js` stays unset.

`formats = ["*/*"]` alone becomes `Mime.symbols` ([`handles */* formats`](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L54-L57)).

### Invalid formats

[`Template.validate_formats`](file:///home/user/workspace/repo/actionview/lib/action_view/template.rb#L204-L207) raises **before** `_set_detail`:

```ruby
@lookup_context.formats = [:html, :invalid, "also bad"]
# ArgumentError: Invalid formats: :invalid, "also bad"
```

[`test "raises on invalid format assignment"`](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L69-L75). `@details` is unchanged. Passing a bad format in `find(..., formats: ...)` options does not go through `formats=`; `DetailsKey` may strip unknown symbols for the interned key via `normalized_formats`, while the per-call details Hash still contains them.

### Locale / variant ordering

Order in the requested arrays **is** priority.

Locale ([`test_templates_with_optional_locale_shares_common_object`](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L128-L146)):

| request | files | `#find_all` sources |
|---|---|---|
| `locale: [:en]` | `hello_world.text.erb`, `hello_world.fr.text.erb` | `["Generic plain text!"]` |
| `locale: [:fr]` | same | `["Texte en Francais!", "Generic plain text!"]` |

The generic file is the same object in both results (`assert_same en[0], fr[1]`). `#find` for `:fr` would return only the French file.

Variant ([`test_finds_variants_in_order`](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L187-L204)):

| request | `#find` | `#find_all` |
|---|---|---|
| `variants: [:tricorder]` | tricorder file | `[tricorder]` |
| `variants: [:lcars]` | lcars file | `[lcars]` |
| `variants: [:tricorder, :lcars]` | tricorder | `[tricorder, lcars]` |
| `variants: [:lcars, :tricorder]` | lcars | `[lcars, tricorder]` |

Format sort is the same pattern: `[:json, :html]` yields JSON then HTML; `[:html, :json]` yields HTML then JSON ([`test_templates_sort_by_formats_*`](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L148-L174)).

Wrong details yield an empty set, not an error: HTML+ERB file with `formats: [:xml]` is `[]` ([`test_doesnt_find_template_with_wrong_details`](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L90-L99)).

### Partial lookup

`partial: true` only changes the virtual path via [`TemplatePath.virtual`](file:///home/user/workspace/repo/actionview/lib/action_view/template_path.rb#L17-L25): `"test" + "foo"` → `"test/_foo"`. The caller still passes `"foo"`, not `"_foo"`.

`#find("foo", %w(test), true)` selects `test/_foo.*`. `#find!` on miss says `Missing partial parent/_foo, child/_foo ...`. Details ranking is unchanged. Fixture test [`uses details as part of cache key`](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L145-L173) uses this path: `_foo.erb` vs `_foo.da.erb`.

### Locals and template selection

Locals do **not** pick a different file. After ranking, [`UnboundTemplate#bind_locals`](file:///home/user/workspace/repo/actionview/lib/action_view/unbound_template.rb#L21-L34) builds or reuses a `Template`.

| template kind | locals A vs B | observable |
|---|---|---|
| non-strict | `[:post]` twice | same `Template` object |
| non-strict | `[:post]` vs `[:post, :other]` | different objects |
| non-strict | `[:post, :other]` vs `[:other, :post]` | same object (sorted/frozen) |
| strict (`<%# locals: (...) %>`) | any locals list | same object; `template.locals` is `nil` |

Covered by [`test_strict_locals_reuses_same_template`](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L258-L267) and [`test_frozen_non_strict_templates_are_cached_per_locals`](file:///home/user/workspace/repo/actionview/test/template/file_system_resolver_test.rb#L95-L108) / [`test_strict_locals_templates_bind_once_for_any_locals`](file:///home/user/workspace/repo/actionview/test/template/file_system_resolver_test.rb#L111-L119).

Two locales that both match the same unbound file also share the bound object ([`test_same_template_from_different_details_is_same_object`](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L123-L126)).

### Cache on vs cache off

`@cache` defaults to `true`.

**Cache on:** `details_key` is a `Requested`. [`unbound_templates_for`](file:///home/user/workspace/repo/actionview/lib/action_view/template/resolver.rb#L177-L183) stores the glob in `@unbound_templates` under the virtual path. Repeated `#find` returns the same `Template` ([`test_found_template_is_cached`](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L102-L107), [`uses details as part of cache key`](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L145-L173)). Changing locale/formats invalidates the lookup-context key, so the resolver is asked with a different `Requested` and may return a different file, while the unbound list for that virtual path stays cached.

**Cache off** (`disable_cache` or `@cache = false`): `details_key` is `nil`. The resolver globs and builds new `UnboundTemplate`s every call, so `#find` returns a new object. The existing unbound cache is not cleared; a later cached find still returns the original object.

```ruby
a = context.find(...)               # cached Template
b = context.disable_cache { find }  # not same as a
c = context.find(...)               # same as a
```

[`test_different_templates_when_cache_disabled`](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L110-L121) and [`can disable the cache on demand`](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L175-L189).

The selected **file set** is the same on or off. What changes is object identity and whether the glob is reused.
