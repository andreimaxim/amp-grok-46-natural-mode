`content_for` is one method with two modes. A write is `name` plus a string/block; a read is `name` alone. Named slots live on `@view_flow` (`ActionView::OutputFlow`), not on `@output_buffer`. The template writes first; the layout reads later via `content_for(:slot)` or `yield :slot`.

```diagram
┌──────────── template.render ────────────┐
│  content_for :script, ... / &block      │
│           │                             │
│           ▼                             │
│     capture(&block)?                    │
│           │                             │
│           ▼                             │
│  view_flow.append / set(:script, html)  │
└──────────────────┳──────────────────────┘
                   │ then layout.render
                   ▼
┌──────────── layout <%= yield :script %> ┐
│  _layout_for(:script)                   │
│    view_flow.get(:script).html_safe     │
└─────────────────────────────────────────┘
```

## Write vs read

```172:192:actionview/lib/action_view/helpers/capture_helper.rb
      def content_for(name, content = nil, options = {}, &block)
        if content || block_given?
          if block_given?
            options = content if content
            content = capture(&block)
          end
          if content
            options[:flush] ? @view_flow.set(name, content) : @view_flow.append(name, content)
          end
          nil
        else
          @view_flow.get(name).presence
        end
      end
```

The branch is `content || block_given?`. Any truthy second argument, or a block, is a write. `content_for(:title)` with neither is a read.

**Write always returns `nil`.** That is deliberate so `<% content_for :x do %>` does not leak into the template buffer. Tests pin this even for whitespace-only blocks and `flush: true`.

**Read returns** `@view_flow.get(name).presence`. `OutputFlow#get` never returns `nil`; missing keys are an empty `SafeBuffer` via `Hash.new`. `.presence` turns that blank buffer into `nil`, which is why a missing slot is `nil` rather than `""`.

`false` and `nil` as the second argument with no block are **reads**, not writes: both are falsy, so `if content || block_given?` fails.

## Block capture vs direct content

Two write shapes, then one store.

**Direct:** `content_for :script, javascript_include_tag(:defaults)` (or a symbol; `OutputFlow` calls `value.to_s`). No `capture`. The value goes straight to `append`/`set`.

**Block:** argument shuffle, then `capture`.

```text
content_for :title, flush: true do ... end
  content  = { flush: true }     # second positional
  options  = {}
  block_given? → options = content, content = capture(&block)

content_for :title, nil, flush: true do ... end
  content  = nil
  options  = { flush: true }
  block_given? → options = content is skipped (nil), content = capture(&block)
```

`capture` does not swap `@output_buffer` for a new object. It swaps the **raw string inside** the same `OutputBuffer`, yields, then restores:

```text
CaptureHelper#capture
  OutputBuffer#capture
    old, @raw_buffer = @raw_buffer, +""
    value = yield
    new_buffer.html_safe          # SafeBuffer
  ensure restore @raw_buffer
  string = buffer if value.equal?(@output_buffer)
           buffer.presence || value   # otherwise
  case string
    OutputBuffer → to_s           # html_safe
    SafeBuffer   → string         # already safe
    String       → ERB::Util.html_escape(string)
    else         → nil            # Integer, etc.
```

ERB blocks write markup into the temp raw buffer and typically return `nil`. `buffer.presence` is that markup. Helper-style blocks that only return a string (`content_for(:bar) { "bar" }`) leave the temp buffer blank, so the return value is used and a plain `String` is escaped.

Whitespace-only ERB/buffer writes are **dropped**. `"  \n  ".presence` is `nil`; if the block also returns `nil`, `capture` returns `nil`. Then `if content` skips `append`/`set`. That is why `content_for :title do; output_buffer << "  \n  "; nil; end` between `"foo"` and `"bar"` still yields `"foobar"`.

Non-string block returns (`{ 1 }`) also produce `nil` from `capture` and never hit the flow.

## Append order and `flush: true`

Slots are a `Hash` of `SafeBuffer`s:

```6:27:actionview/lib/action_view/flows.rb
  class OutputFlow
    def initialize
      @content = Hash.new { |h, k| h[k] = ActiveSupport::SafeBuffer.new }
    end

    def get(key)
      @content[key]
    end

    def set(key, value)
      @content[key] = ActiveSupport::SafeBuffer.new(value.to_s)
    end

    def append(key, value)
      @content[key] << value.to_s
    end
```

Default write is **append in call order**. `content_for :title, "foo"` then `content_for :title, :bar` stores `"foobar"`. Same for two blocks: `"foo"` then `"bar"` → `"foobar"`. `flush: false` is the same path (`options[:flush]` is falsy).

`flush: true` is **replace**, not concatenate: `view_flow.set` assigns a new `SafeBuffer`. Previous chunks for that name are gone. A later append without flush starts from that replacement.

Flush only runs if `content` is truthy after capture. A whitespace-only flushed block does **not** clear the slot; `set` is skipped and the old value remains.

## `content_for?`

```215:217:actionview/lib/action_view/helpers/capture_helper.rb
      def content_for?(name)
        @view_flow.get(name).present?
      end
```

Same `get` as the read path, then `.present?` instead of `.presence`. Empty / missing → `false`. Any stored non-blank string → `true`. Layouts use this for structure (`body` class, optional columns) without emitting the slot.

It does not distinguish “never written” from “written then flushed to `""`”: both are blank `SafeBuffer`s. `get` on a missing key **inserts** the default empty buffer into `@content` (Hash default block). Presence is unchanged; the key now exists.

## Layout read path

```text
TemplateRenderer#render_with_layout
  view.view_flow.set(:layout, template.render { view._layout_for(*name) })
  layout.render { view._layout_for(*name) }

Context#_layout_for(name = nil)
  name ||= :layout
  view_flow.get(name).html_safe
```

The template runs to completion first, so every `content_for` write is in `@view_flow` before the layout evaluates `<%= yield :script %>`. Bare `<%= yield %>` is `_layout_for` with no name → key `:layout` (the template body). Named `yield :script` is the same `get` as `content_for(:script)`, without `.presence` (empty buffer rather than `nil`).

`content_for` still works in helpers; `yield` does not. Both read the same hash.

## Why the stored string stays safe on the view buffer

Safety is applied **on the way in**, then the slot is a `SafeBuffer`, so `<%= content_for :x %>` / `<%= yield :x %>` will not escape again.

1. **Block path.** `capture` returns either `OutputBuffer#to_s` / `html_safe` (already escaped as the ERB buffer appended) or `ERB::Util.html_escape` on a plain `String`. Helpers like `content_tag` already return a `SafeBuffer`; that object is passed through.

2. **Append path.** `@content[key] << value.to_s` concatenates onto a `SafeBuffer`. `SafeBuffer#concat` runs `implicit_html_escape_interpolated_argument`: unsafe strings are escaped; `html_safe?` values are not. Direct `content_for :title, "<p>"` becomes `&lt;p&gt;`. `raw("<p>")` stays `<p>`.

3. **Set / flush path.** `SafeBuffer.new(value.to_s)` is a new buffer whose `html_safe?` is true (`@html_unsafe` is nil). That is why `content_for :title, "", flush: true` followed by another `content_tag` block still has `content_for(:title).html_safe? == true`. Flushing to a raw String would have broken later concatenations.

4. **Read path.** `.presence` on a non-blank `SafeBuffer` returns that buffer. `_layout_for` calls `.html_safe` again (no-op if already safe). Either way the object that hits `@output_buffer <<` is `html_safe?`, so `OutputBuffer#<<` takes the unescaped branch.

Debugging layout slots: if the chunk is missing, check write-vs-read (`nil` second arg / no block), a `nil`/whitespace `capture` that skipped `append`/`set`, or `flush: true` that replaced earlier writes. If markup is escaped twice or not at all, check whether the write went through `capture` (block) or `SafeBuffer#<<` (direct), and whether the value was already `html_safe?`.
