Invariants that every truncated result must keep, except the documented `ArgumentError` case: `result.bytesize <= truncate_to`, `result.valid_encoding?`, `result` is a different object from the receiver, the receiver’s `bytes`/`encoding`/`object_id` are unchanged.

```ruby
# frozen_string_literal: true
require "active_support/core_ext/string/filters"

class MyString < String; end

def probe(str, truncate_to, **kw)
  before = [str.dup, str.encoding, str.bytes, str.object_id, str.class]
  result = str.truncate_bytes(truncate_to, **kw)
  {
    value: result,
    bytesize: result.bytesize,
    encoding: result.encoding,
    klass: result.class,
    frozen: result.frozen?,
    equal_receiver: result.equal?(str),
    receiver: [str, str.encoding, str.bytes, str.object_id, str.class]
  }
rescue ArgumentError => e
  { error: e.class, message: e.message, receiver: before }
end
```

## 1. Within-budget strings

| Receiver | Call | Observe |
|---|---|---|
| `"hello"` | `truncate_bytes(10)` | `"hello"`, new object, unfrozen |
| `"👍👍"` (8 bytes) | `truncate_bytes(16)` | `"👍👍"`, new object |
| `"abc"` | `truncate_bytes(3)` | `"abc"` (equality at the budget still copies) |
| `""` | `truncate_bytes(0)` | `""` |
| `"abc".freeze` | `truncate_bytes(10)` | unfrozen copy; receiver stays frozen |
| `MyString.new("abc")` | `truncate_bytes(10)` | `MyString`, not `equal?` to receiver |

Then mutate the result (`result[0] = "Z"`). Receiver stays `"abc"`.

This proves the `bytesize <= truncate_to` branch returns `dup`: same characters, class, and encoding; never the same object; never a bang-style in-place edit. A refactor that returns `self` when the string already fits fails here.

## 2. ASCII truncation

Receiver `"abcdefghij"` (10 bytes).

| Call | Result | bytesize |
|---|---|---|
| `truncate_bytes(7)` | `"abcd…"` | 7 |
| `truncate_bytes(7, omission: nil)` | `"abcdefg"` | 7 |
| `truncate_bytes(7, omission: "..")` | `"abcde.."` | 7 |
| `truncate_bytes(6, omission: ".....")` | `"a....."` | 6 |

This proves the cut is `truncate_to - omission.bytesize` bytes of prefix plus the omission, and that ASCII (1 byte per grapheme) can fill the budget exactly. A byte-index off-by-one or a character-count cut shows up immediately.

## 3. Multibyte truncation

`"café"` is 5 bytes (`é` is 2). `"👍👍👍👍"` is 16 bytes (four 4-byte clusters).

| Call | Result | bytesize |
|---|---|---|
| `"café".truncate_bytes(5)` | `"café"` | 5 (within budget) |
| `"café".truncate_bytes(4)` | `"c…"` | 4 |
| `"café".truncate_bytes(4, omission: nil)` | `"caf"` | 3 |
| `"café".truncate_bytes(3)` | `"…"` | 3 |
| `"👍👍👍👍".truncate_bytes(15)` | `"👍👍👍…"` | 15 |
| `"👍👍👍👍".truncate_bytes(12)` | `"👍👍…"` | 11 |
| `"👍👍👍👍".truncate_bytes(8)` | `"👍…"` | 7 |
| `"👍👍👍👍".truncate_bytes(5)` | `"…"` | 3 |

This proves the method never emits a partial UTF-8 sequence, and that the result may be *shorter* than the budget when the next cluster does not fit. `"👍👍👍👍".truncate_bytes(12)` at 11 bytes is the smoking gun for “room for one more 👍 (4) plus `…` (3) is 7, not 12.” A `byteslice` refactor that splits `é` or `👍` fails `valid_encoding?` or the exact string.

## 4. Grapheme clusters

`"a ❤️ b"` clusters: `["a", " ", "❤️", " ", "b"]` with sizes `[1, 1, 6, 1, 1]`. `"❤️"` is U+2764 U+FE0F, not one codepoint. `"👩‍❤️‍👩"` is one 20-byte cluster. `"e\u0301e\u0301"` is two 3-byte clusters (`e` + combining acute).

| Call | Result | bytesize |
|---|---|---|
| `"a ❤️ b".truncate_bytes(n, omission: nil)` for `n=2..7` | `"a "` | 2 |
| same, `n=8` | `"a ❤️"` | 8 |
| same, `n=9` | `"a ❤️ "` | 9 |
| `"👩‍❤️‍👩".truncate_bytes(13, omission: nil)` | `""` | 0 |
| `"👩‍❤️‍👩".truncate_bytes(19, omission: nil)` | `""` | 0 |
| `"a 👩‍❤️‍👩".truncate_bytes(13, omission: nil)` | `"a "` | 2 |
| `"e\u0301e\u0301".truncate_bytes(n, omission: nil)` for `n=1,2` | `""` | 0 |
| same, `n=3..5` | `"e\u0301"` | 3 |

Also assert every result’s `each_grapheme_cluster.to_a` is a prefix of the receiver’s clusters.

This proves the walker is grapheme-based, not codepoint- or byte-based. A `each_char` rewrite would split `❤️` or leave a combining mark; a `byteslice` rewrite would split ZWJ sequences. The all-or-nothing 20-byte cluster is the case that distinguishes those.

## 6. Custom and nil omissions

On `"👍👍👍👍"` (16 bytes):

| Call | Result |
|---|---|
| `truncate_bytes(15)` | `"👍👍👍…"` |
| `truncate_bytes(15, omission: nil)` | `"👍👍👍"` |
| `truncate_bytes(15, omission: "")` | `"👍👍👍"` |
| `truncate_bytes(15, omission: " ")` | `"👍👍👍 "` |
| `truncate_bytes(15, omission: "🖖")` | `"👍👍🖖"` |
| `"abcdefghij".truncate_bytes(8, omission: "[..]")` | `"abcd[..]"` |

This proves `omission: nil` is `""` (not the default `"…"`), that `""` and `nil` agree, that a custom omission replaces the suffix rather than appending after a default ellipsis, and that the prefix shrinks to leave room for the omission’s *bytesize*. `nil` vs `""` is the branch a `omission || "…"` bug would break.

## 7. Omission equal to or larger than the budget

| Call | Observe |
|---|---|
| `"abcdefgh".truncate_bytes(3)` | `"…"` (omission bytesize == 3) |
| `"👍👍👍👍".truncate_bytes(4, omission: "🖖")` | `"🖖"` |
| `"abcdef".truncate_bytes(3, omission: "xyz")` | `"xyz"`, not `equal?` to the omission object |
| `"abcdef".truncate_bytes(3, omission: MyString.new("xyz"))` | `MyString` `"xyz"` — class follows the *omission*, not the receiver |
| `"👍👍👍👍".truncate_bytes(3, omission: "🖖")` | `ArgumentError`: `Omission "🖖" is 4, larger than the truncation length of 3 bytes` |
| `"abc".truncate_bytes(2)` | `ArgumentError`: `Omission "…" is 3, larger than the truncation length of 2 bytes` |
| `"a".truncate_bytes(0)` | `ArgumentError` (default omission is 3 bytes) |
| `"a".truncate_bytes(0, omission: nil)` | `""` (nil → `""`, bytesize 0 == budget) |

This proves three separate arms: `omission.bytesize > truncate_to` raises with that exact message; `==` returns `omission.dup` and does not walk the receiver; `nil` at budget 0 is empty, not an error. A refactor that always concatenates a prefix+omission, or that raises on `>=` instead of `>`, fails here. The `MyString` omission proves `omission.dup` rather than `self.class.new(omission)`.

## 8. Encoding and subclass preservation

| Receiver | Call | `result.class` | `result.encoding` |
|---|---|---|---|
| UTF-8 `"a"*30` | `truncate_bytes(15)` | `String` | `UTF-8` |
| UTF-8 `"a"*30` | `truncate_bytes(100)` | `String` | `UTF-8` |
| `US-ASCII "abcdefghij"` | `truncate_bytes(5, omission: ".")` | `String` | `US-ASCII` |
| `US-ASCII "abcdefghij"` | `truncate_bytes(5)` (omission `"…"`) | `String` | `UTF-8` |
| `US-ASCII "abcdefghij"` | `truncate_bytes(20)` | `String` | `US-ASCII` |
| `ASCII-8BIT "abc\xFF"` | `truncate_bytes(3, omission: ".")` | `String` | `ASCII-8BIT` |
| `MyString.new("abcdefghij")` | `truncate_bytes(5)` | `MyString` | UTF-8 (`"…"` widens it) |
| `MyString.new("abcdefghij").force_encoding(US_ASCII)` | `truncate_bytes(5, omission: ".")` | `MyString` | `US-ASCII` |

This proves:

- Within-budget `dup` copies encoding and class.
- The truncate path is `self.class.new.force_encoding(encoding)` then `<< omission`, so a UTF-8 omission can widen `US-ASCII`.
- Subclass is preserved on both the copy path and the cut path.
- A `+""` / `String.new` refactor that drops the subclass, or a `encode` that always forces UTF-8, fails this table.

## 9. Receiver mutation

For every call above, snapshot `object_id`, `bytes`, `encoding`, and `frozen?` before the call.

Observe: they are identical after the call; `result.equal?(receiver)` is always false; `result.frozen?` is always false.

Then, for both a within-budget and a truncated result, mutate the result (`<<` or `[]=`). The receiver does not change.

This proves there is no in-place write and that `dup` is a real copy, not a wrapper around the same buffer. Returning `self` for the fast path, or building the cut by mutating a receiver copy that was not copied, fails here.
