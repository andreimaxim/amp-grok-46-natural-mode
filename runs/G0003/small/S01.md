`travel_to` freezes “now” for the current test object by replacing four class methods. It does not stub `Time.current` or `Date.current`; those keep working because they read through `Time.now` / `Date.today`.

```text
travel_to(date_or_time, with_usec: false)
  reject nested block if in_block
  normalize input → now
  zero usec unless with_usec
  now = now.getlocal          # system TZ
  remember previous Time.now if already stubbed
  stub Time.now / Time.new / Date.today / DateTime.now
  if block
    in_block = true
    yield
    restore previous freeze, or travel_back
    in_block = false
```

The implementation lives in [`activesupport/lib/active_support/testing/time_helpers.rb`](file:///home/user/workspace/repo/activesupport/lib/active_support/testing/time_helpers.rb). `after_teardown` always calls `travel_back`, so a no-block freeze does not leak into the next test.

## Input normalization

Three branches, then a shared local conversion:

```162:175:activesupport/lib/active_support/testing/time_helpers.rb
        if date_or_time.is_a?(Date) && !date_or_time.is_a?(DateTime)
          now = date_or_time.midnight.to_time
        elsif date_or_time.is_a?(String)
          now = Time.zone.parse(date_or_time)
        else
          now = date_or_time
          now = now.to_time unless now.is_a?(Time)
        end

        now = now.change(usec: 0) unless with_usec

        # +now+ must be in local system timezone, because +Time.at(now)+
        # and +now.to_date+ (see stubs below) will use +now+'s timezone too!
        now = now.getlocal
```

**Date** (not `DateTime`): `midnight` is `beginning_of_day`, which is `in_time_zone` — midnight in the **application** time zone. Then `#to_time`. The documented contract: `Time.current` is that midnight; `Time.now` is the same instant in the **system** zone; `Date.today` follows `Time.now` and can therefore differ from `Date.current` when the two zones disagree.

**String**: `Time.zone.parse(...)` in the application zone. A string with fractional seconds still hits the later usec strip unless `with_usec: true`. Tests parse `"2004-11-24T01:04:44.123-05:00"` and assert `Time.zone.now` at whole seconds.

**Time** (and anything else): used as-is if `is_a?(Time)`, otherwise `#to_time`. `DateTime` is a `Date` subclass, so the first branch excludes it and it goes through `#to_time`. `ActiveSupport::TimeWithZone` reports `is_a?(Time)`, so it is not converted again before `change` / `getlocal`.

`getlocal` is required. The stubs below use `Time.at(now)` and `now.to_date`, both of which keep `now`’s zone. After this, every stubbed clock speaks system local time.

## What is stubbed

`SimpleStubs` aliases the original singleton method, then defines a new one. Re-stubbing unaliases first so the recorded original stays the real Ruby method.

| Call | Stub body |
|---|---|
| `Time.now` | `Time.at(now)` |
| `Time.new` | `Time.at(now)` only when both args and kwargs are empty; otherwise the original `Time.new` |
| `Date.today` | `Date.jd(now.to_date.jd)` |
| `DateTime.now` | `DateTime.jd(date, hour, min, sec+subsec, Rational(utc_offset, 86400))` |

`Time.new` is the special case:

```181:188:activesupport/lib/active_support/testing/time_helpers.rb
        stubs.stub_object(Time, :new) do |*args, **options|
          if args.empty? && options.empty?
            at(now)
          else
            stub = stubs.stubbing(Time, :new)
            Time.send(stub.original_method, *args, **options)
          end
        end
```

`Time.new` and `Time.new()` return the frozen instant. Any positional argument (`Time.new(2021)`, `Time.new(2004, 11, 25)`) or any keyword (`Time.new(precision: 3)`) bypasses the freeze and constructs a real `Time`. That is why tests assert `Time.new(precision: 3) !=` the traveled time: `precision:` is a kwarg, so you get wall-clock `Time.new`, not the stub.

`Date.today` / `DateTime.now` are rebuilt from the local `now`, not by wrapping the original objects. Subclasses of `Time`/`Date`/`DateTime` are untouched; only the base class singleton methods are replaced.

## `with_usec`

Default `false`: `now.change(usec: 0)` before stubbing. That is deliberate. MySQL rounds fractional seconds instead of flooring; a usec of `999999` can become the next whole second in the database. Tests freeze `Time.utc(2014, 10, 10, 10, 10, 50, 999999)` and assert both `Time.now` and `DateTime.now` have `sec == 50` and `usec == 0`.

`with_usec: true` skips that `change`. Subseconds survive on `Time.now` and on `DateTime.now` (`sec + now.subsec` in the `DateTime.jd` call). `travel` and `freeze_time` forward the same flag.

## Block cleanup

Before installing new stubs, the method snapshots any existing freeze:

```177:205:activesupport/lib/active_support/testing/time_helpers.rb
        stubs = simple_stubs
        stubbed_time = Time.now if stubs.stubbing(Time, :now)
        stubs.stub_object(Time, :now) { at(now) }
        ...
        if block_given?
          begin
            self.in_block = true
            yield
          ensure
            if stubbed_time
              travel_to stubbed_time
            else
              travel_back
            end
            self.in_block = false
          end
        end
```

Two restore paths:

- **No prior stub** (`stubbed_time` nil): `travel_back` → `simple_stubs.unstub_all!`. Real `Time.now` / `Date.today` / `DateTime.now` / `Time.new` return.
- **Prior no-block travel** on this same helper: `Time.now` was already stubbed, so `stubbed_time` is that frozen instant. The ensure calls `travel_to stubbed_time` (no block), which reinstalls the outer freeze. That is the `test_time_helper_travel_with_subsequent_block` case: `travel_to outer`; then `travel_to(inner) { ... }`; after the block, `Time.now` is `outer` again.

The snapshot is taken on **this** helper’s `SimpleStubs`, before the new stubs go in. A no-block `travel_to` inside a block is allowed and just overwrites the stubs; the outer `ensure` still restores whatever was captured at the outer call (real time, or an earlier freeze).

## Why nested block-form `travel_to` is rejected

The guard is `block_given? && in_block`. `in_block` is set only while a **block-form** `travel_to` on this object is running.

So:

- `travel_to t1 do; travel_to(t2) do ... end; end` → `RuntimeError`
- `travel_to t1 do; travel_to(t2); end` → allowed (inner has no block)
- `travel_to t1` then `travel_to(t2) do ... end` → allowed (`in_block` is still false)

The error text is the reason: a second block would compose against an already-stubbed clock. `travel_to 2.days.from_now` then nested `travel_to 3.days.from_now` is **five** days from real today, not three. `in_block` is a single flag, not a stack, so the helper refuses that shape instead of trying to unwind nested ensures.

The suggested alternative in the exception is sibling `travel N.days do ... end` blocks, each measured from real time.
