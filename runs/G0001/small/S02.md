This looks equivalent, but it removes the compatibility check that `deep_merge!` is supposed to consult.

`this_val` owns that decision today:

```ruby
if this_val.is_a?(DeepMergeable) && this_val.deep_merge?(other_val)
  this_val.deep_merge(other_val, &block)
elsif block_given?
  block.call(key, this_val, other_val)
else
  other_val
end
```

`deep_merge?` is public extension API. The default is `other.is_a?(self.class)`, and includers are documented to override it to restrict or expand what can be merged. `Hash` restricts to `other.is_a?(Hash)`; `ActionController::Parameters` expands to any `DeepMergeable`; `OmniWrapper` in the tests expands to `OtherWrapper`. After this change none of those overrides are called.

That is a behavior change, not a cleanup:

- Two `DeepMergeable` values that fail `deep_merge?` currently skip recursion and use the block, or `other_val` if there is no block. The tests pin that: `Wrapper` does not deep-merge `OtherWrapper`; with a block, that pair would hit the block instead of recursing. The new check always recurses whenever both sides include the module, so the block never runs for those pairs and the nested value is a merged object instead of a replacement.
- Custom classes that expand the domain the other way also break. `deep_merge?(other)` can return true for a non-`DeepMergeable` value; `other_val.is_a?(DeepMergeable)` would reject that and fall through to the block / replace path.
- Recursion still goes through `deep_merge` (dup, then `deep_merge!`), so nested values on the recursive path stay unmutated and `deep_merge!` still returns `self` via `merge!`. What changes is which nested pairs take that path. For `Hash` vs `Parameters`, `Hash#deep_merge?` is false today, so a nested `Parameters` replaces. After this, `Hash#deep_merge` would `merge!` a `Parameters`, which coerces through `to_hash` and can raise `UnfilteredParameters`.

`activesupport/test/deep_mergeable_test.rb` already covers the cases this would break: default subclass merging, default rejection of non-subclasses, and an override that allows a foreign `DeepMergeable`. Please keep `this_val.deep_merge?(other_val)`.
