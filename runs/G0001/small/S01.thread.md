## Assistant

`travel_to` freezes the process clock for a test by stubbing four class methods. It does not stub `Time.current` or `Date.current`; those still go through `Time.zone` and therefore pick up the stubs underneath.

The public method is [`ActiveSupport::Testing::TimeHelpers#travel_to`](file:///home/user/workspace/repo/activesupport/lib/active_support/testing/time_helpers.rb#L133-L205). `travel` and `freeze_time` both call it.

```text
travel_to(date_or_time, with_usec: false)
  reject nested block-form travel
  normalize input → a Time
  zero usec unless with_usec
  convert to system local time (getlocal)
  remember prior stubbed Time.now, if any
  stub Time.now / Time.new / Date.today / DateTime.now
  if block
    in_block = true
    yield
    restore prior travel, or unstub to real time
    in_block = false
```

### Input normalization

Three branches, then two shared steps.

```text
Date (not DateTime)  →  date.midnight.to_time     # midnight in Time.zone
String               →  Time.zone.parse(string)
anything else        →  keep if Time, else #to_time

then: change(usec: 0) unless with_usec
then: getlocal                          # system TZ, not Time.zone
```

**Date.** `DateTime < Date`, so the Date branch is `is_a?(Date) && !is_a?(DateTime)`. `Date#midnight` is `beginning_of_day`, which is `in_time_zone` — start of that calendar day in the **application** zone. `.to_time` then becomes a `Time`. That matches the method docs: `Time.current` is that midnight; `Time.now` is the same instant in the **system** zone, which can be a different calendar day.

**String.** Parsed with `Time.zone.parse`, so `"2004-11-24 01:04:44"` is application-zone local time, not `Time.parse`.

**Time / DateTime / TimeWithZone / other.** A `Time` is kept. Everything else is `#to_time` (covers `DateTime` and `ActiveSupport::TimeWithZone`).

**Then usec, then `getlocal`.** The stubs below use `Time.at(now)` and `now.to_date`. Both follow `now`’s own offset. If the frozen instant stayed in UTC near a zone boundary, `Date.today` would be the UTC date, not the local date. `getlocal` makes every stub speak system local time.

### What is stubbed

[`SimpleStubs`](file:///home/user/workspace/repo/activesupport/lib/active_support/testing/time_helpers.rb#L9-L65) aliases the original singleton method aside and redefines it on `Time`, `Date`, and `DateTime`. A later stub of the same method first restores the original, so the next unstub still lands on real Ruby, not on an older travel.

| Call | Stub body | Effect |
|---|---|---|
| `Time.now` | `at(now)` | Frozen instant as a local `Time` |
| `Time.new` | see below | No-arg constructor only |
| `Date.today` | `jd(now.to_date.jd)` | Local calendar date of `now` |
| `DateTime.now` | `jd(..., now.sec + now.subsec, offset)` | Same instant, including subsec and UTC offset |

Not stubbed: `Time.current`, `Date.current`, `Time.zone.now`, `Time.zone.today`. Those keep working because they call `Time.now` / `Date.today` (or zone equivalents built from them).

Subclasses (`TimeSubclass.now`, etc.) are also unstubbed: the stub lives on `Time` / `Date` / `DateTime`’s singleton class, so a subclass still inherits the frozen clock but keeps its own class.

### `Time.new` with arguments

```ruby
stubs.stub_object(Time, :new) do |*args, **options|
  if args.empty? && options.empty?
    at(now)
  else
    Time.send(stubs.stubbing(Time, :new).original_method, *args, **options)
  end
end
```

- `Time.new` with **no** args and **no** kwargs → same as `Time.now` (frozen).
- Any positional args (`Time.new(2004, 11, 25)`) or any kwargs (`Time.new(precision: 3)`) → real `Time.new`.

That is why tests assert `Time.new == traveled_time` but `Time.new(precision: 3)` and `Time.new(2004, 11, 25)` do not. Construction of a specific wall time is not frozen; only “what time is it right now?” is.

### `with_usec`

Default `false`: `now.change(usec: 0)` before stubbing. `Time.now.usec` and `DateTime.now.usec` are 0. The comment and tests name the reason: MySQL rounds fractional seconds instead of flooring, which otherwise produces off-by-one-second timestamps.

`with_usec: true` skips that. Fractional seconds survive on `Time.now` (`to_f` compared in tests) and on `DateTime.now` because the DateTime stub uses `now.sec + now.subsec`. `travel` and `freeze_time` forward the flag.

A string with millis (`"2004-11-24T01:04:44.123-05:00"`) still ends at `:44` and 0 usec unless you pass `with_usec: true`.

### Block cleanup

Before installing new stubs, `travel_to` snapshots the current frozen clock **only if `Time.now` is already stubbed**:

```ruby
stubbed_time = Time.now if stubs.stubbing(Time, :now)
```

That value is the previous travel destination, not wall-clock now.

```diagram
                  ┌─────────────────┐
     no block     │ stubs stay until │
  ───────────────▶│ travel_back /    │
                  │ after_teardown   │
                  └─────────────────┘
travel_to
                  ┌─────────────────┐
     with block   │ yield           │
  ───────────────▶│                 │
                  │ ensure:         │
                  │  prior stub?    │
                  │   yes → travel_to(stubbed_time)
                  │   no  → travel_back
                  └─────────────────┘
```

Two restore paths:

1. **No prior travel.** `stubbed_time` is nil. `ensure` calls `travel_back`, which `unstub_all!`s. Real `Time.now` / `Date.today` / `DateTime.now` return.
2. **A non-block `travel_to` was already in force.** `stubbed_time` is that frozen `Time`. `ensure` calls `travel_to stubbed_time`, which reinstalls the outer stubs. The inner block is a temporary overlay.

Tests pin this: `travel_to outer` (no block), then `travel_to(inner) { ... }` — after the block, `Time.now` is `outer` again.

`after_teardown` always calls `travel_back`, so a no-block `travel_to` cannot leak into the next test on the same case.

`in_block` is cleared in `ensure` as well, including on raise.

### Nested block-form `travel_to`

Rejected only when **this** helper instance is already inside a block-form `travel_to` **and** the new call also takes a block:

```ruby
if block_given? && in_block
  raise ... "can lead to confusing time stubbing."
end
```

`in_block` is a per-test-instance flag, set only around the `yield`.

Allowed:

- successive no-block `travel_to` (second wins)
- no-block `travel_to` inside a block (clock jumps; outer `ensure` still restores whatever `stubbed_time` was at outer entry — usually real time)
- block-form `travel_to` after a no-block travel (the overlay case above)

Rejected: block inside block on the same helper.

The raise exists because the inner destination is evaluated **on the already-frozen clock**. The error’s own example:

```ruby
travel_to 2.days.from_now do
  travel_to 3.days.from_now do
    # 5 days from today, not 3
  end
end
```

`3.days.from_now` is `Time.now + 3.days`, and `Time.now` is already +2 days. Cleanup would also stack: each block’s `ensure` either `travel_back`s or re-`travel_to`s a snapshot taken at a different nesting level. The helper refuses that rather than define what nested block restore means.

Use `travel 2.days` / `travel 5.days` (relative, each from real now at call time) or a no-block inner `travel_to` if you only need to jump the clock inside one block.
