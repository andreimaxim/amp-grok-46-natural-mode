Current contract is in [`truncate_bytes`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/string/filters.rb#L125-L155). Treat that method as the oracle: same inputs, same process, no I18n, no locale, no RNG.

Do not trust string equality alone. For every case record this tuple:

- `result` value
- `result.bytesize` and `result.bytes`
- `result.valid_encoding?`
- `result.encoding`
- `result.class`
- `result.equal?(receiver)` and `result.equal?(omission)`
- `receiver` before vs after
- exception class and message, if any

A refactor is unchanged only if every field matches. Existing tests in [`string_ext_test.rb`](file:///home/user/workspace/repo/activesupport/test/core_ext/string_ext_test.rb#L340-L408) are necessary but not sufficient: they miss identity, subclass, mutation, and the “result may be strictly shorter than the budget” rule.

### 1. Within-budget strings

**Inputs (fixed):**

| receiver | `bytesize` | budget | omission |
|---|---|---|---|
| `"hello"` | 5 | 5 | default |
| `"hello"` | 5 | 10 | default |
| `"👍👍"` | 8 | 16 | default / `nil` / `"🖖"` |
| frozen `"hello"` | 5 | 10 | default |

**Expect:** value equal to the receiver; `bytesize` unchanged; **not** `equal?` to the receiver; result unfrozen even if the receiver is frozen; receiver unchanged.

**Proves:** the `bytesize <= truncate_to` branch returns `dup`, not `self`, not a truncated copy, and not a frozen share. Omission is ignored when nothing is cut. A refactor that returns `self` for the “no work” path fails identity and frozen-receiver checks.

### 2. ASCII truncation

**Input:** `"Hello World"` (`bytesize` 11).

| budget | omission | expected value | expected `bytesize` |
|---|---|---|---|
| 11 | default | `"Hello World"` | 11 |
| 10 | default `"…"` (3 bytes) | `"Hello W…"` | 10 |
| 8 | default | `"Hello…"` | 8 |
| 8 | `"..."` | `"Hello..."` | 8 |

**Also assert:** `result.bytesize <= budget`, valid encoding, receiver still `"Hello World"`.

**Proves:** the cut point is `budget - omission.bytesize` in **bytes**, then the omission is appended. ASCII graphemes are 1 byte, so this looks like character truncation — which is why it must be paired with the multibyte cases. A `length`-based cut (characters, not bytes) still passes these.

### 3. Multibyte truncation

**Input:** `"👍👍👍👍"` — four 4-byte emoji, `bytesize` 16. Default omission `"…"` is 3 bytes.

| budget | expected | `bytesize` | note |
|---|---|---|---|
| 16 | `"👍👍👍👍"` | 16 | within budget |
| 15 | `"👍👍👍…"` | 15 | 3 emoji + 3-byte omission |
| 12 | `"👍👍…"` | **11** | 8+3; third emoji does not fit in the remaining 1 byte |
| 8 | `"👍…"` | **7** | same undershoot |
| 5 | `"…"` | 3 | no emoji fits in `5-3=2` |
| 4 | `"…"` | 3 | no emoji fits in `4-3=1` |

**Proves two rules together:**

1. Never split a multibyte codepoint (`byteslice(0, n)` would emit invalid UTF-8).
2. Never pad up to the budget. The method takes whole graphemes while `cut.bytesize + grapheme.bytesize <= cut_at`, then appends the omission. Spare bytes are left unused.

A `byteslice` refactor fails validity. A “fill remaining bytes” refactor fails the 12 → 11 observation.

### 4. Grapheme clusters

Use `omission: nil` so the omission does not hide cluster math. Clusters on this checkout:

- `"a ❤️ b"` → `["a", " ", "❤️", " ", "b"]` with sizes `[1, 1, 6, 1, 1]`, total 10. `"❤️"` is U+2764 + U+FE0F, **one** cluster of 6 bytes.
- `"👩‍❤️‍👩"` → one cluster, 20 bytes.
- `"e\u0301e\u0301"` (e + combining acute, twice) → two clusters of 3 bytes each.

| input | budget | expected |
|---|---|---|
| `"a ❤️ b"` | 1 | `"a"` |
| `"a ❤️ b"` | 2..7 | `"a "` |
| `"a ❤️ b"` | 8 | `"a ❤️"` |
| `"a ❤️ b"` | 9 | `"a ❤️ "` |
| `"a ❤️ b"` | 10 | full string (dup) |
| `"👩‍❤️‍👩"` | 13 or 19 | `""` |
| `"👩‍❤️‍👩"` | 20 | full string |
| `"e\u0301e\u0301"` | 1 or 2 | `""` |
| `"e\u0301e\u0301"` | 3..5 | one clustered `é` (3 bytes) |
| `"e\u0301e\u0301"` | 6 | full string |

**Proves:** truncation walks `each_grapheme_cluster`, not codepoints and not bytes. A codepoint walk would split `"❤️"` into `❤` plus VS-16, or emit a combining mark without its base. A byte walk would emit invalid UTF-8. The ZWJ family-emoji case proves an oversized single cluster becomes `""` rather than a partial person/heart.

### 5. Exact byte boundaries

**Input:** `"café"` — `é` is one 2-byte codepoint/cluster; total `bytesize` 5.

| budget | omission | expected | `bytes` |
|---|---|---|---|
| 0 | `nil` | `""` | `[]` |
| 1 | `nil` | `"c"` | `[99]` |
| 3 | `nil` | `"caf"` | `[99,97,102]` |
| 4 | `nil` | `"caf"` | same — the 2-byte `é` does not fit in the last byte |
| 5 | `nil` | `"café"` | full, via the within-budget branch |
| 3 | default | `"…"` | omission only (`cut_at == 0`) |
| 4 | default | `"c…"` | 1 byte prefix + 3-byte omission |

Assert `valid_encoding? == true` and that `bytes` never contain a dangling `0xC3` from a split `é`.

**Proves:** the cut is a whole-cluster prefix of `budget - omission.bytesize`, not `byteslice`. Budget 4 vs 5 also proves the within-budget branch is `<=`, not `<`.

### 6. Custom and nil omissions

**Input:** `"👍👍👍👍"` (`bytesize` 16), budget 15.

| omission | expected | `bytesize` |
|---|---|---|
| default `"…"` | `"👍👍👍…"` | 15 |
| `nil` | `"👍👍👍"` | 12 |
| `""` | `"👍👍👍"` | 12 |
| `" "` | `"👍👍👍 "` | 13 |
| `"🖖"` (4 bytes) | `"👍👍🖖"` | 12 |

**Proves:** `omission ||= ""`, so `nil` and `""` are the same: no suffix, prefix budget equals `truncate_to`. A custom omission consumes its own bytesize from the prefix budget and is concatenated, not interpolated into the last character. If `nil` raised or were treated as the string `"nil"`, this table breaks.

### 7. Omission equal to or larger than the budget

Receiver `"Hello World"` so the within-budget branch does not apply.

| budget | omission | expected |
|---|---|---|
| 3 | `"..."` (3 bytes) | `"..."` — **copy**, `result.equal?(omission) == false` |
| 4 | `"🖖"` (4 bytes) | `"🖖"` — same copy rule |
| 3 | default `"…"` | `"…"` |
| 2 | `"..."` | `ArgumentError`: `Omission "..." is 3, larger than the truncation length of 2 bytes` |
| 3 | `"🖖"` | `ArgumentError`: `Omission "🖖" is 4, larger than the truncation length of 3 bytes` |
| 0 | `nil` | `""` (`nil` becomes `""`, 0 == 0, `"".dup`) |
| 0 or 2 | default | `ArgumentError` (`"…"` is 3 bytes) |

**Proves:** the three-way `case` is ordered: oversize omission raises **before** any cut; equal-size omission returns `omission.dup` and **drops the prefix entirely**; the error message includes the inspected omission, its bytesize, and the budget. Returning the omission object itself fails identity. Swallowing the error, or truncating the omission, fails the raise cases.

### 8. Encoding and subclass preservation

**Encoding** — 30-byte `"a" * 30`:

| receiver encoding | budget | omission | result encoding |
|---|---|---|---|
| UTF-8 | 15 | default `"…"` | UTF-8 |
| UTF-8 | 100 | default | UTF-8 (dup) |
| US-ASCII | 100 | default | US-ASCII (dup; omission unused) |
| US-ASCII | 15 | `"..."` (ASCII) | US-ASCII |
| US-ASCII | 15 | default `"…"` (UTF-8) | **UTF-8** |
| ASCII-8BIT | 15 | default `"…"` | **UTF-8** |

**Proves:** under-budget `dup` keeps the receiver encoding. The truncate path starts at `self.class.new.force_encoding(encoding)` then `cut << omission`. Appending a UTF-8 ellipsis to US-ASCII/BINARY **promotes** the result. A refactor that always forces UTF-8, or that transcodes the omission into the receiver encoding and raises, is a behavior change. Current code does not raise here.

**Subclass:**

```ruby
class MyString < String; end
ms = MyString.new("Hello World")
```

| call | result class | identity |
|---|---|---|
| `ms.truncate_bytes(100)` | `MyString` | not the receiver |
| `ms.truncate_bytes(8, omission: "...")` | `MyString` | new object (`self.class.new`) |
| `ms.truncate_bytes(3, omission: "...")` | **`String`** | `omission.dup` — class follows the **omission** |
| `ms.truncate_bytes(3, omission: MyString.new("..."))` | `MyString` | not the omission object |

**Proves:** within-budget and normal truncate preserve the **receiver** class; the equal-budget omission branch preserves the **omission** class. `String.new(...)` instead of `self.class.new` / `dup` fails the first two. Always using the receiver class fails the third.

### 9. Receiver mutation

Use unfrozen copies (`+"Hello World"`, `+"short"`).

1. After `truncate_bytes(8)`, receiver is still `"Hello World"`; result is a different object.
2. After `truncate_bytes(100)`, mutate the receiver with `<< "x"`: result stays `"short"`.
3. Mutate the result with `<< "y"`: receiver stays `"short"`.
4. Same isolation after a real truncate (`omission: "..."`).

**Proves:** every return path allocates (`dup`, `omission.dup`, or `self.class.new` + `<<`). In-place `replace`, `[]=`, or returning `self` fails (1) or (2). Sharing the omission string fails (3) on the equal-budget path.

1. Keep this checkout’s method as oracle A. Load the refactored method as B (same Ruby, same `active_support` otherwise).
2. Drive both with a **table of the rows above** — no generators, no `rand`, no current locale.
3. Diff the observation tuples. Any mismatch is a behavior change, including “harmless” ones: `self` vs `dup`, `bytesize` 11 vs 12, UTF-8 promotion, `String` vs `MyString`, error-message wording.
4. Re-run [`test_truncate_bytes`](file:///home/user/workspace/repo/activesupport/test/core_ext/string_ext_test.rb#L340), `test_truncate_bytes_preserves_codepoints`, `test_truncates_bytes_preserves_grapheme_clusters`, and `test_truncates_bytes_preserves_encoding` as a regression net, not as the proof.
