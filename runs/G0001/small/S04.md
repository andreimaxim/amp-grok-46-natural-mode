`content_for` is a named slot on `@view_flow`, not a write into the template’s `@output_buffer`. A write stores a string under `name`. A later `yield :name` or `content_for(:name)` reads that slot into the layout.

```text
content_for(name, content = nil, options = {}, &block)
  content || block?  ──yes──▶ capture block if any
  │                           if content
  │                             flush? set : append
  │                           return nil
  └──no──▶ @view_flow.get(name).presence
```

Dispatch lives in [`content_for`](file:///home/user/workspace/repo/actionview/lib/action_view/helpers/capture_helper.rb#L172-L192). The store is [`ActionView::OutputFlow`](file:///home/user/workspace/repo/actionview/lib/action_view/flows.rb#L6-L27). Layout `yield :name` is [`_layout_for`](file:///home/user/workspace/repo/actionview/lib/action_view/context.rb#L29-L32).

## Write versus read

Write if the second argument is truthy **or** a block is given. Otherwise it is a read.

| Call | Path | Return |
|---|---|---|
| `content_for(:title, "foo")` | write | always `nil` |
| `content_for(:title) { ... }` | write | always `nil` |
| `content_for(:title, flush: true) { ... }` | write | always `nil` |
| `content_for(:title)` | read | stored string, or `nil` if blank/missing |
| `content_for(:missing)` | read | `nil` |

Write returns `nil` even when the captured block is a no-op. That keeps `<% content_for :title do %>...<% end %>` from leaking into the template body. Tests pin this in [`test_content_for_returns_nil_when_writing`](file:///home/user/workspace/repo/actionview/test/template/capture_helper_test.rb#L145-L154).

Read is `@view_flow.get(name).presence`. `get` never returns `nil`: the hash default is an empty `SafeBuffer`. `.presence` turns that blank buffer into `nil`.

`yield :title` does **not** use `.presence`. [`_layout_for`](file:///home/user/workspace/repo/actionview/lib/action_view/context.rb#L29-L32) returns `view_flow.get(name).html_safe`, so an unused name yields an empty safe string, not `nil`.

## Block capture versus direct content

**Direct content** skips `capture`. The object is stored as `value.to_s` through `append`/`set`. Symbols work because they are truthy (`content_for :title, :bar` stores `"bar"`).

**Block form** always runs [`capture`](file:///home/user/workspace/repo/actionview/lib/action_view/helpers/capture_helper.rb#L47-L67). If the second argument is present, it is treated as `options` (`content_for :title, flush: true do`). Explicit `nil` plus options keeps the third-arg hash (`content_for :title, nil, flush: true do`).

`capture` swaps [`OutputBuffer#capture`](file:///home/user/workspace/repo/actionview/lib/action_view/buffers.rb#L72-L79)’s raw string, yields, then chooses:

1. If the block returns `@output_buffer` itself → the captured buffer.
2. Else `buffer.presence || value`.

Then it normalizes:

- `OutputBuffer` → `to_s` (already html-safe)
- `SafeBuffer` → kept
- other `String` → `ERB::Util.html_escape`
- anything else (`nil`, Integer, …) → `nil`

ERB blocks usually write into the buffer and return `nil`, so the buffer wins. Builder / a Ruby block that only returns a string leaves the buffer blank, so the return value wins and is escaped if it is not already safe.

Blank-buffer discard is the whitespace trap: a block that only writes `"  \n  "` and returns `nil` makes `capture` return `nil`. `content_for` then skips `append`/`set` because of `if content`. The previous slot is unchanged, including when `flush: true` was passed. [`test_content_for_with_whitespace_block`](file:///home/user/workspace/repo/actionview/test/template/capture_helper_test.rb#L123-L142) is that behavior.

## Append order and `flush: true`

[`OutputFlow`](file:///home/user/workspace/repo/actionview/lib/action_view/flows.rb#L18-L26):

```ruby
def set(key, value)
  @content[key] = ActiveSupport::SafeBuffer.new(value.to_s)
end

def append(key, value)
  @content[key] << value.to_s
end
```

Default is `append`. Repeated writes concatenate in call order: `"foo"` then `:bar` → `"foobar"`.

`flush: true` calls `set`, which replaces the whole slot. Only that write’s content remains. `flush: false` is append.

Flush does not run if `capture` returned nil/false (whitespace-only ERB, non-string return). The next successful write still sees the old value unless it also flushes.

With a layout, the template renders first and fills named slots; then the layout reads them:

```text
render_with_layout
  template.render          # content_for writes
  view_flow.set(:layout, template body)
  layout.render
    yield / yield(:name)   # _layout_for → view_flow.get
```

That order is [`render_with_layout`](file:///home/user/workspace/repo/actionview/lib/action_view/renderer/template_renderer.rb#L76-L80). Named `content_for` in the template is visible to the layout; `content_for` in the layout itself only affects later reads in that same layout.

## `content_for?`

[`content_for?`](file:///home/user/workspace/repo/actionview/lib/action_view/helpers/capture_helper.rb#L215-L217) is `@view_flow.get(name).present?`. Same blankness as the read path: missing and whitespace-only stored buffers are false. It does not distinguish “never written” from “written then flushed to empty”.

Layouts use it for structure (`body` class, optional column) without dumping the slot.

## Why the stored string stays safe in the view buffer

Two escape points, then a safe concat:

```diagram
┌─────────────┐   capture / to_s    ┌──────────────┐  << / set   ┌─────────────┐
│ block or    │────────────────────▶│ SafeBuffer   │───────────▶│ @view_flow  │
│ direct arg  │   escape if unsafe  │ in @content  │            │ slot        │
└─────────────┘                     └──────────────┘            └──────┬──────┘
                                                                       │
                    <%= yield :name %> / content_for(:name)            │
                    _layout_for → html_safe                            ▼
                                                               ┌──────────────┐
                                                               │ OutputBuffer │
                                                               │ << skips     │
                                                               │ re-escape    │
                                                               └──────────────┘
```

Block output is escaped inside `capture` unless it is already a `SafeBuffer` or `OutputBuffer`. [`OutputBuffer#<<`](file:///home/user/workspace/repo/actionview/lib/action_view/buffers.rb#L46-L56) also escapes unsafe chunks while the ERB block is running, so the captured buffer is already safe.

The slot is always a `SafeBuffer` (hash default, and `set` wraps `value.to_s` in a new one). [`SafeBuffer#concat`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/string/output_safety.rb#L80-L85) escapes on `append` only when the incoming `to_s` is not `html_safe?`. Direct `"<p>"` is escaped; `content_tag` / `raw` / captured ERB is not escaped again.

`set(..., "")` replaces with a new empty `SafeBuffer`, so a later append still starts from a safe buffer. [`test_content_for_should_be_html_safe_after_flush_empty`](file:///home/user/workspace/repo/actionview/test/template/capture_helper_test.rb#L168-L178) is that invariant.

When the layout concatenates the slot, `_layout_for` returns `html_safe`, and `OutputBuffer#<<` copies it without a second escape. Unsafe user strings cannot reach that concat unless something already marked them safe before `content_for` stored them.
