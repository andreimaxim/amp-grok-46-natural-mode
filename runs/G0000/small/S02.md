**Request changes.** This is not equivalent, and it deletes the compatibility hook.

`deep_merge?` is the including class’s answer to “can `other` be deep-merged into me?” Default is `other.is_a?(self.class)`. Hash tightens that to `Hash`; Parameters widens it to any `DeepMergeable`; `OmniWrapper` in the tests widens it further. The left-hand value owns that decision. `other_val.is_a?(DeepMergeable)` moves it into the mixin and treats every `DeepMergeable` pair as compatible.

That is the contract the tests encode:

- `Wrapper` / `SubWrapper` recurse (subclass, default `deep_merge?` is true).
- `Wrapper` / `OtherWrapper` do **not** (`OtherWrapper` is `DeepMergeable` but not a `Wrapper`). Nested value is replaced with `other_val`.
- `OmniWrapper` overrides `deep_merge?` so that same pair *does* recurse.

After this diff, both non-subclass cases recurse. `deep_merge?` has one call site; Hash, Parameters, and custom overrides become dead. You can no longer restrict (Hash vs Parameters) or expand (OmniWrapper) the domain.

Incompatible pairs are supposed to hit the merge-block fallback, then `other_val`:

```ruby
if this_val.is_a?(DeepMergeable) && this_val.deep_merge?(other_val)
  this_val.deep_merge(other_val, &block)
elsif block_given?
  block.call(key, this_val, other_val)
else
  other_val
end
```

The new guard never takes that path for two `DeepMergeable`s. A block that today sees `(key, wrapper, other_wrapper)` would not run; you would recurse instead. Unrelated types that only share the mixin (`Wrapper` vs `Hash`) can raise in `merge!` (`other.underlying`) instead of replacing.

Mutation/return of the *true* branch is unchanged (`this_val.deep_merge`, not `deep_merge!`, so nested objects are not mutated in place). What changes is *which* branch you take. For a pair that is `DeepMergeable` but `deep_merge?` is false, today `merge!` stores `other_val` (same object, same class). Afterward it stores `this_val.dup.deep_merge!(other_val)`: new identity, left-hand class, merged contents. Nested `Hash` + `Parameters` would become a `Hash` and drop Parameters wrapping / permitted status; today Hash’s `deep_merge?` refuses that and keeps the Parameters object.

Leave the `deep_merge?` call. If the goal is to skip the recurse for non-`DeepMergeable` others, that is already `this_val.is_a?(DeepMergeable)`.
