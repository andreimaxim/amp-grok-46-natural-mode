`travel_to` freezes “now” for the rest of the test (or for a block) by replacing four class methods on `Time`, `Date`, and `DateTime`. It does not stub `Time.current` / `Date.current` / `DateTime.current`; those still go through `Time.zone` and therefore pick up the stubbed `Time.now`.

```text
travel_to(date_or_time, with_usec: false)
  raise if block given AND already inside a block-form travel_to
  normalize date_or_time → now
  now = now.change(usec: 0)  unless with_usec
  now = now.getlocal
  stubbed_time = Time.now    if Time.now is already stubbed
  stub Time.now, Time.new, Date.today, DateTime.now
  if block
    in_block = true
    yield
    ensure
      stubbed_time ? travel_to(stubbed_time) : travel_back
      in_block = false
```

## Input normalization

The target is always reduced to a `Time` in the **process** timezone (`ENV['TZ']`), then that value is what every stub reads.

```162:175:activesupport/lib/active_support/testing/time_helpers.rb
        if date_or_time.is_a?(Date) && !date_or_time.is_a?(DateTime)
          now = date_or_time.midnight.to_time
        elsif date_or_time.is_a?(String)
          now = Time.zone.parse(date_or_time)
        else
          now = date_or_time
          now = now.to_time unless now.is_a?(Time)
        end

        now = now.change(usec: 0) unless with_usec

        # +now+ must be in local system timezone, because +Time.at(now)+
        # and +now.to_date+ (see stubs below) will use +now+'s timezone too!
        now = now.getlocal
```

**Date** (not `DateTime`): `midnight` is `beginning_of_day` → `in_time_zone`, so midnight in the **application** zone, then `#to_time`. After `getlocal`, `Time.now` is that instant in the system zone. `Time.current` still reports application-zone midnight; `Date.today` is `Time.now`’s calendar date, which can differ from the argument when the two zones disagree.

**String**: `Time.zone.parse` (application zone). `ActiveSupport::TimeWithZone#is_a?(Time)` is true, so the `else` branch does not call `#to_time` again. Then `change` / `getlocal` run on the `TimeWithZone`.

**Everything else** (`Time`, `DateTime`, `TimeWithZone`, …): keep it if `is_a?(Time)`, otherwise `#to_time`. `DateTime` is a `Date` but is excluded from the Date branch, so it takes this path (`DateTime#to_time` keeps the offset, then `getlocal` moves it to system local).

`getlocal` is required: `Time.at(now)` and `now.to_date` both follow `now`’s zone. The stubs are defined to return system-local `Time` / `Date` / `DateTime`.

## `with_usec`

Default `false`: `now.change(usec: 0)` before stubbing. That exists so a time like `10:10:50.999999` does not round to `10:10:51` in MySQL (MySQL rounds, it does not floor).

`with_usec: true` skips that, so microseconds survive on `Time.now` and on `DateTime.now` (`sec + subsec` in the stub). `travel` / `freeze_time` forward the same flag.

## What is stubbed

[`SimpleStubs`](file:///home/user/workspace/repo/activesupport/lib/active_support/testing/time_helpers.rb#L9-L65) aliases the current singleton method aside, then `define_singleton_method`s a new one. Re-stubbing unstubs first, so the saved “original” is always the real method, not a previous freeze.

| Call | Stub |
|---|---|
| `Time.now` | `Time.at(now)` |
| `Time.new` | see below |
| `Date.today` | `Date.jd(now.to_date.jd)` |
| `DateTime.now` | `DateTime.jd(date, hour, min, sec+subsec, offset)` |

Subclasses (`TimeSubclass.now`, …) are not stubbed; they keep their own class methods and only match the frozen values if they delegate to these four.

`Time.current` → `Time.zone.now` → `Time.now.utc.in_time_zone`, so it follows the stub. Prefer `Time.current` / `Date.current` in app code; `Time.now` / `Date.today` are system-zone.

## `Time.new` with arguments

```181:188:activesupport/lib/active_support/testing/time_helpers.rb
        stubs.stub_object(Time, :new) do |*args, **options|
          if args.empty? && options.empty?
            at(now)
          else
            stub = stubs.stubbing(Time, :new)
            Time.send(stub.original_method, *args, **options)
          end
        end
```

`Time.new` with no args and no kwargs is `Time.now` (frozen). Any positional args **or** kwargs (`Time.new(2021)`, `Time.new(precision: 3)`, `Time.new("2000-12-31 23:59:59.567")`) call real `Time.new`. Construction is not frozen; only “give me now” is.

## Block cleanup

Before installing stubs, if `Time.now` is already stubbed, the helper snapshots that frozen `Time.now` into `stubbed_time`.

- No prior travel: `stubbed_time` is nil → `ensure` calls `travel_back` → real clock.
- Prior **non-block** `travel_to` / `travel` / `freeze_time`: `stubbed_time` is that freeze → `ensure` calls `travel_to stubbed_time` (no block) → previous freeze is back.

Non-block `travel_to` is also cleared by `after_teardown` → `travel_back`.

```193:205:activesupport/lib/active_support/testing/time_helpers.rb
        if block_given?
          begin
            self.in_block = true
            yield
          ensure
            if stubbed_time
              travel_to stubbed_time
            else
              travel_back
            end
            self.in_block = false
          end
        end
```

So this is allowed and restores the outer freeze:

```ruby
travel_to Time.new(2004, 11, 24, 1, 4, 44)   # stays in effect
travel_to(Time.new(2004, 10, 24, 1, 4, 44)) do
  # inner freeze
end
# outer 2004-11-24 freeze is back
```

A **non-block** `travel_to` inside a block is also allowed: it replaces the stubs for the rest of the outer block; the outer `ensure` still restores whatever was captured at the outer call (real time, or a still-earlier freeze).

## Why nested block-form `travel_to` is rejected

Only when `block_given? && in_block`. `in_block` is a boolean on the test object, set for the duration of a block-form call.

```ruby
travel_to 2.days.from_now do
  travel_to 3.days.from_now do  # RuntimeError
  end
end
```

The raise exists because that pattern is easy to misread: `3.days.from_now` is computed from the **already stubbed** `Time.now`, so you get “5 days from real now,” not “3 days from the outer freeze,” and the two `ensure`s are not a stack (`in_block` would be cleared by the inner `ensure` while the outer block was still running). Sequential `travel 2.days` / `travel 5.days` (or a non-block inner `travel_to`) is the supported shape.

`in_block` is per object. A different object that includes `TimeHelpers` can still use block-form `travel_to` inside your test’s block; its own `ensure` then `travel_back`s **its** stubs, which typically restores yours.
