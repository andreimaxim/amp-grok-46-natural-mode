`content_for` is a named slot on `@view_flow`, not a write into the template’s `@output_buffer`. A write never prints. A layout `yield :name` later reads the same slot.

## Write vs read

[`content_for`](file:///home/user/workspace/repo/actionview/lib/action_view/helpers/capture_helper.rb#L172-L184) is one method with two modes. The branch is `if content || block_given?`:

```172:184:actionview/lib/action_view/helpers/capture_helper.rb
      def content_for(name, content = nil, options = {}, &block)
        if content || block_given?
          if block_given?
            options = content if content
            content = capture(&block)
          end
          if content
            options[:flush] ? @view_flow.set(name, content) : @view_flow.append(name, content)
          end
          nil
        else
          @view_flow.get(name).presence
        end
      end
```

- Write (second arg and/or block): always returns `nil`. That is why `<% content_for :title do %>` does not leak into the view body.
- Read (`content_for(:title)` only): `@view_flow.get(name).presence`. Missing or blank → `nil`, not `""`.

`get` uses a default proc, so a read of an unused name inserts an empty `SafeBuffer`. `presence` still returns `nil`; `content_for?` stays false.

## Block capture vs direct content

**Direct.** `content_for :title, "foo"` (or a non-string; it is later `to_s`). No `capture`. The second argument is stored as-is after the `if content` check. `""` is truthy in Ruby, so an empty string is a real write.

**Block.** If a block is given, the second argument is options when present (`content_for :title, flush: true do`). Then `content = capture(&block)` replaces it. `content_for :title, nil, flush: true do` keeps the third-arg options hash because `nil` is skipped.

[`capture`](file:///home/user/workspace/repo/actionview/lib/action_view/helpers/capture_helper.rb#L47-L65) does not swap the `OutputBuffer` object. [`OutputBuffer#capture`](file:///home/user/workspace/repo/actionview/lib/action_view/buffers.rb#L72-L79) swaps the inner `@raw_buffer`, yields, then restores it:

```47:65:actionview/lib/action_view/helpers/capture_helper.rb
      def capture(*, **, &block)
        value = nil
        @output_buffer ||= ActionView::OutputBuffer.new
        buffer = @output_buffer.capture { value = yield(*, **) }

        string = if @output_buffer.equal?(value)
          buffer
        else
          buffer.presence || value
        end
        # OutputBuffer → to_s, SafeBuffer → itself, String → html_escape
      end
```

Two capture sources, one stored value:

| Block style | What is kept |
|---|---|
| ERB (`<% content_for :x do %>…<% end %>`) | Temporary buffer (`<<` / `<%= %>`). Return value ignored if the buffer is present. |
| Non-ERB / helper (`content_for(:x) { "bar" }`) | Block return if the temp buffer is blank. |
| Block returns `@output_buffer` itself | The captured buffer, not the object. |

`buffer.presence` treats whitespace as blank. A block that only writes `"  \n  "` and returns `nil` makes `capture` return `nil`. Then `if content` is false: **the write is a no-op**. That is why `"foo"` + whitespace block + `"bar"` still reads `"foobar"`, and why `flush: true` on a whitespace-only block does not clear the slot.

Non-string returns (`capture { 1 }`) become `nil`. Those writes are also no-ops.

## Append order vs `flush: true`

Storage is [`ActionView::OutputFlow`](file:///home/user/workspace/repo/actionview/lib/action_view/flows.rb#L6-L27):

```6:27:actionview/lib/action_view/flows.rb
  class OutputFlow
    def initialize
      @content = Hash.new { |h, k| h[k] = ActiveSupport::SafeBuffer.new }
    end

    def get(key)
      @content[key]
    end

    def set(key, value)
      @content[key] = ActiveSupport::SafeBuffer.new(value.to_s)
    end

    def append(key, value)
      @content[key] << value.to_s
    end
```

Default write: `append`. First use materializes `SafeBuffer.new`, then `<<`. Repeated writes concatenate in call order, including across templates/helpers. `:bar` becomes `"bar"` via `to_s`.

`flush: true` is `set`: replace the slot with a new `SafeBuffer`, previous chunks gone. `flush: false` is the same as omitting it.

`flush` only applies when `content` is truthy after capture. A flushed whitespace/nil block does not replace.

## `content_for?`

```215:217:actionview/lib/action_view/helpers/capture_helper.rb
      def content_for?(name)
        @view_flow.get(name).present?
      end
```

This is `present?` on the stored buffer, not “was `content_for` called”. Empty or whitespace-only stored content is false. A discarded whitespace write never lands in the flow, so `content_for?` stays false. A successful write of `"title"` is true; other names stay false.

Layout `yield :name` does **not** go through `content_for`. It goes through [`_layout_for`](file:///home/user/workspace/repo/actionview/lib/action_view/context.rb#L27-L30): `view_flow.get(name).html_safe`. Empty slot → empty safe string, not `nil`. That is the usual “`content_for(:x)` is nil but `yield :x` is blank” mismatch.

## Why the stored string stays safe on the view buffer

Safety is applied on the way in, then preserved because the slot is always a `SafeBuffer`.

1. **Block path.** ERB output is collected on `OutputBuffer`. `<<` escapes anything that is not `html_safe?`. `capture` then:
   - `OutputBuffer` → `to_s` (`@raw_buffer.html_safe`)
   - existing `SafeBuffer` (e.g. `content_tag`) → unchanged
   - plain `String` → `ERB::Util.html_escape`
2. **Direct path.** Untrusted strings are not marked safe. `append` does `@content[key] << value.to_s`. [`SafeBuffer#concat`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/string/output_safety.rb#L80-L85) HTML-escapes interpolated arguments that are not `html_safe?`. `raw` / `html_safe` concatenates as-is.
3. **`set` / flush.** Always `SafeBuffer.new(value.to_s)`. A new buffer is `html_safe?` (`@html_unsafe` unset). That is why `content_for :title, "", flush: true` then a later `content_tag` still reads as `html_safe?`.
4. **Read into a template.** `<%= content_for :title %>` or `<%= yield :title %>` concatenates a `SafeBuffer` onto `@output_buffer`, so the engine does not escape it again.

`set` wrapping with `SafeBuffer.new` does **not** escape. Direct unsafe HTML is only escaped because `append`/`concat` does, or because `capture` already escaped the block result. After `flush: true`, the replacement value follows the same rule: captured/safe stays raw; a plain `"<p>"` is escaped on the next `append`, or stored as a new safe copy of `value.to_s` on `set`.

Fragment caches never see these slots; `content_for` only mutates `@view_flow` on the current render.
