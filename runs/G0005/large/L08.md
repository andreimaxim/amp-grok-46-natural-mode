`Enumerable#sole` returns the one item in an enumerable, or raises `Enumerable::SoleItemExpectedError`. It walks `each` once, remembers the first yield, and aborts on the second. It never materializes the whole collection.

```238:256:activesupport/lib/active_support/core_ext/enumerable.rb
  def sole
    result = nil
    found = false

    each do |*element|
      if found
        raise SoleItemExpectedError, "multiple items found"
      end

      result = element.size == 1 ? element[0] : element
      found = true
    end

    if found
      result
    else
      raise SoleItemExpectedError, "no item found"
    end
  end
```

### Why `1..` does not run forever

[`test_sole`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L438) wraps the endless range: `GenericEnumerable.new(1..).sole`. `GenericEnumerable#each` is `@values.each(&block)` ([enumerable_test.rb:42-44](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L42-L44)), so a naive full scan of `1..` would never return.

`sole` does not scan. After `1` it sets `found`. On `2` it raises `"multiple items found"` and leaves `each`. The rest of the range is never visited.

That is `Enumerable#sole`’s short-circuit. It is not `Range#sole`, which `GenericEnumerable` never calls.

### `nil` is a real element

`result` starts as `nil` and `found` as `false` ([enumerable.rb:239-240](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/enumerable.rb#L239-L240)). Presence is `found`, not “is `result` non-nil.”

A sole `nil` is therefore a success: one yield, unwrap `[nil]` to `nil`, `found = true`, return `nil`. Two items that include `nil` still fail: [`test_sole`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L437) expects `GenericEnumerable.new([1, nil]).sole` to raise, same class as `[1, 2]`. The tests do not assert `[nil].sole`; the `found` flag is what makes that path distinct from empty.

### How yields become the return value

The block is `|*element|` ([enumerable.rb:242](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/enumerable.rb#L242)). Every value `each` yields is packed into an array. Then:

```ruby
result = element.size == 1 ? element[0] : element
```

([enumerable.rb:247](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/enumerable.rb#L247))

**One value.** Array-style `each` yields a single object. `element` is `[1]`, size 1, so `sole` unwraps to `1`. That is [`test_sole`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L435).

**Several positional values.** [`test_sole_returns_same_value_as_first_for_tuples`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L441-L445) builds `Enumerator.new(1) { |yielder| yielder.yield(1, "one") }`. The splat gets `[1, "one"]`. Size is not 1, so `sole` returns that array. The test also asserts `enum.sole == enum.first`: `Enumerator#first` uses the same multi-yield packing.

**One positional value plus keywords.** [`KeywordYielder#each`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L447-L453) does `yield 1, two: 3`. The block has no `**` parameter, so Ruby passes the keywords as a hash after the positional arguments. `element` is `[1, { two: 3 }]`. [`test_sole_keyword_arguments`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L455-L458) asserts that array, and again `yielder.sole == yielder.first`.
