The contract to preserve is loader ownership, reload vs once lifetime, `$LOAD_PATH` membership, freeze-after-init, and eager-load membership — not the private concatenation order inside `_all_*`.

### What “no externally observable change” means

Path assembly is an internal reduction. The public result is which directories Zeitwerk manages, which loader owns them, whether they eager-load, whether they appear on `$LOAD_PATH`, and what happens to constants across boot and reload.

Do **not** treat these as the contract:

- `Rails::Engine#_all_autoload_paths` / `#_all_load_paths` memoization
- exact `Array` order of `ActiveSupport::Dependencies.autoload_paths` after engine `unshift`
- `config.all_*` concatenation order (`custom + paths.*`)
- whether `uniq` happens per-engine, globally, or both

Those are implementation. Order is only observable when two files share a relative name (`require`) or when Zeitwerk rejects nested/duplicate roots.

```text
each Engine + Application
  set_load_path          → $LOAD_PATH.unshift(reversed load paths); uniq!
  set_autoload_paths     → AS::Dependencies.autoload{,_once}_paths.unshift
                         → freeze config.autoload{,_once}_paths
  set_eager_load_paths   → AS::Dependencies._eager_load_paths.merge
                         → freeze config.eager_load_paths
Bootstrap
  setup_once_autoloader  → freeze autoload_once_paths; once.push_dir; once.setup
Finisher
  setup_main_autoloader  → freeze autoload_paths; main.push_dir; maybe enable_reloading
  run_prepare_callbacks  → reloader.prepare!
  eager_load!            → Zeitwerk::Loader.eager_load_all if config.eager_load
  set_clear_dependencies_hook → main reload only
```

### How to avoid tests coupled only to private ordering

1. **Membership, not sequence.** `assert_includes` on `main.dirs` / `once.dirs` / `$LOAD_PATH`. No `assert_equal full_array, other_array` for assembled paths in new tests.
2. **If order can change which file wins**, write a **named collision** probe (`require "shared"` or two `foo.rb` in different engines) and pin the winner to **current** behavior. That is an external effect, not private sort order.
3. **Do not** reimplement `_all_autoload_paths` in the test (`autoload + eager - once`). Ask Zeitwerk and `$LOAD_PATH`.
4. **Keep** the existing `and in the same order` tests as a tripwire during the refactor, but if they fail while membership, collisions, reload, and freeze pass, treat that as an allowed internal change — or update those two tests to membership-only in the same PR and say so.
5. **Engine order:** vary `config.railties_order` only in the collision probe. Ownership of distinct paths must be identical.
6. **`uniq` vs `Set`:** duplicates must not produce two Zeitwerk roots or two `$LOAD_PATH` entries when the flag is true; the frozen Dependencies arrays may still list duplicates. Don’t lock the latter.
7. **Unit-test `Rails::Paths` separately** ([paths_test.rb](file:///home/user/workspace/repo/railties/test/paths_test.rb)) for glob/exclude/autoload_once flags. Boot tests should not reconstruct `filter_by`.
