## Assistant

**Reject.** The claim is false at this revision. Equality is on stored bytes, not on decrypted values, so a deterministic predicate must bind every on-disk representation that `deserialize` can still read.

The “optimization” is already the steady-state path: [process_arguments](file:///home/user/workspace/repo/activerecord/lib/active_record/encryption/extended_deterministic_queries.rb#L56-L64) no-ops when `previous_types` is empty. Expansion exists only for `previous:` / global previous schemes and for `support_unencrypted_data`. Removing it would not speed up the common post-migration case; it would break the migration cases the expander is for.

### Query compatibility ≠ read compatibility

| Stored bytes | `record.email` (decrypt) | `where(email: value)` without expansion |
|---|---|---|
| Current-scheme ciphertext | works | works |
| Previous-scheme ciphertext | works (`try_to_deserialize_with_previous_encrypted_types`) | **miss** — SQL never sees that ciphertext |
| Plaintext, `support_unencrypted_data` | works (`handle_deserialize_error` returns the value) | **miss** — SQL compares ciphertext to cleartext |

Read fallback lives in [encrypted_attribute_type.rb](file:///home/user/workspace/repo/activerecord/lib/active_record/encryption/encrypted_attribute_type.rb#L94-L129). Query expansion lives in [extended_deterministic_queries.rb](file:///home/user/workspace/repo/activerecord/lib/active_record/encryption/extended_deterministic_queries.rb#L71-L93): `[value] + previous_types.map { AdditionalValue.new(value, type) }`. `AdditionalValue` serializes with the **previous** type; [ExtendedEncryptableType#serialize](file:///home/user/workspace/repo/activerecord/lib/active_record/encryption/extended_deterministic_queries.rb#L148-L155) then skips re-encrypting it.

`previous_types` is previous schemes plus a [NullEncryptor clean-text scheme](file:///home/user/workspace/repo/activerecord/lib/active_record/encryption/encrypted_attribute_type.rb#L73-L90) when `support_unencrypted_data?`. Per-attribute `support_unencrypted_data:` overrides the global flag in [Scheme#support_unencrypted_data?](file:///home/user/workspace/repo/activerecord/lib/active_record/encryption/scheme.rb#L56-L58).

“Current scheme ciphertext” is also the wrong object. With default `deterministic: true` (`fixed: true`), [serialize uses the oldest previous scheme](file:///home/user/workspace/repo/activerecord/lib/active_record/encryption/encrypted_attribute_type.rb#L135-L142), not the newest. Rows written under `deterministic: { fixed: false }` or under a later scheme are a different ciphertext. The guide states this explicitly: querying deterministic data “will add ciphertexts using previous schemes” when `extend_queries` is on. Deterministic **key-list** rotation is unsupported; **scheme** rotation via `previous:` is the supported query path.
