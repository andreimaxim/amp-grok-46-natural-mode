Current request-level behavior is not what the stubbed reloader tests describe: a failed development reload can drop or split live routes, consume the file change, and leave later requests looking like ordinary misses. Here is the maintenance brief from that evidence.

**Problem frame:** In development, a developer editing the application’s or a mounted engine’s route file (or a file pulled in through an external draw path) can save invalid Ruby. Today it is unclear whether the previous routes still serve traffic and when a corrected file becomes the live routing. That uncertainty belongs at the development reload boundary: [`Rails::Application::RoutesReloader`](file:///home/user/workspace/repo/railties/lib/rails/application/routes_reloader.rb) via `app.routes_reloader`, the route sets and external draw paths registered there, and `config.file_watcher`. Successful routing when every route file is valid is not the intended change.

**Kind of work:** Maintenance of that failure/recovery contract. If you instead want prior routes to keep serving, or the load error to keep appearing until the file is valid, that is a behavior change and would reclassify the work.

---

### Actors and pain

The actor is a developer in a reloading development process (HTTP request, and likely console/job wrappers that go through the same reloader). They edit `config/routes.rb`, a mounted engine’s route file, or a file loaded with `draw`.

Pain: after a bad save, the next request may show a load error, a routing miss, or a mix (application routes live, engine routes gone). A later request with the file still invalid may not show the load error again. After a fix, it is unclear whether they must restart, wait, or hit the app once.

### Current behavior (from source, tests, and request probes)

Inspected: [`routes_reloader.rb`](file:///home/user/workspace/repo/railties/lib/rails/application/routes_reloader.rb), [`finisher.rb`](file:///home/user/workspace/repo/railties/lib/rails/application/finisher.rb) reload hooks, engine registration of paths/route sets/external routes, `Mapper#draw`, `config.file_watcher` / `FileUpdateChecker`, [`routes_reloader_test.rb`](file:///home/user/workspace/repo/railties/test/application/routes_reloader_test.rb), routing/engine tests, plus request-level probes in a generated development app.

### Desired observable outcomes

When this boundary is in good condition, a developer can observe all of the following without guessing or restarting:
