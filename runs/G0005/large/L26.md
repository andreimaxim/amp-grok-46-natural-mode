`ActionView::LookupContext` does not search the disk. It holds mutable lookup details and view paths, builds a cache key from those details, and asks `PathSet` / `FileSystemResolver` for the matching templates. File choice is ranking of `TemplateDetails` against a `TemplateDetails::Requested`. Locals never participate in that ranking.

```diagram
┌─────────────────────┐
│ LookupContext       │
│ @details (mutable)  │
│ @cache / details_key│
│ @view_paths         │
└──────────┳──────────┘
           ┃ find / find_all
           ▼
┌─────────────────────┐
│ PathSet             │
│ prefix × resolver   │
└──────────┳──────────┘
           ┃
           ▼
┌─────────────────────┐     ┌──────────────────────┐
│ FileSystemResolver  │────▶│ UnboundTemplate      │
│ glob + rank/filter  │     │ bind_locals(keys)    │
└─────────────────────┘     └──────────┳───────────┘
                                       ▼
                                Template (or nil / [])
```

## What the context actually stores

A context is view paths plus four registered details: `locale`, `formats`, `variants`, `handlers` ([lookup_context.rb](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L15-L54)). Defaults: locale from `I18n` plus fallbacks; formats from `ActionView::Base.default_formats` or `[:html, :text, :js, :css, :xml, :json]`; variants `[]`; handlers from `Template::Handlers.extensions`.

`@details` is a mutable Hash. Assigning `formats=` / `variants=` / `locale=` / `handlers=` goes through `_set_detail`, which copies the hash if a cache key already exists, then clears `@details_key` and `@digest_cache` ([lookup_context.rb](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L133-L139)). The live details and the interned cache key are different objects: changing details does not mutate a previous key; the next lookup builds or reuses another interned `TemplateDetails::Requested`.

`details_key` is computed only while `@cache` is true ([lookup_context.rb](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L123-L126)). It is **not** a `DetailsKey` instance. `DetailsKey` is a namespace that interns `TemplateDetails::Requested` objects in a process-wide `Concurrent::Map` ([lookup_context.rb](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L57-L82), [template_details.rb](file:///home/user/workspace/repo/actionview/lib/action_view/template_details.rb#L5-L27)). Same details hash contents ⇒ same `Requested` object (within one Ractor). The comment about dropping handlers from the key is stale: handlers are still in `@details` and therefore in the interned key.

```text
LookupContext#find(name, prefixes, partial, keys, options)
  normalize_name
  detail_args_for(options) → [details, details_key|nil]
  PathSet#find
    for each prefix, for each resolver:
      FileSystemResolver#find
        requested = details_key || Requested.new(**details)
        unbound_templates_for(virtual_path, cached: !!details_key)
        find_best_by_details → UnboundTemplate
        bind_locals(keys) → Template
```

`find_all` is the same path except the resolver returns every match, sorted, not just the best. `find` returns `nil` on miss; `find!` raises `ActionView::MissingTemplate` ([path_set.rb](file:///home/user/workspace/repo/actionview/lib/action_view/path_set.rb#L40-L56), [error.rb](file:///home/user/workspace/repo/actionview/lib/action_view/template/error.rb#L41-L65)).

## Normalization before the resolver

**Name.** `normalize_name` splits a slash in the template name into prefix. `"users/show"` with prefixes `["app"]` becomes name `"show"`, prefixes `["app/users"]`. No prefixes ⇒ the path prefix alone. A leading slash is stripped ([lookup_context.rb](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L231-L251)).

**Per-call options vs setter.** `detail_args_for` is the common case of empty options: it reuses `@details` and `details_key`. Non-empty options (from `render formats:` / `variants:`) merge into a new hash and intern a separate key; they **do not** run `formats=` ([lookup_context.rb](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L205-L212)). So `lookup_context.formats = [:js]` and `find(..., formats: [:js])` are not the same contract.

**`formats=`.** This is the only place that expands wildcards, validates, and adds the JS/HTML fallback ([lookup_context.rb](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L289-L304)):

1. Dup the array.
2. If `"*/*"` is present (`Mime::ALL` compares equal to `"*/*"`), delete it and append `default_formats`.
3. `uniq!`.
4. `Template.validate_formats` — unknown values raise.
5. If the array is exactly `[:js]`, append `:html` and set `@html_fallback_for_js = true`.
6. `Accessors#formats=` writes the array into `@details`.

`LookupContext.new(paths, { formats: [:js] })` copies constructor details through `initialize_details` and **skips** this setter, so it does not add `:html`.

**Cache-key format cleanup.** `DetailsKey.details_cache_key` calls `Template.normalized_formats`, which is `formats & Types.symbols` only when the list is not already valid ([template.rb](file:///home/user/workspace/repo/actionview/lib/action_view/template.rb#L204-L212)). Invalid symbols on the setter raise; the same junk in a find-options hash is stripped silently for the interned key. The raw merged hash is still what `MissingTemplate` inspects.

## PathSet into the resolver

`PathSet` walks **prefix outer, resolver inner** and stops at the first hit ([path_set.rb](file:///home/user/workspace/repo/actionview/lib/action_view/path_set.rb#L40-L71)):

- `find` — first resolver that returns a template.
- `find_all` — **all** matches from that first non-empty `(prefix, resolver)` pair, not a union across prefixes.
- Miss: `find` → `nil`, `find_all` → `[]`, `find!` → `MissingTemplate`.

Partial is a virtual-path flag, not a second search algorithm. `TemplatePath.virtual("foo", "parent", true)` is `"parent/_foo"` ([template_path.rb](file:///home/user/workspace/repo/actionview/lib/action_view/template_path.rb#L18-L27)). `find!("foo", %w(parent child), true)` therefore reports `Missing partial parent/_foo, child/_foo` ([lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L255-L269)).

`FileSystemResolver` then:

1. Builds or fetches `UnboundTemplate`s whose virtual path equals `prefix/_?name`. A name containing `"."` is rejected (`[]`) so `"hello_world.html"` never matches `hello_world.html.erb` ([resolver.rb](file:///home/user/workspace/repo/actionview/lib/action_view/template/resolver.rb#L188-L201), [resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L232-L236)).
2. Parses filenames as `action(.locale)?(.format)?(+variant)?(.handler)?` ([resolver.rb](file:///home/user/workspace/repo/actionview/lib/action_view/template/resolver.rb#L22-L48)).
3. Uses `details_key` if present, otherwise `Requested.new(**details)`.
4. `find` → `find_best_by_details` (lowest rank). `find_all` → keep matches, sort by the same rank ([resolver.rb](file:///home/user/workspace/repo/actionview/lib/action_view/template/resolver.rb#L156-L230)).

A missing detail on the file (`nil` format/locale/variant/handler) always matches: `Requested` indexes `[*requested, nil]` ([template_details.rb](file:///home/user/workspace/repo/actionview/lib/action_view/template_details.rb#L23-L25)). Rank is `[format_idx, locale_idx, variant_idx, handler_idx]` — **format first, then locale, then variant, then handler**. Lower index wins. Unspecified (`nil`) is last among that axis.

`variants: :any` uses a special index: no-variant files rank `0`; every named variant ranks `1` ([template_details.rb](file:///home/user/workspace/repo/actionview/lib/action_view/template_details.rb#L8-L21)).

## Edge cases: selected set or error

**`formats = [:js]`.** After the setter, `@details[:formats]` is `[:js, :html]` and `@html_fallback_for_js` is true ([lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L61-L64)). A `.js` template ranks ahead of `.html`; a JS-only lookup that found no `.js` file still accepts HTML. The fallback flag is never cleared by later `formats=` assignments. Renderers use it to avoid prepending formats again ([abstract_renderer.rb](file:///home/user/workspace/repo/actionview/lib/action_view/renderer/abstract_renderer.rb#L174-L177), [base.rb](file:///home/user/workspace/repo/actionview/lib/action_view/base.rb#L327-L337)). Per-call `find(..., formats: [:js])` does **not** append `:html`; only an HTML file would then miss.

Observable at render: `render(template: "test/js_html_fallback", formats: :js)` still renders an HTML partial ([render_test.rb](file:///home/user/workspace/repo/actionview/test/template/render_test.rb#L62-L64)).

**Explicit `Mime::ALL` / `"*/*"`.** `"*/*"` alone becomes `Mime.symbols` (or `default_formats`). `[:js, Mime::ALL]` becomes `[:js, *Mime.symbols].uniq` — JS first, then every registered type. Because the array is no longer exactly `[:js]`, `@html_fallback_for_js` is **not** set by this assignment ([lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L53-L59)). Lookup then matches any format the resolver knows, ranked with `:js` at index 0.

**Invalid formats.** `formats = [:html, :invalid, "also bad"]` raises `ArgumentError` with `Invalid formats: :invalid, "also bad"` **before** any resolver call ([lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L66-L73), [template.rb](file:///home/user/workspace/repo/actionview/lib/action_view/template.rb#L204-L208)). No template set is produced.

**Locale / variant ordering.** Requested locale is `[I18n.locale, *fallbacks, I18n.default_locale].uniq`; the getter `locale` returns only the first ([lookup_context.rb](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L50-L54), [lookup_context.rb](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L307-L321)).

With both a generic file and a locale-specific file: `locale: [:en]` → only the generic template; `locale: [:fr]` → `[fr, generic]` in that order, and the generic `Template` object is the same object as the English hit ([resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L123-L137), [fixture_resolver_test.rb](file:///home/user/workspace/repo/actionview/test/template/testing/fixture_resolver_test.rb#L31-L41)).

Variants follow the requested array: `find_all(..., variants: [:tricorder, :lcars])` returns `[tricorder, lcars]`; reversing the array reverses the result. `find` returns only the first of that order ([resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L187-L204)). Combined with formats, the fixture lookup `formats=[:html], variants=[:phone]` selects `hello_world.html+phone.erb` (`"Hello phone!"`); switching formats to `[:text]` selects `hello_world.text+phone.erb` (`"Hello texty phone!"`) ([lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L108-L121)).

`variants: []` (default) matches only files **without** a `+variant`. `variants: :any` (`LookupContext#any?`) returns every variant, no-variant first ([fixture_resolver_test.rb](file:///home/user/workspace/repo/actionview/test/template/testing/fixture_resolver_test.rb#L43-L51)).

Wrong details (e.g. request `:xml` + `:builder` against `hello_world.html.erb`) → empty list, not an error ([resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L93-L99)). Format order in `find_all` is observable: `[:json, :html]` yields JSON then HTML; `[:html, :json]` the reverse ([resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L139-L173)).

**Partial lookup.** `partial=true` only changes the virtual path to `_name`. Selection, ranking, cache, and locals are otherwise identical. `find` of a missing partial is `nil`; `find!` raises `MissingTemplate` whose message uses the underscored path.

**Locals.** Locals are the `keys` argument, not a detail. They are applied after a file is chosen, via `UnboundTemplate#bind_locals` ([unbound_template.rb](file:///home/user/workspace/repo/actionview/lib/action_view/unbound_template.rb#L21-L34)). They do **not** change which file wins.

- Non-strict template: each distinct locals set (normalized to sorted symbols) yields a different `Template` object; `[:post, :other]` and `[:other, :post]` are the same binding ([file_system_resolver_test.rb](file:///home/user/workspace/repo/actionview/test/template/file_system_resolver_test.rb#L84-L96)).
- Strict locals (`<%# locals: ... %>`): every locals list returns the **same** `Template`, with `template.locals == nil` ([resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L258-L267), [file_system_resolver_test.rb](file:///home/user/workspace/repo/actionview/test/template/file_system_resolver_test.rb#L98-L107)).
- Same file requested under different locales/formats still returns the same bound object if it is the same unbound template ([resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L117-L121)).

**Cache on vs off.** `@cache` defaults to `true`. Enabled: `details_key` is a `Requested`; `unbound_templates_for(..., cached: true)` memoizes the glob by virtual path; repeated `find` returns `assert_same` template ([lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L153-L177), [resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L101-L106)). Changing locale/formats builds a new key, so a different file can be selected, but the unbound cache is still by path — only ranking changes.

`disable_cache` sets `@cache = false` for the block, so `details_key` is `nil` and the resolver globs again and builds new `UnboundTemplate`/`Template` objects (`assert_not_same`). It does **not** clear the existing cache; a later cached `find` returns the original object ([lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L179-L193), [resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L108-L115)). `DetailsKey.clear` is the process-wide flush (all resolvers + interned keys).

```diagram
formats=/variants= ──▶ @details mutated, @details_key = nil
                         ┃
                         ▼
cached find ──▶ intern Requested ──▶ reuse glob, re-rank
disable_cache find ──▶ key=nil ──▶ glob again, new Template
                         ┃
                         ▼
cache restored ──▶ previous interned templates still there
```

## Mutable details vs cache keys

| Object | Mutability | Role |
|---|---|---|
| `@details` | Mutated in place (duped once a key exists) | Source of truth for this context |
| `details_key` (`Requested`) | Immutable, interned, identity-eql | Ranking tables (`formats_idx`, …) and resolver cache flag |
| `@unbound_templates` | Cached by virtual path when key is present | File identity; not format/variant identity |
| Bound `Template` | Cached on the unbound template by normalized locals | Compilation/locals; not lookup |

Changing formats or variants updates `@details` and drops `details_key`. The next lookup interns a new `Requested` whose index tables encode the new preference order. The resolver still has the same files; it filters and sorts them differently. Locals never enter `@details` or `details_key`.
