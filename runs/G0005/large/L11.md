`TimeZone#local` does not interpret its arguments as a UTC instant. It packs wall-clock fields into a UTC-flagged `Time` and hands that carrier to `TimeWithZone`, which then picks a TZInfo period, rewrites nonexistent local times, and only then derives UTC, abbreviation, and DST.

```text
TimeZone#local(*args)
  Time.utc(*args)                                 # wall-clock carrier, not a UTC instant
  TimeWithZone.new(nil, zone, carrier)
    get_period_and_ensure_valid_local_time
      period_for_local(carrier)                   # dst=true; on clash, periods.last
      rescue TZInfo::PeriodNotFound
        carrier += 1.hour; retry                  # spring-forward gap
    utc  = carrier + (-period.observed_utc_offset)
    zone = period.abbreviation
    dst? = period.dst?
```

That path is [time_zone.rb](file:///home/user/workspace/repo/activesupport/lib/active_support/values/time_zone.rb#L375-L378) → [TimeWithZone#initialize](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L50-L60) → [get_period_and_ensure_valid_local_time](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L565-L582) → [period_for_local](file:///home/user/workspace/repo/activesupport/lib/active_support/values/time_zone.rb#L578-L580). Observables come from [`#time`](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L63-L70), [`#utc`](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L68-L70), [`#zone`](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L138-L140), [`#dst?`](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L93-L100), and [`#to_a`](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L460-L463).

Do not treat “ambiguous local time always means DST” as a global invariant. US Eastern fall-back 2006 selects EDT; Moscow 2014-10-26 01:00 selects winter MSK. The shared rule is `periods.last`. Pin each zone’s observed tuple.

I ran the existing `#local` tests (`6 runs, 22 assertions, 0 failures`) and a one-off probe of the extra UTC/abbrev/DST fields. Values below are those printed results plus the assertions already in [time_zone_test.rb](file:///home/user/workspace/repo/activesupport/test/time_zone_test.rb).

## What to lock

For every case, assert four independent facts. A refactor can keep wall-clock `#time` while changing the UTC instant, or keep UTC while flipping abbreviation/DST.

- Local components: `twz.time` as `Time.utc(...)` when the year is in range; otherwise `twz.to_a[0, 6]`
- UTC instant: `twz.utc` (this is what `<=>` uses)
- Abbreviation: `twz.zone` (`period.abbreviation`)
- DST: `twz.dst?` (`period.dst?`)
- Zone object: `twz.time_zone` where the existing tests already do

`TimeWithZone.new(nil, zone, Time.utc(...))` in [time_with_zone_test.rb](file:///home/user/workspace/repo/activesupport/test/core_ext/time_with_zone_test.rb#L676-L690) is the same conversion without `#local`’s `Time.utc(*args)` packing. Keep both oracles.

## How to use this as a refactor oracle

Run the five `#local` methods plus the two `TimeWithZone.new(nil, ...)` methods before and after. Any conversion change that only updates `#local` must still pass the TimeWithZone-constructed spring/fall cases, and vice versa.

```bash
cd activesupport && bin/test test/time_zone_test.rb -i "/test_local$|test_local_with_old_date|test_local_enforces_spring_dst_rules|test_local_enforces_fall_dst_rules|test_local_with_ambiguous_time|test_period_for_local_with_ambiguous_time/"
cd activesupport && bin/test test/core_ext/time_with_zone_test.rb -i "/test_instance_created_with_local_time_enforces_spring_dst_rules|test_instance_created_with_local_time_enforces_fall_dst_rules/"
```

That first command is what I ran (6 tests, 22 assertions, pass). Gaps a conversion refactor can still slip through: Hawaii UTC/HST/`dst?`, Moscow `#time`/`MSK`/`dst?`, and 1850 LMT vs HST. Those are the extra assertions above; they are not in the suite today.
