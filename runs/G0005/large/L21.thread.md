## Lazy population and repeat access

Empty cache, table `courses` (3 columns, PK `"id"`, 1 index). Each row is a **new** cache unless noted.

| Call | sqlite3_mem first | Repeat / follow-on | Stored result |
|---|---|---|---|
| `data_source_exists?("courses")` | **1** (list all data sources) | **0** | `true`; fills `@data_sources` for every non-ignored table |
| `data_source_exists?("foo")` after a list | **1** (name-specific) | **0** | `false` |
| `data_source_exists?("foo")` on empty cache | **2** (list all + name-specific) | **0** | `false` |
| `columns("courses")` | **1** (`table_structures`) | **0** | 3 columns |
| `columns_hash("courses")` after `columns` | **0** (derived, frozen) | **0** | size 3 |
| `columns_hash("courses")` on empty cache | **1** (same as `columns`) | then `columns` is **0** | size 3 |
| `primary_keys("courses")` | **2** (list sources + structure) | **0** | `"id"` |
| `indexes("courses")` | **3** (list sources + index list + index details) | **0** | size 1 |
| `add("courses")` | **5** (1 sources + 1 PK + 1 columns + 2 indexes); `columns_hash` is free | **0**; later `columns` / `columns_hash` / `primary_keys` / `indexes` / `data_source_exists?` all **0** | all five maps populated |
| `cached?("courses")` | true only after `columns` / `add` / dump load of columns | `data_source_exists?` does **not** set it | `@columns.key?` |
| `columns_hash?("courses")` | true only after `columns_hash` / `add` | `columns` alone does **not** set it | `@columns_hash.key?` |

Assertions that fail on extra round trips:

- After any successful populate, wrap the same call in `assert_no_queries(include_schema: true)`.
- After `columns`, `columns_hash` must be **0** queries. A query here means the hash is no longer derived from the column list.
- After `add`, a query from `columns` / `primary_keys` / `indexes` means `add` stopped filling that map.
- `size` after `columns` + `columns_hash` + `data_source_exists?` + `primary_keys` + `indexes` on `courses` is **8** (`1+1+1+5`). `@indexes` is **not** part of `size`. A refactor that counts indexes, or that stops listing all data sources on first `data_source_exists?`, changes this number.

## `clear!` and `clear_data_source_cache!`

- Populate the five lookups, then `clear!`. `size == 0`. Next `data_source_exists?("courses")` is **1** (full list again). Next `columns("courses")` is **1**. A **0** here is a stale cache.
- After a full data-source list, `clear_data_source_cache!("courses")` then `data_source_exists?("courses")` is **1** name-specific query, not a full relist (`@data_sources` is not empty). Other tables stay cached: `data_source_exists?("professors")` must stay **0**.
- `clear_data_source_cache!` must drop `@columns`, `@columns_hash`, `@primary_keys`, `@data_sources`, and `@indexes` for that name. If indexes survive, `indexes` after a per-source clear stays **0** queries — that is a stale-index bug.

## Schema-ignored tables (string and regexp)

`ActiveRecord.with(schema_ignored_tables: ["professors"])` and `[/^profess/]` must behave identically.

On a **fresh** cache, with no DB traffic (**0** queries, including schema):

- `data_source_exists?("professors")` → `nil` (not `false`)
- `primary_keys("professors")` → `nil`
- `indexes("professors")` → `[]`
- `add("professors")` is a no-op
- `columns` / `columns_hash` raise `StatementInvalid` (`"Table 'professors' doesn't exist"`) without querying

Dump while ignored, reload, then:

- `courses` is present: 3 columns, PK `"id"`, 1 index, `data_source_exists?` true, **0** queries
- `professors` still ignored as above even if the table exists in the database

A query against `professors`, or `data_source_exists?` returning `false` instead of `nil`, is a miss. Ignored names must also be absent from the bulk `@data_sources` fill.

## Duplicate-cache independence

- Two `SchemaCache.new` instances: first `columns(@pool, "courses")` queries; the other still queries (**1** and **1**). Sharing storage is a regression.
- `dup` copies the five hashes (`initialize_dup`). `copy.clear_data_source_cache!(pool, "courses")` then:
  - original `columns` → **0**
  - copy `columns` → **1**
- `BoundSchemaReflection` / `SchemaReflection` `clear!` replaces `@cache`; it must not empty a different reflection’s cache.

## Frozen / deduplicated values

After live `add` / `columns` / `columns_hash`:

- Column **array** is not frozen; each `Column` and its `name` **are** frozen (`Deduplicable` + `deep_deduplicate` / `-value`).
- `columns_hash` from the live path is **frozen**.
- Equal `SqlTypeMetadata` / `Column` objects intern through `klass.registry` (`assert_same` across tables that share a type, as in the 8.0 YAML fixture’s anchors).
- `init_with` with `"deduplicated" => true` must `assert_same` the given `columns` object.
- `init_with` without that flag must rebuild `@columns_hash` from `@columns` (ignore any dumped hash) and run `deep_deduplicate`.
- Marshal load via `_load_from` uses `Marshal.load(..., freeze: true)`, then `marshal_load` **rebuilds** `@columns_hash` with `index_by` and does **not** freeze it. Live path frozen / Marshal path unfrozen is current behavior; do not “fix” it in a preservation check.

Also assert 3 columns, all with `cast_type`, PK `"id"`, 1 index. Gzip must pass both a manual `Zlib::GzipReader` load and `load_bound_reflection`.

Determinism:

- `encode_with` writes **sorted** `columns`, `primary_keys`, `data_sources`, `indexes`, plus `version`. It does **not** write `columns_hash` or `deduplicated`.
- Gzip writer sets `mtime = 0`. Two dumps one second apart: equal MD5, mtime `1970-01-01 00:00:00 UTC`.
- `dump_to` `mkdir_p`s the parent directory.

## Schema version and dump-version checking

Defaults: `SchemaReflection.use_schema_cache_dump = true`, `check_schema_cache_dump_version = true`.

- `version(pool)` queries once (`schema_migrations` existence on sqlite3_mem) and memoizes `@version`. `schema_version` is the memo, no query.
- **Check on (default):** `cached?` does **not** load a dump without a pool (`nil`). `load!` of a dump whose `version` ≠ `connection.schema_version` warns (`Ignoring ... expired. The current schema version is X, but the one in the schema cache file is Y.`), discards the dump, and subsequent `columns` **query** as an empty cache. Measured stale `load!`: **1** query (version compare).
- **Check off:** `SchemaReflection.with(check_schema_cache_dump_version: false)` — `cached?("courses")` is true with no connection; `BoundSchemaReflection.new(reflection, :__unused_pool__)` can serve `columns` with **0** queries even if the dumped version is wrong.
- `use_schema_cache_dump: false` → dump file is ignored; lookups query as empty.
- `ActiveRecordError` during version compare is warned and treated as no dump (`Failed to validate the schema cache because of ...`).

`lazily_load_schema_cache` (skipped for `in_memory_db?`): pool `@cache` stays `nil` until first connection when the flag is on; `schema_cache.load!` runs from `ConnectionPool#adopt_connection`.

## Adapter portability

Portable (assert on sqlite3, postgresql, mysql2, trilogy):

- Repeat access after a hit is **0** schema queries.
- Dump load of a current dump is **0** schema queries for the five lookups.
- Ignored tables are **0** queries and `data_source_exists?` is `nil`.
- Missing `columns` re-raises and re-queries; missing PK is `nil`; missing indexes is `[]`.
- Composite PK is the column-name array; no-PK table is `nil`.
- YAML key order / gzip mtime / 5.1 missing-indexes query-on-`indexes` / version-check discard.

Adapter-specific (measure per adapter, do not share N):

- Absolute first-miss counts. SQLite uses 1 SQL per `table_structures`, 2 for indexes, 1 to list data sources. PostgreSQL and MySQL also have bulk `columns` / `indexes` / `primary_keys` on an array of names ([`schema_statements_test.rb`](file:///home/user/workspace/repo/activerecord/test/cases/connection_adapters/schema_statements_test.rb)); `add_all` should stay a small constant query count (`<= 2` per bulk reader when the adapter supports it), not `O(tables)`.
- SQL text (`pragma_table_list` vs `pg_class` vs `information_schema.tables`). If you need a portable “no extra round trip” check beyond counts, `assert_no_queries_match(/pragma_table_info|pg_attribute|information_schema/i, include_schema: true)` on hits.
- Column objects (`PostgreSQL::TypeMetadata` / `MySQL::TypeMetadata` in the dedup registry).
- `in_memory_db?` skips the lazily-load connection test.

## Stale-entry oracles

2. `clear_data_source_cache!(name)` then that name queries; other names do not.
3. Expired dump with check on → warning + miss queries; check off → hit, **0** queries.
4. 5.1 dump → `indexes` queries; `columns` does not.
5. Ignored table never appears in `@data_sources` after a full list or `dump_to`.
6. `dup` / second `SchemaCache` does not see the first cache’s entries.
7. Second `insert` into `courses` stays **1** query (`test_insert_uses_schema_cache_for_primary_key`); an extra schema lookup here is a missed PK cache.
