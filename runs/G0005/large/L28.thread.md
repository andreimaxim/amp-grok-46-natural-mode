### Findings

#### 1. Blocker — inverts the `safe_concat` / `safe_append=` contract

ERB static HTML is an ordinary String. The compiler’s whole reason for `safe_append=` vs `append=` is “this text is already HTML.” Escaping it turns every template into entities.

Same break for [`cache`](file:///home/user/workspace/repo/actionview/lib/action_view/helpers/cache_helper.rb#L180) (`safe_concat(fragment_for(...))`): a cache hit that is an ordinary String of HTML becomes `&lt;ul&gt;...`. Printed: `"<ul><li>foo</li></ul>"` → `"&lt;ul&gt;&lt;li&gt;foo&lt;/li&gt;&lt;/ul&gt;"`.

This is not a security improvement. It is a rendering-correctness regression on the hot path.

#### 2. Blocker — the capture claim is false

[`CaptureHelper#capture`](file:///home/user/workspace/repo/actionview/lib/action_view/helpers/capture_helper.rb#L47-L66) already escapes an ordinary String **return** (`test_capture_escapes_html`). [`OutputBuffer#capture`](file:///home/user/workspace/repo/actionview/lib/action_view/buffers.rb#L72-L79) never uses the return value; it only snapshots writes.

When the block both writes and returns, the helper keeps the buffer if it is present (`test_ignore_the_block_return_if_its_the_buffer`). Untrusted writes already go through `#<<`. Trusted writes go through `safe_concat` because ERB capture blocks emit `safe_append=` for `<p>Hello</p>`. Escaping `safe_concat` makes those capture blocks wrong, which is the opposite of “safer capture.”

The XSS-shaped calls that stay dangerous are the trusted APIs: `safe_concat(user_input)`, `raw`, `<%==`, `html_safe`. Those are not capture bugs.

#### 3. High — compatibility breaks beyond HTML

- `nil`: `TypeError` → silent `""` (`ERB::Util.html_escape(nil)` printed `""`).
- Integer: `String#<<` writes a codepoint (`"\u0005"`) → `"5"`.
- Escaped-but-not-`html_safe` strings double-escape.

`#<<` and `RawOutputBuffer#<<` skip `nil`. `safe_concat` does not; that difference is real today and this patch papers over it instead of documenting it.

#### 4. High — `StreamingBuffer#safe_concat` left alone

```121:124:actionview/lib/action_view/buffers.rb
    def safe_concat(value)
      @block.call(value.to_s)
    end
```

Printed: streaming still emits `"<script>alert(1)</script>"`. A one-sided patch would make buffered and streaming templates disagree. Patching both would escape streamed static HTML too.

#### 5. Medium — wrong escape helper even if the contract were `#<<`

`#<<` uses `unwrapped_html_escape` and a `html_safe?` check after `to_s`. The patch uses `html_escape`, which allocates a `SafeBuffer` on every call. `RawOutputBuffer` already exists for “never escape.” Collapsing `safe_concat` into `#<<` for ordinary strings deletes the trusted-append API ERB needs.

---

### Security / compatibility

- **Security:** no new protection for capture. Helper-level return escaping already exists. Trusted concat of untrusted data remains XSS, as designed.
- **Compatibility:** every HTML template, `cache` hits, and helpers that `safe_concat` onto `output_buffer` (e.g. [`TextHelper#safe_concat`](file:///home/user/workspace/repo/actionview/lib/action_view/helpers/text_helper.rb#L67-L69), `test_case_test.rb` `safe_concat render(plain: "<ul>...")`).
- **Do not ship.** If a capture hole exists, it is not “`safe_concat` forgot to escape.” Look at callers that pass untrusted data into `safe_concat` / `raw`, or at treating `OutputBuffer#capture`’s html_safe snapshot as a second sanitizer.
