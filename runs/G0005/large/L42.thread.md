#### Parse: ERB, YAML, empty document

[`ActiveSupport::ConfigurationFile`](file:///home/user/workspace/repo/activesupport/lib/active_support/configuration_file.rb) is `:nodoc:`. `config_for` calls `parse` with only the path.

```22:34:activesupport/lib/active_support/configuration_file.rb

      source = @content.include?("<%") ? render(context) : @content

      if source == @content
        YAML.unsafe_load_file(@content_path, **options) || {}
      else
        YAML.unsafe_load(source, **options) || {}
      end
```

**ERB (contract).** If the raw file contains `"<%"`, it is rendered with `ERB.new(@content)` and `erb.filename = @content_path`. `config_for` does not pass `context:`, so `erb.result` runs against ERB’s toplevel binding. Test: [`config_for containing ERB tags should evaluate`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2820-L2829) (`<%= 'custom key' %>`). Backtrace-filename behavior is in [`activesupport/test/configuration_file_test.rb`](file:///home/user/workspace/repo/activesupport/test/configuration_file_test.rb#L6-L31), not in the railties tests.

**ERB (mechanic).** The `"<%"` gate skips ERB when absent (`c00ef2a00b`). A value like `100%` is not ERB. I ran `ConfigurationFile.parse` on `pct: 100%` and on `<%= 1 + 1 %>`; they returned `{"development" => {"pct" => "100%"}}` and `{"development" => {"key" => 2}}`.

**YAML (mechanic).** Load is Psych `unsafe_load` / `unsafe_load_file` (aliases, arbitrary classes). `config_for` passes no Psych options. `nil`/`false` become `{}` via `|| {}`. I ran parse on `""`, `"---\n"`, `"false\n"`, `"null\n"` → `{}`; on `"0\n"` → `0`.

**Syntax error (contract).** `Psych::SyntaxError` becomes `ActiveSupport::ConfigurationFile::FormatError`. Parse is assumed to yield a Hash of environment keys. A root scalar other than nil/false would call `deep_symbolize_keys` on a non-Hash and raise. That is not in the `config_for` tests.

**Nested hashes (contract vs mechanic).** `deep_symbolize_keys` symbolizes nested keys; `OrderedOptions.new.update` does **not** wrap nested hashes. Nested method access (`config.foo.bar`) is not in the tests; nested access is `[:foo][:bar][:baz]`. Nested string keys are not a `config_for` contract. The 6.1 upgrade note in [`guides/source/upgrading_ruby_on_rails.md`](file:///home/user/workspace/repo/guides/source/upgrading_ruby_on_rails.md#L885-L905) is about that nested-hash change (`e5e9c558a3` removed `HashWithIndifferentAccess`).

**`update` mechanic.** `Hash#update` does not go through `OrderedOptions#[]=`, so it will store string keys as strings. `config_for` is safe only because `deep_symbolize_keys` already ran. I confirmed `OrderedOptions.new.update("key" => "value")` leaves a String key that `oo[:key]` then misses. That is why symbolization is not optional relative to the wrapper.

**Non-hash root (contract).** Arrays (and by the same `is_a?(Hash)` check, scalars) are returned as parsed. Empty file / missing env without shared → `nil`. No `config_for` test uses a scalar env value (`development: 42`); the array tests are the documented non-hash contract.

#### Intentional contract vs incidental mechanic

**Contract (RDoc + tests):** load `config/#{name}.yml` or a given Pathname; ERB; one env (default `Rails.env`, overridable); `shared` deep-merged under env hashes; env arrays replace shared arrays; missing env is nil unless `shared` exists; empty file is nil; missing file raises that RuntimeError; hash results are `OrderedOptions` with symbol keys and string lookup at the root; YAML engines need not honor `symbolize_names`.

**Incidental:** no caching; `unsafe_load*` (trusted files, aliases, Ruby objects); ERB only if `"<%"` appears; `|| {}` collapsing YAML `false`/`null` at the document root; `if shared` truthiness; `Hash#update` not re-symbolizing; nested values remaining plain `Hash`; `database_configuration`’s different `shared` rules; the `YAML.load` stub no longer sitting on the parse call path.
