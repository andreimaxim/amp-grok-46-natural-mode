**Block.** The claim is wrong for this revision, and the diff is not a bang counterpart to `#attach`.

`#attach!` is documented and implemented as “call `#attach`, and raise only if that method was supposed to save and did not.” `#attach` saves only when the record is persisted and has no dirty attributes. Unconditional `record.save!` changes when the record is persisted, what exception is raised, what is returned, and how many times callbacks run.

## Current contract

[`Attached::Many#attach`](file:///home/user/workspace/repo/activestorage/lib/active_storage/attached/many.rb#L51-L57) assigns `blobs + attachables.flatten`, then:

```51:57:activestorage/lib/active_storage/attached/many.rb
    def attach(*attachables)
      record.public_send("#{name}=", blobs + attachables.flatten)
      if record.persisted? && !record.changed?
        return if !record.save
      end
      record.public_send("#{name}")
    end
```

[`#attach!`](file:///home/user/workspace/repo/activestorage/lib/active_storage/attached/many.rb#L59-L67) only raises when that `return` yields `nil`:

```65:67:activestorage/lib/active_storage/attached/many.rb
    def attach!(*attachables)
      attach(*attachables) || raise(ActiveRecord::RecordNotSaved.new("Failed to save the record", record))
    end
```

The comment is explicit: raise if the record **was meant to be saved** and a validation failed. [`Attached::One`](file:///home/user/workspace/repo/activestorage/lib/active_storage/attached/one.rb#L64-L80) is the same pattern. Assignment itself is not a model-attribute change; [`changed_for_autosave?`](file:///home/user/workspace/repo/activestorage/lib/active_storage/attached/model.rb#L313-L314) is separate, which is why a persisted, attribute-clean record still takes the immediate-`save` branch.

|---|---|---|

| New, invalid | Does **not** raise; pending change left | Raises `RecordInvalid` |

## Concrete regressions

1. New records get inserted by `#attach!`.
2. Dirty attributes on an already-persisted record get saved as a side effect.
3. Successful immediate attach double-saves and double-fires `after_commit`.
4. Return value becomes `true` instead of the attachments proxy ([many_test.rb:802](file:///home/user/workspace/repo/activestorage/test/models/attached/many_test.rb#L802-L807) documents the `#attach` return).
5. Exception class/message change on the only covered failure path.
6. `Attached::One#attach!` left unchanged, so the two proxies would diverge.

## Smallest corrected direction

Do not replace the method with unconditional `save!`. Keep `#attach!` as a thin wrapper around `#attach`.

If the only goal is “the immediate-save path should bang”:

- Raise only in the existing `record.persisted? && !record.changed?` branch.
- Call `save!` **instead of** `attach` + `save!`, not after it (avoids the extra save).
- Decide exception class deliberately: keeping `RecordNotSaved` matches today’s test and `One`; switching to `RecordInvalid` is a real API change and must update [many_test.rb:820](file:///home/user/workspace/repo/activestorage/test/models/attached/many_test.rb#L820-L826) and [one_test.rb:148](file:///home/user/workspace/repo/activestorage/test/models/attached/one_test.rb#L148-L155) together.
- Do not persist new or dirty records; that is `#attach`’s documented deferral ([many.rb:43-45](file:///home/user/workspace/repo/activestorage/lib/active_storage/attached/many.rb#L43-L45)).

If the goal is actually “`#attach!` always persists the record,” that is a new behavior, not a bugfix: document it, change `One` the same way, return the proxy after `save!`, and add tests for new, changed, invalid, return value, pending changes, and callbacks. The posted diff does none of that.
