`Rails::Application#config_for` reads one YAML file, picks the `shared` document plus one environment document, deep-merges those when both are hashes, and returns either an `ActiveSupport::OrderedOptions` (hash root) or the raw env/shared value (array/scalar/nil). It does not cache.

```diagram
name / Pathname
        │
        ▼
┌───────────────────┐
│ resolve path      │  Pathname as-is, else #{paths["config"]}/#{name}.yml
└─────────┬─────────┘
          │ missing → raise RuntimeError
          ▼
┌───────────────────┐
│ ConfigurationFile │  ERB if content includes "<%"
│ .parse            │  YAML.unsafe_load(_file); nil/false → {}
└─────────┬─────────┘
          ▼
┌───────────────────┐
│ deep_symbolize_   │  every hash key, including hashes inside arrays
│ keys              │
└─────────┬─────────┘
          ▼
     env.to_sym  and  :shared
          │
          ▼
┌───────────────────┐
│ shared merge      │  hash+hash: shared.deep_merge(env)
│                   │  env nil + shared hash: deep_merge onto {}
│                   │  env nil + shared non-hash: shared
│                   │  otherwise: env unchanged
└─────────┬─────────┘
          ▼
     Hash? → OrderedOptions.new.update(config)
     else  → config  (Array, scalar, nil)
```

The public method is [`Rails::Application#config_for`](file:///home/user/workspace/repo/railties/lib/rails/application.rb#L254-L322). Observable behavior is pinned in [`railties/test/application/configuration_test.rb`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2653-L2888) via [`set_custom_config`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L5502-L5508), which writes `config/custom.yml` and assigns `config.my_custom_config = config_for(...)`.

This is not [`database_configuration`](file:///home/user/workspace/repo/railties/lib/rails/application/configuration.rb#L487-L522). That method also uses `ConfigurationFile` and a `shared` key, but a different merge (`reverse_merge!`, string keys, multi-DB shape).

- A `Pathname` is the file. Test: [`config_for uses the Pathname object if it is provided`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2735-L2744).

### Parse: ERB, YAML, empty document

[`ActiveSupport::ConfigurationFile`](file:///home/user/workspace/repo/activesupport/lib/active_support/configuration_file.rb) is `:nodoc:`. `config_for` calls `parse` with only the path.

```22:34:activesupport/lib/active_support/configuration_file.rb
    def parse(context: nil, **options)
      source = @content.include?("<%") ? render(context) : @content

      if source == @content
        YAML.unsafe_load_file(@content_path, **options) || {}
      else
        YAML.unsafe_load(source, **options) || {}
      end
    rescue Psych::SyntaxError => error
      raise FormatError, "YAML syntax error occurred while parsing #{@content_path}. " \
            "Please note that YAML must be consistently indented using spaces. Tabs are not allowed. " \
            "Error: #{error.message}"
```

**ERB (contract).** If the raw file contains `"<%"`, it is rendered with `ERB.new(@content)` and `erb.filename = @content_path`. `config_for` does not pass `context:`, so `erb.result` runs against ERB’s toplevel binding. Test: [`config_for containing ERB tags should evaluate`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2820-L2829) (`<%= 'custom key' %>`). Backtrace-filename behavior is in [`activesupport/test/configuration_file_test.rb`](file:///home/user/workspace/repo/activesupport/test/configuration_file_test.rb#L6-L31), not in the railties tests.

**ERB (mechanic).** The `"<%"` gate skips ERB when absent (`c00ef2a00b`). A value like `100%` is not ERB. I ran `ConfigurationFile.parse` on `pct: 100%` and on `<%= 1 + 1 %>`; they returned `{"development" => {"pct" => "100%"}}` and `{"development" => {"key" => 2}}`.

**YAML (mechanic).** Load is Psych `unsafe_load` / `unsafe_load_file` (aliases, arbitrary classes). `config_for` passes no Psych options. `nil`/`false` become `{}` via `|| {}`. I ran parse on `""`, `"---\n"`, `"false\n"`, `"null\n"` → `{}`; on `"0\n"` → `0`.

**Empty file (contract).** After that `{}`, both `all_configs[env]` and `all_configs[:shared]` are nil, so the method returns nil. Test: [`config_for with empty file returns nil`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2812-L2818).

**Syntax error (contract).** `Psych::SyntaxError` becomes `ActiveSupport::ConfigurationFile::FormatError`. Tests: railties [`config_for with syntax error show a more descriptive exception`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2831-L2841) and [`ConfigurationFileTest#raises FormatError for malformed YAML`](file:///home/user/workspace/repo/activesupport/test/configuration_file_test.rb#L41-L51).

Parse is assumed to yield a Hash of environment keys. A root scalar other than nil/false would call `deep_symbolize_keys` on a non-Hash and raise. That is not in the `config_for` tests.

### Symbolized access, and parsers that reject `symbolize_names`

```296:296:railties/lib/rails/application.rb
        all_configs    = ActiveSupport::ConfigurationFile.parse(yaml).deep_symbolize_keys
```

[`Hash#deep_symbolize_keys`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/hash/keys.rb#L116-L118) walks nested hashes and arrays of hashes (`key.to_sym rescue key`). Tests: [`HashExtTest#test_deep_symbolize_keys`](file:///home/user/workspace/repo/activesupport/test/core_ext/hash_ext_test.rb#L120-L127).

This is the compatibility contract. `be2fd61137` (Fixes #40031) stopped passing `symbolize_names: true` into YAML so `safe_yaml`-style patches that ignore that option still work. Symbolization always happens in Ruby after parse.

Test: [`config_for handles YAML patches (like safe_yaml) that disable the symbolize_names option`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2856-L2867). It stubs `YAML.load` and expects `{ key: "value" }`.

**Incidental to that test:** current `ConfigurationFile` calls `YAML.unsafe_load_file`, not `YAML.load`. On this Ruby, those are different Psych methods, so the stub does not intercept parse. The assertion still passes because the real file is `key: value` and `deep_symbolize_keys` produces `{ key: "value" }`. The intended contract is “do not depend on Psych `symbolize_names`”; the stub target is leftover from the old `YAML.load(..., symbolize_names: true)` path.

### `shared` and environment selection

```297:307:railties/lib/rails/application.rb
        config, shared = all_configs[env.to_sym], all_configs[:shared]

        if shared
          config = {} if config.nil? && shared.is_a?(Hash)
          if config.is_a?(Hash) && shared.is_a?(Hash)
            config = shared.deep_merge(config)
          elsif config.nil?
            config = shared
          end
        end
```

`if shared` is Ruby truthiness (`nil`/`false` skip merge). Empty YAML `shared:` is nil, so it is skipped.

[`Hash#deep_merge`](file:///home/user/workspace/repo/activesupport/lib/active_support/deep_mergeable.rb#L34-L48): `shared` is the base, env wins at a key; nested hashes recurse; arrays and other non-`DeepMergeable` values are replaced, not concatenated.

### Return wrapper: `OrderedOptions` vs raw value

```309:313:railties/lib/rails/application.rb
        if config.is_a?(Hash)
          config = ActiveSupport::OrderedOptions.new.update(config)
        end

        config
```

**Hash root (contract).** Top-level result is `ActiveSupport::OrderedOptions`. Tests: [`returns an ActiveSupport::OrderedOptions`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2869-L2888) (`config.some_key`), [`makes all hash methods available`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2678-L2695) (`keys`, `values`, `to_h`, `==`).

[`OrderedOptions#[]` / `#[]=` / `#dig`](file:///home/user/workspace/repo/activesupport/lib/active_support/ordered_options.rb#L37-L47) call `key.to_sym`. That is why [`accessible as symbol or string`](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2653-L2663) holds at the **root**: `config[:foo]` and `config["foo"]` after keys were stored as symbols. [`OrderedOptionsTest#test_string_dig`](file:///home/user/workspace/repo/activesupport/test/ordered_options_test.rb#L43-L51) is the unit-level version.

**Nested hashes (contract vs mechanic).** `deep_symbolize_keys` symbolizes nested keys; `OrderedOptions.new.update` does **not** wrap nested hashes. Nested method access (`config.foo.bar`) is not in the tests; nested access is `[:foo][:bar][:baz]`. Nested string keys are not a `config_for` contract. The 6.1 upgrade note in [`guides/source/upgrading_ruby_on_rails.md`](file:///home/user/workspace/repo/guides/source/upgrading_ruby_on_rails.md#L885-L905) is about that nested-hash change (`e5e9c558a3` removed `HashWithIndifferentAccess`).

**`update` mechanic.** `Hash#update` does not go through `OrderedOptions#[]=`, so it will store string keys as strings. `config_for` is safe only because `deep_symbolize_keys` already ran. I confirmed `OrderedOptions.new.update("key" => "value")` leaves a String key that `oo[:key]` then misses. That is why symbolization is not optional relative to the wrapper.

**Non-hash root (contract).** Arrays (and by the same `is_a?(Hash)` check, scalars) are returned as parsed. Empty file / missing env without shared → `nil`. No `config_for` test uses a scalar env value (`development: 42`); the array tests are the documented non-hash contract.

### Intentional contract vs incidental mechanic

**Contract (RDoc + tests):** load `config/#{name}.yml` or a given Pathname; ERB; one env (default `Rails.env`, overridable); `shared` deep-merged under env hashes; env arrays replace shared arrays; missing env is nil unless `shared` exists; empty file is nil; missing file raises that RuntimeError; hash results are `OrderedOptions` with symbol keys and string lookup at the root; YAML engines need not honor `symbolize_names`.

**Incidental:** no caching; `unsafe_load*` (trusted files, aliases, Ruby objects); ERB only if `"<%"` appears; `|| {}` collapsing YAML `false`/`null` at the document root; `if shared` truthiness; `Hash#update` not re-symbolizing; nested values remaining plain `Hash`; `database_configuration`’s different `shared` rules; the `YAML.load` stub no longer sitting on the parse call path.
