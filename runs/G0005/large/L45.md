## Assembly rules

`DefaultMiddlewareStack#build_stack` is the default list. User `config.middleware.use` is replayed afterward via [`MiddlewareStackProxy#merge_into`](file:///home/user/workspace/repo/railties/lib/rails/configuration.rb#L88-L94) and always **appends**. There is no dedup.

`config.session_store` with no args is the **resolved getter**, not “did the user opt in”:

- unset → [`setup_default_session_store`](file:///home/user/workspace/repo/railties/lib/rails/application/finisher.rb#L49-L53) installs `:cookie_store` for **every** app, including API-only
- `:cookie_store` → `ActionDispatch::Session::CookieStore` (truthy)
- `:disabled` → `nil` (falsy); `session_store?` is still truthy (`:disabled`)

That initializer runs before `:build_middleware_stack`. Application, env, and `config/initializers` all run earlier ([`load_config_initializers`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L670)), so a store set in those places is visible at stack build. Setting it after `app` is built is too late today and would stay too late.

Required order (already encoded in [`middleware_test.rb`](file:///home/user/workspace/repo/railties/test/commands/middleware_test.rb#L139)): Session after Cookies, Flash after Session. Session stores write through `request.cookie_jar`; only [`ActionDispatch::Cookies#call`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/middleware/cookies.rb#L712-L726) commits the jar to `Set-Cookie`.

## What the change would do

| App | Cookies today | Cookies after PR | Session after PR |
|---|---|---|---|
| Full-stack default | yes | yes | yes |
| Full-stack `session_store :disabled` | yes | yes (`!api_only`) | no |
| API-only default | no | **yes** (implicit cookie store is truthy) | **no** |
| API-only + explicit `:cookie_store` | no | yes | **no** (still `!api_only`) |
| API-only + `:disabled` | no | no | no |
| API-only + documented `middleware.use Cookies` + `use session_store` | Cookies then Session at the **end** | **two** Cookies (default + append), Session at end | only the appended store |

## Request consequences

- Default API-only: Cookies wraps every request. The jar is lazy, so a request that never touches `cookie_jar` still sends no `Set-Cookie`. Any access (`cookies`, `request.cookie_jar`, CookieStore) starts persisting cookies.
- API-only still has **no session middleware**, so `request.session` stays [`Http::Session.disabled`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/http/session.rb#L30-L33). `reset_session` on API apps remains the no-session path already tested in [`session_test.rb`](file:///home/user/workspace/repo/railties/test/application/middleware/session_test.rb#L373-L399).
- Following [the API guide](file:///home/user/workspace/repo/guides/source/api_app.md#L442-L456) would insert Cookies twice. Inner Cookies writes the jar; outer Cookies writes again (`write` does not `commit!`) → duplicate `Set-Cookie`.
- `ActionDispatch::Flash`, CSP, MethodOverride, TempfileReaper stay API-gated. Adding Flash via `middleware.use` still appends it; it only works if Session is already inner than Flash.
- `ActionController::API` still does not include `ActionController::Cookies`; the helper is unchanged.

## Compatibility

This expands the API stack by default, against `config.api_only` and the guides. It does not make `config.session_store` sufficient for sessions. Apps that already followed the guide get duplicate Cookies.

## Narrower alternative

Do not key Cookies on `config.session_store` while the default initializer still installs cookie store for API apps.

If the intent is “API apps that opt into sessions get Cookies (and Session) without `middleware.use`”:

1. Skip `setup_default_session_store` when `config.api_only`.
2. Insert Cookies and the session store when `config.session_store` is present (`:disabled` stays `nil`).
3. Update `guides/source/api_app.md` so apps drop the extra `middleware.use` lines (or they duplicate).
4. Add tests for default API (no Cookies/Session), API + explicit store (Cookies then Session, `session_options` applied), API + `:disabled`, and full-stack unchanged.

If the intent is only “don’t forget Cookies when the user already `use`s a session store,” detect that store in the stack (or insert Cookies immediately before the session middleware you actually add). Do not treat the implicit default store as opt-in.
