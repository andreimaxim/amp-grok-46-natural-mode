`isolate_namespace` is class-definition work. It does not sit on the request path. It stamps the engine class, the namespace module, and the engine’s `config.default_scope`. Routing, helpers, and controller names later read those stamps: at route-set creation, at `draw`, at controller class inheritance, and only then at dispatch.

```diagram
class body
  isolate_namespace(mod)
    engine_name ← underscore(mod.name).tr("/", "_")
    config.default_scope ← { module: underscore(mod.name) }
    isolated ← true
    unless mod.railtie_namespace already defined:
      mod.railtie_namespace
      mod.table_name_prefix
      mod.use_relative_model_naming?
      mod.railtie_helpers_paths
      mod.railtie_routes_url_helpers

boot
  make_routes_lazy → route_set_class, then Engine#routes (creates the set)
  add_routing_paths → reloader, if routes? or config/routes.rb exists
  define_main_app_helper → MountedHelpers#main_app
  set_routes_reloader_hook
    eager: draw now
    local + !eager_load: leave undrawn (LazyRouteSet)

draw (boot or first use)
  RouteSet#eval_block wraps the block in default_scope
  mount defines :as from engine_name and a RoutesProxy helper

request
  app router matches mount, rewrites SCRIPT_NAME / PATH_INFO
  Engine#call → build_request (routes, engine_script_name)
  endpoint (custom rack app, else the route set)
  Dispatcher constantizes params[:controller] (already prefixed)
```

## Class-level setup

[`Rails::Engine.isolate_namespace`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L384-L419) always does three things, then maybe a fourth:

```384:419:railties/lib/rails/engine.rb
      def isolate_namespace(mod)
        engine_name(generate_railtie_name(mod.name))

        config.default_scope = { module: ActiveSupport::Inflector.underscore(mod.name) }

          mod.singleton_class.instance_eval do
            define_method(:railtie_namespace) { railtie }

            # railtie_helpers_paths, railtie_routes_url_helpers
          end
        end
      end
```

`isolated?` is just the class accessor [`isolated`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L353-L356). The instance delegates to the class. Before `isolate_namespace`, `isolated` is `nil` (falsy). After, it is `true`.

An application can call the same method; [`Rails::Application#isolate_namespace`](file:///home/user/workspace/repo/railties/lib/rails/application.rb#L390-L393) forwards to the class. The `unless mod.respond_to?(:railtie_namespace)` guard is load-order sticky. A second engine isolating the same module still sets *that* engine’s `engine_name`, `default_scope`, and `isolated`. It does not replace the module methods. [`using namespace more than once on one module should not overwrite railtie_namespace method`](file:///home/user/workspace/repo/railties/test/railties/engine_test.rb#L1228-L1256) boots two engines that both `isolate_namespace(AppTemplate)` and asserts `AppTemplate.railtie_namespace` stays `AppTemplate::LoadedFirst::Engine`.

## `engine_name`

`engine_name` is an alias of [`railtie_name`](file:///home/user/workspace/repo/railties/lib/rails/railtie.rb#L178-L181):

```178:181:railties/lib/rails/railtie.rb
      def railtie_name(name = nil)
        @railtie_name = name.to_s if name
        @railtie_name ||= generate_railtie_name(self.name)
      end
```

[`generate_railtie_name`](file:///home/user/workspace/repo/railties/lib/rails/railtie.rb#L250-L252) is `underscore(string).tr("/", "_")`.

Without isolation, the name comes from the *engine class*: `MyEngine::Engine` → `"my_engine_engine"` ([docs at](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L175-L191)). Isolation overwrites it from the *namespace module*: `isolate_namespace Bukkits` → `"bukkits"`. That is what [`isolated engine routes and helpers are isolated to that engine`](file:///home/user/workspace/repo/railties/test/railties/engine_test.rb#L952-L953) asserts, together with `Bukkits.railtie_namespace == Bukkits::Engine`.

`engine_name "my_engine"` (same as `railtie_name "bar"` in [`railtie_name can be set manually`](file:///home/user/workspace/repo/railties/test/railties/railtie_test.rb#L42-L46)) writes `@railtie_name`. Timing matters:

- After `isolate_namespace`, a later `engine_name "..."` wins for mount `:as` and rake namespaces.
- It does **not** rewrite `table_name_prefix`. That method closes over `name, railtie = engine_name, self` at isolate time.
- `isolate_namespace` itself always calls `engine_name(...)`, so a name set *before* isolation is overwritten.

Mount uses that name as the default `:as`. [`Mapper#mount`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/mapper.rb#L641-L643) does `as = app_name(app, rails_app) if as == DEFAULT`, and [`app_name`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/mapper.rb#L688-L695) returns `app.railtie_name` for a Railtie. Nested isolation follows the same rule: `isolate_namespace Bukkits::Awesome` → `"bukkits_awesome"`, which is the helper the parent engine calls in [`nested isolated engines should set correct route module prefix`](file:///home/user/workspace/repo/railties/test/railties/engine_test.rb#L1076-L1121) (`bukkits_awesome.bar_path` → `"/bukkits/awesome/bar"`).

## Anonymous / unnamed namespaces

There is no dedicated isolation test for a nameless module. The methods still run.

[`Inflector.underscore`](file:///home/user/workspace/repo/activesupport/lib/active_support/inflector/methods.rb#L113-L121) returns `camel_cased_word.to_s.dup` unless the string matches `/[A-Z-]|::/`. `nil` does not match, so `underscore(nil)` is `""`. Then:

- `engine_name` becomes `""`
- `config.default_scope` becomes `{ module: "" }`
- if the module methods are defined, `table_name_prefix` is `"_"`

## Mount helpers and `main_app`

Two different helpers, defined at different times.

**`main_app`** is created at boot, before any draw, by [`define_main_app_helper`](file:///home/user/workspace/repo/railties/lib/rails/application/finisher.rb#L60-L62): `app.routes.define_mounted_helper(:main_app)` with no `script_namer`. [`define_mounted_helper`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/route_set.rb#L520-L536) defines methods on the shared [`RouteSet::MountedHelpers`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/route_set.rb#L508-L518) module. The proxy wraps *that* route set’s `url_helpers`. `main_app.bar_path` is therefore the application’s `/bar`, which the isolation test renders next to `foo_path` as `"/bukkits/foo, /bar"` ([lines 906, 966](file:///home/user/workspace/repo/railties/test/railties/engine_test.rb#L906)).

**Engine mount helpers** (`blog`, `bukkits`, `plugin_engine`) are created when `mount` runs, i.e. during draw. [`define_generate_prefix`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/mapper.rb#L697-L731) builds a `script_namer` from the mount’s named route and calls `app.routes.define_mounted_helper(name, script_namer)` on the *mounted* engine’s route set. Because `MountedHelpers` is one shared module, the helper is visible from application controllers, other engines, and views.

[`ActionController::Railtie`](file:///home/user/workspace/repo/actionpack/lib/action_controller/railtie.rb#L80-L82) includes `app.routes.mounted_helpers` on every controller. Isolated engines therefore have `main_app` even though they do not include the application’s named routes.

Request-time URL generation then uses [`RoutesProxy`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/routes_proxy.rb#L31-L41) to merge SCRIPT_NAME. Inside an engine action, [`ActionController::UrlFor#url_options`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/url_for.rb#L46-L57) prefers `request.script_name` when `_routes` is the same set the request is on. That is why [`mounted_engine_test`](file:///home/user/workspace/repo/railties/test/railties/mounted_engine_test.rb#L32-L33) with `scope "/:user"` can generate `/anonymous/blog/posts` from both the engine and the application, and why [`paths are properly generated when application is mounted at sub-path`](file:///home/user/workspace/repo/railties/test/railties/engine_test.rb#L1653-L1695) keeps an outer `SCRIPT_NAME=/foo` on both `main_app.bar_path` and `bukkits.bukkit_path`.

Journey’s unanchored mount is the dispatch half of the same split: it extends `SCRIPT_NAME` and shrinks `PATH_INFO` before calling the engine ([`Router#recognize`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/router.rb#L88-L94)). ## Lazy versus eager route loading

[`make_routes_lazy`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L616-L619) sets `config.route_set_class = LazyRouteSet` when `Rails.env.local?`, then instantiates the set. [`set_routes_reloader_hook`](file:///home/user/workspace/repo/railties/lib/rails/application/finisher.rb#L160-L181) draws immediately only if the set is not lazy **or** `config.eager_load`:


Eager load also sets `reloader.eager_load`, so [`RoutesReloader#reload!`](file:///home/user/workspace/repo/railties/lib/rails/application/routes_reloader.rb#L36) calls `route_sets.each(&:eager_load!)` after draw.

In local, non-eager boot, `config/routes.rb` is not evaluated until something touches routes. [`LazyRouteSet`](file:///home/user/workspace/repo/railties/lib/rails/engine/lazy_route_set.rb) forces that via `Rails.application.reload_routes_unless_loaded` on `call`, `draw`, `recognize_path`, `url_for`, `_path`/`_url` `method_missing`, and mounted-helper `method_missing` for names that are **not** `_path`/`_url`.

Consequences, all from [`lazy_route_set_test.rb`](file:///home/user/workspace/repo/railties/test/engine/lazy_route_set_test.rb):

- App and engine `root_path` are missing from `url_helpers.methods` until invoked, then return `"/"` and `"/plugin/"`.
- A GET `/` or `/plugin/` loads routes as a side effect of `LazyRouteSet#call`.
- `main_app` exists before draw (finisher). `plugin_engine` does not, until `mount` runs. [`mounted helpers lazily load routes`](file:///home/user/workspace/repo/railties/test/engine/lazy_route_set_test.rb#L227-L233) calls `helpers.plugin_engine.posts_path` and then `helpers.main_app.root_path`.
- After an explicit `reload_routes_unless_loaded`, both `main_app` and `plugin_engine` are `method_defined?` on the lazy mounted-helpers module ([lines 269–275](file:///home/user/workspace/repo/railties/test/engine/lazy_route_set_test.rb#L269-L275)).
- `_path`/`_url` are owned by the url-helper `method_missing` module so including both `url_helpers` and `mounted_helpers` still lazy-loads named routes ([lines 251–265](file:///home/user/workspace/repo/railties/test/engine/lazy_route_set_test.rb#L251-L265)).
- Isolation is orthogonal: the plugin engine in that file is **not** isolated. Lazy loading still applies to isolated engines because they use the same `route_set_class` and reloader.

`reload_routes_unless_loaded` is [`initialized? && routes_reloader.execute_unless_loaded`](file:///home/user/workspace/repo/railties/lib/rails/application.rb#L168-L169). The reloader’s monitor lets a nested `routes.draw` during load return false instead of recursing, and a waiter thread return true so `method_missing` retries the helper ([`execute_unless_loaded`](file:///home/user/workspace/repo/railties/lib/rails/application/routes_reloader.rb#L48-L75); concurrent tests around [lines 102–165](file:///home/user/workspace/repo/railties/test/engine/lazy_route_set_test.rb#L102-L165)).

## What is visible on a request

For a mounted isolated engine, the external effects are:

1. **URL space** — only the mount path is in the application route set. Inner routes live in the engine set. `/bukkits/foo` is not an application named route.
2. **Controller** — the drawn route already has `controller: "bukkits/foo"` (or `"bukkits/awesome/foo"`). Dispatch constantizes that. There is no extra isolation check in `Dispatcher`.
3. **Helpers in that controller** — engine named routes, engine helper modules, `main_app`, other mount proxies. Not application named routes or application helpers.
4. **Helpers in the application** — application named routes plus a proxy named from `engine_name` (`bukkits.root_path`, `blog.posts_path`).
5. **SCRIPT_NAME** — Journey sets it to the mount (and any outer scope). Engine `*_path` uses it; `main_app.*` does not; a sibling mount helper recomputes its own prefix.
6. **Forms / polymorphic URLs** — param keys omit the namespace; the generated path still includes the mount prefix.

Non-isolated engines skip `default_scope`, skip the module methods, prepend helpers into the app, and share application url helpers. Their controllers are looked up without a module prefix unless the engine’s own routes said otherwise. `Weblog::Engine` in `mounted_engine_test` is that case: `WeblogsController` is top-level, not `Weblog::WeblogsController`.
