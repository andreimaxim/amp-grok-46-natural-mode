## Established contract (must not change)

**Paths are absolute strings with a trailing slash on fixture dirs, none on `file_fixture_path`.** `"#{Rails.root}/test/fixtures/"` interpolates a Pathname, so you get `"/abs/app/test/fixtures/"`, not a Pathname and not a relative path.

**`uniq` is string equality, not pathname identity.** Executed:

```text
["test/fixtures/", "/abs/app/test/fixtures/"].uniq
  => both kept
["/abs/app/test/fixtures", "/abs/app/test/fixtures/"].uniq
  => both kept
["/abs/app/test/fixtures/", "/abs/app/test/fixtures/"].uniq
  => one kept
[Pathname("/abs/app/test/fixtures"), "/abs/app/test/fixtures/"].uniq
  => both kept
```

**`IntegrationTest` uses `+=`, not `uniq`.** After `TestFixtures` is included on ASTC, `IntegrationTest` already inherits the same array. Then `self.fixture_paths += ASTC.fixture_paths` copies and **duplicates**. Executed:

```text
ASTC: ["/app/test/fixtures/"]
IT:   ["/app/test/fixtures/", "/app/test/fixtures/"]
```

A refactor that “fixes” that duplication is a behavior change.

**`file_fixture_path` is overwritten, not merged.** A later hook run would clobber a custom ASTC value. A subclass that assigned `file_fixture_path` *before* the parent assignment keeps its own value (`class_attribute` override). Subclasses defined after inherit the parent string.

**Classes defined before vs after the require**

- Subclass of ASTC defined before `include TestFixtures`: after the include, it gains `fixture_paths` and inherits the assigned array (same object until it assigns).
- Subclass defined after: inherits ASTC’s values.
- `IntegrationTest` subclasses inherit IT’s *copied* array (the duplicated one), and do **not** follow later ASTC mutations.

**Repeated `require "rails/test_help"`** is a no-op (`$LOADED_FEATURES`). Hooks are not `run_once: true`, but they are not re-registered. `load` (not `require`) would re-register; ASTC `uniq` would stay the same, IT `+=` would **triple** the path. That is not public `require` behavior; do not “fix” it unless you also stop using `on_load` without `run_once`.

**Application-configured extra paths**

- Engine: present on ASTC before the `uniq` append → `[engine, app]` if strings differ; then IT `+=` duplicates that whole list.
- Set in `test_helper.rb` *after* `require "rails/test_help"` (plugin template): **replaces** ASTC, then assigns IT. That path is outside `test_help` but is the documented app-level API.
- Relative extra + absolute default: both remain.

**AR absent** (`defined?(ActiveRecord::Base)` false): no `TestFixtures`, no `fixture_paths`, no IT path copy, no query assertions, no `maintain_test_schema!`. `file_fixture_path` is still set. `fixtures :all` is not available.

**Missing fixture directory:** `fixtures :all` uses `Dir[...]` and yields `[]` (executed: `fixture_table_names == []`, no error). `file_fixture("x")` raises `ArgumentError: the directory '…/files' does not contain a file named 'x'` whether the directory is missing or the file is.

**Multiple boots in one process:** hooks run once. `Rails.root` is read at hook execution. A second `Rails.application` in the same process does **not** update `fixture_paths` / `file_fixture_path`. Isolation tests hide this because they fork.

**`before_setup`:** both controller and integration hooks define an instance method that sets `@routes = Rails.application.routes` then `super`. On IT, that class method **overrides** [`Integration::Runner#before_setup`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/testing/integration.rb#L370-L373) (`@app = nil`); `super` must still reach it. Dropping `super` or defining the method on a module with different precedence is a regression.

## Observable assertions (not class-variable-only)

Use a generated isolation app, real YAML + files, and actually run tests. Inspecting `fixture_paths` is supporting evidence only.

**1. Default ASTC fixture load**

```
test/fixtures/posts.yml          # one: { title: "from-app" }
test/fixtures/files/hello.txt    # "file-hello"
app/models/post.rb               # Post < AR::Base
```

```ruby
class PostsTest < ActiveSupport::TestCase
  fixtures :posts
  test "loads app fixture" do
    assert_equal "from-app", posts(:one).title
  end
  test "file_fixture reads test/fixtures/files" do
    assert_equal "file-hello", file_fixture("hello.txt").read
  end
end
```

**2. Extra engine/app path, relative vs absolute, duplicates**

Give the app an engine whose `test/fixtures/items.yml` is distinct from the app’s `posts.yml`. Also plant a *relative* extra path that is the same directory as the absolute default. Assert:

- `posts(:one)` and `items(:one)` both resolve (two physical dirs both used).
- `fixtures :all` table names include `posts` and `items`, and **exclude** anything under `test/fixtures/files` (TestFixtures already skips `file_fixture_path`).
- Relative + absolute of the same dir still loads once (AR reads both strings; duplicate rows would be the regression to catch).
- After require, `ActiveSupport::TestCase.fixture_paths` contains the extra path **then** `"#{Rails.root}/test/fixtures/"` (engine hook first, then `uniq` append). Order is public.

**3. Integration test uses the copied paths and `@routes`**

```ruby
class PostsIT < ActionDispatch::IntegrationTest
  fixtures :posts
  test "fixture + request" do
    assert_equal "from-app", posts(:one).title
    get "/posts"
    assert_response :success
  end
  test "file_fixture inherited" do
    assert_equal "file-hello", file_fixture("hello.txt").read
  end
end
```

That fails if IT never received `TestFixtures`, if `+=` targeted a different object, or if `before_setup` stopped setting `@routes`.

Do **not** assert IT’s array equals ASTC’s array. Current behavior is a **duplicate copy**. If you snapshot arrays, snapshot:

```text
ASTC: [extra?, "#{root}/test/fixtures/"]
IT:   ASTC.fixture_paths + ASTC.fixture_paths
```

**4. Subclass before vs after require**

In one child process, define `class Early < ActiveSupport::TestCase; end` *before* `require "rails/test_help"`, and `class Late < …` after. Run `fixtures :posts` / `file_fixture` on both. Both must see the same records/file. A subclass that set `self.file_fixture_path = "/other"` before the require must **keep** `/other` (executed `class_attribute` override).

**5. Repeated require**

```ruby
require "rails/test_help"
first = ActiveSupport::TestCase.fixture_paths.dup
require "rails/test_help"
assert_equal first, ActiveSupport::TestCase.fixture_paths
# then still load posts(:one) once
```

**6. Missing fixture dir**

Delete `test/fixtures`. `fixtures :all` must not raise; `file_fixture("hello.txt")` must raise `ArgumentError` mentioning `#{root}/test/fixtures/files`.

**7. AR absent**

`build_app` equivalent of `--skip-active-record` (no `ActiveRecord::Base`). After require:

- `ActiveSupport::TestCase.file_fixture("hello.txt").read` still works.
- `refute_includes ActiveSupport::TestCase.ancestors, ActiveRecord::TestFixtures`
- `refute_respond_to ActiveSupport::TestCase, :fixture_paths`
- integration GET still works (routes hook is outside the AR branch).

**8. Two boots in one process (the leak the isolation suite hides)**

Without forking: boot app A, `require "rails/test_help"`, then point `Rails.application` at app B with a different root. `file_fixture` / `posts(:one)` must still resolve against **A**. If a refactor starts evaluating `Rails.root` lazily per test, that is a behavior change.

## Isolation / cleanup (otherwise regressions hide)

- **Fork every case** (`ActiveSupport::Testing::Isolation`). `on_load` arrays, `class_attribute` values, `$LOADED_FEATURES`, `TestFixtures` inclusion, and `@@already_loaded_fixtures` are process-global. Two examples in one process will share fixture paths and can make a broken `+=` look fine.
- **`teardown_app`** restores `Rails.application` / `Rails.app_class` / `RAILS_ENV` and deletes the tmp app. Isolation forks, but setup still nil’s `Rails.application` in the parent ([`build_app`](file:///home/user/workspace/repo/railties/test/isolation/abstract_unit.rb#L111-L114)).
- **`ENV["PARALLEL_WORKERS"] = "0"`** in setup (as `test_test.rb` does). Parallel workers rebuild DBs and can mask fixture-path errors as schema errors.
- **Do not assert against the railties test suite’s own `ActiveSupport::TestCase`.** That class is already loaded and is *not* configured by the app’s `test_help`.
- **Reset AR fixture cache** if a case loads fixtures in-process (`ActiveRecord::FixtureSet.reset_cache`). Prefer running the generated tests via `rails test` in the child so cache stays in the child.
- **Do not `$LOADED_FEATURES.delete` `test_help` to simulate a second require.** That re-registers hooks and changes IT `+=` cardinality; it is not what `require` does.
- **Keep production abort and `maintain_test_schema!` out of the fixture-path examples** unless that is the case under test; pending migrations `exit 1` before hooks matter.
- **Snapshot both ASTC and IT paths before any in-app `test_helper` overwrite.** Generated `test_helper.rb` calls `fixtures :all` after `test_help`; plugin helpers *replace* paths. Assertions about `test_help` itself must run in a helper that requires `rails/test_help` and then asserts, before those overwrites.

## Reorganization traps

- Splitting the AR `on_load(:active_support_test_case)` so `include TestFixtures` and the `fixture_paths =` assignment are different hooks can reorder relative to engine `:active_record_fixtures` (runs inside `include`). Extra engine paths would land after the app path, or be lost.
- Changing IT from `+=` to `=` or `|=` removes the duplicate and can share the array with ASTC again (later ASTC mutation would leak into IT).
- Evaluating `Rails.root` lazily inside `file_fixture` would make a second boot in-process pick up the new root.
- Moving `before_setup` onto a prepended module can skip `Runner#before_setup` (`@app = nil`) or `TestFixtures#before_setup` (`setup_fixtures`).
- The AR-absent branch must not start including `TestFixtures` “for convenience.”
