**Reject.** The claim is false at this revision. Equality is on stored bytes, not on decrypted values, so a deterministic predicate must bind every on-disk representation that `deserialize` can still read.

The “optimization” is already the steady-state path: [process_arguments](file:///home/user/workspace/repo/activerecord/lib/active_record/encryption/extended_deterministic_queries.rb#L56-L64) no-ops when `previous_types` is empty. Expansion exists only for `previous:` / global previous schemes and for `support_unencrypted_data`. Removing it would not speed up the common post-migration case; it would break the migration cases the expander is for.

## Query compatibility ≠ read compatibility

| Stored bytes | `record.email` (decrypt) | `where(email: value)` without expansion |
|---|---|---|
| Current-scheme ciphertext | works | works |
| Previous-scheme ciphertext | works (`try_to_deserialize_with_previous_encrypted_types`) | **miss** — SQL never sees that ciphertext |
| Plaintext, `support_unencrypted_data` | works (`handle_deserialize_error` returns the value) | **miss** — SQL compares ciphertext to cleartext |

Read fallback lives in [encrypted_attribute_type.rb](file:///home/user/workspace/repo/activerecord/lib/active_record/encryption/encrypted_attribute_type.rb#L94-L129). Query expansion lives in [extended_deterministic_queries.rb](file:///home/user/workspace/repo/activerecord/lib/active_record/encryption/extended_deterministic_queries.rb#L71-L93): `[value] + previous_types.map { AdditionalValue.new(value, type) }`. `AdditionalValue` serializes with the **previous** type; [ExtendedEncryptableType#serialize](file:///home/user/workspace/repo/activerecord/lib/active_record/encryption/extended_deterministic_queries.rb#L148-L155) then skips re-encrypting it.

`previous_types` is previous schemes plus a [NullEncryptor clean-text scheme](file:///home/user/workspace/repo/activerecord/lib/active_record/encryption/encrypted_attribute_type.rb#L73-L90) when `support_unencrypted_data?`. Per-attribute `support_unencrypted_data:` overrides the global flag in [Scheme#support_unencrypted_data?](file:///home/user/workspace/repo/activerecord/lib/active_record/encryption/scheme.rb#L56-L58).

“Current scheme ciphertext” is also the wrong object. With default `deterministic: true` (`fixed: true`), [serialize uses the oldest previous scheme](file:///home/user/workspace/repo/activerecord/lib/active_record/encryption/encrypted_attribute_type.rb#L135-L142), not the newest. Rows written under `deterministic: { fixed: false }` or under a later scheme are a different ciphertext. The guide states this explicitly: querying deterministic data “will add ciphertexts using previous schemes” when `extend_queries` is on. Deterministic **key-list** rotation is unsupported; **scheme** rotation via `previous:` is the supported query path.

## What already fails if expansion is removed

Ran `bin/test` on the encryption files below: **83 runs, 302 assertions, 0 failures**. Then probed generated SQL (probes deleted). Existing tests that encode this contract:

- [extended_deterministic_queries_test.rb](file:///home/user/workspace/repo/activerecord/test/cases/encryption/extended_deterministic_queries_test.rb) — unencrypted `find_by` / relation `find_by`, per-attribute opt-in/opt-out vs global
- [encryption_schemes_test.rb](file:///home/user/workspace/repo/activerecord/test/cases/encryption/encryption_schemes_test.rb#L150-L163) — global previous schemes on `find_by_name("STEPHEN KING")` and `"stephen king"`

Observed SQL at this revision (`name` is the suite stand-in for `email`):

- Encrypted only, no previous, no unencrypted: `WHERE name = '<current ct>'` (expansion already skipped)
- Global unencrypted on, plaintext row: `WHERE name IN ('<current ct>', 'Dune')`
- Array: `IN ('<ct Dune>', '<ct Other>', 'Dune', 'Other')`
- Previous schemes (`downcase: true` then `downcase: false`): `where(name: "STEPHEN KING")` is `IN (oldest/downcase ct, oldest ct, newest/case-preserving ct)`
- `find_by` with extra values: `WHERE name IN (?, ?) LIMIT ?` — expansion turns the value into an Array, which is `StatementCache.unsupported_value?`, so Core `find_by` cannot keep a single-placeholder prepared statement. That is why [CoreQueries patches Base#find_by](file:///home/user/workspace/repo/activerecord/lib/active_record/encryption/extended_deterministic_queries.rb#L23-L28) before the cache, and why `where` uses `check_for_additional_values` to avoid double-expanding. [scope_for_create](file:///home/user/workspace/repo/activerecord/lib/active_record/encryption/extended_deterministic_queries.rb#L107-L119) then strips `AdditionalValue` so `where(email: v).first_or_create` does not persist the IN-list.

`downcase` / `ignore_case` do **not** need expansion for fully encrypted single-scheme rows: current `serialize` downcases first, so `where(name: "DUNE")` already binds the same ciphertext as `"dune"`. With `ignore_case`, [only `:name` is deterministic](file:///home/user/workspace/repo/activerecord/test/models/book_encrypted.rb#L51-L54); `original_name` is a non-deterministic companion. Queries hit downcased `name`; reads return preserved case from `original_name`. Expansion still matters for those options once plaintext or a previous scheme is in the column.

## Minimal failing examples

Same setup as the suite: `extend_queries = true`. Substitute `email` for `name`.

**1. `where(email: value)` + unencrypted data**

```ruby
ActiveRecord::Encryption.config.support_unencrypted_data = true
UnencryptedBook.create!(name: "Dune")
EncryptedBook.where(name: "Dune").to_a  # [] without expansion
EncryptedBook.first.name                # still "Dune" — read path is fine
```

**2. Array-valued predicates**

```ruby
# same config; plaintext "Dune" plus any other value
EncryptedBook.where(name: ["Dune", "Other"]).to_a  # misses plaintext "Dune"
```

**3. `find_by` (prepared/bound)**

```ruby
EncryptedBook.find_by(name: "Dune")                 # nil; would bind only current ct
EncryptedBook.where("id > 0").find_by(name: "Dune") # same miss on the relation patch
```

**4. Per-attribute `support_unencrypted_data` vs global**

```ruby
ActiveRecord::Encryption.config.support_unencrypted_data = false
UnencryptedBook.create!(name: "Dune")
EncryptedBookWithUnencryptedDataOptedIn.find_by(name: "Dune")   # must still find
EncryptedBookWithUnencryptedDataOptedOut.find_by(name: "Dune")  # must stay nil
# inverse: global true, opted-out attribute must not expand (already asserted)
```

**5. `previous:` / scheme rotation (not deterministic key-list rotation)**

```ruby
ActiveRecord::Encryption.config.support_unencrypted_data = false
ActiveRecord::Encryption.config.previous = [
  { downcase: true,  deterministic: true },
  { downcase: false, deterministic: true }
]
klass = Class.new(Author) do
  self.table_name = "authors"
  encrypts :name, deterministic: true, downcase: false  # fixed: true → writes oldest
end
row = klass.create!(name: "STEPHEN KING")  # stored as downcased ct
# write a newest-scheme ciphertext (as `fixed: false` / pre-rotation rows do)
newest = klass.type_for_attribute(:name).previous_types.last.serialize("STEPHEN KING")
ActiveRecord::Encryption.without_encryption { row.update!(name: newest) }

klass.find_by(name: "STEPHEN KING")  # nil if only current/oldest ct is bound
# reload/decrypt of that row can still succeed via previous_types
```

With `deterministic: { fixed: false }`, the miss flips: new rows use newest ct; old downcased rows disappear from `where` unless previous ciphertexts are bound.

**6. `downcase` + unencrypted** (encrypted-only `find_by("DUNE")` would still pass)

```ruby
ActiveRecord::Encryption.config.support_unencrypted_data = true
UnencryptedBook.create!(name: "dune")
EncryptedBookWithDowncaseName.find_by(name: "DUNE")
# today: IN (ct_of("dune"), "dune") because clean-text scheme copies downcase:
#   SQL[DUNE]: IN ('{"p":"Yq9W9w==",...}', 'dune')
```

**7. `ignore_case` + preserved `original_name`**

```ruby
ActiveRecord::Encryption.config.support_unencrypted_data = true
book = create_unencrypted_book_ignoring_case(name: "Dune")
EncryptedBookThatIgnoresCase.find_by(name: "dune")  # query miss without plaintext bind
book.name                                           # still "Dune" from original_name
# where(original_name: "Dune") is not in this expander: original_name is not deterministic
```
