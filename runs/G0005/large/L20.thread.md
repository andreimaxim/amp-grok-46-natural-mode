## Assistant

The method is a Base-only stack push of `{ role, shard, prevent_writes, klasses }` around `yield`, with lookup keyed by those klasses. Existing tests pin argument shape and a two-class role swap; they do not pin flatten-of-nested-arrays, stack restore on raise/throw, concurrent isolation, or actual write rejection. The matrix below is the preservation net for a refactor.

### Contract (from source, not from a desired redesign)

[`connected_to_many`](file:///home/user/workspace/repo/activerecord/lib/active_record/connection_handling.rb#L173-L187) is:

```ruby
def connected_to_many(*classes, role:, shard: nil, prevent_writes: role == ActiveRecord.reading_role)
  classes = classes.flatten
  if self != Base || classes.include?(Base)
    raise NotImplementedError, "connected_to_many can only be called on ActiveRecord::Base."
  end
  if role == ActiveRecord.reading_role && !prevent_writes
    raise ArgumentError, "cannot set `prevent_writes` to false when `role` is `reading`."
  end
  append_to_connected_to_stack(role: role, shard: shard, prevent_writes: prevent_writes, klasses: classes)
  begin
    yield
  ensure
    connected_to_stack.pop
  end
end
```

Effects that a refactor must keep:

- **Receiver.** Only `ActiveRecord::Base`. Any other receiver, including an abstract connection class, raises `NotImplementedError` before the stack is touched.
- **Forbidden klass.** After flatten, `classes.include?(ActiveRecord::Base)` is the same `NotImplementedError`. The check is identity on `Base`, not “any primary class.”
- **Argument shape.** `*classes` then `flatten`. `[A, B]`, `A, B`, and nested arrays become one `klasses` list. `role:` is required. `shard:` defaults to `nil`.
- **One stack entry for all listed klasses**, not N nested `connected_to` calls. [`append_to_connected_to_stack`](file:///home/user/workspace/repo/activerecord/lib/active_record/connection_handling.rb#L428-L434) still raises `ShardSwapProhibitedError` if `shard` is present and any listed klass has swapping prohibited.
- **Lookup is klass-scoped and last-wins.** [`current_role`](file:///home/user/workspace/repo/activerecord/lib/active_record/core.rb#L179-L186) / [`current_shard`](file:///home/user/workspace/repo/activerecord/lib/active_record/core.rb#L196-L203) / [`current_preventing_writes`](file:///home/user/workspace/repo/activerecord/lib/active_record/core.rb#L213-L220) walk `connected_to_stack` from the tail. An entry applies only if `klasses` includes `Base` or `connection_class_for_self`. `shard: nil` is skipped (`if hash[:shard]`), so an omitted shard leaves the outer shard in place. `prevent_writes: false` is not skipped (`!hash[:prevent_writes].nil?`).
- **Unlisted models are untouched.** Their `connection_class_for_self` is not in `klasses`, so they keep the outer/default role, shard, and write flag.
- **`prevent_writes` default.** `role == ActiveRecord.reading_role` (default `:reading`). Explicit `prevent_writes: true` on a writing role is legal. `role: reading, prevent_writes: false` raises `ArgumentError` and must not push.
- **Restore.** `ensure; connected_to_stack.pop` runs on normal return, `raise`, and `throw`. The method does **not** use [`with_role_and_shard`](file:///home/user/workspace/repo/activerecord/lib/active_record/connection_handling.rb#L420-L426); it does not auto-`load` a yielded `Relation`.
- **Isolation.** The stack lives in `ActiveSupport::IsolatedExecutionState[:active_record_connected_to_stack]` ([`connected_to_stack`](file:///home/user/workspace/repo/activerecord/lib/active_record/core.rb#L224-L232)). Default isolation is `:thread` ([`IsolatedExecutionState`](file:///home/user/workspace/repo/activesupport/lib/active_support/isolated_execution_state.rb#L14-L75)).

Pool selection is `retrieve_connection_pool(..., role: current_role, shard: current_shard)`. Accidental writes are `ReadOnlyError` from [`QueryIntent#preprocess_query`](file:///home/user/workspace/repo/activerecord/lib/active_record/connection_adapters/query_intent.rb#L425-L428) when `adapter.preventing_writes?` is true. For a non-replica pool that flag is the stack’s `prevent_writes` for that connection class, not “we selected a replica.”

While latches overlap: parent still reading on `A` **and** `B`; child writing/`shard_one` on `A`, default on `B`. After both join, main thread snapshots match pre-call.

**Instrumentation:** `db_config.name` plus a **value stored in that database** (the tempfile/SQLite pattern in the sharding tests), not only `current_role`. A shared global stack would make the child read the parent’s replica row (or raise `ReadOnlyError` on the child’s write). Lease the connection in each thread before waiting on latches, as the existing tests do.

**9c. Fiber isolation, only if cheap.** If you set `isolation_level = :fiber` for one test, two fibers with the same overlap as 9a must not share the stack. Restore `:thread` in `ensure`. Skip on implementations without fiber-local support rather than weakening 9a.

### Priority order (leaks and writes first)

Run in this order; stop a refactor that fails an earlier row.

1. **8b, 8c** — leftover stack after raise/throw (role/shard/`prevent_writes` leak on the thread).
2. **3a, 3c** — `ReadOnlyError` on listed klasses; successful write on the unlisted klass; successful write after unwind.
3. **2a, 2b** — two classes switch; `P`’s pool name and writes unchanged; omitted shard does not clobber.
4. **9a, 9b** — overlapping thread must not observe the parent’s role/shard or inherit `prevent_writes`.
5. **7a–7c** — inner `connected_to` / `connected_to_many` last-wins; outer restored.
6. **4, 5, 6b** — invalid calls must not push (especially `[A, Base]`).
7. **1c, 1d** — flatten.
8. Existing `base_test` / `test_connected_to_many` as the cheap suite.

Do not treat a green `current_role` as sufficient. Every switch case should include at least one of: `db_config.name`, a `ReadOnlyError` vs successful INSERT pair, and stack-size-before/after. Those three are what leaked state and accidental writes look like after a refactor that still “returns from the block.”
