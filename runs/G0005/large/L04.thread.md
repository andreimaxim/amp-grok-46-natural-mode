## Assistant

`Array#extract_options!` is the pre-kwargs convention for `*args` methods: treat a trailing options hash as keyword-ish, leave everything else positional.

The whole contract lives in [activesupport/lib/active_support/core_ext/array/extract_options.rb](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/array/extract_options.rb):

```ruby
class Hash
  def extractable_options?
    instance_of?(Hash)
  end
end

class Array
  def extract_options!
    if last.is_a?(Hash) && last.extractable_options?
      pop
    else
      {}
    end
  end
end
```

Two predicates, both required. `is_a?(Hash)` is the cheap type gate. `extractable_options?` is the policy gate.

### Trailing-only

Only `last` is inspected. No scan, no reverse search, no merge of earlier hashes.

```text
extract_options!
  last.is_a?(Hash) && last.extractable_options?
    yes → pop          # same object, receiver loses last
    no  → {}           # fresh Hash, receiver unchanged
```

`[{a: 1}, 2].extract_options!` returns `{}` and leaves `[{a: 1}, 2]`. `[{a: 1}, {b: 2}]` pops only `{b: 2}` and leaves `[{a: 1}]`.

### `Hash` vs subclasses

`Hash#extractable_options?` is `instance_of?(Hash)`, not `is_a?(Hash)`. A bare `Hash` is extractable. A `Hash` subclass is not, even though `is_a?(Hash)` is true.

That is why the first check alone is not enough. `last.is_a?(Hash)` lets a subclass through; `extractable_options?` then rejects it. Tests lock this: a `HashSubclass` last element is not popped, and the array is left intact.

### Subclass opt-in

A subclass that wants to be treated as options overrides `extractable_options?` to return true. In-tree opt-ins: `HashWithIndifferentAccess`, `OrderedOptions` (and `ActiveSupport::OrderedHash`). Tests also cover a local `ExtractableHashSubclass`.

Opt-in is per class, not per instance of `Hash`. The default implementation never looks at contents.

### Receiver mutation and the empty return

Success is `pop`: the receiver loses its last element, and the return is that same object (`equal?`), not a copy.

Failure returns a new empty `Hash` (`{}`). It is always a fresh object, class `Hash`, not `nil`, not the last element, not a frozen singleton. Empty array, non-hash last, and non-extractable hash last all take this branch. The receiver is not mutated.

### Why an earlier hash stays positional

The method exists so APIs like `foo(*args)` can end with an optional options hash without consuming a hash that was meant as a positional value.

`foo({ id: 1 }, :sym)` must keep `{ id: 1 }` in `args`. `foo(:sym, { id: 1 })` must peel the trailing hash. Looking only at `last` is that distinction. A non-trailing hash is data.

The subclass rule is the same idea applied to type: a `Hash` subclass is often a domain value (`HashWithIndifferentAccess` is the exception because it *is* used as options). Without the `instance_of?` / opt-in split, a trailing domain hash would be stolen from the positional list.
