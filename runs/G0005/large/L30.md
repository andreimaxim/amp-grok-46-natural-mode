`send_stream` is a thin public wrapper around header assignment, a yielded `response.stream` (`Live::Buffer`), and an `ensure` close. Live’s thread, commit, and disconnect behavior sit around it, not inside it. Verification should pin those observables without touching private layout.

```diagram
request thread                         worker (CachedThreadPool)
──────────────                         ─────────────────────────
Live#process
  copy Thread locals
  post work ─────────────────────────▶ IsolatedExecutionState.share_with
  await_commit ◀── first write/close    send_stream
                                          instrument start
                                          set Content-Type / Content-Disposition
                                          yield response.stream  ──write──▶ Buffer (SizedQueue)
                                          instrument finish
                                        ensure stream.close ──nil──▶ reader
  raise stored pre-commit error         clean locals; commit!
       │
Rack body.each / body.close ──abort──▶ Buffer#abort
```

# Current contract (layout-independent)

[`send_stream`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/live.rb#L397-L413) always:

1. Instruments `send_stream.action_controller` with the **raw kwargs** `{ filename:, disposition:, type: }` (not the resolved MIME).
2. Sets `Content-Type` then `Content-Disposition`, then yields `response.stream`.
3. Closes the stream in `ensure`, including when the block raises. Close is **outside** the instrument block.

Type resolution, as written:

```ruby
(type.is_a?(Symbol) ? Mime[type].to_s : type) ||
  Mime::Type.lookup_by_extension(File.extname(filename).downcase.delete("."))&.to_s ||
  "application/octet-stream"
```

Disposition is whatever [`ActionDispatch::Http::ContentDisposition.format`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/http/content_disposition.rb#L8-L33) returns: `disposition; filename="…"; filename*=UTF-8''…`.

[`Live::Buffer#write`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/live.rb#L221-L239) commits on first write (`Cache-Control` defaults to `no-cache`, `Content-Length` removed), enqueues one chunk per write, then if `!connected?` either raises `ClientDisconnected` or discards. [`#close`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/live.rb#L248-L254) commits, marks closed, and pushes a `nil` terminator. Rack `body.close` is [`Response#abort`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/http/response.rb#L551-L553), not producer close.

[`Live#process`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/live.rb#L319-L364) runs the action on [`live_thread_pool_executor`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/live.rb#L419-L433), copies thread locals, shares `IsolatedExecutionState`, always `commit!`s in `ensure`, and splits exceptions on `committed?`. Functional tests that need this must call `original_new_controller_thread` / `original_clean_up_thread_locals`; the default test stubs run inline and skip local cleanup ([`actionpack/lib/action_controller/test_case.rb`](file:///home/user/workspace/repo/actionpack/lib/action_controller/test_case.rb#L20-L40)). [`LiveStreamTest`](file:///home/user/workspace/repo/actionpack/test/controller/live_stream_test.rb#L361-L372) already restores the real executor.

# Checks

### 1. Inferred content type

**Seam:** `get` of a `send_stream` action with `type` omitted.

| Case | Filename | Assert |
|---|---|---|
| Known extension | `sample.csv` | `headers["Content-Type"]` is the String `"text/csv"` (already [`test_send_stream_with_inferred_content_type`](file:///home/user/workspace/repo/actionpack/test/controller/live_stream_test.rb#L439-L447)) |
| Case-insensitive ext | `Sample.CSV` | same `"text/csv"` |
| Unknown / no ext | `export` or `file.notarealext` | `"application/octet-stream"` |

Also assert joined body from the writes, and `assert_stream_closed`. Do not compare against `Mime[...]` inside the test except as a human comment; pin the header string.

### 2. Explicit content type

**Seam:** same, with `type:` set.

| Case | `type` | Assert `Content-Type` |
|---|---|---|
| MIME symbol | `:csv` / `:json` | `"text/csv"` / `"application/json"` as `String` ([existing implicit/options tests](file:///home/user/workspace/repo/actionpack/test/controller/live_stream_test.rb#L411-L437)) |
| Raw string | `"text/csv"` | exact string, class `String` |
| String wins over ext | filename `x.json`, type `"text/plain"` | `"text/plain"` |

Symbol vs string must stay distinct in the **notification payload** (`:csv` vs `"text/csv"`); only the header is resolved.

### 3. RFC-compatible filename disposition

**Seam:** `response.get_header("Content-Disposition")` after `get`. Pin the **full** header, not `assert_match` fragments (existing [`test_send_stream`](file:///home/user/workspace/repo/actionpack/test/controller/live_stream_test.rb#L391-L397) is too weak).

| Case | Assert |
|---|---|
| Default | `disposition: "attachment"` (kwarg default) |
| Override | `"inline"` |
| ASCII | `attachment; filename="my.csv"; filename*=UTF-8''my.csv` |
| Accented / non-Latin | same shape as [`ContentDispositionTest`](file:///home/user/workspace/repo/actionpack/test/dispatch/content_disposition_test.rb): `filename="…"` (transliterated/percent-escaped) **and** `filename*=UTF-8''…` |

Oracle: the exact string `ActionDispatch::Http::ContentDisposition.format(...)` would produce for those kwargs — that is the public header contract `send_file` already pins. Do not parse the header with a custom regex that would allow dropping `filename*=`.

### 4. Chunk order

**Seam:** action that `write`s/`writeln`s several distinct strings; collect via `response.each` (or `resp.stream.each` after `await_commit`), **not** only `response.body`.

Assert:

- Chunk sequence equals the write sequence (`writeln` adds a trailing `"\n"` only when missing; [`write_lines`](file:///home/user/workspace/repo/actionpack/test/controller/live_stream_test.rb#L141-L145) already documents that).
- Joined body equals concatenation in that order.
- `write` return value is `bytesize` if you exercise the stream object directly (`BufferTest`).

**Sync:** if using the real executor and streaming `each` concurrently with writes, copy the [`test_async_stream`](file:///home/user/workspace/repo/actionpack/test/controller/live_stream_test.rb#L454-L473) latch handshake: reader asserts `parts.shift`, then counts down so the producer may write the next chunk. `assert thread.join(3)`. Do not read `response.body` on the test thread at the same time — that would also consume the queue.

Coalescing writes into one Rack chunk would be a behavior change; this check is what forbids it.

### 5. Exception before commit

Two different observables — do not fold them together.

**A. Action raises before `send_stream` (true pre-commit for `process`)**

**Seam:** action that `raise`s, never calls `send_stream`. Same as [`test_exception_in_controller_before_streaming`](file:///home/user/workspace/repo/actionpack/test/controller/live_stream_test.rb#L667-L671).

Assert: `get` **re-raises** the original exception; `assert_no_notifications("send_stream.action_controller")`; no `Content-Disposition` from `send_stream`. `process` still `commit!`s in `ensure` — do not require `stream.closed?` here unless the action closed it.

**B. Raise inside the `send_stream` block before any `write`**

This is **not** pre-commit for `process`: [`ensure` close](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/live.rb#L411-L413) commits first, then the exception is seen as committed.

**Seam:** `send_stream(...) { raise ... }` with no write.

Assert:

- Notification still emitted (instrument `ensure` finishes before close) with `payload[:exception]` / `:exception_object`.
- After `get`, `assert_stream_closed`.
- For HTML, body may include [`ActionView::Base.streaming_completion_on_exception`](file:///home/user/workspace/repo/actionview/lib/action_view/base.rb#L173-L174); for non-HTML, body stays empty aside from that path — match [`test_exception_handling_html` / `_plain_text`](file:///home/user/workspace/repo/actionpack/test/controller/live_stream_test.rb#L626-L663).
- Exception is **not** re-raised to `get` (committed branch logs and closes). Use `capture_log_output` and `assert_match` the error message.

**Cleanup:** restore logger; drain/close the stream if `get` is rescued.

### 6. Exception after commit

**Seam:** inside `send_stream`, `stream.write ""` (or real data) then `raise`.

Assert:

- First chunk(s) already visible to a reader that `await_commit`s then `each`s.
- Same committed exception path as 5B: logged, not re-raised; HTML completion trailer only when `request.format == :html`.
- Stream closed even if `on_error` is unset (default callback is `{ true }`).
- Notification includes exception keys; duration includes the write + raise, not the later `process` logging.

Optional extra: `stream.on_error` writes a recovery chunk then closes — [`test_exception_callback_when_committed`](file:///home/user/workspace/repo/actionpack/test/controller/live_stream_test.rb#L665-L673) already shows the assertion shape (`body` equals the callback bytes, log has the original error, `assert_stream_closed`).

### 7. Client disconnect, `ignore_disconnect == false` (default)

Existing tests only cover `true`. Need both Buffer-level and `send_stream`-level.

**Buffer seam** (no controller): write one chunk, start a reader thread on `response.each`, wait until the chunk is received **and** `reader.status == "sleep"` ([`test_abort_terminates_a_reader_blocked_on_the_buffer`](file:///home/user/workspace/repo/actionpack/test/controller/live_stream_test.rb#L774-L794)), then `buf.abort`, then `write` again.

Assert: second `write` raises `ActionController::Live::ClientDisconnected` with message `"client disconnected"`; it is a `RuntimeError`, not `IOError`; queue is cleared (`each` yields no extra chunks).

**`send_stream` seam:** restore real executor. Action:

1. `send_stream` block sets nothing on `ignore_disconnect` (default false).
2. `stream.write` a commit token; count down latch `committed`.
3. Wait latch `aborted`.
4. Next `write` should raise; count down `raised` from `rescue ClientDisconnected` **inside** the action (because `process` will swallow it once committed).

Test thread: `get`; `resp.await_commit`; `_, _, body = resp.to_a`; `body.each { body.close; break }`; count down `aborted`; `Timeout.timeout(3)` wait `raised`; `t.join(3)`.

Assert: log contains `ClientDisconnected` / `"client disconnected"`; later writes did not run; `assert_stream_closed` (send_stream `ensure` + process `ensure` both close — closing twice must stay idempotent enough that this passes).

**Sync / cleanup:** latches, `Timeout.timeout`, `reader&.kill` / `join`, never `response.body` on the test thread, restore logger. Do not fill the queue unless testing backpressure; abort-after-commit is enough and avoids the `queue_size` restore dance.

### 8. Client disconnect, `ignore_disconnect == true`

**Seam:** same as [`test_ignore_client_disconnect`](file:///home/user/workspace/repo/actionpack/test/controller/live_stream_test.rb#L509-L531), but the writes must happen **inside** `send_stream`.

Assert:

- After abort, further `write`s do not raise and do not appear as extra body chunks (buffer cleared; writes discarded).
- Producer runs to completion (`latch` + log `"Work complete"`).
- `assert_stream_closed` after the block/`ensure`.
- `write` still returns `bytesize`.

**Sync:** `await_commit` → `body.each { body.close; break }` → `Timeout.timeout(3) { latch.wait }`. `capture_log_output` ensure restores the logger.

### 9. Stream closure on every path

One assertion helper, every `send_stream` path:

`assert_predicate response.stream, :closed?` and `response.committed?` (and `sent?` when the test consumed the body).

Paths that must each have their own example:

- normal yield return
- `writeln`-only body
- raise before write (5B)
- raise after write (6)
- disconnect ignore false (7) and true (8)

Do not read `closed?` until the producer is known finished (`get` returned, or latch after `ensure`). Checking from a notification `finish` callback is the opposite check (see 11).

**Cleanup:** if a reader thread is blocked in `each`, `abort` or `close` then `join(5)` or `kill` in `ensure` ([BufferTest](file:///home/user/workspace/repo/actionpack/test/controller/live_stream_test.rb#L774-L811) pattern). Restore `Buffer.queue_size` if a test sets it (`test_abort_with_full_buffer`).

**Seam:** `capture_notifications("send_stream.action_controller")` or a start/finish subscriber around `get`. Existing [`test_send_stream_instrumentation`](file:///home/user/workspace/repo/actionpack/test/controller/live_stream_test.rb#L399-L409) only subset-matches payload on the happy path.

# Cross-cutting flake rules

- **Executor:** `send_stream` + disconnect + thread-local checks require `original_new_controller_thread`. Header-only checks are safe either way; prefer one setup (current `LiveStreamTest#setup`) so close/commit timing matches production.
- **One consumer:** either `response.body` **or** a reader `each`, never both.
- **Handshake:** `CountDownLatch` / `await_commit` / `join(timeout)` / `Timeout.timeout`. Fail on timeout, don’t hang the suite.
- **Abort vs close:** `body.close` → abort (client gone). Producer close → `nil` terminator. Tests that call both must still terminate the reader (`test_close_then_abort_still_terminates_the_reader`).
- **Queue size:** global `Buffer.queue_size = nil` in tests. Restore if you set it. Don’t depend on the default `10` unless the example is backpressure.
- **Globals to restore:** logger, `queue_size`, `IsolatedExecutionState`, `live_streaming_excluded_keys`, `isolation_level`, notification subscribers, `Thread.current` keys.
- **Parallel tests:** unique latch objects per example (`@controller.latch = ...` in the test, not class-level).
- **`Thread.abort_on_exception = true`** is already on in this file; unexpected worker exceptions fail loudly — keep it.

# What existing tests already pin vs. what a refactor still needs

Already in [`live_stream_test.rb`](file:///home/user/workspace/repo/actionpack/test/controller/live_stream_test.rb): inferred/implicit/explicit CSV type, options (inline + `:json`), weak disposition `assert_match`, happy-path notification payload, ignore-disconnect **true** (not via `send_stream`), process exception before/after commit (not via `send_stream`), thread-local copy/reset, buffer abort/close races.

No production code changes implied; if a check above fails on **current** main, treat that as a missing characterization test, not a product bug, and pin the behavior this trace describes.
