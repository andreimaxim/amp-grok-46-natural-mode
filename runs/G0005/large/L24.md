`recognize_path` is not a second router. It fabricates a Rack request, runs Journey recognition, then **accepts only a dispatcher (or a nested engine dispatcher)** and returns that request’s `path_parameters`. Query keys, redirects, and rack apps never come back as the result.

```text
  method = (environment[:method] || "GET").upcase
  normalize_path(path) unless path includes "://"
  Rack::MockRequest.env_for(path, method:)
    URI::InvalidURIError -> RoutingError
  Request.new(env)

RouteSet#recognize_path_with_request
  Journey::Router#recognize(req) yields |route, params|
    params.merge!(extras)
    URI-unescape every String value
    req.path_parameters = params
    app = route.app
    if app.matches?(req) && app.dispatcher?
      req.controller_class          # NameError -> "A route matches ..."
      return req.path_parameters
    elsif app.matches?(req) && app.engine?
      recurse raise_on_missing: false
      return if nested params
    end                             # else: skip (redirect / rack app)

```

## 1. Input → fake request

[`RouteSet#recognize_path`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/route_set.rb#L911-L924) does three things before Journey sees the request.

**Method.** `environment[:method]` defaults to `"GET"` and is uppercased. That becomes `REQUEST_METHOD` on the mock env. Verb matching later is `Journey::Route#matches?` via `VerbMatchers` ([`journey/route.rb`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/route.rb#L14-L70), [`#matches?`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/route.rb#L172-L194)).

**Relative vs absolute.** Normalization runs only when `path` does **not** contain `"://"`:

```911:924:actionpack/lib/action_dispatch/routing/route_set.rb
def recognize_path(path, environment = {})
  method = (environment[:method] || "GET").to_s.upcase
  path = Journey::Router::Utils.normalize_path(path) unless path&.include?("://")
  extras = environment[:extras] || {}
  begin
    env = Rack::MockRequest.env_for(path, method: method)
  rescue URI::InvalidURIError => e
    raise ActionController::RoutingError, e.message
  end
  req = make_request(env)
  recognize_path_with_request(req, path, extras)
end
```

[`Utils.normalize_path`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/router/utils.rb#L27-L47): `nil` → `"/"`; force a leading `/`; squeeze `//`; strip a trailing `/` except for `"/"`; upcase `%xx`. Tests: [`utils_test.rb`](file:///home/user/workspace/repo/actionpack/test/journey/router/utils_test.rb#L29-L48), trailing-slash recognition in [`routing_test.rb`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L1212-L1213) and [`test_default_route_recognition`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L1846-L1858), `recognize_path(nil)` → root in [`test_recognize_path`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L2133-L2134), downcased percent-encoded unicode in [`test_downcased_unicode_path`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L2181).

An absolute URL skips that pass. `Rack::MockRequest.env_for` RFC2396-parses it and fills `PATH_INFO`, `QUERY_STRING`, `HTTP_HOST` / `SERVER_NAME`, scheme, port. Host/protocol constraints therefore see a real request, which is why [`test_route_with_subdomain_and_constraints_must_receive_params`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L1691-L1700) and [`assert_recognizes` protocol tests](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_assertions_test.rb#L108-L119) pass an `http(s)://...` string.

**Query string.** `env_for` splits `?…` into `QUERY_STRING` and keeps `PATH_INFO` as the path only. Recognition returns **`req.path_parameters` only**. Query keys are not copied in. The supported injection is `environment[:extras]`, merged in `recognize_path_with_request` before constraints run. That is the contract `assert_recognizes` documents and tests: extras must be a third argument; “appending the query string on the path directly will not work” ([`assertions/routing.rb`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/testing/assertions/routing.rb#L157-L163), [`test_assert_recognizes_with_extras`](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_assertions_test.rb#L99-L100), query-constraint extras in [`routing_assertions_test.rb`](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_assertions_test.rb#L122-L126)).

Bad URIs become `ActionController::RoutingError` wrapping `URI::InvalidURIError`, not a Journey miss.

## 2. Journey: which routes, which captures

[`Journey::Router#recognize`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/router.rb#L43-L100) is the matcher. `RouteSet#call` also normalizes `path_info` then calls `@router.serve`; `recognize_path` does not go through `#call` / `#serve`.

```43:100:actionpack/lib/action_dispatch/journey/router.rb
def recognize(req, &block)
  req_params  = req.path_parameters
  path_info   = req.path_info
  script_name = req.script_name

  routes = filter_routes(path_info)
  custom_routes.each { |r| routes << r if r.path.match?(path_info) }

  if req.head?
    routes = match_head_routes(routes, req)
  else
    routes.select! { |r| r.matches?(req) }
  end
  # ... precedence sort ...
  routes.each do |r|
    match_data = r.path.match(path_info)
    path_parameters = req_params.merge r.defaults
    # named captures: CGI.unescapeURIComponent if the value contains "%"
    # anchored: yield; unanchored: strip prefix into script_name, yield, restore
    req.path_parameters = req_params
  end
end
```

Material steps:

1. **GTG filter.** `simulator.memos(path_info)` returns anchored routes whose automaton accepts the path ([`gtg/simulator.rb`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/gtg/simulator.rb#L23-L58)). Unanchored / “custom” routes are appended only if `r.path.match?(path_info)` ([`Routes#partition_route`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/routes.rb#L49-L55)).
2. **Verb / request constraints.** Non-HEAD: keep `r.matches?(req)`. That is verb (`GET?`, `POST?`, …) **and** hash constraints (`host`, `protocol`, …). HEAD has a fallback: if no HEAD-specific match, temporarily set `REQUEST_METHOD` to `GET` ([`match_head_routes`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/router.rb#L115-L125)). Method tests: [`test_request_method_recognized_with_*`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L863-L869), [`test_recognize_array_of_methods`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L871-L881), PUT/DELETE on a GET|POST route → `RoutingError` ([`test_recognize_path`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L2101-L2104)).
3. **Captures + defaults.** `r.defaults` first (so omitted optionals stay as defaults, including `nil`: `/blog/2009` → `month: nil, day: nil`). Then named captures overwrite. `%` in a capture → `CGI.unescapeURIComponent` (path rules: `+` stays `+`, `%20` → space, `%2F` → `/`, `%0A` → newline). Encoding forced to UTF-8. Tests: [`test_paths_escaped`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L595-L601), [`test_default_route_should_uri_escape_pluses`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L1878-L1883), [`test_route_recognition_unescapes_path_components`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L39-L46), newline tests at [`routing_test.rb:651`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L651) / [`665`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L665).
4. **Anchored vs mount.** Anchored routes yield and leave `PATH_INFO` alone. Unanchored (engines) rewrite `script_name` / `path_info` to the unmatched suffix, yield, then restore. That restore is why [`test_assert_recognizes_doesnt_mutate_request`](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_assertions_test.rb#L188-L189) can constrain on `fullpath`.

A path that never yields, or only yields routes whose verb/constraints fail, never reaches the dispatcher check. That is a miss.

## 3. `recognize_path_with_request`: accept, recurse, or miss

```926:954:actionpack/lib/action_dispatch/routing/route_set.rb
def recognize_path_with_request(req, path, extras, raise_on_missing: true)
  @router.recognize(req) do |route, params|
    params.merge!(extras)
    params.each do |key, value|
      if value.is_a?(String)
        value = value.dup.force_encoding(Encoding::BINARY)
        params[key] = URI::RFC2396_PARSER.unescape(value)
      end
    end
    req.path_parameters = params
    app = route.app
    if app.matches?(req) && app.dispatcher?
      begin
        req.controller_class
      rescue NameError
        raise ActionController::RoutingError, "A route matches #{path.inspect}, but references missing controller: #{params[:controller].camelize}Controller"
      end
      return req.path_parameters
    elsif app.matches?(req) && app.engine?
      path_parameters = app.rack_app.routes.recognize_path_with_request(req, path, extras, raise_on_missing: false)
      return path_parameters if path_parameters
    end
  end
  raise ActionController::RoutingError, "No route matches #{path.inspect}" if raise_on_missing
end
```

**Second unescape.** Journey already decoded captures. This pass runs `URI::RFC2396_PARSER.unescape` on **every String** (captures and string defaults; not symbols/integers — see `name: :as_symbol` and `id: 1` in [`test_recognize_path`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L2097-L2100)). `+` is still not a space. `path_parameters=` then encoding-checks and may binary-encode ([`parameters.rb`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/http/parameters.rb#L67-L79)); invalid encoding is `ActionController::BadRequest`, not `RoutingError`.

**`app.matches?` is a second gate.** Journey already applied `Route#matches?` (verb + hash constraints). Here `app` is often `Mapper::Constraints` ([`mapper.rb`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/mapper.rb#L35-L56)): block/class constraints run against the request **after** extras and unescaped path params are installed. That is why a lambda can read `request.params[:name]` ([subdomain test](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L1691-L1700)) or `r.params[:use_query]` ([query-constraint assertions](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_assertions_test.rb#L122-L126)), and why hash/proc/class constraints must not leak across sibling routes ([`TestConstraintsDontLeak`](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_test.rb#L5461-L5476)).

**Dispatcher vs everything else.**

| `app` | `dispatcher?` | `engine?` | recognize_path |
|---|---|---|---|
| `RouteSet::Dispatcher` / `StaticDispatcher` | true | false | constantize, return params |
| `Constraints` wrapping a dispatcher (`SERVE`) | true | false | same, after `Constraints#matches?` |
| mounted `Rails::Engine` | false | true | recurse with `raise_on_missing: false` |
| redirect / Rack app (`CALL`) | false | false | skip; try next route |

Engine miss does not fail the parent: `/shelf/foo` falls through to the app route ([`test_assert_recognizes_continue_to_recognize_after_it_tried_engines`](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_assertions_test.rb#L184-L185)). Engine hit returns the nested params ([`test_assert_recognizes_with_engine`](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_assertions_test.rb#L137-L139)).

## Edge-case results

| Input / case | Observable result |
|---|---|
| Relative path `/pages/show/10` or `/pages/show/10/` | `{ controller:, action:, … }` after normalize |
| `nil` | treated as `/` |
| Absolute `http://subdomain.example.org/page/mypage` | same params; host available to constraints |
| `/articles?page=1` | path recognized; **`page` not in returned hash** unless passed as `extras:` |
| `extras: { page: "1" }` | merged into returned path params; visible to constraints |
| `%20` / `%2B` / `+` / `%0A` in a segment | space / `+` / `+` / newline in params |
| Downcased `%c5%a0…` unicode | still matches (normalize uppercases `%xx`) |
| `method:` not in `via:` | `RoutingError` `No route matches …` |
| No path match / failed regexp / failed block constraint | `RoutingError` `No route matches …` |
| URI parse failure | `RoutingError` with the `URI::InvalidURIError` message |
| Dispatcher whose controller is missing | `RoutingError` `A route matches … missing controller: …Controller` |
| Same missing controller via `#call` | `ActionDispatch::MissingController` |
| Mounted engine recognizes | nested engine `path_parameters` |
| Engine prefix matches, inner miss, later app route | later app params |
| Redirect / Rack endpoint only | `No route matches` (not a dispatcher) |
| Invalid encoding in a path param | `ActionController::BadRequest` from `path_parameters=` |

`path` in both error messages is the string passed into `recognize_path_with_request` (post-normalize for relative paths; original URL for absolute), not necessarily `PATH_INFO`.
