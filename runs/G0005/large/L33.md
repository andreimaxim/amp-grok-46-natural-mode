Dirty keeps two tracker slots. Pending edits live in `@mutations_from_database`. The last applied cycle lives in `@mutations_before_last_save`. The generated `*_changed?` / `*_was` / `*_change` methods read the pending slot; `*_previously_changed?` / `*_previously_was` / `*_previous_change` read the last-applied slot.

```diagram
                    *_will_change! / assignment
                              │
                              ▼
┌─────────────────────────────┐
│ @mutations_from_database    │  changed?, changes, *_was
│ pending cycle               │
└──────────────┳──────────────┘
               ┃ changes_applied
               ▼
┌─────────────────────────────┐
│ @mutations_before_last_save │  previous_changes, *_previously_was
│ last applied cycle          │
└─────────────────────────────┘
               │
               │ clear_changes_information → both slots nil
               │ restore_attributes → rewrite values, forget pending only
```

Two tracker classes implement that contract. Models with `@attributes` ([`activemodel/lib/active_model/dirty.rb`](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L387-L393)) get `AttributeMutationTracker`. Plain `include ActiveModel::Dirty` models get `ForcedMutationTracker`. Until the first save, `@mutations_before_last_save` is `NullMutationTracker`.

`activemodel/test/cases/dirty_test.rb` and `activemodel/test/cases/attributes_dirty_test.rb` both passed (`45 runs, 156 assertions, 0 failures`). Stage values below also come from a probe against this checkout.

## The three methods

**`changes_applied`** ([`dirty.rb` L272–276](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L272-L276)) is the persist/commit step. It returns `nil`.

```272:276:activemodel/lib/active_model/dirty.rb
    def changes_applied
      unless defined?(@attributes)
        mutations_from_database.finalize_changes
      end
      @mutations_before_last_save = mutations_from_database
      forget_attribute_assignments
      @mutations_from_database = nil
    end
```

Call tree:

```text
changes_applied
  ForcedMutationTracker#finalize_changes   # only without @attributes
    @finalized_changes = changes           # freeze [old, new] pairs
  @mutations_before_last_save = pending tracker
  forget_attribute_assignments             # remap @attributes, no-op on Forced
  @mutations_from_database = nil           # next read builds a fresh tracker
```

`finalize_changes` exists so later in-place mutation of a live value cannot rewrite `previous_changes`. After this, `changed?` is false and `previous_changes` is the hash that `changes` held a moment earlier.

**`restore_attributes`** ([`dirty.rb` L320–322, L417–422](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L320-L322)) rolls pending values back. Default argument is `changed`. It returns that name list. It does not touch `@mutations_before_last_save`.

```320:322:activemodel/lib/active_model/dirty.rb
    def restore_attributes(attr_names = changed)
      attr_names.each { |attr_name| restore_attribute!(attr_name) }
    end
```

```417:422:activemodel/lib/active_model/dirty.rb
      def restore_attribute!(attr_name)
        attr_name = attr_name.to_s
        if attribute_changed?(attr_name)
          __send__("#{attr_name}=", attribute_was(attr_name))
          clear_attribute_change(attr_name)
        end
      end
```

It writes through the public setter (which may call `*_will_change!` again), then `forget_change` so the attribute is clean even if the setter re-marked it.

**`clear_changes_information`** ([`dirty.rb` L325–329](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L325-L329)) is a full tracker wipe. It returns `nil`. Attribute values stay as they are.

```325:329:activemodel/lib/active_model/dirty.rb
    def clear_changes_information
      @mutations_before_last_save = nil
      forget_attribute_assignments
      @mutations_from_database = nil
    end
```

After this, both `changes` and `previous_changes` are empty hashes (`NullMutationTracker` for the previous slot). That is the `reload!` contract in the module docs.

## Lifecycle: ForcedMutationTracker (`dirty_test.rb`)

This is the path the module docs describe. Setters must call `*_will_change!`. `ForcedMutationTracker#force_change` clones the current value once and will not overwrite that snapshot ([`attribute_mutation_tracker.rb` L120–122, L140–147](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L120-L122)).

Start: `name = +"Yam"`, `color = "red"`.

**1. In-place mutate without `*_will_change!`**

`name.replace("Hadad")` — tracker stays empty. Observed:

- `changed?` → `false`
- `changes` → `{}`
- `previous_changes` → `{}`
- `name_was` → `"Hadad"` (live value; there is no snapshot)
- `name_changed?` → `false`

Same assertion in [`dirty_test.rb` L93–98](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L93-L98).

**2. `name_will_change!` then in-place mutate**

`name_will_change!` clones `"Yam"` into `forced_changes`. Then `name.replace("Baal")`. Observed:

- `changed?` → `true`
- `changes` → `{ "name" => ["Yam", "Baal"] }`
- `name_change` → `["Yam", "Baal"]`
- `name_was` → `"Yam"`
- `previous_changes` → `{}`
- `name_previously_was` → `nil`

Right after `will_change!` and before the replace, `changes` is `{ "name" => ["Yam", "Yam"] }` — the docs’ `[old, old]` form ([`dirty.rb` L118–126](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L118-L126), [`dirty_test.rb` L99–101](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L99-L101)).

**3. `changes_applied` / `save`**

Returns `nil`. Pending tracker moves to the previous slot; a new empty Forced tracker is built on next read. Observed:

- `changed?` → `false`
- `changes` → `{}`
- `previous_changes` → `{ "name" => ["Yam", "Baal"] }`
- `name_was` → `"Baal"` (pending original is now the live value)
- `name_previously_changed?` → `true`
- `name_previously_was` → `"Yam"`
- `name_previous_change` → `["Yam", "Baal"]`

[`dirty_test.rb` L121–136, L148–151](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L121-L136).

**4. Second edit** (`name = "Bill"`, `color = "blue"`)

- `changed?` → `true`
- `changes` → `{ "name" => ["Baal", "Bill"], "color" => ["red", "blue"] }`
- `name_was` → `"Baal"`
- `color_was` → `"red"`
- `previous_changes` still `{ "name" => ["Yam", "Baal"] }`
- `name_previously_was` still `"Yam"`

A later assignment does not rewrite the previous cycle ([`dirty_test.rb` L138–146, L164–174](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L138-L146)). Multiple assignments in one cycle keep the first original (`name_was` stays `"Otto"` in [`dirty_test.rb` L176–188](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L176-L188)).

**5. Restore all**

`restore_attributes` returns `["name", "color"]` (order is `changed`). Values go back to `"Baal"` / `"red"`. `changed?` is `false`. `previous_changes` is unchanged.

[`dirty_test.rb` L211–222](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L211-L222).

## Edge cases

**Attribute omitted from `restore_attributes`**

After `name = "Bob"`, `color = "White"`, `restore_attributes(["name"])` returns `["name"]`. Observed / tested:

- `name` → `"Dmitry"` (or `"Baal"` in the probe’s longer run), `name_changed?` → `false`
- `color` stays `"White"`, `color_changed?` → `true`
- `changed?` → `true`
- `changes` → `{ "color" => [<saved color>, "White"] }`
- `previous_changes` untouched

[`dirty_test.rb` L225–235](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L225-L235), same in [`attributes_dirty_test.rb` L174–184](file:///home/user/workspace/repo/activemodel/test/cases/attributes_dirty_test.rb#L174-L184).

**Changed back to the original value**

Behavior splits by tracker.

On **ForcedMutationTracker**, `force_change` never clears itself, and `changed?` is “key present in `forced_changes`”, not “value differs”. After `name` went `Baal → Bill → Baal` with an equality-guarded setter:

- `name_changed?` → `true`
- `name_change` → `["Baal", "Baal"]`
- `changed` still includes `"name"`

The setter never calls `forget_change`. Only `restore_*!`, `clear_*_change`, `changes_applied`, or `clear_changes_information` drop the mark. The color setter in the test (`unless val == @color`) avoids marking when you assign the *same* value while clean ([`dirty_test.rb` L111–119](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L111-L119)); that is not the same as un-marking a value that already left and came back.

On **AttributeMutationTracker**, assignment is `Attribute#changed?` → `changed_from_assignment? || changed_in_place?` ([`attribute.rb` L66–76](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute.rb#L66-L76)). Type comparison is `old_value != new_value`. After `Hadad → Bill → Hadad`:

- `name_changed?` → `false`
- `name_change` → `nil`
- `changed` → `["color"]` only
- `changes` → `{ "color" => ["red", "blue"] }`

**Mutable values and `*_will_change!`**

Forced path cannot see `String#replace` / `<<` unless you snapshot first. `clone_value` copies duplicable objects so the clone stays `"Yam"` while the live string becomes `"Baal"`.

Attribute path with `attribute :name, :string` does **not** need `*_will_change!`. `Type::String#changed_in_place?` compares the raw original to the mutated string ([`type/string.rb` L16–19](file:///home/user/workspace/repo/activemodel/lib/active_model/type/string.rb#L16-L19)). [`attributes_dirty_test.rb` L71–75](file:///home/user/workspace/repo/activemodel/test/cases/attributes_dirty_test.rb#L71-L75): after save, `name.replace("Hadad")` alone makes `name_changed?` true. The module docs call that out: Active Record / Attributes detect in-place mutation; plain Dirty does not ([`dirty.rb` L118–126](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L118-L126)).

**`clear_changes_information`**

From [`dirty_test.rb` L196–208](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L196-L208), after save then a new edit:

Before: `previous_changes["name"] == [nil, "Dmitry"]`, `changed_attributes["name"] == "Dmitry"`.

After: both hashes empty. Probe also showed the live value stays `"Bob"`, `name_was` becomes `"Bob"`, and `name_previously_was` becomes `nil`. Trackers are discarded, not replayed.

## Forced vs Attributes, one more observable

After `changes_applied`, an attribute that was **not** in that cycle has different `*_previously_was` behavior:

- Forced: `original_value` for a non-forced name is `_read_attribute` on the live model ([`attribute_mutation_tracker.rb` L113–118](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L113-L118)). A later `color = "blue"` makes `color_previously_was` follow `"blue"` even though `color` was never in `previous_changes`.
- Attributes: the previous tracker still holds the old `AttributeSet`, so `color_previously_was` stays `"red"`.

`previous_changes` itself only includes names that actually changed in that cycle on both paths.

The dirty tests do not assert `*_previously_was` for unchanged attributes; that last split is from the probe on this checkout.
