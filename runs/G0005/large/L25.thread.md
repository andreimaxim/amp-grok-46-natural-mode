## Assistant

`expect` is permit-then-require with two extra constraints: it treats a nested filter as a hash unless you write an explicit array `[[...]]`, and it never fires unpermitted-parameter logging/raising. `permit` plus `require` is the same pipeline with those constraints off, so a string or array in a hash slot can become a `NoMethodError` or a quietly accepted hash/array mix-up.

```text
expect(*filters)
  permit_filters(filters, on_unpermitted: nil, explicit_arrays: true)
    Symbol/String  → permitted_scalar_filter
    Hash           → hash_filter → permit_value
      []      → array of scalars
      {}      → any permitted structure
      [[…]]   → array of hashes / numeric-key hashes
      else    → hash only   (because explicit_arrays: true)
    unpermitted_parameters!(on_unpermitted: nil)   # no-op
    permit!
  require(root keys from filters)
  unwrap if exactly one root key

permit(*filters)
  permit_filters(..., on_unpermitted: config, explicit_arrays: false)
    same dispatch, but non-explicit filters call permit_hash_or_array
  returns the filtered wrapper; does not require; does not unwrap
```

### What `expect` actually does

[`expect`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L779-L787) is three steps:

```779:787:actionpack/lib/action_controller/metal/strong_parameters.rb
    def expect(*filters)
      params = permit_filters(filters)
      keys = filters.flatten.flat_map { |f| f.is_a?(Hash) ? f.keys : f }
      values = params.require(keys)
      values.size == 1 ? values.first : values
    end
```

1. Filter with [`permit_filters`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1189-L1212). The defaults matter: `explicit_arrays: true`, `on_unpermitted: nil`.
2. Require every root key named by the filters, in filter order, via [`require`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L526-L538). `require` raises [`ActionController::ParameterMissing`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L27-L47) unless the value is `present?` or `false`. Empty hash, empty array, `nil`, and `""` all fail. `false` and `0` pass.
3. If that list has one element, return it; otherwise return the array.

[`permit`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L675-L677) calls the same `permit_filters` with `explicit_arrays: false` and `on_unpermitted: action_on_unpermitted_parameters`. It returns the filtered `Parameters` wrapper and stops. The usual Rails form `params.permit(person: [...]).require(:person)` is therefore “lenient permit, then unwrap one key.” `params.require(:person).permit(...)` unwraps first; if `:person` is a String or Array, `permit` is `NoMethodError`.

`expect!` is `expect` with `ParameterMissing` rewritten as [`ExpectedParameterMissing`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L51-L55) ([`expect!`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L793-L798); tests in [parameters_expect_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_expect_test.rb#L47-L56)).

### Filter dispatch

[`permit_filters`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1189-L1212) walks `filters.flatten`. A Symbol/String goes through [`permitted_scalar_filter`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1421-L1436) (value must be a `PERMITTED_SCALAR_TYPES` object). A Hash goes through [`hash_filter`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1442-L1451), which slices to declared keys and calls [`permit_value`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1454-L1465):

```1454:1465:actionpack/lib/action_controller/metal/strong_parameters.rb
      def permit_value(value, filter, on_unpermitted:,  explicit_arrays:)
        if filter == EMPTY_ARRAY # Declaration { comment_ids: [] }.
          permit_array_of_scalars(value)
        elsif filter == EMPTY_HASH # Declaration { preferences: {} }.
          permit_hash(value, filter, on_unpermitted:, explicit_arrays:)
        elsif array_filter?(filter) # Declaration { comments: [[:text]] }
          permit_array_of_hashes(value, filter.first, on_unpermitted:, explicit_arrays:)
        elsif explicit_arrays # ... only allows hash value
          permit_hash(value, filter, on_unpermitted:, explicit_arrays:)
        elsif non_scalar?(value)
          permit_hash_or_array(value, filter, on_unpermitted:, explicit_arrays:)
        end
      end
```

[`array_filter?`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1349-L1351) is the explicit-array branch: the filter must be a one-element array whose only element is itself an array (`[[:flavor]]`, not `[:flavor]`).

[`each_array_element`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1354-L1362) then accepts two input shapes:

- a Ruby `Array` of `Parameters` (`.grep(Parameters).filter_map`)
- a `Parameters` object whose keys all look like `"0"`, `"1"`, `"-1"` and whose values are hashes, unless the filter itself names numeric keys ([`nested_attribute?`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L268-L270), [`specify_numeric_keys?`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L1325-L1329))

If filtering drops a key, `require` sees it as missing and raises `ParameterMissing`. That is how `expect` turns a type mismatch into a 400 rather than a 500.

### Multiple filters and return arity

Root keys are collected with `filters.flatten.flat_map { |f| f.is_a?(Hash) ? f.keys : f }`. One key unwraps; two or more return an array, in that key order.

| Call | Observed return |
|---|---|
| `expect(:a)` on `{a: 1, b: 2}` | `1` (Integer, unwrapped) |
| `expect(:a, :b)` or `expect([:a, :b])` on `{a: 1, b: 2}` | `[1, 2]` |
| `expect(person: [:age])` | the inner `Parameters`, `permitted: true` |
| `expect(subject: [:name], object: [:pie])` | `[Parameters, Parameters]` — one Hash argument, two keys |
| `expect(:a, :b)` on `{a: 1}` | `ParameterMissing` for `:b` |
| `expect(person: :name).expect(:name)` on `{person: {name: "David"}}` | `"David"` |

Covered by [array of key / array of keys](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_expect_test.rb#L101-L114), [keys to arrays: hash key order](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_expect_test.rb#L38-L44), [missing / non-scalar extra key](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_expect_test.rb#L226-L245), and [chain of keys](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_expect_test.rb#L89-L96).

`permit(:a, :b)` never unwraps: it returns `Parameters { "a" => 1, "b" => 2 } permitted: true`. `require([:a, :b])` returns `[value_a, value_b]` without filtering.

### Concrete cases

#### 1. Scalar versus hash

Input `{ user: "hack" }`.

- `expect(user: [:name, pets: [[:name]]])` → `ActionController::ParameterMissing: user`. `permit_hash` requires a `Parameters` value; the string is dropped; `require(:user)` fails. Same idea as [key to non-scalar](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_expect_test.rb#L159-L179).
- `require(:user).permit(...)` → `NoMethodError: undefined method 'permit' for an instance of String`. `require` returns the raw String.

Input `{ comment: { text: "hello" } }`.

- `expect(comment: [:text])` → `#<Parameters {"text"=>"hello"} permitted: true>` (unwrapped).
- `require(:comment).permit(:text)` → the same inner `Parameters`, `permitted: true`.

Input `{ comment: [{ text: "hello" }, { text: "world" }] }` with a hash filter `comment: [:text]`.

- `expect` → `ParameterMissing: comment`. `explicit_arrays: true` takes `permit_hash`; an Array is not `Parameters`. Documented on [`expect`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/strong_parameters.rb#L706-L710) and tested as [key to array of keys: raises when params is an array](file:///home/user/workspace/repo/actionpack/test/controller/parameters/parameters_expect_test.rb#L47-L56).
- `permit(comment: [:text]).require(:comment)` → `Array` of two permitted `Parameters`. `explicit_arrays: false` takes `permit_hash_or_array`.
- `require(:comment).permit(:text)` → `NoMethodError` on Array.

Input `{ user: { name: "Martin", pets: { name: "hack" } } }` with `pets: [[:name]]` (explicit array) vs `pets: [:name]` (hash-or-array).

- `expect(user: [:name, pets: [[:name]]])` → `{ "name" => "Martin" }` permitted, `[:pets]` is `nil`. The pets hash is not an array and its key `"name"` is not numeric, so `each_array_element` returns nil and the key is omitted.
- `require(:user).permit(:name, pets: [:name])` → `{ "name" => "Martin", "pets" => { "name" => "hack" } }` permitted. `permit_hash_or_array` accepts the hash.

That is the type-confusion `expect` was added to close: `permit` will keep a hash where an array of records was declared; `expect` drops it.

### Side-by-side

`permit` + `require` and `expect` share `permit_filters`, `hash_filter`, and `permit_value`. They diverge on three observables:

- **Type:** `expect` (`explicit_arrays: true`) accepts a hash filter only as a hash, and an array of records only as `[[...]]`. `permit` (`explicit_arrays: false`) lets `[:name]` match a hash or an array or numeric-key hashes.
- **Failure class:** type/presence problems in `expect` are `ParameterMissing` (or `ExpectedParameterMissing` from `expect!`). `require` then `permit` is `NoMethodError` when the required value is not Parameters.
- **Return:** `expect` requires every named root and unwraps a single one, so a scalar filter returns a scalar. `permit` returns a permitted wrapper that still has the root key; `require` unwraps one key and does not filter.

Unpermitted keys are a fourth divergence: they are silent under `expect` and subject to `action_on_unpermitted_parameters` under `permit`.
