## Pipeline that defines the contract

```text
Content#to_plain_text
  render_attachments(with_full_attributes: false, &:to_plain_text)
    Fragment#replace(Attachment.tag_name)
      sanitize node["content"] on a dup
      yield Attachment.from_node(node)   # no with_full_attributes
    Content.new(replaced, canonicalize: false)
  .fragment.to_plain_text
    PlainTextConversion.node_to_plain_text
```

Two substitutions happen, in order:

1. Each `action-text-attachment` is replaced by `Attachment#to_plain_text`, then that string is parsed as HTML (`node.replace(replacement.to_s)` in [`Fragment#replace`](file:///home/user/workspace/repo/actiontext/lib/action_text/fragment.rb#L41-L47)).
2. The resulting tree is walked by [`PlainTextConversion`](file:///home/user/workspace/repo/actiontext/lib/action_text/plain_text_conversion.rb#L9-L128).

`#to_plain_text` is an observer. `#render_attachments` always returns a new `Content`. Canonical HTML on the original must not change.

## Observable contract

**Markup.** `p`/`h1`–`h6`/`blockquote`/`ul`/`ol` end with `"\n\n"`; `div` with `"\n"`; `br` and `li` with `"\n"`; trailing newlines stripped at the root. `ul` bullets are `"• "`; `ol` is `"1. "` (1-based among element siblings). Nested lists indent two spaces per extra `ul`/`ol` ancestor. `figcaption` becomes `[…]`. `script` and `style` contribute `""`. Other elements concatenate children. The result is a normal String, not `html_safe?`.

**Entities.** Named/numeric entities are decoded in the plain-text string. Stored HTML keeps the entity form. Probes:

- `"&lt;script&gt;alert()&lt;/script&gt;"` → `"<script>alert()</script>"`; `to_html` stayed `"&lt;script&gt;alert()&lt;/script&gt;"`
- `"Tom &amp; Jerry &copy; 2024"` → `"Tom & Jerry © 2024"`
- `"a&nbsp;b"` → `"a\u00A0b"` (bytes `[97, 194, 160, 98]`)
- `"&#60;b&#62;"` → `"<b>"`; `to_html` stayed `"&lt;b&gt;"`

**Script-like text vs script nodes.** A real `<script>`/`<style>` node is omitted; encoded script text is decoded and kept. `"<div onclick='action()'>safe<script>unsafe</script></div>"` → `"safe"`. `to_html` still contains the `<script>` and `onclick` (plain text does not sanitize stored HTML).

**Attachment captions and filenames.** `to_plain_text` always passes `with_full_attributes: false`. Caption vs filename still comes from the attachable object, not from merging node attributes:

| Attachable | Caption present | Caption absent |
|---|---|---|
| `ActiveStorage::Blob` | `"[Vroom vroom]"` | `"[racecar.jpg]"` |
| `RemoteImage` | `"[Captioned]"` / `"[A photo]"` | `"[Image]"` |
| `MissingAttachable` | `"☒"` (caption ignored) | `"☒"` |
| `Person` / `Page` (no `attachable_plain_text_representation`) | `"Friend"` / `"Home"` (no brackets) | `""` |
| `ContentAttachment` | inner fragment re-parsed as HTML, then converted | same |

Blob `filename="override.jpg"` on the node does not override: still `"[racecar.jpg]"`. Caption wins over filename: `"[Cap]"`.

**Missing attachables.** `"☒"` for invalid sgid, destroyed blob (with or without caption), non-URL `image/*` (`url="image.png"`), and caption-only / filename-only nodes with no sgid. Inner HTML of those nodes is irrelevant after canonical minification.

**Remote images.** `content-type` matching `^image(/.+|$)` plus a URI `url` → `RemoteImage`. Caption or `"Image"`. Surrounding text and inter-attachment whitespace are kept: `"[A] [B]"` vs `"[A][B]"`.

**Duplicates.** Each node is converted independently and concatenated with no extra separator: `"[racecar.jpg][racecar.jpg]"`; `"Hello [racecar.jpg] and [Again]"`.

**Galleries.** Canonicalize unwraps `.attachment-gallery` to `<div>…</div>` and keeps children. Plain text is the concatenation of the children. Probes: two blobs `"[racecar.jpg][report.txt]"`; captions `"[One][Two]"`; whitespace inside the gallery `"\n  [racecar.jpg]\n  [report.txt]"`; gallery in a blockquote `"“[One][Two]”"`.

**Nested attachment nodes.** Default canonicalize minifies attachment inner HTML to empty ([`Minification`](file:///home/user/workspace/repo/actiontext/lib/action_text/attachments/minification.rb#L11-L16)), so a nested attachment never reaches plain text. `"<action-text-attachment sgid=\"123\"><div>HTML</div>…>"` → `to_html` empty child, plain `"☒"`. Nested blob+inner attachment → one attachment, `"[racecar.jpg]"`. With `canonicalize: false`, `find_all` sees both nodes; replacing the outer with `"☒"` drops the inner, so the observable is still `"☒"`.

**`with_full_attributes: false`.** For blob *plain text*, false and true both printed `"[racecar.jpg]"` because filename comes from the attachable method, not node attributes. The flag *does* change HTML if the block returns the attachment/node: default/`true` writes `content-type`, `filename`, `filesize`, `previewable` onto the replacement tag; `false` leaves the original sgid-only tag. `#to_plain_text` uses false so it does not persist those attributes on the original, and the replacement is the plain-text string rather than the node.

**Replacement is HTML.** `Attachment#to_plain_text` of a caption `"<script>"` is `"[<script>]"`. After `replace`, `Content#to_plain_text` printed `"["`. Caption `"x<y>z"` printed `"[xz]"`. `&amp;` in a caption printed `"[Tom & Jerry]"` because `&` is not a tag. `ContentAttachment` of `"<p>abc</p>"` printed `"abc"`; of `"<script>alert(1)</script>"` printed `"alert(1)"` (script node dropped on the second pass).

**Non-mutation.** Every probe left the original `to_html` / `to_s` / `inspect` unchanged. `render_attachments` returned a new `Content` with a different fragment. Returning the same node object skips `node.replace` ([`fragment.rb` L45](file:///home/user/workspace/repo/actiontext/lib/action_text/fragment.rb#L45)). Sanitizing `content=""` / `<script></script>` / `onerror=alert` happens on the dup only. Repeat `to_plain_text` is stable.

## Assertion categories

Pin these, not internals of `BottomUpReducer`:

1. **Exact `to_plain_text` string** — including newlines, `•`, `“”`, `☒`, spaces between attachments, and decoded entities. Use `assert_equal`, not `assert_includes`.
2. **`html_safe? == false`** on the result, including the entity-decoded script case.
3. **Canonical HTML identity** — `to_html` before vs after `to_plain_text` and after `render_attachments` on a different object. Also `to_s` (layout HTML) and `inspect`.
4. **`render_attachments` product** — class `ActionText::Content`; `canonicalize: false` (replacement text/tags survive; see markdown test); original fragment object_id differs; replacement HTML equals `block.call.to_s` parsed as HTML.
5. **`with_full_attributes` HTML delta** — `true`/default adds blob metadata attributes to the returned node; `false` does not; neither mutates the original; *plain text* of a live blob is the same in both modes.
6. **Attachable class + count** — `attachments.size`, `attachable.class`, `gallery_attachments.size` as witnesses that the input was classified correctly, not as a substitute for the plain-text string.
7. **Repeatability** — `content.to_plain_text == content.to_plain_text`.
8. **Custom tag name** — `ActionText::Attachment.tag_name` still drives `replace` / `find_all`.

## Non-mutation checks (required on every attachment case)

For each fixture `content = ActionText::Content.new(html)`:

1. `before = content.to_html` (and once per file, `to_s` / `inspect`).
2. Call `content.to_plain_text` and/or `content.render_attachments(...)`.
3. `assert_equal before, content.to_html`.
4. `assert_not_same` the returned content’s fragment and the original fragment when the block does not return the identical node.
5. Assert the original still contains `action-text-attachment` (or the custom tag) when the input did — `#to_plain_text` must not minify/canonicalize the receiver.
6. If the block returns the same `attachment.node`, `rendered.to_html == content.to_html` and no replacement occurred.

Gallery canonicalize is allowed *at construction* (`to_html` already unwrapped in [`content_test.rb` L125–L146](file:///home/user/workspace/repo/actiontext/test/unit/content_test.rb#L125-L146)). The invariant is: `#to_plain_text` / `#render_attachments` do not change that already-canonical HTML.
