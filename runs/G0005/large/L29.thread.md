The public contract is the HTTP exchange: validators on the way out, `If-None-Match` / `If-Modified-Since` on the way in, then status, body, `ETag`, `Last-Modified`, and `Cache-Control`. `fresh_when` / `stale?` only write those validators and then ask `request.fresh?(response)`. Existing Action Pack tests plus a temporary controller probe (deleted after the run) pin that contract.

### Current path

```text
action
  fresh_when / stale?
    drop cache_control[:no_store]
    derive weak/strong ETag + Last-Modified
    merge public / cache_control
    request.fresh?(response)
      etag_matches?(response.etag)      # If-None-Match
      not_modified?(response.last_modified)  # If-Modified-Since
    if fresh: head :not_modified        # 304, empty body
  stale? then returns !request.fresh?(response)
response.before_committed
  merge Cache-Control
  default max-age=0, private, must-revalidate if ETag or Last-Modified and none set
```

`ActionController::Base` includes [`ConditionalGet`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/conditional_get.rb), [`EtagWithTemplateDigest`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/etag_with_template_digest.rb), and [`EtagWithFlash`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/etag_with_flash.rb). `ActionController::API` includes only `ConditionalGet`. Freshness evaluation lives on the request in [`ActionDispatch::Http::Cache::Request#fresh?`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/http/cache.rb); header emission lives on the response in the same file.

Observed contract, not internals:

- **Validators.** `etag:` / `weak_etag:` / a record emit a weak `ETag` (`W/"…"`). `strong_etag:` emits a strong `ETag` (`"…"`). A record also sets `Last-Modified` from `updated_at`; a collection uses `maximum(:updated_at)`. Matching is exact token equality, including the `W/` prefix. A weak `If-None-Match` does not satisfy a strong response `ETag`, and a strong `If-None-Match` does not satisfy a weak one. `If-None-Match: *` matches any non-nil response `ETag`.
- **304.** `head :not_modified` if `request.fresh?(response)`. Status 304, empty body, validators still present. `stale?` is `fresh_when` plus `!request.fresh?(response)`, so the expensive block runs only when the request is stale.
- **No method gate.** Matching `If-None-Match` yields 304 on GET, HEAD, QUERY, POST, and PUT. That is Rails’ current contract; RFC 9110 would use 412 on unsafe methods. Preserve 304.
- **Both headers.** `ActionDispatch::Http::Cache::Request.strict_freshness` (false in isolated Action Pack tests; true from Rails 8.0 `load_defaults`): when false, both conditions must hold; when true, `If-None-Match` wins and `If-Modified-Since` is ignored if `If-None-Match` is present.
- **Subsecond `Last-Modified`.** Assignment uses `Time#httpdate`, so microseconds drop. `Time.utc(2024,6,15,12,0,0,250000)` is sent as `Sat, 15 Jun 2024 12:00:00 GMT`. An `If-Modified-Since` of that HTTP-date is fresh (`>=` after truncation).
- **Cache-Control.** Default after a validator: `max-age=0, private, must-revalidate`. `public: true` with no other directives: `public`. `fresh_when` deletes `no_store`; a later `no_store` wins (`Cache-Control: no-store`, `ETag` still set).
- **Template ETags.** On `ActionController::Base`, the current action’s digest is mixed into the ETag unless `template: false`. Changing the fixture template changes the ETag. API controllers do not include that etagger.

### Strategy

Keep tests at the HTTP boundary. One controller fixture per concern is enough; do not assert `combine_etags`, digest construction, etagger arrays, or how many times `fresh?` is called (`stale?` currently calls it twice).

**Level 1 (high leverage):** `ActionController::TestCase` against a tiny controller. Assert status, body blank-or-not, `ETag` / `Last-Modified` / `Cache-Control` strings, and a side-effect counter inside the `stale?` block.

**Level 2 (thin):** `ActionDispatch::Request#fresh?` / `#etag_matches?` / `#not_modified?` for header-combination tables that would be noisy as full controller cases. Still public request API, not private helpers.

**Do not use:** `process_action.action_controller` as a freshness signal (it fires on 304). Do not hard-code digest hex except as “same as previous response”. Round-trip: first request captures `ETag` / `Last-Modified`, second request sends them back.

### How this catches drift without pinning internals

Assert only what a client can see or what the `stale?` block did.

| Drift | Row that fails |
|---|---|
| Weak/strong prefix swapped or comparison becomes RFC-weak | 2–5 |
| `*` no longer matches, or matches a missing ETag | 6–8 |
| Precedence flipped or AND vs ETag-only | 9–12 |
| Subseconds kept or `>=` becomes `>` | 13–14 |
| Method gate added (e.g. 412 on POST, skip HEAD) | 15–16 |
| Default `Cache-Control` or `public` / `no_store` order | 17–20 |
| Template digest dropped or not busted | 21–23 |
| `stale?` block runs on 304, or `fresh_when` no longer 304s | 24–25 |
| 304 gains a body, or validators disappear on 304 | 2, 4, 6, 15 |

Do not assert digest hex, `combine_etags` array shape, etagger registration, or `fresh?` call counts. Round-trip equality of `ETag` is the oracle; if hashing or etagger folding changes but the second request with the first response’s `ETag` still 304s, the HTTP contract held.

Keep `strict_freshness` rows parameterized. A refactor that “fixes” RFC 7232 §6 by always preferring ETag would pass Rails 8 defaults and break pre-8.0 apps.
