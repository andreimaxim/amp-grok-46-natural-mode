The contract to preserve is loader ownership, reload vs once lifetime, `$LOAD_PATH` membership, freeze-after-init, and eager-load membership — not the private concatenation order inside `_all_*`.

## What “no externally observable change” means

Path assembly is an internal reduction. The public result is which directories Zeitwerk manages, which loader owns them, whether they eager-load, whether they appear on `$LOAD_PATH`, and what happens to constants across boot and reload.

Do **not** treat these as the contract:

- `Rails::Engine#_all_autoload_paths` / `#_all_load_paths` memoization
- exact `Array` order of `ActiveSupport::Dependencies.autoload_paths` after engine `unshift`
- `config.all_*` concatenation order (`custom + paths.*`)
- whether `uniq` happens per-engine, globally, or both

Those are implementation. Order is only observable when two files share a relative name (`require`) or when Zeitwerk rejects nested/duplicate roots.

```text
each Engine + Application
  set_load_path          → $LOAD_PATH.unshift(reversed load paths); uniq!
  set_autoload_paths     → AS::Dependencies.autoload{,_once}_paths.unshift
                         → freeze config.autoload{,_once}_paths
  set_eager_load_paths   → AS::Dependencies._eager_load_paths.merge
                         → freeze config.eager_load_paths
Bootstrap
  setup_once_autoloader  → freeze autoload_once_paths; once.push_dir; once.setup
Finisher
  setup_main_autoloader  → freeze autoload_paths; main.push_dir; maybe enable_reloading
  run_prepare_callbacks  → reloader.prepare!
  eager_load!            → Zeitwerk::Loader.eager_load_all if config.eager_load
  set_clear_dependencies_hook → main reload only
```

Sources: [engine/configuration.rb](file:///home/user/workspace/repo/railties/lib/rails/engine/configuration.rb#L121-L135), [engine.rb initializers](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L596-L614), [engine.rb assembly](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L749-L769), [bootstrap.rb](file:///home/user/workspace/repo/railties/lib/rails/application/bootstrap.rb#L103-L121), [finisher.rb](file:///home/user/workspace/repo/railties/lib/rails/application/finisher.rb#L18-L85).

## Invariants to freeze as oracles

### I1. Configuration contribution (per engine, including the application)

From [Engine::Configuration](file:///home/user/workspace/repo/railties/lib/rails/engine/configuration.rb#L121-L135):

- `all_autoload_paths` includes every custom `config.autoload_paths` entry **and** every existent directory from `config.paths` marked `autoload:`
- `all_autoload_once_paths` includes custom `autoload_once_paths` **and** `paths` marked `autoload_once:`
- `all_eager_load_paths` includes custom `eager_load_paths` **and** `paths` marked `eager_load:`
- Default `app` is eager-load; `lib`/`vendor` are load-path only; `test/mailers/previews` is autoload only
- `app/assets` and `config.javascript_path` are excluded from autoload
- Reading `config.autoload_paths` / `autoload_once_paths` / `eager_load_paths` must not freeze the path registry (issue 49629)

`all_*` are `:nodoc:`. Probe via `ActiveSupport::Dependencies.*`, `Rails.autoloaders.*.dirs`, and constant loading — not by calling `all_*` in new tests.

### I2. Main vs once partition (per engine, then globally)

From [`_all_autoload_paths`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L753-L760) and [Dependencies](file:///home/user/workspace/repo/activesupport/lib/active_support/dependencies.rb#L44-L55):

- A path in `autoload_once_paths` is **removed** from that engine’s main autoload list even if it is also in `autoload_paths` or `eager_load_paths`
- Main loader roots ⊆ existing directories in `AS::Dependencies.autoload_paths`
- Once loader roots ⊆ existing directories in `AS::Dependencies.autoload_once_paths`
- Non-directories are skipped (`push_dir` only for `File.directory?`)
- User `push_dir` with a custom namespace is not overwritten (`already_configured_dirs`)
- Duplicate path strings are pushed once (`uniq` before `push_dir`)

Observable: `Rails.autoloaders.main.dirs` vs `once.dirs` membership; `Zeitwerk::Loader#cpath_expected_at` / loading a constant from that file.

### I3. Eager-load set is independent of the main/once partition

From [`set_eager_load_paths`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L611-L614) and [`eager_load?`](file:///home/user/workspace/repo/activesupport/lib/active_support/dependencies.rb#L99-L101):

- Every `all_eager_load_paths` entry is in `AS::Dependencies._eager_load_paths` (a `Set`)
- A path in **both** once and eager: owned by **once**, still eager-loaded in production
- A path in once but **not** eager: `once.do_not_eager_load`; production boot does not define its constants until referenced
- A path in main but not eager: `main.do_not_eager_load`
- `Rails.application.eager_load!` loads both loaders ([application.rb](file:///home/user/workspace/repo/railties/lib/rails/application.rb#L663-L664))

`_eager_load_paths.member?(path)` is exact. Pathname vs String is observable if a Pathname was configured; preserve current acceptance ([load_path_test.rb](file:///home/user/workspace/repo/railties/test/application/initializers/load_path_test.rb#L75-L86)).

### I4. `$LOAD_PATH`

From [`set_load_path`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L596-L600), [`_all_load_paths`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L762-L769), and [`add_lib_to_load_path!`](file:///home/user/workspace/repo/railties/lib/rails/application.rb#L439-L443):

- `config.paths` load-path dirs (`lib`, `vendor`) are always on `$LOAD_PATH` if they exist
- Application `lib` is on `$LOAD_PATH` even when `config.add_autoload_paths_to_load_path` is false (default since 7.1)
- If the flag is **true**, existing autoload **and** autoload-once dirs are also on `$LOAD_PATH`
- If the flag is **false**, autoload dirs other than `lib` are **not** on `$LOAD_PATH`
- `$LOAD_PATH.uniq!` keeps the first occurrence; do not assert full order unless two `require "same_relpath"` candidates exist

### I5. Freeze after the matching initializer

| Collection | Frozen by | Observable after |
|---|---|---|
| `config.autoload_paths` | `set_autoload_paths` | `bootstrap_hook` / any initializer after it |
| `config.autoload_once_paths` | `set_autoload_paths` | same |
| `config.eager_load_paths` | `set_eager_load_paths` | same |
| `AS::Dependencies.autoload_once_paths` | `setup_once_autoloader` | initializers, `config/initializers/*` |
| `AS::Dependencies.autoload_paths` | `setup_main_autoloader` | after `initialize!` |

Assertion: `assert_predicate collection, :frozen?` and `assert_raises(FrozenError) { collection << "x" }`. Do not freeze-check the concatenated `all_*` return value; it is a new array.

Once-autoloader must be able to autoload from initializers **after** freeze ([zeitwerk_integration_test.rb](file:///home/user/workspace/repo/railties/test/application/zeitwerk_integration_test.rb#L101-L134)).

### I6. Reloader hooks

From [finisher.rb](file:///home/user/workspace/repo/railties/lib/rails/application/finisher.rb#L33-L227) and [watchable_args](file:///home/user/workspace/repo/railties/lib/rails/application.rb#L458-L465):

- `main.reloading_enabled?` iff `config.reloading_enabled?`; `once.reloading_enabled?` is always false
- `AS::Dependencies.clear` / `reloader.reload!` reloads **main only**
- File watcher dirs = `main.dirs` (not once)
- `to_prepare` runs once at boot (`reloader.prepare!`); again on each reload when reloading is on
- If `eager_load && reloading`: `after_class_unload` re-eager-loads **main**
- Production (`enable_reloading = false`): `reloader.check` is always false; descendants tracking is not cleared

### I7. Engine vs application

Each engine runs the same three `set_*` initializers. Engine `app/*` constants autoload on `main` unless the engine put the dir on `autoload_once_paths`. Engine `lib` is on `$LOAD_PATH` (`paths.add "lib", load_path: true`), not on the autoloaders by default.

Initializer order is `ordered_railties.reverse` ([application.rb](file:///home/user/workspace/repo/railties/lib/rails/application.rb#L731-L747)): application `set_*` runs before engines, engines `unshift` later. Do not assert that sequence. Assert: both app and engine constants load; engine once-paths stay once; `config.railties_order` does not change loader **ownership**, only `$LOAD_PATH`/`require` winner if two engines ship the same relative file.

### I8. Default `app` glob vs nested roots

[Path registry `filter_by`](file:///home/user/workspace/repo/railties/lib/rails/paths.rb#L108-L112) subtracts children that do **not** share the flag, so `app` eager-load does not also register `app/views`. Custom arrays are **not** collapsed. Nested custom roots that Zeitwerk rejects must still raise `Zeitwerk::Error`.

## New black-box probes

Put these in `railties/test/application/` isolation tests (`build_app` / `app(env)`), same style as [zeitwerk_integration_test.rb](file:///home/user/workspace/repo/railties/test/application/zeitwerk_integration_test.rb). One app boot per scenario. Assert outcomes, not `_all_*`.

### 1. Duplicate paths

**Setup:** `config.autoload_paths << extras` twice; engine also adds the same absolute extras dir.

**Assert:**

- `Rails.autoloaders.main.dirs.count { |d| d == extras } == 1`
- `AS::Dependencies.autoload_paths.count { |d| d.to_s == extras } == 1` after freeze (global uniq happens at `push_dir` time via `uniq.each`; the Dependencies array may still contain duplicates from `unshift` **until** freeze — today `setup_main_autoloader` freezes without compacting the array). Safer observable: Zeitwerk dirs uniqueness, and one `on_load` for `Foo` from `extras/foo.rb`
- Boot does not raise `Zeitwerk::Error` / “already managed”

Do not assert `autoload_paths == autoload_paths.uniq` unless you first confirm the frozen array is compacted today (it is **not**; only the `uniq.each` iteration is). Preserve: Zeitwerk sees the path once.

### 2. Overlapping (parent/child) paths

**Setup A (registry, should work):** default `app` + `app/models` — already the default. Assert `User` autoloads; no Zeitwerk nested-root error.

**Setup B (custom nested roots):** `config.autoload_paths << "#{root}/app"` and `<< "#{root}/app/models"` **in addition** to defaults, or a custom `parent/` and `parent/child/` both marked autoload.

**Assert:** same exception class/message family Zeitwerk raises today for nested roots (`Zeitwerk::Error`). The refactor must not silently drop a child to “make it work.”

**Setup C (once parent, main child or vice versa):** `once` owns `extras`, `main` owns `extras/web`. Assert current boot result (error vs both registered). Capture pre-refactor exception with a one-off boot; pin that.

### 3. Path in both eager-load and autoload-once

**Setup:** `extras/money.rb` defining `Money = Object.new` (unique object); both `autoload_once_paths` and `eager_load_paths`.

**Production (`app "production"`):**

- `assert Object.const_defined?(:Money)` at boot (eager)
- `assert_includes Rails.autoloaders.once.dirs, extras`
- `assert_not_includes Rails.autoloaders.main.dirs, extras`
- `assert ActiveSupport::Dependencies.eager_load?(extras)` — only if the configured type matches Set membership; if that is too internal, skip and rely on boot-time constant presence
- `id = Money.object_id`; `Rails.application.reloader.reload!`; `assert_same Money, Object.const_get(:Money)` (once constants survive; production reloader.check is false anyway — also run this in development with `eager_load = true`)

**Development, not in eager:** extras only on once. `Money` is **not** defined at boot; `assert Money` then loads it; after `reload!`, `assert_same` the same object.

### 4. `config.add_autoload_paths_to_load_path = false` (default) vs true

**Setup:** custom `autoload_paths << "#{root}/extras"`, `autoload_once_paths << "#{root}/once_extras"`, both dirs exist; `app/models` exists.

**Flag false:**

- `assert_includes $LOAD_PATH, "#{app_path}/lib"`
- `assert_not_includes $LOAD_PATH, "#{app_path}/extras"`
- `assert_not_includes $LOAD_PATH, "#{app_path}/app/models"`
- `assert_not_includes $LOAD_PATH, "#{app_path}/once_extras"`
- `require "foo"` for `extras/foo.rb` raises `LoadError`; `Foo` still autoloads via Zeitwerk

**Flag true:**

- extras, once_extras, and app autoload dirs **are** on `$LOAD_PATH`
- `assert_empty (autoload_dirs - $LOAD_PATH)` using the same mailer-preview exclusion as the existing test
- `require "foo"` succeeds **and** `Foo` autoload still works (no double-load error)

Do not assert position in `$LOAD_PATH`. If two engines ship `lib/shared.rb`, assert `require "shared"` loads one file (`assert_equal engine_root, Shared::ORIGIN`) — that **is** order-observable and should be pinned with a named winner matching **current** boot, not an assumed railtie order.

### 5. Development reloads after edit / removal

Use `enable_reloading = true` and `Rails.application.reloader.reload!` (or a request, like loading_test). Touch mtime so the file watcher would fire; calling `reload!` directly tests the autoload contract without depending on watcher polling.

| Event | Main (`app/models/user.rb`) | Once (`extras/tool.rb`) |
|---|---|---|
| First load | `u1 = User`; `t1 = Tool` | same |
| Edit file, `reload!` | `assert_not Object.const_defined?(:User)` until next reference; `u2 = User`; `assert_not_same u1, u2`; new method body visible | `assert_same t1, Tool`; old method body |
| Delete file, `reload!` | `assert_raises(NameError) { User }` | if already loaded: still defined, same object; if never loaded: `NameError` on first reference |
| Add new file under main dir | new constant autoloads after reload | n/a |
| Edit once file **without** reload | once does not pick up changes even if you call `reload!` | same |

Also:

- `ActiveSupport::Dependencies.clear` invokes `main.reload` once, `once.reload` never — existing test; keep
- `to_prepare` count: increment a counter in `config.to_prepare`; boot → 1; `reload!` → 2 in development; boot production → 1 and `reload!` does not increment
- Watcher: after boot, `files, dirs = Rails.application.watchable_args`; `assert_includes dirs, main_dir`; `assert_not_includes dirs, once_dir`

### 6. Eager-loaded production

`app "production"` (eager_load true, reloading false):

- Constants under default `app/*` and engine `app/*` are defined at boot (`const_defined?` before any explicit reference)
- Once ∩ eager: defined at boot
- Once ∖ eager: **not** defined at boot; still autoloads on reference
- `assert_not Rails.autoloaders.main.reloading_enabled?`
- `assert_raises(NameError)` does not apply to missing optional dirs (nonexistent custom path is skipped, not an error)

## How to avoid tests coupled only to private ordering

1. **Membership, not sequence.** `assert_includes` on `main.dirs` / `once.dirs` / `$LOAD_PATH`. No `assert_equal full_array, other_array` for assembled paths in new tests.
2. **If order can change which file wins**, write a **named collision** probe (`require "shared"` or two `foo.rb` in different engines) and pin the winner to **current** behavior. That is an external effect, not private sort order.
3. **Do not** reimplement `_all_autoload_paths` in the test (`autoload + eager - once`). Ask Zeitwerk and `$LOAD_PATH`.
4. **Keep** the existing `and in the same order` tests as a tripwire during the refactor, but if they fail while membership, collisions, reload, and freeze pass, treat that as an allowed internal change — or update those two tests to membership-only in the same PR and say so.
5. **Engine order:** vary `config.railties_order` only in the collision probe. Ownership of distinct paths must be identical.
6. **`uniq` vs `Set`:** duplicates must not produce two Zeitwerk roots or two `$LOAD_PATH` entries when the flag is true; the frozen Dependencies arrays may still list duplicates. Don’t lock the latter.
7. **Unit-test `Rails::Paths` separately** ([paths_test.rb](file:///home/user/workspace/repo/railties/test/paths_test.rb)) for glob/exclude/autoload_once flags. Boot tests should not reconstruct `filter_by`.
