## Assistant

`travel_to` does not move a clock. It freezes four class methods on the current test case’s `SimpleStubs` instance so every later `Time.now` / `Time.new()` / `Date.today` / `DateTime.now` returns one local `Time` derived from the argument. `ActiveSupport::TestCase` includes the helper, and [`after_teardown`](file:///home/user/workspace/repo/activesupport/lib/active_support/testing/time_helpers.rb#L69-L72) always calls `travel_back`, so a forgotten non-block travel cannot leak into the next test.

`Time.current`, `Date.current`, and `DateTime.current` are not stubbed. They keep working because they read `Time.zone.now` / `Time.zone.today`, and those go through the stubbed `Time.now`.

```text
travel_to(date_or_time, with_usec: false)
  reject if block given AND in_block
  normalize argument → now
  now.change(usec: 0) unless with_usec
  now = now.getlocal
  remember previous Time.now if this test already stubbed it
  stub Time.now, Time.new, Date.today, DateTime.now
  if block
    in_block = true
    yield
    restore previous stub or travel_back
    in_block = false
```

### Input normalization

The argument is coerced to a `Time` (or something that `is_a?(Time)`, including `ActiveSupport::TimeWithZone`) **before** usec stripping and `getlocal`:

```162:175:activesupport/lib/active_support/testing/time_helpers.rb

          now = date_or_time.midnight.to_time
        elsif date_or_time.is_a?(String)
          now = Time.zone.parse(date_or_time)
        else
          now = date_or_time
          now = now.to_time unless now.is_a?(Time)
        end

        now = now.change(usec: 0) unless with_usec

        # +now+ must be in local system timezone, because +Time.at(now)+
        # and +now.to_date+ (see stubs below) will use +now+'s timezone too!
        now = now.getlocal
```

| Input | Path | Meaning for a test |
|---|---|---|
| `Date` (not `DateTime`) | `midnight` → `to_time` | Midnight of that calendar date in the **application** zone (`Date#midnight` is `in_time_zone`), then a real `Time`. `DateTime` is excluded here because it is a `Date`. |
| `String` | `Time.zone.parse` | Parsed in `Time.zone`. Needs `Time.zone` set. `"2004-11-24 01:04:44"` is that wall time in the app zone; an offset in the string is honored by parse, then later `getlocal`. |
| `Time` | kept | Instant unchanged. |
| `ActiveSupport::TimeWithZone` | kept (`is_a?(Time)` is true) | Instant unchanged; `change` / `getlocal` run on the TWZ. |
| `DateTime` and anything else | `to_time` | `DateTime#to_time` keeps the same UTC offset, then `getlocal` moves the wall clock into `ENV['TZ']`. |

Final `getlocal` is mandatory. The stubs below call `Time.at(now)` and `now.to_date`, both of which take the **receiver’s** timezone. Without converting to system local time, `Date.today` and `Time.now` can disagree with each other when app TZ ≠ process TZ.

A `Time` in `+05` of `2023-12-01 05:06:07` therefore becomes system-local `2023-11-30 19:06:07 -05` when the process is `US/Eastern`. `Time.now`, `Date.today`, and `DateTime.now` all report that system-local wall time. `Time.current` still shows the same instant in the app zone.

Four singleton methods, all closing over that local `now`:

- `Time.now` → `Time.at(now)` (always a system-local `Time` at that instant).
- `Time.new` → see next section.
- `Date.today` → `Date.jd(now.to_date.jd)`, so the calendar date of local `now`, not a `Date` subclass.
- `DateTime.now` → same civil fields plus `now.subsec` and `now.utc_offset` as a day-fraction offset.

`SimpleStubs` aliases the current method aside, then `define_singleton_method`. Restubbing first unstubs, so the saved “original” is always the real Ruby method, not an older travel. Stubs live on `Time` / `Date` / `DateTime` themselves; each test case only tracks which methods **it** stubbed.

Not stubbed: `Time.current`, `Date.current`, `DateTime.current`, `Time.zone.now`, `Process.clock_gettime`, `sleep`. `freeze_time` still lets `sleep` take wall time; only the four methods above freeze.

### `Time.new` with arguments

The stub copies Ruby: no arguments means “now”; any argument means “construct a time”.

- `Time.new` and `Time.new()` → `Time.at(now)` (same as `Time.now`).
- Any positional args (`Time.new(2021)`, `Time.new(2004, 11, 25)`) → real `Time.new` via the aliased original.
- Any kwargs, including only `precision:` → real `Time.new`. `Time.new(precision: 3)` is **not** frozen now.

That is why tests assert `Time.new == expected` and `Time.new(precision: 3) != expected` at the same time.

### `with_usec`

Default `false`. After coercion, `now.change(usec: 0)` zeros subseconds on `Time`, `DateTime`, and `TimeWithZone`.

That exists because MySQL rounds fractional seconds instead of flooring. `travel_to Time.utc(2014, 10, 10, 10, 10, 50, 999999)` would otherwise store as `10:10:51` in MySQL and miss the in-memory `Time`. With the default, both `Time.now.usec` and `DateTime.now.usec` are `0`.

`with_usec: true` skips that `change`. Subseconds survive into `Time.now` and into `DateTime.now` via `now.sec + now.subsec`. `travel` / `freeze_time` pass the flag through.

A string with millis (`"2004-11-24T01:04:44.123-05:00"`) is still truncated unless `with_usec: true`.

### Block cleanup

Before installing stubs, if **this** helper already stubbed `Time.now`, it snapshots `stubbed_time = Time.now` (the previously frozen instant, as a `Time`).

On a block:

1. `in_block = true`
2. `yield`
3. `ensure`: if `stubbed_time` was set, `travel_to stubbed_time` (non-block, so it restubs to the outer freeze); else `travel_back` (drop every stub this instance owns). Then `in_block = false`.

Two restore cases:

```text
real time
  travel_to A do          # stubbed_time nil
    Time.now == A
  end
  real time again         # travel_back

travel_to A               # non-block, stays frozen after this line
  travel_to B do          # stubbed_time == A; in_block is still false
    Time.now == B
  end
  Time.now == A           # travel_to A again, not travel_back
```

Non-block `travel_to` inside an outer **block** is allowed. It overwrites the stubs for the rest of that outer block. The outer `ensure` still `travel_back`s because the outer call had no prior stub of its own. Sequential non-block calls (`travel_to A` then `travel_to B`) also just restub; `Time.now` becomes `B` until `travel_back` or teardown.

`travel_back` without a block unstubs everything this instance installed. With a block it unstubs, yields, then `travel_to`s the previously frozen time if there was one.

### Why nested block-form `travel_to` is rejected

The guard is only `block_given? && in_block`. `in_block` is a per-test-case flag set for the duration of a block-form call on **that** object.

```ruby
travel_to 2.days.from_now do
  travel_to 3.days.from_now do   # RuntimeError
    ...
  end
end
```

The error exists because the inner argument is evaluated **after** time is already frozen. `3.days.from_now` is then 5 days from real now, not 3. The helper refuses that rather than try to nest restores. `in_block` is also a single boolean, not a counter; an inner block’s `ensure` would clear it while the outer block was still running.

Allowed on the same object:

- block then inner **non-block** `travel_to`
- non-block then inner **block** `travel_to` (restores the outer freeze)
- two sibling block `travel_to`s
- another object that includes `TimeHelpers` calling block `travel_to` (its own `in_block`)

Use `travel 2.days do ... end` and a separate `travel 5.days do ... end` when you want two absolute offsets from real now, not a nested freeze.
