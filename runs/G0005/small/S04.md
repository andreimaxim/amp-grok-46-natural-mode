`content_for` is a named slot on `@view_flow`. A call is a **write** if it has a truthy `content` argument or a block; otherwise it is a **read**. Writes never print into the current template. The layout (or a later `<%= content_for :name %>`) reads the same slot after the template has run.

```diagram
template (runs first)
  content_for :title, ... / do ... end
       ┃
       ▼
  OutputFlow @content[:title]   (SafeBuffer)
       ▲
       ┃
layout  yield(:title) / content_for(:title)
  _layout_for → get(:title).html_safe → layout OutputBuffer
```

The store is [OutputFlow](file:///home/user/workspace/repo/actionview/lib/action_view/flows.rb): a hash that autovivifies `ActiveSupport::SafeBuffer.new` per key. [TemplateRenderer](file:///home/user/workspace/repo/actionview/lib/action_view/renderer/template_renderer.rb) renders the template first, then the layout. Layout `yield :title` is [`_layout_for`](file:///home/user/workspace/repo/actionview/lib/action_view/context.rb), which is `view_flow.get(name).html_safe`.

```ruby
def content_for(name, content = nil, options = {}, &block)
  if content || block_given?
    if block_given?
      options = content if content
      content = capture(&block)
    end
    if content
      options[:flush] ? @view_flow.set(name, content) : @view_flow.append(name, content)
    end
    nil
  else
    @view_flow.get(name).presence
  end
end
```

That is [CaptureHelper#content_for](file:///home/user/workspace/repo/actionview/lib/action_view/helpers/capture_helper.rb#L172-L185).

## Block capture versus direct content

**Direct write** (`content_for :title, "foo"`): the second argument is stored as-is. No `capture`. Symbols work because flow methods call `to_s` (`:bar` → `"bar"`).

**Block write**: if a block is given, a truthy second argument is treated as **options**, then the block is run through [`capture`](file:///home/user/workspace/repo/actionview/lib/action_view/helpers/capture_helper.rb#L47-L65):

- `content_for :title do ... end` — `content` is `nil`, `options` stays `{}`.
- `content_for :title, flush: true do ... end` — the hash becomes `options`, then `content = capture(&block)`.
- `content_for :title, nil, flush: true do ... end` — `content` is `nil`, so the hash is already `options`; same capture path.

`capture` does not swap the `OutputBuffer` object. [`OutputBuffer#capture`](file:///home/user/workspace/repo/actionview/lib/action_view/buffers.rb#L72-L80) swaps `@raw_buffer` for an empty string, yields, then returns that string as `html_safe`. ERB `<% content_for :title do %>…<% end %>` therefore writes into a temporary buffer and does not leak into the template body.

What `capture` stores:

1. If the block returns the output buffer object itself, use the captured buffer.
2. Otherwise use `buffer.presence || value` — buffer output wins unless it is blank/whitespace.
3. Result typing: `OutputBuffer` → `to_s` (already-safe string); `SafeBuffer` → unchanged; plain `String` → `ERB::Util.html_escape`; anything else → `nil`.

So ERB blocks that concatenate into `output_buffer` are captured from the buffer. Builder / helper blocks that **return** a string are captured from the return value. A whitespace-only ERB block that returns `nil` produces `nil` from `capture` (`"  \n  ".presence` is `nil`), and the later `if content` skips the store.

That is why [content_for.erb](file:///home/user/workspace/repo/actionview/test/fixtures/actionpack/test/content_for.erb) can do `<% content_for :title do -%>Putting stuff in the title!<% end -%>Great stuff!` and the layout still sees only `"Great stuff!"` as the unnamed yield.

## Append order across repeated writes

Default is concatenate in call order. `options[:flush]` falsey → [`OutputFlow#append`](file:///home/user/workspace/repo/actionview/lib/action_view/flows.rb#L24-L26):

```ruby
@content[key] << value.to_s
```

Two writes to `:title` of `"foo"` then `:bar` become `"foobar"`. A block write of `"foo"` then `flush: false` of `"bar"` is the same. Direct and block writes share one buffer per name; order is wall-clock call order, not “all blocks first.”

`if content` is Ruby truthiness, not `present?`. An empty or whitespace **direct** string still appends. A **blank capture** does not.

## `flush: true` replacement

`options[:flush]` truthy → [`OutputFlow#set`](file:///home/user/workspace/repo/actionview/lib/action_view/flows.rb#L19-L21):

```ruby
@content[key] = ActiveSupport::SafeBuffer.new(value.to_s)
```

That replaces the slot. `"foo"` then `flush: true` `"bar"` leaves `"bar"`. Same for blocks.

Flush only runs if `content` is truthy after capture. A `flush: true` whitespace block that captures to `nil` is a no-op: previous content stays. The tests then replace with a later `content_for :title, "bar", flush: true`.

Flushing with `""` does replace: `set` installs a new empty `SafeBuffer`. Later appends concat onto that new buffer (the `html_safe?` after empty-flush test).

## Write versus read returns

| Call | Returns |
|---|---|
| Write (`content` truthy or block) | always `nil`, including when capture is `nil` or `flush: true` |
| Read (`content_for(:name)` only) | `@view_flow.get(name).presence` |
| Missing key | still a live empty `SafeBuffer` from the hash default; `.presence` → `nil` |

`<%= content_for :title do %>…<% end %>` therefore prints nothing. `<%= content_for :title %>` prints the slot if it is present.

`.presence` uses string `blank?` (empty or whitespace). Direct `content_for :title, "  "` stores spaces, but a later read returns `nil`.

## `content_for?`

```ruby
def content_for?(name)
  @view_flow.get(name).present?
end
```

Same store, `present?` rather than `presence`. Missing / empty / whitespace-only → `false`. It does not consume or flush the slot. Layouts use it for structure (`content_for?(:right_col) ? "two-column" : "one-column"`) while `yield :right_col` still reads the same buffer.

## Why the later view buffer does not re-escape

The slot is always a `SafeBuffer`. Insertion into ERB is `OutputBuffer#<<`, which concatenates without escaping when `value.html_safe?`.

How values become safe before that:

- **Block / `capture`**: `OutputBuffer#<<` already runs `unwrapped_html_escape` on unsafe fragments; `capture` then returns `html_safe` buffer contents, or a `SafeBuffer` helper result as-is, or `html_escape` on a plain `String`. Double-escape is avoided because a `SafeBuffer` is not escaped again (`raw` / `content_tag` stay marked safe).
- **Direct `append`**: `SafeBuffer#concat` escapes unless the argument is already `html_safe?`. `value.to_s` on a `SafeBuffer` is itself; on a plain `String` it is not, so `"<p>"` becomes `&lt;p&gt;`.
- **Direct `set` (`flush: true`)**: wraps `value.to_s` in `SafeBuffer.new(...)`, which marks the result html-safe. A block still went through `capture` first, so that path is escaped. A raw unsafe string passed with `flush: true` is stored as a safe buffer without that concat escape.

`_layout_for` calls `.html_safe` on `get`; for these buffers that is identity. The layout `OutputBuffer` therefore treats named content as trusted markup, which is correct for captured ERB/helpers and for already-safe strings, and is why `<%= yield :title %>` does not escape the title a second time.

`provide` is the streaming cousin: it `append!`s and can resume a waiting layout fiber. Non-streaming `content_for` only `append`/`set`; it does not tell a streaming layout to stop waiting.
