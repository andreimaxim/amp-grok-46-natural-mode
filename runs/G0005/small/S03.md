`String#truncate_bytes` in [activesupport/lib/active_support/core_ext/string/filters.rb](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/string/filters.rb) has four branches: `dup` when `bytesize <= truncate_to`, `ArgumentError` when the omission is larger than the budget, `omission.dup` when they are equal, otherwise grapheme-cluster fill plus omission. I probed all four on this checkout (Ruby 4.0.6) and ran `bin/test test/core_ext/string_ext_test.rb -n "/truncate_bytes|truncates_bytes/"`: **4 runs, 44 assertions, 0 failures**.

A refactor is behavior-preserving iff a second run of the same probes prints the same values. Existing tests are necessary but not sufficient: they miss ASCII truncation, combining marks, subclass, receiver identity, and the encoding quirk below.

Treat every case as an oracle. If any printed field changes, the “unchanged” claim is false.

### 1. Within-budget strings

```text
"hello".truncate_bytes(10)                         => "hello"   equal?=true  same_object?=false
"👍👍👍👍".truncate_bytes(16)                      => "👍👍👍👍" same_object?=false
"👍👍👍👍".truncate_bytes(16, omission: "🖖")      => "👍👍👍👍"  (omission ignored)
"".truncate_bytes(0)                               => ""
"".truncate_bytes(5)                               => ""
```

Proves the early `dup` path: content is copied, the receiver is not returned, and `:omission` is not consulted when `bytesize <= truncate_to`. Empty strings stay empty.

### 2. ASCII truncation

```text
"hello world".truncate_bytes(5)                    => "he…"     bytesize=5
"hello world".truncate_bytes(8)                    => "hello…"  bytesize=8
"hello world".truncate_bytes(11)                   => "hello world"
"hello world".truncate_bytes(5, omission: nil)     => "hello"   bytesize=5
"hello world".truncate_bytes(5, omission: "...")   => "he..."   bytesize=5
```

Proves single-byte graphemes fill up to `truncate_to - omission.bytesize`, then the omission is appended, and the result never exceeds the budget. Exact equality with the budget takes the `dup` path, not the cut path.

### 3. Multibyte truncation

`👍` is 4 bytes; default `"…"` is 3.

```text
"👍👍👍👍".truncate_bytes(16) => "👍👍👍👍"  bytesize=16
"👍👍👍👍".truncate_bytes(15) => "👍👍👍…"   bytesize=15
"👍👍👍👍".truncate_bytes(14) => "👍👍…"     bytesize=11
"👍👍👍👍".truncate_bytes(12) => "👍👍…"     bytesize=11
"👍👍👍👍".truncate_bytes(8)  => "👍…"       bytesize=7
"👍👍👍👍".truncate_bytes(5)  => "…"         bytesize=3
"👍👍👍👍".truncate_bytes(4)  => "…"         bytesize=3
"👍👍👍👍".truncate_bytes(3)  => "…"         bytesize=3
```

Proves characters are never split, leftover room smaller than the next codepoint is left unused, and `bytesize <= truncate_to` is allowed to be strict (`14` yields `11`, not a broken 4th byte of `👍`). Budget `3` is the omission-equals-budget path, not a cut.

### 4. Grapheme clusters

`"a ❤️ b"` clusters `[a(1),  (1), ❤️(6),  (1), b(1)]`. `"👩‍❤️‍👩"` is one 20-byte cluster. `"cafe\u0301 extra"` has combining `é` at 3 bytes.

```text
"a ❤️ b".truncate_bytes(2..7, omission: nil)  => "a "        bytesize=2
"a ❤️ b".truncate_bytes(8,    omission: nil)  => "a ❤️"     bytesize=8
"👩‍❤️‍👩".truncate_bytes(13, omission: nil)    => ""
"👩‍❤️‍👩".truncate_bytes(19, omission: nil)    => ""
"a 👩‍❤️‍👩".truncate_bytes(13, omission: nil)  => "a "
"cafe\u0301 extra".truncate_bytes(4, omission: nil) => "caf"
"cafe\u0301 extra".truncate_bytes(6, omission: nil) => "café"
```

Proves truncation walks `each_grapheme_cluster`, not codepoints: ZWJ sequences and combining marks are kept whole or dropped whole. A cluster larger than the remaining budget contributes nothing (`""`, not a sliced `👩`).

### 5. Exact byte boundaries

```text
"hello".truncate_bytes(5)                       => "hello"     # bytesize == budget → dup
"hello!".truncate_bytes(5)                      => "he…"
"👍👍👍👍".truncate_bytes(8, omission: nil)     => "👍👍"     bytesize=8
"👍👍👍👍".truncate_bytes(9, omission: nil)     => "👍👍"     bytesize=8
"👍👍👍👍".truncate_bytes(7, omission: nil)     => "👍"       bytesize=4
"👍👍👍👍".truncate_bytes(7)                    => "👍…"      bytesize=7
```

Proves `==` vs `>` on the budget, and that a mid-character budget (`9` into a 4-byte `👍`) still emits only complete characters. `7` with default omission is an exact fit: `4 + 3`.

### 6. Custom and nil omissions

On `"👍👍👍👍".truncate_bytes(15, omission: …)`:

```text
nil / ""  => "👍👍👍"      bytesize=12
" "       => "👍👍👍 "     bytesize=13
"..."     => "👍👍👍..."   bytesize=15
"🖖"      => "👍👍🖖"      bytesize=12
"…"       => "👍👍👍…"     bytesize=15
"CUT"     => "👍👍👍CUT"   bytesize=15
```

Proves `omission ||= ""` (nil and empty are the same), the cut length is `truncate_to - omission.bytesize`, and a multibyte omission is itself a suffix, not a further-truncated suffix.

### 7. Omission equal to or larger than the budget

```text
truncate_bytes(4, omission: "🖖") => "🖖"          # equal → omission.dup
truncate_bytes(3, omission: "🖖") => ArgumentError "Omission \"🖖\" is 4, larger than the truncation length of 3 bytes"
truncate_bytes(3, omission: "…")  => "…"
truncate_bytes(2, omission: "…")  => ArgumentError
truncate_bytes(0, omission: "")   => ""
truncate_bytes(0, omission: nil)  => ""
"hello world".truncate_bytes(3, omission: "...") => "..."
"hello world".truncate_bytes(2, omission: "...") => ArgumentError
```

Proves the two omission-size branches and the exact error string. Equal size returns only the omission (no prefix). `nil` at budget `0` is empty, not an error.

Also: `omission.dup` is a new unfrozen `String`, not the omission object. Mutating the result left `"..."` unchanged (`"...x"` vs `"..."`).

### 8. Encoding and subclass preservation

```text
UTF-8 30×"a".truncate_bytes(15)              encoding=UTF-8
UTF-8 30×"a".truncate_bytes(50)              encoding=UTF-8   # within budget
US-ASCII alphabet.truncate_bytes(100)        encoding=US-ASCII
US-ASCII alphabet.truncate_bytes(10)         encoding=UTF-8   # default "…"
ASCII-8BIT "hello world!!".truncate_bytes(100) encoding=ASCII-8BIT
ASCII-8BIT "hello world!!".truncate_bytes(8) encoding=UTF-8

MyString.new("hello world extra").truncate_bytes(8)   class=MyString
MyString.new(...).truncate_bytes(100)                 class=MyString  same_object?=false
MyString.new(...).truncate_bytes(3, omission: "...")  class=String    # not MyString
MyString.new("hello world").truncate_bytes(5, omission: nil) class=MyString
```

Proves encoding is preserved on the `dup` path, but **not** on the cut path when the omission’s encoding differs (default `"…"` is UTF-8). That quirk is current behavior; a “fix” would be a change.

Subclass is preserved on `dup` and on the grapheme-fill constructor (`self.class.new`). It is **not** preserved when the result is `omission.dup`.

### 9. Receiver mutation

```text
orig = "hello world"
orig.truncate_bytes(5)
# orig still "hello world", same object_id, result.equal?(orig) == false

"hello".truncate_bytes(100)
# result.equal?(receiver) == false  (dup, not self)

frozen = "hello world extra".freeze
frozen.truncate_bytes(8)   # no exception; frozen still frozen and unchanged; result unfrozen
"hello".freeze.truncate_bytes(100)  # result unfrozen, not equal? to receiver

result = "hello".truncate_bytes(100); result << "x"
# result "hellox", receiver still "hello"
```

Proves the method is non-destructive on every branch, including frozen receivers, and that “within budget” still allocates. A refactor that returns `self` on the fast path would fail `same_object?=false` and the frozen-within-budget case.
