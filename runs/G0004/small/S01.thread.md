## Assistant

`travel_to` freezes “now” for the rest of the test (or for a block) by replacing four class methods. It does not stub `Time.current`, `Date.current`, or `DateTime.current`; those keep working because they already call `Time.now` / `Date.today` / `Time.zone.now`.

```text
travel_to(date_or_time, with_usec: false)
  reject nested block-form if in_block
  normalize input → Time
  drop usec unless with_usec
  now = now.getlocal          # system TZ
  stub Time.now / Time.new / Date.today / DateTime.now
  if block: yield, then restore previous travel or real time
```

The implementation lives in [`activesupport/lib/active_support/testing/time_helpers.rb`](file:///home/user/workspace/repo/activesupport/lib/active_support/testing/time_helpers.rb). `ActiveSupport::TestCase` includes it, and `after_teardown` always calls `travel_back`, so a non-block `travel_to` cannot leak into the next test.

### Input normalization

Everything is reduced to one `Time` named `now`, then forced into the **process/system** timezone with `getlocal`. The stubs are built from that local `Time`, not from the original argument’s class.

**Date (not DateTime).** `DateTime < Date`, so the Date branch is `is_a?(Date) && !is_a?(DateTime)`:

```ruby
now = date_or_time.midnight.to_time
```

`Date#midnight` is `beginning_of_day` → `in_time_zone`: midnight of that calendar day in the **application** time zone (`Time.zone`). `.to_time` then turns that `TimeWithZone` into a `Time`. After `getlocal`, `Time.now` is that instant in system TZ. That is why the docs say `Time.current` / `Date.current` honor the app zone, while `Time.now` / `Date.today` follow system TZ and can land on a different calendar day.

**String.** Parsed with `Time.zone.parse` (app zone, missing pieces filled from `TimeZone#now`). Fractional seconds in the string survive parse, then the default `with_usec: false` zeros them. There is no `Time.zone` fallback here: a nil zone will raise.

**Time, DateTime, TimeWithZone, anything else.**

```ruby
now = date_or_time
now = now.to_time unless now.is_a?(Time)
```

- `Time` stays as-is (`Time#to_time` is `self`).
- `ActiveSupport::TimeWithZone` reports `is_a?(Time)`, so it is not converted until `change` / `getlocal`.
- `DateTime` is excluded from the Date branch, is not a `Time`, so it goes through `DateTime#to_time` (`getlocal(utc_offset)`), keeping the same UTC offset, then later `getlocal` again to system TZ.

`getlocal` is required because the stubs use `Time.at(now)` and `now.to_date`, both of which follow `now`’s zone. If `now` stayed in another offset, `Date.today` and `Time.now` would disagree with wall-clock local time.

### What is stubbed

`SimpleStubs` rewrites singleton methods on `Time`, `Date`, and `DateTime`. If this helper instance already stubbed a method, it unstubs first so the saved “original” is always Ruby’s method, not a previous travel.

| Call | Stub |
|---|---|
| `Time.now` | `Time.at(now)` |
| `Time.new` | see below |
| `Date.today` | `Date.jd(now.to_date.jd)` |
| `DateTime.now` | `DateTime.jd(date, hour, min, sec + subsec, offset as Rational day)` |

Not stubbed: `Time.current`, `Date.current`, `DateTime.current`, `Time.zone.now`, `Time.at`, `Time.utc`, `Time.local`, constructors with a date, `Process.clock_gettime`, and so on.

Subclasses (`TimeSubclass.now`, `DateSubclass.today`) still call the stubbed parent methods, so they freeze too and keep their class.

`DateTime.now` copies `now.sec + now.subsec` and `now.utc_offset`, so with `with_usec: true` the fractional second shows up on `DateTime.now.usec` / `sec_fraction`.

### `Time.new` with arguments

```ruby
stubs.stub_object(Time, :new) do |*args, **options|
  if args.empty? && options.empty?
    at(now)
  else
    stub = stubs.stubbing(Time, :new)
    Time.send(stub.original_method, *args, **options)
  end
end
```

- `Time.new` with **no** positional args and **no** kwargs → same as `Time.now` (the frozen instant).
- Any positional arg (`Time.new(2021)`, `Time.new(2004, 11, 25)`) **or** any kwarg (`Time.new(precision: 3)`, `Time.new("2000-12-31 23:59:59.56789", precision: 3)`) → real `Time.new`.

That is why tests assert `Time.new == expected_time` but `Time.new(precision: 3) != expected_time`. Keyword-only `Time.new` is treated as “construct a time,” not “what time is it.”

### `with_usec`

Default `false`:

```ruby
now = now.change(usec: 0) unless with_usec
```

Microseconds (and therefore nanoseconds) are stripped **after** parse/convert, **before** stubbing. The comment and tests exist because MySQL DATETIME rounds fractional seconds instead of flooring: `10:10:50.999999` stored then read back can become `10:10:51`. Zeroing usec avoids that off-by-one in assertions and round-trips.

`with_usec: true` keeps the fractional part on `Time.now`, `Time.new()`, and `DateTime.now`. `travel` / `freeze_time` just forward this flag into `travel_to`.

A string like `"2004-11-24T01:04:44.123-05:00"` still ends at `:44` with usec 0 unless you pass `with_usec: true`.

### Block cleanup: real time vs a previous non-block travel

Before installing stubs, the helper snapshots the current frozen clock **only if this instance already stubbed `Time.now`**:

```ruby
stubbed_time = Time.now if stubs.stubbing(Time, :now)
```

Then it stubs, then if a block was given:

```ruby
begin
  self.in_block = true
  yield
ensure
  if stubbed_time
    travel_to stubbed_time   # re-freeze at the previous destination
  else
    travel_back              # unstub all → real time
  end
  self.in_block = false
end
```

Two restore paths:

```diagram
No prior travel on this helper
  travel_to T do ... end
  ┃ ensure: travel_back
  ▼
  Time.now / Date.today / DateTime.now are real again

Non-block travel already in effect
  travel_to T1          # stubs stay for the test
  travel_to T2 do ... end
  ┃ ensure: travel_to T1
  ▼
  clock is T1 again, not real time
```

`travel_back` (`simple_stubs.unstub_all!`) is the “real time” path. The other path calls `travel_to` again with the captured `Time.now` (no block), which replaces the stubs with T1.

That is also why a **non-block** `travel_to` inside a block-form `travel_to` is allowed: it overwrites the stubs for the rest of the outer block; when the outer `ensure` runs, `stubbed_time` was captured **before** the inner call only at the outer entry. Inner non-block travel does not change the outer ensure’s restore target. The outer ensure restores whatever was frozen when the **outer** call started (real time if nothing was stubbed, otherwise the previous non-block destination).

`in_block` is per helper instance (`attr_accessor :in_block`). A second object that includes `TimeHelpers` has its own flag and its own `SimpleStubs`.

### Why nested block-form `travel_to` is rejected

At the top of `travel_to`:

```ruby
if block_given? && in_block
  raise <<~MSG
    Calling `travel_to` with a block, when we have previously already made a call
    to `travel_to`, can lead to confusing time stubbing.
    ...
  MSG
end
```

`in_block` is true only while executing the `yield` of a block-form `travel_to` on **this** helper. So this is rejected:

```ruby
travel_to t1 do
  travel_to t2 do   # RuntimeError
  end
end
```

These are not:

- non-block `travel_to` inside a block (`travel_to t2` with no block)
- block-form `travel_to` after a **non-block** `travel_to` (you are not `in_block` yet)
- nested blocks on a **different** `TimeHelpers` instance

The raise is intentional, not a missing stack. Relative arguments are evaluated **after** the outer freeze, so they compound:

```ruby
travel_to 2.days.from_now do
  travel_to 3.days.from_now do
    # 5 days from the original now, not 3
  end
end
```

Cleanup would also be ambiguous: inner `ensure` might `travel_back` (killing the outer freeze) or `travel_to stubbed_time` (restoring outer). The helper refuses the combination and tells you to use sibling `travel` / `travel_to` blocks instead of nesting.

For a test author: use block form when the freeze should be scoped; use non-block form when it should last until `travel_back` or teardown; pass `with_usec: true` only when you need sub-second clock values; prefer `Time.current` / `Date.current` in app code so the freeze and the app time zone stay aligned.
