# Behavior-preservation strategy for `#to_plain_text` / `#render_attachments`

The public pipeline is:

```text
Content#to_plain_text
  render_attachments(with_full_attributes: false, &:to_plain_text)
    Fragment#replace("action-text-attachment")  # dup source
      sanitize content= on the copy
      Attachment.from_node(node)                 # still resolves attachable
      Attachment#to_plain_text                   # string / Nokogiri replacement
    Content.new(..., canonicalize: false)
  Fragment#to_plain_text
    PlainTextConversion.node_to_plain_text
```

Source: [content.rb](file:///home/user/workspace/repo/actiontext/lib/action_text/content.rb#L99-L133), [fragment.rb](file:///home/user/workspace/repo/actiontext/lib/action_text/fragment.rb#L40-L52), [plain_text_conversion.rb](file:///home/user/workspace/repo/actiontext/lib/action_text/plain_text_conversion.rb#L9-L13), [attachment.rb](file:///home/user/workspace/repo/actiontext/lib/action_text/attachment.rb#L111-L116).

`#to_plain_text` is a pure observer of canonical HTML. A refactor may change the reducer, replacement order, or attachable lookup internals only if every string below stays identical and `#to_html` on the original `Content` does not change.

## Observable contract (this revision)

### 1. Ordinary block / line-break markup

`PlainTextConversion` owns this. Attachment replacement is a no-op when no `action-text-attachment` nodes exist.

| Input | Observable form |
|---|---|
| `<p>Hello world!</p><p>How are you?</p>` | `"Hello world!\n\nHow are you?"` |
| `<h1>…</h1><div>…</div>` and `<h2>`–`<h6>` | heading/block then `"\n\n"` then div’s `"\n"` |
| `<div>Hello world!</div><div>How are you?</div>` | `"Hello world!\nHow are you?"` |
| `<p>Hello world!<br>one<br>two<br>three</p>` | `"Hello world!\none\ntwo\nthree"` |
| `<ul><li>one</li>…` | `"• one\n• two\n• three"` |
| `<li>` with no parent list | same bullets |
| nested `<ol>` | `"1. Item 1\n  1. Item 2"` |
| `<blockquote>Hello world!</blockquote>` | `"“Hello world!”"` with `"\n\n"` between siblings |
| whitespace-only `<blockquote>` | `"“”"` |
| `<div><strong>Hello </strong>world!</div>` | `"Hello world!"` (non-linebreak whitespace kept) |
| `<strong>Hello<br></strong>How are you?` | `"Hello\nHow are you?"` |
| unknown inline (`<span>`) | children concatenated |
| whole-document trailing newlines | stripped (`chomp`) |

Block vs line: `h1`–`h6`/`p`/`blockquote`/`ul`/`ol` → `"\n\n"`; `div`/`li`/`br` → `"\n"`.

### 2. Entities

Nokogiri decodes entities **before** plain-text conversion. The result is a **non-`html_safe`** Ruby string of decoded characters, not escaped HTML.

| Input | Observable form |
|---|---|
| `&lt;script&gt;alert()&lt;/script&gt;` | `"<script>alert()</script>"` |
| `Tom &amp; Jerry` | `"Tom & Jerry"` |
| `Hello&nbsp;world` | `"Hello\u00A0world"` (NBSP, not U+0020) |
| caption `Tom &amp; Jerry` on a remote image | `"[Tom & Jerry]"` |

Docs that say “HTML entities encoded” ([content.rb](file:///home/user/workspace/repo/actiontext/lib/action_text/content.rb#L118-L131), [rich_text.rb](file:///home/user/workspace/repo/actiontext/app/models/action_text/rich_text.rb#L64-L76)) describe the *danger* (decoded `<script>`), not an escaped output.

### 3. Script-like text

Two different rules:

- Real `<script>` / `<style>` **elements** contribute `""` ([plain_text_conversion.rb](file:///home/user/workspace/repo/actiontext/lib/action_text/plain_text_conversion.rb#L30-L38)).
- Script **text** that arrived as entities or as element children of allowed tags is kept.
- `<div onclick='action()'>safe<script>unsafe</script></div>` → `"safe"` (`onclick` is irrelevant to plain text; the `<script>` child is dropped).

`#to_plain_text` must **not** start returning `"safeunsafe"` (that is `#to_s` / sanitizer HTML, [rich_text.rb](file:///home/user/workspace/repo/actiontext/app/models/action_text/rich_text.rb#L21-L26)).

### 4. Attachment captions and filenames

`#to_plain_text` always calls `render_attachments(with_full_attributes: false, &:to_plain_text)` ([content.rb](file:///home/user/workspace/repo/actiontext/lib/action_text/content.rb#L132-L133)). Attachable lookup still happens. `false` means “do not merge attachable attrs onto the node”, not “ignore the attachable”.

`Attachment#to_plain_text` ([attachment.rb](file:///home/user/workspace/repo/actiontext/lib/action_text/attachment.rb#L111-L116)):

- if `attachable_plain_text_representation` exists → that string
- else → `caption.to_s` (**no brackets**)

| Attachable | Caption present | No caption |
|---|---|---|
| `ActiveStorage::Blob` ([engine.rb](file:///home/user/workspace/repo/actiontext/lib/action_text/engine.rb#L59-L61)) | `"[Vroom vroom]"` | `"[racecar.jpg]"` (blob `filename`, not node `filename`) |
| `RemoteImage` | `"[Cat]"` | `"[Image]"` |
| `MissingAttachable` | `"☒"` (caption ignored) | `"☒"` |
| `Person` / `Page` (no override) | raw `"Hello"` / `"[click](javascript:alert(1))"` | `""` |
| HTML `ContentAttachment` | N/A (caption unused) | plain text of **sanitized** `content` |

Node `filename="override.jpg"` does **not** change blob plain text: representation uses `caption \|\| filename` on the blob. Probed: `with_full_attributes` true and false both yield `"[racecar.jpg]"`.

Caption wins over filename when both exist.

### 5. Missing attachables

Always `"☒"` ([missing_attachable.rb](file:///home/user/workspace/repo/actiontext/lib/action_text/attachables/missing_attachable.rb#L24-L26)):

- `sgid="missing"`
- destroyed blob SGID
- `content-type="image/*" url="image.png"` (non-URL path → missing, not remote)
- missing gallery SGIDs
- caption on any of the above is ignored

### 6. Remote images

`RemoteImage` only when `url` matches `URI_REGEXP` and `content-type` is `image` / `image/…` ([remote_image.rb](file:///home/user/workspace/repo/actiontext/lib/action_text/attachables/remote_image.rb#L9-L45)).

| Input | Form |
|---|---|
| `content-type="image" url="http://example.com/cat.jpg" caption="Cat"` | `"[Cat]"` |
| same, no caption | `"[Image]"` |
| with width/height + caption | `"[Captioned]"` (dims unused) |
| `Hello world! <action-text-attachment … caption="Cat">` | `"Hello world! [Cat]"` |

### 7. Duplicate attachables

Each node is replaced independently. No dedup, no separator:

- two identical blob tags → `"[racecar.jpg][racecar.jpg]"`
- same SGID, captions One/Two → `"[One][Two]"`
- `<div>A</div>` + two tags + `<div>B</div>` → `"A\n[racecar.jpg][racecar.jpg]B"`

Persistence may uniq embeds ([model_test.rb](file:///home/user/workspace/repo/actiontext/test/unit/model_test.rb#L55-L61)); plain text must not.

### 8. Attachment galleries

`#to_plain_text` does **not** call `#render_attachment_galleries`. Constructor canonicalizes gallery wrappers to a bare `<div>` ([attachment_gallery.rb](file:///home/user/workspace/repo/actiontext/lib/action_text/attachment_gallery.rb#L14-L17), [content.rb](file:///home/user/workspace/repo/actiontext/lib/action_text/content.rb#L32-L38)). Then attachments convert as usual; the `div` contributes `"\n"` after children, then trailing newlines are stripped.

| Input | `#to_html` (canonical) | `#to_plain_text` |
|---|---|---|
| two missing gallery attachments, no extra whitespace | `<div><action-text-attachment …></div>` | `"☒☒"` |
| gallery markup with `"\n  "` between tags | inner whitespace kept in HTML | `"\n  ☒\n  ☒"` |
| gallery inside `<blockquote>` | `<blockquote><div>…</div></blockquote>` | `"“☒☒”"` |
| real blobs, second captioned `"Second"` | gallery class stripped | `"[racecar.jpg][Second]"` |

### 9. Nested attachment nodes

Canonicalize **minifies** attachment inner HTML ([minification.rb](file:///home/user/workspace/repo/actiontext/lib/action_text/attachments/minification.rb#L11-L15)):

| Input (`canonicalize: true`, default) | `#to_html` | `#to_plain_text` |
|---|---|---|
| `<action-text-attachment sgid="123"><div>HTML</div></…>` | empty inner HTML, sgid kept | `"☒"` |
| same with `caption="Inner"` | inner HTML gone | `"☒"` (missing; caption ignored) |
| attachment nested inside attachment | only outer node remains (`attachments.size == 1`) | `"☒"` |

`canonicalize: false` keeps inner HTML in `#to_html`, but `#to_plain_text` still replaces the outer attachment via `#render_attachments`, so inner text does not leak: `'<div>Hello <action-text-attachment sgid="123"><div>INNER</div></…> world</div>'` → `"Hello ☒ world"`.

### 10. `with_full_attributes: false`

Default for `#attachments` / HTML render is `true` ([content.rb](file:///home/user/workspace/repo/actiontext/lib/action_text/content.rb#L216-L219)). `#to_plain_text` and `#to_markdown` pass `false`.

On a blob node that only has `sgid`:

- `render_attachments(with_full_attributes: false) { \|a\| a.node.to_html }` → node still only `sgid`
- `render_attachments { \|a\| a.node.to_html }` (default true) → adds `content-type`, `filename`, `filesize`, `previewable`
- both `&:to_plain_text` paths still `"[racecar.jpg]"` because the blob method reads `filename` off the attachable

A refactor that skips attachable resolution when `with_full_attributes: false` would turn uncaptioned blobs into `""` and is a contract break.

`#render_attachments` also:

- returns a **new** `Content` with `canonicalize: false` (so replacements are not re-minified / gallery-rewritten / markdown-unwrapped — see [markdown_conversion_test.rb](file:///home/user/workspace/repo/actiontext/test/unit/markdown_conversion_test.rb#L1124-L1133))
- sanitizes `content=` on the **copy**: `onerror=alert` stripped; empty / `<script></script>` attribute removed
- leaves the original node’s `content=` intact

HTML content attachments are sanitized **before** `Attachment.from_node`, so

- `content="abc"` → `"abc"`
- `content="&lt;p&gt;abc&lt;/p&gt;"` → `"abc"`
- `content="&lt;script&gt;alert(1)&lt;/script&gt;"` → `"alert(1)"` (script tags scrubbed, inner text kept)

### Non-mutation of `#to_html` / canonical content

Probed and required:

- `content.to_html` before `#to_plain_text` equals after
- `content.fragment.object_id` unchanged
- `#render_attachments` does not rewrite the receiver’s HTML (attachment tags remain)
- gallery class stripping is constructor canonicalize only; `#to_plain_text` must not restrip or rewrap
- `#to_plain_text` is not `html_safe`

Assert `to_html` snapshots around every attachment case, not only the string result.

## Assertion categories

Use these buckets in characterization tests so a failure names the contract:

1. **Exact string equality** of `#to_plain_text` (newlines, bullets `•`, quotes `“”`, `☒`, NBSP).
2. **Non-`html_safe`** on the result.
3. **Canonical HTML freeze**: `to_html` pre/post; optionally `fragment.object_id`.
4. **Replacement isolation**: `#render_attachments` return value vs receiver HTML.
5. **Attribute-merge isolation**: `with_full_attributes: false` node HTML lacks filename/filesize; `true` has them; plain text of blobs unchanged.
6. **Attachable identity**: `attachments.first.attachable` class (`Blob` / `RemoteImage` / `MissingAttachable` / record) for the same fixture used in (1).
7. **Count / order**: `attachments.size`, duplicate concatenation order, gallery size 2 → two replacements.
8. **Sanitizer-on-copy**: original `content=` vs rendered copy’s `content=`.
9. **`canonicalize: false`**: inner HTML preserved in `to_html`, still absent from `to_plain_text`.

Do not assert Nokogiri tree shape or reducer call counts. Those are implementation.

## Refactor tripwires

A change is **not** behavior-preserving if it:

- resolves attachments only when `with_full_attributes: true`
- deduplicates SGIDs in plain text
- walks gallery attachments via `#render_attachment_galleries` and inserts extra newlines/spaces
- converts figcaptions and attachment captions with different bracket rules
- HTML-escapes the result or marks it `html_safe`
- lets `<script>` element text through, or strips entity-decoded `"<script>…"`
- mutates the receiver fragment (including `content=` sanitization in place)
- re-canonicalizes the `render_attachments` result (`canonicalize: true` would unwrap replacements)
- uses node `filename` instead of `attachable.filename` for blobs
- honors caption on `MissingAttachable`

Pin the gap cases above first; then refactor against that suite. Existing markup tests already lock the newline/list/blockquote table.
