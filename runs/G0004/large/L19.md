**Reject.** The claim is false: a deterministic equality predicate is a byte comparison against the stored column, and that column is allowed to hold more than the ciphertext `EncryptedAttributeType#serialize` produces today.

Current-scheme serialize is the right bind **only** when every stored value was written with that same serialize path. `extend_queries` exists because that is not the supported contract.

## Query vs read

These are different paths. Do not collapse them.

- **Read/decryption** (`EncryptedAttributeType#deserialize`): try current decrypt, then each previous type, then return the raw value if `support_unencrypted_data?`. A row loaded by id still decrypts after this “optimization.”
- **Query** (`ExtendedDeterministicQueries`): rewrite `where` / `exists?` / `find_by` hashes into `[plaintext] + previous_types.map { AdditionalValue }`. SQL never decrypts. If the bound value is only current ciphertext, previous-scheme and clean-text rows are invisible.

`previous_types` is not “legacy decrypt helpers.” It is the query-side list of extra serializations, including the NullEncryptor clean-text scheme when unencrypted data is supported:

```56:90:activerecord/lib/active_record/encryption/encrypted_attribute_type.rb
      def previous_types # :nodoc:
        @previous_types ||= {
          support_unencrypted_data? => build_previous_types_for(previous_schemes_including_clean_text),
        }
        @previous_types[support_unencrypted_data?] || build_previous_types_for(previous_schemes_including_clean_text)
      end
```

Expansion is already skipped when that list is empty (`!type.previous_types.empty?`). Removing it only deletes the cases the feature is for. The guide states the same split: previous schemes keep **reading** working, and with `extend_queries` they also add **query** ciphertexts.

I ran `extended_deterministic_queries_test.rb` + `encryption_schemes_test.rb` (27 runs, 0 failures) and a throwaway probe that stubbed `process_arguments` to a no-op. With expansion, previous-scheme and unencrypted rows match; without it they do not, while `record.reload` still returns the plaintext.

## Why “current ciphertext is enough” fails

`where`/`exists?` go through `RelationQueries` with `check_for_additional_values: true`. `ActiveRecord::Base.find_by` is intercepted separately because of statement-cache:

```23:31:activerecord/lib/active_record/encryption/extended_deterministic_queries.rb
      def self.install_support
        # ActiveRecord::Base relies on ActiveRecord::Relation ... prepared statements caching.
        ActiveRecord::Relation.prepend(RelationQueries)
        ActiveRecord::Base.include(CoreQueries)
```

Expansion turns the bound value into an Array (`StatementCache.unsupported_value?`), so `find_by` cannot cache `name = ?` with one current ciphertext. Dropping expansion re-enables that cache and permanently misses other stored forms.

`fixed: true` (default) writes with the **oldest** previous scheme (`serialize_with_oldest`). That can make *new* rows match a single bind, which is probably what the author observed. It does not cover:

- `deterministic: { fixed: false }` (new writes use the newest scheme; old rows keep old ciphertext)
- rows still in a previous `previous:` / global `config.previous` scheme
- clean-text rows while `support_unencrypted_data` is on (global or per-attribute)

Existing `encryption_schemes_test.rb` “use global previous schemes when performing queries” uses `fixed: true` + `downcase` previous schemes, so it can pass even without expansion. That test does not prove the claim.

## Minimal failing examples

Assume `extend_queries` stays on and expansion is removed. Models follow the test helpers (`EncryptedBook`, `encrypted_books.name`).

**1. `where(email: value)` — unencrypted row**

```ruby
ActiveRecord::Encryption.config.support_unencrypted_data = true
UnencryptedBook.create!(name: "Dune")
EncryptedBook.where(name: "Dune").exists? # false; stored "Dune", bound current ciphertext
```

Today this is `extended_deterministic_queries_test.rb` “Finds records when data is unencrypted” via `find_by`; add a `where` assertion.

**2. Array-valued predicate**

```ruby
UnencryptedBook.create!(name: "Dune")
EncryptedBook.create!(name: "Foundation")
EncryptedBook.where(name: ["Dune", "Foundation"]).pluck(:name)
# => ["Foundation"]  # "Dune" element never expanded to clean text
```

No array-predicate test exists in the encryption suite. `process_encrypted_query_argument` expands each String element.

**3. `find_by` (Relation vs Base / prepared cache)**

```ruby
UnencryptedBook.create!(name: "Dune")
EncryptedBook.where("id > 0").find_by(name: "Dune") # nil; Relation#find_by -> where
EncryptedBook.find_by(name: "Dune")                 # nil; CoreQueries no longer expands,
                                                    # statement cache binds one ciphertext
```

**4. Prepared/bound values**

With expansion, `process_arguments(..., false)` for `{ "name" => "Dune" }` is `["Dune", AdditionalValue, ...]` and the SQL is `IN`. Without it, `name = ?` binds `type.serialize("Dune")` only. Same plaintext, different stored bytes, no match.

**5. Per-attribute `support_unencrypted_data` overrides global**

```ruby
ActiveRecord::Encryption.config.with(support_unencrypted_data: false) do
  UnencryptedBook.create!(name: "Dune")
  EncryptedBookWithUnencryptedDataOptedIn.find_by(name: "Dune")  # nil without expansion
end

ActiveRecord::Encryption.config.support_unencrypted_data = true
UnencryptedBook.create!(name: "Dune")
EncryptedBookWithUnencryptedDataOptedOut.find_by(name: "Dune")   # nil even WITH expansion
```

Opt-in still needs clean-text `previous_types`. Opt-out must keep omitting them. That is already covered for `find_by`; keep `where` too.

**6. Key rotation through `previous:` (`fixed: false`)**

```ruby
klass = Class.new(ActiveRecord::Base) do
  self.table_name = "encrypted_books"
  encrypts :name, deterministic: { fixed: false }, key: "new secret key!!!!",
    previous: [{ deterministic: true, key: "old secret key!!!!" }]
end

plaintext = "user@example.com"
old_ct = klass.type_for_attribute(:name).previous_types.first.serialize(plaintext)
record = ActiveRecord::Encryption.without_encryption { klass.create!(name: old_ct) }

record.reload.name                         # "user@example.com"  (read still works)
klass.find_by(name: plaintext)             # nil
klass.where(name: plaintext).exists?       # false
klass.where(name: [plaintext]).exists?     # false
```

This is the rotation case the current tests do not exercise. `fixed: true` is the wrong counterexample.

**7. `downcase:`**

```ruby
EncryptedBookWithDowncaseName.create!(name: "Dune")
unencrypted = UnencryptedBook.create!(name: "dune")

# without expansion:
EncryptedBookWithDowncaseName.where.not(id: unencrypted.id).find_by(name: "DUNE") # still found
EncryptedBookWithDowncaseName.find_by(id: unencrypted.id, name: "DUNE")           # nil
```

Current serialize downcases then encrypts, so already-encrypted rows keep matching. Clean-text previous type also downcases; unencrypted `"dune"` needs that extra bind. Unencrypted `"Dune"` does **not** match `find_by(name: "DUNE")` even today (`"DUNE"` → clean serialize `"dune"`).

**8. `ignore_case` and `original_name`**

Queries run against `name`, not `original_name`. `ignore_case` sets `downcase` on the scheme; `original_name` is a separate **non-deterministic** encrypted column (`encrypts original_attribute_name` with no `deterministic: true`), so it is not in `deterministic_encrypted_attributes` and is never expanded.

```ruby
EncryptedBookThatIgnoresCase.create!(name: "Dune")
unencrypted = create_unencrypted_book_ignoring_case(name: "Dune") # SQL stores mixed-case "Dune"

EncryptedBookThatIgnoresCase.where.not(id: unencrypted.id).find_by(name: "dune")
# still found; name column holds downcased ciphertext; reader returns original_name "Dune"

EncryptedBookThatIgnoresCase.find_by(id: unencrypted.id, name: "dune")
# nil without expansion

# even WITH expansion, stored "Dune" != clean serialize("dune") == "dune"
create_unencrypted_book_ignoring_case(name: "dune")
EncryptedBookThatIgnoresCase.find_by(name: "DUNE") # found only because clean text is downcased
```

Do not treat `original_name` as a query fallback. It is a read-side case-preservation column.

## Focused regressions (not a replacement design)

Keep them in `extended_deterministic_queries_test.rb` / `encryption_schemes_test.rb`. Assert both “with expansion, found” and that `reload` still decrypts when the query misses.

- `where(name: "Dune")` and `where(name: ["Dune", "Foundation"])` with an unencrypted row
- `EncryptedBook.find_by` (Base / statement cache) and `EncryptedBook.where("id > 0").find_by` (Relation)
- global `support_unencrypted_data: false` + attribute `support_unencrypted_data: true` on `where` and `find_by`
- `deterministic: { fixed: false }` + `previous: [{ deterministic: true, key: other }]` persisted via `without_encryption` + old `serialize`; `reload.name` works; `find_by` / `where` / array `where` find the row **only with expansion**
- `downcase: true`: encrypted `"Dune"` found as `"DUNE"`; unencrypted `"dune"` found only with expansion
- `ignore_case: true`: encrypted `"Dune"` found as `"dune"` and `book.name == "Dune"`; unencrypted downcased `"dune"` found with expansion; assert `original_name` is not a deterministic query attribute

Do not add range/SQL-fragment coverage, uniqueness-validator changes, or a new query API. Uniqueness already walks `previous_types` on its own path (`ExtendedDeterministicUniquenessValidator`); same stored-form issue, out of scope unless this PR also touches it.

**Bottom line:** refuse the optimization. Current-scheme ciphertext is sufficient only when there are no previous types and unencrypted data is not supported — the implementation already no-ops in that case.
