`Object#with` is a temporary public-attribute swap: it reads each current value, writes the replacement, yields the receiver, then writes the saved values back. Restoration is keyed off `old_values`, not off the original keyword list, so only attributes that were successfully read get restored.

## Control flow

```31:43:activesupport/lib/active_support/core_ext/object/with.rb
  def with(**attributes)
    old_values = {}
    begin
      attributes.each do |key, value|
        old_values[key] = public_send(key)
        public_send("#{key}=", value)
      end
      yield self
    ensure
      old_values.each do |key, old_value|
        public_send("#{key}=", old_value)
      end
    end
  end
```

For each keyword, in hash insertion order:

1. `public_send(key)` reads the current value and stores it in `old_values`.
2. `public_send("#{key}=", value)` writes the replacement.
3. After every pair has been applied, `yield self` runs the block.
4. `ensure` walks `old_values` in the same insertion order and writes each saved value back.

The empty hash is allocated before `begin` ([with.rb:32](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L32)). The read/write loop, the yield, and the restore all sit inside `begin`/`ensure` ([with.rb:33-43](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L33-L43)). That is the whole method.

```diagram
attributes.each (insertion order)
  public_send(key)          ──▶ old_values[key] = current
  public_send("#{key}=", v) ──▶ attribute becomes replacement
yield self
ensure
  old_values.each           ──▶ public_send("#{key}=", old_value)
```

The documented one-attribute `begin`/`ensure` pattern in the comment ([with.rb:19-26](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L19-L26)) is the same idea, but the implementation generalizes it: it snapshots *all* requested attributes first, then restores only those snapshots.

Happy-path test: both attrs change inside the block and both originals return after it ([with_test.rb:32-43](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L32-L43)).

## What the block receives and returns

`yield self` ([with.rb:38](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L38)) passes the receiver, not a copy. The method’s return value is the block’s return value, because that is what `yield` returns and nothing after `ensure` overwrites it.

```91:98:activesupport/test/core_ext/object/with_test.rb
  test "yields the instance to the block" do
    assert_equal "1", @object.with(public_attr: "1", &:public_attr)
  end

  test "returns the result of the block" do
    result = @object.with(public_attr: "1") { :block_result }
    assert_equal :block_result, result
  end
```

`&:public_attr` only works if the yielded object is the same `Record` whose `public_attr` was just set to `"1"`. The second test asserts the method returns `:block_result`, not the receiver.

The comment states the same contract: “The receiver is yielded to the provided block.” ([with.rb:15](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L15))

## `ensure` when the block raises

If `yield self` raises, Ruby still runs `ensure`. `old_values` already contains every requested attribute, so every writer is called with the pre-`with` value.

```45:59:activesupport/test/core_ext/object/with_test.rb
  test "restore attribute if the block raised" do
    ...
    assert_raise RuntimeError do
      @object.with(public_attr: :changed, another_public_attr: :changed_too) do
        ...
        raise "Oops"
      end
    end

    assert_equal :public, @object.public_attr
    assert_equal :another_public, @object.another_public_attr
  end
```

The original exception still propagates (`assert_raise RuntimeError`). Restoration does not swallow it.

## Two attributes: first writer succeeds, second writer raises

This is the interesting path. `old_values` is populated *inside* the same `each` that assigns, and only *after* a successful read ([with.rb:34-36](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L34-L36)). A later `public_send("#{key}=", value)` that raises therefore leaves a partial `old_values`.

The test fixture is `Record`: public reader+writer for `public_attr`, public reader but private writer for `mixed_attr` ([with_test.rb:7-26](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L7-L26)).

```61:73:activesupport/test/core_ext/object/with_test.rb
  test "restore attributes if one of the setter raised" do
    assert_equal :public, @object.public_attr
    assert_equal :mixed, @object.mixed_attr

    assert_raise NoMethodError do
      @object.with(public_attr: :changed, mixed_attr: :changed_too) do
        assert false
      end
    end

    assert_equal :public, @object.public_attr
    assert_equal :mixed, @object.mixed_attr
  end
```

Step by step for `with(public_attr: :changed, mixed_attr: :changed_too)`:

1. `old_values` starts `{}`.
2. `public_send(:public_attr)` → `:public`. Stored as `old_values[:public_attr] = :public`.
3. `public_send("public_attr=", :changed)` succeeds. `public_attr` is now `:changed`.
4. `public_send(:mixed_attr)` → `:mixed`. Stored as `old_values[:mixed_attr] = :mixed`.
5. `public_send("mixed_attr=", :changed_too)` raises `NoMethodError` because `mixed_attr=` is private. `mixed_attr` never changes.
6. `yield self` does not run. The test’s `assert false` is the evidence: the block is dead code on this path ([with_test.rb:66-68](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L66-L68)).
7. `ensure` iterates `old_values`, which now has **both** keys:
   - `public_send("public_attr=", :public)` — undoes the successful first write.
   - `public_send("mixed_attr=", :mixed)` — this second restore also uses `public_send`, so it raises `NoMethodError` again.

The test still ends with `public_attr == :public` and `mixed_attr == :mixed` ([with_test.rb:71-72](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L71-L72)). That is because:

- `public_attr` is restored by the first `ensure` iteration, before the private writer is attempted.
- `mixed_attr` was never assigned in step 5, so it is still `:mixed` even if the restore writer also fails.

What the test does **not** pin down is which `NoMethodError` `assert_raise` catches — the original `mixed_attr=` in the setup loop, or the same call in `ensure`. In Ruby, an exception raised from `ensure` replaces the pending exception. The implementation calls `public_send("#{key}=", old_value)` for every snapshot, including attributes whose writer is not public ([with.rb:40-42](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L40-L42)). So if the second writer is not public, `ensure` raises that `NoMethodError` too.

The values that are actually restored are exactly the keys in `old_values` at the moment of the failure: every attribute whose reader succeeded, in insertion order. Attributes not yet reached are absent from `old_values` and are not touched. Attributes whose reader failed never enter `old_values` either.

If the *first* writer were the one that raised, `old_values` would still contain that first key (the read already happened), and `ensure` would try to write the original value back — then raise again if that writer is not public. The shipped test covers the “first succeeds, later writer raises” case, not the “reader fails before any write” case.

## Public reader and public writer

Both directions go through `public_send` ([with.rb:35-36](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L35-L36), [with.rb:41](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L41)). Private and protected methods are not used. The comment states the same requirement ([with.rb:29-30](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/object/with.rb#L29-L30)).

```75:89:activesupport/test/core_ext/object/with_test.rb
  test "only works with public attributes" do
    assert_raises NoMethodError do
      @object.with(private_attr: :changed) { }
    end

    assert_raises NoMethodError do
      @object.with(protected_attr: :changed) { }
    end

    assert_equal :mixed, @object.mixed_attr
    assert_raises NoMethodError do
      @object.with(mixed_attr: :changed) { }
    end
    assert_equal :mixed, @object.mixed_attr
  end
```

Three cases on `Record`:

| attribute | reader | writer | failure point |
|---|---|---|---|
| `private_attr` | private | private | `public_send(:private_attr)` |
| `protected_attr` | protected | protected | `public_send(:protected_attr)` |
| `mixed_attr` | public | private | `public_send("mixed_attr=", ...)` after a successful read |

`mixed_attr` is the split case: the public reader lets the snapshot succeed; the private writer is what raises. After that call, `mixed_attr` is still `:mixed` ([with_test.rb:84-88](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L84-L88)).

## Immediate classes where `#with` is removed

```47:51:activesupport/lib/active_support/core_ext/object/with.rb
# #with isn't usable on immediates, so we might as well undefine the
# method in common immediate classes to avoid potential confusion.
[NilClass, TrueClass, FalseClass, Integer, Float, Symbol].each do |klass|
  klass.undef_method(:with)
end
```

Those six classes inherit `Object#with` but cannot usefully mutate public attributes, so the method is undefined on them. The test checks `respond_to?` is false for `nil`, `true`, `false`, `1`, `1.0`, and `:sym` ([with_test.rb:100-107](file:///home/user/workspace/repo/activesupport/test/core_ext/object/with_test.rb#L100-L107)).

`String` is not in that list. Immediate-ness here means the six classes that are explicitly `undef_method`’d, not every immediate Ruby value.
