## Assistant

Treat `#touch` as a public operation with a public result. The oracle is the receiver after the call, a fresh `find`/`reload`, the exception, the return value, and callbacks you registered yourself. Do not compare `_touch_row`, `@_trigger_update_callback`, SQL AST, or any other private helper across the refactor.

The public envelope is:

```text
record.touch(*names, time:)
  → exception or return value
  → in-memory attributes, dirty APIs, lock_version
  → after_touch (during the call)
  → DB row via find/reload
  → after_commit or after_rollback
```

Use one model family per concern so failures stay local: a timestamped record (e.g. `Topic`), an aliased-timestamp record (`Developer` with `alias_attribute :updated_at, :legacy_updated_at`), a custom-column record (`Task`), a locking record (`Person`), and a no-timestamp record (`Car`).

### Record state

**Persisted.** `persisted?` is true, `new_record?`/`destroyed?`/`readonly?` are false. `touch` is truthy and does not raise. A later `find(id)` shows new timestamp values. That is the only proof the UPDATE landed.

**New.** `Model.new.touch` raises `ActiveRecord::ActiveRecordError` with `Cannot touch on a new or destroyed record object`. `Model.count` is unchanged. No `after_touch` / `after_commit`. Same for `create` never called and for `dup` of a persisted row.

**Destroyed.** Persist, `destroy`, then `touch`. Same exception and message as new. `destroyed?` stays true. A `find_by(id:)` remains nil. That shows the guard is `persisted?`, not “has an id.”

**Readonly record.** `record.readonly!` then `touch` raises `ActiveRecord::ReadOnlyRecord` with `"#{model} is marked as readonly"`. Timestamps on a fresh `find` are unchanged. `readonly?` is the public predicate.

**Guard order.** A new or destroyed record that is also `readonly!` still raises the “Cannot touch…” error, not `ReadOnlyRecord`. A persisted readonly record raises `ReadOnlyRecord` before any attribute work.

**Readonly column.** `touch(:born_at)` on a model with that column marked readonly raises `ActiveRecord::ActiveRecordError` with `"born_at is marked as readonly"`. Default `touch` on the same record still succeeds if the timestamp columns are writable.

### Timestamp columns, custom attributes, aliases

**Default timestamps.** `touch` with no names. In-memory `updated_at`/`updated_on` (or whichever of those columns the table actually has) move forward. `reload` matches. `created_at` does not change unless named. A table with neither timestamp column (`Car.first.touch`) raises nothing and is truthy; a fresh `find` is byte-identical.

**Custom names.** `task.touch(:ending)` and `task.touch(:starting, :ending)` update those attributes to the touch time **and** still update the default update timestamps when those columns exist. `reload` confirms every named column. Extra names are additive; they do not replace the timestamp set.

**Aliases.** On `Developer`, `touch` with no names writes the real columns (`legacy_updated_at`, `legacy_updated_on`). Public proof: `saved_changes.keys` and `reload.legacy_updated_at`. `touch(:updated_at)` using the alias updates that same column; reading either `updated_at` or `legacy_updated_at` after `reload` agrees. The alias is resolved before the write; the DB column name is what `saved_changes` and `reload` show.

**Validations.** Make the record invalid, then `touch`. Timestamps still change on `reload`. `valid?` is still false. That is the public “no validation” clause. `before_validation` / `before_save` / `after_save` counters stay at zero.

### Explicit time

`touch(time: t)` and `touch(:created_at, time: t)` write `t` (not `Time.now`) onto every touched column. Compare the in-memory values and the `reload` values to `t`, not to wall clock. A `travel` block around a no-`time:` call shows the default clock is “now”; the same `t` passed in and out of `travel` shows the keyword wins. Named columns and default update timestamps receive the **same** `t`.

### Optimistic locking

On a locking model (`lock_version` present, `lock_optimistically` on):

**Fresh row.** `touch` increments `lock_version` in memory and in `find(id).lock_version`. `saved_changes` includes both `lock_version` and the update timestamps. `changed?` is false afterward.

**Stale row.** Load A and B; update A; `B.touch` raises `ActiveRecord::StaleObjectError`. B’s `lock_version` is unchanged, `saved_changes?` is false, `find(id)` equals A. The public contract is “touch is a locking update,” not a particular WHERE clause.

**Concurrent delete under locking.** `Model.delete(id)` then `record.touch` is the same stale path: `StaleObjectError`, no `after_touch`, in-memory `lock_version` unchanged.

### Dirty tracking and saved changes

Start from a persisted record with an unsaved attribute change (e.g. `salary += 1`).

After `touch`:

- `changed?` is still true and `changed` still lists only the unsaved attribute.
- Touched timestamp columns are **not** in `changed` (`updated_at_changed?` is false).
- `saved_changes?` is true and `saved_changes.keys` are exactly the columns the touch persisted (timestamps, plus `lock_version` when locking, plus named extras). The unsaved attribute is absent.
- `reload` restores the unsaved attribute to the DB value and keeps the new timestamps.

That split — dirty unsaved attrs left dirty and unwritten; touched attrs applied, cleared, and recorded in `saved_changes` — is the whole dirty contract. Do not inspect mutation objects.

### Callbacks

Install probes as public `after_touch`, `after_commit`, `after_commit(on: :update)`, `after_rollback`, `after_rollback(on: :update)`, and also `after_save` / `before_validation` as negative controls. Record a call log on the instance.

**Successful persisted `touch`.** Log is `after_touch` then `after_commit` / `after_commit(on: :update)`. `after_save` and validation callbacks are absent. Nested `transaction(requires_new: true)` does not fire `after_commit` until the outermost commit.

**Explicit rollback.** `transaction { record.touch; raise ActiveRecord::Rollback }` → `after_touch` ran, `after_commit` did not, `after_rollback` / `after_rollback(on: :update)` did. After the block, in-memory timestamps and `lock_version` match the pre-touch values (transaction restore). `reload` matches the pre-touch DB row.

**`no_touching`.** `Model.no_touching { record.touch }` leaves timestamps, dirty state, and the callback log unchanged. That is a public suppression observation, not a private flag.

**New/destroyed/readonly.** The exception fires with an empty callback log.

### No row updated (no locking)

Keep an in-memory persisted record, then delete its row without the instance (`Model.delete(id)`). `persisted?` is still true. Call `touch`.

Public observations that define this case:

- Return value is falsey (`false`).
- `after_touch` ran (the instance method finished).
- `after_commit` / `after_commit(on: :update)` did not.
- `after_rollback` ran (the false return aborts the persistence transaction).
- In-memory timestamps match the pre-touch values (rollback restores the record).
- `find_by(id:)` is still nil.

That set is the contract. Do not assert affected-row counts or internal trigger flags. Contrast with locking, where the same setup raises `StaleObjectError` and skips `after_touch`.

Contrast also with “default scope hides the row”: `becomes` a subclass whose default scope excludes it, then `touch`. A fresh unscoped `find` still shows new timestamps. Hidden-by-scope is not the no-row case.

### How to use this as a preservation check

For each row below, run the same probes on the old and new `#touch`. Preservation means identical public outcomes, not identical internals.

| Case | Public oracle |
|---|---|
| New / destroyed | `ActiveRecordError` + message; no row; empty callback log |
| Readonly record | `ReadOnlyRecord` + message; `find` unchanged |
| Readonly column | `ActiveRecordError` `"#{name} is marked as readonly"` |
| Persisted default touch | truthy; `reload` timestamps moved; `saved_changes` keys; `changed?` false if starting clean |
| Custom / aliased names | `reload` of real columns; `saved_changes.keys` use column names, not aliases |
| `time:` | in-memory and `reload` equal `t` on every touched column |
| Dirty leftover attrs | still in `changed`; absent from `saved_changes`; restored by `reload` |
| Locking success | `lock_version` + 1 in memory and `find`; in `saved_changes` |
| Locking stale / missing row | `StaleObjectError`; no `saved_changes`; no `after_touch` |
| Happy path callbacks | `after_touch` then `after_commit(on: :update)`; no save/validation callbacks |
| Rollback | `after_rollback(on: :update)`; attributes restored |
| 0-row, no locking | falsey return; `after_touch` yes; `after_commit` no; `after_rollback` yes; memory restored; row still gone |
| No timestamp columns | truthy; no exception; `find` identical |

If those observations match, the refactor preserved `#touch`. If any diverge, the contract changed, even when every private helper still looks equivalent.
