## Lazy populate and repeat access (SQLite, executed)

Empty cache, table `courses` (3 columns, PK `"id"`, 1 index):

| Call | First | Repeat | What the first query is |
|---|---|---|---|
| `data_source_exists?("courses")` | **1** | **0** | full `data_sources` list; result `true`; `@data_sources` filled for every non-ignored table |
| `columns("courses")` | **1** | **0** | `connection.columns`; does **not** fill `@data_sources` |
| `columns_hash("courses")` on empty cache | **1** | **0** | same SQL as `columns`, then `index_by(&:name).freeze` |
| `columns_hash` after `columns` | **0** | **0** | derived only |
| `primary_keys("courses")` | **2** | **0** | data-source list + `connection.primary_key` |
| `primary_keys` after data sources filled | **1** | **0** | PK only |
| `indexes("courses")` | **3** | **0** | list + SQLite index list + index details |
| `indexes` after data sources filled | **2** | **0** | the two index SQLs |

Exact assertions that catch an extra round trip:

- `assert_queries_count(1, include_schema: true) { cache.columns("courses") }` then `assert_no_queries(include_schema: true) { cache.columns("courses") }`
- `assert_equal 3, cache.columns("courses").size` and `assert_equal 3, cache.columns_hash("courses").size`
- `assert_equal "id", cache.primary_keys("courses")`
- `assert_equal 1, cache.indexes("courses").size`
- `assert cache.data_source_exists?("courses")`

`columns_hash?` stays false through `data_source_exists?` and `columns`; true only after `columns_hash`. `cached?` becomes true after `columns` (`@columns.key?`), not after data-source listing alone.

`primary_keys` / `indexes` call `data_source_exists?` first. `columns` / `columns_hash` do not. A refactor that starts checking existence inside `columns` adds a query and fails the `columns` first-access count of 1.

## `add` and `clear!`

`add("courses")` on empty SQLite cache is **5** schema queries: 1 list + 1 PK structure + 1 columns structure (a second, identical `table_structures` read) + 2 index queries. `columns_hash` adds 0. After `add`:

```ruby
assert_no_queries(include_schema: true) do
  assert cache.data_source_exists?("courses")
  assert_equal 3, cache.columns("courses").size
  assert_equal 3, cache.columns_hash("courses").size
  assert_equal "id", cache.primary_keys("courses")
  assert_equal 1, cache.indexes("courses").size
end
```

Fewer than 5 on SQLite means a reader was skipped or results were shared across `primary_keys` and `columns` (current code does not share that work). More than 5 is an extra round trip.

`add("omgponies")` is **2** queries (list + per-name exists). It stores `@data_sources["omgponies"] = false` only. `@columns`, `@primary_keys`, `@indexes` stay empty. `size` becomes 6 (5 listed tables + the false entry). `size` never counts `@indexes`.

`clear!` on the bound reflection issues **0** queries, replaces the cache, `size == 0`, `cached?("courses")` is false. Next `columns("courses")` is **1** again; next `data_source_exists?("courses")` is **1** (full list). If those stay 0, the old maps leaked.

`clear_data_source_cache!("courses")` after a full list is **0** queries. Next `data_source_exists?("courses")` is **exactly 1** targeted exists (not a full list). A full-list query here is a regression. Repeat after that is 0.

Stale-entry trap: populate `columns("courses")`, then `connection.add_column(:courses, :extra, :string)` **without** clear. `columns("courses")` must still return 3 columns and **0** queries. After `clear_data_source_cache!("courses")` or `clear!`, it must query and see the new column. If a refactor starts auto-invalidating, that is a behavior change.

## Nonexistent tables

| Call | First (empty) | Repeat | Result |
|---|---|---|---|
| `data_source_exists?("foo")` | **2** | **0** | `false`, stored |
| `data_source_exists?("foo")` after list | **1** | **0** | per-name only |
| `primary_keys("omgponies")` | **2** | **0** | `nil` |
| `indexes("omgponies")` | **2** | **0** | `[]` |
| `columns("omgponies")` | **1** then `StatementInvalid` | n/a | not stored |
| `columns_hash("omgponies")` | same raise | n/a | via `columns` |

Repeat 0 for missing PK/indexes is **not** because those hashes stored `nil`/`[]`. `Hash#fetch` does not write the block result; `@data_sources["omgponies"] == false` makes the next `data_source_exists?` free. Assert `@primary_keys` / `@indexes` do not contain `"omgponies"`, and that `clear_data_source_cache!("omgponies")` makes the next PK/indexes lookup query again.

`add` of a missing table must not call `connection.columns` / `primary_key` / `indexes`.

## Schema-ignored tables (string and regexp)

`ActiveRecord.with(schema_ignored_tables: ["professors"])` and `with(schema_ignored_tables: [/^profess/])` are the same observable contract (`ignored === table_name`):

- `data_source_exists?("professors")` → `nil` (not `false`), **0** queries, not stored
- `columns` / `columns_hash` → `ActiveRecord::StatementInvalid` (`Table 'professors' doesn't exist`), **0** queries
- `primary_keys` → `nil`, **0**
- `indexes` → `[]`, **0**
- `add("professors")` → **0**, `size == 0`

`data_source_exists?("courses")` is still **1** (list minus ignored names). Listed keys must be `dogs`, `courses_professors`, `colleges`, `courses` — never `professors`. Dump then load under the same ignore list: `courses` served with **0** queries; `professors` still ignored as above. A query against `professors` while it is ignored is an extra round trip.

## Duplicate-cache independence

Two fresh `SchemaCache` instances do not share maps. After A records `data_source_exists?("foo")`, B still pays **2** queries for the same name.

`dup` copies the five hashes (`initialize_dup`) but not the frozen column objects. After `original.clear_data_source_cache!(pool, "courses")`:

- `dup.columns(pool, "courses")` is **0** (still cached)
- `original.columns(pool, "courses")` is **1** (refill)

If both stay 0, the hashes were shared. If `dup` refills, the copy was too deep or missed `@columns`.

## Frozen / deduplicated values

On the live populate path (empty cache, `courses`):

- each `Column` is frozen; the same `Column` instance is reused across caches (`equal?`)
- column `name` strings and `sql_type_metadata` are interned (`equal?` across caches)
- `primary_keys` returns frozen `"id"`
- `columns_hash` is frozen; values are those frozen columns
- the `columns` **array** is not frozen
- `IndexDefinition` is not `Deduplicable`; index arrays/items are not frozen

YAML/`init_with` without `"deduplicated" => true` runs `derive_columns_hash_and_deduplicate_values` and rebuilds `@columns_hash` **without** `freeze`. Marshal load does the same. Do not assert a frozen hash after dump load; do assert it after live `columns_hash`. `"deduplicated" => true` must leave `coder["columns"]` as the same object (`assert_same`).

## Dump / load (YAML, Marshal, gzip, old dumps)

`encode_with` writes sorted `columns`, `primary_keys`, `data_sources`, `indexes`, plus `version`. It does **not** write `columns_hash`. `marshal_dump` is `[@version, @columns, {}, @primary_keys, @data_sources, @indexes]` — slot 2 is always `{}`.

After `dump_to` + `load!` of `.yml`, `.dump`, `.yml.gz`, or `.dump.gz`:

```ruby
assert_no_queries(include_schema: true) do
  assert_equal 3, cache.columns("courses").size
  assert_equal 3, cache.columns("courses").map { |c| c.cast_type }.compact.size
  assert_equal 3, cache.columns_hash("courses").size
  assert cache.data_source_exists?("courses")
  assert_equal "id", cache.primary_keys("courses")
  assert_equal 1, cache.indexes("courses").size
end
```

Any query here is an extra metadata round trip (dump member dropped or not reconstructed).

Gzip: `Zlib::GzipWriter#mtime = 0`. Two dumps one second apart must have identical MD5. A changing header is a determinism break.

Old YAML without `indexes` (`schema_dump_5_1.yml`): `columns("posts")` / `columns_hash("posts")` / `data_source_exists?("posts")` / `primary_keys("posts")` are **0** queries (11 columns, PK `"id"`). `init_with` sets `@indexes = {}`. `indexes("courses")` **must query** (`assert_queries_count(include_schema: true)` is only “≥ 1”; on sqlite3_mem against arunit2 it is **3**: per-name exists, because `courses` is not in that dump’s `@data_sources`, plus two index SQLs). Repeat is **0**. If this becomes 0 on first call, indexes were invented or the empty hash was treated as populated.

Old Marshal with no indexes slot: `marshal_load` of 5 elements sets `@indexes = {}`; `indexes("courses")` queries (2 on SQLite when data sources already include `courses`); `columns` / `primary_keys` stay **0**.

`test_yaml_loads_5_1_dump` uses `assert_no_queries` **without** `include_schema: true`. Do not copy that; it cannot see SCHEMA traffic.

## Schema version and `check_schema_cache_dump_version`

`version(pool)` is **1** then **0**; `schema_version` is the memoized value (0 in this suite).

Check **on** (default): `cached?` is false until a pool is available. Load of a dump whose `version` ≠ `connection.schema_version` writes `Ignoring ... expired. The current schema version is X, but the one in the schema cache file is Y.` to stderr, discards the dump, and installs an empty cache. That load is **1** version query; the next `columns("courses")` is a live **1**. If it stays 0, the expired dump was used (stale entries). If version-check failure (`ActiveRecordError`) occurs, stderr matches `Failed to validate the schema cache because of ...` and the dump is also discarded.

Check **off**: `SchemaReflection.with(check_schema_cache_dump_version: false)`:

- `cached?("courses")` is true with **0** queries and no pool (`BoundSchemaReflection.new(reflection, :__unused_pool__)`)
- a dump with version `999999` loads with empty stderr; `columns` / `indexes` / `primary_keys` / `data_source_exists?` are **0** — stale dump is intentionally served

## Adapter portability

Pin exact first-access numbers only where this suite runs them (sqlite3_mem above). PostgreSQL / MySQL / Trilogy were not executed here.

Portable across adapters:

- repeat hit = 0
- ignored / missing **results** (`nil` / `false` / `[]` / `StatementInvalid`)
- `add` fills all four maps iff the table exists
- dump load of dumped members = 0
- old dump without indexes still queries `indexes`
- composite PK array vs nil for no PK
- gzip MD5 identity
- version-check on/off behavior

Not portable (do not hard-code SQLite 3/5):

- first-access SQL count for `indexes` (SQLite 2 after list; PG/MySQL are typically one `information_schema` / `pg_index` read)
- `add` total (SQLite 5 because PK and columns each call `table_structures`; other adapters usually 1 per reader)
- `version` SQL shape
- `lazily_load_schema_cache` connection-establish test (`unless in_memory_db?`)

On another adapter, capture first-access once with `include_schema: true` and treat that number as the ceiling: a later increase is an extra round trip; a decrease is a change in reader batching, not silently acceptable if the goal is preservation of the current call pattern.

Existing tests in [schema_cache_test.rb](file:///home/user/workspace/repo/activerecord/test/cases/connection_adapters/schema_cache_test.rb) already cover dump/load, gzip identity, 5.1 indexes gap, ignore string/regexp, composite PK, `clear!` size 0, `clear_data_source_cache!` count 1, and check-off `cached?`. They do **not** pin first-access counts for `columns` / `primary_keys` / `indexes` / `add`, duplicate-cache independence, live freeze/dedup, or stale-until-clear. Those are the gaps a preservation suite has to add.
