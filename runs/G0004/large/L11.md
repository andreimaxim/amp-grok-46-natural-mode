Current contract: `#local` stores wall-clock fields on a UTC-valued `Time`, then `TimeWithZone` resolves a TZInfo period. Gaps jump forward one hour; ambiguity prefers DST when the flag works, otherwise `periods.last`. I ran the existing `#local` cases: 5 runs, 21 assertions, 0 failures.

## Conversion the tests lock

```text
TimeZone#local(*args)
  Time.utc(*args)                         # wall clock as UTC-valued Time, not a UTC instant
  TimeWithZone.new(nil, self, time)       # local-time constructor
    get_period_and_ensure_valid_local_time
      period_for_local(time, dst: true)
        on PeriodNotFound: @time += 1.hour; retry
    utc = incorporate_utc_offset(@time, -utc_offset)
```

Evidence: [`time_zone.rb` `#local`](file:///home/user/workspace/repo/activesupport/lib/active_support/values/time_zone.rb#L370-L378), [`TimeWithZone#initialize`](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L50-L60), [gap retry](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L565-L575), [`period_for_local`](file:///home/user/workspace/repo/activesupport/lib/active_support/values/time_zone.rb#L578-L579), lazy [`#utc`](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L68-L70), [`#dst?`](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L99-L101) / [`#zone`](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L138-L140).

Invariants from that path and [`time_zone_test.rb`](file:///home/user/workspace/repo/activesupport/test/time_zone_test.rb#L201-L245):

1. `#time` keeps local Y/M/D/H/M/S on a `Time` with `utc? == true`.
2. `#utc` is that wall clock minus `period.observed_utc_offset` (the comparable instant; `#==` uses `#utc`).
3. Invalid spring-forward local times are not errors: the wall clock is advanced one hour and re-resolved.
4. Ambiguous local times prefer DST when TZInfo honors `dst: true`; otherwise the block `{ |periods| periods.last }` wins.
5. `#zone` is `period.abbreviation`; `#dst?` is `period.dst?`; `#time_zone` is the receiver.
6. Pre-1900 local components must survive even when a `Time.utc(...)` equality would be unsafe; the suite uses `#to_a[0, 6]`.

Observables to assert on every case: `#time` (or `#to_a[0,6]`), `#utc` (or `#==` against a UTC `Time`), `#zone`, `#dst?`, and `#time_zone`. `#utc_offset` is implied by `#time` minus `#utc` and is worth asserting where DST vs standard is the point.

## 1. Ordinary Hawaii date

**Input:** `ActiveSupport::TimeZone["Hawaii"].local(2007, 2, 5, 15, 30, 45)`  
**Existing case:** [`test_local`](file:///home/user/workspace/repo/activesupport/test/time_zone_test.rb#L201-L205)

| Observable | Current value |
|---|---|
| local components `#time` | `Time.utc(2007, 2, 5, 15, 30, 45)` |
| UTC instant `#utc` | `Time.utc(2007, 2, 6, 1, 30, 45)` |
| abbreviation `#zone` | `"HST"` |
| DST `#dst?` | `false` |
| `#time_zone` | Hawaii |
| `#utc_offset` | `-36000` |

The existing test only locks `#time` and `#time_zone`. A preservation suite should also lock `#utc`, `#zone`, and `#dst?` so a refactor cannot keep the wall clock and still pick the wrong period.

**Detects:** constructing a real UTC instant instead of a UTC-valued wall clock; dropping the `TimeWithZone` wrapper; applying an Eastern-style offset; inventing DST in a zone that is HST year-round in 2007.

## 2. US Eastern 2006 spring-forward: 01:59:59, 02:00, 02:30

**Zone:** `ActiveSupport::TimeZone["Eastern Time (US & Canada)"]`  
**Existing case:** [`test_local_enforces_spring_dst_rules`](file:///home/user/workspace/repo/activesupport/test/time_zone_test.rb#L213-L230)  
**Mechanism:** TZInfo raises `PeriodNotFound` for 02:00 and 02:30; [`get_period_and_ensure_valid_local_time`](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L571-L574) does `@time += 1.hour` and retries.

### 2a. `zone.local(2006, 4, 2, 1, 59, 59)` — last valid EST second

| Observable | Current value |
|---|---|
| `#time` | `Time.utc(2006, 4, 2, 1, 59, 59)` |
| `#utc` | `Time.utc(2006, 4, 2, 6, 59, 59)` |
| `#zone` | `"EST"` |
| `#dst?` | `false` |
| `#utc_offset` | `-18000` |

**Detects:** treating 01:59:59 as already in the gap; jumping it to 02:59:59/03:59:59; selecting EDT one second early.

### 2b. `zone.local(2006, 4, 2, 2)` — missing 02:00

| Observable | Current value |
|---|---|
| `#time` | `Time.utc(2006, 4, 2, 3)` (requested 02:00, stored 03:00) |
| `#utc` | `Time.utc(2006, 4, 2, 7)` |
| `#zone` | `"EDT"` |
| `#dst?` | `true` |
| `#utc_offset` | `-14400` |

**Detects:** raising `PeriodNotFound`; leaving 02:00 on `#time`; jumping two hours; mapping 02:00 to 06:00 UTC (EST) instead of 07:00 (EDT); DST flag/abbrev disagreeing with the shifted wall clock.

### 2c. `zone.local(2006, 4, 2, 2, 30)` — missing 02:30

| Observable | Current value |
|---|---|
| `#time` | `Time.utc(2006, 4, 2, 3, 30)` |
| `#utc` | `Time.utc(2006, 4, 2, 7, 30)` |
| `#zone` | `"EDT"` |
| `#dst?` | `true` |

**Detects:** snapping every gap time to 03:00 (losing the 30-minute residue); jumping 30 minutes instead of 60; only covering the 02:00 boundary.

**Pair invariant (01:59:59 vs 02:00):** `#utc` values are consecutive Unix seconds (`1143961199` then `1143961200`). The skipped hour is a hole in local civil time, not in UTC. A refactor that invents a 02:00 EST instant, or that makes 02:00 EDT equal 01:59:59 EST, fails this pair.

```bash
cd activesupport && bin/test test/time_zone_test.rb -i test_local_enforces_spring_dst_rules
```

## 3. Ambiguous US Eastern fall-back hour

**Input:** `zone.local(2006, 10, 29, 1)`  
**Existing case:** [`test_local_enforces_fall_dst_rules`](file:///home/user/workspace/repo/activesupport/test/time_zone_test.rb#L232-L241)  
**Comment in test:** “Mirroring Time.local behavior, this method selects the DST time.”  
**Mechanism:** [`period_for_local(time, dst = true)`](file:///home/user/workspace/repo/activesupport/lib/active_support/values/time_zone.rb#L578-L579). For this instant TZInfo has two periods; `dst: true` yields EDT.

| Observable | Current value | Rejected alternative (`dst: false`) |
|---|---|---|
| `#time` | `Time.utc(2006, 10, 29, 1)` | same wall clock |
| `#utc` | `Time.utc(2006, 10, 29, 5)` | `Time.utc(2006, 10, 29, 6)` |
| `#zone` | `"EDT"` | `"EST"` |
| `#dst?` | `true` | `false` |
| `#utc_offset` | `-14400` | `-18000` |

`#time` alone cannot distinguish the two meanings of 01:00. `#utc`, `#zone`, and `#dst?` must all be asserted.

**Detects:** preferring standard time (the later occurrence); raising `AmbiguousTime`; using `periods.first` vs `periods.last` in a way that would pick EST here (this case is actually decided by `dst: true`, not the block).

## 4. Moscow 2014 ambiguous local time

**Input:** `ActiveSupport::TimeZone["Moscow"].local(2014, 10, 26, 1, 0, 0)`  
**Existing `#local` case:** [`test_local_with_ambiguous_time`](file:///home/user/workspace/repo/activesupport/test/time_zone_test.rb#L243-L245)  
**Related period case:** [`test_period_for_local_with_ambiguous_time`](file:///home/user/workspace/repo/activesupport/test/time_zone_test.rb#L58-L62)

Both candidate periods are `dst? == false` (`MSK` +4 then `MSK` +3). TZInfo raises `AmbiguousTime` for `dst=true`, `false`, and `nil`. The [`periods.last` block](file:///home/user/workspace/repo/activesupport/lib/active_support/values/time_zone.rb#L578-L579) selects offset `10800`.

The existing `#local` test only asserts `twz == Time.utc(2014, 10, 25, 22, 0, 0)`, which is [`#<=>` via `#utc`](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L246-L248). That locks the instant, not the wall clock.

| Observable | Current value | Rejected (`periods.first`, +4) |
|---|---|---|
| local `#time` | `Time.utc(2014, 10, 26, 1, 0, 0)` | same |
| UTC `#utc` / `#==` | `Time.utc(2014, 10, 25, 22, 0, 0)` | `Time.utc(2014, 10, 25, 21, 0, 0)` |
| `#zone` | `"MSK"` | `"MSK"` |
| `#dst?` | `false` | `false` |
| `#utc_offset` | `10800` | `14400` |

Because abbreviation and DST are identical, `#utc` / `#utc_offset` are the disambiguators. Do not treat this as “prefer DST”: both sides are standard time.

**Detects:** relying only on `dst: true` (raises, or if rescued wrongly, mis-picks); taking `periods.first`; collapsing this to the Eastern fall-back rule; changing `#==` to compare wall clocks so the existing assertion would pass for the wrong instant.

```bash
cd activesupport && bin/test test/time_zone_test.rb -i test_local_with_ambiguous_time
```

## 5. Old pre-1900 date

**Input:** `ActiveSupport::TimeZone["Hawaii"].local(1850, 2, 5, 15, 30, 45)`  
**Existing case:** [`test_local_with_old_date`](file:///home/user/workspace/repo/activesupport/test/time_zone_test.rb#L207-L211)

The suite does **not** compare `#time` to `Time.utc(1850, ...)` (unlike 2007). It uses [`#to_a`](file:///home/user/workspace/repo/activesupport/lib/active_support/time_with_zone.rb#L460-L463):

|---|---|

| `#time_zone` | Hawaii |
| `#zone` | `"LMT"` (not `"HST"`) |
| `#dst?` | `false` |
| `#utc` | `1850-02-06 02:02:11 UTC` |
| `#utc_offset` | `-37886` (LMT −10:31, not HST −10:00) |

Keep `#to_a[0, 6]` as the local-component assertion. A `Time.utc(1850, ...)` equality is a different, platform-sensitive contract the current tests deliberately avoid.

**Detects:** year-2038 / pre-epoch construction failures; rewriting 1850 through a modern HST −10:00 period (`#utc` would become `1850-02-06 01:30:45`, `#zone` `"HST"`); truncating the year; dropping sub-hour LMT offset.

## What a green run does and does not prove

These five methods already cover the named civil times. Together they prove: UTC-valued wall clock in, period resolution, one-hour gap skip, DST-preferring Eastern overlap, `periods.last` Moscow overlap, and pre-1900 component survival.

They do **not** by themselves prove: Hawaii `#utc`/`#zone` on the happy path; Moscow wall clock (only the UTC instant); 1850 LMT vs HST; that 01:59:59 and 02:00 are consecutive UTC seconds. If a refactor touches period selection or offset application, add those extra observables on the same inputs rather than new civil times.

I did not change any implementation. Assumption: the current tests plus the conversion source are the preservation oracle, not TZInfo’s default `AmbiguousTime` behavior.
