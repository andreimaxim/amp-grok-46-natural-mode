### Persistence: query, then replace internals

```748:763:activerecord/lib/active_record/persistence.rb
    def reload(options = nil)
      self.class.connection_pool.clear_query_cache

      fresh_object = if apply_scoping?(options)
        _find_record((options || {}).merge(all_queries: true))
      else
        self.class.unscoped { _find_record(options) }
      end

      @association_cache = fresh_object.instance_variable_get(:@association_cache)
      @association_cache.each_value { |association| association.owner = self }
      @attributes = fresh_object.instance_variable_get(:@attributes)
      @new_record = false
      @previously_new_record = false
      self
    end
```

`fresh_object` is discarded. `self` stays the same object (`equal?` is true; `object_id` does not change). What changes is the attribute set, the association cache, and the persistence flags.

`_find_record` always goes through `find_by!` on the in-memory primary key (or query-constraints hash). No row means `RecordNotFound`. `:lock` is passed through as pessimistic locking.

### Scoped versus unscoped lookup

`apply_scoping?` is the gate:

```858:861:activerecord/lib/active_record/persistence.rb
      def apply_scoping?(options)
        !(options && options[:unscoped]) &&
          (self.class.default_scopes?(all_queries: true) || self.class.global_current_scope)
      end
```

A plain `default_scope` does **not** apply on reload. Only a default scope declared with `all_queries: true`, or a `scoping(all_queries: true)` block (`global_current_scope`), does. `reload(unscoped: true)` forces the unscoped path even then.

When scoping applies, Persistence merges `all_queries: true` into the find options. `_find_record` then uses `all_queries_scope`, which:

- builds default scopes with `all_queries: true`, so only those `DefaultScope` objects whose own `all_queries` flag is true are composed (`execute_scope?` is `all_queries.nil? || all_queries && default_scope_obj.all_queries`)
- then merges `global_current_scope`

Ordinary `Model.where(...).scoping { record.reload }` does **not** add that `where` to reload. `scoping(all_queries: true)` does.

Tests in [default_scoping_test.rb](file:///home/user/workspace/repo/activerecord/test/cases/scoping/default_scoping_test.rb#L300-L359):

| Call | SQL on reload |
|---|---|
| plain `default_scope { where(mentor_id: 1) }` | no `mentor_id` |
| `default_scope ..., all_queries: true` | has `mentor_id` |
| mixed: one with `all_queries`, one without | only the `all_queries` clause |
| `reload(unscoped: true)` | no `mentor_id` |
| `where(salary:).scoping { reload }` | `mentor_id`, no `salary` |
| `where(salary:).scoping(all_queries: true) { reload }` | both |

If an `all_queries` default scope (or global current scope) hides the row, `find_by!` raises `RecordNotFound`. That raise is the same mechanism as a deleted row; the scoping tests assert the `WHERE`, not the exception.

### Association cache: replace, then rebind owner

`fresh_object` is a newly instantiated record. Its `@association_cache` is empty unless `_find_record` preloaded `strict_loaded_associations`. Persistence copies that hash onto `self`, then walks every cached `Association` and sets `association.owner = self`.

Without that rebind, the association objects still belong to the throwaway `fresh_object`. Later writes through inverses / autosave would mutate the discarded record. [ReloadAssociationCacheTest](file:///home/user/workspace/repo/activerecord/test/cases/persistence/reload_association_cache_test.rb) is the regression: after `publication.reload`, assigning `editors` inside a transaction still runs `after_save_commit` on **this** publication (`name` becomes `"Rails Way (touched)"`).

`Association#reload` / `collection.reload` is a different method: it resets and reloads one association’s target. Parent `record.reload` does not do that; it drops the old cache.

### Dirty: reset both mutation trackers

### Observable cases

Object identity is unchanged in every successful path. `reload` returns `self`. Internal state (`@attributes`, `@association_cache`, mutation trackers, `@new_record`) is replaced.

**Unsaved local attribute change.** Queries. Before: `changed?` true, in-memory value differs from the row. After: `changed?` false, attributes restored from the database. Same object. Covered by the Dirty test above; [test_reload](file:///home/user/workspace/repo/activerecord/test/cases/base_test.rb#L1321-L1327) is the two-instance version (t1 saves, t2.reload sees it).

**`saved_changes` after a prior save.** After `save!`, `saved_changes?` is true and the hash has the saved attributes. After `reload`, that tracker is nilled, so `saved_changes?` is false and `saved_changes` is `{}`. Still queries; still the same object. Inferred from Dirty#reload + `NullMutationTracker`; not asserted in the suite.

**Row hidden by a default scope.** A default scope *without* `all_queries: true` is ignored: reload queries unscoped and finds the row. A default scope *with* `all_queries: true` is applied: reload queries with that `WHERE`. If the row no longer matches, `find_by!` raises. `reload(unscoped: true)` queries without those scopes and can find a row the default scope would hide. SQL shape is in the default-scoping tests listed above.

**Deleted row.** Queries, then raises `RecordNotFound`. Same object is left as it was (the steal of `@attributes` never runs). [test_delete_all_with_group_by_and_having](file:///home/user/workspace/repo/activerecord/test/cases/relation/delete_all_test.rb#L79) asserts `deleted_post.reload` raises.

It does not refresh the old target in place. The next `record.comments` queries and sees the new rows. Parent identity is unchanged; associated objects loaded after reload are new instances. Contrast: `record.comments.reload` queries only the association and updates that cache in place ([test_force_reload](file:///home/user/workspace/repo/activerecord/test/cases/associations_test.rb#L117-L133)). The empty-cache-after-parent-reload behavior is from the steal of `@association_cache`, not from a dedicated suite test.

| Case | Queries? | Raises? | Identity | Internal state |
|---|---|---|---|---|
| Unsaved attr, then `reload` | yes | no | same | attrs + dirty trackers replaced |
| Save, then `reload` | yes | no | same | `saved_changes` cleared |
| Hidden by plain `default_scope` | yes, unscoped | no | same | loaded |
| Hidden by `all_queries: true` scope | yes, scoped | `RecordNotFound` if no row | same | unchanged (raise before steal) |
| `reload(unscoped: true)` | yes, unscoped | no if the row exists | same | loaded |
| Deleted row | yes | `RecordNotFound` | same | unchanged |
| Loaded assoc, parent `reload` | parent yes; assoc on next access | no | parent same | assoc cache replaced, not updated in place |
