Current contract is already observable at the HTTP boundary. `fresh_when` / `stale?` set validators, then `Request#fresh?` decides 304 vs render. A refactor is safe if those observations stay put; it is not if it starts asserting `combine_etags`, etagger lists, or that `stale?` calls `fresh_when`.

## Current path

```text
controller action
  stale?(...) / fresh_when(...)
    cache_control.delete(:no_store)
    derive weak/strong ETag + Last-Modified
    response.etag / last_modified / cache_control
    request.fresh?(response)
      strict_freshness?  → ETag XOR Last-Modified
      else               → AND of whichever headers are present
        etag_matches?    → exact string or "*"
        not_modified?    → IMS >= response.last_modified
    if fresh → head :not_modified   (status 304, empty body)
  if stale? && stale → yield/render
response.commit
  merge_and_normalize_cache_control!
  handle_conditional_get!   # default max-age=0, private, must-revalidate
```

[`fresh_when`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/conditional_get.rb#L137-L155) always writes validators first, then 304s when `request.fresh?` is true. [`stale?`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/conditional_get.rb#L236-L239) is `fresh_when` plus `!request.fresh?(response)`: the expensive block runs only when that is true.

Freshness lives on the request, not the controller:

Matching is exact-string. `W/"abc"` does not match `"abc"`. `"*"` matches any non-nil ETag, weak or strong. There is no HTTP-method gate here; GET, HEAD, QUERY, and POST all 304 if validators hit. [`Rack::ConditionalGet`](file:///home/user/.local/share/mise/installs/ruby/4.0.6/lib/ruby/gems/4.0.0/gems/rack-3.2.1/lib/rack/conditional_get.rb) is a later stack layer and only GET/HEAD; controller tests do not run it. Preserve the controller methods’ contract, not Rack’s.

On commit, [`last_modified=`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/http/cache.rb#L221-L223) writes `Time#httpdate` (second precision). `fresh?` then compares against `response.last_modified`, which re-parses that header. A subsecond `Time` of `12:00:00.999999` becomes `Mon, 15 Jan 2024 12:00:00 GMT`; an `If-Modified-Since` of that string is fresh. Comparing the original `Time` would be stale (`IMS >= original` is false). I confirmed that round-trip with `Time.httpdate`.

Cache-Control after `fresh_when`:

- etag/last-modified only → `max-age=0, private, must-revalidate` ([`handle_conditional_get!`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/http/cache.rb#L304-L310))
- `public: true` alone → `public` (default is skipped because `@cache_control` is no longer empty)
- `cache_control: { no_cache: true }` → `no-cache`; with `public: true` → `public, no-cache`
- `fresh_when` deletes `no_store`; a later `no_store` wins

Template ETags come from the public `etag { }` hook in [`EtagWithTemplateDigest`](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/etag_with_template_digest.rb), not from `fresh_when` internals. `template: false` omits the digest; a named template or the implicit action template is hashed in. Extra `etag { }` values (and flash) also change the header.

## What these catch, without pinning internals

- **Weak/strong / `*`**: assert the `ETag` header string (`W/"…"` vs `"…"`) and 304 vs 200. A refactor that weakens strong tags, or that treats `*` as a literal ETag, flips those rows. Do not assert `response.weak_etag?` unless you already do in response tests; the header is the contract.
- **Precedence**: default AND vs `strict_freshness` XOR. A merge of the two modes, or an RFC-7232-only rewrite, fails 6 or 8 without anyone reading `fresh?`’s branches.
- **Subsecond**: asserting the truncated `Last-Modified` **and** 304 on that IMS fails a refactor that compares the original `Time` or that emits ISO8601 with fractional seconds.
- **Method**: 304 on POST is today’s controller contract. Dropping it “because RFC” fails row 10. HEAD 304 with a blank body is the same `head :not_modified` path as GET; do not also demand Rack HEAD semantics.
- **Cache-Control / `no_store`**: compare the committed header. That covers default injection, `public: true` skipping the default, and last-writer `no_store` without mentioning `handle_conditional_get!`.
- **Template ETags**: equality across two requests, inequality after `modify_template`, inequality across `template:` values. Never assert digest hex or `etaggers`.
- **Block execution**: `@ran` is the user-visible `stale?` contract (skip expensive work on 304). Status 304 with `@ran == true` (work ran, then 304) or 200 with `@ran == false` is semantic drift even if headers look right.

Reuse [`EtagHelper`](file:///home/user/workspace/repo/actionpack/test/support/etag_helper.rb) so expected ETags are computed the same way clients would, from the public hexdigest of `expand_cache_key` — not by reading `generate_weak_etag`. Extra class-level `etag { }` values belong in the existing [`TestControllerWithExtraEtags`](file:///home/user/workspace/repo/actionpack/test/controller/render_test.rb#L8-L42) tests; do not re-encode them in this matrix.

Do not add assertions on call order, double `fresh?` evaluation, or private helpers. If a refactor still produces the same status, body, validators, `Cache-Control`, and `stale?` side effects on these rows, the public HTTP contract held.
