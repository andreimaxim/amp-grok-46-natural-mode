**Request changes.** The leak claim is wrong for the supported in-process API, and restoring ARGV inside `#perform` is the wrong layer.

## Claim is false for `invoke` / `bin/rails runner`

[`RunnerCommand#perform`](file:///home/user/workspace/repo/railties/lib/rails/commands/runner/runner_command.rb#L22-L69) does replace the process-global `ARGV` object:

```33:33:railties/lib/rails/commands/runner/runner_command.rb
        ARGV.replace(command_argv)
```

That mutation is intentional: runner code is supposed to see only trailing script args, not the code/file operand. That is what [`test_should_set_argv_when_running_code`](file:///home/user/workspace/repo/railties/test/application/runner_test.rb#L41-L44) and [`test_passes_extra_args_to_file`](file:///home/user/workspace/repo/railties/test/application/runner_test.rb#L76-L82) lock in.

It does **not** leak past a normal invocation. `bin/rails` ends in [`Rails::Command.invoke`](file:///home/user/workspace/repo/railties/lib/rails/commands.rb#L15-L18), and `invoke` already snapshots/restores `ARGV`:

```63:68:railties/lib/rails/command.rb
        with_argv(args) do
          if command && command.all_commands[command_name]
            command.perform(command_name, args, config)
          else
            invoke_rake(full_namespace, args, config)
          end
        end
```

```140:146:railties/lib/rails/command.rb
        def with_argv(argv)
          original_argv = ARGV.dup
          ARGV.replace(argv)
          yield
        ensure
          ARGV.replace(original_argv)
        end
```

[`base_test.rb`](file:///home/user/workspace/repo/railties/test/command/base_test.rb#L116-L140) already tests that contract (`ARGV is populated` / `ARGV is isolated`). After `Command.invoke("runner", …)` returns, `ARGV` is the pre-invoke vector. A second `dup`/`replace`/`ensure` in `#perform` is redundant on this path.

The leak exists only if something calls instance `#perform` (or `RunnerCommand.perform`) **without** `Command.invoke`. The class is `:nodoc:`. Generate does the same unrestored `ARGV.replace` ([`generate_command.rb`](file:///home/user/workspace/repo/railties/lib/rails/commands/generate/generate_command.rb#L24)); console mutates `ARGV` in `initialize`. Isolation was put at `invoke`, not in every command.

## Path-by-path

**Inline code.** `ARGV.replace` happens before `eval`. During the snippet, `ARGV` is `command_argv` (dashed extras included). After `invoke`, `with_argv` already restores. Proposed `ensure` does not change what the snippet sees.

**Ruby filename.** Same ARGV contract, plus `$0 = File.expand_path(code_or_file)` with no restore. `$0` and `$PROGRAM_NAME` are the same object; tests only assert them **during** the run ([`test_should_set_dollar_0_to_file`](file:///home/user/workspace/repo/railties/test/application/runner_test.rb#L62-L68), [`test_should_set_dollar_program_name_to_file`](file:///home/user/workspace/repo/railties/test/application/runner_test.rb#L70-L76)). For real in-process embedding this is the process-global leak that **survives** `invoke`. The PR does not touch it.

**stdin (`-`).** No `$0` change. ARGV still replaced before `eval($stdin.read, …, "stdin")`. Same restore story as inline code. `File.exist?` is not consulted because `"-"` is the first branch.

**Syntax errors and missing files.** Replace runs **before** `File.exist?`. A missing `*.rb` still mutates ARGV, then the `SyntaxError`/`NameError` rescue prints the “could not be found” / “valid ruby command” messages and `exit 1`. `ensure` would run on `SystemExit` and restore before that propagates — nicer for a direct `#perform` caller who rescues `SystemExit`, irrelevant for CLI because `with_argv` already does. Help-with-no-operand (`help; exit 1`) never reaches `ARGV.replace`; keep it that way.

**Nested / in-process.** Nested `Command.invoke` from inside runner already saves whatever ARGV is at that moment (the runner args), then restores them for the rest of the script. Adding restore in `#perform` does not fix nested invoke. Direct `#perform` from a long-lived process is the only gap, and it is not exercised anywhere.

**Executor.** Replace is outside `conditional_executor`. After-hooks still see runner ARGV if restore is after the wrap. `--skip-executor` / `-w` is unrelated. Do not move replace inside the executor.

**Args beginning with `-`.** [`test_should_set_argv_when_running_code`](file:///home/user/workspace/repo/railties/test/application/runner_test.rb#L41-L44) shows `--foo`, `-b`, `--moo` are forwarded into `ARGV` during the run. Restore must not run until after eval/load. `-e` / `--skip-executor` remain Thor options and never belong in `command_argv`. Unchanged, and not a reason to restore.

## Compatibility and tests

On the CLI path the extra restore is mostly harmless: `with_argv` already clobbers post-run ARGV, including in-script `ARGV <<` / `ARGV.replace` mutations.

It is still the wrong contract to copy into `#perform`:

- `at_exit` / `exit` inside a script already observe `with_argv`’s restored vector, not `command_argv`. A second restore does not fix a CLI bug.
- Direct `#perform` callers that *want* ARGV left as the script’s args would change.
- `$0` stays leaked after file runs, so embedding is still unclean.

[`railties/test/commands/runner_test.rb`](file:///home/user/workspace/repo/railties/test/commands/runner_test.rb) never inspects ARGV. Application tests only print ARGV **inside** a forked `bin/rails` ([`abstract_unit.rb`](file:///home/user/workspace/repo/railties/test/isolation/abstract_unit.rb#L408-L456) replaces ARGV in the child and exits). Nothing would fail today, and nothing would prove the claimed embed leak unless a test calls `#perform` in-process and asserts ARGV (and `$0`) after return, including `SystemExit` from syntax/missing-file.

## More precise change

Do not add `old_argv = ARGV.dup` / `ensure ARGV.replace(old_argv)` to `#perform`. Leave runner ARGV assignment as the script-visible contract; keep isolation at `Rails::Command.invoke`.

If the product goal is “`#perform` is embeddable without `invoke`”:

1. Restore **both** `ARGV` and `$0` around only the eval/load/`-` branches (not around `help; exit 1`, and after `boot_application!`).
2. Add in-process tests that do not use `rails "runner"`: original ARGV/`$0` after success, after `SyntaxError`, after missing `*.rb`, after `-`, and that dashed extras are still visible **during** the run.
3. Say why generate/console are different, or isolate there too.

Until that is the actual API and those tests exist, this PR should not land.
