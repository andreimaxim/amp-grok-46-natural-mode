**Reject.** `safe_concat` is the trusted-append path. Capture is already made safe by `OutputBuffer#<<` and `CaptureHelper#capture`. Escaping ordinary strings in `safe_concat` would HTML-escape every ERB template’s static markup.

I traced [actionview/lib/action_view/buffers.rb](file:///home/user/workspace/repo/actionview/lib/action_view/buffers.rb), [capture_helper.rb](file:///home/user/workspace/repo/actionview/lib/action_view/helpers/capture_helper.rb), [erubi.rb](file:///home/user/workspace/repo/actionview/lib/action_view/template/handlers/erb/erubi.rb), and the buffer/capture tests, then ran the cases below against this checkout (and a monkey-patched `safe_concat` for the proposed line).

## Contracts (current, observed)

`OutputBuffer#<<` / `concat` / `append=` skips `nil`, calls `to_s`, and escapes unless `html_safe?`. ERB uses this for `<%= expr %>`.

`OutputBuffer#safe_concat` / `safe_append=` appends with no escape, no `to_s`, no `nil` guard. ERB uses `safe_append=` for static template text. Same idea as `ActiveSupport::SafeBuffer#safe_concat`.

`OutputBuffer#capture` swaps `@raw_buffer`, yields, returns the intercepted writes as `html_safe`. It never uses the block return value.

`RawOutputBuffer#<<` writes `value.to_s` with no escaping (`nil` skipped). That is the other trusted-raw channel.

`CaptureHelper#capture` runs `output_buffer.capture`, then:

- if the block returns the same `@output_buffer` object, use the intercepted writes
- else `buffer.presence || value` (whitespace-only writes are blank, so the return value wins)
- `OutputBuffer` → `to_s`; `SafeBuffer` → pass through; ordinary `String` → `ERB::Util.html_escape`; anything else → `nil`

| Input | `#<<` | `#safe_concat` | `CaptureHelper#capture` |
|---|---|---|---|
| `"<script>x</script>"` | `"&lt;script&gt;x&lt;/script&gt;"` | `"<script>x</script>"` | return-only → escaped; write via `<<` → escaped |
| `"<b>ok</b>".html_safe` | `"<b>ok</b>"` | `"<b>ok</b>"` | `"<b>ok</b>"` |
| nested capture writes `"<b>B</b>".html_safe` and returns `"<script>C</script>"` | n/a | n/a | inner `"<b>B</b>"` (return dropped because the buffer was present); outer `"A<b>B</b>"` after writing inner |
| `nil` | no-op `""` | `TypeError: no implicit conversion of nil into String` | `nil` |
| another `OutputBuffer` whose contents are `"<b>z</b>"` | `"<b>z</b>"` via `to_s` | `"<b>z</b>"` via `to_str` | blank intercept → `other.to_s` (already-safe contents) |
| returning `@output_buffer` after writing `"foo"`/`"bar"` | n/a | n/a | `"foobar"` from intercept; outer buffer unchanged |
| `5` | `"5"` | `"\u0005"` (`String#<<` codepoint) | `nil` (not a String) |

`OutputBuffer#capture` of an unsafe return with no writes is `""`, not the return value. Return-value escaping lives only in `CaptureHelper#capture`.

## Findings

### Blocker — ERB static HTML is compiled to `safe_append=`

[erubi.rb](file:///home/user/workspace/repo/actionview/lib/action_view/template/handlers/erb/erubi.rb#L37-L40) emits `@output_buffer.safe_append='<p class="x">Hello</p>\n'.freeze`. That string is a plain `String` (`html_safe? == false`).

Proposed `safe_concat` (after re-aliasing `safe_append=`):

```text
"<p class=\"x\">Hello</p>\n"  →  "&lt;p class=&quot;x&quot;&gt;Hello&lt;/p&gt;\n"
```

Every HTML template would render as escaped source. `<%== %>` / `safe_expr_append=` would still inject raw HTML, so this is not a consistent escaping model.

This also fails the existing contract test [buffers_test.rb](file:///home/user/workspace/repo/actionview/test/buffers_test.rb#L14-L18): `#safe_append= bypasses HTML safety` expects `"<p>This is fine</p>"`.

### Blocker — the capture-safety claim is false

`CaptureHelper#capture` already escapes ordinary string returns ([capture_helper.rb](file:///home/user/workspace/repo/actionview/lib/action_view/helpers/capture_helper.rb#L66-L85); [test_capture_escapes_html](file:///home/user/workspace/repo/actionview/test/template/capture_helper_test.rb#L48-L51)). Untrusted writes are already escaped by `#<<`. `#capture` on the buffer ignores returns.

`safe_concat` is not on that path. The XSS case the patch would “fix” is `safe_concat("<script>xss</script>")` inside a capture, which is the same class of bug as `raw(user_input)` / `<%== user_input %>`. Observed today:

```text
capture { output_buffer.safe_concat("<script>xss</script>"); nil }  →  "<script>xss</script>"  (html_safe)
capture { output_buffer << "<script>xss</script>"; nil }           →  "&lt;script&gt;xss&lt;/script&gt;"
```

That is the documented split between trusted and untrusted append. Closing it inside `safe_concat` attacks the wrong API.

### High — fragment cache and helper `safe_concat` of already-built HTML

[CacheHelper#cache](file:///home/user/workspace/repo/actionview/lib/action_view/helpers/cache_helper.rb#L180) does `safe_concat(fragment_for(...))` via [TextHelper#safe_concat](file:///home/user/workspace/repo/actionview/lib/action_view/helpers/text_helper.rb#L67-L69). Cache stores return ordinary strings of HTML. Today those are injected as markup. After this change they would render as `&lt;div&gt;...`.

Helpers that `safe_concat` html_safe tags would keep working (`html_escape` is a no-op on `html_safe?` values — observed). The break is specifically ordinary trusted strings, which is most of ERB’s output and cached fragments.

### High — `StreamingBuffer#safe_concat` left unchanged

[StreamingBuffer#safe_concat](file:///home/user/workspace/repo/actionview/lib/action_view/buffers.rb#L121-L123) still does `@block.call(value.to_s)`. Shared tests cover both buffers. Streaming vs non-streaming would disagree on the same template.

`RawOutputBuffer#<<` also stays unescaped, so capture of `buffer.raw << "<script>raw</script>"` remains `"<script>raw</script>"` (observed). The patch does not make capture uniformly safer.

### Medium — silent `nil` / Integer contract change

`ERB::Util.html_escape(nil)` is `""`; `html_escape(5)` is `"5"`. Current `safe_concat(nil)` raises; `safe_concat(5)` writes `"\u0005"`. `#<<` already has the nil-skip / `to_s` behavior; copying escape without copying those guards still does not make the two methods equivalent.

`#<<` uses `unwrapped_html_escape` after `to_s`. The patch uses `html_escape`, which allocates a `SafeBuffer` on every static append.

## Compatibility / security

- **Compatibility:** breaking. All HTML ERB literals, annotation preambles (`safe_append='<!-- BEGIN ...'`), and cache hits of plain-string fragments change meaning.
- **Security:** not an improvement. Untrusted data already has an escaping API (`#<<` / `<%= %>`). Trusted HTML has `safe_concat` / `raw` / `RawOutputBuffer`. Collapsing them forces double-escaping of trusted markup and does not touch raw writes during capture.
- `ActiveSupport::SafeBuffer#safe_concat` is the same “do not escape” contract; form-option helpers call it on `"".html_safe`, not on `OutputBuffer`. This patch would not even make those call sites “safer.”

Do not change `safe_concat`. If untrusted values reach it, that is a caller bug; the fix is to use `#<<` / `concat`.
