## What the patch actually does

```683:691:railties/lib/rails/application/configuration.rb
        def credentials_defaults
          content_path = root.join("config/credentials/#{Rails.env}.yml.enc")
          content_path = root.join("config/credentials.yml.enc") if !content_path.exist?

          key_path = root.join("config/credentials/#{Rails.env}.key")
          key_path = root.join("config/master.key") if !key_path.exist?

          { content_path: content_path, key_path: key_path }
        end
```

[`Rails.application.credentials`](file:///home/user/workspace/repo/railties/lib/rails/application.rb#L589-L630) then builds `EncryptedConfiguration` from `config.credentials.content_path` / `key_path`, with `env_key: "RAILS_MASTER_KEY"` and `raise_if_missing_key: config.require_master_key`. `ENV["RAILS_MASTER_KEY"]` is tried before any key file. The patch only changes **which file** is selected; it does not make credentials “always fall back to the global key.”

| Files present | Result |
|---|---|
| env.yml.enc + env.key | Environment pair (correct) |
| env.yml.enc, no env.key, master.key present | Env content + `config/master.key` (the claimed case) |
| no env.yml.enc, global content + master.key | Global pair (correct) |
| no env.yml.enc, global content + stray env.key | **Global content + env.key** (invalid reverse pairing) |
| env.yml.enc + env.key + master.key | Env key wins; master is unused |
| env.yml.enc, neither key file | `key_path` is still `config/master.key`; then ENV / missing-key rules apply |

A present env key never falls back to `master.key`. A wrong-length or wrong key does not retry another file.

## Command split is a blocker

[`credentials:show`](file:///home/user/workspace/repo/railties/lib/rails/commands/credentials/credentials_command.rb#L32-L38) / `fetch` / `diff` inherit `credentials_defaults`. [`credentials:edit --environment`](file:///home/user/workspace/repo/railties/lib/rails/commands/credentials/credentials_command.rb#L17-L31) does not:

```22:25:railties/lib/rails/commands/credentials/credentials_command.rb
        if environment_specified?
          @content_path = "config/credentials/#{environment}.yml.enc" unless config.overridden?(:content_path)
          @key_path = "config/credentials/#{environment}.key" unless config.overridden?(:key_path)
        end
```

Then [`ensure_encryption_key_has_been_added`](file:///home/user/workspace/repo/railties/lib/rails/commands/credentials/credentials_command.rb#L97-L104) creates that env key if `credentials.key?` is false.

For env content encrypted with `master.key` and no env key:

1. `credentials:show --environment production` decrypts with `master.key`.
2. `credentials:edit --environment production` writes `config/credentials/production.key`.
3. Edit fails (`Couldn't decrypt … Perhaps you passed the wrong key?`).
4. The new key remains.
5. Later runtime/show select that env key and raise `ActiveSupport::MessageEncryptor::InvalidMessage`.

`edit` without `--environment` while `RAILS_ENV=production` follows defaults, so the same app behaves differently by invocation form. Custom `config.credentials.content_path` / `key_path` are respected only when marked overridden; ENV still overrides any selected file.

## Missing / invalid keys, require_master_key, env differences

[`EncryptedFile#key`](file:///home/user/workspace/repo/activesupport/lib/active_support/encrypted_file.rb#L41-L77) is `ENV["RAILS_MASTER_KEY"]` then the selected file. [`EncryptedConfiguration#read`](file:///home/user/workspace/repo/activesupport/lib/active_support/encrypted_configuration.rb#L132-L136) swallows `MissingContentError` (empty hash) but not `InvalidMessage`.

- Neither file key, no ENV, `require_master_key: false` (default): empty credentials. In development/test, [`secret_key_base`](file:///home/user/workspace/repo/railties/lib/rails/application/configuration.rb#L557-L567) can still come from `tmp/local_secret.txt`.
- Same, `require_master_key: true`: boot abort via the [railtie initializer](file:///home/user/workspace/repo/activesupport/lib/active_support/railtie.rb#L133-L141) with `MissingKeyError` naming the **selected** `key_path` (after this patch, `config/master.key`, not the missing env key). Production templates do not enable this; default remains false.
- Wrong key of valid length: `InvalidMessage`. That is evaluated before the local-secret fallback, so it raises in development too if credentials are read.
- Malformed key: `InvalidKeyLengthError` on write; read can raise `ArgumentError` / `InvalidMessage`.
- `RAILS_MASTER_KEY` set and wrong: fails closed; it does not try `master.key` or the env key.

AES-GCM does not leak plaintext on a wrong key. The damage is availability and isolation: sharing `master.key` across env files expands its blast radius, and a leftover/generated env key can take down a valid global store.

## Corrected tiny diff

Make fallback **directional**: only env content may use `master.key`; global content never uses an env key. Align `edit --environment` with that for existing files.

```ruby
def credentials_defaults
  content_path = root.join("config/credentials/#{Rails.env}.yml.enc")

  if content_path.exist?
    key_path = root.join("config/credentials/#{Rails.env}.key")
    key_path = root.join("config/master.key") unless key_path.exist?
  else
    content_path = root.join("config/credentials.yml.enc")
    key_path = root.join("config/master.key")
  end

  { content_path: content_path, key_path: key_path }
end
```

```ruby
if environment_specified?
  @content_path = "config/credentials/#{environment}.yml.enc" unless config.overridden?(:content_path)

  unless config.overridden?(:key_path)
    @key_path = "config/credentials/#{environment}.key"
    @key_path = "config/master.key" if !Rails.root.join(@key_path).exist? && Rails.root.join(content_path).exist?
  end
end
```

New env files still get an env key; existing master-encrypted env files keep using `master.key`. Document that as directional, not “always the global key.” Strict pairing (env content never uses `master.key`) is the cleaner security story, but it would break the documented independent fallback; directional fallback is the compatible fix.
