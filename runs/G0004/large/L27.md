The claim is wrong at this revision, and the one-line patch is not safe. I applied it locally, ran the signed-cookie tests, then reverted: rotation upgrade tests fail because a rotated read no longer emits a current-key `Set-Cookie`.

**Verdict:** reject. `force_reserialize: rotated` is the signed-jar rewrite that upgrades old secrets/digests on access. Hard-coding `false` leaves those cookies readable only while the rotator still exists.

## High: rotation rewrite is required, not “unnecessary”

[`SignedKeyRotatingCookieJar#parse`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/middleware/cookies.rb#L641-L646) is the whole upgrade path:

```641:646:actionpack/lib/action_dispatch/middleware/cookies.rb
        def parse(name, signed_message, purpose: nil)
          rotated = false
          data = @verifier.verified(signed_message, purpose: purpose, on_rotation: -> { rotated = true })
          super(name, data, force_reserialize: rotated)
        end
```

[`Messages::Rotator#read_message`](file:///home/user/workspace/repo/activesupport/lib/active_support/messages/rotator.rb#L29-L44) calls `on_rotation` only after a **fallback** verifier succeeds. The primary secret/digest never sets `rotated`. [`SerializedCookieJars#parse`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/middleware/cookies.rb#L600-L610) then does `self[name] = { value: value }`, which re-dumps and re-signs via [`commit`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/middleware/cookies.rb#L649-L653) and records a `Set-Cookie` in [`CookieJar#[]=`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/middleware/cookies.rb#L380-L398).

That is the documented contract, not an accident:

> Old cookies that were written with SHA1 can still be read, and if accessed will be written with the new digest so they're upgraded and won't be invalid when you remove the rotation. ([guides/source/security.md](file:///home/user/workspace/repo/guides/source/security.md#L409-L415))

I applied `force_reserialize: false` on the signed jar only and ran the existing rotation tests. Both errored the same way: `@response.cookies["user_id"]` is `nil`, then `MessageVerifier#verify` raises `InvalidSignature: invalid message string` (nil payload in [`extract_encoded`](file:///home/user/workspace/repo/activesupport/lib/active_support/message_verifier.rb#L338-L351)).

- [`test_signed_cookie_rotating_secret_and_digest`](file:///home/user/workspace/repo/actionpack/test/dispatch/cookies_test.rb#L641-L656) — old secret + SHA1, current SHA256. Read still returns `45`; response is no longer verifiable with the current key.
- [`test_rotating_signed_cookies_digest`](file:///home/user/workspace/repo/actionpack/test/dispatch/cookies_test.rb#L1000-L1014) — same for digest-only rotation.

After revert, those tests pass again (13 runs / 29 assertions on the signed-cookie filter; 30/30 on `message_verifier_rotator_test` + metadata tests).

If this shipped, old-secret cookies would stay on the old signature until some other write. Removing the rotator would log users out / drop signed state. That is the opposite of “safe.”

Serializer upgrades are a separate switch ([`reserialize?`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/middleware/cookies.rb#L592-L597)). The patch would not stop hybrid Marshal→JSON or JSON→MessagePack migration, which is why those tests still passed under the patch — and why “we can skip rewrites” does not follow from “serializer migration still works.”
