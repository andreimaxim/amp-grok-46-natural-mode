`Enumerable#sole` returns the only element of an enumerable, or raises. It walks with `each`, not `to_a` / `count`, and uses a `found` flag so emptiness is not confused with a `nil` element.

## Contract

[`Enumerable#sole`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/enumerable.rb#L230-L258) is specified to return the sole item, and to raise [`Enumerable::SoleItemExpectedError`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/enumerable.rb#L18-L21) (`< StandardError`) when the enumerable does not contain exactly one item. The public name is `Enumerable::SoleItemExpectedError`; after a constant-cache hack the class object lives at `ActiveSupport::EnumerableCoreExt::SoleItemExpectedError` and is recovered through `const_missing`.

Messages established in source:

- empty: `"no item found"`
- more than one: `"multiple items found"`

[`test_sole`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L431-L438) asserts the exception class for those cases, not the strings.

## Control flow

```ruby
result = nil
found = false

each do |*element|
  raise SoleItemExpectedError, "multiple items found" if found

  result = element.size == 1 ? element[0] : element
  found = true
end

found ? result : raise(SoleItemExpectedError, "no item found")
```

```diagram
          found=false, result=nil
                    │
                    ▼
              each yields?
               /        \
             no          yes
              │           │
              ▼           ▼
     raise "no item     found already?
         found"          /         \
                       yes          no
                        │            │
                        ▼            ▼
              raise "multiple    store result
               items found"      found=true
                        │            │
                        │            └──▶ next yield or end
                        X
```

The raise on the second yield unwinds `each`. Later elements are never requested.

### Empty

[`GenericEnumerable.new([]).sole`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L434): `each` never yields, `found` stays `false`, raise `"no item found"`.

### One element

[`GenericEnumerable.new([1]).sole`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L435) is `1`. One yield: capture, `found = true`, `each` ends, return `result`.

### Several elements

[`GenericEnumerable.new([1, 2]).sole`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L436): first yield stores `1`; second yield hits `if found` and raises `"multiple items found"`. The rest of the collection is not visited.

## Endless range: no full traversal

[`GenericEnumerable`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L35-L45) forwards `each` to its wrapped object. [`GenericEnumerable.new(1..).sole`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L438) therefore uses `Enumerable#sole`, not `Range#sole`.

`(1..)` would not terminate if `sole` materialized the whole range. It does not: after `1` it has a candidate; on `2` it raises `"multiple items found"` and leaves `Range#each`. That is why the test can cover an endless range without hanging.

`Range#sole` is a different path: beginless/endless ranges raise immediately with `"infinite range '#{inspect}' cannot represent a sole item"` and never call `super` ([`range/sole.rb`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/range/sole.rb#L15-L21), messages in [`range_ext_test.rb`](file:///home/user/workspace/repo/activesupport/test/core_ext/range_ext_test.rb#L335-L348)).

## `nil` is a real element

`result` starts as `nil`, but presence is `found`, not `result.nil?`.

- A sole `nil` is a successful result (`found == true`, `result == nil`).
- [`GenericEnumerable.new([1, nil]).sole`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L437) raises: `nil` is a second item, not “missing”.

If emptiness were detected with `result.nil?`, `[nil].sole` would be reported empty. The flag is what makes `nil` a legitimate sole value.

## How yields become the return value

The block is `|*element|`. Every yield is packed into an array, then unwrapped only when that array has length 1, so a one-value yield matches `each { |x| }` / `first`, and multi-arg yields stay arrays like `first`.

**One value.** Array `#each` / `yield 1` → `element == [1]` → `result == 1`. That is [`GenericEnumerable.new([1]).sole`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L435).

**Several positional values.** [`Enumerator#yield(1, "one")`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L441-L444) → `element == [1, "one"]` (size ≠ 1) → `result == [1, "one"]`. The test requires that this equal `enum.first`.

**One positional value plus keywords.** [`KeywordYielder#each` does `yield 1, two: 3`](file:///home/user/workspace/repo/activesupport/test/core_ext/enumerable_test.rb#L447-L458). The `|*element|` block does not take `**`. The keywords become a trailing hash: `element == [1, { two: 3 }]`, returned as-is. Same value as `yielder.first`.

So `sole` is “exactly one `each` yield, shaped the way `Enumerable#first` shapes that yield,” with an early abort on a second yield so infinite enumerables remain usable.
