`send_stream` is a thin public contract: it sets headers, instruments one event around the producer block, yields `response.stream`, and always closes. Preserve that by asserting on the HTTP response, notifications, exceptions, and stream/thread state — not on private helpers.

Current implementation (from [actionpack/lib/action_controller/metal/live.rb](file:///home/user/workspace/repo/actionpack/lib/action_controller/metal/live.rb)):

```text
GET action
  Live#process
    snapshot Thread.current keys + IsolatedExecutionState.context
    post work onto Concurrent::CachedThreadPool ("action_controller.live")
      copy thread locals onto pool thread
      IsolatedExecutionState.share_with(context, except: live_streaming_excluded_keys)
        super(action)
          send_stream
            Notifications.instrument("send_stream.action_controller", payload)
              set Content-Type
              set Content-Disposition
              yield response.stream     # Live::Buffer
            ensure response.stream.close
        rescue
          committed?  → log, optional HTML completion write, on_error, close
          else        → stash error for parent
        ensure
          nil copied thread locals
          response.commit!
    parent: await_commit; re-raise stashed error
```

`LiveStreamTest` already restores `original_new_controller_thread` / `original_clean_up_thread_locals`, so these tests run on the real pool. `ActionController::TestCase` otherwise inlines the action and sets `Buffer.queue_size = nil`. Keep using that restored harness for anything involving threads, disconnect, or commit races.

```diagram
┌─────────────┐  await_commit   ┌──────────────────┐  each/close   ┌────────────┐
│ Test thread │◀───────────────▶│ Pool thread      │◀─────────────▶│ Live::Buffer│
│ get / body  │                 │ send_stream      │  write/close  │ SizedQueue  │
└─────────────┘                 │ instrument+ensure│               │ abort flag  │
                                └──────────────────┘               └────────────┘
```

Commit/close facts to treat as oracles, not internals to re-test in isolation:

- First `Buffer#write` (and `Buffer#close`) call `Response#commit!`. That wakes `await_commit` and freezes headers.
- `Response#each` sets `sending!` then `sent!`. `assert_stream_closed` is only valid after the body has been drained.
- Rack `body.close` maps to `Response#abort` → `Buffer#abort` (`@aborted`, queue cleared, `nil` terminator). That is client disconnect, not producer `close`.
- `send_stream`’s `ensure close` runs **after** the notification finishes, and it runs even when the producer block raises. That means an exception **inside** the `send_stream` block always commits before `Live#process` sees it.

## Checks

### 1. Inferred and explicit content types

**Behavior.** Resolution is left-to-right and always stored as a String:

```text
(type is Symbol ? Mime[type].to_s : type)
  || lookup_by_extension(extname(filename).downcase with dots stripped)
  || "application/octet-stream"
```

**Seam.** `get` of four actions (three already exist: inferred `.csv`, `type: :csv`, `type: "text/csv"`). Add unknown-extension (`filename: "export.bin"` / `"noext"`) and symbol `:json` with no extension (`send_stream_with_options` already covers the last).

**Assert.**

- `headers.fetch("Content-Type")` equals the MIME oracle string (`"text/csv"`, `"application/json"`, `"application/octet-stream"`).
- `assert_equal String, content_type.class` — `Mime[sym].to_s` must not leak a `Mime::Type`.
- Body still matches what the block wrote (type selection must not skip or double-yield).

Do not re-derive MIME in the test; call `Mime[...]` / `lookup_by_extension` so a registry change fails both production and oracle together.

Existing tests: `test_send_stream`, `test_send_stream_with_inferred_content_type`, `test_send_stream_with_implicit_content_type`, `test_send_stream_with_explicit_content_type`, `test_send_stream_with_options`. They miss the octet-stream fallback.

### 2. RFC-compatible filename disposition

**Behavior.** `Content-Disposition` is exactly `ContentDisposition.format(disposition:, filename:)`. Default `disposition:` is `"attachment"`.

**Seam.** Same `get` actions. Use the format helper as the expected string, not `assert_match`.

**Assert.**

- ASCII: `attachment; filename="my.csv"; filename*=UTF-8''my.csv`.
- Explicit `inline` + nameless-looking `"export"`: full `inline; filename="export"; filename*=UTF-8''export`.
- Non-ASCII filename (e.g. `råcëçâr.csv` or `автомобиль.csv`): header equals `ContentDisposition.format(...)` — traditional `filename=` plus `filename*=UTF-8''`.

Existing tests only `assert_match "attachment"` / `"my.csv"` / `"inline"` / `"export"`, which would still pass if `filename*` disappeared. Exact equality is the behavior-preserving check.

No extra sync. Headers are visible after `await_commit`, which `get` already waits for.

---

### 3. Chunk order

**Behavior.** Each `write`/`writeln` enqueues one chunk; `writeln` appends `"\n"` only when missing. `Response#body` concatenates; chunk boundaries are only visible through `each`.

**Seam.** Follow `test_async_stream` / `test_parallel`: producer writes N chunks, waiting on a `Concurrent::CountDownLatch` after each write; consumer thread `await_commit` then `each`.

**Assert.** Consumer sees `["fruit,quantity\n", "apple,5\n"]` (or whatever the action wrote), in order, with no extra terminator chunk (`each_chunk` stops at `nil`). Concatenated `response.body` equals the join of those chunks.

**Race-proofing.**

- `await_commit` before `each`. Never `sleep`.
- Handshake: consumer asserts then `count_down`; producer blocks on the latch between writes. That makes order a happens-before, not a scheduler accident.
- `assert t.join(3)` (or `Timeout.timeout`) and fail on timeout — do not let a stuck reader mark the test green.
- `ensure` `reader&.kill` and `stream.close` if the handshake aborts.
- Do not fill a `SizedQueue` in this test (`queue_size` stays `nil` unless you are testing backpressure).

### 4. Exception before commit

Two different observables. Both must stay.

**A. Exception in the action before `send_stream` is called** (true uncommitted path, same as `test_exception_in_controller_before_streaming`).

- **Seam.** `assert_raises` around `get :action`.
- **Assert.** The original exception reaches the test thread. `Live#process` stashes it because `committed?` is still false, then `commit!`s in `ensure`. The test thread must see the raise **after** `await_commit`. Do **not** expect `stream.closed?` — that path does not close.
- **Sync.** None beyond `get`. No consumer thread.

**B. Exception inside the `send_stream` block before any `write`.** This is *not* uncommitted. `ensure close` commits first, so `Live#process` takes the committed branch: it logs, does not re-raise to `get`, and closes again.

- **Seam.** `capture_log_output { get :action }` (no `assert_raises`).
- **Assert.** `get` returns; log matches the exception message; `assert_stream_closed` after draining; body has no producer chunks. For HTML format, committed-path may append `ActionView::Base.streaming_completion_on_exception`; for a `send_stream` CSV/octet response it should not.
- **Why this matters for a refactor.** Moving `close` inside the instrument block, or closing only after a write, would change whether `get` raises.

### 5. Exception after commit

**Behavior.** First `write` commits. A later raise in the producer block still runs `send_stream`’s `ensure close`, then `process`’s committed rescue (log, `on_error`, close).

**Seam.** Action: `send_stream(...) { |s| s.write "partial"; raise ... }`. `capture_log_output { get }`.

**Assert.**

- `get` does not raise (committed path swallows at process).
- Concatenated body starts with `"partial"` (chunk already in the queue before abort/close).
- Log contains the exception.
- `assert_stream_closed`.
- Notification payload includes `:exception` / `:exception_object` (see check 9).

Optional sibling, already covered for raw streaming: `on_error` callback still runs if the action registered one **before** the raise. Not required for a pure `send_stream` refactor unless the refactor touches `Buffer#call_on_error`.

**Race-proofing.** Drain `response.body` on the test thread after `get`; `process` has already `await_commit`ed. Do not start a second consumer.

---

### 6. Client disconnect, `ignore_disconnect` false (default)

**Behavior.** Consumer `body.close` → `abort` → `connected?` false. Next `write` clears the queue and raises `ActionController::Live::ClientDisconnected`. That raise is inside the `send_stream` block, so it follows the committed-exception path. Default `ignore_disconnect` is `false`.

**Seam.** Copy `test_abort_with_full_buffer` / `test_ignore_client_disconnect`: `get`, consumer thread `await_commit`, read at least one chunk (or just enter `each`), then `body.close`. Producer uses a latch so it writes once, waits until abort is in effect, then writes again.

**Assert.**

- Producer’s second write does not complete as success: either the committed-exception log shows `ClientDisconnected`, or an `on_error` latch fires (as in `overfill_buffer_and_die`).
- After abort, further body chunks are not required; `each` must terminate (the `nil` terminator `abort` pushes).
- Stream ends closed.

**Race-proofing.** This is the flaky one if you guess at timing.

- Wait until the reader is actually blocked: `Timeout.timeout` + `Thread.pass until received.any?` and `until reader.status == "sleep"` (see `test_abort_terminates_a_reader_blocked_on_the_buffer`).
- Then `body.close` / `abort`.
- `assert reader.join(5)`.
- `ensure` `reader&.kill`; restore `Buffer.queue_size` if you changed it.
- Do not `sleep`. Do not abort before the first write has committed — `await_commit` first or the parent `get` can hang.
- If you restore a finite `queue_size`, the consumer **must** be running or the producer will deadlock on `SizedQueue#push`. Prefer `queue_size = nil` unless backpressure is the point.

### 7. Client disconnect, `ignore_disconnect` true

**Behavior.** Same abort, but `write` discards and returns bytesize. The producer block runs to completion. `send_stream` still closes.

**Seam.** Existing `test_ignore_client_disconnect` shape, but the action should call `send_stream` and set `stream.ignore_disconnect = true` **inside** the block, then `write ""` (commit), then more writes after the consumer has closed.

**Assert.**

- Producer latch counts down (work finished).
- Log (or a side-effect the action records) shows completion — writes did not raise.
- `Timeout.timeout(3) { latch.wait }` on the test thread.
- Stream closed after `get`/consumer join.

**Race-proofing.** Same as (6): `await_commit` before `body.close`; join + timeout; `ensure` kill. Without the latch, “Work complete” can be asserted before the ignored writes run.

### 8. Stream closure on every path

**Behavior.** `response.stream.close` is in `send_stream`’s `ensure`. `Buffer#close` commits, sets `closed?`, pushes `nil`, broadcasts. Double-close from `process`’s committed rescue is harmless.

**Seam.** `assert_stream_closed` after every `send_stream` `get` that is supposed to finish:

```text
assert_predicate response.stream, :closed?
assert_predicate response, :committed?
assert_predicate response, :sent?
```

Cover at least: happy path, inferred/explicit type paths, exception-in-block (before and after write), both disconnect flags, and a block that itself calls `stream.close` (second close must not raise; `sent?` still true once drained).

**Assert.** Always drain first (`response.body` or `each`). `sent?` is false until `Response#each` finishes.

Existing `send_stream` tests never call `assert_stream_closed`. That is the main closure gap.

**Cleanup.** If a test opens a consumer thread, join/kill it before asserting `closed?`/`sent?` on the test thread, or you can observe a still-open stream while the reader is mid-`each`.

### 9. Copied thread-local state

**Behavior.** `Live#process` copies `Thread.current` keys into the pool thread and `IsolatedExecutionState.share_with`s the parent context (minus `live_streaming_excluded_keys`). After the action, copied keys are niled on the pool thread so the CachedThreadPool can reuse it. Parent thread state is not cleared (see `LiveControllerThreadTest`).

**Seam.** Same as `test_thread_locals_get_copied` / `test_isolated_state_get_copied`, but the action body is `send_stream`. Assert **inside** the action (`@controller.tc = self`) that `Thread.current[:setting]` and `CurrentState.id` / `IsolatedExecutionState[:key]` match what the parent set before `get`. After `get`, assert the parent still has those values.

**Assert.**

- Copy-in: values visible during `send_stream`’s block (headers/write happen on the pool thread).
- Parent unchanged after `get`.
- Optional: `live_streaming_excluded_keys = [:active_record_connected_to_stack]` still excludes that key during `send_stream` (`test_connected_to_stack_not_inherited`).

Do not assert that pool-thread locals were niled; that is private cleanup. The observable contract is: child sees a copy, parent is intact, next request on a reused thread does not see the previous request’s locals (`test_thread_locals_get_reset` / `test_isolated_state_get_reset`).

**Race-proofing.**

- Requires `original_new_controller_thread` (already in `LiveStreamTest#setup`). Inlined test threads would make copy/reset tests tautological or destructive (`LiveControllerThreadTest` documents the inline case).
- `ensure` restore `live_streaming_excluded_keys`, `IsolatedExecutionState.isolation_level`, and `IsolatedExecutionState.delete` test keys.
- Fiber isolation (`isolation_level = :fiber`) is a separate existing check; include it only if the refactor still goes through `share_with`.

### 10. Notification payload and timing

**Behavior.** Payload is the **original** arguments `{ filename:, disposition:, type: }` — not the resolved MIME string. `instrument` wraps header assignment + `yield` only. `handle.finish` runs in `instrument`’s `ensure` **before** `send_stream`’s `ensure close`. On raise, the instrumenter adds `:exception` and `:exception_object` and still finishes.

**Seam.** `assert_notification("send_stream.action_controller", expected_payload)` for the happy path (already `test_send_stream_instrumentation`, which correctly expects `type: "text/csv"` as passed, not a resolved value). For timing and errors, `capture_notifications` or `subscribed` into a concurrent-safe array.

**Assert.**

- Exactly one event per `get` (`assert_notifications_count(..., 1)`).
- Payload subset: original `filename`, `disposition` (default `"attachment"` if omitted), original `type` (`nil` when inferred — do not expect `"text/csv"` in the payload for inferred type).
- Timing on the child thread, recorded by the subscriber:
  1. At notification **finish**, `response.stream.closed?` is **false** (block did not close it).
  2. After `get` + drain, `closed?` is **true**.
  3. At finish, `Content-Type` / `Content-Disposition` are already set (headers are assigned before `yield`).
- On producer raise: same event name; payload still has the original keys **plus** `:exception`; stream still closed after the request; event still emitted (finish runs in `ensure`).

**Race-proofing.**

- Subscriber runs on the pool thread. Append to `Queue` or `Concurrent::Array`, not a plain Array without a barrier.
- Do not read `response.body` from the subscriber (that would compete with the test thread’s `each`).
- Assert timing from the recorded snapshot, then join/`get` return, then assert close. Never `sleep` to “wait for close”.
- `assert_notification` matches payload as a **subset**; extra keys (`:exception`) will not fail a subset match — for the happy path assert the payload does **not** include `:exception`.

## Harness rules (avoid flakes)

Reuse patterns already in [live_stream_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/live_stream_test.rb); do not invent sleeps.

- Keep `LiveStreamTest#setup`’s restoration of `original_new_controller_thread` / `original_clean_up_thread_locals` for every check that involves commit, disconnect, or thread locals.
- `Concurrent::CountDownLatch` for producer/consumer and “work finished”. `Timeout.timeout` / `join(seconds)` around every wait; treat timeout as failure.
- `await_commit` before any `each` or `body.close`.
- `ensure`: restore `Buffer.queue_size`, logger, `live_streaming_excluded_keys`, isolation level, IsolatedExecutionState keys; `reader&.kill`.
- Drain the body before `assert_stream_closed`.
- One consumer per response. A second `each` after the terminator has been popped sees nothing and can hang if you expected chunks.
- Finite `queue_size` only in backpressure tests, and only with a live consumer.

## What not to couple to

A refactor may split `send_stream`, change how the pool is obtained, or move Buffer methods. These checks stay valid if:

- `get :action` still produces the same headers, body bytes, and close/commit/sent bits
- `send_stream.action_controller` still fires once with the original argument payload, finishing before close
- exceptions before `send_stream` still surface on the test thread; exceptions inside the block still log, commit, and close
- disconnect still raises or discards according to `ignore_disconnect`
- the `send_stream` block still runs with the parent’s thread locals / isolated state

Do not assert call order of private methods, queue class, or executor name. If a check needs a hook, add it on the test controller (latch, `on_error`, `ignore_disconnect=`) or subscribe to the public notification — not by stubbing `Live` internals.

Existing tests already cover pieces of 1, 3, 6, 7, 9 and a weak form of 2 and 10. The behavior-preserving net is: tighten disposition and payload assertions, add octet-stream inference, assert close on every `send_stream` path, and add the two exception-in-block cases plus a `send_stream`-specific disconnect pair so a refactor cannot move `close` or `instrument` without a red test.
