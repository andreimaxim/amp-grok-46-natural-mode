**Block.** The claim is wrong for this revision, and the diff is not a bang counterpart of `#attach`.

`#attach!` only raises when `#attach` attempted an immediate save and that save returned false. Unconditional `record.save!` after `#attach` changes the method’s meaning, the exception, the return value, and when the record is persisted.

## Current contract

`#attach` saves immediately only when the record is persisted and has no attribute changes. Otherwise it stages attachments and waits for the next record save:

```51:57:activestorage/lib/active_storage/attached/many.rb
    def attach(*attachables)
      record.public_send("#{name}=", blobs + attachables.flatten)
      if record.persisted? && !record.changed?
        return if !record.save
      end
      record.public_send("#{name}")
    end
```

`record.changed?` is attribute dirty state, not `attachment_changes`. Assigning highlights does not mark the user `changed?`, so a persisted, attribute-clean record does save immediately.

`#attach!` is documented as raising only when that immediate save was supposed to happen and failed:

```59:67:activestorage/lib/active_storage/attached/many.rb
    # Calls attach, and raises an exception if the record was meant to be saved but at least one of the validations failed.
    def attach!(*attachables)
      attach(*attachables) || raise(ActiveRecord::RecordNotSaved.new("Failed to save the record", record))
    end
```

That `|| raise` is correct. `#attach` returns `nil` only on `return if !record.save`. On success or deferred attach it returns the `Attached::Many` proxy, which is truthy. `Attached::One#attach!` is the same pattern.

I ran the existing tests and a probe of current vs proposed behavior.

## What the proposed diff actually does

```ruby
def attach!(*attachables)
  attach(*attachables)
  record.save!
end
```

| Case | Current `#attach!` | Proposed |
|---|---|---|
| Persisted, unchanged, valid | Saves once; returns the Many proxy | Saves **twice**; returns `true` |
| Persisted, unchanged, invalid | `ActiveRecord::RecordNotSaved` `"Failed to save the record"` | `ActiveRecord::RecordInvalid` `"Validation failed: Name can't be blank"` |
| New, valid | Does **not** persist; pending `attachment_changes` | **Creates** the record |
| New, invalid | No raise; stages attachments | Raises `RecordInvalid` |
| Dirty, valid (`name = "Tina"`) | Leaves `name` unsaved; attachments pending | Persists `"Tina"` and the attachments |
| Dirty, invalid | No raise | Raises `RecordInvalid` |
| Empty args / `[]` / nested arrays / duplicate blob | Same as `#attach` | Same attach staging, then extra `save!` |

Validation failures already raise on the path `#attach` tries to save. They do not raise for new/dirty records because those records were never “meant to be saved” by `#attach`. Making `#attach!` always `save!` is a new “attach and save the whole record” API, not a fix.

## Missing tests

The suite only covers persisted + unchanged + invalid. There is no `#attach!` coverage for:

- persisted unchanged valid: one save, returns the Many proxy
- new record: does not persist
- dirty record: does not persist attributes
- new/dirty invalid: does not raise
- exception class **and** message
- no second save / callback pass
- One/Many parity

That is why this tiny diff can look like it “makes validations raise” while rewriting the method.

## Smallest corrected direction

Leave `#attach!` as the bang form of `#attach`’s return value. Do not call `record.save!` unconditionally.

If the real goal is “use `save!` on the path `#attach` already saves,” duplicate `#attach`’s guard instead of stacking `save!` on top of `#attach`:

```ruby
def attach!(*attachables)
  record.public_send("#{name}=", blobs + attachables.flatten)
  record.save! if record.persisted? && !record.changed?
  record.public_send("#{name}")
end
```

That still changes the exception from `RecordNotSaved` to `RecordInvalid`, still needs matching `Attached::One` plus tests for new/dirty/return value/no double-save, and is a different PR than “always `save!`.” If the intended exception is the current `RecordNotSaved` `"Failed to save the record"`, the existing one-liner is already the right code.
