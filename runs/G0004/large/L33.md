`ActiveModel::Dirty` keeps two mutation-tracker slots. Current unsaved work lives in `@mutations_from_database`. The last applied snapshot lives in `@mutations_before_last_save`. Generated `*_changed?` / `*_was` / `*_change` methods read the current tracker; `*_previously_*` methods read the previous one.

Which tracker class you get depends on the model:

- No `@attributes` (plain `ActiveModel::Dirty`) → [`ForcedMutationTracker`](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L109-L173). In-place edits are invisible unless the app calls `*_will_change!`.
- `ActiveModel::Attributes` (or Active Record) → [`AttributeMutationTracker`](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L7-L107). Assignment and in-place string mutation are detected on the `Attribute` objects.

Until the first dirty query, both ivars are `nil`. Readers then lazy-build a current tracker or a [`NullMutationTracker`](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L175-L188) for “nothing previously saved.”

  name=, name_will_change!, name.replace
        │
        ▼
Dirty public API
  changed? / changes / *_was     previous_changes / *_previously_was
        │                                    │
        ▼                                    ▼

## The three lifecycle methods

[`changes_applied`](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L270-L276) is what a `save` calls. It does not persist anything; it only rotates dirty state.

```ruby
def changes_applied
  unless defined?(@attributes)
    mutations_from_database.finalize_changes
  end
  @mutations_before_last_save = mutations_from_database
  forget_attribute_assignments
  @mutations_from_database = nil
end
```

1. **Forced models only:** snapshot `[original, current]` into `@finalized_changes`. Without that freeze, a later edit would make `previous_changes` reread live attributes ([test: new attributes must not affect previous changes](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L148-L156)).
2. Move the current tracker object into `@mutations_before_last_save`.
3. If `@attributes` exists, replace it with `@attributes.map(&:forgetting_assignment)` so each `Attribute` is a fresh “from database” value with no assignment original ([`Attribute#forgetting_assignment`](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute.rb#L74-L76)). The *old* `AttributeSet` stays alive inside the previous tracker, so Attributes models do not need `finalize_changes`.
4. Nil the current tracker. The next `changed?` builds a new empty one.

Return value: `nil` (last statement assigns `nil`). After this, `changed?` is false and `previous_changes` holds what `changes` held.

[`restore_attributes`](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L319-L321) defaults to `changed` (currently dirty names) and restores only those names:

```ruby
def restore_attribute!(attr_name)
  attr_name = attr_name.to_s
  if attribute_changed?(attr_name)
    __send__("#{attr_name}=", attribute_was(attr_name))
    clear_attribute_change(attr_name)
  end
end
```

It writes through the setter, then `forget_change`. Unchanged names, and names you omit from the list, are left alone. It does **not** touch `previous_changes`. Return value is the names array (`each`’s return).

[`clear_changes_information`](file:///home/user/workspace/repo/activemodel/lib/active_model/dirty.rb#L324-L328) drops both trackers and forgets assignments. Attribute *values* stay. Return value: `nil`. This is the `reload!` hook in the module docs.

## Forced-tracker walkthrough

This is the [`DirtyTest::DirtyModel`](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L7-L44) style: instance variables plus explicit `*_will_change!`. Start with `@name = +"Yam"`, `@color = +"Red"`.

**0. Fresh.** `changed?` → `false`. `changes` → `{}`. `previous_changes` → `{}`. `name_was` → `"Yam"` (unchanged Forced original is just the live value). `name_previously_was` → `nil` (`NullMutationTracker#original_value`).

**1. In-place without `*_will_change!`.** `name.replace("Hadad")`. Still clean. Forced `changed_in_place?` is hardcoded `false` ([tracker](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L114-L116); [test](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L94-L101)). `name_was` is already `"Hadad"` because original is live.

**2. `name_will_change!`.** [`ForcedMutationTracker#force_change`](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L144-L146) clones the current value into `@forced_changes` *only if not already dirty*. Return: `"Hadad"`. Now `changed?` → `true`, `changes` → `{ "name" => ["Hadad", "Hadad"] }`, `name_was` → `"Hadad"`. The clone is what makes later in-place edits safe.

**3. In-place after the mark.** `name.replace("Baal")`. `changes` → `{ "name" => ["Hadad", "Baal"] }`. `name_was` stays `"Hadad"` (the clone). `previous_changes` still `{}`.

**4. `changes_applied`.** Finalizes `{ "name" => ["Hadad", "Baal"] }`, moves tracker 104 → previous, builds a new current tracker.

| | after apply |
|---|---|
| `changes_applied` | `nil` |
| `changed?` | `false` |
| `changes` | `{}` |
| `previous_changes` | `{ "name" => ["Hadad", "Baal"] }` |
| `name_was` | `"Baal"` |
| `name_previously_changed?` | `true` |
| `name_previous_change` | `["Hadad", "Baal"]` |
| `name_previously_was` | `"Hadad"` |

Quirk: `color` was never forced, so the *previous* tracker’s `original_value("color")` is a live `_read_attribute`. `color_previously_was` is `"Red"` here, and will drift after the next color write (see stage 5). Attributes models do not do this.

**5. Second edit.** `name = "Bob"`, `color = "White"` (setters call `*_will_change!` unless equal). Current and previous are independent ([test](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L148-L156)):

- `changed?` → `true`
- `changes` → `{ "name" => ["Baal", "Bob"], "color" => ["Red", "White"] }`
- `previous_changes` still `{ "name" => ["Hadad", "Baal"] }`
- `name_was` → `"Baal"`, `name_previously_was` → `"Hadad"`
- `color_was` → `"Red"`
- `color_previously_was` → `"White"` (Forced previous original for an unforced attr is live)

**6. Restore only `name`.** `restore_attributes(["name"])` returns `["name"]`. Name setter writes `"Baal"`, then `forget_change("name")`. Color is omitted, so it stays dirty ([test](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L226-L237)):

- `changed?` → `true`, `changed` → `["color"]`
- `changes` → `{ "color" => ["Red", "White"] }`
- `name` → `"Baal"`, `name_changed?` → `false`, `name_was` → `"Baal"`
- `color` → `"White"`, still dirty
- `previous_changes` unchanged

**7. `restore_attributes` with no args.** Default is `changed` → `["color"]`. Returns `["color"]`. Model is clean again; `previous_changes` still the last apply. Restoring is not a save and does not clear history ([test for full restore](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L213-L224)).

**`clear_changes_information`.** After `name` went `Yam → Dmitry` (applied) then `Bob`:

- before: `changes` `{ "name" => ["Dmitry", "Bob"] }`, `previous_changes` `{ "name" => ["Yam", "Dmitry"] }`
- returns `nil`
- `name` is still `"Bob"`
- `changed?` → `false`, `changes` → `{}`, `previous_changes` → `{}`
- `name_was` → `"Bob"`, `name_previously_was` → `nil`

That matches [the clear test](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L197-L211).

## Attributes-tracker walkthrough (same story, different detection)

[`AttributesDirtyTest::DirtyModel`](file:///home/user/workspace/repo/activemodel/test/cases/attributes_dirty_test.rb#L7-L22) uses `attribute :name, :string`. Dirty status is `Attribute#changed?` = assignment change **or** in-place change ([`attribute.rb`](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute.rb#L66-L72)). String types implement `changed_in_place?` as `raw_old_value != new_value` ([`type/string.rb`](file:///home/user/workspace/repo/activemodel/lib/active_model/type/string.rb#L16-L20)).

After init + `changes_applied`, in-place `name.replace("Hadad")` **is** dirty with no `*_will_change!` ([test](file:///home/user/workspace/repo/activemodel/test/cases/attributes_dirty_test.rb#L93-L98)):

- `changes` → `{ "name" => ["Yam", "Hadad"] }`
- `name_was` → `"Yam"`

`changes_applied` again: `changed?` false, `previous_changes` `{ "name" => ["Yam", "Hadad"] }`. Then `name = "Bob"`, `color = "White"`:

- same current/previous split as Forced
- `color_previously_was` stays `"Red"` because the previous tracker still holds the old `AttributeSet`

Partial restore of `["name"]` and full restore behave as in Forced ([test](file:///home/user/workspace/repo/activemodel/test/cases/attributes_dirty_test.rb#L189-L200)).

`name_will_change!` is optional here but still works: it only sets a key in `@forced_changes`. Original/current still come from the `Attribute`, so `force_change` storing the live string is enough to mark dirty even before the bytes change. After `name << " matey!"`, `name_change` is `["arr", "arr matey!"]`. Active Record’s [`test_attribute_will_change!`](file:///home/user/workspace/repo/activerecord/test/cases/dirty_test.rb#L315-L332) is the same contract; AR also auto-detects `<<` ([in-place test](file:///home/user/workspace/repo/activerecord/test/cases/dirty_test.rb#L667-L687)).

## Edge cases

**Omitted from `restore_attributes`.** Only listed (or currently dirty, when omitted entirely) names go through `restore_attribute!`. An omitted dirty attribute keeps its new value, stays in `changes`, and keeps `*_was`. `previous_changes` is untouched. Restoring a name that is not dirty is a no-op (no setter call).

**Changed back to the original value.** The two trackers disagree.

- **Forced:** `attribute_changed?` is `@forced_changes.include?(name)` ([tracker](file:///home/user/workspace/repo/activemodel/lib/active_model/attribute_mutation_tracker.rb#L164-L166)). A later `force_change` does not overwrite the clone. So `Otto → Dude → Otto` stays dirty with `changes` `{ "name" => ["Otto", "Otto"] }`. The setter must itself skip `*_will_change!` when `val == current` to avoid recording a no-op assign; [`color=`](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L26-L29) does that, [`name=`](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L21-L24) does not.
- **Attributes:** `Type::Value#changed?` is `old_value != new_value` ([`type/value.rb`](file:///home/user/workspace/repo/activemodel/lib/active_model/type/value.rb#L84-L86)). `Otto → Dude → Otto` is clean: `changed?` false, `name_change` nil. Cast-equal writes are also clean (`"2.3"` then `"2.1"` both become `2`, [test](file:///home/user/workspace/repo/activemodel/test/cases/attributes_dirty_test.rb#L193-L200)).

Multiple *distinct* writes keep the first original on both trackers ([test](file:///home/user/workspace/repo/activemodel/test/cases/dirty_test.rb#L179-L189)): `Otto → Dude → Mr. Manfredgensonton` → `name_change` `["Otto", "Mr. Manfredgensonton"]`, `name_was` `"Otto"`.

**Mutable values and `*_will_change!`.** On Forced models it is mandatory before in-place mutation; it clones so `*_was` does not mutate with the live object. On Attributes/AR string types it is not required; the type compares serialized original vs current. Calling it anyway just forces `changed?` even when the bytes are still equal (`["arr", "arr"]`).

**`clear_*` vs restore vs clear-all.** `clear_name_change` forgets tracking but leaves the new value. `restore_name!` writes the old value *and* forgets. `clear_changes_information` forgets current *and* previous tracking, leaves all values, and the next previous tracker is `NullMutationTracker`.
