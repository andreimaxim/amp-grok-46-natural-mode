`recognize_path` is a recognition-only API. It does not dispatch. It builds a fake request, asks Journey for candidate routes, then returns `req.path_parameters` only if the matching app is a dispatcher whose controller constantizes. Anything else either continues or becomes `ActionController::RoutingError`.

## Call flow

```text
RouteSet#recognize_path(path, environment)
  method  = (environment[:method] || "GET").upcase
  extras  = environment[:extras] || {}
  path    = Journey::Router::Utils.normalize_path(path)  unless path includes "://"
  env     = Rack::MockRequest.env_for(path, method:)     # URI::InvalidURIError → RoutingError
  req     = Request.new(env)
  RouteSet#recognize_path_with_request(req, path, extras, raise_on_missing: true)
    Journey::Router#recognize(req)
      filter_routes(path_info) via GTG::Simulator#memos
      append custom_routes whose path matches
      verb filter: Route#matches?(req)  (HEAD uses match_head_routes)
      sort by precedence
      for each route:
        merge route.defaults
        fill named captures; CGI.unescapeURIComponent if the capture contains "%"
        yield [route, params]
    then, per yield:
      params.merge!(extras)
      URI::RFC2396_PARSER.unescape every String value (BINARY first)
      req.path_parameters = params
      if app.matches?(req) && app.dispatcher?
        req.controller_class          # NameError → RoutingError (missing controller)
        return req.path_parameters
      elsif app.matches?(req) && app.engine?
        recurse with raise_on_missing: false
        return if the engine recognized
    if raise_on_missing: RoutingError "No route matches"
```

```diagram
                    path + environment
                            │
                            ▼
                 ┌─────────────────────┐
                 │ recognize_path      │
                 │ normalize? env_for? │
                 └──────────┳──────────┘
                            ▼
                 ┌─────────────────────┐
                 │ recognize_path_     │
                 │ with_request        │
                 └──────────┳──────────┘
                            ▼
                 ┌─────────────────────┐
            ┏━━━━│ Journey#recognize   │
            ┃    └──────────┳──────────┘
            ┃               ▼
            ┃    dispatcher && matches? ──▶ controller_class ──▶ path_parameters

            ┃               │

```

On a Rails app, [`LazyRouteSet`](file:///home/user/workspace/repo/railties/lib/rails/engine/lazy_route_set.rb#L106-L114) reloads routes, then calls this same pair.

## 1. Input → request

[`RouteSet#recognize_path`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/route_set.rb#L911-L924) reads only `:method` and `:extras`. Default method is `"GET"`. Other environment keys (`:subdomain`, etc.) are ignored here.

**Relative path.** Unless `path` contains `"://"`, it goes through [`Journey::Router::Utils.normalize_path`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/router/utils.rb#L22-L42): leading `/`, squeeze `//`, strip trailing `/`, uppercase `%xx`. `nil` becomes `"/"`.

Settled by:

- trailing slash ignored: [`test_draw_default_route`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L1212-L1213), [`test_default_route_recognition`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L1846-L1857)
- `recognize_path(nil)` → root params: [`test_recognize_path`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L2133-L2134)
- downcased percent-encoding still matches: [`test_downcased_unicode_path`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L2180-L2182)

**Absolute URL.** Normalization is skipped. `Rack::MockRequest.env_for` fills `PATH_INFO`, `HTTP_HOST`, `rack.url_scheme`. Journey matches `req.path_info`; host/scheme are available to request constraints.

Settled by [`test_route_with_subdomain_and_constraints_must_receive_params`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L1698-L1702) (`http://subdomain.example.org/page/mypage`) and protocol constraints in [`test_assert_recognizes_with_hash_constraint`](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_assertions_test.rb#L109-L113) (`https://test.host/...` vs `http://...`).

**Invalid URI.** `URI::InvalidURIError` from `env_for` is re-raised as `ActionController::RoutingError` with the URI message ([source](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/route_set.rb#L916-L919)). No routing test covers this; the rescue is the contract.

**Query string.** A `?…` on the path is Rack’s `QUERY_STRING`. Recognition returns **only** `path_parameters`, so query keys never appear in the result unless passed as `extras`. That is why [`assert_recognizes`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/testing/assertions/routing.rb#L177-L181) says appending a query string “will not work” and [`recognized_request_for`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/testing/assertions/routing.rb#L305-L334) always forwards `extras:`. [`test_assert_recognizes_with_extras`](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_assertions_test.rb#L99-L101) expects `{ page: "1" }` in the recognized hash. [`test_assert_recognizes_with_query_constraint`](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_assertions_test.rb#L122-L126) shows extras are also visible to `request.params` during `app.matches?`.

## 2. Journey matching

[`Journey::Router#recognize`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/router.rb#L42-L99):

1. `simulator.memos(path_info)` — GTG walk, returns route memos or `[]`.
2. Unanchored / non-anchored-requirement routes (`custom_routes`) are appended if `r.path.match?(path_info)`.
3. Verb filter via [`Route#matches?`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/route.rb#L172-L191): `VerbMatchers` plus hash constraints (`protocol`, `subdomain`, …) against `request.send(method)`. HEAD is special ([`match_head_routes`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/router.rb#L117-L128)): HEAD-specific routes first, else temporarily treat the request as GET.
4. Sort by `precedence` if more than one candidate.
5. Regex match, merge `r.defaults`, copy named captures.

**Method constraints.** Wrong verb ⇒ no yield ⇒ `"No route matches"`. Settled by [`test_recognize_array_of_methods`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L871-L881) and [`test_recognize_path`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L2101-L2104) (`PUT`/`DELETE` on a GET/POST route). Unknown verbs raise `ActionController::UnknownHttpMethod` from [`Request#check_method`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/http/request.rb#L522-L528) once a verb predicate runs; that is asserted on the serve helper [`request_path_params`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L1313-L1315), not on `recognize_path` itself.

**Path-segment constraints** live in the Journey regexp, so a failed `id: /\d+/` never yields. **Callable constraints** (`proc`, `matches?`) live on [`Mapper::Constraints#matches?`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/mapper.rb#L52-L57) and run *after* yield, with path params already assigned. [`TestConstraintsDontLeakBetweenRoutes`](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_test.rb#L5458-L5476) is the recognize_path coverage for hash/proc/class constraints.

Unanchored matches (mounts) rewrite `script_name` / `path_info` around the yield, then restore them ([router](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/router.rb#L81-L95)).

## 3. Decode, extras, dispatcher vs engine

[`recognize_path_with_request`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/route_set.rb#L926-L954) then:

1. `params.merge!(extras)`
2. For every String value: `force_encoding(BINARY)` then `URI::RFC2396_PARSER.unescape`
3. `req.path_parameters = params` (encoding check; invalid encoding → `ActionController::BadRequest`)
4. Accept only if `app.matches?(req)` **and** (`dispatcher?` or `engine?`)

Rack apps, redirects, and `Constraints::CALL` endpoints are skipped even if the path matched. If nothing dispatcher/engine-shaped succeeds, that is an unmatched route.

**Two unescapes.** Journey already runs `CGI.unescapeURIComponent` on captures that contain `%` ([router](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/journey/router.rb#L67-L76)). `recognize_path_with_request` unescapes again. `+` is not a space in either decoder.

Settled by:

- reserved characters: [`test_route_recognition_unescapes_path_components`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L39-L46)
- `+` stays `+`; `%20` / `%3F` decode: [`test_paths_escaped`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L596-L601)
- `%0A` → newline on dynamic and splat: [`test_escapes_newline_character_for_dynamic_path`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L651-L653), [`test_escapes_newline_character_for_wildcard_path`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L665-L667)
- unicode path: [`test_unicode_path`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L2176-L2177)

**Engine.** [`Endpoint#engine?`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/endpoint.rb#L14-L16) recurses with `raise_on_missing: false`, so an inner miss does not abort the parent walk. Settled by [`test_assert_recognizes_with_engine`](file:///home/user/workspace/repo/actionpack/test/dispatch/routing_assertions_test.rb#L146-L152) (`/shelf/books` → `books#index`).

Before returning, [`Request#controller_class`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/http/request.rb#L85-L88) does `params[:action] ||= "index"` on that same hash.

## 4. Unmatched route vs missing controller

These are different failures that both become `ActionController::RoutingError` at this API. The **message** is the distinction.

**Unmatched** (no dispatcher/engine yield succeeded), [`route_set.rb`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/route_set.rb#L951-L953):

```text
ActionController::RoutingError: No route matches "/none"
```

The `path` in the message is the post-normalize string for relative input, the original URL for absolute input.

Settled by [`test_recognize_path`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L2137) (`/none`), [`test_non_controllers` is the other class], method mismatch ([L2103-L2104](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L2103-L2104)), constraint miss ([L1708-L1710](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L1708-L1710)), root with no route ([L1853](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L1853)).

**Matched, controller will not constantize.** After a dispatcher match, `req.controller_class` → [`controller_class_for`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/http/request.rb#L91-L107) does `name.underscore.camelize << "Controller"` then `constantize`. A `NameError` whose missing name is that constant becomes [`ActionDispatch::MissingController`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch.rb#L50-L51) (`NameError`). `recognize_path_with_request` rescues **any** `NameError` and raises ([source](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/route_set.rb#L938-L941)):

```text
ActionController::RoutingError: A route matches "/not_a/show/10", but references missing controller: NotAController
```

Settled by [`test_non_controllers_cannot_be_matched`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L614-L621): dynamic `:controller/:action/:id` matches `/not_a/show/10`, then constantize fails. The test asserts `RoutingError`, not `MissingController`.

**Serve path is different.** [`Dispatcher#serve`](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/routing/route_set.rb#L46-L58) does not wrap that `NameError`. [`test_route_error_with_missing_controller`](file:///home/user/workspace/repo/actionpack/test/controller/routing_test.rb#L1282-L1286) uses `request_path_params` (real `routes.call`) and expects `ActionDispatch::MissingController` / `uninitialized constant DoesNotExistsController`.

| Case | `recognize_path` | Live `RouteSet#call` |
|---|---|---|
| No Journey/dispatcher/engine match | `RoutingError` `"No route matches …"` | 404 / debug `"No route matches [METHOD] …"` |
| Path matches, controller missing | `RoutingError` `"A route matches … missing controller: XController"` | `ActionDispatch::MissingController` |
| Query keys | Only if `extras:` | `request.query_parameters` / `params` |
| `+` in a segment | Literal `+` | Literal `+` |
| `%20` / `%0A` / `%3F` | Unescaped (` `, newline, `?`) | Unescaped |
| Trailing `/` (relative) | Stripped, then matched | Stripped in `#call` too |
| Absolute URL | Not normalized; host/scheme from URI | Real request env |
| Wrong HTTP method | `"No route matches"` | 404 / method cascade |
| Nested engine miss | Try next parent route | Cascade |

`MissingController` is the constantize failure. `recognize_path` never returns it; it always translates that failure into the “A route matches … missing controller” `RoutingError`. An unmatched path never attempts constantize.
