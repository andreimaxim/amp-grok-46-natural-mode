### `add` and `clear!`

Fewer than 5 on SQLite means a reader was skipped or results were shared across `primary_keys` and `columns` (current code does not share that work). More than 5 is an extra round trip.

### Duplicate-cache independence

Two fresh `SchemaCache` instances do not share maps. After A records `data_source_exists?("foo")`, B still pays **2** queries for the same name.

`dup` copies the five hashes (`initialize_dup`) but not the frozen column objects. After `original.clear_data_source_cache!(pool, "courses")`:

- `dup.columns(pool, "courses")` is **0** (still cached)
- `original.columns(pool, "courses")` is **1** (refill)

If both stay 0, the hashes were shared. If `dup` refills, the copy was too deep or missed `@columns`.

### Frozen / deduplicated values

On the live populate path (empty cache, `courses`):

- each `Column` is frozen; the same `Column` instance is reused across caches (`equal?`)
- column `name` strings and `sql_type_metadata` are interned (`equal?` across caches)
- `primary_keys` returns frozen `"id"`
- `columns_hash` is frozen; values are those frozen columns
- the `columns` **array** is not frozen
- `IndexDefinition` is not `Deduplicable`; index arrays/items are not frozen

YAML/`init_with` without `"deduplicated" => true` runs `derive_columns_hash_and_deduplicate_values` and rebuilds `@columns_hash` **without** `freeze`. Marshal load does the same. Do not assert a frozen hash after dump load; do assert it after live `columns_hash`. `"deduplicated" => true` must leave `coder["columns"]` as the same object (`assert_same`).

### Schema version and `check_schema_cache_dump_version`

`version(pool)` is **1** then **0**; `schema_version` is the memoized value (0 in this suite).

Check **on** (default): `cached?` is false until a pool is available. Load of a dump whose `version` ≠ `connection.schema_version` writes `Ignoring ... expired. The current schema version is X, but the one in the schema cache file is Y.` to stderr, discards the dump, and installs an empty cache. That load is **1** version query; the next `columns("courses")` is a live **1**. If it stays 0, the expired dump was used (stale entries). If version-check failure (`ActiveRecordError`) occurs, stderr matches `Failed to validate the schema cache because of ...` and the dump is also discarded.

Check **off**: `SchemaReflection.with(check_schema_cache_dump_version: false)`:

- `cached?("courses")` is true with **0** queries and no pool (`BoundSchemaReflection.new(reflection, :__unused_pool__)`)
- a dump with version `999999` loads with empty stderr; `columns` / `indexes` / `primary_keys` / `data_source_exists?` are **0** — stale dump is intentionally served

### Adapter portability

Pin exact first-access numbers only where this suite runs them (sqlite3_mem above). PostgreSQL / MySQL / Trilogy were not executed here.

Portable across adapters:

- repeat hit = 0
- ignored / missing **results** (`nil` / `false` / `[]` / `StatementInvalid`)
- `add` fills all four maps iff the table exists
- dump load of dumped members = 0
- old dump without indexes still queries `indexes`
- composite PK array vs nil for no PK
- gzip MD5 identity
- version-check on/off behavior

Not portable (do not hard-code SQLite 3/5):

- first-access SQL count for `indexes` (SQLite 2 after list; PG/MySQL are typically one `information_schema` / `pg_index` read)
- `add` total (SQLite 5 because PK and columns each call `table_structures`; other adapters usually 1 per reader)
- `version` SQL shape
- `lazily_load_schema_cache` connection-establish test (`unless in_memory_db?`)

On another adapter, capture first-access once with `include_schema: true` and treat that number as the ceiling: a later increase is an extra round trip; a decrease is a change in reader batching, not silently acceptable if the goal is preservation of the current call pattern.

They do **not** pin first-access counts for `columns` / `primary_keys` / `indexes` / `add`, duplicate-cache independence, live freeze/dedup, or stale-until-clear. Those are the gaps a preservation suite has to add.
