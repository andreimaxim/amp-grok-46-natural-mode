# Contract

`connected_to_many(*classes, role:, shard: nil, prevent_writes: role == ActiveRecord.reading_role)` is a Base-only, block-scoped, multi-klass stack push.

```text
connected_to_many(*classes, role:, shard: nil, prevent_writes:)
  classes = classes.flatten
  reject unless receiver is ActiveRecord::Base
  reject if flattened classes include ActiveRecord::Base
  reject if role is reading_role and prevent_writes is false
  append { role, shard, prevent_writes, klasses: classes }
  yield
ensure
  pop
```

Lookup walks `connected_to_stack` from the top. An entry applies to a model only if `klasses` includes `ActiveRecord::Base` or that model’s `connection_class_for_self`. Shard is ignored when `shard` is nil/falsey (`if hash[:shard]`). `prevent_writes: false` is a real value (`!hash[:prevent_writes].nil?`).

That yields these invariants:

- Splat + `flatten` accepts `Foo`, `Foo, Bar`, `[Foo]`, and nested arrays; the stored `klasses` list is the flattened result.
- Receiver must be `ActiveRecord::Base`. Any other receiver raises `NotImplementedError` (`"connected_to_many can only be called on ActiveRecord::Base."`) and must not touch the stack.
- Including `ActiveRecord::Base` in the class list raises the same `NotImplementedError`, even when the receiver is Base.
- `role:` is required. Default `prevent_writes` is true iff `role == ActiveRecord.reading_role`. Explicit `role: :reading, prevent_writes: false` raises `ArgumentError` with `"cannot set \`prevent_writes\` to false when \`role\` is \`reading\`."` before any push.
- Only listed connection classes change role/shard/`prevent_writes`. An unrelated connection class keeps the outer/prior entry.
- Nested `connected_to` / `connected_to_many` push a newer entry; `reverse_each` makes the inner entry win for matching klasses only.
- The ensure-pop restores the stack on normal return, `raise`, and `throw`.
- The stack lives in `ActiveSupport::IsolatedExecutionState[:active_record_connected_to_stack]`, so it is per thread by default (`isolation_level = :thread`) and per fiber if the harness sets `:fiber`.

Existing tests already cover receiver/Base rejection, default reading `prevent_writes`, splat flattening for one and two classes, and two-class role swap with one class left on writing. They do not systematically cover shard selection, explicit `prevent_writes` on writing, write attempts, `raise`/`throw` restore, or cross-context isolation.

# Observables and instrumentation

Use two layers. Do not treat a green `connected_to?` as proof that writes are blocked or that the stack was restored.

**Selection (must not leak role/shard)**

- `Klass.current_role`, `Klass.current_shard`, `Klass.connected_to?(role:, shard:)`
- `Klass.connection_pool.db_config.name` — actual pool, same pattern as `test_connected_to_many`
- `ActiveRecord::Base.connected_to_stack.dup` (size + each entry’s `role` / `shard` / `prevent_writes` / `klasses`) captured before the call, inside the block, and after every exit

**Write guard (must not allow accidental writes)**

- `Klass.current_preventing_writes` and `Klass.lease_connection.preventing_writes?`
- A real write on each connection class: `insert`/`update`/`delete` or `create!`. Expect `ActiveRecord::ReadOnlyError` (`"Write query attempted while in readonly mode"`) when prevented; expect the write to succeed when not. Pair every write probe with a `SELECT` that must still succeed.
- After the block, repeat the same write on the previously guarded class; it must succeed again if the outer role was writing and the connection is not a replica.

**Isolation**

- Snapshot `ActiveSupport::IsolatedExecutionState.context` in the parent.
- In a child `Thread` (and a `Fiber` if `isolation_level == :fiber`), assert the parent’s stack/role/shard/`prevent_writes` are invisible, and that a child `connected_to_many` does not mutate the parent’s stack after `join`.

Fixture shape for pool tests: two independent abstract connection classes plus one unrelated class, matching `PrimaryBase` / `SecondaryBase` / `TertiaryBase` in [`connection_swapping_nested_test.rb`](file:///home/user/workspace/repo/activerecord/test/cases/connection_adapters/connection_swapping_nested_test.rb). Skip file-backed sqlite cases with `unless in_memory_db?`. Keep `use_transactional_tests = false` and `clean_up_connection_handler` as that file does. Argument/receiver tests can stay on `FirstAbstractClass` / `SecondAbstractClass` in `base_test.rb`.

# Test matrix

Each row is one assertion cluster. Snapshot stack depth + `{role, shard, prevent_writes}` for all three connection classes at the points named.

## 1. Flattening class arguments

| ID | Call | Inside-block selection | After exit |
|---|---|---|---|
| F1 | `connected_to_many(A, role: :reading)` | `A` reading; `Base` unchanged | stack identical to before |
| F2 | `connected_to_many(A, B, role: :reading)` | `A` and `B` reading; unrelated not | restored |
| F3 | `connected_to_many([A], role: :reading)` | same as F1 | restored |
| F4 | `connected_to_many([A, B], role: :reading)` | same as F2 | restored |
| F5 | `connected_to_many([[A], [B]], role: :reading)` | same as F2 (`flatten` is recursive) | restored |

F1/F2 exist today; F3–F5 are the preservation risk if a refactor stops flattening or stores the unflattened array. Observable: `connected_to_stack.last[:klasses] == [A]` or `[A, B]`, plus `A.connected_to?(role: :reading)`.

## 2. Role and shard for two classes; unrelated stays put

Establish `A` and `B` with writing/reading and at least `default` / `shard_one`. Leave `U` (unrelated) on an outer `connected_to(role: :writing, shard: :default)`.

| ID | Call | A | B | U |
|---|---|---|---|---|
| S1 | `connected_to_many(A, B, role: :reading)` | reading, **prior shard** (entry `shard` is nil, so shard lookup skips it) | same | writing / default |
| S2 | `connected_to_many(A, B, role: :reading, shard: :shard_one)` | reading / shard_one replica | same | writing / default |
| S3 | `connected_to_many(A, B, role: :writing, shard: :shard_one)` | writing / shard_one | same | writing / default |
| S4 | `connected_to_many(A, role: :reading, shard: :shard_one)` | reading / shard_one | **unchanged** | unchanged |

Observables: `connection_pool.db_config.name` for A, B, U; `current_role` / `current_shard`. S1 is the easy leak: a refactor that writes `shard: shard` as `:default` when nil would change U’s or A’s shard even though today’s code leaves shard lookup to the outer entry.

Writes: on S1/S2, `A.create!` and `B.create!` raise `ReadOnlyError`; `U.create!` succeeds. SELECT on all three succeeds.

| ID | Nesting | While inner is active | After inner | After outer many |
|---|---|---|---|---|

## 8. Restoration after return, raise, and throw

Same setup; snapshot stack + A/B/U role/shard/`prevent_writes` before the call.

| ID | Block body | Exit | After |
|---|---|---|---|
| E1 | successful writes/reads; return a value | normal return; yielded value is returned unchanged | stack and A/B/U state identical to before |
| E2 | `raise RuntimeError, "boom"` after asserting inner state | error propagates | restored; A writable again |
| E3 | `throw :done, :token` after asserting inner state | `catch(:done)` gets `:token` | restored |
| E4 | inner `connected_to` raises | both frames restored | restored |
| E5 | `append_to_connected_to_stack` raises `ShardSwapProhibitedError` (`shard:` set while `A.prohibit_shard_swapping`) | error before yield | stack unchanged (nothing pushed, so no pop). A still on prior shard |

E5 already has a prohibition test; add the before/after stack snapshot. E2/E3 are the leak tests a `begin/yield/end` without `ensure` would fail. Use `throw` specifically — `ensure` runs on throw; `rescue` does not.

After E2/E3, run `A.create!` / `B.create!`. If either raises `ReadOnlyError`, `prevent_writes` leaked.

## 9. Concurrent execution contexts

Parent holds `connected_to_many(A, B, role: :reading)` (or has just exited it).

| ID | Context | Child does | Parent after join | Child while running |
|---|---|---|---|---|
| I1 | `Thread.new` | read A/B/U role/shard/`prevent_writes` and stack | parent still reading inside the block | child sees default/writing, empty or its own stack, not parent’s top entry |
| I2 | `Thread.new` | `connected_to_many(A, role: :reading)` then write on U | parent stack depth unchanged | child’s A is reading; parent’s A unchanged from the parent’s point of view |
| I3 | same as I1 after parent block has returned | observe parent | parent fully restored | child never saw the reading entry |
| I4 | if harness can set `IsolatedExecutionState.isolation_level = :fiber` | same as I1–I3 with `Fiber` | same | same |

Default isolation is `:thread`; do not claim fiber isolation unless the test actually sets `:fiber` and restores it (pattern in [`connection_pool_test.rb`](file:///home/user/workspace/repo/activerecord/test/cases/connection_pool_test.rb)). Latch the child so it samples while the parent is still inside the block (`CountDownLatch` is already required in `base_test.rb`).

I1/I2 are the concurrent leak tests: a global stack or a shared array without per-context storage would show the parent’s reading role in the child, or leave the child’s push on the parent.

# Priority order

Run these first; they are the ones that catch leaked role/shard and accidental writes:

1. **E1–E3** — restore after return/raise/throw, with post-exit writes.
2. **S1–S4 + write probes** — two classes swap, unrelated stays, shard nil vs explicit.
3. **P1 and P4 + `ReadOnlyError`** — default reading blocks writes; explicit writing+prevent_writes blocks only listed classes.
4. **I1–I2** — parent/child stacks do not share.
5. **C1/C3** — nested override is per-klass; inner pop does not pop the outer many-entry.
6. **R1, N1, B2** — rejected calls never push.
7. Flattening (F3–F5) and prohibition (E5) after the above are green.

Pass criterion for the refactor: every cell’s selection, write, and stack-snapshot assertions match current main, including error classes and messages already asserted in `base_test.rb`.
