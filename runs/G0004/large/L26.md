`LookupContext` is the request-scoped holder of view paths plus the current locale/format/variant/handler lists. It does not search the disk itself. `#find` / `#find_all` normalize the name, snapshot details, then ask `PathSet` to walk prefixes × resolvers. `FileSystemResolver` globs candidates for one virtual path, then `TemplateDetails` filters and ranks them.

```text
LookupContext#find / #find_all / #find!
  normalize_name
  detail_args_for  →  [details Hash, details_key or nil]
  PathSet#find / #find_all / #find!
    for each prefix:
      for each resolver:
        FileSystemResolver#find / #find_all
          requested = details_key || TemplateDetails::Requested.new(**details)
          unbound_templates_for(virtual path)   # cache iff details_key
          matches? / rank_for / sort_key_for
          UnboundTemplate#bind_locals(locals)
```

## Mutable details vs interned cache keys

Registered details are `locale`, `formats`, `variants`, `handlers` ([lookup_context.rb](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L46-L55)). The live state is `@details`, a Hash. Getters read that Hash. Most setters wrap the value in `Array(...)` (or restore the default if blank) and call `_set_detail`.

`_set_detail` copies `@details` when a cache object already exists, then drops `@details_key` and `@digest_cache` ([lookup_context.rb](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L133-L138)). Changing formats or locale mutates lookup state; it does not mutate a previously interned key.

The interned key is a `TemplateDetails::Requested` built by `DetailsKey.details_cache_key` ([lookup_context.rb](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L64-L73)). Same Hash contents reuse the same `Requested` object (the test that cycles locale `:en` → `:da` → `:en` gets two unique keys, not three: [lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L131-L151)). `DetailsKey` aliases `eql?` to `equal?`, so identity is the equality.

`Requested` is not a filename cache key. It is an index of requested values:

```43:49:actionview/lib/action_view/template_details.rb
    def sort_key_for(requested)
      [
        requested.formats_idx[@format],
        requested.locale_idx[@locale],
        requested.variants_idx[@variant],
        requested.handlers_idx[@handler]
      ]
    end
```

`build_idx_hash` always appends `nil`, so a file that omits locale, format, variant, or handler still matches, ranked last in that dimension. `variants: :any` replaces the variant index with `ANY_HASH` (`nil => 0`, everything else `1`).

`details_cache_key` may rewrite `:formats` through `Template.normalized_formats` (`formats & Types.symbols` when the list is not already all valid symbols) before interning. The mutable `@details` Hash is left as-is. Handlers stay in the interned key even though the comment on `details_key` says they are removed ([lookup_context.rb](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L118-L122)).

`@cache` defaults to `true`. `details_key` is only computed when `@cache` is on. `disable_cache` sets `@cache = false` for the block, so `detail_args_for` passes `details_key = nil`.

## `#find` vs `#find_all`

Both run the same name and details prep ([lookup_context.rb](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L145-L161)):

1. `normalize_name` — `name.to_s`; if it contains `/`, the last segment is the template name and earlier segments are joined onto every prefix (or become the only prefix). A leading `/` on that path prefix is stripped. No slash → prefixes stay as given, or `[""]` if they were blank.
2. `detail_args_for(options)` — empty options (the common path) reuse `@details` and `details_key`. Non-empty options merge onto `@details` without going through `formats=` / `locale=` / `variants=`. Cache on → intern a key for that merged Hash; cache off → `nil` key.
3. Delegate to `@view_paths`.

`#find!` is `#find` plus `MissingTemplate` if the result is `nil` ([path_set.rb](file:///home/user/workspace/repo/actionview/lib/action_view/path_set.rb#L48-L51)). `#find` returns one template or `nil`. `#find_all` returns the matching list or `[]`. Neither method unions hits across prefixes or resolvers: the first prefix × resolver that produces a template (or a non-empty list) wins ([path_set.rb](file:///home/user/workspace/repo/actionview/lib/action_view/path_set.rb#L40-L72)). Search order is prefixes outer, resolvers inner.

`FileSystemResolver#find` picks the single best `rank_for` (lowest `[format, locale, variant, handler]`). `#find_all` keeps every `matches?` hit and `sort_by!` `sort_key_for` ([resolver.rb](file:///home/user/workspace/repo/actionview/lib/action_view/template/resolver.rb#L156-L247)). A one-element candidate list only checks `matches?`; no sort.

A name containing `.` short-circuits to no files ([resolver.rb](file:///home/user/workspace/repo/actionview/lib/action_view/template/resolver.rb#L201-L204)). `find_all("hello_world.html", ...)` is empty even when `hello_world.html.erb` exists ([resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L230-L234)).

## PathSet into the resolver

`PathSet` typecasts strings/Pathnames to `FileSystemResolver` ([path_set.rb](file:///home/user/workspace/repo/actionview/lib/action_view/path_set.rb#L75-L89)). The virtual path is `TemplatePath.virtual(name, prefix, partial)`: `test/hello_world` or, if `partial` is true, `test/_hello_world` ([template_path.rb](file:///home/user/workspace/repo/actionview/lib/action_view/template_path.rb#L17-L24)).

The resolver globs `#{virtual}*` under its root, parses each relative path with `PathParser` (`name.locale.format+variant.handler`), keeps exact virtual-path matches, then filters by requested details. Unbound templates are cached under that virtual path only when `key` is truthy — i.e. when lookup cache is on ([resolver.rb](file:///home/user/workspace/repo/actionview/lib/action_view/template/resolver.rb#L175-L181)). The glob cache is not keyed by locale/format/variant. Details only filter the already-found files. That is why `hello_world.html.erb` is the same object for `locale: [:en]` and `locale: [:fr]` ([resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L124-L130)).

## Ranking (locale / format / variant / handler)

Filename order parsed: locale, format, variant, handler ([resolver.rb](file:///home/user/workspace/repo/actionview/lib/action_view/template/resolver.rb#L23-L48)). Preference order among matches is the opposite of that parse order: **format, then locale, then variant, then handler**. Earlier entries in each requested array win. `nil` (omitted extension) always matches and always loses to a concrete match in the same dimension.

Observable sets from the shared resolver tests ([resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L132-L204)):

| Request | Files present | `#find_all` order | `#find` |
|---|---|---|---|
| `formats: [:json, :html]` | `.html.erb`, `.json.builder` | json, then html | json |
| `formats: [:html, :json]` | same | html, then json | html |
| `locale: [:en]` | `.text.erb` (no locale) + `.fr.text.erb` | generic only | generic |
| `locale: [:fr]` | same | French, then generic (same object as the en hit) | French |
| `variants: [:tricorder]` | `+tricorder`, `+lcars` | `[tricorder]` | tricorder |
| `variants: [:tricorder, :lcars]` | same | tricorder, lcars | tricorder |
| `variants: [:lcars, :tricorder]` | same | lcars, tricorder | lcars |
| `variants: :any` | `html+phone.erb` | that file | that file |
| `variants: []` (default) | a `+phone` file and a no-variant file | only the no-variant file | no-variant |
| `formats: [:xml], handlers: [:erb]` against `.html.erb` | that file | `[]` | `nil` |

Default `variants` is `[]`, so varianted files are excluded until variants are set. `any?` / `any_templates?` is the other path: it builds details from the default procs but forces `variants: :any` ([lookup_context.rb](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L214-L231)).

On the fixture tree used by `LookupContextTest`, `find("hello_world", %w(test))` with default details is `hello_world.erb` (“Hello world!”). After `locale = :da` it is `hello_world.da.html.erb` (“Hey verden”). After `formats = [:html]` and `variants = [:phone]` it is `hello_world.html+phone.erb` (“Hello phone!”). After switching formats to `[:text]` with the same variant it is `hello_world.text+phone.erb` (“Hello texty phone!”) ([lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L100-L121)).

`locale=` does not store the argument in `@details[:locale]`. It writes `I18n.locale`, then stores `default_locale` (current locale, I18n fallbacks if present, then `I18n.default_locale`, uniqued). The `locale` getter returns only `@details[:locale].first` ([lookup_context.rb](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L305-L320)).

## `formats = [:js]`

The `formats=` override runs before the generic setter ([lookup_context.rb](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L287-L303)):

1. Dup the array.
2. If `"*/*"` is present (`==`, so `Mime::ALL` counts; see next section), delete those entries and append `default_formats`.
3. `uniq!`
4. `Template.validate_formats`
5. If the list is exactly `[:js]`, append `:html` and set `@html_fallback_for_js = true`
6. `super`

So `formats = [:js]` stores `[:js, :html]` and sets the HTML-fallback flag ([lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L64-L67)). Lookup then prefers a `.js` template over `.html` because format index 0 beats index 1. A missing `.js` file still matches `.html`. The flag is only set in that branch; later `formats=` assignments do not clear it. `AbstractRenderer#prepend_formats` and `ActionView::Base#in_rendering_context` skip extra format prepending when the flag is already true.

Constructor `LookupContext.new(paths, formats: [:js])` does **not** run this override. `initialize_details` copies the Hash as given, so you can have `[:js]` with no HTML fallback and no validation.

`with_prepended_formats` also skips `formats=`: it dups `@details`, assigns `:formats` directly, and builds a new context ([lookup_context.rb](file:///home/user/workspace/repo/actionview/lib/action_view/lookup_context.rb#L272-L277)).

## Explicit `Mime::ALL`

`Mime::ALL` is `Mime::AllType` with string `"*/*"` ([mime_type.rb](file:///home/user/workspace/repo/actionpack/lib/action_dispatch/http/mime_type.rb#L433-L447)). `values.delete "*/*"` removes it via `Mime::ALL == "*/*"`.

`formats = [:js, Mime::ALL]` therefore becomes `[:js] + default_formats`, uniqued — in the Action Dispatch test environment, `[:js, *Mime.symbols].uniq` ([lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L54-L62)). Length is no longer 1, so the `[:js]`-only HTML fallback branch does not run (HTML is already in `Mime.symbols`). `formats = ["*/*"]` alone becomes `Mime.symbols`.

`"*/*"` / `Mime::ALL` is not itself a lookup format. After expansion, matching uses the concrete symbol list.

## Invalid formats

`formats = [:html, :invalid, "also bad"]` raises before `@details` changes:

```text
ArgumentError: Invalid formats: :invalid, "also bad"
```

([template.rb](file:///home/user/workspace/repo/actionview/lib/action_view/template.rb#L204-L212), [lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L69-L75)). No template is selected.

Invalid formats in `#find` / `#find_all` **options** skip `formats=`. Cache on: the interned `Requested` uses `formats & Types.symbols`, so only valid symbols participate in matching. Cache off: `Requested.new(**details)` indexes the raw list, including junk symbols that no file will have. In both cases lookup does not raise; unmatched junk just does not hit a file.

## Partials

`partial: true` only changes the virtual path (`prefix/_name`) and the missing-template wording. Details, ranking, and cache behavior are unchanged.

`find("foo", %w(parent child), true)` searches `parent/_foo` then `child/_foo`. `find!` on a miss raises `ActionView::MissingTemplate` whose message lists those paths and the inspected details Hash ([lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L268-L280), [error.rb](file:///home/user/workspace/repo/actionview/lib/action_view/template/error.rb#L41-L67)). A string prefix is accepted (`Array(prefixes)`). `normalize_name("parent/foo", [])` with `partial: true` becomes name `foo`, prefix `parent`, virtual `parent/_foo`.

## Locals do not choose the file

The `keys` argument is locals, forwarded as the last argument to the resolver. Selection uses only locale/format/variant/handler. After that, `UnboundTemplate#bind_locals` builds a `Template`.

Non-strict templates: locals are symbolized, sorted, frozen; each distinct set is a different `Template` object, cached on the unbound wrapper. `[:post]` vs `[:post, :other]` are different objects; `[:other, :post]` is the same object as `[:post, :other]` ([file_system_resolver_test.rb](file:///home/user/workspace/repo/actionview/test/template/file_system_resolver_test.rb#L95-L109)).

Strict locals (`<%# locals: (...) %>`): the first bind wins; later local-key lists return that same object. Locals on the `Template` are `nil` ([resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L258-L268), [file_system_resolver_test.rb](file:///home/user/workspace/repo/actionview/test/template/file_system_resolver_test.rb#L111-L121)). Passing the wrong locals is not a lookup miss; it fails later at render (`StrictLocalsError`).

## Cache on vs cache off

Cache **on** (default): `details_key` is a `Requested`. The resolver memoizes the unbound list per virtual path. Repeated `find` of the same path/details returns the same `Template` (`assert_same`). Changing locale to `:da` selects `_foo.da.erb`; changing back to `:en` returns the original object ([lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L153-L177)). Two locale lists that both match the same file still share that object.

Cache **off** (`disable_cache`): `details_key` is `nil`, so `unbound_templates_from_path` runs every time and builds new `UnboundTemplate`s. `find` returns a different object with the same source. The existing unbound cache is not cleared; a `find` after the block is `assert_same` as the pre-block template ([resolver_shared_tests.rb](file:///home/user/workspace/repo/actionview/test/template/resolver_shared_tests.rb#L110-L122), [lookup_context_test.rb](file:///home/user/workspace/repo/actionview/test/template/lookup_context_test.rb#L179-L194)).

Matching and ranking are the same in both modes. Cache only controls object identity and whether the directory glob is reused. `Resolver.caching` on the class is unused by `FileSystemResolver#find` / `#find_all`; the live switch is LookupContext’s `@cache` / truthy `key`.
