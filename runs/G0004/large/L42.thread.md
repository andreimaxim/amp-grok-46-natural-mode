`config_for` is a one-shot file load, not a cached config object. It resolves a YAML path, parses (ERB then Psych), symbolizes keys, picks `env` plus optional `shared`, then wraps a Hash root in `ActiveSupport::OrderedOptions`. Non-Hash roots and missing env/shared fall through as the raw value, which is often `nil`.

```text
Rails::Application#config_for(name, env: Rails.env)
  Pathname: name if Pathname, else #{paths["config"].existent.first}/#{name}.yml
  missing file → raise RuntimeError
  ActiveSupport::ConfigurationFile.parse(yaml)
    File.read
    if content includes "<%": ERB.result (TOPLEVEL_BINDING)
    YAML.unsafe_load_file or YAML.unsafe_load
    nil/false → {}
  Hash#deep_symbolize_keys
  config = all_configs[env.to_sym]
  shared = all_configs[:shared]
  if shared:
    nil env + Hash shared → {} then deep_merge
    both Hash → shared.deep_merge(config)   # env wins
    nil env otherwise → config = shared     # arrays, scalars
    env present and not both Hash → keep env
  Hash root → OrderedOptions.new.update(config)
  return config
```

### ERB

[`ConfigurationFile#parse`](file:///home/user/workspace/repo/activesupport/lib/active_support/configuration_file.rb#L22-L34) ERB-renders only when the raw file contains `"<%"`. `config_for` passes no `context:`, so `ERB#result` runs in `TOPLEVEL_BINDING`. ### `shared` and environment selection

After symbolize, only the **document-root** keys `env` and `:shared` matter.

| Inputs | Result | Established by |
|---|---|---|
| both Hash | `shared.deep_merge(config)` — env overrides, nested hashes recurse | [override](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2769-L2779), [deep merge](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2795-L2809), RDoc/guide example |
| env missing, shared Hash | treat env as `{}`, then same deep_merge | [missing env uses shared](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2782-L2792); empty `test:` in the OrderedOptions test |
| env missing, shared non-Hash | `config = shared` (array/scalar) | [shared-only array](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2709-L2718) |
| env present, not both Hash | keep env; shared ignored | [env array wins over shared array](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2721-L2732) |
| no env, no shared | `nil` | [absent environment](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2758-L2766) |

`Hash#deep_merge` is [`ActiveSupport::DeepMergeable`](file:///home/user/workspace/repo/activesupport/lib/active_support/deep_mergeable.rb#L33-L47): nested Hashes recurse; anything else (including arrays) is replaced by the env value. Array-root non-merge is a tested contract; nested array replacement is just that algorithm.

The `config = {} if config.nil? && shared.is_a?(Hash)` line exists so a missing env still takes the Hash merge path (and therefore later OrderedOptions wrapping) rather than returning the shared Hash unwrapped.

### Return value: OrderedOptions, scalars, arrays

Only a Hash after merge is wrapped:

```ruby
ActiveSupport::OrderedOptions.new.update(config)
```

[`OrderedOptions`](file:///home/user/workspace/repo/activesupport/lib/active_support/ordered_options.rb#L33-L67) is a Hash. `#[]` / `#[]=` coerce the **lookup** key with `to_sym`; `#update` is plain `Hash#update` and does not coerce stored keys. That is why `deep_symbolize_keys` must run first: string keys stored by `update` would miss on `[:foo]`.

**Intentional, tested:**

- Root Hash is `ActiveSupport::OrderedOptions`; method access `config.some_key` works ([test](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2869-L2888)).
- Root still behaves as a Hash: `#keys`, `#values`, `#to_h`, `==` ([test](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2678-L2694)).
- Root lookup accepts string or symbol ([test](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2653-L2662)). That is OrderedOptions, not indifferent nested hashes.
- Nested hashes are **plain Hashes with symbol keys**, not OrderedOptions ([nested test](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2665-L2675)). String keys at nested levels are not part of this contract; the 6.1 upgrade guide states they do not work.
- Array env root is returned as `Array`, not wrapped ([test](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2697-L2706)). Same for a shared-only array.

**Incidental:** wrapping is root-only, so `config.foo.bar` method-chains only if you treat nested values as OrderedOptions — they are not. `Hash#==` against a Hash works because OrderedOptions < Hash.

### Empty file, absent env, missing file

Empty file: Psych `unsafe_load_file` returns `false` for an empty document; parse does `|| {}`. Then `{}[env]` and `{}[:shared]` are both `nil`, so `config_for` returns `nil` ([test](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2812-L2817)). The `nil` is not a special empty-file branch in `config_for`; it is missing env on an empty Hash.

Absent environment in a non-empty file, no usable `shared`: same `nil` ([test](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2758-L2766)).

Missing file: does not parse; raises before ([test](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2746-L2756)).

`development:` with no value is Psych `nil`, which is “env missing,” not an empty Hash. With `shared`, that is the “return shared” path (the `env: :test` half of the OrderedOptions test, where `test:` is blank).

### YAML parsers and `symbolize_names`

Current `config_for` never passes `symbolize_names`. Compatibility is “parse however Psych/`**options` would, then `deep_symbolize_keys`.”

The test named for safe_yaml-style patches ([test](file:///home/user/workspace/repo/railties/test/application/configuration_test.rb#L2856-L2866)) stubs `YAML.load` and asserts `{ key: "value" }`. [`ConfigurationFile`](file:///home/user/workspace/repo/activesupport/lib/active_support/configuration_file.rb#L26-L28) calls `YAML.unsafe_load_file` / `YAML.unsafe_load`, so that stub does not intercept the parser. The assertion still holds because the file on disk is string-keyed YAML and `deep_symbolize_keys` is unconditional.

**Contract:** callers get symbol keys even when the YAML library emits strings. **Not a current contract:** `symbolize_names` support, or `YAML.load` being the parse entry. The test name describes a former implementation (`YAML.load(..., symbolize_names: true)` plus fallback). Parser tests also show raw `ConfigurationFile.parse` returns **string** keys (`{ "ok" => 42 }`); symbolization is `config_for`’s job, not the parser’s.

### Intentional vs incidental

**Intentional (API / tests / RDoc):** `config/*.yml` (or a Pathname), ERB, `env:` override, root `shared` deep-merged under Hash env, env Hash overrides shared, missing env with Hash `shared` still yields that config as OrderedOptions, array roots not merged and not wrapped, missing env without `shared` → `nil`, empty file → `nil`, missing file → `RuntimeError`, YAML syntax → `FormatError`, Hash result is OrderedOptions with symbol keys and Hash methods, string/symbol access at the **root**.

**Incidental (follows from helpers, not specified by `config_for` tests):** ERB binding and the `<%` short-circuit; `unsafe_load*` vs `load`; BOM/encoding split; NBSP warning; `|| {}` Psych fallback; `if shared` truthiness; `deep_merge` replacing nested arrays; no wrapping of nested hashes; `Hash#update` not symbolizing keys (hence the order symbolize-then-wrap); no caching; an environment named `shared`; `database.yml`’s separate shared algorithm.
