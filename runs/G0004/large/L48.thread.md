## Assistant

`rails/test_help` is a require-time hook file, not a library of methods. Its public effects are what those hooks do to already-loaded (or later-loaded) test classes. Existing railties tests never pin that contract; a reorg can pass the suite and still change behavior.

### Current public effects (from source)

[`railties/lib/rails/test_help.rb`](file:///home/user/workspace/repo/railties/lib/rails/test_help.rb) does this, in order:

```text
require "rails/test_help"
  abort if Rails.env.production?
  require AS::TestCase, generators/test_case, autorun
  require rails/testing/maintain_test_schema
    → AR only: maintain_test_schema! / exit 1 on pending migrations
  if defined?(ActiveRecord::Base)
    on_load(:active_support_test_case)                 # runs now: TestCase already required
      include TestDatabases, TestFixtures, QueryAssertions
      TestFixtures.included
        → run_load_hooks(:active_record_fixtures, TestCase)
            engine extra paths: fixture_paths |= ["#{engine.root}/test/fixtures/"]
      fixture_paths = [*fixture_paths, "#{Rails.root}/test/fixtures/"].uniq
      file_fixture_path = "#{Rails.root}/test/fixtures/files"
    on_load(:action_dispatch_integration_test)
      fixture_paths += ActiveSupport::TestCase.fixture_paths
  else
    on_load(:active_support_test_case)
      file_fixture_path = "#{Rails.root}/test/fixtures/files"   # no fixture_paths
  on_load(:action_controller_test_case)
    def before_setup; @routes = Rails.application.routes; super
  on_load(:action_dispatch_integration_test)
    def before_setup; @routes = Rails.application.routes; super
```

Generated apps always boot the environment **before** this file ([`test/test_helper.rb.tt`](file:///home/user/workspace/repo/railties/lib/rails/generators/rails/app/templates/test/test_helper.rb.tt)), so `ActiveSupport::TestCase` and `ActionDispatch::IntegrationTest` are already loaded. Hooks therefore run **immediately** at require time, with the current `Rails.root`.

Consequences that a reorg must keep:

- **App fixture path is interpolated at hook run**, not at file parse. It is always the string `"#{Rails.root}/test/fixtures/"` with a trailing slash. `file_fixture_path` has **no** trailing slash.
- **Engine extra paths land first.** [`Rails::Engine`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb#L655-L661) registers `on_load(:active_record_fixtures)` at boot; `TestFixtures` fires that hook during `include`; then test_help appends the app path with `.uniq`. Applications themselves are skipped (`next if is_a?(Rails::Application)`), so the app path comes only from test_help.
- **`.uniq` is string identity**, not realpath. `/abs/test/fixtures/` and `test/fixtures/` both stay. Trailing-slash vs not are different entries.
- **`IntegrationTest.fixture_paths += TestCase.fixture_paths` assigns a new array on the subclass.** Because `fixture_paths` is a `class_attribute` inherited from `TestCase` ([`test_fixtures.rb`](file:///home/user/workspace/repo/activerecord/lib/active_record/test_fixtures.rb#L31)), this concatenates the inherited list with itself. Duplicate strings on `IntegrationTest` are current behavior. `fixtures :all` later `.uniq`s names ([`fixtures` method](file:///home/user/workspace/repo/activerecord/lib/active_record/test_fixtures.rb#L71-L82)), so loading still works.
- **Subclasses that do not assign `fixture_paths` inherit later parent writes.** `IntegrationTest` *does* assign, so it snapshots at hook time.
- **Repeated `require` is a no-op** (`$LOADED_FEATURES`). A second `load` would re-run hooks: TestCase assignment stays idempotent via `.uniq`; IntegrationTest `+=` would duplicate again; `before_setup` would be redefined (still one method).
- **No existence check** on the app fixtures dir. Missing dir: `fixtures :all` finds nothing and does not raise; `file_fixture` raises `ArgumentError` ([`file_fixtures.rb`](file:///home/user/workspace/repo/activesupport/lib/active_support/testing/file_fixtures.rb#L27-L34)).
- **Without AR:** no `fixture_paths`, no `TestFixtures`/`QueryAssertions`/`TestDatabases`. `file_fixture_path` is still set. `fixtures :all` is omitted from the generated helper ([`shared_generator_tests.rb`](file:///home/user/workspace/repo/railties/test/generators/shared_generator_tests.rb#L261-L263)).
- **`before_setup` captures `Rails.application.routes` at test run**, not at require. A second boot that replaces `Rails.application` is visible on the next test instance *if* the method still calls `Rails.application.routes`. Fixture *paths* captured at first hook run are **not** updated.
- Post-require assignment must keep working. Plugin helpers *replace* paths after require ([`plugin/templates/test/test_helper.rb.tt`](file:///home/user/workspace/repo/railties/lib/rails/generators/rails/plugin/templates/test/test_helper.rb.tt#L15-L20)). Do not freeze the arrays.

### Strategy: isolate, then observe effects

Put new coverage in a railties isolation test (same shape as [`test_test.rb`](file:///home/user/workspace/repo/railties/test/application/test_test.rb)): `build_app`, write fixtures + tests into the app, `rails test`, assert on that run’s output. Do **not** `require "rails/test_help"` in the parent process.

Each child test file should prove behavior by **using** fixtures, not by printing `fixture_paths` as the only assertion. Class-variable dumps are allowed as a secondary check when the observable effect would miss a duplication/inheritance bug.

#### Shared app fixture set

In the generated app:

```text
test/fixtures/users.yml            # app default path
test/fixtures/files/hello.txt      # file fixture
test/extra_fixtures/posts.yml      # extra path
test/extra_fixtures/files/extra.txt
```

Model tests use `users(:bob)` / `posts(:hello)`. File tests use `file_fixture("hello.txt").read`. Integration tests `get` a route **and** read a fixture in the same example so `@routes` and fixture loading are both exercised.

`fixtures :all` must not pick up `test/fixtures/files/*.yml` because of the `file_fixture_path` reject in [`TestFixtures.fixtures`](file:///home/user/workspace/repo/activerecord/lib/active_record/test_fixtures.rb#L76). Put a decoy `test/fixtures/files/not_a_fixture.yml` in and assert it is **not** a fixture set.

#### Case matrix

**1. Default AR app, require once**

- `users(:bob)` is loaded from `"#{Rails.root}/test/fixtures/"` (absolute, trailing slash).
- `file_fixture("hello.txt").read` equals file contents.
- `ActionDispatch::IntegrationTest` can `get "/users"` (routes from `before_setup`) and `users(:bob)` in the same test.
- Secondary: `TestCase.fixture_paths` includes exactly one copy of the app path; `IntegrationTest.fixture_paths` currently contains that path **twice**. Preserve unless the reorg explicitly documents dropping the `+=` duplication. Loading must still succeed either way.

**2. Extra paths already present when the hook runs (engine / `active_record_fixtures`)**

Mount a dummy engine with `test/fixtures/bukkits.yml`, or register:

```ruby
ActiveSupport.on_load(:active_record_fixtures) do
  self.fixture_paths |= ["#{Rails.root}/test/extra_fixtures/"]
end
```

before `require "rails/test_help"`. Assert `users(:bob)` **and** `posts(:hello)` (or engine fixtures) both resolve. Extra path must survive the later `[*fixture_paths, app_path].uniq`.

This is the “application-configured extra fixture paths” path that happens *during* require. The documented post-require `fixture_paths << "component1/test/fixtures"` is case 3.

**3. Extra paths assigned after require**

```ruby
require "rails/test_help"
ActiveSupport::TestCase.fixture_paths << "#{Rails.root}/test/extra_fixtures/"
## plugin style replacement must also work:
## ActiveSupport::TestCase.fixture_paths = [engine_fixtures]
## ActionDispatch::IntegrationTest.fixture_paths = ActiveSupport::TestCase.fixture_paths
```

Assert extra fixtures load on `TestCase` subclasses. For `<<` on TestCase: `IntegrationTest` has already snapshotted via `+=`, so extra paths do **not** appear on IntegrationTest unless assigned there too. Assert that split with one TestCase test that sees `posts(:hello)` and one IntegrationTest that does **not**, unless the helper also assigns IntegrationTest. Plugin overwrite (assign both) must make both see the engine path and **not** require the old app path.

**4. Relative vs absolute, duplicates, trailing slash**

Pre-seed `fixture_paths` (via the AR fixtures hook) with:

- `"#{Rails.root}/test/fixtures/"` (same as test_help)
- `"#{Rails.root}/test/fixtures"` (no slash)
- `"test/fixtures/"` (relative)
- the extra absolute path twice

After require:

- `.uniq` drops only the exact duplicate of the string test_help inserts.
- Relative and no-slash copies remain on TestCase.
- `fixtures :all` still loads each fixture set once (`users(:bob)` works; no double-insert error).
- `file_fixture` still resolves via the absolute `file_fixture_path` string, not via `fixture_paths`.

**5. Missing fixture directory**

Delete `test/fixtures` (keep `test/fixtures/files` in a variant, and delete both in another).

- `fixtures :all` does not raise; tests that do not access named fixtures pass.
- `file_fixture("hello.txt")` raises `ArgumentError` / that error appears in `rails test` output when the files dir is gone.
- If only the YAML dir is missing but extra_fixtures exists and was configured, extra fixtures still load.

**6. Classes defined before vs after require**

In one child process:

```ruby
class BeforeTest < ActiveSupport::TestCase; end
class BeforeIntegration < ActionDispatch::IntegrationTest; end
require "rails/test_help"
class AfterTest < ActiveSupport::TestCase; end
class AfterIntegration < ActionDispatch::IntegrationTest; end
```

Observable: `BeforeTest` and `AfterTest` both load `users(:bob)` and `file_fixture`. Both integration subclasses can `get` a route.

Inheritance trap to catch with a secondary assertion: a before-class that **assigns** `self.fixture_paths = []` after TestFixtures is included but that cannot happen before require (method missing). After require, a subclass that sets `self.fixture_paths = []` must **not** be overwritten by a later parent write. If the reorg moves assignment into `inherited` or `Class.class_eval` on every subclass, this breaks.

**7. Repeated require vs reload**

- `require "rails/test_help"` twice: same fixture access, same `file_fixture`, integration `get` still works. Secondary: `fixture_paths` object/content unchanged.
- `$LOADED_FEATURES.delete` + `require` (or `load`): TestCase paths stay unique; IntegrationTest `+=` currently grows. Assert loading still works. If the reorg uses `on_load(..., run_once: true)` or guards, say so — that **is** a public-effect change for `load`.

**8. Active Record absent**

`build_app` then comment out `active_record/railtie` (same as `--skip-active-record`). Child test:

- `file_fixture("hello.txt").read` works.
- `ActiveSupport::TestCase.respond_to?(:fixture_paths)` is false.
- `assert_queries_count` is not defined.
- `ActionDispatch::IntegrationTest` can still `get "/posts"`.
- Requiring test_help does not raise.

**9. Multiple boots in one process**

One isolation test, **no inner fork**, two apps:

```ruby
## boot app A, require test_help, record file_fixture / users(:a)
## reset Rails.application / app_class (as teardown_app does)
## boot app B with different root and fixtures
## do not re-require test_help
```

Current behavior: paths and `file_fixture_path` still point at **app A**. `before_setup` uses **app B**’s routes (`Rails.application.routes`). Assert that split. Then a variant that `load`s test_help after boot B: TestCase assignment picks up B’s root; IntegrationTest `+=` appends B’s paths onto the snapshotted list.

This is the case most likely to be broken by moving interpolation to file load time or by caching `Rails.root`.

**10. Production abort**

Child with `RAILS_ENV=production` around the require: process aborts with `Abort testing: Your Rails environment is running in production mode!`. Not a fixture test, but it is a public effect of this file.

### Isolation and cleanup (or regressions hide)

`rails/test_help` mutates process-global classes. Parent-process pollution will make later cases look green.

- Include `ActiveSupport::Testing::Isolation` and `build_app` / `teardown_app` ([`abstract_unit.rb`](file:///home/user/workspace/repo/railties/test/isolation/abstract_unit.rb#L111-L165)). Each example forks.
- Never `require "rails/test_help"` in the isolation parent. Drive the child with `rails "test", path`.
- Set `ENV["PARALLEL_WORKERS"] = "0"` in setup (as `test_test.rb` does) so parallelization does not fork inside the already-forked example.
- Unique tmp apps: `teardown_app` must run so `Rails.application`, `Rails.app_class`, and `RAILS_ENV` are restored.
- For in-process double-boot (case 9), reset `Rails.application`, `Rails.app_class`, and do **not** rely on Isolation between the two boots. Clear `ActiveRecord::FixtureSet` cache if AR loaded (`reset_cache`).
- Do not leak `on_load` blocks: those are global and **not** removed. Isolation’s fork is what makes that safe. In-process reload tests will see accumulated hooks — that is current `on_load` behavior (`run_once` is not set in [`lazy_load_hooks.rb`](file:///home/user/workspace/repo/activesupport/lib/active_support/lazy_load_hooks.rb#L68-L88)).
- Do not mutate `ActiveSupport::TestCase.fixture_paths` in non-isolated railties tests (`engine_test.rb` uses a dummy class for this reason).
- Keep `test/fixtures/files` out of YAML fixture discovery; a decoy yml there is the regression probe.

### What a reorg may change vs must not

Safe internal moves: split modules, rename privates, register the same hooks from another file **as long as they still run at `require "rails/test_help"`** with the same `on_load` names and no `run_once`.

Must not change without an explicit product decision:

- string path shape (`#{Rails.root}/test/fixtures/` vs no slash, relative vs absolute)
- engine paths surviving the TestCase assignment
- `file_fixture_path` on the no-AR branch
- `@routes = Rails.application.routes` on both controller and integration tests
- includes of `TestDatabases` / `TestFixtures` / `QueryAssertions` when AR is defined
- production abort
- post-require `fixture_paths=` / `<<` still writable

Call out, do not silently “fix”: IntegrationTest path duplication from `+=`; second `load` appending again; fixture paths frozen to the first boot’s `Rails.root`. Those are current effects. Observable fixture/file-fixture/integration tests should stay green even if you later drop duplication; add a named secondary assertion if you intend to keep the duplicate list.
