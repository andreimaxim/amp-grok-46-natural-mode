## Assistant

`ActionController::Parameters#expect` is permit-then-require in one call, with two extra constraints: nested values must match the declared shape (`explicit_arrays: true`), and every root named in the filter is required. `#permit` plus `#require` is the same pipeline with those constraints off.

### `#expect` always filters first, then requires the filter roots

```779:783:actionpack/lib/action_controller/metal/strong_parameters.rb
    def expect(*filters)
      params = permit_filters(filters)
      keys = filters.flatten.flat_map { |f| f.is_a?(Hash) ? f.keys : f }
      values = params.require(keys)
      values.size == 1 ? values.first : values
    end
```

That is the whole public method. It does not call `#permit`. It calls the shared filter engine with the expect defaults, then `#require` on the **filtered** object.

```text
expect(*filters)
  permit_filters(filters)                    # on_unpermitted: nil, explicit_arrays: true
    for each filter:
      Symbol/String → permitted_scalar_filter
      Hash          → hash_filter → permit_value
    unpermitted_parameters!(on_unpermitted: nil)  # no-op
    params.permit!
  keys = flatten filters to root names
  require(keys)                              # always an Array, so require maps
  unwrap if keys.size == 1
```

`#permit` uses the same engine with the opposite defaults:

```675:676:actionpack/lib/action_controller/metal/strong_parameters.rb
    def permit(*filters)
      permit_filters(filters, on_unpermitted: self.class.action_on_unpermitted_parameters, explicit_arrays: false)
```

So the contrast is not “expect is require+permit”. The contrast is:

| | `#permit` then `#require` | `#expect` |
|---|---|---|
| Filter engine | `permit_filters` | same |
| Arrays vs hashes | `explicit_arrays: false` — a list filter matches a hash **or** an array | `explicit_arrays: true` — a list filter matches only a hash; `[[:key]]` matches only an array |
| Unpermitted keys | honors `action_on_unpermitted_parameters` (`:log` / `:raise` / false) | `on_unpermitted: nil` — never logs or raises |
| Required roots | only if you call `#require` | every root named in the filters |
| Empty after filtering | `#permit` keeps `[]` / omits keys; `#require` may still see the original | `#require` runs on the filtered copy, so a type miss becomes `ParameterMissing` |
| Return value | whatever you chained | unwraps a single root; multiple roots → Array |

`#require` itself only checks presence, not type:

```526:533:actionpack/lib/action_controller/metal/strong_parameters.rb
    def require(key)
      return key.map { |k| require(k) } if key.is_a?(Array)
      value = self[key]
      if value.present? || value == false
        value
      else
        raise ParameterMissing.new(key, @parameters.keys)
      end
    end
```

### Filter dispatch: `permit_filters` → `hash_filter` → `permit_value`

```1189:1209:actionpack/lib/action_controller/metal/strong_parameters.rb
      def permit_filters(filters, on_unpermitted: nil, explicit_arrays: true)
        params = self.class.new
        filters.flatten.each do |filter|
          case filter
          when Symbol, String
            permitted_scalar_filter(params, filter)
          when Hash
            hash_filter(params, filter, on_unpermitted:, explicit_arrays:)
          end
        end
        unpermitted_parameters!(params, on_unpermitted:)
        params.permit!
      end
```

A top-level symbol (`expect(:id)`) only copies a permitted scalar. A hash declaration goes through `hash_filter`, which slices to declared keys and asks `permit_value` what the declared shape allows:

```1442:1466:actionpack/lib/action_controller/metal/strong_parameters.rb
      def hash_filter(params, filter, on_unpermitted: self.class.action_on_unpermitted_parameters, explicit_arrays: false)
        filter = filter.with_indifferent_access
        slice(*filter.keys).each do |key, value|
          next unless value
          next unless has_key? key
          result = permit_value(value, filter[key], on_unpermitted:, explicit_arrays:)
          params[key] = result unless result.nil?
        end
      end

      def permit_value(value, filter, on_unpermitted:,  explicit_arrays:)
        if filter == EMPTY_ARRAY
          permit_array_of_scalars(value)
        elsif filter == EMPTY_HASH
          permit_hash(value, filter, on_unpermitted:, explicit_arrays:)
        elsif array_filter?(filter)
          permit_array_of_hashes(value, filter.first, on_unpermitted:, explicit_arrays:)
        elsif explicit_arrays
          permit_hash(value, filter, on_unpermitted:, explicit_arrays:)
        elsif non_scalar?(value)
          permit_hash_or_array(value, filter, on_unpermitted:, explicit_arrays:)
        end
      end
```

`array_filter?` is the double-array syntax:

```1353:1364:actionpack/lib/action_controller/metal/strong_parameters.rb
      def array_filter?(filter)
        filter.is_a?(Array) && filter.size == 1 && filter.first.is_a?(Array)
      end

      def each_array_element(object, filter, &block)
        case object
        when Array
          object.grep(Parameters).filter_map(&block)
        when Parameters
          if object.nested_attributes? && !specify_numeric_keys?(filter)
            object.each_nested_attribute(&block)
          end
        end
      end
```

`[[:text]]` is an array filter. `[:text]` is not. Under `#expect`, that `elsif explicit_arrays` branch then forces `permit_hash`, which returns nil unless the value is a `Parameters` object. Under `#permit`, `permit_hash_or_array` tries the array path first and falls back to hash, so the same `[:text]` filter accepts both.

Numeric-key hashes (`"0"`, `"1"`, `"-1"`) count as nested attributes (`Parameters.nested_attribute?`) and therefore take the array-of-hashes path **when that path is reached**. `#expect` only reaches it for `[[:name]]`, not for `[:name]`.

If `permit_value` returns nil, `hash_filter` omits the key. `#expect` then `#require`s that key on the filtered copy and raises `ActionController::ParameterMissing`. `#permit` just leaves the key out.

#### 1. Scalar versus hash (type confusion)

Input: `{ user: "hack" }`. Filter: `user: [:name]`.

- `params.require(:user).permit(:name)` → `NoMethodError` (`String#permit`).
- `params.permit(user: [:name]).require(:user)` → `ParameterMissing` for `:user` (string is not a hash, so `#permit` drops it; empty filtered user then fails `#require`).
- `params.expect(user: [:name])` → `ParameterMissing` for `:user`. Same filtered miss, then require.

Input: `{ user: { name: "Martin" } }`. Same filter.

| `expect(comment: [:text])` | inner `{ "text" => "hello" }` permitted, unwrapped | `ParameterMissing: comment` |
| `expect(comment: [[:text]])` | `ParameterMissing: comment` | `[{ "text" => "hello" }, { "text" => "world" }]` both permitted |

#### 4. Missing multiple required roots

Roots are collected in filter order, then passed to `#require` as an Array. `#require` maps and re-raises the first miss.

```ruby
params = ActionController::Parameters.new(a: 1)
params.expect([:a, :b])   # ParameterMissing: b
params.require([:a, :b])  # ParameterMissing: b   (same class, no filtering)
```

`expect(:a, :b)` with `{ a: 1, b: 2 }` returns `[1, 2]`.  
`expect(:a)` with the same hash returns `1` — not `[1]`. Arity is `keys.size`, after flattening:

- one root → the required value itself
- two or more roots → Array in filter/hash-key order

```ruby
params.expect(subject: [:name], object: [:pie])
## => [Parameters{"name"=>"M"} permitted, Parameters{"pie"=>"p"} permitted]
```

`array of keys: returns multiple permitted params`, `array of key: returns single permitted param`, `array of keys: raises ParameterMissing when one is missing`, and `keys to arrays: returns permitted params in hash key order` cover this. A non-scalar among several roots (`{ a: 1, b: [] }` / `expect([:a, :b])`) is also `ParameterMissing` for `:b`, because the symbol filter only accepts scalars.

`expect!` is the same path; it rescues `ParameterMissing` and raises `ExpectedParameterMissing` (`expect! missing` / several `assert_raises(ExpectedParameterMissing)` cases).

#### 5. Numeric-key nested parameters

Input:

```ruby
book: {
  authors_attributes: {
    "0" => { name: "William Shakespeare", age_of_death: "52" },
    "1" => { name: "Unattributed Assistant" },
    "2" => { name: ["injected", "names"] }
  }
}
```

`#permit(book: { authors_attributes: [:name] })` uses `permit_hash_or_array`. Numeric keys are nested attributes, so this becomes an array-of-hashes walk. Result (still wrapped under `:book`):

```ruby
{ "book" => { "authors_attributes" => {
  "0" => { "name" => "William Shakespeare" },
  "1" => { "name" => "Unattributed Assistant" },
  "2" => {}   # :name was not a scalar
} } }
```

`#expect` with the same `[:name]` filter does **not** take that walk. `explicit_arrays` sends `authors_attributes` to `permit_hash`, which then looks for a scalar `:name` on the numeric-key hash itself. There is none, so the inner hash is empty, the parent `:book` is still present, and expect unwraps to:

```ruby
{ "authors_attributes" => {} }  # permitted: true
```

`#expect(book: { authors_attributes: [[:name]] })` does take `permit_array_of_hashes` / `each_nested_attribute`, and matches `#permit`’s numeric-key result (minus the outer `:book` wrap):

```ruby
{ "authors_attributes" => {
  "0" => { "name" => "William Shakespeare" },
  "1" => { "name" => "Unattributed Assistant" },
  "2" => {}
} }
```

Naming numeric keys in the filter disables the nested-attribute walk (`specify_numeric_keys?`). `#expect(book: { authors_attributes: { "1": [:name] } })` returns only `"1"`:

```ruby
{ "authors_attributes" => { "1" => { "name" => "Unattributed Assistant" } } }
```

That last shape is the test `nested params with numeric keys addressing individual numeric keys using require first` in [nested_parameters_permit_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/parameters/nested_parameters_permit_test.rb). The `[:name]` permit behavior is `nested params with numeric keys` in the same file. Non-numeric extra keys (`new_record`) are dropped on the array walk; negative keys (`"-1"`) still count as nested attributes.

#### 6. Unpermitted keys

`#expect` passes `on_unpermitted: nil`, so `unpermitted_parameters!` returns immediately. With `action_on_unpermitted_parameters = :raise` and `{ id: 1, book: { pages: 65, title: "x" } }`:

- `permit(book: [:pages])` → `ActionController::UnpermittedParameters` (`:title`; `:id` also unpermitted at the root in the sibling test that includes a top-level extra key)
- `expect(book: [:pages])` → `{ "pages" => 65 }` permitted, no exception
- `expect!(book: [:pages])` → same; `expect!` only remaps `ParameterMissing`

With the default `false` handler, `#permit` returns `{ "book" => { "pages" => 65 } }` permitted; `#expect` returns the unwrapped inner hash. Extra keys are dropped in both cases. Tests: `expect never raises on unexpected params` / `expect! never raises...` in [raise_on_unpermitted_params_test.rb](file:///home/user/workspace/repo/actionpack/test/controller/parameters/raise_on_unpermitted_params_test.rb), and `key: unknown keys are filtered out` in the expect file.

---

`#expect` is therefore `#permit_filters` (strict shapes, silent unpermitted) plus `#require` of every declared root, with return arity equal to the number of those roots. `#require` plus `#permit` either explodes on a scalar root (`require.permit`) or accepts hash/array confusion (`permit.require`), keeps empty arrays, and can raise `UnpermittedParameters`. No change to that behavior is implied here.
