**Request changes.** `ids` cannot be reduced to `pluck(*primary_key)`. That drop would reintroduce duplicate parent IDs on unloaded `includes` / `eager_load` relations.

Current code in [calculations.rb](file:///home/user/workspace/repo/activerecord/lib/active_record/relation/calculations.rb#L376-L388):

```376:388:activerecord/lib/active_record/relation/calculations.rb
    def ids
      if !loaded? && has_include?(primary_key)
        return apply_join_dependency.group(*primary_key).pluck(*primary_key)
      end

      pluck(*primary_key)
    end

    def async_ids
      async.ids
    end
```

`pluck` already joins through `has_include?`, but it does **not** collapse the one-to-many join. The `GROUP BY primary_key` branch is the only difference, and it is load-bearing.

```
  -- no GROUP BY
```

## Behavior matrix at this revision

| Shape | `ids` today | `pluck(*primary_key)` | Same? |
|---|---|---|---|
| Unloaded `includes` / `eager_load` with collection children | unique parent ids via `GROUP BY` | one row per joined child | **no** |
| Composite PK + `includes(:chapters)` (3 chapters) | 4 unique `[author_id, id]` tuples | 6 rows, parent repeated 3× | **no** |
| `async_ids` on those relations | `async.ids` keeps the group path | would inherit pluck duplicates | **no** |
| `includes` + `limit(2)` with 5 children | `[1, 2]` (distinct PK subquery, then `GROUP BY`) | `[1, 1, 1, 1, 1, 2]` | **no** |
| Loaded relation (`to_a` then `ids`) | in-memory `pluck` on unique records | same | yes |
| `preload` (no join) | `has_include?` is false → `pluck` | same | yes |
| Plain `joins` | duplicates kept | duplicates kept | yes |
| `where(id: [])` / contradicting scope | empty, 0 queries | same | yes |
| `skip_query_cache!` | still goes through `pluck` | same | yes |
| `order(:rating)` with no child rows | `GROUP BY id ORDER BY rating` | `ORDER BY rating` | values match on sqlite3 |

`has_include?` is true whenever `includes_values` is present, even if `includes` would otherwise preload. That is why `Company.includes(:contracts).ids` joins and groups, while `Company.preload(:contracts).ids` does not join.

`group(*primary_key)` / `pluck(*primary_key)` already splat a composite key. The CPK bug is not splat handling; it is the missing `GROUP BY "cpk_books"."author_id", "cpk_books"."id"`. Observed:

- `ids`: `[[550090038, 342015473], [550090038, 385957113], …]` (4)
- `pluck`: same list plus two extra `[550090038, 342015473]` (6)

`GROUP BY` rather than `DISTINCT` exists so `ORDER BY` a non-selected column stays valid on PostgreSQL/MySQL (`Post.order(:created_at).includes(:comments).ids`). Dropping the branch avoids that error only by returning join-multiplied rows instead.

`Relation#none` is not the interesting case: both methods already return `[]`.
