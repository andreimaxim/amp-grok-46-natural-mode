`Array.wrap` is a three-way branch in [`activesupport/lib/active_support/core_ext/array/wrap.rb`](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/array/wrap.rb#L38-L46). It never calls `to_a`.

```ruby
def self.wrap(object)
  if object.nil?
    []
  elsif object.respond_to?(:to_ary)
    object.to_ary || [object]
  else
    [object]
  end
end
```

```diagram
          object
             │
             ▼
        object.nil? ──yes──▶ []
             │no
             ▼
 respond_to?(:to_ary) ──no──▶ [object]
             │yes
             ▼
        object.to_ary
             │
        truthy? ──yes──▶ that value (unchanged)
             │no (nil)
             ▼
          [object]
```

`respond_to?(:to_ary)` is the gate. Only if that is true does `to_ary` run. The `||` then treats a `nil` result as “not an array,” and wraps the original object.

### Contrast with `Kernel#Array` (only as documented)

The comment in [wrap.rb:16–29](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/array/wrap.rb#L16-L29) states three differences:

1. If `to_ary` returns `nil`, `Kernel#Array` continues to `to_a`; `Array.wrap` wraps immediately (`[object]`). That matches `NilToAry` above.
2. If `to_ary` returns neither `nil` nor an `Array`, `Kernel#Array` raises; `Array.wrap` returns that value. That matches `DoubtfulToAry`.
3. `Array.wrap` never calls `to_a`. No `to_ary` means `[object]`. The documented Hash example is the illustration: `Array(foo: :bar) # => [[:foo, :bar]]` vs `Array.wrap(foo: :bar) # => [{:foo=>:bar}]`.

The splat note ([wrap.rb:31–37](file:///home/user/workspace/repo/activesupport/lib/active_support/core_ext/array/wrap.rb#L31-L37)) is about `[*object]`, not about `Array.wrap` itself: `[]` for `nil`, otherwise `Array(object)` with the same `Kernel#Array` differences.
