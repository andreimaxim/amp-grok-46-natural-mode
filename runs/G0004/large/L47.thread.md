Path assembly is a pipeline from three config collections into two Zeitwerk loaders, `$LOAD_PATH`, and the reloader. The public surface is not `_all_autoload_paths`.

### Invariants (derived, not promised)

#### 1. Config collections are concatenations, computed late

From [`Rails::Engine::Configuration`](file:///home/user/workspace/repo/railties/lib/rails/engine/configuration.rb):

- `all_autoload_paths` = `autoload_paths + paths.autoload_paths`
- `all_autoload_once_paths` = `autoload_once_paths + paths.autoload_once`
- `all_eager_load_paths` = `eager_load_paths + paths.eager_load`

Custom arrays are not frozen until `:set_autoload_paths` / `:set_eager_load_paths`. The path tree still filters through [`Rails::Paths::Root#filter_by`](file:///home/user/workspace/repo/railties/lib/rails/paths.rb): existent directories only, children with incompatible flags stripped, then `uniq`. Reading `config.autoload_paths` must not snapshot `config.paths` — already covered by the issue 49629 regression.

Default flags that a refactor must not change:

- `app` and `app/{controllers,channels,helpers,models,mailers}`: `eager_load: true` (hence also autoload)
- `app` glob `{*,*/concerns}`, exclude `assets` and `javascript_path`
- `lib` and `vendor`: `load_path: true` only
- `test/mailers/previews`: `autoload: true`, not eager

#### 2. Engine formula for the main set

From [`Rails::Engine#_all_autoload_paths`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb):

```text
main = uniq(all_autoload_paths ∪ all_eager_load_paths − all_autoload_once_paths)
once = uniq(all_autoload_once_paths)
```

Consequences:

- Every eager path is a main autoload path **unless** it is also once.
- A path listed in both `autoload_paths` and `autoload_once_paths` on the **same** engine is once-only for that engine.
- `_eager_load_paths` still receives the once+eager path. The once loader then eager-loads it (`do_not_eager_load` is skipped when `ActiveSupport::Dependencies.eager_load?(path)`).
- [`ActiveSupport::Dependencies`](file:///home/user/workspace/repo/activesupport/lib/active_support/dependencies.rb) documents that the two global arrays may intersect. Engine assembly tries to prevent that per engine. Cross-engine “A’s autoload == B’s once” is the remaining hazard: `once` is set up first, then `main.push_dir` would raise Zeitwerk’s “already managed” error. Preserve that: same-engine overlap is silent and once-owned; conflicting cross-engine ownership still errors.

`_all_autoload_paths` / `_all_load_paths` are memoized on the engine. After `:set_autoload_paths` has run, later mutation of that engine’s config arrays must not change what was published.

#### 3. Initializer timing

Published **before** `:bootstrap_hook`, per engine, in [`railties/lib/rails/engine.rb`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb):

| Initializer | Observable freeze / publish |
|---|---|
| `:set_load_path` | existent dirs from `_all_load_paths` unshifted; `$LOAD_PATH.uniq!` |
| `:set_autoload_paths` | `config.autoload_paths` and `config.autoload_once_paths` frozen |
| `:set_eager_load_paths` | `config.eager_load_paths` frozen; `_eager_load_paths` is a `Set` |

Then [`Bootstrap#setup_once_autoloader`](file:///home/user/workspace/repo/railties/lib/rails/application/bootstrap.rb) (after `:set_eager_load_paths`, before `:bootstrap_hook`):

- freezes `ActiveSupport::Dependencies.autoload_once_paths`
- `push_dir` only existing directories not already on `once`
- `once.setup` — so initializers **can** autoload from once paths

Then [`Finisher#setup_main_autoloader`](file:///home/user/workspace/repo/railties/lib/rails/application/finisher.rb):

- freezes `ActiveSupport::Dependencies.autoload_paths` (so initializers **can** still append to the main array; the Zeitwerk test does this)
- `push_dir` existing dirs not already on `main`
- `enable_reloading` + `on_load` descendants tracking **only** if `config.reloading_enabled?`
- `ActiveSupport::Dependencies.autoloader` is `main` only when reloading is on

User-preconfigured `push_dir(..., namespace:)` must not be overwritten (`already_configured_dirs`).

#### 4. Loader ownership and reload

- `Rails.autoloaders.main` / `.once` stay two distinct `Zeitwerk::Loader`s, tags `rails.main` / `rails.once`.
- `once.reloading_enabled?` is always false.
- `ActiveSupport::Dependencies.clear` calls `autoloader.reload` (main). `once.reload` must not run.
- `Rails.application.watchable_args` dirs are `main.dirs` with `[:rb]`, plus `config.watchable_*`. Once dirs are not watched.
- Production (`eager_load: true`): `Zeitwerk::Loader.eager_load_all` then `Rails.autoloaders.each(&:eager_load)`. Dirs marked `do_not_eager_load` stay unloaded until first constant reference.
- If both `eager_load` and reloading: `reloader.after_class_unload` re-eager-loads **main only**.

#### 5. `$LOAD_PATH`

[`_all_load_paths`](file:///home/user/workspace/repo/railties/lib/rails/engine.rb): `paths.load_paths`, plus main+once autoload dirs **only** when `config.add_autoload_paths_to_load_path`. Since 7.1 that flag is false ([`load_defaults "7.1"`](file:///home/user/workspace/repo/railties/lib/rails/application/configuration.rb)).

`lib` is on `$LOAD_PATH` anyway via [`Application.add_lib_to_load_path!`](file:///home/user/workspace/repo/railties/lib/rails/application.rb) and `paths["lib"]` (`load_path: true`). Autoload dirs such as `app/models` must not appear when the flag is false.

Only **directory** paths are unshifted; missing custom paths never enter `$LOAD_PATH`.

### How not to couple to private ordering

1. **Do not rebuild `_all_autoload_paths`.** If `main.dirs` must be checked against `AS::Dependencies.autoload_paths`, keep the existing consistency test (same pipeline, two exits). That relative order is observable for shadowing, but default `app/models` vs `app/controllers` order is not worth pinning.

2. **Do not assert engine-before-app or unshift polarity.** Reverse railtie order + `unshift` is an implementation accident. Assert both paths are present and each constant loads.

3. **Pin relative order only for a sequence the test appended** (`e1,e2,e3` on once). Use `slice(index, n)` as the existing test does, not `assert_equal entire_once.dirs, expected`.

4. **Prefer `assert_includes` on `Set.new(loader.dirs)`** when order cannot affect constant resolution (disjoint roots).

5. **Do not assert `$LOAD_PATH.index`.** After `uniq!`, only membership of autoload-derived entries matters.

6. **Do not count global reloader callbacks.** Register your own blocks; assert those counters.

7. **Keep Pathname vs String as current behavior.** `eager_load?` uses set membership on the object stored in `_eager_load_paths`. A preservation test that normalizes paths would hide a real behavior change — or fail a refactor that started normalizing. If you care, add an explicit probe: Pathname eager path still eager-loads (`load_path_test` already does `assert Foo`).

A refactor that switches `unshift` to `concat`, or custom-before-paths to paths-before-custom, should still pass this suite **unless** it changes loader ownership, freeze timing, `$LOAD_PATH` membership, or reload semantics. That is the point of the black-box probes.
